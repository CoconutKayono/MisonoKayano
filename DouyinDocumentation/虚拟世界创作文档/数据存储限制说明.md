# 数据存储限制
由于DataStore占用全局服务器存储资源，整个世界的存储用户以及单条存储的key和value的长度有一定的限制，具体限制如下：
## 单世界容量限制
单个世界的存储容量上限默认为**100Mb**，超出世界存储容量的部分会失效。**因此，请在使用该能力前，合理的评估世界存储用量，如有超出风险，请及时联系运营进行处理。**
## 接口容量限制
### DataStore
#### 参数限制
**GetDataStore参数限制**
| 参数 | 类型 | 长度限制 |
| --- | --- | --- |
| name | string | **20** |
| scope | string | **50** |
**DataStore中方法的参数**
| 参数 | 类型 | 长度限制 |
| --- | --- | --- |
| key | string | **128** |
| value | * number <br> * boolean <br> * string | **6000** <br>  |
| metadata | string | **1000** |
#### 容量限制
每个DataStore实例的键值对存储设计**容量上限为1000个**独立键值（key）单元，当单个DataStore实例存储的键数量达到1000个时，系统将自动触发写入保护机制，后续所有**新增键值的操作将返回错误**。**已存在键的更新操作不受此限制影响**。
#### 使用建议
| 场景 | 说明 | 实现 |
| --- | --- | --- |
| **确定容量存储** | 明确数据量上限不超过1000键值单元的业务实体。例如：存储系统配置。 | 明确系统配置的参数数量一定小于1000，可以直接创建system的DataStore <br> ```Lua <br> --在config存储空间下，创建system的DataStore <br> _, store = DouyinDataService.GetDataStore('Config', 'system') <br>  <br> --设置system中属性f1、f2，已明确system属性数量不超过1000 <br> store:SetData('f1', 1) <br> store:SetData('f2', 2) <br> ``` <br>  |
| **不定容量存储** | 数据量不可控的业务主体。例如：用户数据，由于++用户总数量++不会少于1000，所以我们**不能创建某种属性的DataStore，在该DataStore中添加不同用户数据**。 <br>  | **错误实现** <br> ```Lua <br> --在game存储空间下，创建score的DataStore <br> _, store = DouyinDataService.GetDataStore('Game', 'score') <br>  <br> --设置不同用户积分，最多只可设置1000个用户积分，设置第1001个用户时会报错 <br> store:SetData('user001', 1) <br> store:SetData('user002', 2) <br> store:SetData('user003', 3) <br> store:SetData('user004', 4) <br> ``` <br>  <br> **正确实现** <br> ```Lua <br> --在game存储空间下，创建user001的DataStore，设置score属性 <br> _, store = DouyinDataService.GetDataStore('Game', 'user001') <br> store:SetData('score', 1) <br>  <br> --在game存储空间下，创建user002的DataStore，设置score属性 <br> _, store = DouyinDataService.GetDataStore('Game', 'user002') <br> store:SetData('score', 2) <br>  <br> --在game存储空间下，创建user003的DataStore，设置score属性 <br> _, store = DouyinDataService.GetDataStore('Game', 'user003') <br> store:SetData('score', 3) <br>  <br> --在game存储空间下，创建user004的DataStore，设置score属性 <br> _, store = DouyinDataService.GetDataStore('Game', 'user004') <br> store:SetData('score', 4) <br> ``` <br>  |
### OrderedDataStore
#### 参数限制
**GetOrderedDataStore的参数**
| 参数 | 类型 | 长度限制 | 说明 |
| --- | --- | --- | --- |
| name | string | **50** | - |
| scope | string | **50** | - |
**OrderedDataStore中方法的参数**
| 参数 | 类型 | 长度限制 | 说明 |
| --- | --- | --- | --- |
| key | string | **1000** | - |
| value | number | **-** | 转为字符串的长度 |
#### 容量限制
每个OrderedDataStore实例默认支持**最大5000个**有序键值（key）单元，单个OrderedDataStore实例存储的键数量达到5000个时，系统将自动触发写入保护机制，后续所有**新增键值的操作将返回错误**。**已存在键的更新value不受此限制影响**。当需要突破5000键限制时，可视业务场景**进行分片等设计**来进行实现。
#### 排行示例（仅提供实现思路，请勿参考写法）
```Lua
--在game存储空间下，创建football的OrderedDataStore
_, store = DouyinDataService.GetOrderedDataStore('Game', 'football')

--最多5000个玩家，超过需进行分片设计处理
store:SetData('user001', 10)
store:SetData('user002', 20)
store:SetData('user003', 30)
store:SetData('user004', 40)


--每页数量
local pagesize = 100

--按照降序获取pages，每一页100个数据
_, pages = GetSortedData(false, pagesize, -1, 0)

--第一页数据（100个）
_, value = pages:GetCurrentPage()

--遍历当前页具体数据
for k, v in pairs(value) do 
    print('user:' .. k .. ' score:' .. v.value)
end
```

## 访问次数限制：
**什么是访问次数**：当前世界每分钟累计最多处理900次数据存储API的调用（所有数据的读、写相关接口）。
举例：假设房间里一共有10个玩家，如果你的代码逻辑里，在一分钟内分别对房间内10个玩家进行一次数据存储的读/写操作，则每分钟最多会调用10次DataStore API。

* **限制是多少**：单个房间的 DataStore API 调用次数是有上限的，每分钟内请求量默认限制为**900次**，峰值限制为**1800次；超出限制的API调用均会失效。**
* **默认限制**：默认每分钟API调用限制为900次，举例：如果前三分钟每分钟调用了900次，第四分钟调用了901次，则第901次的API调用会失效。
* **峰值限制**：如果当前世界内，当前一分钟内没有API相关的调用的话，那么下一分钟API的调用峰值可达**1800次**。

所有的数据存储API（读写）共享一个请求量限制队列。
