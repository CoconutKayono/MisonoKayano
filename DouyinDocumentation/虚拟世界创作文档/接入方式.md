    public static void Purchase(string productId, int productNum, string orderData)

## 获取商品信息
通过调用`DouyinMarketingService.GetProductInfos`接口获取商品信息。该接口通过回调返回商品信息结果，具体说明如下：

* **方法定义**：`public static void GetProductInfos(Action<int, string, List<DouyinProductInfo>> callback)`
* **参数说明**：`callback`为结果回调函数，包含以下返回内容：
   * 状态码（int）：0 表示成功，非 0 表示失败；
   * 错误信息（string）：状态码非 0 时返回具体错误描述；
   * 商品信息列表（List<DouyinProductInfo>）：包含商品 ID、名称、描述、图标、价格、状态等详细信息（[商品详细信息](/s196aspp/eyfwfk6f)）。
* **商品状态**：
   * 调用`DouyinMarketingService.GetProductInfos`接口时，将返回全量商品信息，包含以下状态的商品数据：
      * **下架（Offline=1）**：已暂停销售的商品；
      * **上架（Online=2）**：当前可正常销售的商品；
      * **删除（Delete=3）**：已被逻辑删除的商品。
   * 由于接口返回结果包含所有状态的商品数据，在界面展示时需根据业务需求对商品状态（`DouyinProductInfo.status`字段）进行过滤处理，仅展示符合条件的商品（如仅展示上架状态商品）。
   * **测试商品过滤说明**：当前接口暂不支持直接通过参数过滤测试商品。若需排除测试商品，需通过商品 ID（`DouyinProductInfo.id`字段）进行筛选，即根据预定义的商品 ID 列表白名单，在获取接口返回结果后手动过滤。

## 商品购买流程
通过调用`DouyinMarketingService.Purchase`接口发起商品购买操作。具体说明如下：

* **方法定义**：`public static void Purchase(string productId, int productNum, string orderData)`
* **参数说明**：
   * `productId`：待购买的商品 ID；
   * `productNum`：购买商品数量；
   * `orderData`：订单额外信tt息（可选参数，用于传递业务自定义数据）。

### 商品购买回调
商品购买结果通过`DouyinMarketingService.onPurchaseResult`事件回调通知。该事件为 Unity 引擎事件，具体说明如下：

* **事件定义**：`public static UnityEvent<int, string, List<DouyinReceiptInfo>> onPurchaseResult = new()`
* **触发时机**：商品购买操作完成（如支付超时、已支付等状态变更时）；
* **返回参数**：
   * 状态码（int）：0 表示成功，非 0 表示失败；
   * 错误信息（string）：状态码非 0 时返回具体错误描述；
   * 订单票据列表（List<DouyinReceiptInfo>）：包含订单状态、用户 OpenID、商品 ID、交易数量等详细信息（[订单的票据信息](/s196aspp/eyfwfk6f)）。

# 商品发货流程 - 服务器Dedicated Server
## 服务器核心流程
![Image](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/bb9ab6919b8543e1bc3d963c359f3218~tplv-goo7wpa0wc-image.image)
```C#
public class DouyinOrderPaymentEvent : UnityEvent<string, DouyinReceiptInfo> {}
public static class DouyinMarketingService 
{
    public static DouyinOrderPaymentEvent onOrderPayment = new();
    public static void ConfirmOrder(string sequenceId, DouyinReceiptInfo receiptInfo, int code)
}
```

## 扣款成功通知发货
在 DedicatedServer 环境中，需监听`DouyinMarketingService.onOrderPayment`事件以感知订单扣款成功状态。当用户完成订单支付且系统确认扣款成功后，该事件将被触发，此时需启动后续发货处理逻辑。

* **事件定义**：`public static DouyinOrderPaymentEvent onOrderPayment = new()`
* **触发时机**：当用户完成订单支付且系统确认扣款成功后，该事件将被触发；
* **返回参数**：
   * 订单查询序列号（string）：订单查询序列号，同一个订单如果没有完成发货，会涉及补单查询，同一个订单每次查询的序列号不同；
   * 订单票据 DouyinReceiptInfo：包含订单状态、用户 OpenID、商品 ID、交易数量等详细信息（[订单的票据信息](/s196aspp/eyfwfk6f)）。

## 发货
在 DedicatedServer 中，完成实际发货操作后，需通过调用`DouyinMarketingService.ConfirmOrder`方法向平台同步最终发货状态。

* **方法定义**：`public static void ConfirmOrder(string sequenceId, DouyinReceiptInfo receiptInfo, int code)`
* **参数说明**：
   * `sequenceId`：订单的查询序列号；
   * `DouyinReceiptInfo`：包含订单状态、用户 OpenID、商品 ID、交易数量等详细信息（[订单的票据信息](/s196aspp/eyfwfk6f)）。
   * `code`: 订单的发货状态：
      * `code = 0`：表示发货成功，平台将标记订单为已发货状态；
      * `code > 0`：表示发货失败，平台将触发补单机制（[商品补单流程 - 服务器Dedicated Server](/s196aspp/eyfwfk6f)）；
      * `code < 0`：表示发货失败且需退款，暂不支持；

## 不要在客户端发货
### DS服务器发货流程与补单保障
在 Dedicated Server（DS 服务器）中，需通过以下流程确保订单发货的可靠性：

* **监听支付事件**：监听`onOrderPayment`事件，捕获玩家支付成功的订单信息；
* **数据持久化**：在事件回调中，将玩家购买的商品信息保存至数据库；
* **通知平台状态**：
   * 若数据保存成功，调用`ConfirmOrder`接口通知平台发货成功；
   * 若数据保存失败，调用`ConfirmOrder`接口通知平台触发补单机制 —— 玩家重新登录时，DS 服务器会再次触发`onOrderPayment`事件，确保用户支付成功后不会出现发货失败的问题。

### 客户端发货的局限性
客户端直接处理发货存在以下风险和不足：

* **无官方补单支持**：客户端发货没有官方提供的补单逻辑，需开发者自行设计并实现补单流程；
* **数据保存不稳定**：客户端保存数据易受弱网、应用闪退等异常情况影响，导致数据保存失败；而 DS 服务器的运行环境更稳定，可有效避免此类问题。

# 商品补单流程 - 服务器Dedicated Server
## 补单触发条件
平台将针对以下三种场景触发补单机制：

1. 服务器未成功调用`DouyinMarketingService.ConfirmOrder(string sequenceId, DouyinReceiptInfo receiptInfo, int code)`接口同步最终发货状态；
2. 订单发货操作超时（指发货操作在2秒内未完成）；
3. 发货状态码`code > 0`（明确表示发货失败，需要补单）。

## 补单执行流程
```C#
public static void BackOrder()
```


* 自动补单逻辑
   * 补单触发后，平台将在用户 **下次登录并在线满 1 分钟** 时，自动核查所有待补发订单，并触发`DouyinMarketingService.onOrderPayment`事件回调，通知服务器执行订单补发逻辑。
* 手动补单触发
   * 除自动补单外，支持在客户端主动调用`DouyinMarketingService.BackOrder`接口手动触发补单， **建议在用户数据完全加载完成后执行调用** ，以确保补单逻辑可靠性。

## 幂等性保障要求
为避免重复补发，创作者需记录订单票据信息（`DouyinReceiptInfo`），通过比对记录的票据的订单状态，确认当前订单的实际发货状态，并根据状态判断是否需要执行商品补发操作，确保同一订单仅会发货一次。

* 发货幂等 
   * 防止订单多次查询，导致重复发货
* 订单状态幂等
   * Code = 0 的时候，以后所有的返回值都必须是 Code = 0; 发货成功之后，后续的所有返回状态都必须是发货成功。
   * Code < 0 的时候，以后所有的返回值都必须是 Code < 0; 发货失败退款之后，后续的所有返回状态都必须是发货失败退款。
