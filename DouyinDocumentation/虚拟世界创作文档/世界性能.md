# 世界运行模式
世界支持在抖音端、多闪端上体验，在不同的APP中，世界支持三种不同的运行模式供用户体验。
| 运行模式 | 手机端体验特征 | 宿主 | 用户占比 |
| --- | --- | --- | --- |
| Native（IOS） | 手机端体验流畅丝滑体验，和传统手游本地体验一致 | 仅多闪 | 10% |
| SC（安卓） |  | 抖音端 | 90% |
| WebGL | 手机端体验流畅丝滑体验，但是世界有显著的内存压力 |  |  |
| 云游戏 | 游戏在云端真机运行，将渲染后的画面以视频流的形式传回本地，本地运行无性能压力，但是依赖<span style="background-color: rgba(247,105,100, 0.96)">网络环境，延迟高，容易卡顿、画质模糊</span> |  |  |
# 世界运行时性能参考
| 性能指标 | 建议参考值 | 指标意义 | 如何优化 |
| --- | --- | --- | --- |
| FPS | > 30 | 用于反映世界在非云游方案下，实机运行流畅程度 | 尽量减少同屏渲染物体 |
| 内存占用 | < 1400 Mb | 过高的内存会带来显著的掉帧、卡顿、设备发热、崩溃等问题 |  |
| 网络对象数量 | 小于 8000 | 反映世界内网络对象的数量，网络对象数量过高会带来房间内玩家卡顿 |  |
| 异常率 | 小于 30% | 反映用户受到报错数量影响的指标，避免持续 / 高频 / 重复的报错也是提升世界稳定性/性能的有效方式之一 |  |
# 优化建议
## 线上内存
若是想要降低线上内存均值，可以考虑使用[世界流式能力](/s196aspp/prhoy3fv)，通过对场景资源的动态加载/卸载能力，能够有效降低线上资源内存的压力。
## 业务逻辑侧优化
如果处理不好业务逻辑，也可能会引发较大的性能问题。比如：频繁的创建与销毁物体、在Update中每帧去遍历大量的GameObject或者组件、频繁的触发GC、因逻辑漏洞导致出现较多空引用情况等等。
为了能在世界上线前尽可能的检测出性能问题，平台强烈建议使用本地调试器中的性能分析看板，通过Unity的profiler来监控项目在本地的运行情况，提现发现和修复明显的内存相关的问题。
性能分析看板使用方式：[性能分析看板使用指南](/s196aspp/m6rp32q3)
## 资源侧优化
### 减少纹理尺寸
较大的纹理尺寸会增加内存消耗和 GPU 带宽使用率。
建议的最大纹理尺寸为 **1024x1024** 像素。你可能会问，我们如何决定使用大纹理尺寸还是小纹理尺寸？
答案是考虑物体在世界中的体积。例如，如果物体在世界中是一块小石头，则使用较小的纹理尺寸（128x128）；如果是一栋大型建筑，则使用较大的纹理尺寸（1024x1024）。你可以参考“纹素密度”（Texel Density）的概念，其计算公式如下：纹素密度 = 纹理分辨率 / 物体尺寸
### 减少网格数量
在 Unity 中，每个网格可以包含多个子网格，每个子网格会生成 1 个或多个额外的绘制调用。绘制调用是指 CPU 调用图形 API（例如 OpenGL）来请求 GPU 绘制内容。通常，每帧的绘制调用次数越多，每帧的 CPU 消耗就越高。
因此，我们建议每个网格使用 1 个 Mesh Renderer，最多 3 个 Mesh Renderer。您可以在建模软件中将多个 Mesh Renderer 合并为一个。
### 减少网格三角形的数量
确保不要使用过多的三角形。如果您尝试上传三角形数量超过上限的网格，SDK 会发出警告（请参阅[资源规范](/s196aspp/ok71g68d)）。您很少需要过多的多边形细节。您可以考虑烘焙法线贴图，并通过抽取或重新拓扑来简化网格。
过多的网格三角形会导致世界渲染性能下降，影响所有玩家的体验。建议在建模软件中尽量减少模型的三角形数量。
### 使用更少的材质球
如果多个材质球与一个网格关联，则运行时会生成大量绘制调用，并且 Unity 中使用的每个子网格组件都会对应一个单独的材质。我们建议您将多个纹理合并为一个纹理图集，并将多个子网格合并为一个网格，以减少材质球数量。
### 使用更简单的着色器（shader）/减少Shader变体数量
复杂的着色器会增加 GPU 渲染帧的成本。每个像素的着色器指令越多，渲染像素所需的时间就越长，从而导致帧持续时间更长。
着色器指令的数量会随着数学函数数量的增加而增加，某些操作的成本也会更高。构建复杂的着色器时，请尽量限制指令数量。
### 使用不透明材料
除非您确定需要使用透明材质，否则我们建议您使用不透明材质。透明材质通常需要更多的 GPU 计算资源来绘制。使用不透明材质将为您的世界带来更好的渲染效果。
### 设置要剔除的材质面
您可以配置材质，将模型的组件设置为在正面、背面或两者可见。我们建议您渲染组件的一侧，因为渲染两侧通常需要更多的 GPU 计算时间。
### 减少使用 Alpha 测试材料
我们建议您使用不透明材质，除非您确定需要使用透明材质（例如：树叶）。此外，尽量不要使用经过 Alpha 测试的材质，因为它们对移动终端的 binning 渲染机制极其不友好，并且会降低 GPU 渲染的效率。减少或避免使用经过 Alpha 测试的材质将为您的世界带来更好的渲染效果。
### 减少发射的颗粒数量
虽然粒子系统可以产生很多炫酷的效果，但过多的粒子系统可能会在某些计算机上导致问题。我们建议您限制应用的粒子系统数量，并设置任何特定时刻发射的粒子数量的上限。
有一些方法可以确保粒子系统拥有大量粒子而不影响性能。例如，您可以使用精灵粒子的动态批处理；不要使用碰撞，并确保粒子的运动简单。
有关相关技术的更多信息，请参阅 Unity 的 Profiler 视图，以评估粒子模拟所需的 CPU 时间。通常，我们建议您使用许多小而不透明的粒子，而不是大的透明粒子。Unity 的粒子系统非常出色，如果使用得当，运行速度会很快。
### 减少实时光源的使用
如果您的世界中灯光处于实时模式，则确保性能的成本非常高。向您的世界添加灯光意味着灯光接触到的所有内容都将使用双倍绘制调用进行渲染。额外的灯光还会使渲染时间加倍。这显然会对性能造成不利影响。请勿使用始终亮着的灯光。您可以使用动画覆盖来打开和关闭手电筒，或者根本不使用灯光。
如果使用灯光，请禁用阴影。实时灯光的阴影非常消耗性能，但通常在移动物体上表现并不理想。
一般来说，我们建议您尽量不要在您的世界中使用任何实时渲染的灯光。它们不仅会对您自己的世界的性能产生不利影响，而且还会在物体被照亮时成倍增加性能消耗的成本。
### 减少动态阴影的使用
世界中的物体可以拥有两种类型的阴影：动态阴影和静态阴影。静态阴影由离线烘焙生成，运行时不会产生额外成本；而动态阴影则在每帧渲染过程中生成，在移动设备上成本非常高昂。
因此，强烈建议物体投射静态阴影，并尽量减少或避免在世界中使用动态阴影。
### 减少后期处理效果的数量
后处理是指对整个屏幕进行像素级处理，其成本与分辨率密切相关。分辨率越高，需要处理的像素越多，过多的后处理效果会导致较高的 GPU 开销。这在分辨率较高但 GPU 计算能力较弱的移动设备上可能会成为瓶颈。
### 优化碰撞器
尽量避免在世界场景中使用网格碰撞器，因为它们的效率低于基本形状碰撞器（例如盒子碰撞器和球体碰撞器）。如果在某些情况下必须使用网格碰撞器，请尽可能使用凸网格碰撞器，因为非凸网格碰撞器效率最低，最好作为最后的选择。

## 从第一天开始优化
如果您希望您的世界在所有移动设备上都能以每秒 30 帧 (FPS) 的帧率流畅运行，请在整个开发过程中始终以此为目标。您不必始终保持 30 FPS 的帧率，但即使在世界开发的早期阶段，也应至少在 80% 的时间内保持 28 FPS 的帧率。这将确保您的世界始终保持良好的性能，并避免在开发接近尾声时出现性能危机。
