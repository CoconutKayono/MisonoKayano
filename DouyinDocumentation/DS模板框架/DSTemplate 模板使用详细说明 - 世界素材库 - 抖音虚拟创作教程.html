DSTemplate 模板使用详细说明
范围：本文只描述 Assets/DSTemplate 下的内容——以 Scripts 里的 Lua 为主，并简要说明同目录下的资源、Prefab、内嵌 SDK 等如何与脚本配合。不涉及工程里其他文件夹（如 FLY01 关卡美术等）的细节。​
创作者：要在本模板上改玩法、加系统、或排查数据/网络问题的开发者。​
配套文档：具体到一条新业务的接入步骤，见DSTemplate快速上手业务系统接入指南：成就系统​
关于成就系统的定位：模板内置的 AchievementSystem / ServerAchievementData / ServerAchievementManager / ClientAchievementData 一整套是给创作者参考的简易 demo，不是模板自身的业务——它的作用是把"新增一条业务域 + 一对协议 + 一个 System"的端到端链路完整跑通，用最小代码示范每一处该改的位置。模板默认只做 4 个基础域（actor / bag / ranking / social），第 5 个 achievement 是示范出来的"新加域"。创作者接入自己业务时，照成就 demo 的形状改即可，不要把 demo 当成模板必须的功能。​
一、DSTemplate 根目录在做什么​
后续章节都围绕 Scripts/ 展开，按 Common → Server → Client → 端到端数据流 的顺序逐层介绍。​
二、整体架构​
模板把"端"和"层"两件事分开看：​
  • 双端各自分层：服务端四层、客户端三层；​
  • 双端共享 Scripts/Common（协议名、网络包、OOP、配置、工具）。​
2.1 服务端四层​
调用方向：协议层 → Logic → Data → DataStore。​
反向调用是禁忌：协议层不直接读写数据、Logic 不直接打 KV、Data 不直接发包。出现这种"穿层"调用通常意味着该把逻辑挪到 *Manager。​
2.2 客户端三层​
调用方向：协议层 → Logic → Data（KV 永远走服务端，客户端不持久化）。​
客户端只有三层，是因为 KV 永远走服务端——本地的 ClientPlayerData 只是服务端权威快照的镜像，所有写都要经 C2S 协议落到服务端。​
​
三、Common 共享层（Scripts/Common/）​
3.1 协议入口 NetPacketType​
NetPacketType 既是协议类型枚举，也是注册入口。文件顶部内置了一组通用协议（玩家数据、商业化、邮件、CDK、成就），玩法相关协议在文件底部通过 NetPacketType.RegisterExtensions({...}) 合并，不要散落到业务层去写。​
文件顶部有"已初始化则 return"的去重保护：避免多路径重复 require 时把 RegisterExtensions 合并的结果清空。新增协议必须放进文件顶部表或底部 RegisterExtensions，不要再单独建 GameNetPacketType.lua 之类的并行表。​
3.2 OOP / 工具 / 配置​
  • Common/Core/OOP/BaseClass.lua：所有 Lua 类用 BaseClass:DefineClass("ClassName") 定义。​
  • Common/Utility：Json / JsonWrapper / ServerUtils / tprint 双端共用。​
  • Common/Config：GameDataLib / GoodsDataLib / LevelDataLib / LotteryDataLib / ShopDataLib / ActivityEventDataLib，对应 Common/ExcelConfig/*.xls 表数据。​
​

五、服务端​
5.1 入口与生命周期（GameServerModule.lua）​
宿主调度的单脚本，承担四件事：​
    Start：ServerEventNetwork.Init() → CommercialDeliverManager.Start() / CommercialModule.Start() → ServerPacketRegister.RegisterAll()；用 hasStartedServerRuntime 自身去重。​
    Update：ServerPlayerManager.TickFlush() + ServerGameLogicManager.Tick()。​
    OnPlayerJoined / OnPlayerRejoined / OnPlayerLeft：转发到 ServerPlayerManager 与 ServerGameLogicManager，离房后还要 coroutine.yield(WaitForSeconds(5)) 给落盘协程留时间。​
    OnDestroy：ServerEventNetwork.Clear() + CommercialModule.OnDestroy()。​
JudgeIsServer() 是入口闸门——同一份 Lua 在双端跑，所有服务端逻辑都先做这一道判断。​
5.2 在线表与 Tick（ServerPlayerManager.lua）​
  • roomPlayers 维护 openId → player 的在线表；AddPlayer / RemovePlayer / GetPlayer / GetAllPlayers / GetPlayerCount。​
  • OnPlayerJoined 注册玩家、ServerPlayerDataManager.GetOrCreate(openId) 拿聚合根、立刻 agg:LoadIntoCache()。​
  • OnPlayerRejoined 仅注册 + 取聚合（不再次 Load，命中缓存）。​
  • OnPlayerLeft：agg:ClearPending() → agg:Flush(true) → ServerDataCache.ClearCacheData → ServerPlayerDataManager.Remove → RemovePlayer。​
  • TickFlush 节流 5 分钟（flushIntervalSeconds = 300），遍历在线玩家 agg:Flush(false)。​
  • HandlePlayerDataRequest / HandleResyncRequest 是协议层薄转发，最终落到聚合根的 HandlePlayerDataRequest / HandleResyncRequest。​
  • 引导协议 CSUpdateNoviceGuid / CSUpdateIsGuidEvent 在这里就近处理：actorData:Update("noviceGuid"/"isGuidEvent", value) 后回 SC。​
5.3 聚合根 ServerPlayerData（ServerPlayerData.lua）​
模板里"一名玩家所有持久化数据"的唯一入口，构造时绑定 openId，并显式持有五个域：​
​
ServerActorData / ServerBagData / ServerRankingData / ServerSocialData / ServerAchievementData​
​
默认架构是 4 个基础域（actor / bag / ranking / social）。第 5 个 ServerAchievementData 是模板预置的简易 demo——给创作者参考"接入新业务域"的示范，不是模板的真业务。新加任何业务域都按它的样子改，详见 DSTemplate快速上手业务系统接入指南：成就系统.md。​
聚合根对外暴露的动作：​
  • HandlePlayerDataRequest(player, packet)：未加载完则挂 _pendingPlayerDataAfterLoad，加载完后由 LoadIntoCache 的回调自动补发。​
  • HandleResyncRequest(player, packet)：未加载完则把请求体挂 _pendingResyncRequestData，加载完补发。​
  • LoadIntoCache()：把 4 次回调（bag / ranking / actor+social / achievement）聚齐才算加载完成。​
  • Flush(forceFlushAll)：force=true 或 IsDirty()==true 才真写；写成功后清脏。​
  • ClearPending()：玩家离线时清挂起标记。​
SendResyncToPlayer 内按 resyncDomains = { "actor", "bag", "ranking", "social", "achievement" } 列表逐域比对 clientVersion < serverVersion 或 missingDomains[domain] == true，只发增量 + 版本 + changedDomains 清单。​
5.4 数据子域（Server/Data/Server*Data.lua）​
每个子域构造时绑定 openId，统一对外暴露（继承自 ServerDataBase.lua）：​
​
:Get(key?) 查：nil 返回整表，有 key 返回 snapshot[key]​
:Create(key, value) / :Add(key, value) 增：写键值并标脏（Add 为 Create 别名）​
:Update(key, value) 改：与 Create 等价（覆盖写）​
:Remove(key) 删：移除键并标脏（实例析构走 BaseClass 的 obj:Delete()，本类不重写）​
:SetCache(snapshot, markDirty) 写整表快照 + 脏标；markDirty=false 用于云端 Load 回写​
:Load(callback) 从 DataStore 拉取 → NormalizeValue → SetCache(_, false) → MarkLoaded​
:Save(forceFlushAll, callback?) force=true 或 IsDirty() 才真写；写成功后清脏​
:IsLoaded() / :MarkLoaded() 首次 Load 完成标记​
:IsDirty() 是否有未持久化的变更​
:GetDefaultValue() / :NormalizeValue(raw) 默认值与入参规整（子类按需重写）​
​
ServerDataBase:__init(playerOpenId, domainKey, scopePrefix, dataKey) 四参数已不再传 storeName；DataStore 命名空间在基类内固定为 STORE_NAMESPACE = "sim_game"，子类不要再传第 5 个参数。​
业务写数约定（Logic / Manager）：经 ServerPlayerDataManager.Get(openId).xxxData 调用上表 Get / Create / Update / Remove 改键并标脏；不要 Get() 整表手改后再 SetCache（易漏脏标或与版本号不同步）。SetCache(snapshot, markDirty) 仅用于框架 Load 回写（markDirty=false）或确需整表替换（markDirty=true）；业务 Logic 不要直接调 ServerDataCache.SetCacheData。查内存统一用 Get(key?)（已无历史 :Read）。​
ServerActorData 的 Load 还会带出一份内嵌的 socialData，由聚合根接力传给 ServerSocialData:Load(embedded, cb)——这是"actor + social 同源一条记录"的历史写法，新业务域不需要这么干，按 ServerAchievementData 的样子独立 KV 即可。​
5.5 缓存与平台出口（ServerDataCache.lua / ServerDataStoreManager.lua）​
  • ServerDataCache 维护 playerDatas[openId][domain] 的内存快照与脏标 dirty<key>，并按白名单 versionedDomains 维护 domainVersions。​
  • versionedDomains = { actor=true, bag=true, ranking=true, social=true, achievement=true }：SetCacheData 在 markDirty != false 时才递增对应域版本号；接入的新域如果想参与"按版本算增量"的重同步，必须把域 key 加进 versionedDomains，否则 GetDomainVersionMap 不会导出它的版本号。​
  • ServerDataStoreManager 是平台 KV 的薄封装，提供 GetData / SetData，所有写都是 JSON 字符串。​

文件清单（参见 Logic/index.lua）：​
​
ServerRankingManager 排行域聚合写入 + 推送​
ServerLevelManager 关卡解锁​
ServerGameEventManager 活动事件抽奖​
ServerShopManager 商店购买 / 装备​
ServerLotteryManager 抽奖​
ServerSocialManager 分享奖励​
ServerSettleManager 局内金币结算​
ServerPlayerManager 在线表 + Tick + 引导协议​
ServerAchievementManager 成就 demo（创作者参考用，不是真业务）​
ServerGMManager GM：加货币 / 加奖杯 / 清存档​
GameStateMachine/* 服务端状态机​
ServerGameLogicManager Tick + 进局 / 属性重算​
​
具体字段与分支以各 .lua 为准；上表用于快速定位「改哪种玩法找哪个文件」。各 Manager 写玩家持久化数据时，经聚合根取对应 Server*Data，用 Get / Update（或 Create / Remove） 改域内字段，落盘仍由 ServerPlayerData:Flush 统一调度。​
5.7 服务端状态机（Server/Logic/GameStateMachine/）​
按状态切换驱动 ServerGameLogicManager 的进局/计时/结算节奏，状态文件：ServerStateLobby / ServerStateInMatchIdle / ServerStateInMatchStart + ServerGameStateManager。这部分对 UGC 创作者一般是"读"，不需要改。​
​
六、客户端​
6.1 入口与生命周期​
客户端不像服务端有单脚本入口；改为"按系统挂宿主脚本"，每个系统目录下放一份 *Register.lua，宿主用它的 Awake / Update / OnDestroy / OnPlayerJoined / OnPlayerLeft / OnActorSpawned 跑生命周期。​
握手由 ClientEventNetwork.Init() 完成（ClientEventNetwork.lua）：​
  • 绑定 serverToClientRemote.onClientEvent → ClientEventNetwork.OnS2CEventHandle​
  • 内部调 ClientPacketRegister.RegisterAllHandlers() 把所有 S2C handler 一次注册到 NetPacketManager​
  • s2cListenerBound 与 handlersRegistered 都做了去重，多个 Register 在 Awake 里都调一次是安全的​
PlayerSystemRegister.Awake 是关键起点——它在 OnPlayerJoined / OnActorSpawned 之前就先 ClientEventNetwork.Init() 把 handler 注册好，否则首包 SC 可能丢。​
6.2 客户端协议层（Client/Network/）​
  • ClientPacketRegister.lua：声明所有 S2C 协议的 handler 落点（"协议名 → 调哪个 System 的哪个方法"）；GM 协议（SCGMAddCurrency / SCGMAddTrophy / SCGMClearSave）就地直接覆写 ClientPlayerData 的 bagData / actorData，没有专门的 GM System。​
  • ClientEventNetwork.lua：OnS2CEventHandle 收包 → NetPacketManager.Handle(协议名, packet)；同时提供 FireServer 给上层发 C2S。​
  • NetPacketManager（位于 Common，双端共用）做 Pack / Unpack 与 handler 派发。​
6.3 PlayerSystem 与首包/重同步流水线（PlayerSystem.lua）​
模板里最复杂的一个系统，关注三件事：​
  • 首包流水线：SendPlayerDataRequest 发 CSRequestPlayerData → OnSCRequestPlayerData 收到全量快照后，用 ClientPlayerData.New("local", payload) 构造聚合根、IOCContainer:RegisterModel("ClientPlayerData", ...) 入库，再启动 Main / Currency / Trophy UI 与大厅 Buff（TryApplyLobbyBuff）。流水线状态机通过 playerDataPipelineState = { completed, requested, knownVersions, pendingResyncPayload } 驱动，去重靠 requested / completed 两个标志。​
  • 重同步流水线：PlayerDataOnReconnect 时基于 knownVersions / missingDomains 主动发 CSResyncPlayerData；本地 4 域（actor / bag / ranking / social / achievement）若有未加载，把 SC 包挂 pendingResyncPayload，等条件齐了再 apply。​
  • 被动推送：SCPlayerAttrsPush、SCRankSync 等增量推送直接打到现有聚合根的对应域上；SCRankSync 还做了一次"过亿才上报平台 + 去重"的逻辑（MaybeUploadRankToPlatform）。​
聚合根、子域、PlayerSystem 三者的边界与新增域的修改点，详见 DSTemplate快速上手业务系统接入指南：成就系统.md。​
6.4 客户端数据层（Client/Model/）​
  • ClientDataBase.lua：纯内存基类，提供 _data / _sortData / _modelName / IsLoaded / MarkLoaded / Get(key, default) / GetData / Count / EmitEvent，最关键的写入接口是 ReplaceRootDataFromServer(rootTable)——服务端首包/重同步直接整表覆写。​
  • 各域：ClientActorData / ClientBagData / ClientRankingData / ClientSocialData / ClientAchievementData；具体业务方法各域自己加（如 ClientActorData:GetEquipAircraftPK()、ClientAchievementData:IsAlreadyUnlocked(id)）。​
  • ClientPlayerData.lua：聚合根，构造时接收单一 payload 表（{ actorData, bagData, socialData, rankingData, achievementData }），只持有/销毁子域，不做调度也不暴露透传 getter，业务方直接读 agg.xxxData 即可。​
客户端域不持久化：所有写都应经 C2S 协议 → 服务端 Save → SC 回包后再覆写本地缓存，避免本地状态与服务端发散。​

每个系统目录下一般有 *System.lua（业务类）+ *SystemRegister.lua（host 脚本，由框架自动挂载，不要在 index.lua 中 require）。​
6.6 表现层 View（Client/View/）​
View 只做"渲染 + 用户输入采集 + 转给对应 System"，不要在 View 里读写 Model，避免数据回包到达和 UI 刷新出现竞态。​
6.7 IOC 容器（IOCContainer.lua）​
  • 系统：IOCContainer:Register / RegisterSystem / RemoveSystem / GetSystem，对应全局便利函数 GetSys(name) / TryGetSys(name)。​
  • Model：IOCContainer:RegisterModel / RemoveModel / GetModel，对应全局便利函数 GetMol(name)。​
  • RegisterModel 会自动调用模型上的 Init()（如果有），RemoveModel 会自动调用 Release()（如果有）。​
业务层永远走 GetSys("XxxSystem") / GetMol("ClientPlayerData")，不要直接持有实例引用。​
​
七、双端共用约定​
  • OOP：所有 Lua 类用 BaseClass:DefineClass("ClassName") 创建；构造方法名固定 __init、析构 __delete。​
  • 全局表：_G["ClassName"] = ClassName 是显式约定（双端共用 _G 解析，类加载先后由 index.lua 控制）。​
  • require 顺序：Common → Server/Client 业务子目录，每层都有 index.lua 把内部文件按依赖排好。host 脚本（带 Awake/Start/Update/OnDestroy/OnActor*/OnTrigger*/OnInteractor* 等裸生命周期函数）由框架自动挂载，禁止在 index.lua 中 require。​
  • 日志标签：服务端用 ServerUtils.Log("[DS_TRACE][...]") 系列标签，便于在控制台串数据链路（首包/重同步/Flush/玩家进离房一目了然）。​
  • assert 与防御代码：服务端权威路径优先用 assert 暴露契约违反；客户端展示路径优先用读默认值的"软兜底"。​

十、扩展指南：如何接入一条新业务​
模板把"接入新业务"拆成两件事，两件都做完才算闭环：​
    新增一条业务域（与 actor / bag / ranking / social 并列）​
    修改点固定：​
  • ServerPlayerData.__init 构造新域实例​
  • AreAllDomainsLoaded 加新域 IsLoaded 判断​
  • SendPlayerDataToPlayer 首屏全量 payload 加新域 key​
  • SendResyncToPlayer 顶部 resyncDomains 加新域名 + 函数体 if-elseif 加新域分支​
  • LoadIntoCache 加一次 Load 调用并把 pendingAsyncCount 同步 +1​
  • Flush 加一次 Save​
  • ServerDataCache.versionedDomains 加新域 key（新域要参与版本化重同步必须加）​
  • 新增 Server<Name>Data.lua 与 Client<Name>Data.lua​
  • ClientPlayerData.__init / __delete 加新域​
  • PlayerSystem 4 处：首包构造 / 重同步派发 / 缺域探测 / IOC 清理​
    新增一个业务 System + 一对协议​
  • 服务端写 Server<Name>Manager.lua，客户端写 <Name>System/<Name>System.lua + <Name>SystemRegister.lua​
  • 协议名进 NetPacketType.RegisterExtensions、Pack/Unpack 放进 Common/NetworkPacket/NetPacket/、Common/NetworkPacket/index.lua 加 require​
  • 双端落点：ServerPacketRegister.RegisterAll 注册 C2S handler；ClientPacketRegister.RegisterAllHandlers 注册 S2C handler（薄转发到 System）​
  • Server/Data/index.lua / Server/Logic/index.lua / Client/index.lua / Client/System/index.lua 加 require​
模板里 AchievementSystem 就是这件事的样板 demo，从 ServerAchievementData 到 AchievementSystem 完整覆盖了上面所有改动点 + 协议 + Pack/Unpack + Register。它不是模板的真业务，只是一个"按下 1 解锁随机成就 / 按下 0 打印已解锁列表"的最小可运行示范，链路是完整的，可以照着抄。​
具体到一条任务级别的步骤、要改哪些行、加什么字段，见DSTemplate快速上手业务系统接入指南：成就系统​

术语​
含义​
域 / domain​

聚合根​
ServerPlayerData / ClientPlayerData，按 openId 持有该玩家所有域​
首包​
CSRequestPlayerData / SCRequestPlayerData，客户端进房第一次拿到全量快照​
重同步​
CSResyncPlayerData / SCResyncPlayerData，断重连或补域时按版本号增量补发​
标脏​
ServerDataCache 的 dirty<key> 标志，标识本域内存快照与 KV 不一致，等待 Flush 落盘​
域版本号​
ServerDataCache.domainVersions[domain]，仅 versionedDomains 白名单内的域维护，重同步比对用​
host 脚本​
带 Awake/Update/OnDestroy/OnActor*/OnPlayerJoined 等裸生命周期函数的 *Register.lua，由框架自动挂载，禁止 require​
GetSys / GetMol​
IOC 全局便利函数，分别取 System / Model 实例​
