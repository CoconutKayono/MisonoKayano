00先把“算法”想简单一点

算法就是：给定一些信息，按照明确的步骤，算出一个结果。

想象你在做一个“守卫追玩家”的小游戏。守卫需要知道玩家在哪、离自己多远、该不该追、怎么绕过墙、每帧向哪边走。这些问题各自对应一小段算法。你不必先学完高等数学，才能让游戏动起来。

C# 片段 · 最小的读码练习
放入现有脚本；留意下方说明
float speed = 3f;           // 小数：每秒移动 3 个单位，f 表示 float
Vector3 direction = Vector3.right; // 三维箭头：向世界右侧
bool canMove = true;        // 布尔值：是 / 否

起步 / CHAPTER 01

01循环、容器与复杂度

当敌人从 10 个变成 10,000 个，你的算法还能跑得动吗？

寻找最近的敌人，最直观的方法是从头到尾比较一遍。敌人数量翻倍，比较次数也大约翻倍，这叫 O(n)。如果让每个敌人都与每个其他敌人比较，工作量会接近平方增长，叫 O(n²)。

工具 / 思路适合什么常见代价
数组 / List按顺序遍历敌人、通过索引取元素索引 O(1)，查找 O(n)；List 中间移除通常 O(n)
Dictionary / HashSet按 ID 查对象、判断是否访问过查找平均 O(1)，不是绝对保证
Queue 队列先来的先处理，BFS 用它入队 / 出队摊销 O(1)
Stack 栈后来的先处理，回溯 / 对象复用入栈 / 出栈摊销 O(1)
最小堆持续取出代价最低的候选项入堆 / 出堆 O(log n)

只想找最近的敌人，不必先把所有敌人排序

C# 片段 · 一次遍历找最近目标
放入现有脚本；留意下方说明
// 放在 MonoBehaviour 类中。需要 using UnityEngine;
Transform FindNearest(Transform[] enemies)
{
    Transform best = null;
    float bestSqr = float.PositiveInfinity;
    foreach (Transform enemy in enemies)
    {
        if (enemy == null) continue; // 跳过已销毁或未赋值的对象
        float d2 = (enemy.position - transform.position).sqrMagnitude;
        if (d2 < bestSqr)
        {
            bestSqr = d2;
            best = enemy;
        }
    }
    return best; // 数组里没有有效目标时返回 null
}

这里比较“距离的平方”，能得到相同的远近顺序，而且省去平方根。假设距离非负，3 < 5 与 9 < 25 的结论一致。完整排序通常是 O(n log n)，只取最近一个时没有必要。

二分查找：每次排除一半

有序数列：2, 5, 9, 14, 20, 31, 42
→
找 20，先看中间的 14
→
只看右半边，再逐次缩小

二分查找要求数据已经按同一规则排序。搜索是 O(log n)，但为了每次查一次就重新排序，可能比直接遍历更贵。后面的“掉落表前缀和”可以复用这个思路。

想一想：100 个单位两两检查，每对只查一次，需要几次？

100 × 99 ÷ 2 = 4,950 次。避免自己与自己比较，并且避免把 A-B 与 B-A 重复检查。

本章记住：先选合适的数据结构，再讨论微小优化；O 记号描述增长趋势，不直接代表毫秒。

02向量、距离与归一化

位置告诉你“在哪里”，向量告诉你“往哪走、走多远”。

玩家在 A=(1,1)，目标在 B=(4,3)。从 A 指向 B 的箭头是 B−A=(3,2)，意思是横向走 3、纵向走 2。它的长度为 √(3²+2²)=√13≈3.61。

归一化就是把箭头缩放到长度 1，保留方向。之后再乘速度，你就能独立控制“去哪边”和“走多快”。

C# 片段 · 从方向变成位移
放入现有脚本；留意下方说明
Vector3 delta = target.position - transform.position;
Vector3 direction = delta.normalized;
float distance = delta.magnitude;
// 概念演示：朝目标方向走，不负责避免越过目标。
transform.position += direction * speed * Time.deltaTime;
// 需要可靠停在终点时，使用下一章的 MoveTowards。

一个常见问题：为什么斜着走更快？

右移输入 (1,0) 的长度是 1，同时右移和前进得到 (1,1)，长度是 √2≈1.414。如果直接乘速度，斜向就快了约 41%。对输入使用 Vector3.ClampMagnitude(input, 1f) 可以限制最大长度，同时保留摇杆的轻推力度；无条件归一化会丢掉轻推的大小。

容易踩的坑

零向量没有方向。Unity 的 normalized 对过小向量返回零；手写除以长度时要先判断长度是否接近 0。不要混用世界坐标 position 与相对父对象的 localPosition。

想一想：目标就在当前位置，delta 是多少？

是 (0,0,0)。这时应该停止移动，也不要把零向量交给 LookRotation 作为朝向。

03每帧移动与 deltaTime

速度的单位是“每秒多少距离”，不是“每帧多少距离”。

如果每帧移动 0.1 个单位，30 FPS 时每秒移动 3 个单位，120 FPS 时每秒移动 12 个单位。同一款游戏在不同电脑上会像开了不同倍速。

本帧位移 = 速度 × 本帧经过的秒数
Δp = v × Δt；3 单位/秒 × 1/60 秒 = 0.05 单位
Update 每帧调用
→
读取 Time.deltaTime
→
计算小步位移
→
写回位置

Update 适合一般逻辑；FixedUpdate 按固定时间步处理物理相关更新，一帧可能调用 0 次或多次；LateUpdate 常用于在角色更新之后跟随的摄像机。固定步长不是“保证每帧都执行一次”。

完整脚本 · ChaseTarget.cs
按标题文件名保存
using UnityEngine;

public class ChaseTarget : MonoBehaviour
{
    public Transform target; // 把另一个对象拖到这里
    [Min(0f)] public float speed = 3f;

    void Update()
    {
        if (target == null) return;
        transform.position = Vector3.MoveTowards(
            transform.position, target.position,
            Mathf.Max(0f, speed) * Time.deltaTime);
    }
}
  1. 新建一个 Cube 和一个 Sphere，拉开它们的距离。
  2. 创建 ChaseTarget.cs，粘贴完整代码，挂到 Cube 上。
  3. 把 Sphere 拖进 Cube 脚本组件的 Target 字段，点击 Play。
  4. 在 Scene 窗口移动 Sphere，观察 Cube 追过去并停住。
容易踩的坑

这段脚本直接控制 Transform，适合无物理约束的演示。需要动态刚体碰撞时，用 Rigidbody 的物理移动或力，别让 Transform 与物理系统争夺同一物体。乘 deltaTime 也不自动解决高速穿墙或不稳定数值积分。

04插值、缓动与平滑跟随

都叫“平滑移动”，但你想控制的可能是速度、时长，或跟随手感。

插值是在两个值之间取一个中间值。Lerp(a,b,t)=a+(b−a)×t。从 0 到 10，t=0.3 就得到 3。这里的 t 是比例，不是速度；Unity 的 Lerp 会把它限制到 0～1。

需求推荐思路你设置什么
恒定速度追目标MoveTowards每秒的速度
固定 2 秒播完Lerp(固定起点, 终点, elapsed / duration)总时长
开头与结尾都柔和先对 t 做 Smoothstep缓动曲线
持续追随的柔顺感指数平滑 / SmoothDamp响应强度 / 平滑时间
C# 片段 · 固定时长与指数跟随
放入现有脚本；留意下方说明
// 方案 A：字段 start、end 是固定的 Vector3；duration > 0。
// 开始新移动时，只记录一次 start，并把 elapsed 设为 0。
elapsed += Time.deltaTime;
float t = Mathf.Clamp01(elapsed / duration);
float eased = t * t * (3f - 2f * t); // Smoothstep，先慢后快再慢
transform.position = Vector3.Lerp(start, end, eased);

// 方案 B：独立使用，不要和方案 A 同时写同一个位置。
// k > 0，单位约为 1/秒；静止目标下误差按 exp(-k*t) 衰减。
float alpha = 1f - Mathf.Exp(-k * Time.deltaTime);
transform.position = Vector3.Lerp(transform.position, target.position, alpha);

每帧用当前坐标当 Lerp 的起点，会反复取“剩余距离的一部分”，于是越接近越慢。它不等于固定时长动画。指数公式在目标固定、k 固定时，可使不同帧率下的时间响应一致；目标帧间变化时仍受采样影响。

完整脚本 · SmoothFollow.cs
按标题文件名保存
using UnityEngine;

public class SmoothFollow : MonoBehaviour
{
    public Transform target;
    public Vector3 offset = new Vector3(0f, 4f, -6f);
    [Min(0.01f)] public float smoothTime = 0.3f;
    private Vector3 velocity; // 必须跨帧保存，不要每帧清零

    void LateUpdate()
    {
        if (target == null || Time.deltaTime <= 0f) return;
        transform.position = Vector3.SmoothDamp(
            transform.position, target.position + offset,
            ref velocity, Mathf.Max(0.01f, smoothTime));
    }
}

将此脚本挂到 Camera，把角色拖进 Target。它只跟随位置，摄像机朝向请在编辑器里设置。ref velocity 表示函数会更新这份速度状态，下一帧继续使用；smoothTime 不是严格的到达截止时间。瞬移后可清零 velocity，避免沿用旧的跟随速度。

05点积、视野与转向

敌人不仅要知道你离它多远，还要知道你是不是在它面前。

两个单位向量的点积等于夹角的余弦。完全同向是 1，垂直是 0，反向是 −1。你可以把它当成“两个方向有多一致”的数值。

dot = ax × bx + ay × by + az × bz
归一化以后：dot = cos(夹角)
C# 片段 · 前方、距离与遮挡分别检查
放入现有脚本；留意下方说明
// 片段放在方法中。eye 是观察点 Transform，target 是目标 Transform。
Vector3 toTarget = target.position - eye.position;
float distance = toTarget.magnitude;
bool inRange = distance > 0.001f && distance <= viewRange;
float threshold = Mathf.Cos(viewAngle * 0.5f * Mathf.Deg2Rad);
bool inCone = inRange &&
    Vector3.Dot(eye.forward, toTarget / distance) >= threshold;
// obstacleMask 仅包含墙等遮挡层，不包括观察者和目标自身。
bool blocked = inCone && Physics.Raycast(
    eye.position, toTarget.normalized, distance,
    obstacleMask, QueryTriggerInteraction.Ignore);
bool visible = inCone && !blocked;

转身：先求想要的朝向，再逐步转过去

Quaternion 是 Unity 保存旋转的方式。入门时先把它当成一种“朝向值”，不必手算四个分量。让模型沿本地 +Z 为正前方，使用 LookRotation 生成目标朝向，RotateTowards 控制每秒最多转多少度。

C# 片段 · 平面转向；放在 Update 中
放入现有脚本；留意下方说明
Vector3 direction = target.position - transform.position;
direction.y = 0f; // 只在 XZ 地面上转身
if (direction.sqrMagnitude > 0.000001f)
{
    Quaternion desired = Quaternion.LookRotation(direction, Vector3.up);
    transform.rotation = Quaternion.RotateTowards(
        transform.rotation, desired, turnSpeed * Time.deltaTime);
}

叉积会产生同时垂直于两个输入向量的方向，可用于求平面法线、侧向方向。Unity 中 Vector3.Cross(Vector3.up, Vector3.forward) 得到 right；交换输入顺序会反向。想判断目标在左右哪边，也可以用 Vector3.SignedAngle，并明确旋转轴。

容易踩的坑

总视角 90° 对应的阈值是 cos(45°)，不是 cos(90°)。Mathf.Cos 用弧度，所以要乘 Deg2Rad。三维锥形视野与忽略高度的水平扇形视野是两种模型，代码与游戏设计要一致。

06抛物线与数值积分

弓箭向前飞，同时不断被重力向下拉。

先忽略空气阻力，并假设重力不变。水平方向保持速度，竖直方向的速度不断减小。这两个运动叠加，就得到抛物线。不要先被符号吓到：p 是位置，v 是速度，g 是重力加速度，t 是经过的秒数。

p(t) = p₀ + v₀t + ½gt²
二维展开：x = x₀ + vx·t；y = y₀ + vy·t − ½·9.81·t²

初速度大小为 speed，角度为 θ 时：vx=speed×cosθ，vy=speed×sinθ。落回同一高度的飞行时间是 2vy/9.81，水平射程为 vx×飞行时间。45° 最大射程只成立于无阻力、相同发射和落点高度等条件下。

C# 片段 · 解析轨迹与半隐式欧拉；两种方案择一
放入现有脚本；留意下方说明
// 方案 A：已记录 origin、initialVelocity，经过时间 elapsed。
// 适合预览落点；不自动处理碰撞。
Vector3 p = origin + initialVelocity * elapsed
          + 0.5f * Physics.gravity * elapsed * elapsed;

// 方案 B：每个固定步更新，velocity 是跨帧保存的字段。
// 放在 FixedUpdate 中；这是手写积分演示，不要同时启用刚体重力。
float dt = Time.fixedDeltaTime;
velocity += Physics.gravity * dt;
position += velocity * dt;

数值积分就是把连续变化拆成很多小步。先更新速度再更新位置称为半隐式欧拉法；它与直接算公式会有误差，时间步越大通常误差越明显。遇到碰撞、摩擦和弹跳等复杂情况，优先交给 Rigidbody 及物理系统处理。

容易踩的坑

高速子弹可能一帧从墙前跳到墙后，两个端点都没重叠。可以检查上一位置到新位置的线段，带半径的弹体用 SphereCast 等扫掠检测；物理刚体也可考虑合适的连续碰撞检测模式。

想一想：重力是每帧都把位置减去 9.81 吗？

不是。9.81 是每秒速度改变多少的加速度。先乘时间步改变速度，再根据速度与时间改变位置；或者直接代入带 t² 的解析公式。

基础 / CHAPTER 07

07贝塞尔曲线：用控制点塑造路线

金币飞向 UI、摄像机绕场、技能轨迹，都可以先画一条曲线。

两点 Lerp 给你直线。再加一个“拉弯路线”的控制点 P1，就能得到二次贝塞尔曲线：先在 P0→P1 和 P1→P2 上各取一个相同比例的点，再在这两个点之间插值一次。这叫 de Casteljau 思路。

B(t) = (1−t)²P0 + 2(1−t)tP1 + t²P2
C# 片段 · 二次贝塞尔位置计算；类内方法
放入现有脚本；留意下方说明
Vector3 QuadraticBezier(Vector3 p0, Vector3 p1, Vector3 p2, float t)
{
    t = Mathf.Clamp01(t);
    Vector3 a = Vector3.Lerp(p0, p1, t);
    Vector3 b = Vector3.Lerp(p1, p2, t);
    return Vector3.Lerp(a, b, t);
}

四个控制点会得到三次贝塞尔曲线，可以分别控制出发与到达时的切线方向。Catmull–Rom 样条则适合需要穿过给定路点的路线；贝塞尔的中间控制点通常不在曲线上。

容易踩的坑

t 匀速增长不代表沿曲线移动的实际速度恒定。如果要求匀速，先采样曲线并累计相邻点的距离，得到“距离→t”查找表；运行时按路程查找 t（可二分），再算位置。

想一想：t=0.5，物体一定走过了一半路程吗？

不一定。它只走过一半参数范围；弯曲程度和控制点分布会影响实际路程。

实践 / CHAPTER 08

08碰撞检测：先问“重叠了吗”

碰撞检测判断是否相交；碰撞响应才决定弹开、停止，还是扣血。

最简单的二维碰撞模型是两个圆：只要圆心距离不大于半径之和，就相交。三维中把圆换成球，公式完全一样。我们通常比较平方距离，省去开根号。

重叠条件：|B−A|² ≤ (rA+rB)²
C# 片段 · 球与 AABB；类内方法
放入现有脚本；留意下方说明
bool SpheresOverlap(Vector3 a, float ra, Vector3 b, float rb)
{
    float sum = ra + rb; // 调用者应保证半径非负
    return (b - a).sqrMagnitude <= sum * sum;
}

bool BoxesOverlap(Bounds a, Bounds b)
{
    return a.min.x <= b.max.x && a.max.x >= b.min.x
        && a.min.y <= b.max.y && a.max.y >= b.min.y
        && a.min.z <= b.max.z && a.max.z >= b.min.z;
}

AABB：各条轴上的区间都重叠，就相交

AABB 是“与坐标轴对齐的包围盒”。想象把两个盒子的影子分别投到 x、y、z 轴上：只要有任意一条轴的区间分开，盒子就没有相交。物体旋转后，其世界 AABB 会变大，可能出现包围盒重叠但模型没有接触的情况。

粗检测：AABB / 网格筛选
→
精检测：形状是否相交
→
响应：停止 / 弹开 / 触发效果

更进一步，SAT 分离轴定理用“是否存在一条投影不重叠的轴”判断凸形状分离。二维凸多边形可检查各边法线；三维凸多面体还要考虑两物体边方向的叉积等候选轴。入门先会用碰撞体，不必立即手写通用物理引擎。

容易踩的坑

Raycast 是一条无厚度射线，不能代表整个角色的体积。3D 用 Physics，2D 用 Physics2D；对应的碰撞体与刚体系统也要一致。Overlap 查询只是找重叠对象，不会自动推开它们。

09有限状态机：让敌人有条理地做决定

先问“我现在在做什么”，再问“满足什么条件才切换”。

一个守卫可以有巡逻、追击、攻击三种状态。每一时刻只处于其中一种，状态里执行对应行为，转换条件负责切换。这样比在一大段 Update 里塞几十个互相打架的 if 更容易理解。

为什么进入和离开的距离不一样？

如果在 6 内追击、6 外巡逻，玩家站在边界抖动时，状态会频繁切换。使用不同的进入与离开阈值叫滞回，它给状态留了一点稳定空间。演示里的 6～8 区间并不唯一决定状态：要看守卫之前在巡逻还是追击。

enum State { Patrol, Chase, Attack }
State state = State.Patrol;
public Transform target;

void Update()
{
    if (target == null) { state = State.Patrol; return; }
    float d = Vector3.Distance(transform.position, target.position);
    switch (state)
    {
        case State.Patrol:
            if (d <= 6f) state = State.Chase;
            break;
        case State.Chase:
            if (d >= 8f) state = State.Patrol;
            else if (d <= 1.5f) state = State.Attack;
            break;
        case State.Attack:
            if (d >= 8f) state = State.Patrol;
            else if (d > 2f) state = State.Chase;
            break;
    }
    // 转移完成后，再按 state 执行巡逻、移动或冷却攻击。

}

行为树与效用 AI：什么时候升级？

行为树把决策拆成树形任务。Selector 依次尝试候选分支，遇到成功或运行中就停；Sequence 依次执行步骤，遇到失败或运行中就停。任务通常返回成功、失败、运行中三种结果。效用 AI则给行为打分，例如饥饿越高，“吃东西”的得分越高，最后选择高分行为。状态很少先用 FSM，复杂的组合行为再考虑这些方法。

想一想：为什么把距离从 10 一次拖到 1，会进入攻击？

实验会继续求解已满足的状态转移，等价于若干次逻辑更新。骨架代码每次 Update 只走一次转移，所以通常先追击，再在下一次 Update 进入攻击。

10转向行为：追逐、减速与群体移动

寻路给你一条路线，转向行为决定眼前这一小步怎么走。

最简单的 Seek（趋近）会生成“朝目标的期望速度”。当前速度与期望速度的差，是需要修正的部分。如果立刻把速度替换为期望速度，转弯会很硬；限制每秒速度的改变量，就得到更柔和的加速与转向。

目标位置 − 当前位置
→
归一化 × 期望速度
→
与当前速度比较
→
限制加速度，更新速度与位置
C# 片段 · Arrive：靠近目标时减速
放入现有脚本；留意下方说明
// velocity 是 Vector3 字段；speed、acceleration >= 0，slowRadius > 0。
// 在 Update 中执行。stopRadius 是一个很小的到达容差。
Vector3 offset = target.position - transform.position;
float d = offset.magnitude;
if (d <= stopRadius)
{
    velocity = Vector3.zero;
}
else
{
    float desiredSpeed = speed * Mathf.Clamp01(d / slowRadius);
    Vector3 desired = offset.normalized * desiredSpeed;
    velocity = Vector3.MoveTowards(velocity, desired,
        acceleration * Time.deltaTime);
    transform.position += velocity * Time.deltaTime;
}

这个简单的 Arrive 模型适合入门；速度很大或减速半径太小时仍可能越过目标。可以参考刹车距离 v²/(2a) 提前减速，或在适合的场景做最终位置约束。

Boids：三条局部规则组成群体

01

分离 Separation

太近就远离邻居。贡献方向可取差向量除以距离平方，并处理零距离。

02

对齐 Alignment

参考附近同伴的平均速度，让运动方向逐渐一致。

03

聚合 Cohesion

朝邻居平均位置靠近，避免整个群体散开。

把三种修正乘权重后相加，再限制总加速度。分离权重高会更疏散，聚合权重高会更抱团。计算邻居时排除自己，最好基于这一帧的同一份状态快照计算所有单位，避免更新顺序造成偏差。

容易踩的坑

Boids 是局部群体行为，不保证绕出迷宫，也不保证绝对不相撞。它可与全局寻路结合。每只鸟遍历全部鸟是 O(n²)，第 16 章的空间网格可减少邻居候选。

寻路 / CHAPTER 11

11BFS：像水波一样找到最少步数

先把地图变成格子，再从起点一圈一圈向外探索。

地图里的可走格子叫节点，两格之间允许移动的关系叫边。本文先只允许上、下、左、右四方向移动，墙不能进入。每步成本相同时，BFS（广度优先搜索）能找到步数最少的路线。

起点入队并标记
→
队首取出一个格子
→
未访问的邻居入队
→
记录邻居从哪里来

Queue 是排队：先进先出。起点旁边的格子先被探索，再轮到它们的邻居。因此 BFS 按 0 步、1 步、2 步……向外推进。格子入队时就标记访问，否则多个邻居可能把同一个格子重复塞进队列。

找到终点以后，路线从哪来？

发现 B 时，记 parent[B]=A
→
发现 C 时，记 parent[C]=B
→
终点 C → B → A
→
反转得到 A → B → C

parent 是“这个格子第一次由谁发现”的记录。回溯终点的 parent，直到起点，反转列表就得到路径。起点等于终点时，路径只有一个点；队列空了仍没到终点，说明没有路径。

BFS：时间 O(V+E)，空间 O(V)
V 是可访问节点数量，E 是边数量；四方向网格的 E 与 V 同阶。

适用：无权重迷宫、回合制移动范围、洪水填充、连通区域检测。不适用：当泥地走一步要 5 点体力、道路只要 1 点时，最少步数不一定最省体力。下一章解决这个问题。

想一想：DFS 深度优先搜索也能到终点，为什么不用它找最短路？

DFS 往一个方向走到深处再回退，首次找到终点的路线可能绕很远。它适合探索、回溯和某些迷宫生成，但一般不保证首次得到最短路径。

本章记住：BFS 用队列，按层推进；最短路保证依赖每条边成本相同。

寻路 / CHAPTER 12

12Dijkstra：找到总代价最低的路线

最短的路，未必是走起来最便宜的路。

现在把普通格子的进入成本设为 1，泥地设为 5。BFS 只数格子数量；Dijkstra 会记住到达每个格子目前已知的最低代价 g，并优先展开 g 最小的候选格。

候选代价 = g(当前格) + 进入邻居的成本
若候选代价更低：更新 g(邻居)，并把 parent(邻居) 改为当前格。

这个“发现更便宜的路线就更新”的步骤叫松弛。例如第一次走到某格花费 10，后来找到另一条只花 7 的路线，就把记录改成 7。不能简单把“第一次发现”当成“最优路线”。

候选 A：g=4
→
候选 B：g=7
→
先展开 A
→
更新受影响的邻居

要不断取出最小 g，常用最小堆实现优先队列。使用合适的二叉堆实现时，典型复杂度是 O((V+E) log V)，搜索记录空间 O(V)；允许重复堆条目的实现可能使用更多空间。

容易踩的坑

Dijkstra 要求边权非负。目标刚被发现时不一定已经最优；当它作为最低代价候选被取出时，才可以结束。堆里如果保留了旧条目，要跳过已经过期的代价记录。

想一想：只有普通地面时，Dijkstra 与 BFS 的路径一定逐格相同吗？

都能找到相同步数的最短路线，但存在多条同价路线时，邻居顺序和并列项处理可能让路线形状不同。

寻路 / CHAPTER 13

13A*：在最优搜索里加入方向感

已经走了多远，加上估计还要走多远。

Dijkstra 会向四周扩张；A* 再增加一个“离终点还有多远”的估计 h，让搜索更有方向感。它优先展开 f=g+h 最小的候选格。这个估计函数叫启发式。

四方向网格：h = (|x−目标x| + |y−目标y|) × 最小单步成本
这叫曼哈顿距离：忽略墙壁，横着与竖着至少要走多少步。

像估计开车还有几分钟：可以低估，不能为了“聪明”而乱高估。可采纳启发式不高估真实剩余成本；使用不重新打开已关闭节点的图搜索实现时，还需要一致性等条件。本文每格成本至少为 1，四方向曼哈顿距离满足这些条件。

这样玩，最容易看出差别

  1. 先保留默认地图，选择 BFS，点击“直接看结果”。它会取中间那条少步数但经过泥地的路线。
  2. 改选 Dijkstra，再看结果：它愿意绕一点路，避开昂贵的泥地。
  3. 改选 A*，观察最低成本与展开格数。它保证的是这里条件下的最优成本，不是保证每张地图都比 Dijkstra 快。
  4. 用墙把终点围住，检查“无路可达”；点“还原地图”恢复。

“待探索”是已经发现、但还没处理完的候选格；“已展开”是已经检查过邻居的格子。A* 的动态说明会显示当前格的 g、h、f。路线形状可能受并列 f 的处理顺序影响。

完整脚本 · GridPathfinding.cs · 可复用的 A* 核心
按标题文件名保存
using System.Collections.Generic;
using UnityEngine;

// 普通 C# 工具类，不挂到 GameObject。cost[x,y] >= 1 表示可走，<= 0 为墙。
// 仅四方向移动；起点不计费。返回路径包含起点与终点；无路返回 null。
public static class GridPathfinding
{
    static readonly Vector2Int[] Dirs = {
        Vector2Int.right, Vector2Int.up, Vector2Int.left, Vector2Int.down
    };

    static int H(Vector2Int a, Vector2Int b)
    {
        return Mathf.Abs(a.x - b.x) + Mathf.Abs(a.y - b.y);
    }

    static bool Valid(int[,] cost, Vector2Int p)
    {
        return p.x >= 0 && p.y >= 0 && p.x < cost.GetLength(0)
            && p.y < cost.GetLength(1) && cost[p.x, p.y] >= 1;
    }

    public static List<Vector2Int> Find(int[,] cost, Vector2Int start,
                                       Vector2Int goal)
    {
        if (cost == null || !Valid(cost, start) || !Valid(cost, goal))
            return null;
        var open = new List<Vector2Int> { start };
        var closed = new HashSet<Vector2Int>();
        var parent = new Dictionary<Vector2Int, Vector2Int>();
        var g = new Dictionary<Vector2Int, float> { [start] = 0f };

        while (open.Count > 0)
        {
            // 为了容易读，直接扫描最低 f。大地图建议换成最小堆。
            int best = 0;
            for (int i = 1; i < open.Count; i++)
                if (g[open[i]] + H(open[i], goal) <
                    g[open[best]] + H(open[best], goal)) best = i;
            Vector2Int current = open[best];
            open.RemoveAt(best);

            if (current == goal)
            {
                var path = new List<Vector2Int> { current };
                while (parent.TryGetValue(current, out Vector2Int previous))
                {
                    current = previous;
                    path.Add(current);
                }
                path.Reverse();
                return path;
            }
            closed.Add(current);
            foreach (Vector2Int dir in Dirs)
            {
                Vector2Int next = current + dir;
                if (!Valid(cost, next) || closed.Contains(next)) continue;
                float candidate = g[current] + cost[next.x, next.y];
                if (!g.TryGetValue(next, out float old) || candidate < old)
                {
                    parent[next] = current;
                    g[next] = candidate;
                    if (!open.Contains(next)) open.Add(next);
                }
            }
        }
        return null;
    }
}

例如 int[,] map = {{1,1,1},{1,0,1},{1,1,1}};，再调用 GridPathfinding.Find(map, new Vector2Int(0,0), new Vector2Int(2,2))。把路径节点映射成世界坐标 (x*cellSize, groundY, y*cellSize)，随后用 MoveTowards 逐个走过。小心数组第二维在这里代表地面的 z。

为了便于逐行读懂，以上代码与网页加权搜索演示用 List 扫描候选，最坏可达 O(V²+E)；不要把它的效率与最小堆版本混为一谈。大地图可换优先队列、分帧搜索，或做分层寻路。

Unity 自带导航怎么选？

普通 3D 地面导航可以使用 AI Navigation 包：构建 NavMesh，给角色配置 NavMeshAgent，设置目标点。格子战棋、特殊移动规则则更适合自定义图。NavMesh 是可走区域的多边形表示；A* 是搜索策略，这两个概念不是同一个层次。

14加权随机与洗牌

“随机”不一定是等概率，也不代表短期结果必定平均。

掉落表里普通、稀有、传说的权重为 60、30、10。把它们接成一条总长 100 的线：取一个 0～99 的随机整数，落在哪段就选择哪种掉落。概率等于“该项权重 ÷ 总权重”。

C# 片段 · 整数权重选择与 Fisher–Yates 洗牌
放入现有脚本；留意下方说明
// 类内方法。需要 using System; using System.Collections.Generic;
int WeightedPick(int[] weights)
{
    if (weights == null) throw new ArgumentNullException(nameof(weights));
    int total = 0;
    foreach (int w in weights)
    {
        if (w < 0) throw new ArgumentException("权重不能为负");
        total = checked(total + w); // 总和过大则报错，避免整数溢出
    }
    if (total == 0) throw new ArgumentException("至少一项权重必须大于0");
    int r = UnityEngine.Random.Range(0, total); // int 上界不包含
    for (int i = 0; i < weights.Length; i++)
    {
        if (r < weights[i]) return i;
        r -= weights[i];
    }
    throw new InvalidOperationException();
}

void Shuffle<T>(IList<T> list)
{
    for (int i = list.Count - 1; i > 0; i--)
    {
        int j = UnityEngine.Random.Range(0, i + 1); // j 可以等于 i
        T temp = list[i]; list[i] = list[j]; list[j] = temp;
    }
}

单次加权选择是 O(n)。固定掉落表需要频繁抽取时，可以预先计算前缀和，随机后用二分查找第一个大于 r 的前缀，单次变成 O(log n)。Fisher–Yates 则从尾到头，每次和尚未确定位置的任意元素交换；在随机索引均匀的前提下，得到均匀排列，时间 O(n)。

容易踩的坑

Unity Random.Range 的 int 版本不包含上界，float 版本包含上界，别混淆。传说概率 10% 不意味着每 10 次必出；“保底”需要额外记录连续未出的次数并明确定义规则。

API 核对：Random.Range ↗

想一想：把传说权重从 10 改到 20，概率是 20% 吗？

不是。新的总权重是 60+30+20=110，所以传说概率为 20/110≈18.18%。

15噪声与程序化地形

纯随机像锯齿；连续噪声像连绵的山丘。

如果每个地块独立随机高度，相邻格子就可能一个在山顶、一个在谷底。噪声函数让相邻采样点的数值有联系，因此变化更连贯。采样坐标乘以 frequency（频率），控制山丘的疏密；结果乘以 amplitude（振幅），控制高低。

C# 片段 · Unity 中的二维噪声采样
放入现有脚本；留意下方说明
// 放在方法中；x、z 为采样坐标，frequency > 0，amplitude >= 0。
// offsetX、offsetZ 是保存的采样偏移，改变它们可以得到不同地形区域。
float sample = Mathf.PerlinNoise(
    (x + offsetX) * frequency,
    (z + offsetZ) * frequency);
float height = Mathf.Clamp01(sample) * amplitude;
// 可将 height 写入网格顶点的 y；或换算为 Terrain 需要的归一化高度。

多层噪声：大山上再叠小山

叠加多层（octave）噪声：第一层频率低、振幅大，决定整体山形；后面频率逐渐升高、振幅逐渐减小，添加细节。例如频率每层乘 2，振幅每层乘 0.5。把加权总和除以振幅总和，可以保持相近的数值范围。这类构造常称为 fBm。

生成洞穴与地牢的其他常见算法

  • 细胞自动机：先随机填墙，然后根据周围 8 格的墙数更新自己。每轮读旧网格、写新网格；最后用 BFS 检查连通性，避免生成孤岛。
  • BSP 分割：把矩形区域递归切成子区域，在叶子区域放房间，再用走廊连接，适合规则地牢。
  • Poisson Disk 采样：放置点时保持最小间距，适合树木、石头和刷怪点；通常配合网格加速邻居检查。
容易踩的坑

固定种子还需要固定随机数算法、调用顺序与参数，才便于复现。Mathf.PerlinNoise 本身没有 seed 参数，可保存采样偏移；不要每帧给整个游戏重新 InitState。需要跨版本严格一致时，应保存生成结果或控制完整算法。

API 核对：Mathf.PerlinNoise；范围可能略超出 0～1，必要时 Clamp ↗

16空间网格：只检查附近的对象

先把世界装进小格子，再去相关格子里找邻居。

假设有 1,000 个敌人，每个敌人都遍历全部敌人查邻居，大约要做百万级检查。很多对象其实离得很远，根本不值得比较。均匀网格把世界划分成小区域，字典记录“格子坐标→这个格子里的对象”。

cellX = floor(worldX / cellSize)
cellZ = floor(worldZ / cellSize)

查询半径为 r 时，先找到覆盖查询圆的包围盒所跨越的格子：从 floor((x−r)/cellSize) 到 floor((x+r)/cellSize)，z 也同理。只遍历这些格子里的对象，最后再做精确平方距离检查。候选格子的边角可能在圆外，所以“同格或附近格”不等于“在半径内”。

C# 片段 · 把位置映射成网格键
放入现有脚本；留意下方说明
// 需要 using System.Collections.Generic; using UnityEngine;
// 这些字段与方法放在类内，cellSize 必须 > 0。
float cellSize = 2f;
Dictionary<Vector2Int, List<Transform>> cells =
    new Dictionary<Vector2Int, List<Transform>>();

Vector2Int CellOf(Vector3 p)
{
    return new Vector2Int(Mathf.FloorToInt(p.x / cellSize),
                          Mathf.FloorToInt(p.z / cellSize));
}

静态物体可建立一次索引。移动物体跨格时，需要从旧格移除、加入新格；也可以按逻辑帧重新填充网格，但要复用列表，控制垃圾分配。二维空间可用四叉树，三维可用八叉树；这些结构在对象分布不均匀时更有弹性，但维护也更复杂。

容易踩的坑

负坐标要用 floor 向下取整。例如 −0.1 / 2 应属于 −1 格，直接转 int 会变成 0。网格只能减少候选数量，最坏所有对象挤在一格时仍可能退化；格子太小或太大都有额外代价。

想一想：查询半径超过格子边长时，只看周围 3×3 格够吗？

不一定。必须按实际半径计算跨越的格子范围，否则会漏掉仍在查询半径内的对象。

17对象池：让子弹循环上岗

对象池是复用对象的管理模式，解决反复创建与销毁的问题。

想象餐厅的盘子：用完洗干净，放回架子，下次再拿。每次射击都创建子弹、命中就销毁，会带来对象生命周期和分配成本。对象池保留不用的对象，下一次优先取出复用。

完整脚本 · SimpleBulletPool.cs
按标题文件名保存
using System.Collections.Generic;
using UnityEngine;

// 挂到一个空 GameObject 上；Prefab 应是专用、初始非激活的子弹预制体。
public class SimpleBulletPool : MonoBehaviour
{
    public GameObject prefab;
    [Min(0)] public int prewarm = 8;
    readonly Stack<GameObject> idle = new Stack<GameObject>();
    readonly HashSet<GameObject> active = new HashSet<GameObject>();

    void Awake()
    {
        if (prefab == null) { enabled = false; return; }
        for (int i = 0; i < prewarm; i++) idle.Push(Create());
    }

    GameObject Create()
    {
        GameObject obj = Instantiate(prefab, transform);
        obj.SetActive(false);
        return obj;
    }

    public GameObject Rent(Vector3 position, Quaternion rotation)
    {
        if (prefab == null) return null;
        GameObject obj = idle.Count > 0 ? idle.Pop() : Create();
        obj.transform.SetPositionAndRotation(position, rotation);
        active.Add(obj);
        // 在激活前重置该子弹的速度、伤害来源、寿命等自定义状态。
        obj.SetActive(true);
        return obj;
    }

    public void Return(GameObject obj)
    {
        // 防止重复回收或把不属于本池的对象放进池里。
        if (obj == null || !active.Remove(obj)) return;
        obj.SetActive(false);
        idle.Push(obj);
    }
}

这是最小管理骨架，不包含发射、碰撞与自动回收：你的发射逻辑调用 Rent，子弹命中或超时后调用所属池的 Return。池拥有这些对象，使用期间不要另外 Destroy 它们；池的父对象应保持固定且无意外缩放。

实际使用时先补齐状态重置：刚体速度、粒子、拖尾、计时器、事件订阅和协程都可能留下上次使用的状态。需要有容量上限的池时，要明确耗尽后扩容、拒绝，还是复用最旧对象。上面的 C# 骨架会按需扩容，与网页实验的 10 个教学上限不同。

Unity 也提供 UnityEngine.Pool.ObjectPool<T>，可以通过获取、归还和销毁回调管理生命周期。池化不会让子弹飞行与碰撞计算消失，它主要减少反复创建、销毁的成本。

想一想：只把子弹 SetActive(false) 就等于回池了吗？

不一定。还需要把对象放回池的空闲集合、从活跃集合移除，并保证下一次取出时状态被重置。

18冷却、调度与帧预算

游戏中很多“算法问题”，其实是“什么时候执行、执行多少次”。

技能每 0.5 秒发动一次，不应该用“30 帧一次”实现。记录下次允许执行的时刻，或累计经过的时间，才能避免帧率改变冷却速度。还要明确：卡顿后是补齐漏掉的次数，还是只触发一次？这是游戏规则的一部分。

C# 片段 · 两种不同的冷却语义
放入现有脚本；留意下方说明
// 方案 A：放在输入被触发的分支中。冷却内的按键不排队。
// nextAllowed 是 float 字段，初值 0；cooldown > 0。
if (Time.time >= nextAllowed)
{
    CastSkill(); // 你实现的技能方法
    nextAllowed = Time.time + cooldown;
}

// 方案 B：放在 Update 中。自动持续触发，允许补帧但限制单帧工作。
// accumulator 为 float 字段；interval > 0；Spawn 为自定义方法。
accumulator += Time.deltaTime;
int workThisFrame = 0;
while (accumulator >= interval && workThisFrame < 4)
{
    accumulator -= interval;
    Spawn();
    workThisFrame++;
}
// 这里保留剩余欠账，后续帧继续消化；长期过载时需要丢弃或限流策略。

菜单和真实时间倒计时可用 Time.unscaledDeltaTime 或相应未缩放时钟；受游戏暂停和慢动作影响的技能通常用缩放时间。对联网权威计时，还需要服务器时间与同步策略，不能依赖客户端本地冷却保证规则。

分帧处理：把大任务切成小块

第1帧：更新敌人 0～24
→
第2帧：更新敌人 25～49
→
第3帧：更新敌人 50～74

远处敌人可能不需要每帧重新寻路，可以每 0.2 秒评估一次，且错开不同敌人的开始时间。把一次大搜索保存成可继续的状态，每帧只展开一部分节点，就能控制峰值；代价是结果稍晚出现。

容易踩的坑

协程不自动在后台线程运行，重计算仍可能卡住主线程。先用 Unity Profiler 找真正耗时点，再决定降低频率、减少分配、改算法或使用 Jobs/Burst；不要仅凭感觉优化。

19把算法拼成一个小型守卫游戏

让“感知 → 决策 → 寻路 → 移动 → 攻击”各司其职。

现在回到最开始的守卫。你已经不需要一个巨大而神秘的“AI 算法”，而是把能解释清楚的小模块连接起来。建议按下面顺序做，每一步能独立观察效果，再进入下一步。

感知：距离、点积、射线
→
决策：FSM
→
计划：A* / NavMesh
→
执行：移动、转向、冷却
  1. 先让它移动。摆好 Cube 守卫与 Sphere 玩家，用第 03 章的 ChaseTarget 追踪。验收：更改速度能改变追逐速度，到达后不来回越过目标。
  2. 让它只在附近追。接上第 09 章的状态转移，只有 Chase 状态才移动。验收：距离在 6～8 之间时，状态不因轻微抖动反复跳转。
  3. 让它真的“看见”。用点积、距离和遮挡射线计算 visible，代替单纯距离条件。验收：玩家在背后或墙后时不被直接发现；如需记忆，保存最后可见位置与时间。
  4. 让它绕墙。选择网格 A* 或 NavMesh。A* 返回路径后，保存路点下标并逐个移动；到达阈值内切换下一个节点。验收：有路能绕行、无路能停下，目标变化后可以重新规划。
  5. 让攻击有节奏。Attack 状态下停止追逐，用计时器约束攻击频率；从池里租子弹，命中或超时后归还。验收：暂停/恢复符合设计，不重复扣血，不重复回池。
  6. 最后才增加数量。从 1 个守卫加到 100 个，用 Profiler 检查感知、寻路、物理和分配；按瓶颈引入空间网格、降低决策频率或分帧搜索。
同一个位置，只交给一个模块写

如果你同时用 ChaseTarget、NavMeshAgent、Rigidbody 和自写路径移动修改守卫位置，它们可能互相覆盖。组合时由状态机决定意图，由一个运动模块统一执行，替换旧移动脚本而不是全部叠加。

排查问题时，先把中间结果画出来

用 Debug.DrawLine 或 Gizmos 画视线、方向、路径和检测半径；在 Inspector 或屏幕上显示状态、当前路点、下一次攻击时间。不要只看最终“没追上”，要能看到是哪一个环节没有满足条件。
