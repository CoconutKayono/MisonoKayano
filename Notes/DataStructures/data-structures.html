00 / 先建立直觉

数据结构，就是组织数据的方法

同样是 1,000 本书，随手堆在地上、按编号摆上书架、按主题分柜，找书的方式和速度会完全不同。

计算机也会遇到这个问题。姓名、分数、聊天记录、地图地点都是数据；怎样摆放它们、怎样表示它们之间的关系，就是数据结构。在这种组织方式上执行的操作步骤，叫作算法。

数据

书本上的信息。
例如：书名 = 小王子。

数据结构

书怎么组织。
例如：按编号连续摆放。

算法

具体怎么做。
例如：从左到右逐本查找。

所有结构，都在回答四类问题

访问：取第几个？查找：它在哪里？插入：新数据放哪？删除：拿走后怎么办？

“取第 3 个数”和“找到数字 3”是两件事：前者已经知道位置，后者只知道内容。许多速度差异就来自这里。

没有全能的最好结构，只有更适合某种操作的结构。

经常按位置读取？经常在中间修改？总要取最小值？先明确你要做什么，再选择怎么存。

关系长什么样代表结构日常比喻
一条线数组、链表、栈、队列座位、寻宝线索、盘子、排队

这里按直觉分组，不是互斥的严格分类。栈、队列首先描述操作规则，底层可以由数组或链表实现。

01 / 一把比较效率的尺子

复杂度，看数据变多以后会怎样

用 n 表示数据数量。我们通常关心：n 变大时，操作所需的工作量怎样增长？大 O 记号描述增长的上界，入门时可以先把它看成“工作量的增长级别”。它不是精确秒数，也不天然表示最坏情况；需要同时说明是在讨论平均、最坏还是均摊。

写法直觉常见例子
O(1)数据再多，也只做固定几步数组按下标读取
O(log n)每一步把问题规模缩小一大截有序数组的二分查找
O(n)可能看完全部数据逐个查找一个值
O(n log n)约 log n 层，每层处理 n 份工作归并排序
O(n²)两层遍历，数据翻倍，工作量约四倍检查所有有序元素对

改变 n，感受增长差距

动手 01

条形使用同一线性比例，数值为示意公式的计算结果，不是实际运行时间；此处 log 取底数 2。短条保留最小可见宽度，请以右侧数值为准。

空间复杂度

关注额外需要多少存储空间。复制 n 个数通常需要 O(n) 额外空间；只用几个临时变量通常是 O(1)。递归调用本身也会占用调用栈空间。

均摊是什么意思？

动态数组偶尔扩容，要搬走全部元素，单次是 O(n)；采用合理的成倍扩容策略时，把成本分摊到一长串末尾追加操作，每次平均承担 O(1)。这叫均摊，不是随机输入的“平均情况”。

复杂度不是全部。 小规模数据下，常数开销、内存布局、实现方式也很重要。先理解增长趋势，不必为几个小数据过度优化。
02 / ARRAY

数组：一排有编号的格子

像电影院座位。知道座位号，就能直接定位。

经典数组把同类元素放在连续的存储位置上。每个位置有一个编号，叫下标（index），通常从 0 开始。长度为 5 的数组，下标是 0、1、2、3、4。

访问很快，插入需要腾位置

动手 02

试着读取下标 2，再在下标 2 插入 99，观察后面元素的编号。

为什么能直接定位？因为地址可以算出来：首地址 + 下标 × 每格大小。不必从头检查前面的格子。实际语言可能存放对象的引用，但按下标访问仍然可以很快。

  • 按下标访问：O(1)。
  • 在未排序数组中按值查找：最坏 O(n)。
  • 在中间插入或删除并保持顺序：后面元素要移动，最坏 O(n)。
  • 动态数组末尾追加：通常均摊 O(1)，扩容那一次可能是 O(n)。
用在哪里：学生成绩列表、像素数据、需要频繁按位置读取的序列。固定长度数组不能随意变长；演示展示的是可以增减元素的动态数组。
进一步：为什么有序数组可以二分查找？

像猜 1～100 之间的数：每次看中间位置，根据目标更大还是更小，舍弃一半候选。前提是数据已按同一规则排序，并且能快速访问中间位置。先排序也有成本，不能忽略。

03 / LINKED LIST

链表：每个节点，留下下一站的地址

像寻宝游戏。第一张纸条告诉你第二张在哪里，第二张再指向第三张。

链表由一个个节点（node）组成。每个节点保存数据，以及指向下一个节点的引用或指针。节点不必在内存里挨在一起。head 指向第一个节点，null 表示后面没有节点了。

在已知节点后插入，只需改连接

动手 03

为什么查找慢？

知道“第 8 个节点”还不够，因为它的地址算不出来。要从头顺着连接走过去，所以按位置访问和按值查找通常是 O(n)。

为什么修改连接快？

如果已经拿到前驱节点，插入或移除它后面的一个节点只需改少量引用，是 O(1)。如果先要找到位置，总成本通常仍是 O(n)。

变体连接方式带来的变化
单向链表只记住 next只能向后走；删除通常需要前驱
双向链表记住 prev 和 next能前后走；已知节点时更方便删除，但多占空间
循环链表尾节点重新指回头节点适合循环访问；遍历必须设置停止条件
别背成“链表插入永远比数组快”。 寻找位置也要时间，指针也占空间。数组的连续布局通常更利于 CPU 批量读取。

用在哪里：频繁移动已知节点的场景。例如 LRU 缓存常把哈希表与双向链表组合：哈希表定位节点，链表维护最近使用顺序。

04 / STACK

栈：后来放上去的，先拿走

想象一摞盘子。放盘子和拿盘子，都从最上面进行。

这种规则叫后进先出（LIFO，Last In, First Out）。允许操作的一端叫栈顶。放入叫 push（入栈），取出叫 pop（出栈），只看最上面叫 peek。

亲手叠起一摞数据

动手 04

10 → 20 → 30 依次入栈，所以现在先取出的是 30。

撤销操作为什么适合用栈？

输入「你」→输入「好」→加粗→撤销：先取消加粗

最近发生的动作最先撤销，正好符合栈的规则。浏览器返回、括号匹配、函数调用和递归也都能用栈来理解。完整的撤销/重做系统常使用两个栈。

栈 = 空
push(10)     // [10]，右边是栈顶
push(20)     // [10, 20]
pop()        // 返回 20，栈变成 [10]
peek()       // 返回 10，栈仍是 [10]

效率：链表实现的入栈、出栈、看栈顶可为 O(1)；动态数组实现的入栈通常为均摊 O(1)。栈不提供任意中间位置的直接访问操作。

两个“栈”有关联，但别混为一谈。 这里讲的是数据结构；程序的“调用栈”是利用这种后进先出规则管理函数调用的机制。空栈继续出栈需要处理，不能凭空取出元素。
05 / QUEUE

队列：先排进来的，先被处理

像在便利店结账。新顾客排到队尾，队头顾客先离开。

这种规则叫先进先出（FIFO，First In, First Out）。从队尾放入叫 enqueue（入队），从队头取出叫 dequeue（出队）。

怎样做到出队 O(1)？

如果每取走数组的第一个元素，就把后面所有元素往前挪，会花 O(n)。更合适的实现是带头尾指针的链表，或循环数组：移动队头编号，让已经空出来的格子之后再次被利用。

E格 0 · 队尾元素空格 1C格 2 · 队头D格 3

逻辑顺序是 C → D → E。走到格 3 后，绕回格 0；空/满可用计数等方式区分。

双端队列 deque

两头都能插入和删除。适合需要灵活操作两端的任务，例如滑动窗口算法。它也可以只使用其中一部分操作来充当栈或普通队列。

优先队列 priority queue

按“优先级”取出元素，不保证先来先走。例如总先处理最紧急任务。它描述的是操作规则，常用后面要学的堆实现。

用在哪里：打印任务、请求缓冲、按层搜索。正确实现的普通队列入队和出队可以达到 O(1)；动态扩容实现可能涉及均摊成本。

06 / HASH TABLE

哈希表：从一个名字，算出存放位置

把“编号找座位”升级为“给出姓名，就能查到对应资料”。

哈希表存储键值对（key → value）。例如 "小林" → "138…"，姓名是键，电话号码是值。哈希函数把键转换成一个数，再映射到存放位置，通常称作桶（bucket）。

键 key→哈希函数 hash(key)→桶编号→核对键，取得 value

两个键，也可能算出同一个桶

动手 06

为了看清原理，这里只接受小写英文字母：把字母编码相加，再对 5 取余。这是教学用的简单函数，不适合实际系统。

ab 与 ba 都映射到桶 0，但它们是不同的键。点击查找，观察桶内仍需核对键。

同一个桶，不代表同一个键

不同的键映射到同一位置叫哈希冲突。不能直接覆盖旧数据！一种解决方法是在桶里放一个列表，逐个核对真正的键，称为链地址法。另一种是继续寻找其他空槽位，称为开放寻址。

  • 查找、插入、删除：哈希分布良好且负载受控时，通常平均或期望 O(1)；大量冲突时，某些实现最坏可退化为 O(n)。
  • 负载因子：元素数量 ÷ 桶数量。太拥挤时需要扩容、重新分配数据；一次重建可能需要 O(n)。
  • 键相同：通常更新这个键的值。键不同但哈希相同，仍需分别保存。
Map 与 Set：Map（映射/字典）存“键 → 值”；Set（集合）只关心“某个元素在不在”，且不重复。它们是抽象功能，可以由哈希表实现，也可以由有序树实现。哈希表本身不保证按键排序。

用在哪里：词频统计、查用户资料、去重、缓存、判断某个 ID 是否存在。遍历 n 项仍然需要 O(n)，不会因为查找快就变成一步完成。

07 / TREE

树：让关系长出层次

从一个入口，沿分支向下。文件夹、组织结构、网页元素都常呈现树形关系。

在一棵有根树里，最上面的节点叫根；下一层是它的孩子；反过来叫父节点；没有孩子的节点叫叶子。除了根之外，每个节点恰好有一个父节点，不会绕圈回到自身。

根：8　/　8 的孩子：3、10　/　叶子：1、6、14

二叉树 ≠ 二叉搜索树

二叉树只要求每个节点最多有两个孩子，区分左、右。二叉搜索树（BST）还要求：对每个节点，左子树所有值都更小，右子树所有值都更大。这里假设键不重复；允许重复时，需要另外约定规则。

寻找 6：先与根 8 比较。每次沿左或右分支继续，不必遍历另一侧。

当前比较已走过 / 已找到

查找、插入、删除的成本取决于树高 h，一般为 O(h)。如果结构保持平衡，高度约为 log n；如果依次插入 1、2、3、4 而不做平衡，可能长成一条链，高度变成 n。

“树查找都是 O(log n)”不对。 普通树没有排序规则，查找可能要遍历全部节点；普通 BST 也可能退化。AVL 树、红黑树等通过维护平衡，保证搜索、插入、删除为 O(log n)。

遍历：按照某个顺序，把每个节点看一遍

对上方这棵树，下列规则会得到不同顺序。“序”指根节点在左、右子树之前、中间还是之后被访问；规则在每棵子树中重复使用。

方法规则本例结果
前序根 → 左 → 右8, 3, 1, 6, 10, 14
中序左 → 根 → 右1, 3, 6, 8, 10, 14

只有满足搜索树规则，中序遍历才会得到有序结果；普通二叉树不保证这一点。

08 / BINARY HEAP

堆：让最该被取出的元素站到最上面

不必把所有任务完整排序，只要随时知道下一项最优先处理谁。

这里讲二叉堆。它是一棵完全二叉树：除了最后一层，其他层都填满；最后一层从左往右连续填。它还满足一种局部大小关系：

最小堆

每个父节点 ≤ 它的孩子。
因此，根节点一定是全局最小值。

最大堆

每个父节点 ≥ 它的孩子。
因此，根节点一定是全局最大值。

最小堆：看一次“上浮”和“下沉”

动手 08 · 分步演示

同一棵堆的数组表示（按层、从左到右）：

当前最小值是根节点 3。试着插入 2，看它如何与父节点比较、交换。

  1. 插入：先加到最后一个位置，保持完全二叉树形状；如果比父节点小，就交换，继续上浮。
  2. 取出最小值：移走根，把最后一个元素补到根；与较小的孩子比较，必要时交换，继续下沉。

完全二叉树的高度是 O(log n)，因此只沿一条路径调整，就能恢复规则。看最小值 O(1)，插入和取出最小值 O(log n)（通常不计底层数组偶发扩容成本）。

堆不是已经排好序的数组，也不是二叉搜索树。

堆只约束父节点与孩子，不约束左右兄弟谁更小。最小值易取，但寻找任意一个值最坏仍是 O(n)。反复取出最小值，才会逐个得到递增序列。

为什么堆通常直接存进数组？

完全二叉树没有中间空位，可以按层存进数组。下标从 0 开始时，节点 i 的左孩子在 2i + 1，右孩子在 2i + 2，父节点在 floor((i - 1) / 2)（仅 i > 0）。不需要为每个节点额外保存指针。

进阶：建堆与 Top K

逐个插入 n 个数建堆是 O(n log n) 上界；自底向上“下沉”的建堆方法可以做到 O(n)。要保留最大的 K 个数，可维护大小为 K 的最小堆：新数比堆顶大才替换堆顶，让堆顶充当入选门槛，整体通常为 O(n log K)（K ≥ 2）。

用在哪里：优先任务调度、Top K、合并多个有序序列。数据结构里的“堆”与程序内存管理中的“堆内存”是不同概念。

09 / GRAPH

图：关系不再只是“一层一层”

地铁站可以交汇，朋友之间可以互相认识。这样的关系会形成网络。

图由顶点（vertex）和边（edge）组成。边可以有方向，也可以无方向；还可以带上距离、费用等权重。树是图的一种特殊情况：从无向图角度看，它连通且没有环。

从 A 出发：广度优先 vs 深度优先

动手 09

这是无向、无权图。从 A 出发，邻居按字母顺序考虑；BFS 入队时标记，DFS 采用迭代栈、弹出时检查是否已访问，逆序压栈以优先访问字母较小的邻居。

BFS：先看附近，再向外扩

使用队列。先访问距离起点 1 条边的顶点，再访问 2 条边的顶点……在无权图，或所有边权相等时，能找到按边数计算的最短路径。

DFS：先沿一条路走到底

使用栈或递归。沿分支持续深入，走不通再返回，探索其他分支。适合遍历、探索连通关系，也是许多回溯方法的基础；不保证最短路径。

图可能绕圈，所以要记住“访问过谁”。 否则沿 A → B → D → C → A 就可能一直重复。如果图不连通，从 A 出发只会访问 A 所在的连通部分。

图在内存里怎么存？

邻接表

每个顶点列出它的邻居：

A: [B, C]
B: [A, D, E]
C: [A, D]

其余顶点同理。空间 O(V + E)，适合边较少的稀疏图。

邻接矩阵

做一张 V × V 的表。第 i 行、第 j 列记录 i 到 j 有没有边，或记录权重。

空间 O(V²)，可 O(1) 判断两点是否直接相连；适合顶点不多或图比较稠密的情况。

这里 V 是顶点数，E 是边数。用邻接表遍历图时，BFS 和 DFS 的时间通常是 O(V + E)；用邻接矩阵遍历通常是 O(V²)。

用在哪里：道路导航、社交关系、课程先修关系、任务依赖。带权最短路径需要选择合适算法，例如非负权图可使用 Dijkstra；普通 BFS 不能直接处理不同代价的边。

10 / 扩展视野

还有几位，各有擅长

掌握前面的结构后，再看这些会容易很多。第一次阅读，记住它们解决什么问题即可。

字典树 Trie：共享单词前缀

把字符串按字符拆开，共同的开头走同一条路。例如 cat 和 car 共用 c → a，最后才分叉。

适合前缀匹配、自动补全。若每层能 O(1) 查找字符分支，查一个长度为 L 的词需要 O(L)。它可能用较多空间；自动补全列出所有结果还要计入输出成本。

根 ├─ c ─ a ─┬─ r ● car │ └─ t ● cat └─ d ─ o ─── g ● dog ● 表示一个完整单词结束

并查集：这些元素，属于同一组吗？

{ A, B }{ C, D }→ 合并 →{ A, B, C, D }

连接 B 和 C 后，两组变成一组。再次问 A 与 D 是否同组，答案就是“是”。

find 找到元素所属组的代表，union 合并两组。配合路径压缩与按秩/大小合并时，操作均摊为 O(α(n))，实际中非常接近常数。常用于动态连通性、最小生成树；它不负责告诉你两点之间的具体路线，也不擅长一般的拆组操作。

区间查询结构：一次问一段，而不是一个

24173

查询下标 1～3 的和：4 + 1 + 7 = 12

数据不变时，可以先计算前缀和，用两个前缀之差 O(1) 回答区间和；但数据频繁变化时，维护前缀和可能较慢。树状数组（Fenwick Tree）常以 O(log n) 支持单点增加、前缀求和；线段树把区间递归分段，可用 O(log n) 完成常见的单点更新与区间查询，代价是实现和空间更复杂。

B 树 / B+ 树：一层放更多键，减少外部存储访问

当数据多到需要放在磁盘或按页面管理时，一次访问往往比一次内存比较更昂贵。B 树家族采用多路、平衡的结构，降低树高。B+ 树的叶子通常相互连接，方便范围扫描，因此经常出现在数据库与文件系统索引中。具体布局和用途依实现而定。

学习顺序建议：先熟悉数组、链表、栈、队列 → 理解哈希、树、堆 → 会用 BFS / DFS → 再按需求学习这些进阶结构。
