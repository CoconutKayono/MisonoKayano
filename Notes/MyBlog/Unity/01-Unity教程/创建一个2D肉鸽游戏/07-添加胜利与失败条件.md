## 概要（Summary）

游戏目前拥有以下要素：

- 一个可以在当前棋盘上移动的玩家。
- 一个每回合递减的食物计数器，以及棋盘上可以补充该计数器的对象。
- 可以阻止玩家随意移动、也可以被摧毁的墙壁。

如果你回顾一下教程开始时制作的任务清单，就会发现：开始为关卡添加结局并生成新关卡所需的一切，你都已经具备了！

完成一个关卡，是由到达某个标记为出口的单元格触发的，而你可以使用 CellObject 来检测玩家是否进入了某一类单元格！

到本教程结束时，你将完成以下内容：

- 添加一个出口单元格：玩家角色一碰到它，当前关卡就结束。
- 编写功能，让旧关卡结束时生成一个新关卡。
- 当玩家的食物耗尽时，添加一个 Game Over（游戏结束）状态。
- 使用 UI Builder 窗口，在玩家失败时向游戏添加一个 Game Over 标签。

## 1. 概述（Overview）

现在，你的游戏有了更复杂的要素，比如回合系统、食物系统和障碍物。是时候把它们整合到一起了。在本教程中，你将添加胜利与失败条件，让你的游戏成为真正的游戏！

## 2. 完成关卡（Finishing a level）

让我们先编写一种新的 CellObject——ExitCellObject。它会把瓦片设置为出口瓦片（这样玩家就知道出口在哪里），并在玩家角色进入该单元格时做出反应，生成一个新关卡。

为此，你需要做以下事情：

- 创建一个继承自 CellObject 的新子类 ExitCellObject。
- 创建一个新的出口瓦片（有一个出口标志精灵可以用）。
- 把出口瓦片作为公共引用提供给新的 ExitCellObject。
- 为这种新类型的 CellObject 创建一个预制体。
- 把该预制体作为新的公共引用提供给 BoardManager，这样它就能把对象添加到出口单元格中（使用右上角的空单元格作为出口位置）。

既然你已经知道了需要完成的要求，让我们从代码开始。你应该已经掌握了编写 ExitCellObject 子类所需的一切；你可以暂时让重写的 PlayerEntered 函数保持为空，或者用 Debug.Log 来检查它是否有效。这是我们最终得到的代码：

```csharp
using UnityEngine;
using UnityEngine.Tilemaps;

public class ExitCellObject : CellObject
{
   public Tile EndTile;

   public override void Init(Vector2Int coord)
   {
       base.Init(coord);
       GameManager.Instance.BoardManager.SetCellTile(coord, EndTile);
   }

   public override void PlayerEntered()
   {
       Debug.Log("Reached the exit cell");
   }
}
```

1. 向场景添加一个新的空游戏对象，将其重命名为 "ExitCell"，并把上面的脚本添加到它上面。

2. 在 Inspector 窗口中，把你想要用作出口的瓦片资源赋值给 EndTile 属性，然后创建这个 ExitCell 游戏对象的预制体，并将其从场景中删除。

3. 在 BoardManager 中添加一个对 ExitCell 预制体的引用，并在关卡创建阶段，在右上角（与玩家角色起始位置相对的一端）生成该游戏对象。

4. 在 Init 函数内部、生成棋盘的 for 循环之后，添加以下代码：

```csharp
public class BoardManager : MonoBehaviour
{

public ExitCellObject ExitCellPrefab;

...

public void Init()
{
   
   ...
   for (int y = 0; y < Height; ++y)
   {
        ...
   }   

   m_EmptyCellsList.Remove(new Vector2Int(1, 1));

   Vector2Int endCoord = new Vector2Int(Width - 2, Height - 2);
   AddObject(Instantiate(ExitCellPrefab), endCoord);
   m_EmptyCellsList.Remove(endCoord);
  
   GenerateWall();
   GenerateFood();
}
```

你需要记得把出口单元格从用于放置 CellObject 的空单元格列表中移除，因为你不想在出口单元格上生成食物或墙壁。

现在，当你进入 Play 模式时，出口瓦片应该会出现在右上角。

如果它没有出现，而且控制台中有错误，请检查你是否在场景中正确分配了 ExitCellObject 预制体和 BoardManager 的引用。

目前，当玩家到达出口单元格时，游戏只会在控制台打印一行，但你需要修改 GameManager 和 BoardManager，让游戏在这种情况下重新生成一个新关卡！

### 生成新关卡（Generating a new level）

欢迎你自己从头尝试编写代码！这里有一些提示，帮你列出需要做的事情：

- BoardManager 将需要一个清理当前关卡的新函数。这意味着要遍历每个单元格，从瓦片地图中移除它们的瓦片，删除其中保存的数据，并销毁它们的 CellObject。
  - 提示：如果你把 null 作为 SetTile 函数的参数，它会移除该单元格的瓦片，让它空出来。

- GameManager 将需要一个 NewLevel 函数，用来清理当前棋盘、创建新棋盘，并把玩家角色生成到新棋盘的起点。
  - 作为一个小彩蛋，你可以声明一个新的 int 成员 m_CurrentLevel，初始化为 1，每次创建新关卡时递增，用来统计玩家已经通过了多少关卡。

这是我们对这些问题的解决方案：

BoardManager

```csharp
public void Clean()
{
    //no board data, so exit early, nothing to clean
   if(m_BoardData == null)
       return;


   for (int y = 0; y < Height; ++y)
   {
       for (int x = 0; x < Width; ++x)
       {
           var cellData = m_BoardData[x, y];

           if (cellData.ContainedObject != null)
           {
               // 注意！要销毁的是整个 GameObject，而不仅仅是 cellData.ContainedObject
			   // 否则你销毁的只是 CellObject 组件本身，
			   // 而不是整个带精灵的游戏对象
               Destroy(cellData.ContainedObject.gameObject);
           }

           SetCellTile(new Vector2Int(x,y), null);
       }
   }
}
```

GameManager

```csharp
private int m_CurrentLevel = 1;
...
void Start()
{
   TurnManager = new TurnManager();
   TurnManager.OnTick += OnTurnHappen;
  
   NewLevel();
  
   m_FoodLabel = UIDoc.rootVisualElement.Q<Label>("FoodLabel");
   m_FoodLabel.text = "Food : " + m_FoodAmount;
}

public void NewLevel()
{
   BoardManager.Clean();
   BoardManager.Init();
   PlayerController.Spawn(BoardManager, new Vector2Int(1,1));

   m_CurrentLevel++;
}
```

注意：我们用 NewLevel 方法替换了 Start 中对 BoardManager.Init 和 PlayerController.Spawn 的调用，而 NewLevel 做的事情是一样的！

ExitCellObject

```csharp
public override void PlayerEntered()
{
   GameManager.Instance.NewLevel();
}
```

进入 Play 模式，观看玩家角色每次到达出口单元格时，被传送到游戏的新关卡中。

## 3. 游戏结束（Game over）

现在玩家可以穿越无数个关卡了。但如果他们耗尽了食物，什么都不会发生。

为了让你的游戏有一个结局，让我们为游戏添加一个 Game Over 状态。当食物计数降到 0 时，就会进入这个状态。之后，需要发生以下事情：

- UI 文本显示需要改为一条 Game Over 消息，显示玩家在食物耗尽之前生存了多少关。
- 游戏需要进入 Game Over 状态，禁用输入读取，这样用户就无法再移动玩家角色。
- 当按下某个按键时，整个游戏需要从第 1 关重新开始，形成游戏循环。

让我们从 UI 游戏结束消息开始，它由一个半透明的背景（让屏幕变暗）和中间一段显示已通过关卡数量的文本组成：

1. 在 Project 窗口的 UI 文件夹中，双击 uxml 文档 GameUI，打开 UI Builder 窗口。

2. 在 Library 窗口的 Containers 部分，将一个 VisualElement 点击拖入 Hierarchy 窗口，并重命名为 "GameOverPanel"。

    确保它放在 Hierarchy 窗口中 FoodLabel 之后（下方），因为对象是从上到下渲染的，所以放在 FoodLabel 之后，意味着它会渲染在 FoodLabel 之上。

3. 选中 GameOverPanel 元素，使用展开箭头（三角形）展开 Inspector 窗口中的 Position 部分，然后打开 Position Mode 下拉菜单，选择 Absolute，并将 Top、Right、Bottom 和 Left 偏移都设置为 0，确保它覆盖整个屏幕。

    你不希望 GameOverPanel 元素成为布局的一部分，你希望它覆盖在所有内容之上。

4. 使用展开箭头（三角形）展开 Background 部分，将颜色设置为黑色（000000），但 Alpha（A）值设为约 200。

    你可以随意调整这个值；查看 Game 视图预览一下画面会变多暗。

5. 在 Library 窗口的 Controls 部分，将一个 Label 点击拖到 Hierarchy 中，直接放在 GameOverPanel 元素之上，然后将这个 Label 元素重命名为 "GameOverMessage"。

    这会让 GameOverMessage 元素成为 GameOverPanel 元素的子元素。

    你的 Hierarchy 窗口应该看起来像下面的图片。如果不是这样，你可以通过在 Hierarchy 窗口中拖拽元素来重新排列，直到它与下面的示例一致。

6. 选中 GameOverMessage，使用展开箭头（三角形）展开 Attributes 部分，将 Text 属性设置为 "Game Over"。然后使用展开箭头（三角形）展开 Inlined Styles 部分，再展开 Text 部分，更改文本的 Font（字体）、Size（大小）和 Color（颜色），让它在深色背景上清晰可见。

    Game Over 文本属性只是一个占位符，帮你设计它的外观；真正的消息会在游戏结束事件发生时通过代码写入。

目前，GameOverMessage 位于 Viewport 窗口的左上角，因为默认布局是列式的，从左上角开始。但游戏结束文本应该更醒目，以提醒用户，所以让我们把它居中。

7. 选择 GameOverPanel 游戏对象，使用展开箭头（三角形）展开 Inspector 窗口中的 Inlined Styles 部分，然后展开 Align 部分。将 Align Items 属性设置为 center，将 Justify Content 属性设置为 space-around。

如果现在进入 Play 模式，GameOverPanel 游戏对象会从一开始就覆盖整个游戏画面。你需要让它在游戏开始时隐藏，只在游戏结束条件发生时显示。

为此，你需要在 GameManager 中添加两个新的私有成员变量：

- 一个 VisualElement 类型，用来存储对 GameOverPanel 元素的引用。
- 一个 Label 类型，用来存储对 GameOverMessage 元素的引用，以便在 GameOver 条件发生时更新它。

```csharp
private VisualElement m_GameOverPanel;
private Label m_GameOverMessage;
```

8. 在 GameManager 的 Start 函数中，你需要从 UI Document 的根 VisualElement 中获取 GameOverPanel VisualElement 和 GameOverMessage Label，并将面板的可见性设置为 Hidden（隐藏）：

```csharp
m_GameOverPanel = UIDoc.rootVisualElement.Q<VisualElement>("GameOverPanel");
m_GameOverMessage = m_GameOverPanel.Q<Label>("GameOverMessage");

m_GameOverPanel.style.visibility = Visibility.Hidden;
```

注意：我们在 GameOverPanel 上使用 Query（Q）函数来获取 GameOverMessage Label 元素，是因为我们知道它是面板的子元素；这样就不必在整个层级上运行查询。

9. 在 GameManager 的 ChangeFood 函数中，你需要测试食物数量是否小于或等于 0。如果是，就满足 Game Over 条件，这意味着你需要把 GameOverPanel 游戏对象的可见性设置为 Visible，并显示包含已通过关卡数量的消息。

```csharp
public void ChangeFood(int amount)
{
   m_FoodAmount += amount;
   m_FoodLabel.text = "Food : " + m_FoodAmount;

   if (m_FoodAmount <= 0)
   {
       m_GameOverPanel.style.visibility = Visibility.Visible;
      m_GameOverMessage.text = "Game Over!\n\nYou traveled through " + m_CurrentLevel + " levels";

   }
}
```

注意：如果你不熟悉 `\n`，它是一个表示换行的特殊字符。在这里，Game Over 之后我们先换一行，再换一行（留出一个空行），然后继续消息。

现在进入 Play 模式，让玩家角色在棋盘上四处移动，直到食物耗尽来测试它。

提示：你可以把食物数量的初始值改成一个更小的数字，比如 10，以加快测试过程。

你现已成功地为游戏实现了一个游戏结束场景！然而，如果你在 Game Over 画面期间继续按键，你会看到玩家角色仍然在 Game Over 面板后面移动，游戏也仍可以继续。你将在下一步修复这个问题。

### 游戏结束状态（Game Over state）

要让游戏在 Game Over 事件被触发后真正结束，你需要通知 PlayerController 进入 Game Over 状态并停止处理用户输入。在查看下面的解决方案之前，先想想你需要做什么来实现这个功能，并尝试提出你自己的解决方案。这里有一些关于 PlayerController需要做什么的提示：

- 在 PlayerController 中创建一个 bool 变量，存储玩家角色是否处于 Game Over 状态。
- 提前退出 Update 函数，以禁用输入处理。
- 让 GameManager 持有一个对 PlayerController 脚本的引用，这样它就可以轻松调用其上的函数。

以下是我们的解决方案：

PlayerController

```csharp
using UnityEngine;
using UnityEngine.InputSystem;

public class PlayerController : MonoBehaviour
{
private bool m_IsGameOver;

. . . 

public void GameOver()
{
   m_IsGameOver = true;
}

. . . 

private void Update()
{
   if (m_IsGameOver)
   {
       return;
   }
...
}
```

注意：请确保把 if(m_IsGameOver) 条件写在 Update 函数中所有与处理用户输入相关的其他代码之前，这样如果游戏处于游戏结束状态，检查输入的代码就不会运行。

GameManager

```csharp
public void ChangeFood(int amount)
{
     m_FoodAmount += amount;
     m_FoodLabel.text = "Food : " + m_FoodAmount;

     if (m_FoodAmount <= 0)
     {
         PlayerController.GameOver();
         m_GameOverPanel.style.visibility = Visibility.Visible;
         m_GameOverMessage.text = "Game Over!\n\nSurvived " + m_CurrentLevel + " days";
     }

}
```

这样一来，当 GameOver 条件发生时，玩家角色将停止响应用户输入！

最后，你需要添加这样一个功能：在游戏结束时按下 Enter 键，允许用户重新开始游戏。这需要对 GameManager 进行一些重构；看看你是否能自己把它做出来！

要添加这个功能，你需要做以下事情：

- 把 GameManager 的 Start 函数中负责初始化游戏的部分，移动到一个名为 StartNewGame 的新函数中。
  - 像获取 UI 元素引用、或创建 TurnManager 这样的新对象这类事情，只在游戏启动时做一次，而不是每次新游戏都做，可以留在 Start 函数中。

注意：别忘了在 Start 函数中也调用那个新函数，这样游戏启动时就会自动开始一个新游戏！

- PlayerController 需要只在游戏结束时检查是否按下了 Enter 键；如果按下了，就启动一个新游戏。

在你尝试让这个功能运转的过程中，可能会出现很多错误和小问题。例如，很多东西只在游戏启动时初始化，而这些需要在一个函数中显式初始化，才能让它们恢复到起始状态；你可能还会发现食物数量不对，或者无法移动玩家。

这是我们的解决方案：

GameManager

```csharp
void Start()
{
   TurnManager = new TurnManager();
   TurnManager.OnTick += OnTurnHappen;
  
   m_FoodLabel = UIDoc.rootVisualElement.Q<Label>("FoodLabel");
  
   m_GameOverPanel = UIDoc.rootVisualElement.Q<VisualElement>("GameOverPanel");
   m_GameOverMessage = m_GameOverPanel.Q<Label>("GameOverMessage");

   StartNewGame();
}

public void StartNewGame()
{
   m_GameOverPanel.style.visibility = Visibility.Hidden;
  
   m_CurrentLevel = 1;
   m_FoodAmount = 20;
   m_FoodLabel.text = "Food : " + m_FoodAmount;
  
  BoardManager.Clean();
   BoardManager.Init();
  
   PlayerController.Init();
   PlayerController.Spawn(BoardManager, new Vector2Int(1,1));
}
```

我们将在 Start 函数中保留两次新游戏之间不会变化的一切，比如创建对象（如 TurnManager）或获取组件和 UI 元素。下面这些步骤都会移到 StartNewGame 函数中，因为它们需要在每次新游戏开始时执行：

- 隐藏 Game Over 消息。
- 在开始时把关卡重置回 1。
- 设置起始食物值（之前它只是通过默认值设置，而只调用那个函数时不会重置）。
- 初始化棋盘。
- 初始化玩家角色并生成它。

你可能会在代码中看到关于 PlayerController.Init() 函数的错误。这是因为这是一个我们需要创建的新函数。以下是 PlayerController 中的新内容：

PlayerController

```csharp
public void Init()
{
   m_IsGameOver = false;
}

private void Update()
{
   if (m_IsGameOver)
   {
       if (Keyboard.current.enterKey.wasPressedThisFrame)
       {
           GameManager.Instance.StartNewGame();
       }

       return;
   }

   ...
}
```

我们需要这个新函数把 IsGameOver 变量重置为 false，以重新开始游戏。和 FoodAmount 一样，之前它只是由默认值设置；但也和食物数量一样，这意味着当你没有重新启动整个应用就开始新游戏时，m_IsGameOver 变量会保持为 true！因此，重启后玩家角色将无法移动，因为对 PlayerController 来说，游戏仍处于 Game Over 状态。

现在，你只需检查 Update 中游戏是否处于 Game Over 状态、且 Enter 键是否被按下，如果是，就在 GameManager 上调用 StartNewGame。与输入一样，在一个完整的游戏中，你可能会想通过 Input Action 来处理这一点，以便可以重新映射按键或处理多个不同的按键。

最后，最好也更新一下 Game Over 消息，告知玩家可以按 Enter 键重新开始游戏。
