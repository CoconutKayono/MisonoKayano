## 3. 什么是命名空间？（What are namespaces?）

命名空间将类型定义分组，把它们封装成可以协同工作的系统。你可以把命名空间想象成操作系统中的文件夹。同一个命名空间内的类型可以自由地互相使用，但不在同一个命名空间内的类型，必须先导入才能使用。

## 4. 从命名空间使用类型的条件（Conditions for using a type from a namespace）

编写脚本时，要使用来自某个命名空间的类型，你需要满足以下三个条件之一：

- 你的脚本必须包含一条针对你所要使用类型所属命名空间的 using 指令。
- 使用该类型时，必须同时带上它的命名空间。
- 你的脚本必须与你想要使用的类型位于同一个命名空间。

### 包含该类型命名空间的 using 指令

这是脚本中最常满足的条件。这种从其他命名空间引入类型的方式，正确的语法是在脚本顶部写上关键字 using，后跟命名空间的名称。下面是一个例子：

```csharp
using UnityEngine;
public class PlayerMovement : MonoBehaviour
{
   // …
}
```

在这个代码示例中，引入了 UnityEngine 命名空间。这意味着 UnityEngine 命名空间中的所有类型都可以在这个脚本中使用，包括 MonoBehaviour、GameObject、Transform、Rigidbody 等常见类型。

### 使用类型时带上命名空间

你可以通过在类型前面加上命名空间的名称（用点运算符连接）来满足这个条件。下面是一个使用这种技巧的例子：

```csharp
public class PlayerMovement : UnityEngine.MonoBehaviour
{
   // …
}
```

使用类型时带上命名空间，在以下情况下很有用：你只想使用一次来自某个命名空间的类型，或者你想区分两个同名的类型。

### 把脚本写在与类型相同的命名空间中

## 5. 重复的类型名（Duplicated type names）

同一个命名空间中的所有类型都必须有不同的名称。不过，不同命名空间中的类型可以同名。例如，UnityEngine 和 System 命名空间都定义了一个名为 Random 的类型。

当你使用一个在多个命名空间中都存在的类型名称时，必须指定你实际想要使用的类型。这有两种不同的方式：

- 你可以像上一步学到的那样，在类型前面加上命名空间的名称。
- 你可以在脚本顶部添加另一条 using 指令，指定该类型名称在整个脚本中的默认含义。

下面是第二种技巧的例子：

```csharp
using UnityEngine;
using System;
using Random = UnityEngine.Random;
public class PlayerMovement : MonoBehaviour
{
   void Start()
   {
       float speed = Random.value;
       // …
   }
}
```

在这个例子中，UnityEngine 命名空间中的 Random 类型被指定为：脚本其余部分凡是使用 Random 的地方，指的都是它。

## 6. 将类型声明为命名空间的一部分（Declare a type as part of a namespace）

你可以通过把类型声明放在一个命名空间块内，来把该类型声明为命名空间的一部分。

命名空间块的语法如下：关键字 namespace 后跟命名空间的名称。这个名称可以是现有命名空间，也可以是一个新命名空间。下面是一个例子：

```csharp
using UnityEngine;
namespace Player
{
   public class PlayerMovement : MonoBehaviour
   {
       // ...
   }
}
```

在这个例子中，PlayerMovement 类是 Player 命名空间的一部分。要在其他脚本中使用 PlayerMovement 类型，你需要做以下三件事之一：

- 把你的其他脚本写在同一个命名空间（Player 命名空间）中。
- 在每个脚本顶部包含一条针对 Player 命名空间的 using 指令。
- 在每次使用 PlayerMovement 类型时指定其命名空间（Player.PlayerMovement）。

## 7. 嵌套命名空间（Nested namespaces）

你可以像操作系统中的文件夹一样嵌套命名空间。要访问嵌套的命名空间及其中的类型，请使用点运算符。点运算符是一个句点，表示命名空间之间的嵌套关系。

你可以使用嵌套命名空间，进一步组织项目中的系统和概念。例如，你可以把所有的编辑器脚本放在一个父命名空间中，然后为自定义检查器（custom inspectors）和各种其他工具创建嵌套命名空间。

让我们针对使用命名空间的三种方式，各看一个嵌套命名空间的例子。

### 嵌套命名空间声明

```csharp
namespace EditorTools.MapCreation
{
   public class Drawing
   {
       // ...
   }
}
```

### 嵌套命名空间的 using 指令

```csharp
using System.Collections;
public class AIManager
{
   // …
}
```

### 嵌套命名空间的类型使用

```csharp
public class Inventory : MonoBehavior
{
   public System.Collections.List<Item> items;
}
```

（译注：原文此处把 MonoBehaviour 误写为 MonoBehavior，缺少字母 u；代码中应使用 MonoBehaviour。）

## 8. 总结（Summary）

在本教程中，你复习了命名空间的基础用法，以及它们作为类型组织工具的作用。

如果你正处于游戏开发之旅的起点，命名空间可能看起来没有必要。然而，它们是一个有用的工具，随着你的项目变得更大、更复杂，你应该记住它们。
