01 · What：什么是池化对象的状态隔离？

池化对象的状态隔离，就是确保同一个对象在不同使用周期之间，不会发生不被允许的状态、行为或影响的继承。

对象池让不同业务复用同一个物理对象，但一次业务的状态和使用权，不能因为对象被复用就自动延续到下一次业务。

概念回答的问题
对象身份 Object Identity是不是同一个 C# 实例？
使用身份 Usage Identity属于哪一次业务使用？
状态 State现在保留了哪些数据？
使用权 Ownership / Lease谁有资格读取或修改它？

1. 从一个子弹例子开始

csharp · 代码片段
public class Bullet
{
    public int Damage;
    public float Speed;
    public int TargetId;
}

Bullet bullet = pool.Get();
bullet.Damage = 100;
bullet.Speed = 10;
bullet.TargetId = 5;
pool.Release(bullet);

Bullet nextBullet = pool.Get();
nextBullet.Damage = 20;
nextBullet.Speed = 5;
// 忘记设置 TargetId。

如果池返回刚才的实例，ReferenceEquals(bullet, nextBullet) 就为 true，而 TargetId 仍可能等于 5。第二次发射的子弹，便在不知情的情况下继承了第一次的目标。这是最基本的状态泄漏（State Leakage）。

2. 物理对象和逻辑使用必须分开

物理对象第一次使用 Usage #101第二次使用 Usage #102
Bullet #17，同一个 C# 实例Damage = 100，Target = 敌人 ADamage = 20，Target = 敌人 B
身份关系与第二次共享物理实例是独立的一次业务使用

用 O 表示物理对象、Uᵢ 表示第 i 次使用：两次使用指向相同 O，但 U₁ ≠ U₂。

物理身份相同，不代表逻辑身份相同。共享的是物理实例，不应共享未经许可的业务状态。

3. 状态隔离不等于把全部字段清零

csharp · 代码片段
public class Bullet : MonoBehaviour
{
    [SerializeField] private MeshRenderer meshRenderer;
    [SerializeField] private Rigidbody body;

    private int damage;
    private Transform target;
    private float remainingLife;
}
状态是否需要重置原因
MeshRenderer、Rigidbody 组件引用通常不需要属于对象长期结构
damage每轮重新初始化本轮配置可能不同
target清理或覆盖不能保留旧目标
remainingLife重置不能继承旧剩余时间
Rigidbody 速度通常需要不能继承旧动量
事件订阅按其所属生命周期解除旧业务关系不应意外延续
协程、异步任务停止或隔离旧任务可能在新一轮继续运行

可以将内部状态分为：S = S持久 + S使用。这里的加号表示组成，而非数值相加。

  • 持久状态：跨使用周期允许保留的组件、资源和数据。
  • 使用状态：只属于本次业务使用的目标、伤害、回调、计时器等。

下一次使用的初始状态，应由新配置与明确允许保留的持久状态决定，不能偶然继承上一次残留的数据。两次状态可以恰好数值相同；关键在于它们的来源符合契约。

02 · Why：为什么需要状态隔离？

1. 对象池改变了生命周期假设

普通创建池化复用
创建 → 初始化 → 使用 → 结束 → 销毁或等待回收创建 → 使用₁ → 归还 → 使用₂ → 归还 → 使用₃
构造与字段初始化建立初始状态再次 Get 不会重新执行构造函数

直接创建对象时依赖的初始化保证，不能直接假定在复用时仍然成立。 因此对象池必须有专门的复用契约。

2. 状态泄漏也包括行为关系

csharp · 代码片段
// 第一次使用时注册，结束后忘记解除。
bullet.OnHit += questSystem.RecordHit;

// 第二次使用时又注册。
bullet.OnHit += achievementSystem.RecordHit;

// 第二次命中时，两轮业务的订阅者都可能被通知。
OnHit?.Invoke();

残留的不只是 Damage、Speed 等数值，旧业务的行为关系也可能被带到新业务中。反过来，如果子弹订阅了外部目标的事件，外部目标也可能继续持有子弹的回调，必须从对应的事件发布者上解除订阅。

3. 字段全部重置，也可能出错

csharp · 代码片段
IEnumerator ExplodeLater()
{
    yield return new WaitForSeconds(2f);
    Explode();
}
时刻发生的事情
t = 0 秒第一次使用，安排两秒后爆炸
t = 0.5 秒归还并重置字段，旧延迟工作尚未失效
t = 1 秒同一物理对象作为新子弹再次使用
t = 2 秒旧操作尝试爆炸，可能影响新子弹

这是概念性时间线：Unity 禁用 GameObject 会停止附着在其 MonoBehaviour 上的协程，但外部调度器、独立任务或其他对象管理的回调不一定随之停止。

状态隔离既要处理对象里已经保存的数据，也要处理未来可能影响对象的旧操作。

因此，正确的状态隔离 ≠ 仅仅重置字段。必须一起管理数据、行为、引用、使用身份和生命周期。

03 · How：如何实现可靠的状态隔离？

层次核心职责
数据隔离清理或完整覆盖上一轮可变数据
关系隔离解除旧事件订阅、目标引用和业务回调
时间隔离阻止旧延迟操作影响新一轮使用
使用权隔离归还后的旧使用者不能继续控制对象

这四层是分析隔离的四个方面，并非必须分别实现的四种设计模式。

1. 定义状态集合与允许的转换

csharp · 代码片段
public enum PooledState
{
    Available,
    InUse,
    Destroyed
}

正常复用路径是 Available → 获取并初始化 → InUse → 撤销使用权并清理 → Available。销毁后的对象不得再次正常分配。

  • 获取前置条件：State = Available。
  • 获取后置条件：State = InUse，且业务状态由本轮配置完整建立。
  • 归还后置条件：旧使用权失效，对象满足空闲契约。

真正重要的是：对象被视为可正常使用之前，本轮所需的数据必须已经准备完成。 在 Unity 中，通常先初始化，再激活会触发 OnEnable() 的 GameObject。

2. 定义重置契约

归还后，所有只属于上一次使用的业务状态必须失效；下一次使用前，所有需要的业务状态必须重新建立。
操作时机职责
Create()首次创建建立长期资源和基本结构
PrepareForPool()本轮结束停止活动，清理旧状态
BeginUse(config)每次获取建立本轮完整业务状态
csharp · 代码片段
private void PrepareForPool()
{
    _damage = 0;
    _target = null;
    _remainingLife = 0f;
    _onHit = null;
}

private void BeginUse(BulletConfig config)
{
    _damage = config.Damage;
    _target = config.Target;
    _remainingLife = config.Lifetime;
    _onHit = config.OnHit;
}

如果一个字段每次使用前必然被完整覆盖，而且初始化前不会被观察，它未必需要在归还时清零。但旧业务引用、事件订阅和运行中的任务，通常应在本轮结束时及时解除或使其失效。

3. 引入使用代次 Generation

物理对象始终是 Bullet #17，但第一次使用代次为 1，第二次为 2。一次使用的身份可表达为：

LeaseId = (ObjectId, Generation)

旧回调保存旧代次；执行时与当前代次比较，不一致就拒绝修改。它检查的不再只是“是不是同一个对象”，还包括“是不是同一次使用”。

    4. 引入租约 Lease

    若 API 直接返回 Bullet，使用者即使已经归还，仍可以长期保存并使用 C# 引用。归还操作不会自动使普通引用失效。

    一种更强的边界是返回 BulletLease：它保存对象引用与获取时的代次，仅暴露 TryHit()、TryRelease() 等受控操作。

    csharp · 代码片段
    public readonly struct BulletLease
{
    private readonly Bullet _bullet;
    private readonly long _generation;
}

    所有操作都校验 InUse 且 Lease.Generation = Object.Generation。这使使用权边界从口头约定变为代码能检查的规则。前提是不能通过其他 API 绕过租约、直接修改可变对象。

    04 · C# 实现：具有状态隔离能力的对象池

    下面是完整的纯 C# 教学示例，专注于代次、租约、重置与归还顺序。全部操作假定在同一线程顺序执行；没有加入容量限制、池销毁、初始化失败恢复等生产级机制。

    1. 对象、租约与对象池

    csharp · 完整示例
    using System;
using System.Collections.Generic;

public sealed class Bullet
{
    private long _generation;
    private bool _inUse;
    private BulletPool _owner;

    private int _damage;
    private int _targetId;
    private Action<int> _onHit;

    internal BulletLease BeginUse(
        BulletPool owner,
        int damage,
        int targetId,
        Action<int> onHit)
    {
        if (_inUse)
            throw new InvalidOperationException("对象已在使用中");

        // 新的使用身份；不能在归还时清零。
        _generation = checked(_generation + 1);

        // 完整建立当前业务状态。
        _owner = owner;
        _damage = damage;
        _targetId = targetId;
        _onHit = onHit;
        _inUse = true;

        return new BulletLease(this, _generation);
    }

    internal bool IsCurrent(long generation)
    {
        return _inUse && _generation == generation;
    }

    internal bool TryHit(long generation, int targetId)
    {
        if (!IsCurrent(generation))
            return false;

        if (_targetId != targetId)
            return false;

        int damage = _damage;
        Action<int> callback = _onHit;

        // 先结束本轮，避免对外回调重入当前使用。
        TryRelease(generation);
        callback?.Invoke(damage);
        return true;
    }

    internal bool TryRelease(long generation)
    {
        if (!IsCurrent(generation))
            return false;

        // 先撤销本轮使用权，再进入清理流程。
        _inUse = false;
        _owner.Return(this);
        return true;
    }

    internal void ResetForPool()
    {
        if (_inUse)
            throw new InvalidOperationException("不能重置正在使用的对象");

        _damage = 0;
        _targetId = 0;
        _onHit = null;
        _owner = null;

        // 特意保留 _generation，防止旧租约重新有效。
    }
}

public readonly struct BulletLease
{
    private readonly Bullet _bullet;
    private readonly long _generation;

    internal BulletLease(Bullet bullet, long generation)
    {
        _bullet = bullet;
        _generation = generation;
    }

    public bool IsValid =>
        _bullet != null && _bullet.IsCurrent(_generation);

    public bool TryHit(int targetId)
    {
        return _bullet != null &&
               _bullet.TryHit(_generation, targetId);
    }

    public bool TryRelease()
    {
        return _bullet != null &&
               _bullet.TryRelease(_generation);
    }
}

public sealed class BulletPool
{
    private readonly Stack<Bullet> _available = new();

    public BulletLease Get(int damage, int targetId, Action<int> onHit)
    {
        Bullet bullet = _available.Count > 0
            ? _available.Pop()
            : new Bullet();

        return bullet.BeginUse(this, damage, targetId, onHit);
    }

    internal void Return(Bullet bullet)
    {
        // 清理完成后，才能对下一位使用者开放。
        bullet.ResetForPool();
        _available.Push(bullet);
    }
}

    2. 为什么同时检查 InUse 和 Generation？

    Valid(Lease) = InUse ∧ (Lease.Generation = Object.Generation)

    第一次归还后、第二次获取前，代次仍是原来的值。只比较 Generation，就会把已经归还的租约误判为有效。InUse 负责判定使用是否仍在进行，Generation 负责判定是否为同一轮。

    ResetForPool() 必须在 Push() 之前完成：对象一旦进入可用集合，就应符合安全复用契约。在并发实现中，反过来的顺序还可能让其他线程取到尚未清理的对象；但仅调整顺序并不能使本示例变为线程安全。

    3. 验证旧租约失效

    csharp · 代码片段
    var pool = new BulletPool();

BulletLease oldLease = pool.Get(
    damage: 100,
    targetId: 5,
    onHit: damage => Console.WriteLine($"第一次命中：{damage}"));

Console.WriteLine(oldLease.TryRelease()); // True

BulletLease newLease = pool.Get(
    damage: 20,
    targetId: 8,
    onHit: damage => Console.WriteLine($"第二次命中：{damage}"));

Console.WriteLine(oldLease.TryHit(5));    // False
Console.WriteLine(oldLease.TryRelease()); // False
Console.WriteLine(newLease.TryHit(8));
// 第二次命中：20
// True

    这个例子隔离了旧数据，拒绝旧租约修改或归还新一轮使用，也拒绝同一租约重复归还。它不依赖调用者主动把变量设为 null。

    租约结构体可以被复制，副本表示同一轮使用权；其中一个成功归还后，其他副本也会失效。它本身并不是 C# 类型系统强制的唯一所有权。

    命中回调在归还后执行，回调可能重入并获取同一物理对象，因此 TryHit() 预先保存本轮数据，回调后不再访问对象状态。回调若抛出异常，异常仍会传播；本轮使用已经结束。

    05 · Unity 中如何进行完整的状态隔离？

    GameObject 的状态分布在多个组件中，清理 C# 字段通常不够。

    状态来源常见残留常见处理
    Transform位置、旋转、缩放按新配置初始化
    Rigidbody线速度、角速度清零或指定新运动状态
    Animator参数与播放进度按业务重置参数、播放状态
    ParticleSystem旧粒子Stop、Clear
    TrailRenderer上轮轨迹Clear()
    C# 事件上一轮回调解除对应订阅
    Coroutine未结束协程停止对应协程
    异步任务未完成加载、计算取消并校验使用身份
    业务组件目标、生命值、计时器、Buff按业务契约重置

    1. 清理方法示意

    以下代码假定字段已经定义和初始化，使用 Unity 6 的 Rigidbody 属性名称。实际需要按组件是否存在、物理模拟状态与订阅情况调整。

    csharp · 代码片段
    private void PrepareForPool()
{
    // 1. 终止当前业务身份。
    _inUse = false;

    // 2. 只停止当前 MonoBehaviour 管理的协程。
    StopAllCoroutines();

    // 3. 解除对旧目标的订阅。
    if (_target != null)
    {
        _target.OnDied -= HandleTargetDied;
        _target = null;
    }

    // 4. 重置运动状态。
    _rigidbody.linearVelocity = Vector3.zero;
    _rigidbody.angularVelocity = Vector3.zero;

    // 5. 清理视觉状态。
    _trailRenderer.Clear();

    // 6. 清理业务状态。
    _damage = 0;
    _remainingLife = 0f;
    _onHit = null;

    // 7. 最后禁用对象。
    gameObject.SetActive(false);
}

    StopAllCoroutines() 只影响当前 MonoBehaviour 上启动的协程，无法停止其他组件或外部系统的工作。

    2. OnDisable() 能否承担全部责任？

    它可以承担一部分清理，但它既可能由归还触发，也可能由父对象禁用、场景卸载或组件关闭触发。它不必然表示一次池化业务正常结束。

    还需区分：禁用 GameObject 会停止其 MonoBehaviour 上的协程；仅设置 MonoBehaviour.enabled = false 不会自动停止这些协程。

    通常更清晰的流程是：Release → 撤销使用权 → 停止本轮工作 → 清理业务状态 → 禁用 GameObject → 放回空闲池。

    OnDisable 处理组件被禁用时的生命周期事项，必要时作为额外防护；应避免它再度递归归还对象。

    对象不可见，不代表业务使用已经正确结束。

    06 · 时间隔离：如何处理旧异步任务？

    1. 为什么 CancellationToken 不够？

    Cancel() 发出取消请求，并不保证所有工作立即停止。异步操作必须配合取消协议；有些工作已经完成，或回调已经排队。

    因此，一个稳妥策略是：取消旧操作 + 使用身份校验。前者尽量节省旧工作，后者拒绝迟到结果。

    2. 使用代次检查异步结果

    以下是片段示意，假设 FetchAsync、ApplyResult 等已经定义，并且检查与结果应用被安排在 Unity 主线程，期间不会发生让出执行权的操作。

    csharp · 代码片段
    private long _generation;
private bool _inUse;
private CancellationTokenSource _cts;

private async Task LoadAsync(
    long expectedGeneration,
    CancellationToken token)
{
    try
    {
        var result = await FetchAsync(token);
        token.ThrowIfCancellationRequested();

        if (!_inUse || expectedGeneration != _generation)
            return;

        ApplyResult(result);
    }
    catch (OperationCanceledException)
        when (token.IsCancellationRequested)
    {
        // 本次使用已经被取消。
    }
}

private void EndUse()
{
    _inUse = false;
    _cts?.Cancel();
}

    这里的 CancellationTokenSource 还需在相关工作结束、不会再使用时正确 Dispose。Dispose 本身不会请求取消；新一轮使用也应建立自己的取消上下文，不能复用已取消的令牌来源。

    如果延续可能跨线程执行，必须把 Unity API 调用切回主线程。Generation 检查不能单独解决“检查后、修改前”的竞态；应使用同步协议，或把身份检查与修改统一安排在同一主线程步骤中。若检查后再次 await、调度或执行可能重入的外部代码，应重新考虑有效性检查的位置。

    3. 旧操作失去的是资格

    第一次使用 Generation 1 启动加载，归还后对象进入 Generation 2。第一次加载返回时，对象仍存在，C# 引用也有效，但这不赋予旧加载修改新使用的权利。

    旧操作被拒绝，是因为它所属的那次业务已经结束。

    07 · 怎样从正确性角度验证隔离？

    1. 空闲状态不变量

    当 State = Available，应满足：InUse = false，没有有效的旧业务使用权，ReadyForReuse = true。

    ReadyForReuse 不要求所有字段为零，而要求：旧业务行为不能继续污染对象，旧使用者不能再修改本轮状态，旧业务关联已经按契约处理，并且可以安全进入下一轮初始化。

    2. 使用状态不变量

    当 State = InUse，应满足：配置有效、当前代次有效、业务状态已初始化。不能把尚未准备完成的对象暴露成一个可正常运行的业务对象。

    3. 归还的前置与后置条件

    { InUse(o, g) } Release(o, g) { Available(o) ∧ ¬Valid(o, g) }

    含义是：对象 o 正处于代次 g 时，成功归还后，它可以复用，而旧代次的使用权已失效。这针对正常执行且清理成功的情况，并假定中间没有再次分配对象。

    如果 ResetForPool 抛出异常，不应把未知清理状态的对象交给下一位使用者。应将其隔离为不可复用，再按资源类型清理或销毁。

    4. 跨使用周期测试

    测试场景应验证的结果
    归还后再次获取本轮状态由新配置建立
    旧租约修改新使用被拒绝
    同一租约重复归还第二次失败
    上次事件迟到不影响新使用
    上次异步结果迟到不影响新使用
    归还到错误池被拒绝或无法通过公开 API 表达
    重置发生异常不进入可用集合
    多线程同时获取不产生两个相互独立的有效使用者

    这些测试检查隔离规则，而不只检查某个字段是否等于零。上面的教学代码只演示其中一部分；并发、异常恢复等要求需要额外实现。

    08 · 什么时候不需要复杂的代次与租约？

    对于完全内部使用的临时集合：

    csharp · 代码片段
    var list = pool.Get();
try
{
    list.Clear();
    // 在本同步调用范围内使用 list。
}
finally
{
    pool.Release(list);
}

    如果操作在同步范围内结束，没有异步任务，没有逃逸引用或跨周期订阅，并且调用者遵守契约，那么清理配合 try/finally 通常足够。

    Unity 的 PooledObject<T> 也可配合 using，在作用域结束时归还对象。但 using 不能阻止你把内部可变引用泄漏给其他代码。

    场景按需要采用的机制
    局部临时集合清理 + try/finally 或 using
    普通同步子弹、特效明确初始化、清理和使用状态检查
    有延迟回调的对象加入 Generation
    多个业务系统长期持有Lease 或受控访问接口
    跨线程对象池线程安全容器 + 同步 + 使用权协议

    这些是按风险选机制的参考，并非互斥分类。Unity 内置 ObjectPool 的重复归还检查也不能替代业务隔离；检查行为应以所用版本为准。内置 ObjectPool 本身不提供线程安全保证。

    09 · 回到本质：复用资源，隔离业务

    概念解决的问题
    对象池 Object Pool如何复用物理对象？
    重置 Reset如何处理上轮残留状态？
    状态隔离 State Isolation如何使不同使用周期互不污染？
    使用权 Ownership谁有资格操作对象？
    租约 Lease如何表示并限制这次使用权？
    使用代次 Generation如何识别某次特定使用？
    不变量 Invariant如何定义始终应成立的约束？
    • 复用与状态：对象可复用，业务状态不能无意继承。
    • 状态与行为：字段全重置，旧操作仍可能污染新使用。
    • 身份与使用权：必须区分当前与过期使用者，并拒绝过期操作。

    状态隔离 = 状态边界 + 生命周期边界 + 使用权边界。 这是分析问题的思维模型，并非必须照搬的代码公式。

    Reset 解决“过去留下了什么”；Lease 和 Generation 解决“过去是否还能影响现在”。

    两类问题都得到妥善处理，复用才具有可靠的隔离性。
