行为（Behavior）与转移（Transition）的区别

行为：对象做什么。
转移：对象的状态如何从一种状态变成另一种状态。

它们并不是两个互相排斥的概念。一个行为可能引起状态转移，但行为不一定会改变状态。

一、What：什么是行为？什么是转移？

1. 行为（Behavior）

行为描述一个对象能够执行什么操作，以及执行操作时会发生什么。例如，游戏角色可以移动、攻击、跳跃、查看当前生命值、播放动画。

行为关注的是对象执行的操作，而不是一定产生什么状态变化。

public int GetHealth()
{
    return health;
}

这个方法也是一种行为。但是它没有改变对象的状态，只是读取当前生命值。

2. 转移（Transition）

转移描述状态之间的变化，可以表示为：

Sbefore → Safter

其中，Sbefore 是转移前的状态，Safter 是转移后的状态。

在状态机里，转移通常还规定：什么事件或条件允许这次变化发生。例如，从待机状态转移到攻击状态，需要玩家按下攻击键，并且角色没有死亡、当前可以攻击。

因此，转移既可以表示发生的状态变化，也可以指规定这种变化的规则。

二、Why：为什么需要区分？

因为我们要区分两个问题：

  • 系统要执行什么操作？这是行为关心的问题。
  • 系统的状态如何变化？这是转移关心的问题。

例如游戏里的 Attack()：

public void Attack()
{
    // 检查是否能够攻击
    // 消耗弹药
    // 对敌人造成伤害
    // 播放攻击动画
    // 播放攻击音效
}

这是一个行为，但它内部涉及多个不同性质的事情：

操作观察角度原因
检查能否攻击状态检查判断操作是否允许
弹药 10 → 9状态转移弹药数量发生变化
敌人 HP 100 → 80状态转移敌人的生命值发生变化
播放攻击音效对外部系统的作用向音频系统发出播放请求
播放攻击动画对外部系统的作用向动画系统发出播放请求

这些分类不是互斥的。修改弹药、修改敌人生命值，在通常的编程语境下也属于副作用。表格是为了突出各操作的观察重点；音效和动画也可能改变其他系统的内部状态。

一次行为可能包含零次、一次或多次状态转移，也可能产生输出或其他副作用。

三、How：在程序中如何区分？

下面是一个可用于 Unity 项目的普通 C# 类：

using System;

public class Player
{
    private int health = 100;

    public void TakeDamage(int damage)
    {
        if (damage <= 0 || health <= 0)
            return;

        health = Math.Max(0, health - damage);
    }

    public int GetHealth()
    {
        return health;
    }
}

这里有两个行为：TakeDamage() 表示受到伤害，GetHealth() 表示查询生命值。只有 TakeDamage() 在符合条件时会引起生命值变化。

转移前100 HP
TakeDamage(20) →
转移后80 HP

如果在生命值为 100 时调用 GetHealth()，返回值是 100，调用后生命值仍然是 100。查询是行为，但没有改变角色的生命值。

用数学表达观察角度

在一个简化模型中，行为可以抽象成：

B(S, I) = (S′, O)
  • S：当前状态。
  • I：输入，例如伤害值。
  • S′：操作后的状态。
  • O：输出，例如返回值或发给外部系统的指令。

状态转移主要关注其中的状态部分：

T(S, I) = S′

T 是状态转移函数，描述给定当前状态和输入后，下一个状态是什么。这是对确定性转移的一种简化表达；如果某个行为没有改变所观察的状态，那么 S′ = S。

这里把外部作用抽象为输出指令，方便理解；实际程序也可能直接操作外部系统。另外，在形式化模型中，S′ = S 也可以建模为自转移或保持原状态，不能仅凭数值没变就断言没有执行转移规则。

转移可以看成行为中关于状态变化的那一部分，也可以作为独立规则建模。

四、不同层次的“状态”

我们可以说：“玩家执行攻击行为，从待机状态转移到攻击状态。”也可以说：“玩家受到伤害，生命值从 100 变成 80。”两者观察的状态不同。

层次示例关注点
状态机状态Idle、Attack、Dead当前处于哪个模式，以及如何切换
对象数据状态生命值、弹药、金币当前数据是什么，以及如何改变

广义地说，两者都涉及状态变化。但在状态机设计的语境中，Transition 通常指状态机的转移，不能把每次数值变化都直接当成状态机模式切换。

判断之前，先明确：我们正在观察哪个对象、哪一层状态？

五、三个概念之间的关系

概念核心问题例子
状态 State对象现在是什么样？生命值为 100，当前处于 Idle
行为 Behavior对象做什么，以及如何执行？受到伤害、查询生命值、攻击
转移 Transition状态如何变化？HP 100 → 80；Idle → Attack
行为强调操作，转移强调状态变化。
行为不一定引起状态变化；状态机转移也不一定需要通过显式调用一个对应的业务方法来触发。

例如，角色生命值归零后，状态机可以根据条件自动进入死亡状态，而不是必须由调用者主动调用 Die()。不过，“自动”仍然需要程序在某个执行时机检查条件并执行转移。
