## 学习目标

- 用简单的对象搭建一个时钟。
- 编写一个 C# 脚本。
- 旋转时钟的指针来显示时间。
- 让指针动起来。

这是「学习 Unity 的[基础](https://catlikecoding.com/unity/tutorials/basics/)」系列教程的第一篇。在这一篇里，我们会创建一个简单的时钟，并编写一个组件，让它显示当前时间。你不需要事先有任何 Unity 编辑器经验，但默认你已经有一些使用多窗口编辑器应用的经验。

## 创建项目

在我们开始使用 Unity 编辑器之前，必须先创建一个项目。

### 新建项目

打开 Unity 时，你会看到 Unity Hub。这是一个启动器和安装器应用，你可以在这里创建或打开项目、安装 Unity 版本，以及做一些其他事情。如果你还没装 Unity 2020.3 或更高版本，现在就去装一个。

> **应该用哪个 Unity 版本？**
>
> Unity 每年会发布多个新版本，有两条并行的发布线。最稳定、最安全的是 LTS 版本。LTS 意为长期支持（long term support），Unity 的长期支持期是两年。我的教程都坚持使用 LTS 版本。本教程具体用的是 2020.3.6。版本号第三段表示补丁（patch）版本，补丁版本只包含 bug 修复，极少引入新功能。后面的 `f1` 后缀表示这是官方最终版本。对于本教程，任何 2020.3 版本都可以。
>
> 最高版本的 Unity 属于开发分支，会引入新功能，也可能移除旧功能。这些版本不像 LTS 版本那么可靠，每个版本只支持几个月。

我的教程偶尔会包含一些小问题及其答案，它们总是放在一个灰色方框里，就像上面那样。在网页上，答案默认是隐藏的，点击或轻触问题即可切换显示。

当你创建新项目时，可以选择 Unity 版本和一个模板。我们用标准的 3D 模板。创建完成后，它会加入项目列表，并在对应版本的 Unity 编辑器中打开。

> **我能用不同的渲染管线来创建项目吗？**
>
> 可以，唯一区别是项目的默认场景里会多出一些东西，材质看起来也会不同。项目里还会包含相应的包。

### 编辑器布局

如果你还没有自定义过编辑器，你会看到它的默认窗口布局。

![默认的编辑器布局。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/default-layout.png)

默认布局包含我们需要的所有窗口，但你可以随意自定义它，比如重新排序、组合窗口。你也可以打开和关闭窗口，比如资源商店（Asset Store）的窗口。每个窗口都有自己的配置选项，可以通过右上角的三点按钮访问。此外，大多数窗口还有一个带更多选项的工具栏。如果你的窗口看起来和教程里不一样——例如场景窗口是纯色背景而不是天空盒——那说明它的某个选项设置不同。

你可以通过 Unity 编辑器右上角的下拉菜单切换到预设布局。你也可以在那里保存当前布局，以便日后恢复。

### 包

Unity 的功能是模块化的。除了核心功能，还有可以下载并包含进项目的额外包（packages）。默认的 3D 项目目前默认包含几个包，你可以在项目窗口的 *Packages* 下看到它们。

![默认的包。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/default-packages.png)

这些包可以被隐藏，方法是切换项目窗口右上角那个「眼睛带一条斜杠」样式的按钮。这纯粹是为了减少编辑器里的视觉杂乱，包仍然是项目的一部分。这个按钮上也会显示这类包的数量。

你可以通过包管理器（package manager）来控制项目里包含哪些包，它可以通过 *Window / Package Manager* 菜单打开。

![包管理器，只显示项目内的包。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/package-manager.png)

这些包为 Unity 增加了额外功能。例如 *Visual Studio Editor* 为 Visual Studio 编辑器（用于编写代码）增加了集成。本教程用不到这些包的功能，所以我把它们都移除了。唯一的例外是 *Visual Studio Editor*，因为这是我写代码用的编辑器。如果你用的是别的编辑器，你会想包含它的集成包（如果有的话）。

> **难道你不需要 Visual Studio Code Editor 包吗？**
>
> 尽管名字相似，*Visual Studio* 和 *Visual Studio Code* 是两个不同的编辑器。你只需要其中一个包，取决于你用哪个编辑器。

移除包最简单的方法是：先用工具栏把包列表限制为只显示 *In Project*（项目内）。然后逐个选中这些包，用窗口右下角的 *Remove* 按钮移除。每次移除后 Unity 都会重新编译，所以要过几秒才能完成。

把除 *Visual Studio Editor* 之外的所有东西移除后，项目窗口里就剩下三个可见的包：*Custom NUnit*、*Test Framework* 和 *Visual Studio Editor*。另外两个还在，是因为 *Visual Studio Editor* 依赖它们。

你可以通过项目设置窗口（*Edit / Project Settings...* 打开）让包管理器显示依赖项和隐式导入的包。选择它的 *Package Manager* 分类，然后在 *Advanced Settings* 下启用 *Show Dependencies*。

![包管理器的项目设置；已启用 Show Dependencies。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/package-manager-settings.png)

### 色彩空间

如今渲染通常在线性色彩空间（linear color space）中进行，但 Unity 默认仍配置为伽马色彩空间（gamma color space）。为了获得最佳视觉效果，选择项目设置窗口的 *Player* 分类，打开 *Other Settings* 面板，向下滚动到 *Rendering* 部分，确保 *Color Space* 设置为 *Linear*。Unity 会警告这可能需要很长时间，但对于一个几乎空的项目来说并不会。确认切换即可。

![色彩空间已设为线性。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/color-space.png)

> **有什么理由要用伽马色彩空间吗？**
>
> 只有当你面向旧硬件或旧图形 API 时才需要。OpenGL ES 2.0 和 WebGL 1.0 不支持线性空间，此外在旧移动设备上，伽马可能比线性更快。

### 示例场景

新项目包含一个名为 *SampleScene* 的示例场景，默认会打开它。你可以在项目窗口的 *Assets / Scenes* 下找到它的资源。

![项目窗口里的示例场景。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/two-column-layout.png)

默认情况下，项目窗口使用双列布局。你可以通过它的三点配置菜单切换到单列布局。

![单列布局。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/one-column-layout.png)

示例场景包含一个主摄像机（Main Camera）和一个方向光（Directional Light）。这些是游戏对象（game object）。它们列在层级窗口（Hierarchy）里，位于场景之下。

![场景中的对象层级。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/sample-scene-hierarchy.png)

你可以通过层级窗口或场景窗口选择游戏对象。摄像机有一个看起来像老式胶片摄像机的场景图标，而方向光的图标看起来像太阳。

![场景窗口里的图标。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/scene-icons.png)

> **如何在场景窗口里导航？**
>
> 你可以用 Alt（或 Mac 上的 Option）键加鼠标来旋转视角，也可以用方向键移动视点，用滚轮缩放。另外，按 F 键会把视角聚焦到当前选中的游戏对象上。还有更多方式，但这些足够你在场景里找到方向了。

当某个对象被选中时，它的详情会显示在检视窗口（Inspector）里，不过我们会在需要时再讲这些。我们不需要修改摄像机或灯光，所以可以在层级窗口里点击它们左侧的眼睛图标，把它们在场景里隐藏起来。这个图标默认不可见，把光标悬停上去时才会出现。这纯粹是为了减少场景窗口里的视觉杂乱。

![隐藏的对象。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/hidden-objects.png)

> **眼睛图标旁边那个像手的图标是干什么的？**
>
> 在眼睛图标那一列旁边，还有一列像手一样的图标。这些图标默认也是不可见的。当某个游戏对象的手形图标处于激活状态时，就无法通过场景窗口选中该对象。这样你就能控制哪些对象响应场景窗口的选择。

## 搭建一个简单的时钟

现在项目已经设置正确，我们可以开始创建时钟了。

### 创建游戏对象

我们需要一个游戏对象来代表时钟。我们从最简单的游戏对象——一个空对象——开始。它可以通过 *GameObject / Create Empty* 菜单选项创建。或者，你也可以用层级窗口右键菜单（通常是右键或双指轻触打开）里的 *Create Empty* 选项。这会把游戏对象添加到场景中。它在层级窗口里 *SampleScene* 下立即可见并被选中，而 *SampleScene* 现在会带一个星号，表示它有未保存的更改。你也可以立刻给它改名，或留到以后再改。

![选中新游戏对象后的层级窗口。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/new-game-object.png)

只要游戏对象处于选中状态，检视窗口就会显示它的详情。顶部是一个头部，包含对象的名字和几个配置选项。默认情况下，对象处于启用状态、不是静态的、没有标签、位于默认图层。这些设置都没问题，除了名字。把它改名为 *Clock*。

![选中时钟后的检视窗口。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/inspector.png)

头部下方是该游戏对象所有组件的列表。列表顶部始终有一个 `Transform` 组件，这是我们的时钟目前唯一的组件。它控制游戏对象的位置、旋转和缩放。确保时钟所有位置和旋转值都设为 0，缩放统一为 1。

> **2D 对象呢？**
>
> 在 2D 而不是 3D 中工作时，你可以忽略三个维度中的一个。专用于 2D 的对象——比如 UI 元素——通常使用 `RectTransform` 来代替，它是一种特殊的 `Transform` 组件。

因为这个游戏对象是空的，所以它在场景窗口本身里不可见。不过，在游戏对象所在的位置（即世界的中心）会显示一个操控工具（manipulation tool）。

![用移动工具选中。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/move-tool.png)

> **为什么我选中时钟后看不到操控工具？**
>
> 操控工具存在于场景窗口里。确保你在看的是场景窗口，而不是游戏（Game）窗口。

哪个操控工具处于激活状态，可以通过编辑器工具栏左上角的按钮来控制。这些模式也可以用 Q、W、E、R、T、Y 键激活。这一组里最右边的按钮用于启用自定义编辑器工具，我们没有这种工具。移动工具默认处于激活状态。

![操控模式工具栏。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/manipulation-toolbar.png)

模式按钮旁边还有三个按钮，用于控制操控工具的放置、朝向和吸附。

### 创建时钟的表盘

虽然我们有了时钟对象，但还是什么都看不到。我们必须给它添加 3D 模型，才能渲染出东西。Unity 内置了一些基础对象（primitive），我们可以用它们搭建一个简单的时钟。我们先通过 *GameObject / 3D Object / Cylinder* 往场景里加一个圆柱体。确保它的 `Transform` 值和我们的时钟一样。

![代表圆柱体的游戏对象。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/cylinder-scene.png)

新对象比空游戏对象多三个组件。首先，它有一个 `MeshFilter`，包含对内建圆柱体网格（mesh）的引用。

![MeshFilter 组件，设为圆柱体。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/mesh-filter.png)

第二是 `MeshRenderer`。这个组件的用途是确保对象的网格被渲染。它还决定了渲染时使用什么材质，这里用的是默认材质。这个材质也会显示在检视窗口组件列表的下方。

![MeshRenderer 组件，设为默认材质。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/mesh-renderer.png)

第三是 `CapsuleCollider`，用于 3D 物理。这个对象代表圆柱体，但它的碰撞体是胶囊（capsule），因为 Unity 没有内置的圆柱体碰撞体。我们不需要它，所以可以移除这个组件。如果你想给时钟用物理，最好使用 `MeshCollider` 组件。组件可以通过它们右上角的三点下拉菜单移除。

![没有碰撞体的圆柱体。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/cylinder-without-collider.png)

我们要把圆柱体压扁，变成时钟的表盘（face）。这可以通过减小它缩放的 Y 分量来实现，减到 0.2。由于圆柱体网格有两单位高，它的有效高度就变成了 0.4 单位。我们还要做一个大时钟，所以把缩放的 X 和 Z 分量增大到 10。

![缩放后的圆柱体。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/cylinder-scaled-scene.png)

我们的时钟应该是立着或挂在墙上的，但它的表盘现在平躺着。我们可以通过把圆柱体旋转四分之一圈来解决。在 Unity 中，X 轴指向右，Y 轴指向上，Z 轴指向前。所以让我们以同样的朝向思路来设计时钟，也就是说，当我们沿 Z 轴看向它时，看到的是它的正面。把圆柱体的 X 旋转设为 90，并调整场景视角让时钟正面可见，让移动工具的蓝色 Z 箭头指向远离你的方向、即指向屏幕里。

![旋转后的圆柱体。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/cylinder-rotated-scene.png)

把圆柱体对象改名为 *Face*，因为它代表时钟的表盘。它只是时钟的一部分，所以我们把它设为 *Clock* 对象的子对象。做法是在层级窗口里把表盘拖到时钟上。

![Face 子对象。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/child-object.png)

子对象会受到其父对象变换的影响。这意味着当 *Clock* 改变位置时，*Face* 也会跟着变，就好像它们是同一个整体。旋转和缩放也是如此。你可以利用这一点来构建复杂的对象层级。

### 创建时钟的周边刻度

钟表表盘的外圈通常有一些标记，用来帮助指示它显示的时间，这就是所谓的时钟周边刻度（periphery）。让我们用方块来指示 12 小时制时钟的小时。

通过 *GameObject / 3D Object / Cube* 往场景里加一个立方体对象，命名为 *Hour Indicator 12*，也把它设为 *Clock* 的子对象。层级窗口里子对象的顺序无关紧要，你可以把它放在表盘上面或下面。

![小时刻度子对象。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/hour-indicator-child.png)

把它的 X 缩放设为 0.5，Y 缩放设为 1，Z 缩放设为 0.1，让它变成一块又窄又扁的长条。然后把它的 X 位置设为 0，Y 位置设为 4，Z 位置设为 −0.25。这样它就位于表盘顶部，用来指示 12 点。同时移除它的 `BoxCollider` 组件。

![12 点刻度。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/indicator-scene.png)

这个刻度很难看清，因为它和表盘颜色一样。让我们通过 *Assets / Create / Material*，或项目窗口的加号按钮或右键菜单，为它单独创建一个材质。这会得到一个材质资源，它是默认材质的副本。把它的名字改成 *Hour Indicator*。

![项目窗口里的小时刻度材质，单列和双列布局。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/material-project-one-column.png)

选中材质，点击它的颜色字段，把 *Albedo* 改成别的颜色。这会打开一个颜色弹出窗口，提供多种选色方式。我选了深灰色，对应十六进制 494949，也就是 RGB 0–255 模式下统一的 73。我们用不到 alpha 通道，所以它的值无关紧要。其他材质属性也可以保持默认。

![深灰色的反照率。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/hour-indicator-material.png)

> **什么是反照率（Albedo）？**
>
> Albedo 是一个拉丁词，意为「白度」。它是某物在白光照射下呈现的颜色。

让小时刻度使用这个材质。你可以把材质拖到场景窗口或层级窗口里的对象上，也可以在刻度游戏对象被选中时把它拖到检视窗口底部，或者修改它 `MeshRenderer` 的 *Materials* 数组的 *Element 0*。

![深色的小时刻度。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/dark-hour-indicator-scene.png)

### 十二个刻度

我们只用一个 12 点的刻度也能凑合，但让我们给每个小时都配一个刻度。先把场景视角调整到沿 Z 轴正对时钟。你可以点击场景视图右上角视角摄像机 gizmo 的坐标轴锥体，也可以通过网格工具栏按钮把场景网格的轴改为 Z。

![沿 Z 轴正对时钟。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/looking-along-z-axis.png)

复制 *Hour Indicator 12* 游戏对象。你可以通过 *Edit / Duplicate*、相应的键盘快捷键，或层级窗口里它的右键菜单来完成。副本会出现在层级窗口里原对象的下方，也是 *Clock* 的子对象。它的名字会被设为 *Hour Indicator 12 (1)*。把它改名为 *Hour Indicator 6*，并把位置 Y 分量取反，让它指示 6 点。

![6 点和 12 点的刻度。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/hour-indicator-6-hierarchy.png)

用同样的方法创建 3 点和 9 点的刻度。这次它们的 X 位置应为 4 和 −4，Y 位置应为 0。同时把它们的 Z 旋转设为 90，让它们转过四分之一圈。

![四个小时刻度。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/four-hour-indicators.png)

然后再复制一个 *Hour Indicator 12*，这次用于 1 点。把它的 X 位置设为 2，Y 位置设为 3.464，Z 旋转设为 −30。然后为 2 点再复制一个，交换它的 X 和 Y 位置，并把 Z 旋转加倍到 −60。

![1 点和 2 点的刻度。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/hour-indicators-1-2.png)

> **这些数字是从哪来的？**
>
> 每个小时沿 Z 轴覆盖 30° 的顺时针旋转。这里我们用负旋转，因为 Unity 的旋转是逆时针的。我们可以通过三角函数求出 1 点的位置。30° 的正弦是 ½，余弦是 `sqrt(3)/2`。我们用刻度到中心的距离（这里是 4）去缩放它们。于是得到 X 为 2、Y 为 `2sqrt(3)≈3.464`。对于 2 点，旋转是 60°，我们只需交换正弦和余弦即可。

复制这两个刻度，把它们的 Y 位置和旋转取反，就得到了 4 点和 5 点的刻度。然后对 1、2、4、5 点用同样的技巧来创建剩余的刻度，这次把它们的 X 位置取反，旋转也再次取反。

![所有小时刻度。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/all-hour-indicators.png)

## 让时钟动起来

我们的时钟目前不能报时，它永远停在十二点。要让它动起来，我们必须给它添加一个自定义行为。做法是创建一个自定义组件类型，它通过脚本来定义。

### C# 脚本资源

通过 *Assets / Create / C# Script* 往项目里添加一个新的脚本资源，命名为 *Clock*。C# 是 Unity 脚本使用的编程语言，读作 *C-sharp*。我们也立刻把它放进一个新的 *Scripts* 文件夹，保持项目整洁。

![带 Clock 脚本的 Scripts 文件夹，单列和双列布局。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/script-asset-one-column.png)

当脚本被选中时，检视窗口会显示它的内容。但要编辑代码，我们必须使用代码编辑器。你可以通过脚本检视窗口里的 *Open...* 按钮，或在层级窗口里双击它来打开脚本进行编辑。打开的是哪个程序，可以在 Unity 的偏好设置里配置。

![C# Clock 资源的检视窗口。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/clock-inspector.png)

### 定义一个组件类型

脚本在代码编辑器里加载后，先删掉标准模板代码，因为我们要从零创建组件类型。

一个空文件什么都不定义。它必须包含我们时钟组件的定义。我们要定义的不是组件的某个实例，而是名为 `Clock` 的通用类（class）或类型。一旦定义好，我们就能在 Unity 里创建多个这样的组件，尽管本教程里我们只用一个时钟。

在 C# 里，定义 `Clock` 类型的方法是：先声明我们正在定义一个类，后面跟上它的名字。在下面的代码片段中，被修改的代码有黄色背景（如果你用深色网页主题看本教程，则是暗红色背景）。因为我们从一个空文件开始，它的内容就应该是 `class Clock`，别的什么也没有，不过你可以在单词之间随意加空格和换行。

```diff
+class Clock
```

> **从技术上讲，类（class）是什么？**
>
> 你可以把类想象成一张蓝图，用它来创建驻留在计算机内存里的对象。蓝图定义了这些对象包含什么数据、具有什么功能。
>
> 类还可以定义不属于对象实例、而属于类本身的数据和功能。这常被用来提供全局可用的功能。我们会用到其中一部分，但 `Clock` 不会有这种成员。

因为我们不想限制哪些代码可以访问我们的 `Clock` 类型，所以最好在它前面加上 `public` 访问修饰符。

```diff
+public class Clock
```

> **类的默认访问修饰符是什么？**
>
> 不加访问修饰符，就相当于写了 `internal class Clock`。这会限制只有同一程序集（assembly）内的代码才能访问，当你把代码打包到单独的程序集里时，这一点就很重要了。为了确保它始终可用，默认把类设为 public。

此时我们还没有合法的 C# 语法。如果你保存文件并回到 Unity 编辑器，编译错误会被记录到它的控制台窗口里。

我们声明了正在定义一个类型，所以必须真正定义它的样子。这靠声明之后的一整块代码来完成。代码块的边界用花括号表示。我们现在先让它空着，所以只写 `{}`。

```diff
public class Clock {}
```

现在我们的代码合法了。保存文件，切回 Unity。Unity 编辑器会检测到脚本资源已更改，并触发重新编译。完成后，选中我们的脚本。检视窗口会告诉我们：这个资源不包含 `MonoBehaviour` 脚本。

![不是组件的脚本。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/non-component.png)

这意味着我们还不能用这个脚本在 Unity 里创建组件。此时，我们的 `Clock` 定义的是一个基础的 C# 对象类型。我们的自定义组件类型必须扩展 Unity 的 `MonoBehaviour` 类型，继承它的数据和功能。

> **MonoBehaviour 是什么意思？**
>
> 思路是，我们可以编写自己的组件，为游戏对象添加自定义行为（behavior），这就是其中「behavior」一词的由来。它碰巧用了英式拼写，算是个怪癖。「mono」部分指的是 Unity 当初添加自定义代码支持的方式：它使用了 Mono 项目——一个 .NET 框架的多平台实现。因此得名 `MonoBehaviour`。这是个因为向后兼容而不得不保留的旧名字。

要把 `Clock` 变成 `MonoBehaviour` 的子类型，我们必须修改类型声明，让它扩展那个类型。做法是在类型名后加一个冒号，后面跟它要扩展的类型。这让 `Clock` 继承 `MonoBehaviour` 类类型的所有内容。

```diff
public class Clock : MonoBehaviour {}
```

不过，这会导致编译错误。编译器抱怨找不到 `MonoBehaviour` 类型。这是因为该类型位于一个命名空间（namespace）里，也就是 `UnityEngine`。要访问它，我们必须使用它的全限定名 `UnityEngine.MonoBehaviour`。

```diff
public class Clock : UnityEngine.MonoBehaviour {}
```

> **什么是命名空间？**
>
> 命名空间就像代码里的网站域名。就像域名可以有子域名，命名空间也可以有子命名空间。最大的区别是它反着写。所以不是 forum.unity.com，而是 com.unity.forum。命名空间用来组织代码、防止命名冲突。
>
> 包含 `UnityEngine` 代码的程序集随 Unity 一起提供，你不必单独联网获取。如果你导入了合适的编辑器集成包，代码编辑器使用的项目文件应该会自动配置好以识别它。

在访问 Unity 类型时总是带上 `UnityEngine` 前缀很不方便。幸运的是，我们可以声明：在 C# 文件中应自动搜索某个命名空间来补全类型名。做法是在文件顶部添加 `using UnityEngine;`。分号是必需的，用来标记语句结束。

```diff
+using UnityEngine;

public class Clock : MonoBehaviour {}
```

现在我们可以把自定义组件添加到 Unity 里的 *Clock* 游戏对象上了。这可以通过把脚本资源拖到对象上，或通过对象检视窗口底部的 *Add Component* 按钮来完成。

![带我们 Clock 组件的 Clock 游戏对象。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/clock-with-component.png)

注意，我教程里的大多数代码类型都链接到在线文档。例如 `MonoBehaviour` 就是一个链接，会把你带到该类型的 Unity 在线脚本 API 页面。

### 拿到一根指针

要旋转指针，`Clock` 对象需要知道它们。我们先从时针开始。和所有游戏对象一样，它可以通过调整 `Transform` 组件来旋转。所以我们必须让 `Clock` 知道指针枢轴的 `Transform` 组件。做法是在它的代码块里添加一个数据字段（field），定义方式是「名字 + 分号」。

字段名用 `hours pivot` 很合适。但是名字必须是单个词。惯例是把字段名的第一个词小写，其余词首字母大写，然后把它们拼在一起。所以命名为 `hoursPivot`。

```diff
public class Clock : MonoBehaviour {

+	hoursPivot;
}
```

> **using 语句去哪了？**
>
> 它还在那里，只是我没显示出来。代码片段会包含足够的现有代码，好让你知道更改的上下文。

我们还必须声明字段的类型，这里是 `UnityEngine.Transform`。它要写在字段名的前面。

```diff
+	Transform hoursPivot;
```

现在我们的类定义了一个字段，它可以持有对另一个对象的引用，其类型必须是 `Transform`。我们必须确保它持有的是时针枢轴 `Transform` 组件的引用。

字段默认是私有的（private），也就是说只有属于 `Clock` 的代码才能访问它们。但类并不知道我们的 Unity 场景，所以没有直接的办法把这个字段和正确的对象关联起来。我们可以通过把字段声明为可序列化（serializable）来改变这一点。这意味着当 Unity 保存场景时，它应该被包含进场景数据里——Unity 的做法是把所有数据排成一个序列（序列化）然后写入文件。

把字段标记为可序列化，是通过给它附加一个特性（attribute），这里是 `SerializeField`。它写在字段声明前面，放在方括号之间，通常独占一行，但也可以放在同一行。

```diff
+	[SerializeField]
	Transform hoursPivot;
```

> **难道不能直接把它设为 public 吗？**
>
> 可以，但通常让类的字段公开可访问是不好的做法。经验法则是：只有当其他类型的 C# 代码需要访问时，才把类成员设为 public，而且此时优先用方法或属性而非字段。成员越难被访问，就越容易维护，因为可能直接依赖它的代码越少。本教程里我们唯一的 C# 代码就是 `Clock`，所以没有理由把它的成员设为 public。

一旦字段可序列化，Unity 就会检测到它，并把它显示在我们 *Clock* 游戏对象 `Clock` 组件的检视窗口里。

![Hours Pivot 字段。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/hours-pivot-field.png)

为了建立正确的连接，把 *Hours Arm Pivot* 从层级窗口拖到 *Hours Pivot* 字段上。或者，用字段右侧的圆形按钮，在弹出的列表里搜索这个枢轴。两种情况下，Unity 编辑器都会拿到 *Hours Arm Pivot* 的 `Transform` 组件，并把它的引用放进我们的字段里。

![Hours Pivot 已连接。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/hours-pivot-connected.png)

### 认识三根指针

我们还得对分针和秒针枢轴做同样的事。所以给 `Clock` 再添加两个可序列化的 `Transform` 字段，起合适的名字。

```diff
	[SerializeField]
	Transform hoursPivot;

+	[SerializeField]
+	Transform minutesPivot;

+	[SerializeField]
+	Transform secondsPivot;
```

这些字段声明可以写得更简洁，因为它们共享相同的特性、访问修饰符和类型。可以把它们合并成一个逗号分隔的字段名列表，跟在特性和类型声明之后。

```diff
	[SerializeField]
	Transform hoursPivot, minutesPivot, secondsPivot;

-	//[SerializeField]
-	//Transform minutesPivot;

-	//[SerializeField]
-	//Transform secondsPivot;
```

> **`//` 是干什么的？**
>
> 双斜杠表示注释（comment）。从它之后到行尾的所有文本都会被编译器忽略。它用来给代码加说明文字（如果需要的话）。我也用它来表示已被移除的代码。此外，被删除的代码还会有一条删除线。

在编辑器里把另外两根指针也连接好。

![三个枢轴都已连接。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/all-pivots-connected.png)

### 苏醒（Awake）

现在我们能访问指针枢轴了，下一步是旋转它们。为此，我们需要告诉 `Clock` 执行一些代码。做法是往类里添加一个代码块，称为方法（method）。这个代码块前面要加一个名字，惯例是首字母大写。我们命名为 `Awake`，暗示这段代码应该在组件苏醒时执行。

```diff
public class Clock : MonoBehaviour {

	[SerializeField]
	Transform hoursPivot, minutesPivot, secondsPivot;

+	Awake {}
}
```

方法有点像数学函数，比如 `f(x) = 2x + 3`。那个函数接收一个数——由变量参数 `x` 表示——把它翻倍，再加三。它作用于单个数字，结果也是单个数字。而方法更像是 `f(p) = c`，其中 `p` 表示输入参数，`c` 表示它执行的任意代码。

和数学函数一样，方法可以产生结果，但这不是必需的。我们必须声明结果的类型——就像声明字段一样——或者写 `void` 表示没有结果。我们这里只想执行一些代码而不提供结果值，所以用 `void`。

```diff
+	void Awake {}
```

我们也不需要任何输入数据。不过，我们仍然必须定义方法的参数，作为圆括号之间的逗号分隔列表。我们这里只是一个空列表。

```diff
	void Awake () {}
```

现在我们有了一个合法的方法，尽管它还没做任何事。就像 Unity 检测到我们的字段一样，它也会检测这个 `Awake` 方法。当一个组件有 `Awake` 方法时，Unity 会在组件苏醒时调用它。这发生在播放模式下它被创建或加载之后。我们现在处于编辑模式，所以还不会发生。

> **Awake 难道不应该是 public 的吗？**
>
> `Awake` 和一批其他方法被视为特殊的 Unity 事件方法。Unity 引擎会找到它们，并在合适的时机调用它们，无论我们如何声明。这是从受管 .NET 环境之外发起的。

注意，`Awake` 和其他特殊 Unity 事件方法在我的教程里是粗体字，并链接到它们的在线 Unity 脚本 API 页面。

### 用代码旋转

要旋转指针，我们必须创建一个新的旋转。我们可以通过给 `Transform` 的 `localRotation` 属性赋一个新值来改变它的旋转。

> **什么是属性（property）？**
>
> 属性是一个假装成字段的方法。它可以是只读的或只写的。C# 惯例是把属性首字母大写，但 Unity 的代码没有这么做。

尽管 `Transform` 组件的旋转在检视窗口里是用每轴的欧拉角（度）来定义的，但在代码里我们必须用四元数（quaternion）。

> **什么是四元数？**
>
> 四元数基于复数，用来表示 3D 旋转。虽然它比分开的 X、Y、Z 旋转角组合更难理解，但它有一些有用的特性。例如，它不会遇到万向锁（gimbal lock）。

我们可以通过调用 `Quaternion.Euler` 方法来基于欧拉角创建一个四元数。在 `Awake` 里写下它，后面加分号结束语句。

```diff
	void Awake () {
+		Quaternion.Euler;
	}
```

这个方法有一些参数，用来描述期望的旋转。这里我们提供一个逗号分隔的、包含三个实参的列表，全部放在方法名后的圆括号之间。我们提供三个数字，分别对应 X、Y、Z 旋转。前两个用 0，Z 旋转用 −30。

```diff
	Quaternion.Euler(0, 0, -30);
```

这次调用的结果是一个 `Quaternion` 结构体（struct）值，包含绕 Z 轴 30° 的顺时针旋转，正好对应我们时钟上的 1 点。

> **什么是结构体（struct）？**
>
> 结构体——structure 的缩写——是一张蓝图，和类一样。区别在于它创建出的东西被当作简单值（比如整数或颜色）来处理，而不是对象。它没有「身份」的概念。定义自己的结构体和定义类一样，只是把 `class` 写成 `struct`。

要把这个旋转应用到时针上，用 `=` 赋值语句把 `Quaternion.Euler` 的结果赋给 `hoursPivot.localRotation`。

```diff
+		hoursPivot.localRotation = Quaternion.Euler(0, 0, -30);
```

> **`localRotation` 和 `rotation` 有什么区别？**
>
> `localRotation` 属性表示 `Transform` 组件单独描述的旋转，因此它是相对于其父对象的旋转，也就是你在它检视窗口里看到的那个旋转。相比之下，`rotation` 属性表示世界空间里的最终旋转，考虑了整个对象层级。如果我们把时钟作为一个整体旋转，设置那个属性会产生奇怪的结果，因为指针会忽略它——那个属性会补偿时钟的旋转。

> **难道不应该有个警告说 hoursPivot 从未初始化吗？**
>
> 编译器能检测到没有代码给这个字段赋任何值，它确实可能发出这样的警告，因为它不知道我们通过 Unity 检视窗口设置过它。不过，这个警告默认被抑制了。抑制可以通过项目设置来控制。在 *Player / Other Settings / Script Compilation* 下有一个 *Suppress Common Warnings* 开关，它会抑制关于未初始化和未使用的私有字段的警告。

现在进入编辑器的播放模式（play mode）。你可以通过 *Edit / Play*、相应的键盘快捷键，或编辑器窗口顶部中央的播放按钮进入。Unity 会把焦点切到游戏窗口，它渲染的是场景中 *Main Camera* 看到的内容。时钟组件会苏醒，时钟会被设置为一点钟。

![播放模式下总是一点钟。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/one-o-clock.png)

如果摄像机没对准时钟，你可以移动它让时钟可见，但要记住：退出播放模式时场景会被重置，所以你在播放模式里对场景做的任何更改都不会保留。不过资源（asset）不是这样，对它们的更改总是会保留。你也可以在播放模式下打开场景窗口——甚至多个场景窗口和游戏窗口。继续之前先退出播放模式。

### 获取当前时间

下一步是在苏醒时弄清当前时间。我们可以用 `DateTime` 结构体来访问所运行设备的系统时间。`DateTime` 不是 Unity 类型，它位于 `System` 命名空间里，是 .NET 框架核心功能的一部分——Unity 就是用 .NET 来支持脚本的。

`DateTime` 有一个 `Now` 属性，能产生一个包含当前系统日期和时间的 `DateTime` 值。为了检查它是否正确，我们会在 `Awake` 开头把它记录到控制台。做法是把它传给 `Debug.Log` 方法。

```diff
+using System;
using UnityEngine;

public class Clock : MonoBehaviour {

	[SerializeField]
	Transform hoursPivot, minutesPivot, secondsPivot;

	void Awake () {
+		Debug.Log(DateTime.Now);
		hoursPivot.localRotation = Quaternion.Euler(0, 0, -30);
	}
}
```

现在每次进入播放模式，我们都会记录一条时间戳。你可以在控制台窗口和编辑器窗口底部的状态栏里看到它。

### 旋转指针

我们离一个能工作的时钟越来越近了。让我们再从小时开始。`DateTime` 有一个 `Hour` 属性，能拿到 `DateTime` 值里的小时部分。在当前时间戳上调用它，就会得到一天中的小时数。

```diff
		Debug.Log(DateTime.Now.Hour);
```

所以，要让时针显示当前小时，我们必须把 −30° 旋转乘以当前小时数。乘法用星号 `*` 字符。我们也不再需要记录当前时间，所以可以删掉那条语句。

```diff
-		//Debug.Log(DateTime.Now.Hour);
		hoursPivot.localRotation = Quaternion.Euler(0, 0, -30 * DateTime.Now.Hour);
```

![播放模式下现在是四点钟。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/four-o-clock.png)

为了明确我们是在把小时转换成度数，可以定义一个 `hoursToDegrees` 字段来存放转换系数。`Quaternion.Euler` 的角度被定义为浮点值，所以我们用 `float` 类型。因为我们已知这个数字，所以可以直接在字段声明里给它赋值。然后在 `Awake` 里乘以这个字段，而不是字面量 `-30`。

```diff
+	float hoursToDegrees = -30;

	[SerializeField]
	Transform hoursPivot, minutesPivot, secondsPivot;

	void Awake () {
		hoursPivot.localRotation =
			Quaternion.Euler(0, 0, hoursToDegrees * DateTime.Now.Hour);
	}
```

> **什么是 float？**
>
> 计算机无法存储所有数字，数字必须能用它的二进制内存来表示——内存由要么是 0 要么是 1 的位（bit）组成。这使得许多数字无法在有限内存里精确存储，比如 ⅓，就像我们无法用十进制记法精确写出它一样。我们最多只能写 0.3333333，然后在某处停下。
>
> 假设我们规定小数点后最多写三位、前面只写一位。那么 ⅓ 就被近似为 0.333。如果我们把 ⅓ 除以 100，就不得不写 0.003，也就是说我们丢掉了两位精度。为了提高小数值的精度，我们加一个单独的指数来表示数字的数量级。那么 `0.333×10^-2` 就能表示 ⅓ 除以 100，同时不丢失有效数字。我们也能用 `0.333×10^2` 表示乘以 100，同时小数点前只保留一位。于是小数点可以被视为「浮动」的，因为它不代表固定的数量级。这样我们只用几个数字就能表示大量数字。
>
> 浮点数对计算机也是同样的道理，只是它用二进制而非十进制数字，还必须表示特殊值，比如无穷大和「非数字」（NaN）。一个 `float` 就是这样用四个字节（即 32 位）存储的值。

如果我们声明一个不带后缀的整数，它会被假定为整数（integer），那是一种不同的值类型。虽然编译器会自动转换，但让我们明确地把所有数字都标记为 `float` 类型——给它们加上 `f` 后缀。

```diff
	float hoursToDegrees = -30f;

	[SerializeField]
	Transform hoursPivot, minutesPivot, secondsPivot;

	void Awake () {
		hoursPivot.localRotation =
			Quaternion.Euler(0f, 0f, hoursToDegrees * DateTime.Now.Hour);
	}
```

每小时对应的度数永远是相同的。我们可以通过在 `hoursToDegrees` 的声明前加 `const` 前缀来强制这一点，这把它从字段变成了常量（constant）。

```diff
+	const float hoursToDegrees = -30f;
```

> **const 值有什么特别之处？**
>
> `const` 关键字表示一个值永远不会变，而且不必是字段。它的值会在编译期计算出来，并替换所有用到该常量的地方。这只能用于数字这样的原始类型。

让我们对另外两根指针做同样的处理，使用 `DateTime` 相应的属性。一分钟和一秒都由负六度的旋转表示。

```diff
	const float hoursToDegrees = -30f, minutesToDegrees = -6f, secondsToDegrees = -6f;

	[SerializeField]
	Transform hoursPivot, minutesPivot, secondsPivot;

	void Awake () {
		hoursPivot.localRotation =
			Quaternion.Euler(0f, 0f, hoursToDegrees * DateTime.Now.Hour);
+		minutesPivot.localRotation =
+			Quaternion.Euler(0f, 0f, minutesToDegrees * DateTime.Now.Minute);
+		secondsPivot.localRotation =
+			Quaternion.Euler(0f, 0f, secondsToDegrees * DateTime.Now.Second);
	}
```

![现在是 5:16:31。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/time-5-16-31.png)

我们用了三次 `DateTime.Now` 来获取小时、分钟和秒。每次都要再走一遍属性，需要一些工作，理论上可能得到不同的时间值。为了确保不发生这种情况，我们应该只获取一次时间。做法是在方法里声明一个变量，把时间赋给它，之后使用这个值。命名为 `time`。

> **什么是变量（variable）？**
>
> 变量的行为像字段，只是它只在方法执行期间存在。它属于方法，而不属于类。

```diff
	void Awake () {
+		DateTime time = DateTime.Now;
		hoursPivot.localRotation =
			Quaternion.Euler(0f, 0f, hoursToDegrees * time.Hour);
		minutesPivot.localRotation =
			Quaternion.Euler(0f, 0f, minutesToDegrees * time.Minute);
		secondsPivot.localRotation =
			Quaternion.Euler(0f, 0f, secondsToDegrees * time.Second);
	}
```

对于变量，可以省略类型声明，用 `var` 关键字代替。这能缩短代码，但只有当变量的类型能从声明时赋给它的值推断出来时才可行。另外，我更倾向于只在语句中明确提到了类型时才这么做，这里正是这种情况。

```diff
+		var time = DateTime.Now;
```

### 让指针动起来

我们在进入播放模式时获取当前时间，但之后时钟就静止不动了。要让时钟和当前时间保持同步，把 `Awake` 方法的名字改成 `Update`。这是另一个特殊事件方法，只要我们在播放模式下，Unity 就会每帧调用它，而不是只调用一次。

```diff
	void Update () {
		var time = DateTime.Now;
		hoursPivot.localRotation =
			Quaternion.Euler(0f, 0f, hoursToDegrees * time.Hour);
		minutesPivot.localRotation =
			Quaternion.Euler(0f, 0f, minutesToDegrees * time.Minute);
		secondsPivot.localRotation =
			Quaternion.Euler(0f, 0f, secondsToDegrees * time.Second);
	}
```

时钟正在更新。

> **什么是帧（frame）？**
>
> 在播放模式下，Unity 会不断地从主摄像机的视角渲染场景。渲染完成后，结果被呈现到显示器上。显示器会一直显示那一帧，直到收到下一帧。在渲染新的一帧之前，一切都会被更新。所以 Unity 经历的是「更新、渲染、更新、渲染……」这样的序列。一次更新步骤加上渲染场景一次，通常被认为是一帧，尽管实际上时间安排更复杂。

注意，我们的 `Clock` 组件在检视窗口里它的名字前面多了一个开关。这允许我们禁用它，从而阻止 Unity 调用它的 `Update` 方法。

![可以被禁用的 Clock 组件。](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/enabled-toggle.png)

### 连续旋转

我们时钟的指针指示的是精确的当前小时、分钟或秒。它的行为像数字时钟——离散的，但用的是指针。通常时钟有缓慢旋转的指针，能模拟（analog）表示时间。让我们改变做法，让时钟变成模拟式的。

`DateTime` 不包含小数数据。幸运的是，它确实有一个 `TimeOfDay` 属性。这会给我们一个 `TimeSpan` 值，它通过 `TotalHours`、`TotalMinutes` 和 `TotalSeconds` 属性，以我们需要的格式包含数据。

先获取 `DateTime.Now` 的 `TimeOfDay` 结构体值，把它存进变量里。因为这条语句里没提到 `TimeSpan` 类型，我会把变量的类型明确写出来。然后调整我们用来旋转指针的属性。

```diff
	void Update () {
+		TimeSpan time = DateTime.Now.TimeOfDay;
		hoursPivot.localRotation =
			Quaternion.Euler(0f, 0f, hoursToDegrees * time.TotalHours);
		minutesPivot.localRotation =
			Quaternion.Euler(0f, 0f, minutesToDegrees * time.TotalMinutes);
		secondsPivot.localRotation =
			Quaternion.Euler(0f, 0f, secondsToDegrees * time.TotalSeconds);
	}
```

这会导致编译错误，抱怨无法从 `double` 转换到 `float`。这是因为 `TimeSpan` 的属性产生的是双精度浮点类型的值，即 `double`。这些值比 `float` 精度更高，但 Unity 的代码只使用单精度浮点值。

> **单精度够用吗？**
>
> 对大多数游戏来说，够。只有当处理非常大的距离或尺度差异时才成问题。那时你就得用一些技巧，比如传送或「摄像机相对渲染」（camera-relative rendering），让活动区域保持在世界原点附近。虽然用双精度能解决这个问题，但它也会让相关数字的内存占用翻倍，从而带来其他性能问题。游戏引擎通常使用单精度浮点值，GPU 也是。

我们可以通过显式地从 `double` 转换到 `float` 来解决这个问题。这个过程称为强制转换（casting），做法是在要转换的值前面，用圆括号写上新的类型。

```diff
		hoursPivot.localRotation =
			Quaternion.Euler(0f, 0f, hoursToDegrees * (float)time.TotalHours);
		minutesPivot.localRotation =
			Quaternion.Euler(0f, 0f, minutesToDegrees * (float)time.TotalMinutes);
		secondsPivot.localRotation =
			Quaternion.Euler(0f, 0f, secondsToDegrees * (float)time.TotalSeconds);
```

模拟时钟。
