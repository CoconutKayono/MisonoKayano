# B04｜顶点读取、图元处理与面剔除

> 核心问题：索引缓冲怎样成为三角形？GPU 为什么认为某一面是背面，修改法线为什么通常救不回被剔除的面？
>
> 结论：索引与拓扑定义几何连接，顶点程序输出决定投影位置，投影后的绕序与正面约定决定面朝向。普通着色法线不会直接参与固定功能面剔除。

本卡讨论 Unity 普通索引化 Triangle List、VS→光栅化路径；不含曲面细分、几何 Shader、Mesh Shader、保守光栅化和蒙皮的完整机制。文档基线 Unity 6.7 Beta / 6000.7（2026-06-26）；示例公共 HLSL 参考 Graphics `275a7f9ad9330e3cf7f3ea57a0b242a551fde291`，Core/URP 17.0.4。

## 1. 读取的是一套顶点属性

一个顶点记录可包含 Position、Normal、UV 等属性。**索引**选择记录；**拓扑**规定怎样组织选中的记录；**stride** 是相邻记录起点的字节间距；**offset** 是某属性在记录内的偏移。

若存储索引为 `i`，基顶点为 `b`，单流步长为 `s`，某属性偏移为 `o`，其简化地址为：

$$address=bufferBase+(i+b)s+o$$

例如 `bufferBase=1000`、`i=3`、`b=10`、`s=32`、`o=24`，属性地址为 `1440`。格式还规定这些字节应解释为 float、归一化整数等，不能仅凭地址推断含义。

Triangle List 每三个索引描述一个三角形：`[0,1,2, 2,1,3]` 描述两个三角形，共 6 个索引、至多 4 个不同记录。Strip 等拓扑有不同连接和绕序规则，不能沿用这个计数公式。

重复索引可能复用顶点处理结果，但硬件与驱动的复用不是“每个索引必跑一次 VS”或“每个唯一索引永远只跑一次 VS”的绝对规则。跨 Draw、跨 Pass 更不能凭索引相同推定免费复用。

## 2. 逻辑执行链与实际优化顺序

```mermaid
flowchart LR
    A[索引/顶点布局与拓扑] --> B[顶点属性读取与 VS]
    B --> C[按连接关系得到裁剪空间图元]
    C --> D[裁剪/投影/朝向与覆盖准备]
    D --> E[光栅化产生片元输入]
    E --> F[片元着色及后续测试输出]
```

图中把需要先理解的依赖展开，不主张每种 GPU 都按图逐块串行执行。实际硬件可以融合、提前拒绝或利用缓存；API 约束的是可见行为。

VS 通常输出齐次裁剪坐标 `C=(x,y,z,w)`。在有效投影条件下，透视除法给出 `(x/w,y/w,z/w)`；视口再映射到目标坐标。**不能先对越过相机平面的任意顶点直接除 w，再把异常巨大三角形当作正常输入。** 裁剪应基于齐次几何及对应 API 规则。

以常见 D3D 默认深度裁剪规则为例，相关范围包括 `-w≤x≤w`、`-w≤y≤w`、`0≤z≤w`，实际可有 guard band 和深度裁剪状态差异。OpenGL 类深度约定不同，Unity 还会按后端调整投影，不能把一个 API 的不等式抄成所有平台规则。[D3D 光栅状态与裁剪](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ns-d3d11-d3d11_rasterizer_desc)

裁剪也不等于“一个顶点在外，整三角形删除”。跨过一个裁剪平面的三角形可能保留一个三角形或成为四边形区域，再由后续实现处理覆盖。例如二维三角形 `(-1,0),(1,-1),(1,1)` 按半平面 `x≥0` 裁剪，保留四边形 `(0,-0.5),(1,-1),(1,1),(0,0.5)`，面积为 1.5。这个二维截面练习只说明几何关系，不替代真实齐次裁剪实现。

## 3. 正面判断看绕序，不看 NORMAL

在已明确坐标轴方向的二维平面，设三个投影点为 `P₀,P₁,P₂`，有向二倍面积为：

$$A_2=(x_1-x_0)(y_2-y_0)-(y_1-y_0)(x_2-x_0)$$

当 x 向右、y 向上，`A₂>0` 表示逆时针，`A₂<0` 表示顺时针。若改为 y 向下，符号解释反转；具体 API 还具有自己的 front-face 状态。因此不能在截图上看到“顺时针”就忽略坐标系与引擎转换。

例如 `(0,0),(1,0),(0,1)` 的 `A₂=1`；交换后两个点，得到 `-1`。保持位置不变、把三个顶点法线都乘 `-1`，面积仍为 1。**这就是“翻法线不等于翻面”的反例。**

Unity 常规 Mesh 按其绕序约定构造正面；到底哪个三角形在目标上被标为正面，应结合 VS 输出、投影和前面状态核对。D3D 的 `FrontCounterClockwise` 明确控制这种解释，不能认为硬件永远固定某一符号为正。[D3D 正面约定](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ns-d3d11-d3d11_rasterizer_desc)

`A₂=0` 是二维退化情况，没有普通面积覆盖。有限精度、小三角形与具体光栅规则会影响实际覆盖；此处不声称能用 CPU 浮点面积函数逐像素复制硬件结果。

## 4. Cull 与其他“消失原因”

| 状态或机制 | 主要判断对象 |
| --- | --- |
| CPU/SRP 可见性剔除 | 对象边界、视锥、层等 |
| 齐次裁剪 | 图元与裁剪体 |
| `Cull Back/Front/Off` | 投影朝向与正面约定 |
| 深度测试 | 样本深度与已有深度 |
| `clip/discard` | Shader 中的条件 |

Unity 的 `Cull Back` 去掉背面，`Cull Front` 去掉正面，`Cull Off` 不按面朝向剔除。关闭 Cull 不会关闭视锥裁剪或深度测试，也不会修复 NaN 位置。[Unity Cull](https://docs.unity3d.com/6000.0/Documentation/Manual/SL-Cull.html)

镜像变换可改变绕序；普通负缩放还可能触发引擎的朝向处理，不能把所有情况下的结果只归结为一个行列式符号。下面在 VS 中显式翻转裁剪空间 x，避免把这个实验混同于 Unity Transform 负缩放的自动处理。

## 5. 完整实验：分别翻索引、翻法线、翻投影

在空测试场景创建空对象，挂 `B04TriangleLab.cs`，给自动添加的 MeshRenderer 赋一个使用后附 Shader 的材质。进入 Play Mode 后，从组件菜单执行 `Rebuild Triangle` 应用两个布尔参数。脚本只管理自己的临时 Mesh，并在销毁时恢复原先 Mesh 引用。

```csharp
using UnityEngine;

[RequireComponent(typeof(MeshFilter), typeof(MeshRenderer))]
public class B04TriangleLab : MonoBehaviour
{
    public bool reverseIndices;
    public bool reverseNormals;
    Mesh ownedMesh;
    Mesh previousMesh;
    MeshFilter filter;
    void Start()
    {
        filter=GetComponent<MeshFilter>();
        previousMesh=filter.sharedMesh;
        ownedMesh=new Mesh { name="B04 Owned Triangle" };
        filter.sharedMesh=ownedMesh;
        Rebuild();
    }
    [ContextMenu("Rebuild Triangle")]
    public void Rebuild()
    {
        if (!Application.isPlaying || ownedMesh==null)
        {
            Debug.LogWarning("Enter Play Mode before rebuilding.");
            return;
        }
        ownedMesh.Clear();
        ownedMesh.vertices=new Vector3[] {
            new Vector3(-0.7f,-0.6f,0),
            new Vector3(0,0.7f,0),
            new Vector3(0.7f,-0.6f,0) };
        Vector3 n=reverseNormals ? Vector3.back : Vector3.forward;
        ownedMesh.normals=new Vector3[] { n,n,n };
        ownedMesh.triangles=reverseIndices ? new int[] {0,2,1} : new int[] {0,1,2};
        // Shader uses clip-space positions; a generous bound keeps this lab visible.
        ownedMesh.bounds=new Bounds(Vector3.zero,Vector3.one*10000);
    }
    void OnDestroy()
    {
        if (filter!=null && filter.sharedMesh==ownedMesh)
            filter.sharedMesh=previousMesh;
        if (ownedMesh!=null) Destroy(ownedMesh);
    }
}
```

保存 Shader 为 `B04FacingLab.shader`。采用普通 URP Forward，相机位于世界原点附近，关闭遮挡剔除、Depth Priming、SSAO、额外 Renderer Feature、后处理和 XR。位置由 Shader 直接送入裁剪空间，所以画面不随对象移动；巨大 bounds 只是本实验避免 CPU 视锥剔除的脚手架，生产 Mesh 应有准确边界。

```shaderlab
Shader "Encyclopedia/B04FacingLab"
{
    Properties
    {
        [Enum(UnityEngine.Rendering.CullMode)] _Cull("Cull", Float)=0
        [Toggle] _ShowNormals("Show Input Normals", Float)=0
        [Toggle] _MirrorX("Mirror Clip X", Float)=0
    }
    SubShader
    {
        Tags { "RenderPipeline"="UniversalPipeline" "RenderType"="Opaque" }
        Pass
        {
            Tags { "LightMode"="UniversalForward" }
            Cull [_Cull]
            ZTest Always
            ZWrite Off
            HLSLPROGRAM
            #pragma target 3.0
            #pragma vertex Vert
            #pragma fragment Frag
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
            CBUFFER_START(UnityPerMaterial)
                float _Cull;
                float _ShowNormals;
                float _MirrorX;
            CBUFFER_END
            struct A { float3 p:POSITION; float3 n:NORMAL; };
            struct V { float4 p:SV_POSITION; float3 n:TEXCOORD0; };
            V Vert(A input)
            {
                V output;
                float x=_MirrorX>0.5 ? -input.p.x : input.p.x;
                output.p=float4(x,input.p.y,0.5,1);
                output.n=input.n;
                return output;
            }
            half4 Frag(V input, FRONT_FACE_TYPE facing:FRONT_FACE_SEMANTIC):SV_Target
            {
                float3 faceColor=IS_FRONT_VFACE(facing,float3(0,1,0),float3(1,0,0));
                float3 normalColor=input.n*0.5+0.5;
                return half4(_ShowNormals>0.5 ? normalColor : faceColor,1);
            }
            ENDHLSL
        }
    }
}
```

默认 Cull=Off，绿色表示 API 报告的正面、红色表示背面。**先观察基准颜色，不跨 API 预写“初始必绿”。** Show Input Normals 显示输入法线映射色；本例法线恒为单位 ±Z，不是一个通用法线贴图 Shader。

| 修改 | 预测 |
| --- | --- |
| 只翻 Reverse Normals 并重建 | 正反面颜色不变；法线视图变色 |
| 只翻 Reverse Indices 并重建 | 正反面颜色互换；法线视图不变 |
| 只翻 Mirror Clip X | 几何镜像、正反面颜色互换 |
| 同时翻索引和 Clip X | 两次翻转恢复原先朝向 |
| 根据已观察朝向选择 Cull Back 或 Front | 对应一侧消失；Cull Off 时恢复 |

前面宏由 Core 的平台头文件提供；[固定提交 D3D11.hlsl](https://github.com/Unity-Technologies/Graphics/blob/275a7f9ad9330e3cf7f3ea57a0b242a551fde291/Packages/com.unity.render-pipelines.core/ShaderLibrary/API/D3D11.hlsl) 可查看 `FRONT_FACE_TYPE`、`FRONT_FACE_SEMANTIC` 与 `IS_FRONT_VFACE`。本例通过平台宏读取朝向，避免假设每个后端使用同一种 VFACE 数据类型。

## 6. NPR 应用、自测与证据范围

反壳描边通常扩张几何并绘制所需朝向的一侧。若接缝、镜像或 Cull 状态不一致，描边可以局部消失；仅重算法线未必修复。反过来，双面着色关闭 Cull 后，还需按材质设计决定背面法线如何用于光照，关闭剔除本身不会自动完成双面光照。

自测：① 法线乘 -1 必然翻面吗？**普通几何位置不变时不会。** ② 一个顶点在裁剪体外就删除整个三角形吗？**不一定。** ③ Cull Off 后一定看得见吗？**还有对象剔除、裁剪、深度和其他机制。** ④ 6 个索引必然执行 6 次 VS 吗？**不能从数量直接确定。**

Python 检查地址、Triangle List、面积符号、双翻转与一个跨平面裁剪反例；它不实现硬件光栅化或预测精确覆盖。C#/Shader 尚未在 Unity 编译、运行或抓帧。本地参考根目录为 `E:\Claude Skills\学习仓库\09_Unity官方文档\Documentation\en`，核对 `Manual/SL-Cull.html`；顶点数据接口另参考 [Mesh.cs 固定提交](https://github.com/Unity-Technologies/UnityCsReference/blob/9d487cab41b00c50af020b56d27a3c768d54f770/Runtime/Export/Graphics/Mesh.cs)。
