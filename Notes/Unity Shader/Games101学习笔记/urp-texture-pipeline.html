01 /

纹理管线，究竟在传递什么？

先建立一个模型：纹理是一份可以被 GPU 查询的数据，而不是一张会自己贴到物体上的图片。

导入设置决定数据怎样保存，UV 决定查询位置，采样器决定怎样读取，Shader 决定数值的含义，URP 决定何时绘制，以及怎样组织光照与输出。

下面是一份纹理从磁盘到画面的路径。点击每个节点，查看它处理什么，以及它没有替你处理什么。

01 · 源文件：创作与交换的载体

PNG、TGA、EXR 保存美术或程序生成的源数据。图里的 RGB 可以是颜色，也可以是金属度、遮罩或法线编码。文件扩展名和图像外观并不能决定 Shader 怎样使用它。

输入：创作工具输出 / 输出：可导入的资源文件
编辑器与构建阶段运行时：加载阶段 + 每帧绘制阶段

再倒过来，追踪一块屏幕像素

网格顶点 UV→光栅化与插值→Shader 采样→表面属性→光照 / 后处理→显示像素

一个三角形覆盖屏幕时，GPU 生成片元，并把顶点上的 UV 插值给它们。片元 Shader 用这些 UV 查询纹理，得到颜色、法线或其他参数。Lit Shader 再结合灯光、阴影与环境计算画面。一个屏幕像素可能接收多个片元、样本或透明层；片元并不总与最终显示像素一一对应。

Texture · 数据

例如一张木纹 Base Color。纹理资源本身不知道什么是“木材”。

Material · 配置

指定 Shader，绑定纹理与颜色、平铺等参数。多个材质可以共享同一纹理。

Shader · 计算规则

决定读哪个通道、怎样解码，以及读出的数值如何参与最终计算。

“纹理管线”与“URP 渲染管线”的关系：前者描述资源如何被准备并采样；后者组织相机剔除、绘制 Pass、光照、Render Target 与后处理。纹理流程嵌入 URP，但也广泛适用于其他渲染管线。

依据：纹理导入URP 相机与渲染循环

02 /

源图片，不等于 GPU 纹理

PNG 的体积取决于文件压缩。GPU 纹理的体积主要取决于导入后分辨率、运行时格式与 mip 级别。

将图片放入 Assets 后，Unity 的 Texture Importer 根据导入设置生成引擎可用的数据；构建时使用目标平台的设置。运行时加载资源，再建立并上传 GPU 可使用的纹理。正常情况下，每次绘制是绑定并读取已有资源，整张图片并不会每帧重新从磁盘上传。动态纹理更新与 Mipmap Streaming 则可能在运行中改变部分数据的驻留。

导入项它影响什么学习时的判断方法
Texture TypeUnity 如何解释与处理资源。基础色或数值图通常选 Default；切线空间法线选 Normal Map；UI 精灵用 Sprite。
sRGB (Color Texture)在线性项目中，采样 RGB 时是否做 sRGB → Linear 转换。先问“这是颜色还是数值”。不要通过看起来亮不亮来决定。
Max Size / 平台覆盖最终导入尺寸、格式与压缩质量。原图 4096 不意味着构建里也是 4096。检查当前目标平台。
Generate Mipmap生成逐级缩小的纹理版本。用于会缩小、会远离相机的 3D 表面。固定像素尺寸的 UI 要结合实际缩放判断。
Wrap / Filter / Aniso默认寻址和过滤规则。平铺用 Repeat；边缘贴图常用 Clamp。采样器也可能由 Shader 显式指定。
Read/Write是否为 CPU 脚本访问保留额外像素数据副本。普通 Shader 采样通常不需要开启；需要 CPU 读写的 API 才按需求保留。
Stream Mipmap Levels允许系统按需要加载 mip 级别。需同时启用纹理 mip 与 Quality 中的 Mipmap Streaming；还要检查预算和使用方式。

三种“压缩”要分开理解

文件压缩：便于存储与传输

PNG、JPEG 是源文件格式，GPU 不会直接按 PNG 文件结构做纹理过滤。JPEG 的损失也不会因导入为高质量格式而恢复。

构建 / 下载数据压缩

例如资源包压缩和 Crunch。Crunch 在 DXT / ETC 数据上增加磁盘压缩，加载时在 CPU 端还原为对应的 GPU 格式。

GPU 块压缩：便于驻留与采样

BC、ETC2、ASTC 把固定区域编码为块。受支持的 GPU 能使用这些数据，不需要先把整张纹理解压成 RGBA32。格式、块大小与质量会影响细节、色带、法线和 Alpha。

格式必须匹配目标设备；不支持时可能触发解压回退，增加加载和内存成本。

例子：2048 × 2048 的 RGBA32 原级约占 16 MiB，不论源 PNG 是 300 KB 还是 8 MB；完整 mip 链约 21.33 MiB。BC7 原级约 4 MiB。这里算的是 GPU 纹理数据，不包含 CPU 副本与驱动对齐。

依据：ImporterDefault 设置平台覆盖GPU 格式与 Crunch

03 /

一次采样 = 数据 + 坐标 + 规则

纹理中的一个数据单元叫 texel（纹素）。屏幕上的数据单元叫 pixel（像素）。纹理分辨率与屏幕分辨率并不相同，所以一次采样经常需要选择或混合纹素。

UV 通常是归一化的二维坐标。对于一张 8 × 8 纹理，第一个纹素中心大约在 (0.0625, 0.0625)。UV 可以小于 0 或大于 1；Sampler 决定超出范围时如何处理，以及坐标位于纹素之间时怎样插值。

uv' = uv × Tiling + Offset

Wrap 管位置

Repeat：循环平铺。例如 U = 1.2 对应 0.2。
Clamp：固定在边界，超出后沿用边缘纹素。
Mirror：交替镜像，U = 1.2 对应 0.8。

Clamp 不会替图集里的每个小区域自动隔离边缘。Atlas 中仍可能需要 padding、边缘扩展与合适的 mip 生成。

Filter 管混合

Point：选择一个纹素，像素风常用。
Bilinear：同一个 mip 内插值。
Trilinear：两个相邻 mip 内各做插值，再跨 mip 混合。
Anisotropic：改善斜视时拉长采样足迹的过滤质量，例如远处地面；成本需在设备上测量。

04 /

远处的纹理，为什么会闪烁？

当一个屏幕像素覆盖许多纹素时，只读其中几个点就可能错过大量细节。摄像机稍微移动，采样点读到的黑白纹素变化很大，画面就会出现锯齿、摩尔纹与闪烁。这是缩小采样的混叠。

Mip Map 提前生成低分辨率版本。2048² 的纹理依次变成 1024²、512²……直到 1²。小版本包含经过过滤的细节，适合覆盖范围较大的查询。约定是 mip 0 为最高分辨率，数字越大，分辨率越低。

Mip 选择与 mip 驻留，是两件事

GPU 采样时选择某一级，不意味着其他级别自动从显存消失。对两维持续减半的大尺寸二维纹理，完整 mip 链总数据量约为原级的 1 + 1/4 + 1/16 + … ≈ 4/3，也就是增加约 33%。极窄纹理与块压缩的小 mip 会偏离这个近似，后面的计算器按每级实际数据量求和。使用适当 mip 通常改善缓存局部性、带宽和稳定性，但额外存储仍然存在。

Mipmap Streaming 才负责按需求控制哪些级别驻留。它根据相机、网格 UV 分布和预算加载所需 mip；共用纹理需要满足使用者中的较高分辨率需求。预算不足、相机突然切换或高 mip 尚未加载时，画面可能暂时较糊。

开启路径：Project Settings → Quality → Mipmap Streaming，再给纹理开启 Generate Mipmap 与 Stream Mipmap Levels。自定义 UV、非 UV0、某些非标准 Renderer 与运行时网格可能需要额外处理。使用前核对对应版本的限制，不能假定所有纹理都自动有效。

依据：Mipmaps 与导数Streaming 原理启用方式与限制

04A /

三线性过滤：在两个 mip 之间平滑过渡

What：两次层内双线性插值，再加一次层间线性插值。Why：避免选中 mip 改变时突然切换清晰度。How：用连续 LOD 的小数部分分配两层权重。

What · 第三条“线”是 mip 级别

在本文的 2D 纹理语境中，Trilinear 可以理解为沿 U、V、mip 级别三个方向进行线性插值。每个 mip 里先进行双线性过滤，分别得到 Bₖ 和 Bₖ₊₁，再按 LOD 的小数部分混合这两个结果。这里的“三”不是 RGB 三个通道，也不是三张纹理。

定义依据：D3D11.3 规范 §7.18.8–7.18.10。3D 体纹理也有“空间三线性插值”，沿 X/Y/Z 混合 8 个体素；这是另一种语境。

Why · 双线性为什么仍然会出现切层？

双线性解决的是一个 mip 内部纹素之间的插值。如果采样器在 mip 级别之间采用最近层选择，LOD 从约 2.49 变为 2.51 时，就可能从 mip 2 切到 mip 3。两层细节含量不同，远处地面可能出现一条清晰度变化带，或者运动时突然变糊。

三线性在 LOD = 2.25 时取约 75% mip 2 + 25% mip 3，在 2.75 时变为约 25% mip 2 + 75% mip 3。权重连续变化，使切层更平滑。它不会凭空恢复丢失的细节，也不能改变斜视时足迹被拉长的事实。

注意两个动作：生成 mip是准备数据；Trilinear是读取数据时混合相邻级别。已有同一完整 mip 链时，把 Bilinear 改为 Trilinear，通常不会再生成第二份纹理链。

How · 从连续 LOD 到最终读值

  1. 先估计纹理在屏幕上的缩小程度。普通片元采样使用屏幕空间 UV 导数。一个常见的各向同性教学近似如下，W/H 为基础层尺寸：
    gₓ = ddx(uv) × (W, H)
    gᵧ = ddy(uv) × (W, H)
    ρ ≈ max(length(gₓ), length(gᵧ))
    λ ≈ log₂(max(ρ, ε)) + LOD Bias

    当 ρ ≈ 4，LOD 约为 2；当 ρ ≈ 8，约为 3。这是理解尺度的近似，真实 GPU 有自己的精度、限幅和实现规则；导数来自局部屏幕变化，并非仅由物体距离决定。

  2. 在可访问范围内处理 LOD，选择两层。简化写成 k = floor(λ)、t = λ − k。读取 mip k 和 k+1；超出 mip 范围时受限幅约束。放大情况还受 magnification 设置控制，不能无限往“负 mip”读取。
  3. 分别在每一层做双线性。对 mip k 的尺寸 Wₖ/Hₖ，先把 UV 转到纹素中心坐标：
    xₖ = u × Wₖ − 0.5；yₖ = v × Hₖ − 0.5
    fᵤ = fract(xₖ)；fᵥ = fract(yₖ)
    Bₖ = (1−fᵥ)[(1−fᵤ)C₀₀ + fᵤC₁₀]
    　 + fᵥ[(1−fᵤ)C₀₁ + fᵤC₁₁]

    在 k+1 层重新计算坐标、四个邻居和权重，得到 Bₖ₊₁。两层的 fᵤ/fᵥ 一般不同，不能直接把同一套局部权重重复使用。

  4. 按层间权重组合。C = lerp(Bₖ, Bₖ₊₁, t)。RGB、Alpha 或其他可过滤数值各分量遵循相应过滤规则；下方实验用单个线性标量，便于看清数学。

Unity / URP 中怎样使用？

选择纹理，开启 Generate Mipmap，将 Filter Mode 设为 Trilinear，然后 Apply。普通 SAMPLE_TEXTURE2D 会使用其采样器状态；若 Shader 明确使用其他 Sampler，Importer 的默认过滤方式可能不会生效。这里改变的是纹理读取规则，不是给 URP 额外添加一遍光照 Pass。

“三线性”是不是把图像生成了三份？
不是。它在已存在的 mip 链里取相邻两级。标准 2D mip 链的存储开销来自各级图像；三线性本身不要求再保存三套图像。
最多 8 个纹素，是否等于 8 次 HLSL Sample 或 8 次显存读取？
不是。一条采样指令可以让纹理单元完成过滤。8 是概念支持范围，某些权重可为零；缓存、压缩块、访问合并和硬件并行会影响实际读取与时间。不能据此断言它一定比双线性慢两倍。
为什么 Trilinear 开了，斜着看地面仍然糊？
它平滑了 mip 层间过渡，但没有充分匹配拉长的采样足迹。依据长边选 mip 时，短方向可能平均过宽。这是下一节各向异性过滤针对的问题。
不开 Generate Mipmap，只选 Trilinear 有效吗？
只有一个可访问层时，没有相邻级别可混合，无法获得完整 mip 过渡效果。Filter Mode 并不等于生成 mip；运行时创建的纹理也要检查是否实际创建并填充了 mip 链。
负 LOD Bias 可以让画面更清楚，为什么不一直调得很低？
它偏向更高分辨率 mip，可能造成欠过滤、远处闪烁、摩尔纹、缓存与带宽压力。先检查纹理尺寸和足迹形状，再测适当 Bias。斜视问题通常应先考虑 AF，而非强迫每个方向都用过高分辨率。
它比双线性“更高级”，是否所有纹理都应该开启？
需要平滑 mip 过渡的表面受益较明显。固定像素尺寸的 UI、像素风、特殊数值纹理要按需求选择；某些格式也不支持普通线性过滤。先观察画面，再在目标设备测成本。

04B /

各向异性：匹配“长而窄”的采样足迹

What：不同方向使用不同过滤尺度。Why：斜视表面时，一个屏幕像素覆盖的纹理范围会被拉长。How：估计方向与长宽比，在现有 mip 上组合多个过滤样本。

先回应你的笔记。你提供的语雀文章在 RipMap 之后讨论“3 倍空间”，并说明各向异性过滤是一类方法。这一区分是关键。需要进一步精确的是：完整二维 Ripmap 额外约增加 3 倍，总量约为原图的 4 倍；Mipmap 额外约增加 1/3，总量约为 4/3 倍。Unity 常规 Aniso Level 并不要求导入完整 Ripmap。

What · “各向异性”描述的是哪个空间？

这里谈的是纹理空间的采样足迹。屏幕上一个小像素区域，通过 UV 映射落到纹理上，正面观察时两个方向的覆盖尺度可能接近；斜看地面时，可能在一个方向覆盖 16 个原级纹素，另一个方向只有 2 个。尺度随方向不同，就是各向异性。

Why · 三线性已经抗混叠，为什么仍不够？

对一个约 16 × 2 texel 的足迹，普通各向同性 mip 选择只能使用一个统一尺度。按长方向 16 选择较低分辨率 mip，可以抑制长方向混叠，但短方向也被按约 16 的尺度平均，于是短方向本可保留的细节被模糊。若只按短方向 2 选更清晰 mip，长方向又平均不足。

AF 的思路是：用多个较小的过滤样本沿长方向覆盖，尽量把短方向的过滤范围维持在所需尺度。三线性关注“级别之间的平滑过渡”，AF 关注“方向不同的足迹”。两者经常一起使用。

How · 在现有 Mipmap 上组合样本

  1. 从 UV 导数估计足迹。根据纹理尺寸换算为 texel 单位，判断长方向、短方向及拉长程度。通常由 GPU 采样系统完成，并非要求你在每个片元中手写完整逆投影矩阵。
  2. 受最大各向异性比例限制，选择过滤尺度。上限越高，可以处理更细长的足迹；上限不足时，通常需要增大过滤尺度，接受更多模糊，以限制采样工作量。
  3. 沿长方向组合过滤样本。每个样本可在已有 mip 里做层内过滤，也可结合层间混合。位置、权重、样本数与近似方式由硬件及 API 实现决定。
  4. 返回一个采样结果。你仍可能只写一条 Sample；纹理单元在内部做更多工作。不能把一条 Shader 指令当成一次单纹素外部显存访问。
教学模型：L ≥ S ≥ 1；最大比例 Aₘₐₓ
A = min(L / S, Aₘₐₓ)
S有效 = max(S, L / Aₘₐₓ)
λAF ≈ log₂(S有效)；探针数 N ≈ ceil(L / S有效)

例如 L = 16、S = 2，比例为 8:1。上限 8 时，可用约 2 的尺度组合约 8 个探针；上限 4 时，有效尺度增为约 4，约 4 个探针。这里是帮助理解的算法模型，不是所有 GPU 的固定实现，也不是每个像素都必须用满上限。

进阶：为什么不能仅用 ddx / ddy 的长度比当成精确各向异性？

两条导数可能不正交，而且存在剪切。更精确的主轴模型从 Jacobian J = [gₓ, gᵧ] 的奇异值 σmax、σmin 获取尺度与方向；GPU 可采用近似。

例如 gₓ=(8,0)、gᵧ=(8,1)，两列长度比只有约 1.008，但主轴尺度比约 16.06。只比较两列长度会把一块很细长的斜足迹误认为接近各向同性。本文用 L/S 是假设已得到主轴尺度的教学模型。

依据：D3D11.3 §7.18.11：正交 Jacobian 与允许的近似。

空间疑问 · 额外 3 倍与额外 1/3，分别来自哪里？

令原图基础层占用 B。先假设它是大尺寸正方形、尺寸为 2 的幂、各层格式一致；忽略压缩块、对齐和元数据。这两种预处理结构保存的缩小版本不同：

Mipmap：B × (1 + 1/4 + 1/16 + …) ≈ 4B/3
Ripmap：B × (1 + 1/2 + 1/4 + …)² ≈ 4B
结构 / 操作总数据量相对原图额外量解决的侧重点
基础层B0只有原始分辨率。
完整 Mipmap约 1.333B约 +33.3%为统一尺度缩小预过滤。
完整二维 Ripmap约 4B约 +300%预先保存 U / V 独立尺度，适合与轴对齐的矩形查询；任意斜向仍有局限。
已有 mip 上提高 AF沿用已有 mip 图像数据通常没有固定倍数的新图像改变运行时足迹与样本组合；可能增加采样工作量。

2048² RGBA32 的例子：基础层 16 MiB，完整 Mipmap 约 21.33 MiB，完整 Ripmap 约 64 MiB。若图像数据与驻留不变，仅把 Aniso 1 调到 16，普通硬件 AF 不需要因此再生成额外 48 MiB 的 Ripmap。这与 mip 额外约 1/3 的观察是一致的；仅凭 Inspector 数字，无法反推出具体 GPU 用了哪种内部算法。

因此，你的“采用 Mipmap”判断基本抓住了资源存储这一部分：Unity 的普通纹理可以保留标准 mip 链，再由硬件在采样时实施 AF。Mipmap 和 AF 可以同时存在；Ripmap、积分图（Summed-Area Table）等是另外的预处理方案，不是 Aniso Level 的必需数据结构。

结构定义：Heckbert 原始研究：纹理映射与过滤Rip-NeRF §3.2 的二维 Ripmap 构造。上述比例与例子按结构定义独立推导；小尺寸、极窄纹理和压缩块会使结果偏离大尺寸近似。

成本疑问 · mip 已经预计算，为什么 AF 仍会耗时？

预计算 mip 提前做了很多低通平均，但当前像素的方向、比例和样本位置会随视角、UV 与画面变化。AF 仍然要选择合适级别，并读取、过滤、组合多个位置的结果。它通常由专用纹理采样硬件完成；“反向映射到纹理空间”是在描述足迹的来源，不能据此认为主要成本就是在 Shader 里算一个昂贵的逆矩阵。

容量 · 存了多少

例如一条完整 mip 链约 21.33 MiB。改变采样策略可以不增加固定图像容量。

带宽 · 每帧读多少

更多过滤探针可能触及更多纹素或压缩块，增加缓存压力与实际内存流量。

时间 · 完成得多快

取决于纹理单元吞吐、缓存、并行、格式及片元覆盖量。不能单看纹理文件大小。

所以不多存三倍，与运行时更慢并不矛盾。更高 AF 在斜视、大面积地面、多层材质和带宽紧张的 GPU 上可能更昂贵；在某些镜头或设备上，增量也可能很小。NVIDIA 的优化指南强调，不能按概念纹素数量推导固定倍数，应结合画质与实测决定。

把两类“耗时”分开：生成 mip / 压缩通常发生在导入或构建阶段（动态纹理例外）；AF 过滤发生在运行时采样阶段。启用 AF 不代表每帧重新生成整条 mip 链。

Unity 6.7 / URP · 如何设置与验证

  1. 给地面、道路等会斜视缩小的纹理生成 mip。先比较 Bilinear / Trilinear，再提高 Aniso Level。
  2. 检查 Project Settings → Quality → Anisotropic Filtering，它可以禁用、按纹理设置或强制开启。测试 1、2、4、8、16 时，使用允许每纹理设置的模式，避免全局覆盖干扰。
  3. 确认 Shader 实际使用的 Sampler 支持对应过滤。Unity 6.7 文档说明：Metal、Vulkan、OpenGL 可独立控制 mip 过滤与 AF；其他图形 API 开启 AF 时，Unity 也会开启三线性过滤。
  4. 固定同一镜头、平台格式、尺寸和驻留 mip，比较纹理资源内存与 GPU 帧时间。先记录 1×，再记录 4×、8×、16×，让容量变化与采样性能分开观察。

Unity 6.7 的 Texture.anisoLevel 范围为 0–16；1 表示没有 AF 效果。该版本文档中的 Forced On 会将 1–9 提到 9，更高值限制在 9–16；0 可以作为不应用 AF 的例外。具体以项目安装版本和图形后端为准。

16× 是否表示每个像素固定做 16 次采样，或者读 128 个纹素？
16× 是允许的最大各向异性程度。实际足迹接近正面时并不需要用满；探针数量、mip 选择、权重与硬件优化也不同。“16 个三线性探针 × 8”可以作为一种概念工作量估计，不能当作每像素固定的 HLSL 指令数、外部显存读取数或耗时倍数。
开启 AF 后，为什么纹理内存几乎不变？
常规硬件 AF 可以使用已有 mip 图像，只改变采样状态与内部访问。资源数据相同、格式相同、驻留相同时，容量就可以基本不变。缓存、驱动和加载行为另算，不能承诺整机内存绝对一字节不变。
为什么 AF 16× 仍然不能让远处无限清晰？
像素的覆盖范围、原图细节和上限共同限制结果。足迹比例大于上限时仍需接受额外过滤与模糊；太高频的内容本来就不能在少量像素里稳定展示。AF 是更合适的平均方式，不是超分辨率重建。
为什么设置了高 Aniso Level，却看不出差异？
检查是否斜视、纹理是否实际缩小、mip 是否存在、Quality 是否禁用、Shader 是否覆盖 Sampler、纹理是否已因尺寸限制或 Streaming 而变低分辨率。正面几乎各向同性的足迹本来就可能差别不大。
手动指定 LOD 后，为什么各向异性可能失效？
标量 LOD 不包含足迹方向。在 D3D11.3 的 sample_l / SampleLevel 语义下，采样忽略导数，AF 退化为各向同性过滤。若需要方向信息，可用普通隐式采样或受支持的显式梯度路径 SampleGrad。不同 API 与节点语义要分别核对。
是否可以关掉 Mipmap，再只靠 AF 解决远处闪烁？
不能把它当成通用替代方案。Mip 链提供预过滤数据与缓存优势，AF 利用这些数据匹配方向。缺少合适 mip 时，远处大范围平均可能更昂贵或不充分。对会缩小的普通 3D 表面，先保留合适 mip，再调整 AF。
各向异性是否一定“计算非常耗时”？
它可能增加成本，但程度由 GPU、格式、采样足迹、纹理覆盖量与瓶颈决定。主要应观察纹理过滤单元、缓存、带宽以及总体 GPU 时间，不要把它固定解释成大量 CPU 计算。先在目标设备测量，再按画质需求设上限。
Ripmap 明明预处理得更多，为什么也不能解决所有方向？
普通 Ripmap 的矩形预过滤与 U/V 轴对齐。倾斜、旋转的长足迹不一定与这些矩形匹配，仍可能额外模糊。保存更多尺度组合不等于预存了所有旋转角度的精确过滤结果；现代硬件 AF 的动态方向处理有不同取舍。

同一个 0.5，可以有两种含义

颜色图片常用 sRGB 编码保存，而光照计算需要线性 RGB。在 Linear 项目中，把颜色纹理标为 sRGB，GPU 采样时就会把 RGB 解码到线性空间。存储值 0.5 对应约 0.214 的线性值；这并不等于“颜色被压暗了”，而是同一信息换了编码。

但金属度、AO、粗糙度、遮罩等是参数。它们的 0.5 就应该作为 0.5 使用。如果把这些数据当 sRGB 解码，数值会变化，从而改变材质。法线图使用 Normal Map 类型，HDR 颜色数据通常本来就是线性的。

URP 把纹理数值接到哪里？

这里以 Universal Render Pipeline/Lit 的 Metallic 工作流为例。不同 Shader Graph 或自定义 Shader 可以使用其他通道约定。

贴图 / 插槽数值含义导入与通道要点
Base MapRGB 是基础色，乘材质颜色参数；不是完整受光后的照片。通常开启 sRGB。Alpha 是否作为透明度取决于 Transparent / Alpha Clipping 等设置；也可被选择为 Smoothness 来源。
Normal Map扰动光照使用的表面方向。Texture Type = Normal Map。常见切线空间法线需匹配网格切线与 Y 通道约定，使用 Unity 的法线解包逻辑。
Metallic MapR 表示金属度；默认 Smoothness 从 A 读取。关闭 sRGB。Metallic 工作流与 Specular 工作流不要混用通道含义。
Occlusion MapG 表示遮蔽；通常影响间接光照。关闭 sRGB。不是实时灯光产生的阴影贴图，不应期待它替代阴影系统。
Smoothness控制微表面光滑程度与高光外观。默认来自 Metallic Alpha，也可选 Albedo Alpha；贴图值受 Smoothness 参数缩放。常见粗糙度约定可转为 1 − Roughness，再写到正确通道。
Emission Map表面发光颜色，与 Emission 参数共同决定结果。普通非 HDR 发光颜色图通常按 sRGB；HDR 数据通常为 Linear。Bloom 与场景照明贡献还需对应功能和配置。

贴图接入表面之后，URP 继续做什么？

Forward / Forward+

绘制物体时采样纹理，得到表面参数，并在物体的着色过程中计算光照。Forward+ 改变灯光组织与筛选方式，纹理仍按 Shader 的需求采样。

Deferred / Deferred+

不透明物体先把表面属性写入 G-buffer，再执行光照阶段。常规不透明 Lit 路径通常在 G-buffer 阶段采样材质纹理；透明物体等仍走相应的前向路径。Deferred+ 对透明与前向专用 Pass 使用 Forward+。

这些路径会改变光照成本与 Pass 组织，却不改变“UV 查询纹理、Shader 解释数值”这个基础模型。最后，结果写入相机颜色缓冲，并经过配置的后处理与输出转换。

另一条入口：运行时生成的纹理

纹理也可以来自 RenderTexture，由 GPU 的一个 Pass 写出，再由后续 Pass 读取；合适的 RenderTexture 也可以绑定到材质纹理槽。URP 的 Camera Opaque Texture 是不透明阶段颜色的副本，Camera Depth Texture 提供深度数据；它们需要相应配置和 Shader 支持。相机颜色通常按屏幕 UV 读取，原始深度则需正确解码与线性化，不能直接当作线性距离。

屏幕纹理通常使用屏幕坐标，而不是网格的 UV0。读取深度时还需考虑图形 API、反向 Z 与正确的线性化函数。Render Graph 用于描述与调度 Pass 之间的资源读写和生命周期；普通文件纹理的导入设置不是由它替代的。

用最小 Shader 看清“读纹理”

下面是一个 URP 的 Opaque Unlit 教学 Shader。它只显示 Base Map 与颜色参数的乘积，便于隔离导入、UV 与采样问题。它没有 PBR 光照、阴影、法线或透明混合。代码沿用官方 URP 采样写法，并添加颜色参数；需在实际 Unity 项目中编译验证。

TexturePath.shader · URP / UNLIT
Shader "Learning/URP/TexturePath"
{
    Properties
    {
        [MainTexture] _BaseMap ("Base Map", 2D) = "white" {}
        [MainColor] _BaseColor ("Base Color", Color) = (1, 1, 1, 1)
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque"
               "RenderPipeline" = "UniversalPipeline" }

        Pass
        {
            Tags { "LightMode" = "UniversalForwardOnly" }
            HLSLPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

            struct Attributes
            {
                float4 positionOS : POSITION;
                float2 uv : TEXCOORD0;
            };
            struct Varyings
            {
                float4 positionHCS : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            TEXTURE2D(_BaseMap);
            SAMPLER(sampler_BaseMap);

            CBUFFER_START(UnityPerMaterial)
                float4 _BaseMap_ST;
                half4 _BaseColor;
            CBUFFER_END

            Varyings vert(Attributes IN)
            {
                Varyings OUT;
                OUT.positionHCS = TransformObjectToHClip(IN.positionOS.xyz);
                OUT.uv = TRANSFORM_TEX(IN.uv, _BaseMap);
                return OUT;
            }

            half4 frag(Varyings IN) : SV_Target
            {
                half4 texel = SAMPLE_TEXTURE2D(
                    _BaseMap, sampler_BaseMap, IN.uv);
                return texel * _BaseColor;
            }
            ENDHLSL
        }
    }
}

① Attributes → Varyings网格提供位置与 UV；顶点阶段输出裁剪空间位置。光栅化阶段将 UV 插值到片元。

② _BaseMap_ST / TRANSFORM_TEXST 的 xy 保存 Tiling，zw 保存 Offset。宏将材质参数应用到 UV。

③ TEXTURE2D / SAMPLER纹理资源与采样规则分开声明。纹理和采样器放在 CBUFFER 外，材质数值放入 UnityPerMaterial。

④ SAMPLE_TEXTURE2D片元里执行普通隐式 LOD 采样；受 UV、mip、过滤、格式和 sRGB 设置影响，然后乘颜色参数。

Shader Graph 对应路径：Texture2D 属性 → Sample Texture 2D；UV 节点 → Tiling And Offset → UV 输入；RGB → Unlit 的 Base Color。改成 Lit 后，Base Color、Normal、Metallic、Smoothness 等分别成为表面属性输入。导入为 Normal Map 的纹理，应使用对应的 Normal 采样 / 解包方式。

理解这一行就抓住了关键：SAMPLE_TEXTURE2D(texture, sampler, uv)。它返回数值，但不会替你决定这些数值应接到 Metallic 还是 Base Color。若 sRGB 颜色采样已自动解码，代码中不需要再手动转换。

依据：Unity 官方 URP 纹理采样示例URP Pass 标签

用尺寸和格式，建立显存预算

未压缩格式逐级计算 宽 × 高 × 每纹素字节数。块压缩则按每一级的完整块数计算，小 mip 也至少占一个块。把所有驻留级别相加，再乘独立纹理数量。

块压缩每级字节 = ceil(宽 / 块宽) × ceil(高 / 块高) × 每块字节

估算边界：不含 CPU Read/Write 副本、驱动对齐、资源元数据、加载临时内存与格式回退。普通 Texture2D 与有 MSAA / 深度附件的 RenderTexture 不能套用同一总量。

逐级求和，非 2 的幂尺寸也逐级向下取整，最小为 1。块压缩使用向上取整块数，结果是理想纹理数据大小；是否允许该尺寸与格式组合、实际驻留和内存开销以 Unity 与目标设备为准。MiB = 1,048,576 字节。

优化时，把“存储成本”和“读取成本”一起看

合理降低导入分辨率、选择设备支持的格式、对大型场景配置 Streaming，通常能改善纹理数据预算。Read/Write 会额外保留 CPU 可寻址副本，不能因为 GPU 数据压缩就忽略它。Streaming 预算还计入非 Streaming 纹理；后者占得越多，留给可流式纹理的空间就越少。

GPU 每帧成本还取决于采样次数、过滤方式、缓存命中、过度绘制与材质使用规模。更少的 MiB 不等于必然更快；把质量、带宽与加载成本放到目标设备上比较。

09 /

看到症状，先定位管线环节

每次只改一个变量。先用 Unlit 观察数据与采样，再回到 Lit 检查表面解释、光照和后处理。

近处也很糊 / 目标平台明显更糊

先查平台 Max Size、实际导入尺寸、格式与 Quality 的 mip 限制，再查 Streaming 所需高分辨率 mip 是否加载。放大低分辨率纹理也会模糊；提高过滤质量无法恢复不存在的细节。

使用 Rendering Debugger 和 Streaming 分析工具检查，而不是只看源文件尺寸。

远处闪烁 / 地面出现摩尔纹

查是否生成 mip、Filter 是否合适、LOD Bias 是否过度偏向高分辨率。Point 或只使用 mip 0 会更易产生缩小混叠。AA 不一定能修复纹理采样造成的全部问题。

正面清晰，斜着看地面很糊

查 Aniso Level 以及 Quality 中的各向异性设置。斜视采样足迹被拉长，普通各向同性过滤可能过度模糊。增加 Aniso 后测量 GPU 成本，并确认纹理原始分辨率足够。

颜色不对 / 金属度与粗糙度效果不对

先区分颜色图与数据图，检查 sRGB。再查纹理通道约定、Smoothness Source、参数缩放及 Roughness 转换。颜色问题还可能来自 Base Color 乘色、光照、曝光和色调映射。

法线凹凸反了 / 接缝明显

检查 Normal Map 导入类型、Y 通道约定（必要时 Flip Green Channel）、网格法线与切线，以及 Shader 的切线空间解包。RGB × 2 − 1 仅能解释常见源数据编码，不能替代所有导入格式的解包。

法线图不会改变模型轮廓；期待真实位移需要相应的几何或位移方案。

有 Alpha，却没有透明 / Alpha 被错误使用

Alpha 可以保存透明度，也可以保存 Smoothness 或遮罩。检查 Shader 的 Surface Type、Alpha Clipping、混合状态和所选 Smoothness Source。仅有 Alpha 通道不会自动切换透明渲染。

UV 接缝 / 图集边缘漏出邻图颜色

查 UV 岛边缘 padding、纹理边缘扩展、Wrap、mip 生成和双线性过滤范围。图集小块之间需要留足空间；整图 Clamp 只处理整张纹理边界。

显存超额 / 加载尖峰 / 摄像机切换后贴图迟迟变清晰

查独立纹理数量、实际 GPU 格式、Read/Write、Streaming 预算及格式回退。检查 desired、loading、loaded mip 的差异。镜头切换可考虑提前预加载，且应测量存储读取、解压与上传耗时。

调试工具各看一层：Texture Inspector 看导入数据与通道；Rendering Debugger 看材质、光照与相关可视化；Frame Debugger 看执行了哪些绘制事件与资源绑定；Profiler / Memory Profiler 看成本与资源占用。GPU 捕获工具还能检查编译后的采样与实际资源格式。

依据：Rendering DebuggerStreaming 分析

10 /

把这条路径，在 Unity 里走一遍

准备一个 URP 3D 项目、一张对比明显的棋盘颜色图、一个 Quad 和一个 Plane。保持项目使用 Linear，并先关闭干扰观察的后处理。以下步骤不需要修改 URP 源码。

  1. 确认资源端

    选中纹理，记录尺寸、平台格式、sRGB、mip 和 Read/Write。把相同图片以颜色图与数据图用途各导入一份，理解设置是如何绑定到资产的。

  2. 先看 Unlit

    创建 .shader 文件，粘贴第 07 节代码，在实际版本中编译。创建材质并赋给 Quad，将纹理拖到 Base Map。颜色乘数设为白色，先排除灯光因素。

  3. 改变 UV 与采样

    Tiling 设为 (4, 4)，再改变 Offset、Repeat / Clamp、Point / Bilinear。记录哪些变化改变坐标，哪些变化改变采样规则。改变 Importer 后 Apply。

  4. 缩小与斜视

    将纹理放到地面 Plane，拉远相机并改变俯视角。对比 mip 开关、Trilinear 与 Aniso。观察闪烁和细节稳定性，而不只看静止截图。

  5. 回到 Lit 的通道约定

    准备 R 金属度、G AO、A 光滑度的打包图，关闭 sRGB，同时绑定 Metallic 与 Occlusion。再用相反粗糙度值验证 Smoothness 的含义。法线另设 Normal Map 类型。

  6. 验证真实成本

    在目标平台构建中检查实际纹理格式、内存和 GPU 时间。若启用 Streaming，检查请求与已加载 mip。记录修改前后同一镜头的结果，让“更清晰”与“更快”各自有证据。

用三个问题，检查自己是否理解

一张 4K PNG 只有 1 MB，运行时显存一定也只有 1 MB 吗？
不一定。看导入后的尺寸、GPU 格式和驻留 mip，而不是 PNG 文件体积。以 RGBA32 4096² 原级为例，理想数据约 64 MiB。
为什么金属度图里的 0.5，勾选 sRGB 后会出问题？
在 Linear 项目中，RGB 会从 sRGB 解码到线性值，0.5 约变为 0.214。金属度是数值参数，通常应关闭 sRGB。
远处用了 mip 4，为什么显存仍没有显著下降？
采样选择 mip 与资源驻留不同。普通完整 mip 链仍保存高分辨率级别；Streaming 或 mip 限制才可能改变加载和驻留的数据量。

遇到纹理问题时，沿这条线回溯：
源数据 → 导入格式 → 驻留级别 → UV / Sampler → 通道解释 → 光照与输出。
