# Games101 第七节：深度缓冲（Z-Buffer）注释

> [!summary] 一句话理解
> **Z-Buffer 就是给每个屏幕采样点保存一个“目前见过的最近深度”。** 光栅化一个新三角形时，只要它在这个采样点更近，就同时更新颜色和深度；更远就丢弃。

## 1. 这张幻灯片在解决什么问题？

光栅化之后，一个三角形会覆盖屏幕上的一批采样点。同一个采样点可能同时落在多个三角形内部，例如一个物体挡住另一个物体：

```text
相机
  |
  |       三角形 A：更近
  |      /\
  |     /  \
  |    /____\
  |
  |       三角形 B：更远，但可能先被光栅化
```

如果只按照“谁后画谁覆盖”的规则，就会依赖绘制顺序：先画远处物体、再画近处物体，结果可能正确；反过来就可能错误。我们真正需要的是：

> 对每一个屏幕位置 $(x,y)$，只保留深度最小（也就是离相机最近）的那个采样点。

这里先按照 Games101 这张课件使用的约定理解：**$z$ 越小，表示越近**。不同图形 API 或使用 Reverse-Z 时，深度方向可能相反，但算法结构不变，只需把比较符号反过来。

## 2. 两个重要的缓冲区

### Frame Buffer：颜色缓冲

```text
framebuffer[x,y] = 这个屏幕位置最终显示的颜色
```

它回答的是：**这个位置最后应该显示什么颜色？**

### Z-Buffer / Depth Buffer：深度缓冲

```text
zbuffer[x,y] = 这个屏幕位置目前记录到的最近深度
```

它回答的是：**这个位置目前离相机最近的是谁？**

因此，Z-Buffer 不是用来存颜色的，也不是每个三角形只有一个深度。它是一个与屏幕采样点一一对应的二维数组：每个 $(x,y)$ 位置都有自己的深度值。

## 3. 课件伪代码逐行翻译

课件中的算法可以改写成下面的中文：

```text
把整个 depth buffer 初始化为无穷大

光栅化过程中：
    对每一个三角形 T：
        对三角形 T 覆盖到的每一个采样点 (x, y, z)：
            如果 z < zbuffer[x, y]：
                framebuffer[x, y] = rgb    // 更新颜色
                zbuffer[x, y] = z           // 更新深度
            否则：
                什么也不做                 // 这个采样点被更近的物体挡住了
```

### `Initialize depth buffer to ∞`

一开始还没有任何物体，所以每个位置都应该看成“目前没有最近物体”。用无穷大表示：

$$
zbuffer(x,y) = +\infty
$$

当第一个有效采样点的深度为 $z$ 时，总有 $z < +\infty$，因此它可以正常写入颜色和深度。

实际程序里通常不会真的存数学上的无穷大，而是使用足够大的初始值，例如深度范围中的最大值。

### `for each triangle T`

三角形的绘制顺序不重要。Z-Buffer 的目的之一，就是让最终可见结果不依赖三角形提交的顺序。

### `for each sample (x, y, z) in T`

这里不是只检查三角形的三个顶点，而是检查这个三角形光栅化后覆盖到的每一个屏幕采样点。

一个采样点包含：

- $(x,y)$：屏幕位置；
- $z$：这个三角形在该屏幕位置处插值得到的深度；
- `rgb`：这个采样点最终准备写入的颜色。

### `if z < zbuffer[x,y]`

这是整套算法最关键的一句：比较“新采样点的深度”和“该位置已经记录的最近深度”。

如果：

$$
z < zbuffer(x,y)
$$

说明新采样点更近，所以它应该挡住原来的内容。

### 同时更新颜色和深度

通过深度测试后，必须同时执行：

$$
\begin{aligned}
framebuffer(x,y) &\leftarrow rgb \\
zbuffer(x,y) &\leftarrow z
\end{aligned}
$$

这两行必须看成一个整体：颜色表示“当前获胜者是谁”，深度则记录“这个获胜者有多近”。如果只更新颜色、不更新深度，后面的采样点就会拿旧深度做错误比较。

### `else: do nothing`

如果新采样点满足：

$$
z \ge zbuffer(x,y)
$$

它不比当前记录的采样点更近，因此它被遮挡，直接丢弃，不修改颜色，也不修改深度。

## 4. 一个具体例子

假设屏幕位置 $(100,200)$ 被两个三角形覆盖：

| 光栅化顺序 | 三角形 | 深度 $z$ | 判断 | 结果 |
|---:|---|---:|---|---|
| 1 | A | $4$ | $4 < +\infty$ | 写入 A 的颜色，深度变成 $4$ |
| 2 | B | $7$ | $7 < 4$ 为假 | 丢弃 B |

最终显示 A，因为 A 更近。

如果顺序反过来：

| 光栅化顺序 | 三角形 | 深度 $z$ | 判断 | 结果 |
|---:|---|---:|---|---|
| 1 | B | $7$ | $7 < +\infty$ | 先写入 B |
| 2 | A | $4$ | $4 < 7$ | A 覆盖 B |

最终仍然显示 A。也就是说，只要深度比较方向正确，绘制顺序不影响结果。

> [!tip] 最核心的心算方式
> 每个屏幕位置都像有一个小裁判：它只保留目前见过的最小 $z$。新样本来了就问一句：**“你比我手里的更近吗？”** 更近就替换，否则淘汰。

## 5. 为什么初始化成无穷大之后就能工作？

把某个屏幕位置固定为 $(x,y)$。经过若干个三角形之后，Z-Buffer 中保存的值始终是已经处理过的样本深度的最小值：

$$
zbuffer(x,y) = \min\{z_1,z_2,\dots,z_n\}
$$

当新的样本深度 $z_{n+1}$ 到来时，算法执行：

$$
zbuffer(x,y) \leftarrow \min\bigl(zbuffer(x,y), z_{n+1}\bigr)
$$

因此，不管输入顺序如何，最后留下来的都是最近的样本。颜色缓冲区则保存产生这个最小深度的样本对应的颜色：

$$
framebuffer(x,y) = color\left(\operatorname*{arg\,min}_{i} z_i\right)
$$

这里的 `arg min` 可以理解为“让深度最小的那个样本的编号”。

## 6. Z-Buffer 和光栅化分别负责什么？

这两个步骤容易混在一起，可以这样分工：

| 模块 | 负责的问题 |
|---|---|
| 三角形光栅化 | 哪些屏幕采样点落在三角形内部？ |
| 属性插值 | 这些采样点的颜色、纹理坐标、深度是多少？ |
| 深度测试 | 这个新采样点是否比旧采样点更近？ |
| Frame Buffer 写入 | 如果它获胜，屏幕最终显示什么颜色？ |

所以，Z-Buffer **不负责判断一个点是否在三角形内**，也不负责生成三角形；它只负责遮挡关系中的最后一步：比较深度、保留最近者。

## 7. 容易混淆的几个点

### 7.1 深度是每个采样点一个，不是每个三角形一个

一个三角形通常不与屏幕平行，所以它在不同 $(x,y)$ 位置的深度不同。实际要比较的是：

$$
z_{triangle}(x,y) \quad \text{和} \quad zbuffer(x,y)
$$

而不是拿整个三角形的某个统一深度去比较。

### 7.2 “越小越近”不是永远成立

本节按照课件里的 `$z < zbuffer[x,y]$` 来理解，即较小的 $z$ 更近。但实际工程中还要看坐标系和深度映射约定。判断方法很简单：

1. 确定相机前方的深度范围；
2. 确定近裁剪面和远裁剪面分别对应什么深度值；
3. 决定使用“小于测试”还是“大于测试”；
4. 初始化值要放在“最不可能胜出”的一端。

### 7.3 颜色和深度必须配套更新

错误做法：

```text
如果新深度更近：更新颜色
但忘了更新 zbuffer
```

后果是：颜色已经显示了新物体，但深度记录还属于旧物体，后续采样点会得到错误结果。

### 7.4 深度相等时怎么办？

如果两个样本的深度完全相等，使用 `<` 时后到的样本不会覆盖先到的样本；使用 `<=` 时则可能覆盖。真实渲染中还会遇到浮点误差、共面三角形和 Z-Fighting 等问题，通常需要深度偏移、合理的深度精度或更明确的绘制规则。

## 8. 一段更接近程序的写法

```cpp
for (Triangle triangle : triangles) {
    for (Sample sample : rasterize(triangle)) {
        int x = sample.x;
        int y = sample.y;

        if (sample.z < depthBuffer[x][y]) {
            depthBuffer[x][y] = sample.z;
            frameBuffer[x][y] = sample.color;
        }
    }
}
```

其中：

- `rasterize(triangle)`：找出三角形覆盖的采样点，并得到每个采样点的深度；
- `depthBuffer[x][y]`：保存当前位置目前最小的深度；
- `frameBuffer[x][y]`：保存当前位置目前胜出的颜色；
- `if`：就是课件中的深度测试。

## 9. 用一个不太严谨但好记的比喻

把每个像素想成一个信箱：

- `framebuffer` 是信箱里贴着的“最终颜色”；
- `zbuffer` 是信箱里贴着的“当前最近距离”；
- 每个三角形都来投递一张候选卡片；
- 只有候选卡片的距离更近，才能替换信箱中的旧卡片；
- 替换时必须同时换颜色和距离。

最后，每个信箱里留下的就是从相机看过去真正可见的表面。

## 10. 自测题

### 问题 1

为什么不能把所有三角形按照从远到近排序后再绘制，完全不使用 Z-Buffer？

> [!answer]- 点击查看答案
> 对简单不透明物体来说，从远到近绘制有时可以得到正确结果，但三角形可能互相穿插，难以得到全局正确的排序；透明物体也不能简单地用同一套排序解决。Z-Buffer 是在每个屏幕采样点上独立做深度测试，因此更直接、更稳健。

### 问题 2

屏幕位置 $(x,y)$ 当前的深度是 $5$，新样本深度是 $3$。按照课件的约定，应该更新吗？

> [!answer]- 点击查看答案
> 应该。因为 $3 < 5$，新样本更近，所以同时执行 `framebuffer[x,y] = newColor` 和 `zbuffer[x,y] = 3`。

### 问题 3

如果只更新深度、不更新颜色，会发生什么？

> [!answer]- 点击查看答案
> 深度会声称当前位置已经被新物体占据，但颜色仍然是旧物体的颜色。之后的样本会被这个错误的深度挡住，最终出现颜色和遮挡关系不一致的画面。

## 11. 最后压缩成四句话

1. 光栅化会让多个三角形竞争同一个屏幕采样点。
2. 每个采样点用 Z-Buffer 记录目前最近的深度。
3. 新深度更近时，同时更新深度和颜色。
4. 最后每个采样点留下的颜色，就是从相机真正看到的表面颜色。
