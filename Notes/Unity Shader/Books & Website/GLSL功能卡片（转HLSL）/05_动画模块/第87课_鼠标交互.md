# 第 87 课 · 鼠标交互

> 学习目标：把鼠标位置传进 shader，做一个跟随鼠标移动的光晕。

ShaderToy 有现成的 `u_mouse`，但 Unity 没有内置的鼠标变量。这一课教你 Unity 的标准做法：**Properties 暴露一个向量 + C# 脚本喂数据**。

---

## 1. 完整代码

```hlsl
Shader "Lesson/87_MouseGlow"
{
    Properties
    {
        _MousePixel ("鼠标像素坐标", Vector) = (0, 0, 0, 0)
    }

    SubShader
    {
        Tags
        {
            "RenderType" = "Opaque"
            "RenderPipeline" = "UniversalPipeline"
        }

        Pass
        {
            HLSLPROGRAM
            #pragma vertex vert
            #pragma fragment frag

            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

            float2 _MousePixel;

            struct Attributes
            {
                float4 positionOS : POSITION;
                float2 uv : TEXCOORD0;
            };

            struct Varyings
            {
                float4 positionHCS : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            Varyings vert (Attributes IN)
            {
                Varyings OUT;
                OUT.positionHCS = TransformObjectToHClip(IN.positionOS.xyz);
                OUT.uv = IN.uv;
                return OUT;
            }

            half4 frag (Varyings IN) : SV_Target
            {
                float2 mouseUV = _MousePixel.xy / _ScreenParams.xy;   // 像素 → 0~1 UV
                float distanceToMouse = length(IN.uv - mouseUV);

                float glowMask = 1.0 - smoothstep(0.0, 0.3, distanceToMouse);

                float3 backgroundColor = float3(0.02, 0.03, 0.06);
                float3 glowColor = float3(1.0, 0.6, 0.2);
                float3 color = lerp(backgroundColor, glowColor, glowMask);
                return half4(color, 1);
            }
            ENDHLSL
        }
    }
}
```

画面是一团暖橙色光晕，紧紧跟随鼠标移动。

---

## 2. 为什么要绕这一圈

ShaderToy 里鼠标是内置的 `u_mouse`，直接拿来用。但 Unity 的 shader 不知道鼠标在哪——它运行在 GPU 上，而鼠标位置是 CPU 端的信息。**必须有人把鼠标位置从 CPU 传进 GPU**，这个「传」就是本课的核心。

---

## 3. 三步走：暴露 → 传值 → 换算

第一步，Properties 里声明 `_MousePixel`，`Vector` 类型；第二步，HLSLPROGRAM 里再次声明 `float2 _MousePixel` 才能使用（这是 Unity shader 的固定规矩：属性要在 Properties 和代码里各写一次）；第三步，`_MousePixel.xy / _ScreenParams.xy` 把像素坐标换算成 0~1 的 UV——`_ScreenParams.xy` 是屏幕宽高（像素）。

---

## 4. C# 脚本：谁来喂数据

把下面脚本挂到带这个材质的物体上，每帧读鼠标位置、写进 `_MousePixel`：

```csharp
using UnityEngine;

public class MouseToShader : MonoBehaviour
{
    public Material targetMaterial;   // 使用第 87 课材质的材质

    void Update()
    {
        Vector2 mouse = Input.mousePosition;                 // 像素坐标（左下角原点）
        targetMaterial.SetVector("_MousePixel", new Vector4(mouse.x, mouse.y, 0, 0));
    }
}
```

`Input.mousePosition` 返回的是屏幕像素坐标、左下角是原点。`SetVector` 按属性名写进去，shader 里的 `_MousePixel` 就能读到。

---

## 5. 距离 → 光晕

`length(IN.uv - mouseUV)` 是每个像素到鼠标的距离。`smoothstep(0.0, 0.3, ...)` 在 0~0.3 内做柔和过渡，`1.0 -` 翻转后鼠标处最亮、向外渐暗，形成光晕。

---

## 6. 试着改一改

| 效果 | 写法 |
|------|------|
| 光晕更大 | `0.3` 改成 `0.5` |
| 光晕更小更硬 | `0.3` 改成 `0.1` |
| 换颜色 | `glowColor` 改成 `float3(0.2, 0.8, 1.0)` |
| 光晕变成光环 | `1.0 - smoothstep(0.0, 0.3, distanceToMouse)` 改成 `1.0 - smoothstep(0.05, 0.15, abs(distanceToMouse - 0.2))` |

## 7. 练习

练习代码里 `mouseUV = float2(0.5, 0.5)`。补全从 `_MousePixel` 和 `_ScreenParams` 换算 UV 的表达式。

### 答案解析

```hlsl
float2 mouseUV = _MousePixel.xy / _ScreenParams.xy;
```

`_MousePixel` 存的是像素坐标，`_ScreenParams.xy` 是屏幕宽高（像素），两者相除得到 0~1 的归一化 UV，和 `IN.uv` 在同一坐标系下，才能直接求距离。

试着把 C# 里 `Input.mousePosition` 换成 `Input.mousePosition * 2.0`，观察光晕位置被「放大」到屏幕外。

## 8. 【小灶解析】专家补充

### ① CPU → GPU 传数据是 TA 的核心工作

shader 是纯函数，它需要的所有外部输入——时间、鼠标、纹理、颜色、矩阵——都要有人显式传进来。`_Time` 是引擎自动传的，鼠标没有自动，所以要自己搭管道。**理解「什么数据需要手动传」，是 TA 和纯 shader 程序员的区别所在。**

### ② Properties 是「材质面板的入口」

任何想在材质 Inspector 里调、或用 `SetVector/SetFloat/SetTexture` 动态改的值，都要先声明在 Properties。名称以下划线开头（`_MousePixel`）是约定。**「Properties 声明 + HLSL 再声明」这个双写规则**，写多了就成肌肉记忆。

### ③ 坐标系统一才能做运算

`_MousePixel` 是像素、`IN.uv` 是 0~1，两者直接相减会错位，所以先除以 `_ScreenParams` 对齐。**坐标不一致是 shader bug 的头号来源**，每次做位置运算前都先问自己：这两个量在同一个坐标系里吗？
