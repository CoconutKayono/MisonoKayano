# 第 11 课 · UV 坐标基础

> 学习目标：理解着色器中的 UV 坐标系统及其应用，学习如何把 UV 映射到颜色、创建渐变。

第 01 课每个像素都输出同一个颜色。想让左边暗、右边亮，着色器就需要知道**当前像素在哪里**——这就是 UV 坐标的用途。

---

## 1. 完整代码

```hlsl
Shader "Lesson/11_UVGradient"
{
    SubShader
    {
        Tags
        {
            "RenderType" = "Opaque"
            "RenderPipeline" = "UniversalPipeline"
        }

        Pass
        {
            HLSLPROGRAM
            #pragma vertex vert
            #pragma fragment frag

            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

            struct Attributes
            {
                float4 positionOS : POSITION;
                float2 uv : TEXCOORD0;
            };

            struct Varyings
            {
                float4 positionHCS : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            Varyings vert (Attributes IN)
            {
                Varyings OUT;
                OUT.positionHCS = TransformObjectToHClip(IN.positionOS.xyz);
                OUT.uv = IN.uv;
                return OUT;
            }

            half4 frag (Varyings IN) : SV_Target
            {
                float3 color = float3(IN.uv.x, IN.uv.x, IN.uv.x);
                return half4(color, 1);
            }
            ENDHLSL
        }
    }
}
```

跑起来步骤同前，Shader 选 `Lesson → 11_UVGradient`。左边黑、右边白。

---

## 2. 什么是 UV 坐标

UV 坐标是「**归一化的表面坐标**」——每个值都在 0.0 到 1.0 之间：

- 左边缘：`uv.x = 0.0`
- 右边缘：`uv.x = 1.0`
- 下边缘：`uv.y = 0.0`
- 上边缘：`uv.y = 1.0`

在 Unity 里，这个 UV **不需要你自己算**——它是模型顶点自带的数据（顶点数据里的 `TEXCOORD0`），由顶点着色器传进来（回忆第 02 课 `OUT.uv = IN.uv;` 那一行）。

> 为什么是「归一化」？因为如果用像素位置（比如 `(142.0, 87.0)`），这个数字和模型/屏幕尺寸绑定，换个大小就不一样了。归一化到 0~1 之后，UV 就与尺寸无关，任何模型、任何分辨率都能通用。

---

## 3. 用 uv.x 控制颜色

`uv.x` 从左到右是 0.0 → 1.0，正好可以当亮度用。把它同时设给三个颜色通道，就得到从黑到白的灰度渐变：

```hlsl
float3 color = float3(IN.uv.x, IN.uv.x, IN.uv.x);
// 左边 uv.x = 0.0 → 黑色；右边 uv.x = 1.0 → 白色
```

HLSL 也有简写：`float3(IN.uv.x)` 等价于 `float3(IN.uv.x, IN.uv.x, IN.uv.x)`——用单个标量构造向量时，它会被复制到所有分量。

---

## 4. 试着改一改

| 效果 | 写法 |
|------|------|
| 竖直渐变（下黑上白） | 把 `IN.uv.x` 全改成 `IN.uv.y` |
| 反向（左白右黑） | `float3(1.0 - IN.uv.x, 1.0 - IN.uv.x, 1.0 - IN.uv.x)` |
| 只留红色通道 | `float3(IN.uv.x, 0.0, 0.0)` |

## 5. 练习

练习区画面是黑色的，用 `uv.x` 让它从左边黑色渐变到右边白色。

初始状态：

```hlsl
half4 frag (Varyings IN) : SV_Target
{
    float3 color = float3(0.0, 0.0, 0.0);   // 全黑
    return half4(color, 1);
}
```

### 答案解析

```hlsl
float3 color = float3(IN.uv.x, IN.uv.x, IN.uv.x);
```

三个通道相同就是灰色。`uv.x` 从 0 到 1，灰色就从黑到白。

进阶：试试 `float3(IN.uv.y, IN.uv.y, IN.uv.y)`，渐变方向会变成从下到上。

## 6. 【小灶解析】专家补充

### ① Unity 里 UV 来自模型，不是屏幕

有些全屏工具需要自己算「像素坐标 ÷ 分辨率」来得到 0~1 的 UV。但 Unity 的 UV 是美术在建模软件里「展开」好、存在每个顶点里的数据（`TEXCOORD0`），你直接用即可。所以**同一个 Shader 在不同模型上 UV 分布不同**（回忆第 02 课小灶 ⑤）。

### ② TEXCOORD0 只是第一套 UV

顶点数据里可以有多个 UV 通道：`TEXCOORD0`、`TEXCOORD1`、`TEXCOORD2`……Unity 惯例用 `TEXCOORD0` 放第一套 UV（贴图用），光照贴图、额外数据会用到后面的通道。现在你只需记住「UV 一般从 TEXCOORD0 来」。

### ③ 归一化的意义

0~1 是与分辨率无关的「比例」，所以同一段 Shader 能在任何尺寸的模型、任何分辨率的屏幕上复用。这是「0~1 是 Shader 通用货币」（第 03/10 课都提过）的又一体现。

### ④ float3(标量) 的构造器简写

`float3(x)` 会把标量 x 复制到三个分量。同理 `float3(float2, 标量)` 这种「用小向量拼大向量」的写法也常见——下一课《UV 可视化》就会用到。
