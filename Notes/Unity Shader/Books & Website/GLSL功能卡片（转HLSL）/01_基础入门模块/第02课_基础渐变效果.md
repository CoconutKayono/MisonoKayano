# 第 02 课 · 基础渐变效果

> 学习目标：学习如何使用 HLSL 创建**线性**和**径向**渐变效果。

上一课，每个像素都是同一个颜色。这一课我们让颜色**跟着位置走**——这就是「渐变」的本质。而要想描述「位置」，我们需要引入一个新概念：**UV 坐标**。

---

## 1. 完整代码：水平线性渐变

```hlsl
Shader "Lesson/02_Gradient"
{
    SubShader
    {
        Tags
        {
            "RenderType" = "Opaque"
            "RenderPipeline" = "UniversalPipeline"
        }

        Pass
        {
            HLSLPROGRAM
            #pragma vertex vert
            #pragma fragment frag

            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

            struct Attributes
            {
                float4 positionOS : POSITION;
                float2 uv : TEXCOORD0;          // 模型自带的 UV 坐标
            };

            struct Varyings
            {
                float4 positionHCS : SV_POSITION;
                float2 uv : TEXCOORD0;          // 传给片元着色器
            };

            Varyings vert (Attributes IN)
            {
                Varyings OUT;
                OUT.positionHCS = TransformObjectToHClip(IN.positionOS.xyz);
                OUT.uv = IN.uv;                 // 原样传给片元
                return OUT;
            }

            half4 frag (Varyings IN) : SV_Target
            {
                half brightness = IN.uv.x;      // ★ 水平位置决定亮度
                return half4(brightness, brightness, brightness, 1);  // 左黑 → 右白
            }
            ENDHLSL
        }
    }
}
```

跑起来的步骤和第 01 课一样：建 `.shader` 文件 → 粘入代码 → 建材质 → 在 Shader 下拉框选 `Lesson → 02_Gradient` → 拖到 Cube 上。

对比上一课，改动只有三处：

1. 两个结构体里各多了一行 `float2 uv : TEXCOORD0;`
2. 顶点着色器多了一行 `OUT.uv = IN.uv;`
3. 片元着色器从「写死颜色」变成「用 `IN.uv.x` 算颜色」

---

## 2. uv 坐标是什么

UV 是「表面坐标」。它把模型表面的每个点，映射到一个 **0~1 的矩形**里：

- **u**：横向，`0` = 最左，`1` = 最右
- **v**：纵向，`0` = 最下，`1` = 最上

每个顶点天生就带着一个 uv 值（顶点数据里的 `TEXCOORD0`）。到了片元着色器里，这个 uv 已经被 GPU **插值**好了——三角形内部每个像素都自动拿到一个连续变化的 (u, v)。

所以 `IN.uv.x` 在物体表面从左到右，就是从 0 一路走到 1。

> **关键直觉：UV 只是一串数字（坐标），它不是贴图。**
> 贴图是「拿 UV 去查一张颜色表」；而 UV 本身就可以直接拿来算颜色——本课干的就是这件事。没有贴图，一样能做渐变。

---

## 3. 颜色随位置变化

### 3.1 线性渐变

`IN.uv.x` 是一个 0~1 的数。把它同时塞进红、绿、蓝三个通道，得到的就是从黑 `(0,0,0)` 到白 `(1,1,1)` 的**水平渐变**：

```hlsl
half brightness = IN.uv.x;                    // 0（最左）→ 1（最右）
return half4(brightness, brightness, brightness, 1);  // 三个通道相等 = 灰阶，数值 0~1 = 黑到白
```

把它换成 `IN.uv.y`，就是**竖直渐变**（下黑上白）。这利用的是上一课学到的规律：颜色三个通道相等时是灰，数值 0~1 就是黑到白。

### 3.2 径向渐变

径向渐变 = 颜色取决于「这个像素离某个中心点有多远」。做法：

```hlsl
float2 centeredUV = IN.uv - 0.5;              // 把中心 (0.5, 0.5) 平移到原点 (0,0)
half distanceToCenter = length(centeredUV);   // 当前像素到中心的距离
half brightness = saturate(distanceToCenter * 2.0);  // 缩放到 0~1，并夹在 0~1 内
return half4(brightness, brightness, brightness, 1);  // 中心黑 → 边缘白
```

逐行解释：

- `centeredUV = IN.uv - 0.5`：UV 的中心本来是 (0.5, 0.5)，整体减掉 0.5 后，中心变成了 (0,0)。这样「到中心的距离」就能直接用 `length()` 算（到原点的距离）。
- `distanceToCenter = length(centeredUV)`：向量的长度，即该像素到中心的距离。中心是 0，边上是 0.5，四角约 0.707。
- `* 2.0`：把距离放大，让边缘大致到 1.0。
- `saturate(...)`：把超出 0~1 的值夹回 0~1（四角本来会超过 1，被压成纯白）。

## 4. 试着改一改

| 效果 | 替换 frag 里的写法 |
|------|------|
| 竖直渐变（下黑上白） | `half brightness = IN.uv.y;` |
| 反向水平渐变（右黑左白） | `half brightness = 1.0 - IN.uv.x;` |
| 红绿渐变 | `return half4(IN.uv.x, IN.uv.y, 0.0, 1.0);` |
| 只保留红色的径向 | 径向代码不变，最后 `return half4(brightness, 0.0, 0.0, 1.0);` |

## 5. 练习

把 `frag` 改成「竖直渐变」，让物体从下到上由黑变白。

初始状态（当前是水平渐变）：

```hlsl
half4 frag (Varyings IN) : SV_Target
{
    half brightness = IN.uv.x;      // 水平：左黑右白
    return half4(brightness, brightness, brightness, 1);
}
```

### 答案解析

把 `IN.uv.x` 改成 `IN.uv.y`：

```hlsl
half brightness = IN.uv.y;          // 竖直：v 从下到上是 0→1
return half4(brightness, brightness, brightness, 1);
```

因为 v 轴 0 在最下、1 在最上，所以下面是黑、上面是白。

进阶：试试 `1.0 - IN.uv.y`，让渐变反过来（下白上黑）。

## 6. 【小灶解析】专家补充

### ① UV 是「数据」，不是「贴图」

很多新手以为「UV = 贴图」。其实 UV 只是每个顶点自带的一组坐标数据，它本身不含任何颜色。贴图是「用 UV 去查一张颜色表」，而本课的渐变是「直接用 UV 算颜色」。理解了这一点，你就能自由地用 UV 造出无数效果——渐变、棋盘格、条纹……都只是「对 UV 做数学」。

### ② 渐变为什么是平滑的：GPU 帮我们做了插值

顶点着色器其实只在**顶点**上运行。一个三角形只有 3 个顶点，这 3 个顶点各自带一个 uv 值。但片元着色器却能在几万个像素上拿到连续变化的 uv——这中间的平滑过渡，是**光栅化阶段 GPU 自动做的线性插值**。

这就是第 01 课小灶 ② 那条流水线的延续：顶点着色器给「点」，光栅化把「点」铺成「面」，片元着色器处理「面上的每个像素」。你写 Shader 时不需要手动插值，但要知道它在发生。

### ③ saturate 是什么

`saturate(x)` 等价于 `clamp(x, 0, 1)`——把数值夹在 0~1 之间。它是 Shader 里用得最多的内置函数之一，因为「颜色、亮度、比例」几乎都希望落在 0~1。径向渐变里的 `* 2.0` 会让四角超过 1，`saturate` 就把超出的部分压回纯白。

### ④ length 的开销：开方

`length(v)` 内部会算一次**平方根**，而开方在 GPU 上相对较贵。如果你只是想要「距离感」而不需要精确距离，可以用**平方距离**代替：`dot(centeredUV, centeredUV)`（等于 x²+y²，没有开方）。平方距离的渐变形状会略有不同（更「硬」），但省一次开方。这是性能优化里常见的一招——先想清楚「我真的需要精确距离吗」。

### ⑤ 为什么同一个 Shader 在不同模型上渐变走向不同

UV 的 0~1 是怎么铺在模型表面上的，由模型的**「UV 展开（UV Unwrap）」**决定，而不是由物体形状决定。同一个 Shader 挂在 Cube 和 Sphere 上，渐变的方向、密度都可能不一样。TA 经常会和美术沟通 UV 展开，就是因为「美术怎么展 UV」直接影响「你的 Shader 效果最终长什么样」。
