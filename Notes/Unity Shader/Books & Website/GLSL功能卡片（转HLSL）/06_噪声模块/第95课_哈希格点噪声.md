# 第 95 课 · 哈希格点噪声

> 学习目标：用 `hash21` 给每个网格单元生成随机灰度，做出马赛克噪声。

噪声模块的第一课。程序化噪声的起点是「伪随机函数」——先学会给每个格子一个稳定的随机值。

---

## 1. 完整代码

```hlsl
Shader "Lesson/95_HashGridNoise"
{
    SubShader
    {
        Tags
        {
            "RenderType" = "Opaque"
            "RenderPipeline" = "UniversalPipeline"
        }

        Pass
        {
            HLSLPROGRAM
            #pragma vertex vert
            #pragma fragment frag

            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

            float hash21(float2 coord)
            {
                float2 fractCoord = frac(coord * float2(123.34, 345.45));
                fractCoord += dot(fractCoord, fractCoord + 34.345);
                return frac(fractCoord.x * fractCoord.y);
            }

            struct Attributes
            {
                float4 positionOS : POSITION;
                float2 uv : TEXCOORD0;
            };

            struct Varyings
            {
                float4 positionHCS : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            Varyings vert (Attributes IN)
            {
                Varyings OUT;
                OUT.positionHCS = TransformObjectToHClip(IN.positionOS.xyz);
                OUT.uv = IN.uv;
                return OUT;
            }

            half4 frag (Varyings IN) : SV_Target
            {
                float noiseValue = hash21(floor(IN.uv * 64.0));
                float3 color = float3(noiseValue, noiseValue, noiseValue);
                return half4(color, 1);
            }
            ENDHLSL
        }
    }
}
```

画面是被切成 64×64 的格子，每格一个随机灰度，像马赛克电视雪花。

---

## 2. hash21 是什么

`hash21` 是一个**伪随机函数**——给它一个二维坐标，返回 0~1 之间的数。

关键在「伪随机」：它不是真正随机的，**相同输入永远返回相同输出**。这正是我们要的——同一个格子在每次渲染时必须是同一个颜色，不能每帧闪烁。函数里那串魔法数字（123.34、345.45、34.345）不需要记，把它当工具直接用。

---

## 3. floor 的作用

`IN.uv` 是 0~1 的连续坐标。`floor(IN.uv * 64.0)` 做了两件事：

乘 64 把坐标放大到 0~64；`floor` 砍掉小数、只留整数 0、1、2……63。**同一格内所有像素的 `floor` 结果相同**，传给 `hash21` 得到同一个随机值，于是整格同一颜色。系数越小格子越大，系数越大格子越细。

---

## 4. 为什么用整数坐标喂 hash

`hash21` 对小数坐标极其敏感——相邻像素坐标差一点点，结果就完全不同。所以必须先 `floor` 把整格压成同一个整数点，才能得到「块状」而非「雪花」的效果。**「先 floor 再 hash」是格点噪声的标准动作。**

---

## 5. 试着改一改

| 效果 | 写法 |
|------|------|
| 格子变大、马赛克感更强 | `64.0` 改成 `8.0` |
| 格子极小、像真噪点 | `64.0` 改成 `256.0` |
| 每格变黄橙色调 | `float3(noiseValue, noiseValue, noiseValue)` 改成 `float3(noiseValue, noiseValue * 0.5, 0.2)` |
| 随机分布变化 | `34.345` 改成 `12.0` |

## 6. 练习

练习代码里 `noiseValue = 0.0`。用 `hash21(floor(IN.uv * 64.0))` 计算格点随机值并输出灰度图。

### 答案解析

```hlsl
float noiseValue = hash21(floor(IN.uv * 64.0));
float3 color = float3(noiseValue, noiseValue, noiseValue);
```

关键改动只有一行：把 `noiseValue = 0.0` 换成 `hash21(floor(IN.uv * 64.0))`。`IN.uv * 64.0` 放大坐标决定格子密度；`floor(...)` 把同一格内所有像素压到同一整数；`hash21(...)` 对这个整数取伪随机值；`float3(n, n, n)` 把单浮点扩展成灰度。

试着把 64.0 改成 16.0，感受格子大小和噪声粗细的关系。

## 7. 【小灶解析】专家补充

### ① 伪随机的「可复现」是最大的价值

真随机每次都不一样，反而没用——游戏里贴图会每帧闪烁。伪随机**同样的输入 → 同样的输出**，让噪声可以稳定复现、可以平铺、可以在不同机器上结果一致。这是所有程序化纹理的根基。

### ② hash21 的魔法数字是「种子」

`123.34、345.45` 这些常数就像随机种子的组成部分，换掉它们就换一种随机分布，但视觉结构相似。**把它们理解为「换个花样」，不用深究数学细节。**

### ③ 格点噪声是后面所有噪声的地基

这一课的「格子 + hash」会在第 105 课的 Value Noise 里被拿去插值，进而衍生出 FBM、云朵、大理石等一切。先把「每格一个稳定随机值」这个动作吃透，后面全是它的组合。
