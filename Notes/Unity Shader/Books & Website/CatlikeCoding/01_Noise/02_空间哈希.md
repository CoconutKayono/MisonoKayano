# Hashing Space

在任意网格中进行哈希


- 对经过变换的三维空间进行哈希。
- 使用不同形状对空间采样。
- 手动向量化作业。
- 创建形状作业模板。

这是“[伪随机噪声](https://catlikecoding.com/unity/tutorials/pseudorandom-noise/)”系列教程的第二篇。本文会调整哈希算法，使其能够适用于任意网格和形状。

本教程使用 Unity 2020.3.6f1 编写。

## 网格变换

在[上一篇教程](https://catlikecoding.com/unity/tutorials/pseudorandom-noise/hashing/)中，我们通过对整数 UV 坐标进行哈希，为平面上的采样点着色并使其产生位移，因此每个点都有自己的哈希值。本教程改为对空间本身进行哈希，然后在其中采样。我们依据空间定义的整数网格来完成这件事。这样一来，哈希就与采样点解耦，不再依赖可视化所用的形状和分辨率。

### 调整缩放

为了说明哈希图案与采样分辨率可以彼此独立，我们先把哈希图案的有效分辨率加倍。只需在 `HashJob.Execute` 中把 UV 坐标加倍，再将它们传给哈希函数即可。

```csharp
public void Execute(int i) {
	int v = (int)floor(invResolution * i + 0.00001f);
	int u = i - resolution * v - resolution / 2;
	v -= resolution / 2;

	u *= 2;
	v *= 2;

	hashes[i] = hash.Eat(u).Eat(v);
}
```

![[images/hashing-space/grid-transformation/scale-normal.png]]
![[images/hashing-space/grid-transformation/scale-double.png]]
**图：正常缩放与两倍缩放；分辨率为 32，种子为 0。**

将 UV 的缩放加倍会产生不同的图案，但整体特征并没有根本变化。我们只是缩放了哈希函数的定义域，让它以原来两倍的速度移动。也可以缩小定义域，例如把 UV 除以 4。

```csharp
u /= 4;
v /= 4;
```

![[images/hashing-space/grid-transformation/scale-quarter-misalinged.png]]
**图：缩小到四分之一，但未对齐。**

现在每 4×4 个采样点会得到相同的哈希值，看起来就像可视化分辨率降低了。不过，图案没有对齐，而且零点附近会重复，这是因为整数除法实际采用的是向零截断。

这两个问题都可以这样解决：先把 UV 坐标计算为 −0.5 到 0.5 范围内的浮点数，而不是整数；然后通过 `floor` 方法向下取整，得到整数坐标。

```csharp
	float vf = floor(invResolution * i + 0.00001f);
	float uf = invResolution * (i - resolution * vf + 0.5f) - 0.5f;
	vf = invResolution * (vf + 0.5f) - 0.5f;

	int u = (int)floor(uf);
	int v = (int)floor(vf);

	hashes[i] = hash.Eat(u).Eat(v);
}
```

要让哈希图案恢复到之前的尺度，需要在向下取整之前，将 UV 乘以可视化分辨率再除以 4。这里使用的可视化分辨率是 32。

```csharp
int u = (int)floor(uf * 32f / 4f);
int v = (int)floor(vf * 32f / 4f);
```

![[images/hashing-space/grid-transformation/scale-quarter-aligned.png]]
**图：缩小到四分之一并完成对齐。**

### 定义域变换

我们将固定的定义域缩放改为可配置项。除此之外，也不必局限于缩放；可以把定义域视为常规的三维空间，对它应用平移、旋转和缩放，就像变换游戏对象一样。不过，单独使用 `Transform` 组件并不合适，因此我们在新文件中定义自定义的 `SpaceTRS` 结构体，其中包含三个公开的 `float3` 字段来描述变换。

```csharp
using Unity.Mathematics;

public struct SpaceTRS {

	public float3 translation, rotation, scale;
}
```

在 `HashVisualization` 中添加该类型的字段，以便配置空间变换。将默认缩放设为 8，与当前硬编码的可视化设置一致。

```csharp
[SerializeField]
SpaceTRS domain = new SpaceTRS {
	scale = 8f
};
```

要让这一设置生效，自定义的 `SpaceTRS` 必须支持序列化。给它添加 `System.Serializable` 特性即可。

```csharp
[System.Serializable]
public struct SpaceTRS { … }
```

![[images/hashing-space/grid-transformation/domain-configuration.png]]
**图：定义域配置。**

可以通过将 4×4 矩阵与向量相乘，对位置或方向应用三维空间变换。在 `SpaceTRS` 中添加公开的 `float4x4 Matrix` getter 属性来返回这样的矩阵。调用 `float4x4.TRS`，并传入平移、旋转和缩放向量即可创建矩阵。旋转参数必须是四元数。按照 Unity 的约定，我们可以调用 `quaternion.EulerZXY` 来创建旋转，并使用 `radians` 方法将旋转向量转换为弧度。

```csharp
public float4x4 Matrix {
	get {
		return float4x4.TRS(
			translation, quaternion.EulerZXY(math.radians(rotation)), scale
		);
	}
}
```

由于这里的变换仅包含平移、旋转和缩放，矩阵的第四行始终是 0、0、0、1。因此可以省去这一行以缩小数据，改为返回 `float3x4` 矩阵。两种矩阵类型之间没有直接转换方法，所以需要将矩阵的四个列向量作为参数，调用 `math.float3x4` 方法。列向量分别叫作 `c0`、`c1`、`c2` 和 `c3`。这里只需要每列的前三个分量，可以通过它们的 `xyz` 属性取得。

```csharp
public float3x4 Matrix {
	get {
		float4x4 m = float4x4.TRS(
			translation, quaternion.EulerZXY(math.radians(rotation)), scale
		);
		return math.float3x4€(m.c0.xyz, m.c1.xyz, m.c2.xyz, m.c3.xyz);
	}
}
```

### 应用矩阵

要在 `HashJob.Execute` 中应用矩阵，首先需要一个 `float3` 位置。利用 −0.5 到 0.5 范围的 UV 坐标，在 XZ 平面上创建点，再取它的 X、Z 分量作为整数 UV 坐标。

```csharp
public void Execute(int i) {
	float vf = floor(invResolution * i + 0.00001f);
	float uf = invResolution * (i - resolution * vf + 0.5f) - 0.5f;
	vf = invResolution * (vf + 0.5f) - 0.5f;

	float3 p = float3€(uf, 0f, vf);

	int u = (int)floor(p.x);
	int v = (int)floor(p.z);

	hashes[i] = hash.Eat(u).Eat(v);
}
```

接着在作业中添加 `float3x4 domainTRS` 字段，并通过 `mul` 方法将矩阵与点相乘。此运算要求输入为 `float4` 而不是 `float3`，所以第四个分量设为 1。这个分量会与矩阵的第四列（平移向量）相乘，因此平移量会原样加上。Burst 会优化掉与常量 1 的乘法。

```csharp
public float3x4 domainTRS;

public void Execute(int i) {
	…

	float3 p = mul(domainTRS, float4€(uf, 0f, vf, 1f));

	…
}
```

此时若查看 Burst Inspector，会发现作业不再自动向量化。这是因为现在处理的是向量类型，而不是单个值。我们暂时先接受这个限制，稍后再解决。

要应用定义域变换，在调度作业时把定义域矩阵传入即可。

```csharp
new HashJob {
	hashes = hashes,
	resolution = resolution,
	invResolution = 1f / resolution,
	hash = SmallXXHash.Seed(seed),
	domainTRS = domain.Matrix
}.ScheduleParallel(hashes.Length, resolution, default).Complete();
```

![[images/hashing-space/grid-transformation/domain-rotation-y30.png]]
**图：定义域绕 Y 轴旋转 30°。**

现在可以移动、旋转和缩放用于生成哈希的定义域。效果相当于移动、旋转或缩放用于采样哈希函数的平面。因此，定义域向右移动时，哈希图案看起来会向左移动，因为平面本身保持不动。同样，旋转看起来会朝相反方向进行，而放大定义域会让图案看起来更小。

### 三维哈希

空间变换可以在三维中进行，例如沿 Y 轴移动。但由于当前哈希只依赖 X 和 Z，这样做不会有任何影响。同样，例如绕 X 轴旋转时，哈希方块会被拉长，直到从中心一直延伸到平面边缘。

![[images/hashing-space/grid-transformation/domain-rotation-x90.png]]
**图：定义域绕 X 轴旋转 90°。**

要将图案划分为哈希立方体，只需在 `Execute` 中把三个坐标都传给哈希函数。

```csharp
int u = (int)floor(p.x);
int v = (int)floor(p.y);
int w = (int)floor(p.z);

hashes[i] = hash.Eat(u).Eat(v).Eat(w);
```

现在沿 Y 轴移动也会影响哈希；绕某个轴旋转 90° 会生成方形图案，显示哈希体积中的另一个切片。

## 采样形状

既然我们有了三维哈希体积，就不必只用平面形状采样。可以编写其他作业，以不同形状采样哈希体积。

### 形状作业

我们不创建多个不同版本的 `HashJob`，而是将生成形状与采样哈希体积拆成两个作业。为此，在新文件中创建静态 `Shapes` 类，先放入一个 `Job` 结构体：它为平面生成 `float3` 位置，并将位置存入原生数组。定义域变换作用于哈希过程，因此不属于形状作业。形状作业只需要分辨率、分辨率倒数和输入数据。

```csharp
using Unity.Burst;
using Unity.Collections;
using Unity.Jobs;
using Unity.Mathematics;

using static Unity.Mathematics.math;

public static class Shapes {

	[BurstCompile(FloatPrecision.Standard, FloatMode.Fast, CompileSynchronously = true)]
	public struct Job : IJobFor {

		[WriteOnly]
		NativeArray<float3> positions;

		public float resolution, invResolution;

		public void Execute (int i) {
			float2 uv;
			uv.y = floor(invResolution * i + 0.00001f);
			uv.x = invResolution * (i - resolution * uv.y + 0.5f) - 0.5f;
			uv.y = invResolution * (uv.y + 0.5f) - 0.5f;

			positions[i] = float3€(uv.x, 0f, uv.y);
		}
	}
}
```

再为作业添加静态 `ScheduleParallel` 方法，将作业的创建与调度封装起来，并接收、返回一个作业句柄。这个方法不需要把分辨率倒数作为参数，因为它可以自行计算。

```csharp
public struct Job : IJobFor {
	
	…
	
	public static JobHandle ScheduleParallel (
		NativeArray<float3> positions, int resolution, JobHandle dependency
	) {
		return new Job {
			positions = positions,
			resolution = resolution,
			invResolution = 1f / resolution
		}.ScheduleParallel(positions.Length, resolution, dependency);
	}
}
```

### 生成位置

这些位置会传给 `HashJob`，绘制实例时也会用到。因此，要在 `HashVisualization` 中添加着色器标识符、原生数组和位置缓冲区，并在需要时创建和释放它们。

```csharp
static int
	hashesId = Shader.PropertyToID("_Hashes"),
	positionsId = Shader.PropertyToID("_Positions"),
	configId = Shader.PropertyToID("_Config");

…

NativeArray<uint> hashes;

NativeArray<float3> positions;

ComputeBuffer hashesBuffer, positionsBuffer;

MaterialPropertyBlock propertyBlock;

void OnEnable () {
	int length = resolution * resolution;
	hashes = new NativeArray<uint>(length, Allocator.Persistent);
	positions = new NativeArray<float3>(length, Allocator.Persistent);
	hashesBuffer = new ComputeBuffer(length, 4);
	positionsBuffer = new ComputeBuffer(length, 3 * 4);

	…
}

void OnDisable () {
	hashes.Dispose();
	positions.Dispose();
	hashesBuffer.Release();
	positionsBuffer.Release();
	hashesBuffer = null;
	positionsBuffer = null;
}
```

在 `OnEnable` 中先调度形状作业，再调度哈希作业，并把前者的句柄传给后者，因为必须先生成位置才能进行哈希。之后还要把位置发送到 GPU。

```csharp
JobHandle handle = Shapes.Job.ScheduleParallel(positions, resolution, default);

new HashJob {
	…
}.ScheduleParallel(hashes.Length, resolution, handle).Complete();

hashesBuffer.SetData(hashes);
positionsBuffer.SetData(positions);

propertyBlock ??= new MaterialPropertyBlock();
propertyBlock.SetBuffer(hashesId, hashesBuffer);
propertyBlock.SetBuffer(positionsId, positionsBuffer);
```

调整 `HashGPU`，让它使用传入的位置，而不是自行生成平面；再在该位置上叠加垂直偏移。

```hlsl

		unity_ObjectToWorld._m00_m11_m22 = _Config.y;
	#endif
}
```

### 形状变换

采样时可以变换定义域，生成形状时也可以变换形状本身。为此，在 `Shapes.Job` 中添加一个 `float3x4` 位置变换，并在 `Execute` 中用它修改最终位置。

```csharp
public float3x4 positionTRS;

public void Execute (int i) {
	…

	positions[i] = mul(positionTRS, float4€(uv.x, 0f, uv.y, 1f));
}
```

此处可以直接使用可视化游戏对象的 `Transform` 组件中的矩阵，这样形状会按预期变换，而不是固定在原点。为了简化操作，在 `ScheduleParallel` 中添加 `float4x4` 参数，并将其相关的 3×4 部分传给作业。

```csharp
public static JobHandle ScheduleParallel (
	NativeArray<float3> positions, int resolution,
	float4x4 trs, JobHandle dependency
) {
	return new Job {
		positions = positions,
		resolution = resolution,
		invResolution = 1f / resolution,
		positionTRS = float3x4€(trs.c0.xyz, trs.c1.xyz, trs.c2.xyz, trs.c3.xyz)
	}.ScheduleParallel(positions.Length, resolution, dependency);
}
```

在 `HashVisualization.OnEnable` 中调度作业时，将局部到世界变换矩阵传入。

```csharp
JobHandle handle = Shapes.Job.ScheduleParallel(
	positions, resolution, transform.localToWorldMatrix, default
);
```

### 也可以旋转和缩放实例网格吗？

可以，将合适的矩阵传给 GPU，并让 `HashGPU` 把它合并到最终矩阵中即可。不过，非均匀缩放可能引发问题，因为这里假设缩放是均匀的。因此我保留实例原样。

### 更新位置

若要在播放模式下响应变换变化，就要在 `Update` 而不是 `OnEnable` 中运行作业。不过，只有发生变化时才需要运行，不必每帧都运行。我们在 `HashVisualization` 中添加 `bool isDirty` 字段来表示这一点：当可视化中的相关内容发生变化，需要刷新时，它就处于脏状态。每次调用 `OnEnable` 都需要刷新，因此在那里将 `isDirty` 设为 `true`。

```csharp
bool isDirty;

void OnEnable () {
	isDirty = true;

	…
}
```

在 `Update` 绘制之前检查可视化是否处于脏状态。如果是，就将 `isDirty` 设为 `false`、运行作业，并用新数据填充缓冲区。

```csharp
void Update () {
	if (isDirty) {
		isDirty = false;

		JobHandle handle = Shapes.Job.ScheduleParallel(
			positions, resolution, transform.localToWorldMatrix, default
		);

		new HashJob {
			positions = positions,
			hashes = hashes,
			hash = SmallXXHash.Seed(seed),
			domainTRS = domain.Matrix
		}.ScheduleParallel(hashes.Length, resolution, handle).Complete();

		hashesBuffer.SetData(hashes);
		positionsBuffer.SetData(positions);
	}

	Graphics.DrawMeshInstancedProcedural(…);
}
```

这样一来，就不必再在 `OnEnable` 中执行这些工作。


最后，当变换发生变化时，也要在 `Update` 中刷新可视化。`Transform.hasChanged` 属性会在每次变换变化后设为 `true`。它不会自动恢复为 `false`，所以检测到变化后必须手动重置。

```csharp

}
```

### 位移

如果平面可以采用任意朝向，那么基于哈希值施加的偏移就应该沿着平面的法线方向，而不是始终沿世界 Y 轴方向。一般来说，位移方向取决于形状；形状不一定是平面，这时每个采样点都可能有自己的位移方向。为此，将 `verticalOffset` 字段替换为 `displacement` 字段，之后它表示世界空间中的单位距离，而不再是相对于分辨率的值。

```csharp
//[SerializeField, Range(-2f, 2f)]
//float verticalOffset = 1f;

[SerializeField, Range(-0.5f, 0.5f)]
float displacement = 0.1f;

…

void OnEnable () {
	…
	
	propertyBlock ??= new MaterialPropertyBlock();
	propertyBlock.SetVector(configId, new Vector4(
		resolution, 1f / resolution, displacement
	));
}
```

![[images/hashing-space/sample-shapes/displacement-inspector.png]]
**图：以位移代替垂直偏移。**

沿表面法线方向位移（即沿远离形状表面的方向位移）要求 `Shapes.Job` 同时输出法线向量。对于 XZ 平面，法线始终朝正上方，但也要对法线应用变换。按需调整作业和 `ScheduleParallel` 方法。

```csharp
public struct Job : IJobFor {

	[WriteOnly]
	NativeArray<float3> positions, normals;

	public float resolution, invResolution;

	public float3x4 positionTRS;

	public void Execute (int i) {
		…

		positions[i] = mul(positionTRS, float4€(uv.x, 0f, uv.y, 1f));
		normals[i] = normalize(mul(positionTRS, float4€(0f, 1f, 0f, 1f)));
	}

	public static JobHandle ScheduleParallel (
		NativeArray<float3> positions, NativeArray<float3> normals, int resolution,
		float4x4 trs, JobHandle dependency
	) {
		return new Job {
			positions = positions,
			normals = normals,
			…
		}.ScheduleParallel(positions.Length, resolution, dependency);
	}
}
```

## 手动向量化

如前所述，引入向量类型后，作业的自动向量化失败了。典型的自动向量化方式，是把针对 `float`、`int` 等基本类型的运算替换成针对 `float4`、`int4` 等类型的同类运算。这样作业就能并行执行四次迭代，利用 SIMD 指令加速。遗憾的是，由于我们使用 `float3` 来表示位置和法线向量，自动向量化已无法用于这些作业。不过，稍加改造后仍可手动向量化。

### 向量化哈希

`SmallXXHash` 结构体本来就是为自动向量化设计的。要支持手动向量化，需要创建一个能够并行处理四个值的 `SmallXXHash4` 版本。复制并重命名这个结构体，与原结构体放在同一个文件中。从现在开始还需要使用 Mathematics 库。

```csharp
using Unity.Mathematics;

public readonly struct SmallXXHash { … }

public readonly struct SmallXXHash4 { … }
```

确保 `SmallXXHash4` 内部所有指向自身类型的引用都改为向量版本，而不是单值版本。另外，由于没有对应的字节向量类型，要从中移除该方法；同时移除常量 `primeA`，因为其他方法不再使用它。

```csharp
public readonly struct SmallXXHash4 {

	//const uint primeA = 0b10011110001101110111100110110001;
	const uint primeB = 0b10000101111010111100101001110111;
	const uint primeC = 0b11000010101100101010111000111101;
	const uint primeD = 0b00100111110101001110101100101111;
	const uint primeE = 0b00010110010101100110011110110001;

	readonly uint accumulator;

	public SmallXXHash4 (uint accumulator) {
		this.accumulator = accumulator;
	}

	public static implicit operator SmallXXHash4 (uint accumulator) =>
		new SmallXXHash4(accumulator);

	public static SmallXXHash4 Seed (int seed) => (uint)seed + primeE;

	static uint RotateLeft (uint data, int steps) =>
		(data << steps) | (data >> 32 - steps);

	public SmallXXHash4 Eat (int data) =>
		RotateLeft(accumulator + (uint)data * primeC, 17) * primeD;

	//public SmallXXHash Eat (byte data) =>
	//	RotateLeft(accumulator + data * primeE, 11) * primeA;

	public static implicit operator uint (SmallXXHash4 hash) { … }
}
```

接下来，将所有 `int` 和 `uint` 类型替换为 `int4` 和 `uint4`。唯一的例外是 `RotateLeft` 的 `steps` 参数，它必须仍是单个 `int`。

```csharp
readonly uint4 accumulator;

public SmallXXHash4 (uint4 accumulator) {
	this.accumulator = accumulator;
}

public static implicit operator SmallXXHash4 (uint4 accumulator) =>
	new SmallXXHash4(accumulator);

public static SmallXXHash4 Seed (int4 seed) => (uint4)seed + primeE;

static uint4 RotateLeft (uint4 data, int steps) =>
	(data << steps) | (data >> 32 - steps);

public SmallXXHash4 Eat (int4 data) =>
	RotateLeft(accumulator + (uint4)data * primeC, 17) * primeD;

public static implicit operator uint4 (SmallXXHash4 hash) {
	uint4 avalanche = hash.accumulator;
	…
}
```

这样就足以让 `SmallXXHash4` 向量化。再给 `SmallXXHash` 添加一个运算符，让单值版本可以隐式转换为向量版本。

```csharp
public readonly struct SmallXXHash {

	…

	public static implicit operator SmallXXHash4 (SmallXXHash hash) =>
		new SmallXXHash4(hash.accumulator);
}
```

### 也可以反向转换吗？

把一个哈希值转换为向量哈希，只需复制这个值即可。但反向转换则必须想办法把四个相互独立的哈希合并成一个值，没有简单直接的做法，因此不添加这种转换。

### 向量化哈希作业

接下来向量化 `HashJob`。先将它的哈希输出和哈希输入替换为四分量版本。

```csharp
[WriteOnly]
public NativeArray<uint4> hashes;

public SmallXXHash4 hash;
```

还需要并行处理四个位置。可以把一组四个位置存入一个 `float3x4` 矩阵，每一列各包含一个位置。

```csharp
[ReadOnly]
public NativeArray<float3x4> positions;
```

不过，为了向量化计算，`Execute` 需要分别取得 x、y、z 分量的向量，而不是每个位置各对应一个向量。对位置矩阵调用 `transpose` 方法，就能得到布局符合要求的 `float4x3` 矩阵。这样也可以向量化提取 u、v、w，暂时先不应用定义域变换。

![[images/hashing-space/manual-vectorization/transposing-matrix.png]]
**图：将 3×4 矩阵转置为 4×3 矩阵。**

```csharp
public void Execute(int i) {
	float4x3 p = transpose(positions[i]);

	int4 u = (int4)floor(p.c0);
	int4 v = (int4)floor(p.c1);
	int4 w = (int4)floor(p.c2);

	hashes[i] = hash.Eat(u).Eat(v).Eat(w);
}
```

现在需要在 `Update` 中把向量化数组传给作业。所需数组已经存在，只需将它们重新解释为每个元素包含四个 `float3` 值即可。`NativeArray` 提供了 `Reinterpret` 泛型方法，可以指定目标类型和原始元素大小来完成转换。这样作业的有效数组长度会缩短为四分之一，因此调度作业时也要把长度除以 4。

```csharp
new HashJob {
	positions = positions.Reinterpret<float3x4>(3 * 4),
	hashes = hashes.Reinterpret<uint4>(4),
	hash = SmallXXHash.Seed(seed),
	domainTRS = domain.Matrix
}.ScheduleParallel(hashes.Length / 4, resolution, handle).Complete();
```

这要求数组长度能被 4 整除，否则重新解释操作会失败。因此要确保分辨率为偶数。

### 向量化变换

现有的数学方法无法将 3×4 TRS 矩阵与按列存储 XYZ 分量的 4×3 矩阵相乘。我们在 `HashJob` 中添加 `TransformPositions` 方法来完成这项工作：它接收前面提到的矩阵，并返回经过变换、按列存储 XYZ 分量的 4×3 矩阵。最初可以直接返回未变换的位置，然后在 `Execute` 中调用它。

```csharp
float4x3 TransformPositions (float3x4 trs, float4x3 p) => p;

public void Execute(int i) {
	float4x3 p = TransformPositions(domainTRS, transpose(positions[i]));

	…
}
```

这是常规的矩阵乘法，只不过包含平移量的第四个 TRS 列只需直接相加。前一次矩阵乘法中最后一部分需要乘以常量 1，这里可以省略该操作。

由于位置分量已经向量化，乘法操作会针对整个位置矩阵列执行，而不是针对单个分量执行。

```csharp
float4x3 TransformPositions (float3x4 trs, float4x3 p) => float4x3(
	trs.c0.x * p.c0 + trs.c1.x * p.c1 + trs.c2.x * p.c2 + trs.c3.x,
	trs.c0.y * p.c0 + trs.c1.y * p.c1 + trs.c2.y * p.c2 + trs.c3.y,
	trs.c0.z * p.c0 + trs.c1.z * p.c1 + trs.c2.z * p.c2 + trs.c3.z
);
```

现在可视化效果与之前相同，但 `HashJob` 已经向量化。Burst Inspector 的诊断视图仍会显示作业没有向量化，因为 Burst 不知道我们是手动完成的。检查生成的汇编代码可以看到，作业确实使用了 SIMD 指令，并行生成四个哈希值。

### 向量化形状作业

最后，用相同的方法向量化 `Shapes.Job`。首先将位置和法线数组的元素类型改为 `float3x4`。

```csharp
[WriteOnly]
NativeArray<float3x4> positions, normals;

…

public static JobHandle ScheduleParallel (
	NativeArray<float3x4> positions, NativeArray<float3x4> normals,
	int resolution, float4x4 trs, JobHandle dependency

```

在 `Execute` 中，使用 4×2 UV 列矩阵向量化 UV 坐标的计算。

```csharp
float4x2 uv;
uv.c1 = floor(invResolution * i + 0.00001f);
uv.c0 = invResolution * (i - resolution * uv.c1 + 0.5f) - 0.5f;
uv.c1 = invResolution * (uv.c1 + 0.5f) - 0.5f;
```

要把单个索引参数替换为对应的四个向量化索引，需要先将原索引乘以 4，再分别给各个索引加上 0、1、2 和 3。

```csharp
float4 i4 = 4f * i + float4€(0f, 1f, 2f, 3f);
uv.c1 = floor(invResolution * i4 + 0.00001f);
uv.c0 = invResolution * (i4 - resolution * uv.c1 + 0.5f) - 0.5f;
```

接下来也要应用 TRS 变换，不过这次要同时变换位置和法线向量。为了用一个方法处理两者，将 `TransformPositions` 从 `HashJob` 复制到 `Shapes.Job`，改名为 `TransformVectors`，并添加一个默认值为 1 的 `float w` 参数。用它乘以平移部分。

```csharp
float4x3 TransformVectors (float3x4 trs, float4x3 p, float w = 1f) => float4x3(
	trs.c0.x * p.c0 + trs.c1.x * p.c1 + trs.c2.x * p.c2 + trs.c3.x * w,
	trs.c0.y * p.c0 + trs.c1.y * p.c1 + trs.c2.y * p.c2 + trs.c3.y * w,
	trs.c0.z * p.c0 + trs.c1.z * p.c1 + trs.c2.z * p.c2 + trs.c3.z * w
);
```

在 `Execute` 中，先生成包含平面位置的 4×3 XYZ 列矩阵，应用位置 TRS 变换，再将其转置，以便赋值给位置输出元素。

```csharp
positions[i] =
	transpose(TransformVectors(positionTRS, float4x3€(uv.c0, 0f, uv.c1)));
```

法线向量也采用相同处理，不过这次将 0 作为第三个参数传给 `TransformVectors`，以忽略平移。Burst 会移除所有乘以常量 0 的运算。最后，对 3×4 矩阵各列中的向量进行归一化。

```csharp
float3x4 n =
	transpose(TransformVectors(positionTRS, float4x3€(0f, 1f, 0f), 0f));
normals[i] = float3x4€(
	normalize(n.c0), normalize(n.c1), normalize(n.c2), normalize(n.c3)
);
```

### 向量化数组

既然两个作业都需要向量化数组，就直接在 `HashVisualization` 中将数组定义为向量化形式，而不是之后再重新解释。


若要让计算缓冲区保持原来的大小，现在需要将它们的长度乘以 4。

### 能否直接把向量化数据复制到计算缓冲区？

虽然 CPU 和 GPU 会以各自的方式解释计算缓冲区中的数据，但某些情况下可能发生数据未对齐。因此必须确保计算缓冲区使用的是未向量化的数据。

此时也可以重新支持奇数分辨率。例如分辨率为 3 时，初始长度是 9，向量化后的长度会变成 2，只能表示 8 个元素。只需给最终长度加 1，就能容纳第 9 个元素。这样会多分配四个值，其中三个不会用到，但开销可以忽略。对于任意分辨率，都可以在 `OnEnable` 中将初始长度的最低位加到向量化长度上：偶数长度的最低位为 0，奇数长度则为 1。

```csharp
int length = resolution * resolution;
length = length / 4 + (length & 1);
```

现在不必再在 `Update` 中为 `HashJob` 重新解释数组。调度作业时也要重新使用数组的长度，因为它已经在向量化时缩短了。

```csharp
new HashJob {
	positions = positions,
	hashes = hashes,
	hash = SmallXXHash.Seed(seed),
	domainTRS = domain.Matrix
}.ScheduleParallel(hashes.Length, resolution, handle).Complete();
```

最后，调用 `Graphics.DrawMeshInstancedProcedural` 时传入分辨率的平方，以绘制正确数量的实例。

```csharp

	instanceMesh, 0, material, bounds, resolution * resolution, propertyBlock
);
```

## 更多形状

两个作业都完成向量化后，我们将添加两种备选采样形状。可以为每种形状创建单独的作业，但大部分代码都会重复。因此改用基于模板的方法。

### Plane 结构体

为了支持多种形状，将生成位置和法线的代码从 `Shapes.Job` 移到 `Shapes` 类中。每种形状都可以用独特的方式生成，不过这里统一以 UV 网格为基础。为避免重复代码，将 `Job.Execute` 中的 UV 代码复制到 `Shapes` 的新静态方法 `IndexTo4UV` 中。移除减去 0.5 的操作，使 UV 范围从 −0.5 到 0.5 改为 0 到 1。

```csharp
public static class Shapes {
	
	public static float4x2 IndexTo4UV (int i, float resolution, float invResolution) {
		float4x2 uv;
		float4 i4 = 4f * i + float4€(0f, 1f, 2f, 3f);
		uv.c1 = floor(invResolution * i4 + 0.00001f);
		uv.c0 = invResolution * (i4 - resolution * uv.c1 + 0.5f);
		uv.c1 = invResolution * (uv.c1 + 0.5f);
		return uv;
	}
	
	…
}
```

每个形状作业唯一不同的部分，是设置位置和法线的方式。为传递这些数据，在 `Shapes` 中加入 `Point4` 结构体，用来简单封装向量化后的位置和法线。

```csharp
public static class Shapes {

	public struct Point4 {
		public float4x3 positions, normals;
	}

	…
}
```

要将生成平面的代码从 `Job.Execute` 中提取出来，在 `Shapes` 中添加 `Plane` 结构体，其中包含 `GetPoint4` 方法。该方法接收索引、分辨率和分辨率倒数，并生成 `Point4` 值。由于 UV 范围已改变，现在要在此处从 UV 中减去 0.5，才能让平面继续以原点为中心。

```csharp
public struct Plane {

	public Point4 GetPoint4 (int i, float resolution, float invResolution) {
		float4x2 uv = IndexTo4UV(i, resolution, invResolution);
		return new Point4 {
			positions = float4x3(uv.c0 - 0.5f, 0f, uv.c1 - 0.5f),
			normals = float4x3(0f, 1f, 0f)
		};
	}
}
```

`Plane` 结构体没有字段，其唯一用途是提供 `GetPoint4` 方法。在 `Job.Execute` 中，可以通过 `default(Plane)` 调用该方法。这就替换了原先显式生成平面的代码。

```csharp
public void Execute (int i) {
	//float4x2 uv;
	//float4 i4 = 4f * i + float4(0f, 1f, 2f, 3f);
	//uv.c1 = floor(invResolution * i4 + 0.00001f);
	//uv.c0 = invResolution * (i4 - resolution * uv.c1 + 0.5f) - 0.5f;
	//uv.c1 = invResolution * (uv.c1 + 0.5f) - 0.5f;
	
	Point4 p = default(Plane).GetPoint4(i, resolution, invResolution);

	positions[i] = transpose(TransformVectors(positionTRS, p.positions));

	float3x4 n = transpose(TransformVectors(positionTRS, p.normals, 0f));
	normals[i] = float3x4€(
		normalize(n.c0), normalize(n.c1), normalize(n.c2), normalize(n.c3)

}
```

### 形状接口

我们希望能够将 `Plane` 替换成其他结构体类型，以生成不同的形状。要让泛型形状能够实现这一点，需要引入接口类型。接口相当于一份契约，规定类或结构体必须提供哪些公开方法或属性。

使用 `interface` 关键字声明接口，按照惯例，类型名称以 I 开头，因此这里命名为 `IShape`。在接口中定义 `GetPoint4` 方法签名，不写方法体，只以分号结束。接口成员默认公开，所以不需要显式访问修饰符。之后让 `Plane` 扩展并实现该接口即可。

```csharp
public interface IShape {
	Point4 GetPoint4 (int i, float resolution, float invResolution);
}

public struct Plane : IShape {

	public Point4 GetPoint4 (int i, float resolution, float invResolution) { … }
}
```

### 泛型作业

下一步是把作业改为泛型，使它成为作业模板。为此，在 `Job` 的类型声明后用尖括号附加泛型类型参数。按照惯例，类型参数名通常是单个字母。由于该参数代表形状类型，这里命名为 `S`。

```csharp
public struct Job<S> : IJobFor { … }
```

我们要通过两项约束限制 `S` 的类型：第一，它必须是结构体；第二，它必须实现 `IShape` 接口。在 `Job` 类型声明后添加 `where S : struct, IShape` 即可。

```csharp
public struct Job<S> : IJobFor where S : struct, IShape { … }
```

现在可以在 `Execute` 中使用这个泛型类型，而不是明确指定某个类型。

```csharp
public void Execute (int i) {
	Point4 p = default(S).GetPoint4(i, resolution, invResolution);

	…
}
```

创建 `ScheduleParallel` 方法中的作业时，也必须指定要创建的作业类型，和创建 `NativeArray` 等其他泛型类型值时一样。这里应使用同一种作业类型，因此将 `S` 作为泛型参数传入。

```csharp
return new Job<S> {
	…
}.ScheduleParallel(positions.Length, resolution, dependency);
```

最后，在 `HashVisualization.Update` 中调度时，明确指定形状作业的类型。

```csharp
JobHandle handle = Shapes.Job<Shapes.Plane>.ScheduleParallel(
	positions, normals, resolution, transform.localToWorldMatrix, default
);
```

注意，在 Burst Inspector 中，平面作业现在显示为 `Shapes.Job`1[Shapes.Plane]`，而不再只是 `Shapes.Job`。除此之外，生成的汇编代码与之前相同。

### 球体与圆环

现在可以轻松添加更多形状作业。我们会再添加两个，先从球体开始。可以复制并调整[“数学曲面”教程](https://catlikecoding.com/unity/tutorials/basics/mathematical-surfaces/)中的代码。区别在于，由于 UV 范围不同，`sin` 和 `cos` 方法的所有参数都要乘以 2；计算 `s` 和 `c1` 时，还要交换 `sin` 和 `cos`。将半径设为 0.5，使其包含在单位立方体内。

球体的法线可以直接使用位置向量。它们的长度是 0.5，不过没有关系，因为作业会在应用空间变换后将法线归一化。

```csharp
public struct Plane : IShape { … }

public struct Sphere : IShape {

	public Point4 GetPoint4 (int i, float resolution, float invResolution) {
		float4x2 uv = IndexTo4UV(i, resolution, invResolution);

		float r = 0.5f;
		float4 s = r * sin(PI * uv.c1);

		Point4 p;
		p.positions.c0 = s * sin(2f * PI * uv.c0);
		p.positions.c1 = r * cos(PI * uv.c1);
		p.positions.c2 = s * cos(2f * PI * uv.c0);
		p.normals = p.positions;
		return p;
	}
}
```

要使用球体形状，只需在 `HashVisualization.Update` 中更改 `Shapes.Job` 的泛型类型参数。

```csharp
JobHandle handle = Shapes.Job<Shapes.Sphere>.ScheduleParallel(
	positions, normals, resolution, transform.localToWorldMatrix, default
);
```

![[images/hashing-space/more-shapes/uv-sphere.png]]
**图：球体形状，位移为零。**

第二种形状是圆环，同样复制自[“数学曲面”教程](https://catlikecoding.com/unity/tutorials/basics/mathematical-surfaces/)，并再次将 `sin` 和 `cos` 方法的参数乘以 2。将 `r1` 设为 0.375，`r2` 设为 0.125。

```csharp
public struct Torus : IShape {

	public Point4 GetPoint4 (int i, float resolution, float invResolution) {
		float4x2 uv = IndexTo4UV(i, resolution, invResolution);

		float r1 = 0.375f;
		float r2 = 0.125f;
		float4 s = r1 + r2 * cos(2f * PI * uv.c1);

		Point4 p;
		p.positions.c0 = s * sin(2f * PI * uv.c0);
		p.positions.c1 = r2 * sin(2f * PI * uv.c1);
		p.positions.c2 = s * cos(2f * PI * uv.c0);
		p.normals = p.positions;
		return p;
	}
}
```

圆环表面的法线比球体复杂一些。法线不能全部从中心向外，而是要从圆环管截面的中心向外。这里不必担心重复计算，因为 Burst 会将重复部分优化掉。

```csharp
p.normals = p.positions;
p.normals.c0 -= r1 * sin(2f * PI * uv.c0);
p.normals.c2 -= r1 * cos(2f * PI * uv.c0);
```

现在可以切换为使用圆环形状进行采样。

```csharp
JobHandle handle = Shapes.Job<Shapes.Torus>.ScheduleParallel(
	positions, normals, resolution, transform.localToWorldMatrix, default
);
```

![[images/hashing-space/more-shapes/torus.png]]
**图：圆环形状，位移为零。**

### 选择形状

要通过 Inspector 切换形状，需要添加代码，以便调用正确作业类型的 `ScheduleParallel`。同样可以参考[“数学曲面”教程](https://catlikecoding.com/unity/tutorials/basics/mathematical-surfaces/)，使用选择枚举和静态委托数组。

在 `Shapes` 中添加 `ScheduleDelegate` 委托类型，使其签名与 `ScheduleParallel` 一致。

```csharp
public delegate JobHandle ScheduleDelegate (
	NativeArray<float3x4> positions, NativeArray<float3x4> normals,
	int resolution, float4x4 trs, JobHandle dependency
);
```

可用形状由 `HashVisualization` 决定，因此要在那里添加形状枚举、委托数组和形状配置字段。

```csharp
public enum Shape { Plane€, Sphere€, Torus€ }

static Shapes.ScheduleDelegate[] shapeJobs = {
	Shapes.Job<Shapes.Plane>.ScheduleParallel,
	Shapes.Job<Shapes.Sphere>.ScheduleParallel,
	Shapes.Job<Shapes.Torus>.ScheduleParallel
};

…

[SerializeField]
Shape shape;
```

![[images/hashing-space/more-shapes/shape-inspector.png]]
**图：形状下拉选择菜单。**

然后调整 `Update`，让它生成当前选中的形状。

```csharp
JobHandle handle = shapeJobs[(int)shape](
	positions, normals, resolution, transform.localToWorldMatrix, default
);
```

### 变换后的法线

到目前为止，一切看起来都正常，但对球体或圆环使用非均匀缩放时会出问题。例如，几乎将球体压扁时，位移方向仍然是从球心向外，而不是垂直于变形后的表面，因此位移显得太平。

![[images/hashing-space/more-shapes/scaled-normals-incorrect.png]]
**图：球体的 Y 轴缩放为 0.01，位移为 0.5。**

这是因为非均匀缩放会破坏法线向量。法线必须通过不同的变换矩阵进行变换。为此，在 `Shapes.Job` 中添加单独的法线变换输入，并用它来变换法线。

```csharp
public float3x4 positionTRS, normalTRS;

…

public void Execute (int i) {
	…

	float3x4 n = transpose(TransformVectors(normalTRS, p.normals, 0f));
	…
}
```

要正确变换表面法线，必须使用 4×4 TRS 矩阵的逆矩阵的转置。可以在 `ScheduleParallel` 中通过 `transpose(inverse(trs))` 得到它。

```csharp
public static JobHandle ScheduleParallel (
	NativeArray<float3x4> positions, NativeArray<float3x4> normals,
	int resolution,	float4x4 trs, JobHandle dependency
) {
	float4x4 tim = transpose(inverse(trs));
	return new Job<S> {
		…
		positionTRS = float3x4(trs.c0.xyz, trs.c1.xyz, trs.c2.xyz, trs.c3.xyz),
		normalTRS = float3x4(tim.c0.xyz, tim.c1.xyz, tim.c2.xyz, tim.c3.xyz)
	}.ScheduleParallel(positions.Length, resolution, dependency);
}
```

![[images/hashing-space/more-shapes/scaled-normals-correct.png]]
**图：修正后的位移。**

### 八面体球

当前生成的球体称为 UV 球。它由一圈圈圆环组成，在两极处收缩为点，因此点的分布并不均匀：两极附近的点太密，赤道附近的点太疏。我们改用另一种方法，生成八面体球。

八面体球先在原点生成一个八面体，再将所有位置向量归一化。通过几个步骤，就能根据 0 到 1 范围的 UV 坐标生成八面体。首先，生成一个以原点为中心的 XY 平面。

```csharp
public struct Sphere : IShape {

	public Point4 GetPoint4 (int i, float resolution, float invResolution) {
		float4x2 uv = IndexTo4UV(i, resolution, invResolution);

		//float r = 0.5f;
		//float4 s = r * sin(PI * uv.c1);

		Point4 p;
		p.positions.c0 = uv.c0 - 0.5f;
		p.positions.c1 = uv.c1 - 0.5f;
		p.positions.c2 = 0f;
		p.normals = p.positions;
		return p;
	}
}
```

![[images/hashing-space/more-shapes/octahedron-plane.png]]
**图：XY 平面，位移为零。**

第二步，沿 Z 轴移动平面来生成八面体的面：令 Z 等于 0.5 减去 X 和 Y 的绝对值之和。这样会得到一个单侧展开的八面体形状。

```csharp
p.positions.c2 = 0.5f - abs(p.positions.c0) - abs(p.positions.c1);
```

![[images/hashing-space/more-shapes/octahedron-folded-open.png]]
**图：展开一侧的八面体。**

八面体的正 Z 一侧已经完成。要封闭负 Z 一侧，需要一个等于负 Z 的偏移量，并将它的最小值限制为 0，这样正 Z 一侧就不会受到影响。

```csharp
p.positions.c2 = 0.5f - abs(p.positions.c0) - abs(p.positions.c1);
float4 offset = max(-p.positions.c2, 0f);
```

我们需要分别对 X 和 Y 加上或减去这个偏移量：分量为负时加上，否则减去。X 和 Y 都按此规则处理。向量数据需要根据条件选择不同值，因此要使用 `select` 方法。它的签名是 `select(valueIfFalse, valueIfTrue, condition)`。

```csharp
float4 offset = max(-p.positions.c2, 0f);
p.positions.c0 += select(-offset, offset, p.positions.c0 < 0f);
p.positions.c1 += select(-offset, offset, p.positions.c1 < 0f);
```

![[images/hashing-space/more-shapes/octahedron-closed.png]]
**图：封闭后的八面体。**

最后，要把八面体转换为半径 0.5 的球体，需要乘以 0.5 再除以向量长度。可以使用勾股定理和 `rsqrt` 方法来计算。

```csharp
p.positions.c1 += select(-offset, offset, p.positions.c1 < 0f);

float4 scale = 0.5f * rsqrt(
	p.positions.c0 * p.positions.c0 +
	p.positions.c1 * p.positions.c1 +
	p.positions.c2 * p.positions.c2
);
p.positions.c0 *= scale;
p.positions.c1 *= scale;
p.positions.c2 *= scale;
p.normals = p.positions;
```

![[images/hashing-space/more-shapes/octahedron-sphere.png]]
![[images/hashing-space/more-shapes/uv-sphere.png]]
**图：八面体球和 UV 球。**

与 UV 球相比，八面体球有六个点聚集区域，而不是两个，但整体点分布更均匀。
