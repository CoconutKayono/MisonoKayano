Feline：用一串过滤探针
近似细长的纹理足迹

从为什么需要它，到一次能手算的完整采样

Feline 是一种具体的各向异性纹理过滤算法。它保留标准 Mipmap，在纹理空间沿一条线执行多次各向同性过滤，再加权合并。它解决的是“怎样读取纹理更合理”，而不是“怎样给模型生成 UV”。

阅读约定

本文是原创教学讲解，不是论文全文翻译。以论文 §3.1 的“期望计算”作为数值主线；Simple Feline、Table Feline 及优化变体另作区分。自绘圆形表示探针的名义有效范围，不是精确的硬件滤波核。所有灰度计算均在线性空间中进行。

1　它要解决的，是足迹形状不匹配

假设一个屏幕像素的过滤区域，在纹理空间内近似为细长椭圆。沿长轴需要混合较大范围，沿短轴只需要混合较小范围。普通三线性 Mipmap 过滤在两个方向采用相同的名义尺度：范围取得太小，长轴方向可能混叠；范围取得很大，短轴方向又会模糊。

Feline 的策略是：让每次过滤的大小适合短轴，再沿长轴排列多个过滤探针（Probes）。每个探针返回一个已经过滤过的颜色，并不是只返回某一个原始纹素。最终组合的是这些过滤结果。

先确认它在管线中的位置

三角形已经投影、光栅化，片元已经获得 UV，采样器还知道 UV 在相邻屏幕位置变化多少。Feline 从这里开始工作。位置怎样变成屏幕坐标、UV 怎样被插值，详见第二篇。

2　采样需要哪些输入？

对于二维纹理，一次普通隐式采样不只涉及中心 UV。采样器还可以利用纹理坐标对屏幕坐标的导数，估计局部缩放、方向和足迹。为了不混淆单位，本文把归一化坐标叫 u, v，把基准层纹素空间坐标叫 S, T：

S = W · u，T = H · v
gx = (W · ∂u/∂x, H · ∂v/∂x)
gy = (W · ∂u/∂y, H · ∂v/∂y)

W, H 是基准层纹理的宽、高；x, y 的单位是屏幕像素。因此 gx 的意思是“屏幕向右走一个像素，纹理空间大致移动多少纹素”。gy 同理。

给定屏幕滤波核，这两个向量可用来构造局部椭圆，得到长半轴 R、短半轴 r 和长轴单位方向 e。精确的局部轴可以由二维 Jacobian 的奇异值分解得到；Simple Feline 实际使用较便宜的轴长、方向近似，不能把精确求轴误写成它的实际硬件步骤。

半轴为什么不能与“一个像素宽度”随意互换？

论文用屏幕空间半径为 1 像素的圆形滤波核讲解：经局部仿射变换得到椭圆。若把几何上 1 × 1 像素方格的半宽 0.5 当作基准，得到的尺寸会不同。滤波核的支持范围、重建核以及几何像素方格不是同一个对象。下文直接给定“名义椭圆半轴 R = 8、r = 2 纹素”，不把它混称为“一个像素恰好覆盖 8 × 2 纹素”。

3　完整算例：16 × 4 纹素的名义椭圆

设纹理为 1024 × 1024，采样中心为 UV = (0.5, 0.5)，即纹素空间中心 (S, T) = (512, 512)。给定长半轴 R = 8、短半轴 r = 2，长轴朝向 30°。这个椭圆的全长是 16 纹素，全宽是 4 纹素。

先假设预算足够。下面按原论文 §3.1 的探针布局和权重公式计算，暂不使用 §3.3 的进一步提速策略。

3.1　选择探针的名义大小与 Mipmap 层级

探针名义半径取短半轴大小，也就是 2 纹素。按论文约定：

LOD = log2(r) = log2(2) = 1

因此从第 1 级 Mipmap 进行过滤。若 LOD 是小数，三线性过滤还会在相邻层级之间插值。注意：Mipmap 的一个纹素对应多少基准层纹素，与探针滤波核的完整支持范围不能简单画等号；这里遵循论文的“名义半径”约定。

3.2　为什么本例用 7 个探针？

期望数量 F = 2 · R / r − 1 = 2 · 8 / 2 − 1 = 7
N = min(floor(F + 0.5), maxProbes)

探针中心不放在椭圆两端，而是各向里缩一个短半轴：

中心线长度 L = 2(R − r) = 12
探针间距 Δ = L / (N − 1) = 12 / 6 = 2 纹素
d = −6, −4, −2, 0, 2, 4, 6

d 是沿长轴相对中心的有符号距离。各向异性比 R/r = 4，并不意味着这段原论文公式必然使用 4 个探针。这里得到 7 个，不能把现代 API 的“4× AF”直接套成它的探针数量。

3.4　怎样加权成为一个颜色？

取论文示例使用的 Gaussian 参数 α = 2。沿轴的归一化距离为 d/R，因此：

wi = exp[−2(di/R)2]
C = Σ(wi · Ci) / Σwi

4　探针预算不足时，为什么会重新变模糊？

仍然是 R = 8、r = 2。若最多只允许 4 个探针，直接减少采样、却保持探针很小，会使覆盖过于稀疏。论文 §3.1 的处理是增大短半轴，也增大每个探针的过滤范围：

若 N < F，则 r′ = 2R / (N + 1)
N = 4 → r′ = 16/5 = 3.2
LOD = log2(3.2) ≈ 1.678072
L = 2(8 − 3.2) = 9.6；Δ = 9.6/3 = 3.2

因此 4 个中心位于 d = −4.8、−1.6、1.6、4.8。每个探针变宽，短轴细节损失增加，但比留下明显的过滤空隙更稳妥。若只允许 1 个探针，r′ = 8，LOD = 3，最后就退化为中心处的大范围各向同性过滤。

5　Feline 不只是“多采几次”

它并非最早提出沿线组合各向同性探针的算法。相较于论文讨论的前代方案，关键改进涉及采样线长度、探针间距、数量取整、预算不足时扩大范围，以及 Gaussian 加权。布点方向合理但距离过大，仍会产生混叠；密度足够但范围过宽，又会模糊。

称呼这里应怎样理解
§3.1 的期望计算先解释理想几何、布局和加权。本文完整算例与计算器采用这一主线。
Simple Feline使用较便宜的轴近似、长度近似与查表权重，适合当时硬件实现。
Table Feline通过表格更准确地估计椭圆轴；论文指向配套技术报告详述。
§3.3 提速策略还可允许少量缩短、加宽或增加探针间距，以质量换取更少采样。
现代硬件 AF是 API 暴露的过滤功能，其具体采样算法由实现决定，不能直接与上述某一版本画等号。

另外，组合相同半径的小圆并不精确等于一个椭圆。真实三线性核也不是理想圆盘。Feline 在计算成本与椭圆加权过滤质量之间取折中；EWA（Elliptical Weighted Average）是另一类直接针对椭圆区域加权的方法。

6　把数值过程写成伪代码

下面展示采样逻辑。它不是可直接复制到所有 Unity 渲染管线的完整 Shader：函数参数、纹理资源与采样器绑定需要按项目补齐。probeSampler 必须是各向同性的三线性采样器，避免每个手动探针又触发一轮硬件各向异性采样。

// uvCenter：归一化 UV；textureSize：基准层宽、高
// R、r：名义半轴，单位为基准层纹素，已保证 R >= r >= 1
// axis：纹素空间长轴单位方向；maxProbes >= 1
float desired = 2 * R / r - 1;
int N = min((int)floor(desired + 0.5), maxProbes);

if (N < desired)
    r = 2 * R / (N + 1);       // 增宽探针，抑制稀疏采样混叠

float lod = log2(r);
if (lod > lastMip) {          // 最后一级已经是 1×1
    lod = lastMip;
    N = 1;
}

float lineLength = 2 * (R - r);
float4 sum = 0;
float weightSum = 0;
for (int i = 0; i < N; ++i) {
    float d = (N == 1) ? 0 : -lineLength/2 + i*lineLength/(N-1);
    float2 probeUV = uvCenter + d*axis/textureSize;
    float weight = exp(-2 * (d/R) * (d/R));
    float4 color = texture.SampleLevel(probeSampler, probeUV, lod);
    sum += weight * color;
    weightSum += weight;
}
return sum / weightSum;

SampleLevel 这里明确指定 LOD，是因为每个探针的过滤尺度已经由算法决定。生产实现还要处理精度、各向异性比上限、足迹估计、纹理地址模式和更高效的权重计算。

7　与 Ripmap、今天的 Unity 有什么关系？

标准 Mipmap 同时缩小宽、高。Ripmap 则预先存储宽、高分别缩小的多种组合，能提供轴对齐的长方形预滤波。它用更多存储换取采样时的便利；Feline 用普通 Mipmap 加多个探针，适应旋转的长轴方向。

方案纹理层级数据量运行时主要特点
标准 Mipmap约为原图的 4/3层级结构紧凑；普通各向同性采样难贴合细长足迹。
Feline 这一主线继续使用标准 Mipmap组合多次探针过滤，增加采样工作，不要求整套 Ripmap。
标准 Ripmap约为原图的 4分别预滤波两个纹理轴，长方形方向仍与 U、V 轴对齐。

上述存储比由完整层级的纹素数推导，针对较大的二维纹理，忽略压缩、对齐及元数据。Feline 的“与 Mipmap 相同内存”指纹理层级数据，不表示额外计算与采样是免费的。

今天在 Unity 中启用 Aniso Level，通常是在请求底层采样器执行硬件 AF。OpenGL 规范明确把算法留给实现；Direct3D 12 的 MaxAnisotropy 是上限参数。因而“16× AF”既不意味着 16 倍纹理内存，也不能直接解释为 Feline 每次固定使用 16 个探针。

实际观察时，可以给一个 Plane 使用高对比地面纹理，启用 Mipmap，让相机以浅角度观察，再比较 Aniso Level = 1、4、16；同时确认质量设置允许使用纹理自身的 AF 设置。成本与清晰度应在目标设备上实测。AF 改善的是纹理采样，不会提高原图的真实信息量，也不能代替几何边缘抗锯齿。
