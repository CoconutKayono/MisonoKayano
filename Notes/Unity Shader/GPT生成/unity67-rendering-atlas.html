01

五个层次，别混成一个概念

遇到新术语，先问它属于哪一层。点击每一层，查看它负责的事和最容易混淆的边界。

一条完整关系：相机请求渲染 → 当前 Pipeline 组织工作 → Renderer / 路径安排 Pass → Render Graph 描述资源依赖 → Shader 在 GPU 上处理几何、像素或计算任务。

概念依据：HDRP 概览 · URP Render Graph。这是一张分工图，实际内部调用会更复杂。

03

设置分层，决定你该去哪里改

同一个“效果没出现”，可能是管线不支持、相机没开启、Volume 没生效，或材质根本没参与对应的 Pass。

URP · 以 Renderer 组织功能

Graphics / Quality → URP Asset选择管线资产；Quality 的有效覆盖优先于 Graphics 默认值
URP Asset → Renderer Data渲染器列表与默认项；分辨率、阴影等管线设置
Universal Renderer / 2D Renderer3D 或 2D 的组织方式；Universal Renderer 中选择路径
Renderer Features → Render Pass挂载可选效果；自定义 Pass 在指定时机插入

Camera 决定用哪个 Renderer、看哪些 Layer、是否应用后处理；Volume Profile 提供效果参数。项目中的“资产文件”和场景中的“组件”要一起检查。

HDRP · 三层开关共同生效

Graphics / Quality → HDRP Asset定义支持的功能与质量预算
Default / Custom Frame Settings决定当前 Camera 或 Reflection Probe 实际执行什么
Volume → Profile → Overrides环境、曝光、雾、后处理等的空间混合和参数覆盖
Material / Light / Camera对象本身仍要满足效果的参与条件

理解为三个问题：允许使用吗？这一帧开启吗？当前参数是什么？功能能否显示，往往取决于多个条件同时满足。

Volume：混合参数

Global / Local 决定影响范围；Weight、Priority 和 Blend Distance 影响混合。还要检查参数的 Override 勾选、相机的 Volume Layer Mask 与评估位置。Volume 不会替你创建灯或光照数据。

Shader Graph：定义表面

节点图最终生成 Shader。它控制材质的表面响应，也可用于合适的全屏效果。不同管线的 Target、节点和 Pass 支持有差异；会连节点不等于掌握渲染流程。

Render Graph：安排依赖

记录 Pass 的输入、输出和执行逻辑，让框架分析资源生命周期、裁剪无用工作，并在条件允许时优化执行。它不是另一个材质编辑器。

扩展入口：URP 从 Renderer Feature / ScriptableRenderPass 进入，并学习 Render Graph 工作流；HDRP 从 Custom Pass / Custom Post Process 进入。描边需要什么缓冲区、在哪个阶段执行，比先复制一段脚本更重要。

参阅：URP 自定义 Pass · HDRP Asset · Frame Settings · Custom Pass。

04

画面质量，拆成四个问题

材质、光照、反射与成像共同决定结果。先确定缺的是哪一种信息，再决定增加哪项功能。

01 / SURFACE

物体是什么表面？

Base Color、金属度、粗糙度 / 光滑度、法线决定光怎样散射。PBR 是两者都能使用的基础。

02 / DIFFUSE LIGHT

漫反射光从哪来？

直接光来自灯；间接光来自环境与多次反弹。阴影描述遮挡，AO 不能代替完整的 GI。

03 / SPECULAR LIGHT

表面反射了什么？

Reflection Probe、SSR 与光追反射用不同数据重建环境。镜面反射和漫反射 GI 要分开考虑。

04 / IMAGE

光如何变成可见图像？

曝光、色调映射、抗锯齿与后处理影响最终输出。HDR 缓冲或 HDR 显示输出都不等于 HDRP。

关心的问题URP · 广覆盖与可伸缩HDRP · 成熟的高保真工具集
部署范围移动、Web、桌面、主机与 XR 是常见目标。某个平台能运行 URP，不代表每个高级功能都可用。以支持 Compute Shader 的桌面与主机平台为重点。移动与 Web 项目优先考察 URP；XR 仍需核对设备、插件与功能组合。
预计算间接光Lightmap 与探针 / APV 是重要基础路线。把昂贵的光照计算预先存为数据，运行时采样。同样需要理解烘焙和探针系统；高保真项目也会混合使用预计算与实时效果，控制运行时预算。
动态间接光Surface Cache GI6.7 Beta
面向动态光源与几何变化的间接漫反射路线。需按对应构建的配置和限制验证，不可直接套用旧 URP 结论。		可评估 SSGI、硬件光追 GI 等路线。屏幕空间数据覆盖有限，硬件光追受设备 / API 与性能约束；SCGI 不应默认视为 HDRP 内置能力。
反射Reflection Probes 是基础；SSR6.7 Beta增加屏幕空间实时反射。离屏或被遮挡的信息需要回退方案；SSR 不要求硬件光追。可组合 Reflection Probes、Planar Reflection、SSR 与支持条件下的光追反射。根据表面与镜头需要选择成本。
表现工具Lit / Unlit、Shader Graph、2D Renderer、Renderer Features；适合按项目裁剪或定制表现。风格化与写实都可以作为目标。物理光照与曝光工作流、体积效果、复杂材质等构成较完整的高保真工具链。功能完整性需与维护及制作成本一起衡量。
定制与迁移Renderer Features / Render Pass 是常用扩展入口。转换器能处理部分资源，无法自动重建所有自定义效果。Custom Pass / Custom Post Process 是常用扩展入口。两条管线的材质、Shader 和扩展代码不能假设直接互换。

新功能依据：Beta 发布说明 [2] · SCGI 官方介绍 [3] · SSR 官方介绍 [4]。平台与功能入口见参考 [5–6]；这是概念对照，不是完整兼容性矩阵。

三个不能画等号的关系：APV ≠ 无需预计算的动态 GI；SSR ≠ 完整世界空间反射；启用 HDRP ≠ 启用硬件光追。先区分数据来源，才能理解画面为什么会缺失、延迟或失真。

CPU · 提交与组织

检查主线程 / 渲染线程、可见对象和状态切换。SRP Batcher 减少兼容绘制的 CPU 设置开销；GPU Instancing 复用几何绘制。它们解决的问题不同，Draw Call 数不是唯一指标。

GPU · 计算与带宽

检查像素成本、透明 Overdraw、阴影、G-buffer、全屏 Pass、体积和光追。功能减少后 GPU 时间是否下降，比主观猜测更有价值。

工具 · 各回答一个问题

Profiler：时间花在哪里？Frame Debugger：画了什么、顺序如何？Rendering Debugger：光照与材质数据对吗？Render Graph Viewer：Pass 依赖和资源生命周期是什么？

常见症状 → 最短检查路线

材质变成粉色

先看 Console 中的 Shader 编译错误，再检查材质的 Shader / Shader Graph Target 是否匹配当前管线。确认正在使用的 Quality 级别与 Pipeline Asset。不要先调灯光或曝光。

加了 Bloom / 雾 / SSR，却没有效果

按顺序确认：所需功能是否支持并开启 → 相机的相关设置 → Volume Layer Mask 与影响范围 → Profile 中 Override 是否勾选 → 材质和缓冲区是否满足条件。URP 的一些功能还需要 Renderer Feature。

画面过暗、曝光乱跳、反射缺物体

暗：分开检查直接光、间接光和曝光。曝光变化：检查自动曝光及 Volume 混合。反射缺失：先判断使用的是 Probe、SSR 还是光追；SSR 看不到完整场景，不能靠提高采样消除所有离屏缺失。

优化与迁移 → 保持可验证

开了 Deferred，为什么更慢？

G-buffer 的写入、带宽和固定开销可能超过多灯收益；透明物体依然需要前向处理。用同场景、同分辨率、同画质在目标设备对比，别把路径名字当成性能承诺。

编辑器流畅，真机却卡顿

在目标设备的代表性构建中采样，检查 GPU、CPU、显存 / 内存、分辨率、图形 API、VSync 和温控。记录稳定区间与最差场景，不只看瞬时 FPS。

想从 URP / HDRP 换到另一条管线

先复制项目或建版本控制分支，再做一个代表性场景。盘点 Shader、材质、灯光、Volume、自定义 Pass、插件与后处理；验证外观和毫秒成本后再估算完整迁移量。切换资产不是完整迁移。

07

用六个小实验，把知识连起来

建议先用 URP 建立基础；如果已有 HDRP 项目，就保留项目上下文学习同一组概念。每一步都应产出一个能解释的观察结果。

LAB 01 / 场景与材质

一个球、一面墙、一盏灯

分别使用 Lit 和 Unlit 材质。改变灯光、金属度、光滑度与法线，观察哪些变化影响哪种材质。

验收：能解释“材质颜色”与“最终像素”为什么不同。
LAB 02 / 帧与路径

逐步查看一帧

打开 Frame Debugger，辨认阴影、不透明、透明和后处理。复制场景比较 Forward+ 与 Deferred。

验收：能找到 G-buffer，并解释透明物体去了哪里。
LAB 03 / 光照信息

一次只改变一种光

比较直接光、烘焙间接光、APV 与反射探针。理解基础后，再单独实验 6.7 的 SCGI 和 SSR。

验收：能预测移动灯、打开门、转动镜头分别会影响什么。
LAB 04 / 控制链

让效果有意“失效”

创建局部 Volume，改变 Layer Mask、Weight、Override。HDRP 再检查 Frame Settings；URP 检查 Renderer Feature。

验收：不靠随机勾选，也能定位效果为何没有出现。
LAB 05 / 自定义扩展

实现一个简单全屏效果

先做颜色处理，再尝试依赖深度 / 法线的描边。记录输入缓冲区、输出目标和 Pass 的插入位置。

验收：能区分 Shader Graph 与 Render Graph 各自的作用。
LAB 06 / 项目判断

做一份目标设备记录

固定视角、分辨率和构建设置，逐个开关高成本功能。记录 CPU / GPU 时间与画面变化，选择有收益的组合。

验收：能用平台、功能和预算解释选型，而非只比较截图。
QUICK CHECK / 认知自测

选择答案，查看原因。

Pipeline / Renderer / Pass

Pipeline 是整体组织者；Renderer 是具体渲染工作组织方式；Pass 是完成一个阶段的渲染或计算工作。它们的范围逐步缩小。

Material / Shader / Shader Graph

Material 保存 Shader 引用与参数；Shader 描述 GPU 计算；Shader Graph 是编写并生成 Shader 的节点工具。

Depth / Normal / G-buffer

Depth 记录可见表面的深度，Normal 记录方向；G-buffer 存储后续照明需要的表面属性。具体编码和通道布局取决于管线。

GI / APV / SSR

GI 关注间接光传输；APV 是自适应探针体积，用来存储并采样预计算的光照信息；SSR 从相机可见的屏幕空间数据估计反射。

HDR / HDRP / Tone Mapping

HDR 是高动态范围；HDRP 是一条渲染管线；色调映射把场景的光照范围映射到输出范围。这三个名字不应混用。

Draw Call / SRP Batcher / Instancing

Draw Call 是绘制提交；SRP Batcher 优化兼容 Shader 的 CPU 设置流程；Instancing 用实例数据绘制共享几何。减少其中一个指标不保证消除整体瓶颈。
