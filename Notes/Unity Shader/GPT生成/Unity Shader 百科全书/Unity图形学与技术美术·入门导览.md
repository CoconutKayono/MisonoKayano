# Unity 图形学与技术美术 · 入门导览

> 这是一份给「有编程基础、但没怎么碰过图形学/Shader」的你的领域地图。
> 目标不是把你变成会背公式的人，而是帮你建立一张「遇到任何概念都知道它该挂在哪」的认知框架。
> 本导览默认你使用 **Unity 6.x（URP，Universal Render Pipeline）** 作为学习环境。

---

## 1. 这个领域到底在做什么

先花两分钟把三个容易混在一起的名词拆开，这是后面所有内容的地基：

- **图形学（Computer Graphics）**：一门学科，研究「计算机如何把 3D 场景数据，变成屏幕上的一排 2D 像素」。它和引擎无关，是底层原理。
- **Unity**：一个游戏引擎。它负责把建模软件（Maya/Blender）导出的模型、贴图，加上你写的脚本、灯光、物理，整合起来，最终「画」到屏幕上。渲染只是引擎的其中一块能力。
- **Shader**：运行在 **GPU（显卡）** 上的小程序。它决定「一个顶点该在屏幕哪个位置」「一个像素该是什么颜色」。它是图形学原理在 Unity 里的具体落点。

那么**技术美术（Technical Artist, TA）**是什么？一句话：

> **TA 是站在「美术」和「程序」中间的人，负责让「好看」和「跑得动」同时成立。**

美术追求画面表现力，程序追求性能和正确性，这两拨人经常互相听不懂。TA 的价值就在于：既懂美术要什么效果，又懂引擎和 GPU 是怎么工作的，能把两边的语言翻译成对方能执行的东西。

## 2. 先建立一个心智模型：一帧画面是怎么产生的

你不需要先懂公式，但需要先有一个「数据是怎么流动的」的画面感。这比任何单个知识点都重要。

**第 0 步（在 CPU 上准备数据）**
游戏运行时，CPU 手里有一堆数据：模型（一堆顶点坐标）、贴图、材质参数、灯光位置、相机位置。这些数据还只是「描述」，屏幕上一片黑。

**第 1 步（CPU 把数据交给 GPU，叫 Draw Call）**
CPU 说：「用这个模型、这套材质、这盏灯，画一次」。这一次提交就叫做一个 **Draw Call**。你可以把它理解成一次「下单」。下单越频繁，CPU 和 GPU 之间的通信开销越大——这也就是后面性能优化的核心战场之一。

**第 2 步（GPU 开始干活：渲染管线）**
GPU 拿到数据后，会按一条固定的流水线处理，这条流水线叫 **渲染管线（Render Pipeline）**，大致分几个阶段：

```
顶点数据
   ↓  ① 顶点着色器（Vertex Shader）：把每个顶点从模型空间变换到屏幕空间
   ↓  ② 光栅化（Rasterization）：把三角形「铺」成一个个像素（片元）
   ↓  ③ 片元着色器（Fragment Shader）：计算每个像素的颜色
   ↓  ④ 输出合并：写进屏幕缓冲，成为你看到的一帧
```

**用编程的类比来理解 Shader**（这是你最容易上手的角度）：

- 你平时写的 C# 代码，是一条指令一条指令**串行**执行，你自己控制循环。
- Shader 更像一个「函数」，由 GPU 同时调用**成千上万次**：顶点着色器对**每个顶点**各跑一遍，片元着色器对**每个像素**各跑一遍。你没有 for 循环去遍历这些像素——并行是 GPU 自动完成的，你只是写「处理**一个**顶点/像素时该做什么」。

这个「一个 Shader 函数被海量并行执行」的思维转变，是入门阶段最重要的一步。

## 3. 渲染管线：Unity 里的三种选择

Unity 历史上出现过几套渲染管线，你需要知道它们的存在和区别，因为你会在教程和资料里反复看到这些词：

| 管线 | 全称 | 定位 | 现状 |
|------|------|------|------|
| **Built-in RP** | 内置渲染管线 | Unity 的老默认管线 | 老项目在用，新项目不推荐 |
| **URP** | Universal Render Pipeline | 通用/移动优先，跨平台 | **当前主流推荐** |
| **HDRP** | High Definition Render Pipeline | 高端画质（PC/主机） | 追求顶级画面时用 |

它们共同的基础叫 **SRP（Scriptable Render Pipeline，可编程渲染管线）**，意思是 Unity 把渲染流程「开放」出来，让开发者可以用 C# 定制管线。URP 和 HDRP 都是 Unity 官方基于 SRP 做好的「现成实现」。

**给你的建议**：学习阶段就用 **URP**。它覆盖了 90% 的现代游戏场景，资料多、跨平台、性能友好。HDRP 等你明确要做「电影级写实画面」时再碰。

## 4. Shader 基础：语言、类型、和一个最小例子

### 4.1 你会在 Unity 里遇到哪些「语言」

- **ShaderLab**：Unity 自己的一层「壳」，用来描述一个 Shader 的整体结构（叫什么名字、有哪些属性、哪些 Pass、用哪种着色语言）。它不是计算语言，是「组织语言」。
- **HLSL**：真正干计算活的语言，在 URP/HDRP 里用。语法和 C 很接近（有 `float`、`float3`、`float4x4`、`if`、函数等），你作为有编程基础的人会很有亲切感。
- **CG**：更早的着色语言，老教程里大量出现。本质和 HLSL 几乎一样，Unity 正在逐步淘汰它，**你新写的东西用 HLSL 即可**。

> 一个容易混淆的点：你在 Unity 里新建的 `.shader` 文件，整体是 ShaderLab 结构，里面嵌的 `CGPROGRAM` / `HLSLPROGRAM` 代码块才是真正跑在 GPU 上的逻辑。

### 4.2 两种核心 Shader 类型

- **顶点着色器（Vertex Shader）**：输入一个顶点（位置、法线、UV 等），输出它变换后的屏幕位置，顺带把需要的数据传给片元着色器。跑的次数 = 顶点数。
- **片元着色器（Fragment Shader / Pixel Shader）**：输入光栅化后插值出来的数据（比如这个像素对应的 UV、法线），输出最终颜色。跑的次数 = 像素数，通常是性能的大头。

除此之外 Unity 还提供 **Surface Shader（表面着色器）**——一种「语法糖」，帮你自动生成光照计算代码，写起来省事但不够灵活。入门时了解即可，深入后建议直接写顶点/片元。

### 4.3 一个最小 Shader 的解剖（示意）

```hlsl
Shader "Custom/MyFirstShader"
{
    Properties
    {
        _MainColor ("主颜色", Color) = (1,1,1,1)   // 暴露在材质面板上的属性
    }

    SubShader
    {
        Pass
        {
            HLSLPROGRAM
            #pragma vertex vert        // 声明：顶点着色器函数叫 vert
            #pragma fragment frag      // 声明：片元着色器函数叫 frag

            float4 vert (float4 pos : POSITION) : SV_POSITION
            {
                // 把顶点从模型空间变换到裁剪空间（屏幕空间的前一步）
                return UnityObjectToClipPos(pos);
            }

            float4 frag () : SV_Target
            {
                // 每个像素都返回同一个颜色
                return float4(1, 0, 0, 1);   // 纯红
            }
            ENDHLSL
        }
    }
}
```

哪怕这个 Shader 只输出纯红色，它也完整地走了「顶点变换 → 光栅化 → 像素着色」这一整条路。**先把这段代码在 Unity 里跑通、改成绿色、加一个属性参数**，你就已经迈出了第一步。

### 4.4 必须认识的核心概念（先混个脸熟）

- **顶点位置（Position）**：模型空间 → 世界空间 → 观察空间 → 裁剪空间，这套「空间变换」是顶点着色器的核心任务。
- **法线（Normal）**：垂直于表面的方向，用来算光照。没有法线就不知道「面朝哪」，光照无从谈起。
- **UV 坐标**：把「贴图上的哪个点」对应到「模型表面的哪个点」，范围一般是 0~1。贴图采样靠它。
- **光照模型**：一套数学规则，回答「给定光线、法线、视线，这个表面该多亮」。后面会展开。

## 5. 核心技术地图：你要学的东西全景

下面这些是「图形学 + Unity TA」这座山上的主要山头。你现在只需要知道它们的存在和彼此关系，不用现在都懂。

### 5.1 光照与着色模型

- **Lambert（漫反射）**：光打到粗糙表面向四面八方散开，决定「基础明暗」。
- **Blinn-Phong / Phong（高光）**：光滑表面反射出的「亮点」，决定「油亮感」。
- **PBR（Physically Based Rendering，基于物理的渲染）**：现代主流，用「金属度（Metallic）+ 粗糙度（Roughness）」等物理参数描述材质，保证在不同光照下都「物理正确」。URP 默认就是 PBR 工作流。
- **全局光照（GI）、环境光、阴影、AO（环境光遮蔽）**：这些决定「光在场景里如何二次传播」，是画面「高级感」的重要来源。

### 5.2 纹理与采样

贴图不只是「颜色」。常见有：**反照率（Albedo）**、**法线贴图（Normal Map，用贴图伪造表面凹凸）**、**金属度/粗糙度贴图**、**AO 贴图**等。如何「采样」这些贴图、如何处理 UV 重复/偏移，是 Shader 的日常。

### 5.3 后处理（Post-Processing）

在画面渲染完之后，再对整张图做一层滤镜：Bloom（泛光）、色调映射（Tone Mapping）、景深、抗锯齿等。URP 里通过 Volume 系统配置。这是「让画面瞬间变好看」性价比最高的手段之一。

### 5.4 渲染优化（TA 的硬通货）

- **Draw Call 优化**：合批（Batching）、减少材质种类——因为切换材质也会打断合批。
- **Overdraw**：同一个像素被重复画了很多次（尤其半透明物体），是移动端发热元凶。
- **LOD（Level of Detail）**：远处物体用低模，近处用高模。
- **纹理压缩、Mipmap**：省内存、减采样闪烁。

> **性能意识是 TA 区别于「只会写 Shader 的人」的关键**。一个效果再炫，如果让移动端掉帧发热，就不是好效果。

## 6. 技术美术（TA）的职责与技能树

TA 不是一个单一岗位，而是很多细分方向的统称。了解它们，有助于你找到自己感兴趣的主攻方向：

- **材质 / Shader TA**：写 Shader、搭材质库、做风格化效果。这是最贴近「图形学」的 TA。
- **渲染 TA**：深入渲染管线，做全局光照、后处理、性能优化，和引擎底层打交道最多。
- **工具 TA（Tools TA）**：给美术写编辑器工具、自动化流程（比如一键导入、批量命名、资源检查），偏「程序化生产」。
- **程序化 TA（Procedural TA）**：用 Houdini 等做程序化建模、地形、散布。
- **动画 / 绑定 TA（Rigging TA）**：解决骨骼绑定、动画状态机、DCC 工具链问题。

**一套通用的 TA 技能树**（按重要性排序给你参考）：

```
     美术素养（审美、色彩、能看出「哪里不对」）
         ×
   图形学原理（管线、光照、PBR）
         ×
   编程能力（C#、HLSL、工具脚本）
         ×
   引擎熟练度（Unity 编辑器、URP、性能工具）
         ×
   DCC 工具（Blender/Maya/Substance/Houdini，按方向选）
```

你已有编程基础，这是很大的优势——很多 TA 是美术出身，补编程反而更难。你要补的主要是「图形学原理」和「美术审美」这两块。

## 7. 从你的编程基础出发：一条建议的学习路线

这条路线刻意「先跑通、再深挖」，避免你一开始就陷进矩阵和积分里失去兴趣。

**阶段 1：把环境跑起来（1 周）**
- 装 Unity 6.x，建一个 URP 项目。
- 把上面第 4.3 节的最小 Shader 跑通，改颜色、加属性参数。
- 目标：能新建材质、挂 Shader、在场景里看到效果变化。

**阶段 2：跟着做一个 Shader 入门（2~4 周）**
- 学 HLSL 基本语法（和 C 很像，你会很快）。
- 实现一个「顶点着色 + 简单漫反射光照 + 贴图采样」的完整 Shader。
- 理解顶点/片元着色器之间数据是怎么传递的（v2f 结构体、插值）。

**阶段 3：补图形学基础（并行进行，长期）**
- 学「空间变换」（模型→世界→观察→裁剪），这是顶点着色的灵魂。
- 学光照模型：Lambert → Blinn-Phong → PBR。
- 学渲染管线的完整流程和「为什么要分这些阶段」。

**阶段 4：实战与进阶**
- 做几个经典效果：卡通描边（Outline）、溶解（Dissolve）、水面波动、边缘光（Rim Light）。
- 学后处理、URP 的自定义 Renderer Feature。
- 开始接触性能优化：用 Frame Debugger 看 Draw Call、用 Profiler 找瓶颈。

> 核心心法：**每学一个概念，都问自己「它在这帧画面的数据流里处于哪一环」**。能把它挂到管线图上的正确位置，才算真懂，而不是背下来。

## 8. 常见误区（提前给你排雷）

1. **死记公式而不是理解数据流**。光照公式忘了可以查，但如果你不知道「法线和光线方向做点积」是在算「夹角余弦」，你就没法举一反三。
2. **用串行思维写 Shader**。总想「遍历所有像素」——不行，GPU 已经帮你并行遍历了，你只写「单个像素怎么办」。
3. **过早优化**。先让效果正确，再用工具（Profiler / Frame Debugger）**测量**出真正的瓶颈再优化。凭感觉优化往往是负优化。
4. **陷进老教程**。很多资料用的还是 Built-in RP + CG。学的时候注意区分，认准「URP + HLSL」的现代写法。
5. **忽视美术审美**。TA 的「A」是 Art。如果看不出「为什么这个画面丑」，再强的技术也救不回来。多看好作品、多临摹，是硬功课。

## 9. 推荐资源

- **LearnOpenGL**（learnopengl.com）：图形学原理的经典免费教程，从 C++/OpenGL 讲起，但原理通用，务必过一遍「变换」「光照」「PBR」章节。
- **The Book of Shaders**（thebookofshaders.com）：在浏览器里实时写 Shader，交互式理解片元着色器，非常适合建立「逐像素思考」的直觉。
- **Catlike Coding**（catlikecoding.com）：Unity 渲染的深度系列教程（尤其「Rendering」系列），质量极高。
- **Unity 官方文档**：URP 文档 + Shader Graph 文档，作为随时查阅的手册。
- **Shader Graph**：Unity 的可视化 Shader 工具，用节点连线代替写代码。学 HLSL 的同时可以对照着用，帮助理解「每个节点背后是段什么代码」。
