# N00｜让方块显示一种颜色

**学完这张卡，你能修改一行 Shader 代码，把方块从红色变成绿色，并解释颜色来自哪里。**

## 必须掌握：先由你决定颜色

先把 Shader 想成一套“怎样画这个物体”的规则。材质使用这套规则，再把结果画到物体表面。

今天只做最简单的规则：不问灯在哪里，直接返回红色。负责计算表面输出的这段函数叫**片元程序**。你现在只需要找到它返回颜色的那一行。

颜色用红、绿、蓝三个分量表示，简称 RGB。`(1,0,0)` 是纯红，`(0,1,0)` 是纯绿。完整代码还要带第四个数，这张卡固定为 1，暂时不研究它。

下面这段放在完整示例的 `Frag` 函数位置：

```hlsl
float4 Frag() : SV_Target
{
    float3 color = float3(1, 0, 0);
    return float4(color, 1);
}
```

`float3` 装三个数，`float4` 装四个数；`return` 把结果交出去。`SV_Target` 先理解成“这里输出的是颜色”的标签即可。

为什么先学这个？之后的光照、法线和卡通色阶，最终都需要变成颜色输出。先能控制这一步，后面的画面变化才有落点。

## 先预测，再验证：只改颜色

**准备：** 用 Unity 6 的 URP 项目，新建 Cube，保持位置/旋转为 0、缩放为 1，让相机看见它。复制下面完整示例，创建材质并选择 `BeginnerNPR/N00Color`，赋给 Cube。关闭额外后处理，先看到红方块。

**只改一个变量：** 将 `float3(1,0,0)` 改成 `float3(0,1,0)`。

先预测：方块会变绿，还是转动灯光后才变绿？

保存并等待 Unity 编译。预期是直接变绿，因为这段代码没有读取灯光。它看上去缺少立体明暗也是正常的，我们还没有计算光照。

## 理解即可

完整 Shader 中还有一段处理模型位置的程序，叫顶点程序。今天它只是把方块放到正确的画面位置，照抄即可。

## 完整示例

保存为 `N00Color.shader`，也可用 [独立文件](../示例/N00Color.shader)。下面可以直接复制，不要求背模板。

```shaderlab
Shader "BeginnerNPR/N00Color"
{
    SubShader
    {
        Tags { "RenderPipeline"="UniversalPipeline" "RenderType"="Opaque" }
        Pass
        {
            Tags { "LightMode"="SRPDefaultUnlit" }
            HLSLPROGRAM
            #pragma vertex Vert
            #pragma fragment Frag
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

            struct Input { float3 positionOS : POSITION; };
            struct Output { float4 positionCS : SV_POSITION; };
            Output Vert(Input input)
            {
                Output output;
                output.positionCS = TransformObjectToHClip(input.positionOS);
                return output;
            }
            float4 Frag() : SV_Target
            {
                float3 color = float3(1, 0, 0);
                return float4(color, 1);
            }
            ENDHLSL
        }
    }
}
```

看不到方块时，先确认材质已赋给 Cube、相机对准 Cube。粉色通常提示 Shader 或管线有问题，先看 Console。若测试项目启用了 **Depth Priming（预先写深度的选项）**，本组先关闭它；原理现在不用学。

## 带走这些

**三个结论**

1. Shader 是绘制规则，材质使用它。
2. RGB 的三个分量决定这里返回的颜色。
3. 没有写灯光计算，灯光就不会自动改变这个示例的明暗。

**两个自测**

- 改成 `(0,0,1)` 是什么颜色？——蓝色。
- 为什么红方块没有正常的受光层次？——片元程序一直返回同一种颜色。

**一个最小实践：** 不动相机和灯光，只改 RGB，让方块变成黄色 `(1,1,0)`。

**什么时候继续深入：** 能找到并解释返回颜色的那一行后，进入 [N01：用向量移动方块](N01-用一个向量移动方块.md)。
