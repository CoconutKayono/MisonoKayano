# N02｜让方向只负责朝向

**学完这张卡，你能用 `normalize` 消除方向长度的影响：把方向从 `(1,0,0)` 改成 `(2,0,0)`，方块仍移动相同距离。**

## 必须掌握：先把箭头统一成同样长

想象两支指向右方的箭头，一支长 1，一支长 2。如果只想问“往哪边走”，第二支并没有提供新的朝向，却偷偷带进了两倍长度。

**归一化**就是把一支非零箭头缩放到长度 1，保持朝向不变。得到的箭头叫**单位向量**：这里的“单位”指长度为 1。

HLSL 提供 `normalize` 做这件事。你现在不用手算复杂长度，先看最直观的输入：

| 输入 | 归一化后 |
| --- | --- |
| `(1,0,0)` | `(1,0,0)` |
| `(2,0,0)` | `(1,0,0)` |
| `(-2,0,0)` | `(-1,0,0)` |

归一化不会把负方向翻正，它只处理长度。

## 核心代码：先定方向，再定距离

下面是完整示例中 `Vert` 的关键部分，只讨论非零方向：

```hlsl
float3 direction = _Direction.xyz;
float3 unitDirection = normalize(direction);
float3 offset = unitDirection * _Distance;
float3 movedPosition = input.positionOS + offset;
Output output;
output.positionCS = TransformObjectToHClip(movedPosition);
return output;
```

先归一化，再乘距离。数学上就是：

`单位方向 = 原向量 / 原向量长度`

`位移 = 单位方向 × 距离`

在本卡物体缩放为 1 的设置下，Distance=0.5 就让方块移动 0.5，而不会被方向参数的长度放大。

以后用法线与光方向算明暗时，也常常只需要朝向。如果带入了额外长度，就可能把表面算得过亮；明暗公式之后再学。

## 先预测，再验证：仍然只改 X

在 Unity 6 URP 场景中创建 Cube，位置/旋转为 0、缩放为 1。复制完整 Shader，创建并赋予 `BeginnerNPR/N02UnitDirection` 材质，相机对准 Cube。

基准：Direction=`(1,0,0,0)`，Distance=0.5。

只把 Direction 的 X 从 1 改为 2，Distance 不动。

先预测：是否会像未归一化时一样移得更远？预期是不变，两种输入都先变成 `(1,0,0)`。若仍变远，检查材质是否确实用了这张卡的 Shader。

## 理解即可

零向量 `(0,0,0)` 没有朝向，不能按普通非零方向归一化。完整示例把“没有有效方向”约定为不移动；保护判断照抄即可。

## 暂时跳过

浮点精度和平方根实现，**现在不用学**。也不用认为所有向量都必须归一化：以后需要保留距离的位移数据，恰恰不能先把长度丢掉。

## 完整示例

保存为 `N02UnitDirection.shader`，或使用 [独立文件](../示例/N02UnitDirection.shader)。

```shaderlab
Shader "BeginnerNPR/N02UnitDirection"
{
    Properties
    {
        _Direction("Direction XYZ",Vector)=(1,0,0,0)
        _Distance("Distance",Range(0,0.5))=0.5
    }
    SubShader
    {
        Tags { "RenderPipeline"="UniversalPipeline" "RenderType"="Opaque" }
        Pass
        {
            Tags { "LightMode"="SRPDefaultUnlit" }
            HLSLPROGRAM
            #pragma vertex Vert
            #pragma fragment Frag
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
            CBUFFER_START(UnityPerMaterial)
                float4 _Direction;
                float _Distance;
            CBUFFER_END
            struct Input { float3 positionOS : POSITION; };
            struct Output { float4 positionCS : SV_POSITION; };
            Output Vert(Input input)
            {
                float3 direction = _Direction.xyz;
                float3 unitDirection = float3(0,0,0);
                if(length(direction) > 0.00001)
                    unitDirection = normalize(direction);
                float3 movedPosition = input.positionOS + unitDirection * _Distance;
                Output output;
                output.positionCS = TransformObjectToHClip(movedPosition);
                return output;
            }
            float4 Frag() : SV_Target { return float4(1,0.6,0.1,1); }
            ENDHLSL
        }
    }
}
```

`length` 取得向量长度。这里把极短向量也当作无方向，避免用它做归一化；这是示例约定，不是 `normalize(0)` 本来就返回零。若开启 Depth Priming，本组测试先关闭；其他模板暂时不用展开。

## 带走这些

**三个结论**

1. 归一化保留朝向，把非零向量长度变成 1。
2. 单位方向乘距离，可以把朝向与移动量分开控制。
3. 零向量没有朝向，完整示例选择不移动。

**两个自测**

- 归一化 `(0,3,0)` 后是什么？——`(0,1,0)`。
- 归一化会不会把“朝左”变成“朝右”？——不会，方向保持不变。

**一个最小实践：** 保持 Distance=0.5，只把 Direction 的 X 改成 -2，先预测再观察反向移动。
