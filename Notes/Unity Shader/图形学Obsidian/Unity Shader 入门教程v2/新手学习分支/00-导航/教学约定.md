# 新手学习分支的教学约定

## 分支边界

所有新手卡、路线、示例与检查记录只写入 `新手学习分支/`。原版卡片、导航、进度、实验和工具不改写，不替换，也不因为本分支增加内容而推进原版进度。

这是一套重新安排学习顺序和解释方式的材料，不是把旧卡全文缩短。旧卡是参考资料；新卡应能脱离旧卡独立阅读。

当前任务后续的“继续”默认推进本分支；只有用户明确要求推进原版时，才恢复原版路线。

## 读者与目标

读者有 Unity/C# 基础，正在建立渲染直觉。目标是先写出可观察的效果、预测参数变化、解释核心代码，再逐步进入 URP 和 GPU 底层。

优先级：**易懂 → 可实践 → 能预测 → 能解释 → 完整性与底层细节。**

## 每张卡的结构

1. **学完能做什么**：一句具体、可以检查的结果。
2. **必须掌握**：先给直觉，再定义术语；解释它解决的 Shader 问题和理解错后的现象。
3. **核心代码**：通常 5—20 行，解释与当前问题直接相关的行。极小功能可以更短，不凑行数。
4. **先预测，再验证**：写清初始设置，只改变一个变量；区分预测和实际结果。
5. **理解即可**：知道用途，不要求记住细节。
6. **暂时跳过**：明确“现在不用学”，并注明何时回来。
7. **完整示例**：放在后部，包含独立复现所需代码与最少设置；模板行允许暂时照抄。
8. **深入验证**：官方文档、源码与调试工具在这里提供证据；没有真实编译/运行则如实标注。
9. **带走这些**：严格保留三个结论、两个带答案的自测问题、一个最小实践、一个继续深入的时机提示。

单卡最多引入三个重要新概念，超过就拆。目标是一次普通学习时段能读完；正文超过约 1500—2500 中文字时优先拆卡，完整代码也不能借此无限扩张。

## 数学与代码

每个符号先说明代表什么，再写公式，并说明数值如何改变画面。讲点积时必须解释 N、L、空间、归一化及正/零/负值；若前置不足，先用独立卡补齐，不把所有前置压进一张卡。

类比用于建立直觉，但要说明容易误解的边界。短代码若只是替换片段，明确写出放在哪里；完整示例不得依赖未提供的自定义文件。

实践以 Unity 为主，不新增 Python 学习实验。不为了短而给出错误保证；平台差异在必要时只解释对当前操作有影响的部分。

## 资料与状态

资料用于核对结论，不作为正文的叙述顺序。只在深入具体源码时说明固定提交；不要求初学者背提交号。旧卡和新卡如出现不同表述，按已经核对的事实解释，新手版不能靠省略条件制造错误直觉。

“已生成”“Unity 已实测”“个人已掌握”分别记录。文件检查不等于 Shader 编译通过；预期画面不等于实际截图。
