# D01—D04｜URP 调度与 Render Graph 实验

本组把相机候选对象、Shader Pass 选择、状态覆盖、图记录/执行和资源寿命对应到可观察的 Unity 实验。每张卡都保留完整代码和必要解释，本页用于统一设置与排查。

**版本边界：** 源码阅读固定 Graphics `275a7f9ad9330e3cf7f3ea57a0b242a551fde291`（URP/Core 17.0.4 / 6000.0），API 对照本地 Unity 6000.7 Beta 文档。未在 Unity 编译、播放或 GPU 抓帧，所有画面与裁剪状态都是预测。无需 Python 学习实验。

## 1. 本组的共同设置

1. 使用 Unity 6、URP Forward Renderer，单 Base Game Camera；先关闭 MSAA、XR、动态分辨率、Depth Priming、GPU Resident Drawer、后处理和其他 Renderer Feature。
2. 确认 Render Graph 开启，Compatibility Mode（关闭 Render Graph 的兼容模式）未开启。例子只实现 RecordRenderGraph，不提供旧 Execute 路径。
3. 文件复制到项目 `Assets/KnowledgeCards/`；在相机实际使用的 **Universal Renderer Data → Renderer Features** 中添加对应 Feature。它们不是 MonoBehaviour，不要挂到 GameObject；也不是直接添加到 URP Asset 的功能列表。
4. 一次只启用一个实验 Feature。D03 将当前 Renderer 的 Intermediate Texture 设为 Always，确保相机颜色可作为普通纹理采样。
5. 在 Game 视图观察。示例主动过滤 Scene/Preview/Overlay 相机；Scene 视图没显示效果不等于 Feature 失败。多 Game Camera、相机栈和生产配置待明确扩展后再用。

## 3. 四个必须先做预测的对照

### D01：候选集合不能靠后续列表扩回去

两个 Cube 使用不同 Layer。Feature 只选择其中一个层，该层可见表面变洋红；相机先排除该层后，Feature 无法恢复它。把材质队列改到 opaque 范围之外、或改掉自定义 LightMode，也会阻止本次重画，但原因与相机剔除不同。

定位 `D01 Filtered Objects`，依次核对相机 Culling Mask、Feature LayerMask、Render Queue、LightMode、列表及 GPU 深度状态。不要看到无像素就直接判定对象没进列表。

### D02：字段值与覆盖范围同时生效

Shader 检查 Pass 默认 Never，基础画面蓝色；同时开启两个覆盖选项，比较被改成 Always，表面变黄。只关闭 Include Depth In Mask，虽然代码仍填写 Always，最终不应用这份覆盖。

修改 Pass Name 不应移除本例按 LightMode 选择的覆盖；修改 LightMode 才会改变匹配。抓帧检查最终状态，不用材质 Inspector 代替实际绘制证据。

### D03：记录回调不等于 GPU 完成

用有渐变的场景测试 Levels=4 的每通道色阶。Trace Next Frame 输出记录阶段及回调阶段两条 CPU 日志；两条日志都不能证明 GPU 已完成。

图中 Source 与 Destination 不同，Destination 接续为相机颜色。若去掉输出接续且没有其他消费，任务可能被裁剪。禁止裁剪不会自动把结果送上屏幕。

### D04：写入导入资源与只读导入资源不同

InternalConsumed：生产与消费保留，画面洋红。InternalUnused：内部生产者可被移除，画面原样。ImportedUnused：写入外部结果的生产者保留，但画面原样。ImportedReadUnused：外部写入生产者保留，无用只读消费者可被移除。

在 Render Graph Viewer 启用 Culled Passes 等显示项，查看图节点、资源和实际保留原因；在 Frame Debugger 对照执行事件。调试图中显示被裁剪节点并不代表它执行过。

## 4. 源码阅读顺序

1. D01：UniversalRenderPipeline 中的相机入口、剔除参数、Cull、AddRenderPasses；注意托管到原生边界。
2. D02：DrawObjectsPass 的标签集合、DrawingSettings/FilteringSettings 和 Depth Priming 覆盖条件。
3. D03：UniversalRenderPipelineRenderGraph 的 BeginRecording/EndRecordingAndExecute，再进入 Core RenderGraph 的编译与执行分支。
4. D04：ImportTexture 与资源登记、builder 访问约定、NativePassCompiler 的副作用和裁剪处理；最后看合并逻辑。

各卡来源链接固定到同一 Graphics 提交，UnityCsReference 另固定 `9d487cab41b00c50af020b56d27a3c768d54f770`。不要把公共 C# 入口继续猜成未公开的驱动/硬件实现，也不要用本地文档版本替代实际工程包版本。
