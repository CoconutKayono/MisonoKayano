# B 阶段检查点｜预测采样、遮挡与局部显示

目标：在单相机小场景中，能够分别说明“没有提交”“图元没有覆盖”“模板失败”“深度失败”“写入被禁止”和“采样结果与预期不同”。文件生成不代表实验已经完成。

## 1. 使用范围与基础模型

一个 Draw 选择几何、程序、资源和状态；光栅化产生带覆盖和属性的候选贡献；采样根据坐标及其变化率重建纹理；深度与模板限制贡献，写掩码再控制目标更新。实际 GPU 可提前测试、融合阶段或跳过无效工作，这个顺序是用于预测可见结果的概念模型。

当前主线采用普通 Unity URP Forward、单相机、非 XR、非 Deferred，不包含生产级完整阴影/深度法线/运动矢量 Pass。先关闭 Depth Priming、SSAO、额外 Renderer Feature、后处理、MSAA 和动态分辨率，记录 Editor、URP/Core 包版本、API、GPU 和相机投影设置。

## 3. 修改前先填写预测

| 修改 | 应能给出的预测与原因 |
| --- | --- |
| 倾斜表面从透视插值切到屏幕仿射 | UV 分布变化；屏幕权重不是三维表面权重 |
| 阈值由 step 换为基于 fwidth 的平滑 | 局部边界出现随像素尺度变化的过渡，不保证完全消除运动闪烁 |
| 远处棋盘强制 LOD 0 | 可能更锐也更不稳定；没有合适缩小预滤波 |
| frac 后才计算隐式采样梯度 | 接缝附近变化率可能突增；比较预先保留梯度的版本 |
| 近物体 ZWrite Off、远物体后画 | 近物体不再为后续绘制更新深度；不等于它自己关闭深度测试 |
| 模板 Writer 的 ColorMask 0 | Writer 本身不显色，但可改变 Reader 的显示区域 |
| 模板 WriteMask 0 | 旧模板值保留，而非写零 |
| Reader 先于 Writer，初值每帧清为 0 | Reader 不能利用后写标签补画已经测试过的贡献 |

最后选一个自己的 NPR 局部效果，写出输入是颜色、方向、距离还是类别；它应该采用怎样的插值、过滤和遮挡规则。允许先使用一个简单色阶/遮罩，无需此阶段就完成整个人物材质。

## 4. 当画面不符合预测时

按证据逐层定位：先确认对象和目标 Draw 是否存在；再检查程序/变体、顶点输出、Cull 与覆盖；随后核对绑定纹理、Mip 和 sampler；最后查看深度模板附件、比较状态、写掩码及绘制顺序。没有看到某个 Draw 时，不要先改 Stencil Ref；附件根本没有 S8 时，也不要靠提高 Ref 解决。

记录环境、修改项、原先预测、实际观察、定位事件和仍未解释的问题。截图只能证明一个观察结果；编译报告、GPU 事件和性能数据各有不同证据范围。不要把调试抓帧耗时当成正常游戏性能基准。

## 5. Unity 验证和阶段完成条件

按上面的四组入口运行 Unity 实验即可，不需要阅读或运行 Python。每组保留一条“修改前预测 → 实际画面 → 原因解释”的记录；涉及绘制顺序、附件和测试状态时，再通过 Frame Debugger 或合适的抓帧工具补证。

本阶段的个人通过条件是：能够独立预测上表的变化，并对一次不符合预测的现象提供可复查的定位证据。当前 B01—B08 八张卡及实验材料已生成；接口、源码和文内数学关系已核对；Unity 编译、实际画面、GPU 抓帧和个人掌握程度仍待验证。
