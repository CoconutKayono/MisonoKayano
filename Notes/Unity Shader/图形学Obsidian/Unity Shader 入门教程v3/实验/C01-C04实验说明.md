# C01—C04｜从深度拒绝到颜色 Resolve 的 Unity 实验

本组用四个独立实验回答：被挡住的片元是否着色、透明颜色怎样合成、输出进入哪张附件、MSAA 怎样形成边缘。每张卡已经包含完整必要代码和步骤；本页提供选择与排查入口，不代替卡片正文。

**环境：** Unity 6、URP 包；本地参考是 Unity 6.7 Beta / 6000.7 文档。C01/C02 使用普通 URP Forward 单相机场景，关闭 Depth Priming、SSAO、额外 Renderer Feature 与后处理；C03/C04 自行执行离屏命令，在 Game 视图预览。建议每个实验单独场景，避免离屏预览相互遮挡。

**状态：** 文件已生成并核对接口与文本；没有运行 Unity 编译、GPU 抓帧或性能测试。下面都是待观察的预测。无需 Python 实验。

## 2. 四个预测检查点

| 修改 | 应先写下的预测 | 能证明与不能证明 |
| --- | --- | --- |
| C01 启用近处遮挡物 | 远处被挡区域不贡献最终颜色 | 能观察可见性；单凭画面不能证明 early/late 调度 |
| C02 交换红蓝顺序 | 重叠处分别偏向后画颜色；正确预乘配对仍保留这种顺序差异 | 能验证合成顺序；不能声称预乘解决相交排序 |
| C03 关闭槽位 0 颜色写入 | Beauty 黑色，ID 仍有红色方块 | 能验证槽位独立写掩码；不能声称 Draw 全部工作已省掉 |
| C04 从 1× 改到实际多样本 | 几何斜边更细；Clip 圆边与 A2C 圆边不同 | 能对照覆盖处理；不能用请求值证明实际样本数 |

### C01：结果正确与省掉着色分开观察

先比较 Opaque 在有/无遮挡物时的画面，再比较 Clip 自身的有/无遮挡物情况。Depth 模式使用原始深度偏移，初始为 0。不要把覆盖不同、寄存器不同的变体时间直接相减当作 Early-Z 节约量。

若进一步测时，需要目标 GPU、图形 API、固定相机/分辨率、变体预热、实际 Draw 状态与相关硬件计数器。新增原子计数会改变程序副作用，应避免把被修改程序的调度当作原程序调度。

### C02：先检查配对，再看排序

正确组合是 Premultiply Off + SrcAlpha，或 Premultiply On + One。故意错配后应能解释变暗/变亮。常量颜色实验没有测试纹理预乘、Mip 或边缘扩色；这部分用卡片中的两 texel 反例理解。

透明 RT 中的 Alpha 需检查真实通道值；普通 Game 画面不一定使用最终 Alpha。使用线性公式做预测，不要求屏幕 sRGB 字节直接等于计算值。

### C03：资源名字不是输出槽位

默认左侧 Beauty 渐变、右侧 ID 红色；交换绑定后两种内容交换资源。ID 仅写 R，Alpha 保持清除值 0，所以预览关闭 Alpha 混合。改变 ColorMask 不影响下一帧独立 Clear 的初始化。

### C04：先读 actual，再比较效果

修改 Requested Samples 后在 Play 模式调用组件菜单 **Rebuild Targets**。脚本显示请求/实际样本数；实际单样本时 A2C 模式不绘制并提示。四种模式分别是整个倾斜方块、硬裁剪圆、覆盖圆、混合软圆。

多样本路径显式 Resolve 到单样本目标；1× 路径用 Blit。预览 Point 放大是为了看清输出栅格，不等于增加渲染分辨率。C04 用单个面和 ZTest Always，不测试多层头发的遮挡。

## 3. 排查顺序

1. Console 是否存在编译、能力或格式错误；URP 和 Shader 是否对应。
2. 材质、Shader、模式和重建操作是否正确。
3. 实际 Draw 顺序、选中 Pass、绑定附件与样本数是否符合预测。
4. ZTest/ZWrite、Blend、ColorMask、AlphaToMask 是否符合预期。
5. 读取与预览是否额外使用 Alpha、过滤、sRGB 或后处理。

记录“输入设置 → 预测 → 观察 → 抓帧证据 → 尚未解释的问题”。没有 GPU 性能证据时，学习结论写成机制推断，不写成提升百分比。
