# E05｜美术法线、平滑法线与轮廓法线

> 核心问题：为什么同一个角色可能需要几套方向数据？本卡保留网格原法线，额外生成平滑与编辑法线，通过同一材质比较明暗，避免把“修复描边”变成“破坏主体光照”。

## 1. 三角形几何与着色方向不是一回事

三角形的位置和绕序决定几何表面、光栅覆盖及面朝向。顶点 NORMAL 是参与插值的着色数据；把它改成朝上，不会把三角形旋转到朝上，也不会自动改变背面剔除。

| 数据 | 主要目的 | 修改后通常影响什么 |
| --- | --- | --- |
| 几何面法线 | 描述三角形真实朝向 | 几何推导、面判定和某些偏移算法 |
| 导入/平滑着色法线 | 构建连续或硬边明暗 | 漫反射、高光、法线贴图基底 |
| 美术编辑法线 | 按设计改变方向响应 | 脸部大色块、头发高光等 |
| 描边用方向 | 引导壳体外扩并控制接缝 | 轮廓连续性、局部线宽、挤出形状 |

“轮廓法线”是用途名称，不保证它仍是严格垂直于表面的数学法线。若存的是法线，非均匀缩放下按逆转置变换；若存的是普通位移向量，应按线性变换处理。不能只因数据放在 NORMAL 或 UV 槽里就决定数学语义。

本地文档：Unity **6.7 Beta / 6000.7，2026-06-26**。Graphics 固定 `275a7f9ad9330e3cf7f3ea57a0b242a551fde291`，manifest 为 URP/Core **17.0.4、Unity 6000.0**；UTS 固定 `1520a78a95292cb045f1edb4d60ea0dba2f213b3`，版本 **0.15.1-preview、Unity 6000.0**。示例只用于静态 MeshRenderer。

## 2. 为什么接缝不一定能靠 RecalculateNormals 修复

同一个空间角点可能对应多个顶点记录：它们的位置相同，但 UV、硬边法线或材质边界不同。索引共享关系决定哪些顶点被视为同一记录。`RecalculateNormals` 按共享顶点重算，不保证跨 UV 拆点平滑，也不自动生成切线。参见 [Unity Mesh.RecalculateNormals](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Mesh.RecalculateNormals.html)。

要跨位置重合的顶点生成平滑方向，可以先按位置分组，再对相邻面的贡献求和并归一化。一种角度加权方法为：

`n_group = normalize(Σ θ_corner × n_face)`。

θ_corner 是该三角形在这个顶点处的内角，n_face 是单位面法线。与直接平均面数相比，角度权重能减轻同一平面被不同三角化方式切分带来的偏差。但它仍不是通用修复：重合但属于不同薄层、嘴内外或独立零件的顶点不应随意合并。

立方体某角点附近三个互相垂直的面，若各贡献 90°，归一化结果为 `(±1,±1,±1)/√3`。用这个方向照明会让立方体呈现圆滑明暗，但几何边界仍然是方的。用它引导外扩则可能减少三个面各自分离的问题；这两个用途不要求共用同一 NORMAL。

## 3. GPU 顶点通道与变形约束

UV 通道可以存 Vector3，不必只存二维纹理坐标。本文将平滑法线放在 `Mesh.SetUVs(3, ...)`，对应 HLSL `TEXCOORD3`；编辑法线放在 channel 2，对应 `TEXCOORD2`。Unity API 的通道编号从 0 开始，`mesh.uv3` 这个属性名却对应 channel 2，应区分编号方式。[Mesh.SetUVs API](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Mesh.SetUVs.html)。

额外两个 float3 通道的逻辑有效载荷是每顶点 24 字节。10 万顶点约 2.4 MB 十进制数据，实际布局、压缩与加载还要看导入和平台。保存方向换取了读取与插值成本，不是免费元数据。

本文存储的是**物体空间法线**。只旋转 MeshRenderer 时，Shader 能正常变换它们；蒙皮系统不会因为一个 UV 值长得像法线就自动替它执行同样的骨骼变换。用于 SkinnedMeshRenderer 时需要专门的编码和变形方案，例如与变形后的 TBN 配合的局部表示，并验证所有 Pass。

## 4. UTS 源码如何区分用途

固定 UTS 的 `UniversalToonOutline.hlsl` 支持原法线与烘焙方向的外扩选项，还存在沿位置方向外扩的路径；其烘焙法线贴图使用切线基进行转换。这并不是“把 mesh.normals 全部重算一遍”的同义词。[UTS 描边源码](https://github.com/Unity-Technologies/com.unity.toonshader/blob/1520a78a95292cb045f1edb4d60ea0dba2f213b3/com.unity.toonshader/Runtime/Shaders/URP/UniversalToonOutline.hlsl)。

不要只复制一个变量名便改变其存储空间：贴图法线、物体空间 UV 向量、世界空间外扩方向具有不同解码和变换约定。实际包的完整顶点路径与变体需要一起看。

## 5. 完整 Unity 实验：不覆盖原 NORMAL

保存为 `E05NormalStreams.cs`，挂到 Unity 自带 Cube。代码在 Play 中克隆 Mesh，按**精确相同位置**分组，保存两个新通道；原网格资产和 NORMAL 保留。实验限可读、三角形网格，并会覆盖克隆网格的 channel 2/3，不能直接当作复杂角色导入工具。

```csharp
using System.Collections.Generic;
using UnityEngine;

[RequireComponent(typeof(MeshFilter))]
public class E05NormalStreams : MonoBehaviour
{
    MeshFilter target;
    Mesh original, owned;
    void OnEnable()
    {
        if (!Application.isPlaying) return;
        target = GetComponent<MeshFilter>();
        original = target.sharedMesh;
        if (original == null || !original.isReadable)
        {
            Debug.LogWarning("E05: use a readable triangle mesh, such as the built-in Cube.", this);
            return;
        }
        Vector3[] p = original.vertices;
        Vector3[] oldNormals = original.normals;
        if (oldNormals.Length != p.Length) return;
        int[] triangles = original.triangles;
        var sums = new Dictionary<Vector3, Vector3>();
        for (int k = 0; k < triangles.Length; k += 3)
        {
            int a = triangles[k], b = triangles[k+1], c = triangles[k+2];
            Vector3 face = Vector3.Cross(p[b]-p[a], p[c]-p[a]);
            if (face.sqrMagnitude < 1e-16f) continue;
            face.Normalize();
            Add(sums, p[a], face * Vector3.Angle(p[b]-p[a], p[c]-p[a]) * Mathf.Deg2Rad);
            Add(sums, p[b], face * Vector3.Angle(p[c]-p[b], p[a]-p[b]) * Mathf.Deg2Rad);
            Add(sums, p[c], face * Vector3.Angle(p[a]-p[c], p[b]-p[c]) * Mathf.Deg2Rad);
        }
        var smooth = new List<Vector3>(p.Length);
        var artistic = new List<Vector3>(p.Length);
        for (int i = 0; i < p.Length; ++i)
        {
            Vector3 n;
            if (!sums.TryGetValue(p[i], out n) || n.sqrMagnitude < 1e-12f)
                n = oldNormals[i];
            n.Normalize();
            smooth.Add(n);
            artistic.Add(new Vector3(n.x, n.y * 0.2f, n.z).normalized);
        }
        owned = Instantiate(original);
        owned.name = "E05 Private Direction Streams";
        owned.SetUVs(3, smooth);
        owned.SetUVs(2, artistic);
        target.sharedMesh = owned;
    }
    static void Add(Dictionary<Vector3,Vector3> sums, Vector3 position, Vector3 value)
    {
        Vector3 sum;
        sums.TryGetValue(position, out sum);
        sums[position] = sum + value;
    }
    void OnDisable()
    {
        if (target != null && owned != null && target.sharedMesh == owned)
            target.sharedMesh = original;
        if (owned != null) Destroy(owned);
        owned = null;
    }
}
```

保存下面 Shader 为 `E05NormalStreams.shader`，创建材质赋给同一个 Cube。艺术方向只是把平滑法线的 Y 分量压低后归一化，便于观察；不是通用脸部法线生成算法。

```shaderlab
Shader "Encyclopedia/E05NormalStreams"
{
    Properties
    {
        [Enum(Original,0,Smooth,1,Edited,2)] _Source("Normal Source", Float) = 0
        [Enum(NormalRGB,0,TwoBands,1)] _View("View", Float) = 0
        _Threshold("Half Lambert Threshold", Range(0,1)) = 0.5
    }
    SubShader
    {
        Tags { "RenderPipeline"="UniversalPipeline" "RenderType"="Opaque" "Queue"="Geometry" }
        Pass
        {
            Tags { "LightMode"="UniversalForward" }
            Cull Back ZWrite On ZTest LEqual
            HLSLPROGRAM
            #pragma target 3.5
            #pragma vertex Vert
            #pragma fragment Frag
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Lighting.hlsl"
            CBUFFER_START(UnityPerMaterial)
                float _Source, _View, _Threshold;
            CBUFFER_END
            struct Attributes
            {
                float4 positionOS : POSITION;
                float3 normalOS : NORMAL;
                float3 artisticOS : TEXCOORD2;
                float3 smoothOS : TEXCOORD3;
            };
            struct Varyings { float4 positionCS : SV_POSITION; float3 normalWS : TEXCOORD0; };
            Varyings Vert(Attributes i)
            {
                Varyings o;
                float3 n = _Source < 0.5 ? i.normalOS :
                           _Source < 1.5 ? i.smoothOS : i.artisticOS;
                if (dot(n,n) < 1e-8) n = i.normalOS;
                o.normalWS = TransformObjectToWorldNormal(n);
                o.positionCS = TransformObjectToHClip(i.positionOS.xyz);
                return o;
            }
            float4 Frag(Varyings i) : SV_Target
            {
                float3 n = normalize(i.normalWS);
                float3 color = n * 0.5 + 0.5;
                if (_View > 0.5)
                {
                    Light light = GetMainLight();
                    float q = saturate(0.5 * dot(n,light.direction) + 0.5);
                    color = lerp(float3(0.1,0.12,0.22), float3(1,0.7,0.4), step(_Threshold,q));
                }
                return float4(color,1);
            }
            ENDHLSL
        }
    }
}
```

### 操作与预测

1. 使用 URP Forward、Linear、单相机、一盏方向主光。关闭阴影、附加光、后处理、Depth Priming、SSAO、GPU Resident Drawer 与额外 Feature。进入 Play 生成通道。
2. Original / NormalRGB：Cube 的每个面基本为单色。Smooth：同一面内部出现连续变化，但几何轮廓仍是立方体。
3. Edited 与 Smooth 对照，观察法线颜色和 TwoBands 分界变化；相同灯方向不保证相同色块，因为被改变的是 N。
4. 退出 Play 或禁用脚本，克隆网格被恢复。选择 Smooth 时 Shader 对缺失通道回退到原法线，避免零向量；此时不要误认为“生成的平滑法线与原法线相同”。
5. 在 Play 中将 Cube 非均匀缩放，观察法线经逆转置后的响应。不要把数学正确变换与“美术一定喜欢缩放后的图案”混为一谈。

精确位置分组在浮点位置略有差别时不会合并；引入容差又可能错误合并薄层。生产工具需要明确焊接组、硬边、材质/拓扑与变形约束，而不只增加一个距离阈值。

## 6. 各 Pass 必须明确选择自己的数据

主体光照使用艺术法线，不意味着 ShadowCaster 的 Bias 也应使用它。偏移若沿不符合几何的方向进行，可能产生漏光。DepthNormals 若要供屏幕描边使用，则必须决定输出几何、平滑还是艺术法线，否则描边会检测到意料之外的“假边”。

描边挤出方向也必须随着顶点动画一致变化。只更新主体 position/NORMAL，而把存入 UV 的方向留在绑定姿态，会在转头或骨骼弯曲时撕开壳体。此问题不能靠增加线宽解决。

## 7. 自测与验证边界

1. **改 NORMAL 会改变 Cull Front/Back 吗？** 不会直接改变，面朝向取决于投影后的几何绕序。
2. **为什么 Cube 平滑后仍方？** 改的是着色数据，三角形位置未变。
3. **位置相同的顶点必须平滑合并吗？** 不一定，可能属于不同薄层或硬边设计。
4. **SetUVs(3) 对应 TEXCOORD 几？** TEXCOORD3；不要与属性名 mesh.uv3 混淆。
5. **自定义 UV 方向会自动跟随蒙皮吗？** 不能这样假设，必须设计其变形与重建路径。
