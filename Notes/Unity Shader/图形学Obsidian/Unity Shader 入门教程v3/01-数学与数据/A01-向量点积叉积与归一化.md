# A01｜向量、点积、叉积与归一化：NPR 明暗判断的数值基础

> **只有在同一正交单位坐标系中、两个向量都已单位化时，点积才直接等于夹角余弦。卡通明暗分界错误，可能是向量长度或空间错误，并非 Ramp 纹理有问题。**

## 1. 本卡要解决什么

学会区分位置与方向，计算向量长度、点积和叉积，并用它们解释一条可控制的卡通明暗边界。

**前置知识：** 会做实数的加减乘除，知道平方根。文中将解释所需几何概念。**应用环境：** Unity URP、HLSL；数学本身与引擎版本无关。NPR 是 Non-Photorealistic Rendering，即卡通、绘画等非真实感渲染。

本卡使用普通三维欧氏空间和正交单位坐标轴。Unity API 语义核对用户本地 **Unity 6.7 Beta / 6000.7，2026-06-26 构建**文档；Shader 库示例核对 Graphics 提交 `275a7f9ad9330e3cf7f3ea57a0b242a551fde291`，URP/Core RP 17.0.4。二者不是同一个源码版本。

## 2. 三个数字为什么有不同含义

`float3(2, 0, 1)` 只规定三个分量，类型本身不会告诉 GPU 这些数表示位置、速度、方向还是法线。

| 数据 | 含义 | 正确操作举例 |
| --- | --- | --- |
| 点 P | 相对于坐标原点的位置 | 两点相减得到从一个点指向另一个点的位移 |
| 位移 v | 从起点到终点的变化量，含长度 | 位置加位移得到新位置 |
| 单位方向 d | 长度为 1，只表达朝向 | 与另一单位方向点积判断夹角 |
| 法线 N | 与表面切平面垂直的方向 | 单位化后用于朝向与光照判断 |

例如 `P=(1,0,0)`，光源位置 `Q=(1,3,4)`，则从表面指向光源的位移为 `Q-P=(0,3,4)`。它的长度为 5，单位方向为 `(0,0.6,0.8)`。**位移与距离必须先保留，需要方向时再归一化。** 否则会丢失计算距离衰减所需的信息。

## 3. 长度与归一化

对 `v=(x,y,z)`，长度是：

$$
\|v\|=\sqrt{x^2+y^2+z^2},\qquad \hat v=v/\|v\|\quad(\|v\|>0)
$$

帽子符号表示单位向量。`(0,3,4)` 与 `(0,6,8)` 朝向相同，单位化后都是 `(0,0.6,0.8)`。

零向量没有方向，不能定义其归一化。CPU 的 `Vector3.Normalize` 对过小向量有返回零的保护，但不要把这个行为自动套到 HLSL `normalize(0)`。Shader 应对非法输入定义明确策略，例如返回一个指定的单位方向；这个回退是工程约定，不是恢复了原本不存在的方向。[Unity Normalize 文档](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Vector3.Normalize.html)

## 4. 点积：同时包含方向和长度

点积输出一个数：

$$
a\cdot b=a_xb_x+a_yb_y+a_zb_z=\|a\|\|b\|\cos\theta
$$

`θ` 是两向量间夹角。若 `a`、`b` 都是单位向量，长度乘积为 1，点积才直接等于 `cos θ`。

| 夹角 | 单位向量点积 | 几何意义 |
| --- | --- | --- |
| 0° | 1 | 同向 |
| 60° | 0.5 | 有一半的方向投影 |
| 90° | 0 | 垂直 |
| 180° | −1 | 反向 |

点积还表示投影：若 `u` 是单位方向，`v·u` 是 v 沿 u 的带符号长度，`(v·u)u` 是对应的投影向量。投影不是无条件的距离，也不是永远位于 `[−1,1]`。[Unity Dot 文档](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Vector3.Dot.html)

### 4.1 为什么一定要在同一空间

一个向量在物体局部坐标中写作 `(0,0,1)`，不代表它在世界坐标中也指向 `(0,0,1)`。先把 N 和 L 变到同一坐标系，再点积。变量名用 `normalWS`、`lightDirWS` 标出 World Space，即世界空间，可以降低误用概率。

在斜交坐标基下，分量直接相乘再相加通常不足以得到几何点积。本卡不使用这种基；不要把这里的简式推广到任意坐标表示。

### 4.2 一个能推翻错误理解的例子

设单位法线 `N=(0.8,0,0.6)`，单位光线方向 `L=(0,0,1)`。则 `N·L=0.6`。若错误地使用 `2N`，点积变成 1.2，`saturate` 将其截断为 1，表面看起来更亮，但方向根本没变。

更隐蔽的是两段明暗。定义 `step(t,x)`：`x<t` 返回 0，否则返回 1。当 `t=0.5` 时：

- 正确单位法线：亮部条件 `cos θ≥0.5`，边界为 60°。
- 错误地将法线乘 2：亮部条件 `2cos θ≥0.5`，边界变为约 75.52°。

归一化错误移动了整条边界。`saturate` 只是把数限制在 `[0,1]`，不能修复这个错误。

## 5. 叉积：构造垂直方向

叉积输出向量：

$$
a\times b=(a_yb_z-a_zb_y,\ a_zb_x-a_xb_z,\ a_xb_y-a_yb_x)
$$

非退化时它垂直于两个输入，长度为 `|a||b|sin θ`，等于输入围成的平行四边形面积。交换顺序会反向：`a×b=−(b×a)`；平行输入叉积为零，不能用于稳定生成法线。

给定三角形顶点 `P0、P1、P2`，可以从两条边 `e1=P1-P0`、`e2=P2-P0` 构造 `normalize(cross(e1,e2))`。但这是一个按所选顺序定义的面法线，不能据此替代 GPU 对正反面的绕序判断，也不一定等于模型作者编辑过的顶点法线。

Unity 的坐标约定下，`Cross(right,up)=forward`。其文档用左手规则说明方向；教材可能以右手坐标系画图。优先核对坐标轴定义、上面的分量公式和输入顺序，避免只记一张手势图。[Unity Cross 文档](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Vector3.Cross.html)

## 6. 一个完整的 URP 明暗实验 Shader

下面的脚手架把数学直接显示出来。Mesh 是模型几何，VS 是逐顶点程序，片元 Shader 为被图元覆盖的屏幕区域计算候选颜色。`NORMAL` 读取模型法线；`TEXCOORD0` 在这里用于传递世界法线，名字不代表它必须是 UV。

将代码保存为 `A01VectorLab.shader`，新建材质选择 `Encyclopedia/A01VectorLab`，赋给 Unity Sphere。使用 URP Forward、单相机，关闭 Depth Priming、SSAO 和后处理。无需灯光：本实验直接使用材质里的世界方向，排除灯光配置干扰。

```hlsl
Shader "Encyclopedia/A01VectorLab"
{
    Properties
    {
        _LightDirectionWS("Surface To Light (World)", Vector) = (0,0,1,0)
        _NormalScale("Normal Length Multiplier", Range(0.1,3)) = 1
        _Threshold("Band Threshold", Range(0,1)) = 0.5
        [Toggle] _NormalizeInput("Normalize Normal", Float) = 1
        [Toggle] _ShowBands("Show Two Bands", Float) = 1
    }
    SubShader
    {
        Tags { "RenderPipeline"="UniversalPipeline" "RenderType"="Opaque" "Queue"="Geometry" }
        Pass
        {
            Tags { "LightMode"="UniversalForward" }
            Cull Back
            ZTest LEqual
            ZWrite On
            Blend Off
            HLSLPROGRAM
            #pragma target 3.0
            #pragma vertex Vert
            #pragma fragment Frag
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
            CBUFFER_START(UnityPerMaterial)
                float4 _LightDirectionWS;
                float _NormalScale;
                float _Threshold;
                float _NormalizeInput;
                float _ShowBands;
            CBUFFER_END
            struct Attributes
            {
                float3 positionOS : POSITION;
                float3 normalOS : NORMAL;
            };
            struct Varyings
            {
                float4 positionCS : SV_POSITION;
                float3 normalWS : TEXCOORD0;
            };
            float3 UnitOrZ(float3 v)
            {
                float lenSq = dot(v,v);
                if (lenSq < 1e-8) return float3(0,0,1);
                return v * rsqrt(lenSq);
            }
            Varyings Vert(Attributes input)
            {
                Varyings o;
                o.positionCS = TransformObjectToHClip(input.positionOS);
                o.normalWS = TransformObjectToWorldNormal(input.normalOS);
                return o;
            }
            half4 Frag(Varyings input) : SV_Target
            {
                // 先统一基线长度，再故意引入可控的长度错误。
                float3 n = UnitOrZ(input.normalWS) * _NormalScale;
                if (_NormalizeInput > 0.5) n = UnitOrZ(n);
                float3 l = UnitOrZ(_LightDirectionWS.xyz);
                float x = saturate(dot(n,l));
                float value = (_ShowBands > 0.5) ? step(_Threshold,x) : x;
                return half4(value,value,value,1);
            }
            ENDHLSL
        }
    }
}
```

`UnitOrZ` 用倒平方根 `rsqrt` 归一化，并规定极短输入退回世界 +Z；阈值比较的是长度平方。它面向有限、尺度正常的教学输入，不是通用数值库。示例选择 `float` 做方向计算，不能据此断言所有平台上 `half` 与 `float` 的成本和精度都相同。

**执行预测：**

| 设置变化 | 预期 |
| --- | --- |
| Normalize Normal 开启，长度从 1 改到 2 | 边界不变 |
| Normalize Normal 关闭，长度从 1 改到 2 | 亮部扩大 |
| 输入光方向从 `(0,0,1)` 改为 `(0,0,2)` | 光方向始终在 Shader 中归一化，边界不变 |
| 世界光方向反向 | 亮部朝向反转 |
| 关闭 Show Two Bands | 显示连续的 `saturate(N·L)` 灰度 |

显示器编码可能让灰度视觉不呈线性。这个实验比较边界与相对变化；准确读数应看 Shader 数据或对应的线性目标，不凭截图亮度估算点积。

## 7. GPU 与 Unity 源码对应

点积、叉积、归一化在这里是 Shader 算术，编译器会映射为目标 GPU 支持的指令组合；不能仅从一行 HLSL 宣称固定指令数或固定耗时。VS 产生的数据经插值到片元后，单位法线通常需要再次归一化。

本示例调用的 `TransformObjectToWorldNormal` 位于 [固定提交的 SpaceTransforms.hlsl](https://github.com/Unity-Technologies/Graphics/blob/275a7f9ad9330e3cf7f3ea57a0b242a551fde291/Packages/com.unity.render-pipelines.core/ShaderLibrary/SpaceTransforms.hlsl)。其职责是空间变换，逆转置原因见本卡后续主题；当前只需知道法线转换后再与世界光方向比较。NPR 的色阶阈值和艺术法线都是上层选择，GPU 不会理解“卡通脸部”的意图。

## 8. 自测、答案与完成标准

1. `a=(0,3,4)`、`b=(0,0,1)`，`a·b` 与 `normalize(a)·b` 分别是多少？**4 与 0.8。**
2. 为什么 `saturate(dot(a,b))` 不能代替单位化？**它截断结果，却保留长度对未截断区间和阈值的影响。**
3. `cross((1,0,0),(0,1,0))` 与反向输入分别是什么？**+Z 与 −Z。**
4. 零向量归一化能恢复原方向吗？**不能；回退方向是人为定义。**

**完成标准：** 不看答案说明“长度变化如何移动 0.5 阈值边界”，能用上述 Shader 设计对照实验，并能区分数学数值验证与真实 GPU 运行证据。
