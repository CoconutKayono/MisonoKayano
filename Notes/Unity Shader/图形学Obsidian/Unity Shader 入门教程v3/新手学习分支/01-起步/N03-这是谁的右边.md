# N03｜这是谁的右边：物体空间与世界空间

**学完这张卡，你能解释为什么同样写“沿 +X 移动”，一种跟着物体旋转，另一种始终沿场景的 +X 移动。**

## 必须掌握：先问这句话按谁的轴解释

你手拿一个箭头牌，牌上写着“右边”。转动牌子，牌子的右边会跟着转；房间里固定的右边却不变。

模型自己的坐标轴像牌子，叫**物体空间**；整个场景使用的公共坐标轴像房间，叫**世界空间**。空间在这里是描述位置和方向所用的一套原点和轴，不是两张互不相干的地图。

同样的 `(1,0,0)`：按物体轴解释，是物体自己的 +X；按世界轴解释，是固定的世界 +X。物体没有旋转时，两者可能恰好同向，所以错误不容易暴露。

这也不是“屏幕右方”。相机换个角度看，世界 +X 在画面里未必水平向右。

## 核心代码：先转到世界，再加世界位移

下面是完整示例中世界模式的核心：

```hlsl
float3 positionWS = TransformObjectToWorld(input.positionOS);
float3 offsetWS = float3(_Distance, 0, 0);
positionWS = positionWS + offsetWS;
Output output;
output.positionCS = TransformWorldToHClip(positionWS);
return output;
```

第一行把模型位置换成世界坐标；第二行明确生成世界 +X 的位移；第三行让两个世界空间的数据相加。

变量后面的 OS 表示 Object Space（物体空间），WS 表示 World Space（世界空间），只是方便辨认的名字，名字本身不会替你转换数据。

对照物体模式，它先在物体坐标上加 `(Distance,0,0)`，再进行转换。**加位移发生在转换之前还是之后，决定这次位移按哪套轴解释。**

以后法线与光方向也要先用同一套轴再比较。若混用，常见现象就是模型一转，明暗方向便不符合预期。

## 先预测，再验证：只转动 Cube

Unity 6 URP 场景：Cube 位置为 0、旋转为 0、缩放为 1。相机固定并留出足够空间。创建材质选择 `BeginnerNPR/N03SpaceMove`，Distance=0.5，World Space Move=开启。

只把 Cube 的 Rotation Z 从 0 改为 90，其他参数不动。

先预测：移动方向会跟着 Cube 转向世界 +Y 吗？预期不会，它仍在世界 +X 一侧，只有 Cube 本身旋转。

这组实验只检验世界模式。完整示例还提供物体模式，留到末尾最小实践单独做对照；不要同时换模式又旋转来猜原因。

## 理解即可

空间转换函数在内部做数学运算。现在只要读懂函数名字的起点与终点，不用展开矩阵乘法。

## 完整示例

保存为 `N03SpaceMove.shader`，或使用 [独立文件](../示例/N03SpaceMove.shader)。

```shaderlab
Shader "BeginnerNPR/N03SpaceMove"
{
    Properties
    {
        _Distance("Distance",Range(0,0.5))=0.5
        [Toggle] _WorldSpace("World Space Move",Float)=1
    }
    SubShader
    {
        Tags { "RenderPipeline"="UniversalPipeline" "RenderType"="Opaque" }
        Pass
        {
            Tags { "LightMode"="SRPDefaultUnlit" }
            HLSLPROGRAM
            #pragma vertex Vert
            #pragma fragment Frag
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
            CBUFFER_START(UnityPerMaterial)
                float _Distance, _WorldSpace;
            CBUFFER_END
            struct Input { float3 positionOS : POSITION; };
            struct Output { float4 positionCS : SV_POSITION; };
            Output Vert(Input input)
            {
                Output output;
                if(_WorldSpace > 0.5)
                {
                    float3 positionWS = TransformObjectToWorld(input.positionOS);
                    positionWS += float3(_Distance,0,0);
                    output.positionCS = TransformWorldToHClip(positionWS);
                }
                else
                {
                    float3 positionOS = input.positionOS + float3(_Distance,0,0);
                    output.positionCS = TransformObjectToHClip(positionOS);
                }
                return output;
            }
            float4 Frag() : SV_Target { return float4(1,0.6,0.1,1); }
            ENDHLSL
        }
    }
}
```

预期不符先看是否选对 Shader、World Space Move 是否开启，以及旋转的是 Cube 还是相机。若物体完全不见，确认相机能看到它；启用 Depth Priming 的测试项目先关闭该选项。这里移动的是绘制位置，不会改变 Transform 的 Position。

## 带走这些

**三个结论**

1. 方向的三个数必须连同“按哪套轴解释”一起理解。
2. 物体 +X 会随物体旋转，世界 +X 不会随它旋转。
3. 名字带 WS 不会自动完成转换，真正起作用的是计算。

**两个自测**

- 世界 +X 是否永远是屏幕右边？——不是，它取决于相机观察角度。
- 物体没有旋转时，两种模式看起来一样，能否证明空间可以混用？——不能，只是这个姿势没有暴露差别。

**一个最小实践：** 重置 Rotation Z=0，关闭 World Space Move，建立新的基准；然后只把 Rotation Z 改为 90。预期物体 +X 的位移转到世界 +Y。
