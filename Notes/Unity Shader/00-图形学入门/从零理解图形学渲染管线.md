# 从零理解图形学渲染管线

> **适合谁：** 没学过图形学、不熟悉三维坐标，也还不知道 Shader 是什么的读者。  
> **需要什么基础：** 知道图片由像素组成即可；不知道也没关系，下面会解释。  
> **学习目标：** 能用自己的话讲清楚：一个三维物体，怎样一步一步变成屏幕上的画面。  
> **阅读方式：** 可以分三次读：第 1～5 节建立整体印象，第 6～11 节理解核心过程，第 12～17 节复习和自测。第一次不必记住所有英文名称。

---

## 1. 先把问题想清楚：电脑究竟在“画”什么？

想象一个非常简单的场景：

- 一张桌子上放着一个红色杯子。
- 左上方有一盏灯。
- 你站在桌子前，拿着相机对准杯子。

如果让人画这幅画，人会观察杯子的轮廓、明暗、遮挡，然后下笔。

但是，电脑不会天然理解“杯子”。它拿到的通常是一堆数据：

- 一些点的位置，以及这些点怎样连接成表面。
- 杯子的颜色、花纹和材质参数。
- 灯的位置、方向、颜色和强度。
- 相机的位置、朝向，以及能看到多大的范围。

而屏幕需要的是另一种东西：**一张二维图片，每个位置应该显示什么颜色。**

于是，中间就有一个任务：

> **把“关于三维场景的数据”，计算成“一张二维图片”。这个过程叫渲染。**

把这个任务拆成一连串有先后关系的步骤，就得到了**渲染管线**。

“管线”听起来复杂，其实可以先理解成流水线：前一步把结果交给后一步，各自解决一部分问题。

### 屏幕为什么能让你看到立体感？

屏幕显示的仍然是一张平面图片。图中的近大远小、前后遮挡、明暗变化等线索，让我们感受到立体感。

可以把像素想象成图片中的一个个小格子。每个格子记录一种颜色，排列在一起，就组成画面。比如一张 1920 × 1080 的图片，大约有 207 万个像素。

渲染器最终要回答的，就是大量这样的具体问题：

> “图片第 500 列、第 300 行，这个位置应该是什么颜色？”

不过，它通常不会先理解“这里是杯子”，而是通过几何、覆盖关系和颜色计算得到答案。

**本节只记一句：渲染，就是根据场景数据，算出图片。**

## 2. 先看地图：整条管线在忙什么？

本文主要介绍**基于光栅化的三维渲染管线**。这是理解实时三维画面的重要基础。“光栅化”这个词先不用背，到第 7 节你就会知道它在做什么。

下面是一张用于理解的流程图：

```text
准备场景数据和绘制命令
        ↓
处理顶点：物体在哪里？相机从哪里看？
        ↓
组织三角形、裁剪、映射到屏幕区域
        ↓
光栅化：三角形覆盖了哪些采样位置？
        ↓
片元着色：这些位置的表面应该呈现什么颜色？
        ↓
深度等测试与混合：哪些结果保留？怎样与已有颜色组合？
        ↓
写入图像，按需要做后期处理
        ↓
提交显示
```

**这张图表示理解上的数据流，不是 GPU 内部严格逐个执行的时间表。** 例如，满足条件时，深度测试可以提前进行，避免给注定被挡住的片元计算颜色。

第一次阅读时，可以把它缩成四个问题：

| 问题 | 主要由谁解决？ |
| --- | --- |
| 物体在画面中的什么位置？ | 顶点处理、投影和视口变换 |
| 它覆盖画面的哪些位置？ | 光栅化 |
| 表面应该是什么颜色？ | 片元着色 |
| 它是否被挡住，怎样加入已有画面？ | 深度测试、混合等操作 |

后面出现的新名词，都可以放回这四个问题里。

> **范围说明：** 光线追踪是另一条理解渲染的路线，本文只在后面做简单对比。这里也先跳过曲面细分、几何着色器等可选阶段，避免一开始就被细节淹没。传统管线中可编程阶段与固定功能阶段的划分，可对照 [Microsoft 的图形管线概览](https://learn.microsoft.com/en-us/windows/win32/direct3d11/overviews-direct3d-11-graphics-pipeline)。

## 3. 原料：电脑怎样表示一个物体？

### 3.1 顶点：带有信息的点

一个三维位置需要描述三个方向。为了方便想象，我们暂时约定：

- `x` 表示左右。
- `y` 表示上下。
- `z` 表示前后。

这就像在房间里告诉别人：“从指定的起点向右走一点、向上抬一点、再向前挪一点。”

这里的方向约定只用于解释；不同软件可能有不同约定。

**顶点（Vertex）**可以先理解成模型表面上的一个点。实际存储时，它通常不只有位置，还可以带着：

- 颜色。
- 纹理坐标：对应花纹图片的哪个位置。
- 法线：表面朝向哪个方向。

后两项暂时记住用途就行，后面会展开。

### 3.2 三角形：连接点，形成表面

三个不在同一直线上的点，可以确定一个三角形。

```text
          A
         / \
        /   \
       /     \
      B-------C
```

把许多三角形连接起来，就能拼出杯子、汽车、人物等模型的表面。这种结构通常叫**网格（Mesh）**。

为什么经常用三角形？

- 三个不共线的点总能确定一个平面，形状明确。
- 复杂表面可以用许多小三角形来近似。
- 它适合统一处理，硬件也为这类工作提供了支持。

例如，立方体的每个正方形面可以切成两个三角形，六个面总共十二个三角形。

球面是弯的，三角形是平的，因此三角形网格表示的球面通常是一种近似。三角形足够细，再配合平滑的明暗变化，就可以显得很圆润。

**注意：三角形往往只是内部表示方式，最终画面不需要把三角形的边线画出来。**

### 3.3 连接关系也需要告诉电脑

只有一串点的位置，还不能确定它们要拼成什么。

程序还需要说明：“用哪三个顶点组成一个三角形？”用于引用顶点的编号叫**索引（Index）**。

比如一个正方形有四个角，用两个三角形来画时，可以重复引用公共顶点，而不必把每个位置的数据都复制一遍。

### 3.4 几何、纹理、材质有什么区别？

| 概念 | 主要回答什么？ | 杯子的例子 |
| --- | --- | --- |
| 几何／网格 | 形状是什么？ | 杯身、杯口和把手的表面 |
| 纹理（Texture） | 表面各处存着什么数据？ | 印在杯身上的花纹图片 |
| 材质（Material） | 表面怎样参与外观计算？ | 是粗糙陶瓷，还是光滑金属 |

先把纹理理解成花纹图片最容易，但纹理也可以存储粗糙度、表面方向等数据。材质通常把着色规则、纹理和参数组织在一起。

**本节只记一句：网格描述形状，纹理提供表面数据，材质组织外观规则。**

## 4. 谁在工作：CPU、GPU 和 Shader

### 4.1 CPU：组织这一帧需要做什么

CPU 是电脑里执行通用程序的处理器。

在一个简单的三维程序中，它通常负责更新场景，例如：

- 用户按了前进键，相机要移动。
- 杯子正在旋转，需要更新旋转角度。
- 本次绘制要使用哪个模型、哪张纹理、什么着色程序。
- 向图形系统提交绘制命令。

这类“用这些数据和设置进行绘制”的命令，常被称为 **Draw Call，绘制调用**。

一次调用可能画许多三角形，也可能画多个重复物体；不要把它直接等同于“画一个像素”或“固定画一个物体”。

### 4.2 GPU：并行处理大量相似工作

GPU 是特别适合处理大量并行计算的处理器。

想象一个物体有很多顶点，画面又有很多需要处理的位置。对它们执行的计算往往很相似，GPU 可以让大量这样的工作并行进行。

可以把 CPU 想成安排工作的负责人，把 GPU 想成擅长大规模相似计算的工作团队。不过，这只是入门比喻，真实程序里两者的分工更灵活。

模型和纹理等资源也不一定每帧重新上传；它们可以留在 GPU 可访问的存储中，重复使用。

### 4.3 Shader：写给 GPU 的小程序

**Shader 通常译作着色器，是在 GPU 上执行的一类程序。**

这个中文名字容易让人以为它只负责“涂颜色”。实际上，不同着色器负责不同工作。

本文最重要的两种是：

| 着色器 | 主要处理什么？ | 你可以给它什么任务？ |
| --- | --- | --- |
| 顶点着色器（Vertex Shader） | 顶点数据 | 调整位置，把顶点变换到后续阶段需要的坐标 |
| 片元着色器（Fragment Shader） | 光栅化产生的片元 | 读取纹理、计算光照、输出颜色等数据 |

在 Direct3D 的术语里，第二种常叫**像素着色器（Pixel Shader）**。先把它们当成这里对应的阶段即可；“片元”和最终像素的区别，第 7 节会解释。

还有一些步骤，主要通过设置规则控制，不需要自己写一整段着色程序。例如选择是否剔除背面、怎样比较深度。这类步骤通常称为**固定功能阶段**，意思是工作方式由图形系统提供，而不是完全不可配置。

**本节只记一句：CPU 组织绘制，GPU 执行大量计算，Shader 定义其中一部分计算规则。**

## 5. 顶点处理：同一个点，为什么要换好几种坐标？

这是最容易被一串名词吓住的地方。先忘掉矩阵，想一个生活问题：

> “杯把在哪里？”

你可以回答：

- 在杯子中心的右边。
- 在房间桌子的某个位置。
- 在我前方稍微偏左的地方。

**你说的是同一个杯把，只是参照物不同。** 坐标变换首先就是在做这种“换一种参照方式描述位置”的事。

### 5.1 模型空间：以物体自己为参照

模型制作时，通常会选择自己的原点。例如，把杯子底部中心作为原点。

杯把上的一个点，位置是相对于这个原点记录的。这种表示叫**模型空间**，也叫局部空间。

好处是：模型不用提前知道自己将来放在哪个房间。

### 5.2 世界空间：把物体放进共同场景

现在把杯子放到桌子右侧，再转动一点。

需要对它进行移动、旋转，也可能缩放。这些操作让模型中的点获得场景里的位置。

这个过程叫**模型变换**，有的资料称为世界变换。

可以把它理解成：

> “这只杯子本身长这样；现在请把整只杯子摆到房间的这里。”

场景里的桌子、杯子和灯，都可以用同一套世界坐标来描述。

### 5.3 观察空间：以相机为参照重新描述

接下来需要回答：“从相机这里看，这个点在什么方向、什么位置？”

把世界里的位置改成相对于相机的表示，叫**观察变换**，得到的空间也叫观察空间或相机空间。

一个直观例子：

- 你站在杯子左边，杯子相对于你在右侧。
- 你绕到另一边，杯子相对于你的方向变了。
- 杯子在房间里的位置可以完全没变。

因此，**移动相机就能改变画面，并不需要修改杯子原始的形状。**

### 5.4 投影：决定远近怎样影响画面

现在虽然已经“站到相机的位置”，但还没有得到屏幕图片。

还要决定：三维位置怎样映射到二维画面？这由**投影（Projection）**参与解决。

两种常见方式是：

| 投影 | 直观效果 | 想象方法 |
| --- | --- | --- |
| 透视投影 | 同样大的物体，越远通常显得越小 | 看一条向远处延伸的道路 |
| 正交投影 | 在投影参数固定时，物体不会仅因远离相机而变小 | 看不强调近大远小的工程示意图 |

透视投影还与**视野角度（FOV）** 有关：相机能张开多大的“视野”。在其他条件相同时，视野越宽，能容纳的范围越大，同一个物体往往显得越小。

### 5.5 不用公式，也可以读懂完整坐标路线

稍微完整一点的路线如下：

```text
模型空间：点相对于物体在哪里？
    ↓ 模型变换
世界空间：点在共同场景里在哪里？
    ↓ 观察变换
观察空间：点相对于相机在哪里？
    ↓ 投影变换
裁剪空间：进入适合判断可见范围的中间表示
    ↓ 裁剪之后进行透视除法
标准化设备坐标（NDC）：转换到统一的坐标范围
    ↓ 视口变换
屏幕／渲染目标坐标：对应图像上的什么位置？
```

不用背最后几个名词的数学定义，只要理解：

1. 先摆好物体。
2. 再换成相机的视角。
3. 再按投影规则整理位置。
4. 最后映射到实际图像的宽度和高度。

**透视除法**可以暂时理解成：利用投影阶段保留的辅助信息，完成透视所需的坐标换算。那个辅助量常记作 `w`，现在不需要计算它。

**视口（Viewport）** 是这次绘制使用的图像区域。例如，它可以是整张 800 × 600 的图像，也可以只是窗口的一部分。

还有一个关键细节：**从三维走向二维画面，并不意味着马上扔掉深度。** 后面仍需要深度来判断遮挡。

> 在这里介绍的常见流程中，顶点着色器输出的是裁剪空间位置，之后还需要裁剪、透视除法和视口变换，才得到屏幕位置。这个阶段划分可对照 [Microsoft 的变换管线说明](https://learn.microsoft.com/en-us/windows/win32/dxtecharts/the-direct3d-transformation-pipeline)。不需要阅读其中的矩阵公式。

**本节只记一句：物体坐标 → 场景坐标 → 相机视角 → 投影与屏幕位置。**

## 6. 组织三角形、裁剪与剔除：哪些部分值得继续处理？

顶点位置被处理之后，还需要按照连接关系，把相应顶点视为一个个三角形。这通常称为**图元装配**；图元就是用于绘制的基本形状，比如点、线和三角形。

不同图形接口的阶段名称和划分略有不同。这里关心的是：后续要处理的是有边界、有面积的三角形，不是彼此无关的一堆点。

### 6.1 裁剪：只保留相机范围内的部分

相机能看到的范围有限。

透视相机的可见空间，可以想象成一个向前张开的四棱锥，被近处和远处的两个平面截掉尖端及远端，留下中间一段。这通常叫**视锥体**。

它限定了左右、上下，以及允许显示的近处和远处范围。

如果三角形：

- 完全在可见范围内，就继续处理。
- 完全在某个裁剪边界之外，可能被整个去掉。
- 横跨边界，就切掉外面的部分，保留里面的部分。

例如，杯子的一半伸出画面右边缘，正常结果应该是“只显示杯子的左半部分”，而不是整只杯子突然消失。

这就是**裁剪（Clipping）** 的直观用途。

不要把裁剪想成“只检查顶点，顶点不在范围内就删除整个三角形”。一个大三角形即使三个顶点都在画面之外，中间仍可能覆盖画面。

### 6.2 背面剔除：有些背向相机的面可以跳过

对于封闭且不透明的物体，背向相机的表面通常不需要绘制，因此经常开启**背面剔除（Back-face Culling）**。

你可以把一个三角形想成一张有正反面的薄纸：从正面看允许画，从背面看可以跳过。

图形系统通常利用三角形顶点的绕序，也就是投影后顶点呈顺时针还是逆时针，结合设置来判断正反面。

但一张需要两面都看得见的纸，或某些叶片，就可能需要关闭背面剔除或采用双面渲染。

**背面剔除不等于遮挡判断。** 正对相机的杯子表面，也可能被前面的书挡住；那是后面深度测试要解决的问题。

**本节只记一句：裁剪处理超出范围的部分，背面剔除按规则跳过背向相机的面。**

## 7. 光栅化：从三角形，走到图片的格子

前面处理的是点和三角形的位置。现在到了整条管线中一个重要转折：

> 已经知道一个三角形落在画面的哪里，怎样知道应该处理哪些像素位置？

### 7.1 把三角形盖在方格纸上

想象在方格纸上画一个大三角形。

```text
· · · · · · · · ·
· · · · ■ · · · ·
· · · ■ ■ ■ · · ·
· · ■ ■ ■ ■ ■ · ·
· ■ ■ ■ ■ ■ ■ ■ ·
· · · · · · · · ·
```

上图只是示意：`■` 表示需要处理的图像位置。

**光栅化（Rasterization）** 的核心任务，就是根据三角形的形状和覆盖规则，找出它覆盖哪些采样位置，并产生供后续处理的数据。

为了入门，可以先假设每个像素只有一个采样点，放在像素中心：

- 中心落在三角形覆盖范围内，就产生相应候选数据。
- 中心不在范围内，就不为这个三角形产生该位置的数据。

实际还有边界归属规则、多重采样等细节。这些不影响你先理解“用连续的形状找出离散的图像位置”。

### 7.2 片元不是已经确定的最终像素

光栅化产生的候选数据叫**片元（Fragment）**。

在上面的简单情形下，可以把一个片元理解成：

> “这个三角形想对图片的这个位置贡献一个结果；它带着深度和供着色使用的信息，等待后续处理。”

它与最终像素的区别非常重要：

- **像素**是输出图片里的一个位置及其最终存储结果。
- **片元**是绘制过程中，某个图元对该位置产生的一份候选数据。

假设一块玻璃、一个杯子和一面墙，在画面上都覆盖同一个位置，这个位置就可能先后收到多个片元。后续步骤决定谁留下、谁被挡住、谁与其他颜色混合。

因此：

> **产生了片元，不等于它一定会出现在最终画面里。**

### 7.3 为什么三个顶点能画出那么大一块区域？

因为三个顶点确定了整个三角形的边界。光栅化会找出边界内需要处理的位置。

它不是只画三个顶点，也不是必须提前给每个像素提供一个顶点。

一个只有三个顶点的大三角形，可以覆盖图像中的很多位置。

> 光栅化生成片元，顶点输出的属性可插值后交给片元着色器，这些阶段之间的关系可对照 [Khronos 的图形管线入门说明](https://docs.vulkan.org/tutorial/latest/03_Drawing_a_triangle/02_Graphics_pipeline_basics/00_Introduction.html)。

**本节只记一句：光栅化找出三角形覆盖的位置，产生尚待处理的片元。**

---

## 8. 插值和纹理：三角形中间的信息从哪里来？

现在我们知道三角形覆盖了一大片图像位置。但如果输入只给了三个顶点的数据，中间位置的颜色、纹理坐标等信息怎么办？

### 8.1 插值：用端点信息，推算中间值

先看更简单的线段：

- 左端亮度是 0。
- 右端亮度是 100。
- 如果要求均匀过渡，中间就可以取 50。

这种根据已知位置的值，计算中间位置的值的方法，叫**插值（Interpolation）**。

对于三角形，也是类似的想法：依据内部位置与三个顶点的关系，组合顶点上的数据。

比如三个角分别是红、绿、蓝，而且我们让片元着色器直接使用插值颜色，那么三角形内部就可以呈现平滑的颜色过渡。

但不要把它记成“每个位置都把三个值平均一下”。位置不同，权重不同；倾斜的三维表面通常还需要**透视校正插值**，避免纹理出现错误的拉伸。第一遍只需知道：图形系统能按指定规则补出内部位置的数据。

### 8.2 纹理坐标：这个表面位置，该去图片哪里取数据？

假设杯身有一张猫咪贴纸。

电脑需要建立一种对应关系：杯子表面的这个位置，对应贴纸图片的哪个位置？

这就是**纹理坐标**的用途。二维纹理坐标常写成 `u`、`v`，合称 **UV**。

可以把 UV 理解成图片上的“地址”：一个方向表示横向位置，另一个方向表示纵向位置。常用 0 到 1 表示从一端到另一端，具体上下方向按使用的约定确定。

用一张三角形纸做例子：

- 纸的顶角对应贴纸上边中间。
- 纸的左下角对应贴纸左下角。
- 纸的右下角对应贴纸右下角。

这些对应关系可以放在三个顶点上。光栅化过程中，通过插值，三角形内部的位置也能获得对应的 UV。

片元着色器随后就能按这个地址读取纹理。

### 8.3 采样：读取数据，有时需要综合附近的信息

从纹理中获取数据，叫**纹理采样（Texture Sampling）**。

纹理图片里的小数据单元叫**纹素（Texel）**。它与屏幕像素不是同一件东西：纹理可以被放大、缩小、旋转，再映射到表面上。

因此，读取纹理时不一定只是挑一个纹素直接复制。根据过滤设置，也可以综合附近的纹素，让放大或缩小时的结果更合适。纹理资源、纹素和过滤的关系见 [Microsoft 的纹理介绍](https://learn.microsoft.com/en-us/windows/uwp/graphics-concepts/introduction-to-textures)。

你现在只需要抓住这个链条：

```text
顶点提供 UV
    ↓
插值得到内部位置的 UV
    ↓
片元着色器按 UV 采样纹理
    ↓
拿到这个表面位置所需的颜色或其他数据
```

**本节只记一句：UV 指路，插值补出中间的地址，纹理采样按地址读取数据。**

---

## 9. 片元着色：这个表面位置，应该是什么颜色？

现在，一个片元可能已经有了：

- 自己对应的图像位置和深度。
- 插值得到的颜色、UV、法线等信息。
- 着色器可以访问的纹理、材质参数和灯光数据。

片元着色器利用这些输入，计算输出。

### 9.1 最简单的着色：全部涂红

最简单的规则可以只有一句：

```text
对每个待着色的片元，输出红色。
```

这就能画出一个纯红色三角形。它不需要纹理，也不需要光照。

因此，**着色不等于必须模拟灯光。** 显示纯色、纹理、卡通色块，都属于可以编写的着色规则。

### 9.2 为什么加上光照，平面图片会显得立体？

想象用手电筒照一个白色纸盒：

- 正对手电筒的面通常更亮。
- 侧对手电筒的面通常较暗。

一个简单的光照模型可以模仿这种变化。

为了计算这种朝向关系，需要**法线（Normal）**。你可以把它想象成从表面垂直伸出来的一根小箭头，用来说明“这里的表面朝哪里”。

通过比较表面方向、光线方向，再结合材质等信息，就能得到不同的明暗。

这里不需要记住角度公式，只需理解：

> 同一种表面颜色，在不同朝向和光照条件下，可以算出不同的显示颜色。

### 9.3 材质为什么也重要？

同一盏灯照着陶瓷杯和金属杯，外观不会一样。

着色规则可以使用粗糙度、金属属性等参数，让不同表面对光照产生不同的外观响应。

最初学习时，不需要一次理解这些参数的物理意义。先把它们当成“控制表面怎样显现”的输入即可。

### 9.4 阴影不是基本光照自动附赠的

一个面背向灯而变暗，与它被别的物体挡住灯光而处于阴影中，是两件事。

- **表面朝向造成的明暗：** 需要知道这个面朝哪里。
- **投下的阴影：** 还需要知道它与光源之间有没有遮挡物。

只知道法线和灯的位置，通常不足以自动判断所有遮挡。渲染器需要额外方法，例如从光源视角生成深度信息，或者追踪通往光源的射线。

本文先不展开阴影算法，但要记住：**基础管线提供处理框架；具体效果还需要对应的数据和算法。**

**本节只记一句：片元着色器使用输入数据和你指定的规则，计算表面的输出颜色等结果。**

## 10. 深度测试与混合：算出了颜色，为什么不一定能留下？

### 10.1 问题：后画的东西会不会盖住先画的东西？

如果程序只是不断覆盖图片里的颜色，那么后画的墙可能把前面的杯子盖掉。

可是我们想要的规则通常是：

> 对于普通不透明表面，同一观察方向上，更靠近相机的表面应该挡住更远的表面。

这就需要**深度测试（Depth Test）**。

### 10.2 除了颜色表，再准备一张深度表

可以先想象两张与画面位置对应的表：

| 表                              | 记录什么？        |
| ------------------------------ | ------------ |
| 颜色缓冲（Color Buffer）             | 这个位置目前保存的颜色  |
| 深度缓冲（Depth Buffer，也叫 Z-buffer） | 这个位置目前保存的深度值 |

“缓冲”在这里可以理解成一块保存数据的存储区域。

为了方便举例，**下面约定深度越小表示越近，并启用“小于才通过”的深度比较和深度写入**。

注意：实际深度值通常经过投影和映射，不是直接以米记录的距离；也存在数值越大越近的设置。这里只用一种简单约定理解比较过程。

### 10.3 同一个位置，两份候选结果

假设画面的某个位置，同时被前方红色三角形和后方蓝色三角形覆盖：

- 红色三角形在这里的深度是 `0.3`。
- 蓝色三角形在这里的深度是 `0.8`。
- 开始时，把深度缓冲清成 `1.0`，颜色清成背景色。

**情况一：先画蓝色，再画红色。**

| 操作 | 比较 | 结果 |
| --- | --- | --- |
| 蓝色片元到来 | 0.8 比 1.0 小 | 保留蓝色，把深度更新成 0.8 |
| 红色片元到来 | 0.3 比 0.8 小 | 保留红色，把深度更新成 0.3 |

最终是红色。

**情况二：先画红色，再画蓝色。**

| 操作 | 比较 | 结果 |
| --- | --- | --- |
| 红色片元到来 | 0.3 比 1.0 小 | 保留红色，把深度更新成 0.3 |
| 蓝色片元到来 | 0.8 不比 0.3 小 | 测试失败，保留已有的红色和深度 |

最终仍然是红色。

这说明：**在这个正常的不透明绘制例子中，遮挡关系可以由深度决定，不必靠“碰巧按正确顺序画”。**

比较的是图像各位置上的深度，不是给整个物体只算一个距离。所以两个物体相互穿插时，也能在不同位置分别判断谁在前面。

### 10.4 为什么还听说过“提前深度测试”？

如果 GPU 能在计算片元颜色之前，就确定它被已有表面挡住，那么跳过昂贵的着色工作会更划算。

所以，满足条件时可以提前进行深度测试或相关剔除。这就是为什么不同资料中的流程图，可能把深度测试画在不同位置。

你现在应当记住的是它的**职责**，不用把一张教学图当成所有硬件的唯一执行顺序。

另外，深度测试与深度写入是两项可以分别控制的设置：通过比较，不一定就要更新深度表。Direct3D 中这两类控制的具体配置可对照 [Microsoft 的深度与模板功能说明](https://learn.microsoft.com/en-us/windows/win32/direct3d11/d3d10-graphics-programming-guide-depth-stencil)。

### 10.5 透明物体：前面的颜色不一定完全替换后面的颜色

假设蓝色背景前有一层半透明红色薄片。

我们可能希望最终颜色同时保留薄片和背景的贡献。这种组合新颜色与已有颜色的操作，叫**混合（Blending）**。

颜色数据里经常有一个 **Alpha** 值。在简单透明混合的例子里，可以把它当成不透明程度：

- `0`：完全透明。
- `1`：完全不透明。
- `0.5`：部分透明。

在一种简单的混合设置下，Alpha 为 0.5 可以让新颜色和已有颜色各贡献一半。真正的玻璃还涉及反射、折射等效果，不能只靠这个例子完整模拟。

**仅仅输出小于 1 的 Alpha，不保证物体自动透明；还需要相应的混合设置。**

常见的透明绘制做法是：先画不透明物体，再把透明表面大致从远到近画，保留深度测试，但通常关闭透明表面的深度写入。这不是所有透明场景的万能方案，复杂交叠还需要其他方法。

为什么透明常常要考虑顺序？因为每一层都在与“已经画好的结果”组合，换个顺序，结果就可能改变。

### 10.6 还有一种可选检查：模板测试

**模板测试（Stencil Test）**可以根据图像位置上的标记，决定允许不允许绘制。

可以把它想成一张带有孔洞的纸模板：只允许某些区域被画出来。

第一遍知道它是“按标记限制绘制区域”的工具即可，不需要展开。

**本节只记一句：深度测试决定遮挡，混合决定新结果怎样与已有颜色组合。**

## 11. 画面到哪里去：图像存储、后期处理与显示

### 11.1 先写到图像里，再交给显示系统

GPU 通常先把结果写入可供渲染的图像资源，这类目标叫**渲染目标（Render Target）**。

你还会遇到**帧缓冲（Framebuffer）**这个词。初学时，可以把它理解成一次绘制所使用的颜色、深度等图像的组织；不同图形接口对这个对象的具体定义并不完全相同。

关键是：

> 渲染的输出先是存储中的图像数据，它不一定立刻就是显示器正在显示的那张图。

### 11.2 一帧画面，可以经历多次绘制

**一帧（Frame）**就是动画或实时画面中的一次图像结果。

为了生成一帧，程序可能先画背景，再画桌子、杯子和其他物体。它们可以多次经过管线，共同构成一张图像。

有时还会先画到中间图像，再利用这张图像继续计算。例如：

```text
绘制场景 → 中间图像 → 调整颜色或添加效果 → 用于显示的图像
```

围绕某个目的组织的一轮渲染处理，常被称为 **Pass**。它可能包含很多绘制调用，不必把 Pass、Draw Call 和 Frame 当成同一个东西。

### 11.3 后期处理：把已经画好的图像当作输入

**后期处理（Post-processing）**可以利用已有图像，完成诸如：

- 调整整体色彩。
- 让高亮区域产生辉光。
- 模糊某些区域。
- 改善部分边缘锯齿。

这类操作可能使用覆盖画面的三角形和片元着色器，也可能使用计算着色器等方式。入门时先理解“上一轮的输出，成为下一轮的输入”。

### 11.4 锯齿为什么会出现？

斜线和曲线是连续的，但图像用有限的离散像素表示它们。

一条斜边落到像素网格上，就可能呈现台阶状。物体运动时，覆盖关系不断变化，也可能出现闪烁。

**抗锯齿（Anti-aliasing）**是一类缓解这种采样问题的方法。有些通过更多采样了解一个像素内的覆盖情况，有些分析已经生成的图像，有些结合多帧信息。

所以抗锯齿不一定都是最后加的一层模糊，也不一定都发生在同一个阶段。

### 11.5 最后是呈现，然后开始下一帧

用于显示的图像准备好后，程序把它提交给显示系统。屏幕更新还会涉及窗口系统、缓冲切换和显示时机等机制，这里不再展开。

下一帧中，程序更新场景，再生成新的图像。连续显示，就形成运动效果。

例如，要持续生成每秒 60 帧，平均每帧可用时间大约是 16.7 毫秒。顶点处理、片元计算、图像读写等工作，都要分享有限的时间。

**本节只记一句：一帧常由多次绘制和图像处理组成，完成后再提交显示。**

---

## 12. 把所有步骤串起来：一张三角形纸的屏幕之旅

现在不看复杂的杯子，只想象一张带猫咪图案的三角形纸，放在蓝色墙面前。

我们先把纸当成不透明表面，只关注它的一个三角形。

### 第一步：准备原料

程序拿到三个顶点、它们组成三角形的连接关系、每个顶点的 UV、猫咪纹理，以及相机和灯光信息。

此时有的是**数据**，还没有这张纸的屏幕图片。

### 第二步：把纸摆进场景

通过模型变换，把纸放到墙前，再稍微倾斜一点。

此时知道三个角在场景里的位置。

### 第三步：换成相机视角，并处理投影

观察变换描述三个角相对于相机的位置；投影变换为后面的裁剪和屏幕映射准备位置数据。

纸的远端与近端，可能因为透视而呈现不同的视觉尺寸关系。

### 第四步：保留可见部分，映射到图像区域

组织三角形，处理可见范围边界，再进行透视除法、视口映射等步骤。

假设这张纸的三个角最终落在图像中的这些位置：

- A：第 400 列附近、第 100 行附近。
- B：第 200 列附近、第 450 行附近。
- C：第 600 列附近、第 450 行附近。

这组数字只是演示屏幕位置，不需要你计算。顶点可以落在非整数坐标，并不要求刚好处于像素中心。

### 第五步：光栅化找出覆盖位置

虽然只有三个顶点，三角形内部却覆盖了很多图像位置。

光栅化为这些位置产生片元，并让后续着色获得插值属性。

### 第六步：采样纹理，计算外观

某个片元的 UV 指向猫咪图案的耳朵，于是读取耳朵附近的纹理数据。

片元着色器再按选定规则结合光照、表面方向等信息，计算这个片元的输出颜色。

这一步重复处理许多片元，图案就出现在整张纸的表面上。

### 第七步：与墙面进行遮挡判断

同一个画面位置，墙面也可能产生过片元。

深度测试发现纸比墙更近，所以这个位置保留纸的结果。纸没有覆盖的位置，仍可以显示墙。

### 第八步：完成图像并显示

通过测试的结果写入目标图像。按需要完成后期处理，再提交显示。

**你看到的是一张带图案的三角形纸；电脑执行的是一系列位置、覆盖、取样、颜色和深度处理。**

## 13. 用四种“变化”，检查你是否理解了分工

假设画面里还是那张三角形纸。我们一次只改变一件事。

| 改变什么？ | 主要影响哪里？ | 你会看到什么？ |
| --- | --- | --- |
| 把纸向右移动 | 顶点的位置变换，进而影响覆盖位置 | 纸在画面中移动 |
| 相机后退，透视参数保持不变 | 相对相机的位置与透视结果 | 纸通常显得更小 |
| 把猫咪纹理换成格子纹理 | 纹理采样取得的数据 | 形状和位置相同，但图案改变 |
| 把灯移到另一侧 | 光照着色所使用的输入 | 明暗发生变化，几何轮廓可以不变 |

再想一个变化：把一块不透明木板放到纸前面。

纸仍然可能有需要提交和处理的数据，但重叠区域会受到遮挡；在正确配置的普通深度测试下，前方木板会留下。

这个例子能帮助你区分：

- **位置变了**，与**外观变了**，不是同一种操作。
- **覆盖一个位置**，与**最终显示在这个位置**，不是同一个条件。

## 14. 初学者最容易混淆的八件事

### 误区一：渲染管线就是给模型涂颜色

涂颜色只占一部分。位置变换、裁剪、覆盖判断、遮挡处理和结果存储同样重要。

### 误区二：顶点越多，图像像素就越多

顶点属于模型；像素属于输出图像。三个顶点构成的大三角形也能覆盖整张图片的大部分区域。提高输出分辨率，也不会自动增加原模型的顶点数量。

### 误区三：光栅化会自动算出真实光照

光栅化主要解决覆盖关系。表面呈现什么颜色，需要着色规则和相应输入。

### 误区四：片元就是最终像素

片元是候选数据。多个片元可能对应同一图像位置，有些会被丢弃，有些会被混合。

### 误区五：换成二维坐标以后，深度就没用了

深度仍然需要参与遮挡判断。画面是二维的，不代表所有中间信息都只能有两个维度。

### 误区六：模型有纹理，就一定有立体感和阴影

纹理可以只是颜色图片。立体感还与几何、投影、光照等有关；阴影通常需要额外的遮挡信息。

### 误区七：所有阶段都要自己写 Shader

部分阶段可编程，部分阶段主要通过设置控制。现代程序也可能采用与本文简化流程不同的组织方式。

### 误区八：一帧只从管线入口走到出口一次

一个场景通常包含多次绘制，还可能生成中间图像、绘制阴影信息，再做后期处理。

## 15. 与光线追踪、游戏引擎是什么关系？

### 15.1 光栅化与光线追踪：从不同问题出发

可以用下面的方式建立初步区别：

| 方法 | 一个便于入门的核心提问 |
| --- | --- |
| 光栅化 | 这个三角形投到画面上，覆盖哪些位置？ |
| 光线追踪 | 从这个图像采样位置沿观察方向发出射线，会碰到什么表面？ |

光线追踪可以继续查询反射方向、通往光源的方向等，用来计算相关效果。但“找到交点”之后，仍然需要材质和着色规则才能得到外观。

实际渲染也可以组合不同方法，例如用光栅化处理主要可见表面，再用射线查询计算部分阴影或反射。

这部分只是帮助你安放名词。**你不需要先学会光线追踪，才能理解本文这条管线。**

### 15.2 为什么游戏引擎也会有自己的“渲染管线”？

“渲染管线”这个词，有时指本文讲的顶点、光栅化、片元等处理阶段，有时指引擎组织整帧工作的方式。

后者还会决定：

- 哪些物体先绘制。
- 生成哪些中间图像。
- 在哪一步计算光照。
- 怎样组织透明效果和后期处理。

以后你遇到“前向渲染”和“延迟渲染”，可以先理解成整帧工作的一些不同安排：前向渲染通常在绘制表面时计算光照；延迟渲染通常先存下表面信息，再用这些信息计算光照。

先理解本文的基础阶段，就更容易理解这些安排为什么不同。

## 16. 自测：不用计算，也能知道自己懂了没有

建议先自己回答，再展开答案。如果阅读器不支持折叠，答案会直接显示，不影响阅读。

### 题目一：三角形只有三个顶点，为什么能覆盖一大片屏幕？

<details>
<summary>查看答案</summary>

三个顶点确定三角形的边界。光栅化会找到边界内被覆盖的采样位置，并产生对应的片元。不是一个顶点只能画一个像素。

</details>

### 题目二：模型没动，只把相机绕到另一边，为什么画面变了？

<details>
<summary>查看答案</summary>

因为点相对于相机的位置发生了变化。观察变换随之改变，投影和后续屏幕位置也可能变化；原始模型不必修改。

</details>

### 题目三：片元着色器输出了红色，屏幕对应位置一定是红色吗？

<details>
<summary>查看答案</summary>

不一定。它可能被深度或其他测试排除，可能与已有颜色混合，也可能在之后的绘制或后期处理中发生变化。

</details>

### 题目四：相机不动、物体不动，只把纹理换掉，轮廓一定会变化吗？

<details>
<summary>查看答案</summary>

不一定。在本文简单的不透明贴图例子里，替换颜色纹理只会改变表面图案，几何轮廓不会因此改变。若纹理被用于控制顶点位移或丢弃片元，那是另外加入的规则。

</details>

### 题目五：一张纸有一半在画面外面，应该直接删除整张纸吗？

<details>
<summary>查看答案</summary>

不应该。裁剪保留范围内的部分。不能因为部分顶点越界，就把整个三角形一律丢弃。

</details>

### 题目六：在深度越小越近的约定下，已有深度为 0.2，新片元深度为 0.7。启用“小于才通过”时会怎样？

<details>
<summary>查看答案</summary>

新片元更远，不能通过深度测试，因此不替换这个位置已有的颜色和深度。

</details>

### 题目七：为什么 UV 只存在顶点上，也能给三角形内部贴上完整图案？

<details>
<summary>查看答案</summary>

通过插值得到内部位置的 UV，然后由着色器按 UV 采样纹理。实际通常使用适合透视的插值规则。

</details>

### 题目八：把一个普通光照 Shader 放到场景里，其他物体就会自动投下正确阴影吗？

<details>
<summary>查看答案</summary>

不会自动保证。表面朝向与光源遮挡是不同问题。阴影通常还需要额外的可见性信息及相应算法。

</details>

如果你能用自己的话解释第 1、2、3、6、7 题，就已经抓住了本文的大部分核心内容。

## 17. 最后一页：记忆卡与学习顺序

### 17.1 一张表复习整条管线

| 环节 | 输入的直观样子 | 要解决的问题 | 得到什么 |
| --- | --- | --- | --- |
| 场景准备 | 模型、纹理、材质、相机等 | 这次用什么数据、怎样画？ | 绘制命令和所需资源 |
| 顶点处理 | 模型上的点 | 点相对于场景和相机在哪里？ | 变换后的位置与顶点属性 |
| 装配、裁剪和屏幕映射 | 变换后的点和连接关系 | 哪些几何部分继续处理，落在图像哪里？ | 后续可光栅化的图元 |
| 光栅化与属性插值 | 三角形等图元 | 覆盖哪些位置，各处有什么属性？ | 片元及着色输入 |
| 片元着色 | 插值属性、纹理、材质、灯光等 | 表面在这里呈现什么？ | 颜色等输出 |
| 测试与混合 | 新结果、已有颜色和深度等 | 谁留下，怎样组合？ | 更新后的目标图像 |
| 后期与呈现 | 一张或多张图像 | 怎样完成这一帧并显示？ | 最终可见画面 |

仍要记得：这是一张职责表，某些测试可提前，实际管线也有可选阶段。

### 17.2 把名词翻译成人话

| 名词 | 第一次学习时这样记 |
| --- | --- |
| 顶点 Vertex | 带着位置等信息的点 |
| 网格 Mesh | 由点及连接关系组成的表面结构 |
| 变换 Transform | 改变摆放，或换一种参照描述位置 |
| 投影 Projection | 决定三维位置怎样参与形成二维画面 |
| 光栅化 Rasterization | 找到图元覆盖的采样位置 |
| 片元 Fragment | 某个图元对图像位置的一份候选数据 |
| 插值 Interpolation | 根据已知数据推算中间位置的数据 |
| UV | 纹理里的地址 |
| 法线 Normal | 表面朝向的小箭头 |
| Shader | 在 GPU 上执行指定处理的一类程序 |
| 深度缓冲 Depth Buffer | 保存各位置深度信息的存储 |
| 混合 Blending | 按规则组合新颜色和已有颜色 |
| 渲染目标 Render Target | 接收渲染结果的图像资源 |
| 帧 Frame | 连续画面中的一次图像结果 |

### 17.3 如果继续学，按这个顺序做小实验

不需要一开始就做完整游戏。下面每一步只引入一个主要概念：

1. **画一个纯色三角形。** 认识顶点输入、着色器与输出画面。
2. **让三个角使用不同颜色。** 观察三角形内部的插值过渡。
3. **移动、旋转这个三角形。** 体会位置变换与颜色计算的分工。
4. **给它贴一张格子图片。** 观察 UV 怎样控制图案。
5. **画两个相互遮挡的三角形。** 比较开启和关闭深度测试的差异。
6. **换成一个立方体，移动相机。** 理解观察变换、透视和正交投影。
7. **加入一盏简单的灯。** 观察法线方向怎样影响明暗。

当你能预测“改一个输入，会影响哪个阶段和哪种画面变化”，就比只背阶段名称更接近真正理解。

### 17.4 最终只记住这一段也可以

> 电脑先用顶点和三角形描述物体，把它们放进场景，再换成相机视角。经过投影、裁剪和屏幕映射，确定三角形在画面中的位置。光栅化找出它覆盖的采样位置，产生片元；片元着色器利用纹理、材质和光照等输入计算颜色。深度等测试与混合决定结果怎样写进图像。多次绘制和可能的后期处理共同完成一帧，最后提交显示。

**从头到尾，你都可以反复问四句话：在哪里？覆盖哪里？什么颜色？最后留下什么？**
