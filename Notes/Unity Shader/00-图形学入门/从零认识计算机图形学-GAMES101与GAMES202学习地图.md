## 1. 图形学究竟在研究什么？

想象你要在电脑里制作这样一个房间：

- 桌上有一只陶瓷杯和一颗金属球。
- 窗外的阳光照进来，杯子在桌上投下阴影。
- 红色墙壁让附近的白色物体稍微泛红。
- 一个角色伸手拿杯子，袖口跟着摆动。
- 相机向前移动，背景逐渐模糊。

这一个画面，已经包含了好几类独立的问题。

| 你想实现什么？ | 对应方向 | 用人话说 |
| --- | --- | --- |
| 杯子有杯口和把手 | 几何表示与建模 | 怎样在电脑里描述形状？ |
| 陶瓷和金属看起来不同 | 材质与着色 | 表面怎样与光发生作用？ |
| 看见杯子、阴影和反射 | 渲染与光传输 | 哪些光最终进入相机？ |
| 角色抬手拿杯子 | 动画 | 怎样安排形状和姿态随时间改变？ |
| 袖口自然晃动 | 物理模拟 | 怎样根据力和约束计算运动？ |
| 近处清楚、背景模糊 | 相机与成像 | 相机怎样把光记录成图像？ |
| 白色不发灰，亮部保留层次 | 颜色与显示 | 怎样把计算结果变成人能看懂的颜色？ |
| 转动视角时仍然流畅 | 实时渲染系统 | 怎样在有限时间里做完这些工作？ |

它们之间是一张关系网：

```text
几何：物体是什么形状？ ───────────┐
动画／模拟：这一刻是什么姿态？ ───┤
材质：表面怎样响应光？ ──────────┼─→ 渲染 ─→ 成像与颜色处理 ─→ 显示
光源：光从哪里来？ ─────────────┤
相机：从哪里观察？ ─────────────┘

数学、采样、算法、数据结构与硬件贯穿整个过程。
```

你已经读过的渲染管线，主要解释了这张图中“渲染”的一条基础实现路线。接下来要学习的是它的输入从哪里来，以及各个环节为什么这样计算。

**本节记住：形状、外观、运动、成像和效率，共同组成了图形学的主要问题。**

## 3. 数学工具：让“摆放、朝向、变化”可以计算

数学先从具体用途理解，不必一上来背一整本公式。

### 3.1 点、向量与法线

**点**表示一个位置，例如杯子中心；**向量**表示方向和大小，例如从杯子指向灯的箭头。同样写成三个数，它们的含义也可以不同。

向量的**归一化**，就是把长度变成 1，保留方向。这样比较朝向时，不会把“距离更远、箭头更长”误算成“朝得更正”。零向量没有确定方向，不能这样归一化。

**法线**是表示表面朝向的向量。杯子侧面的法线朝向侧面，杯底的法线朝向另一边。它是光照计算的重要输入。

### 3.2 点积与叉积

- **点积**可以帮助比较方向是否一致。对两个单位向量，它等于夹角的余弦：同向为 1，垂直为 0，反向为 -1。
- **叉积**可以得到同时垂直于两个输入向量的向量。拿三角形的两条边做叉积，可以求出垂直于三角形的方向；交换输入顺序，方向会反转。

不必今天就熟练手算。先知道：以后看到 `dot`，想想“在比较方向吗”；看到 `cross`，想想“在求垂直方向吗”。

### 3.3 矩阵与坐标空间

矩阵可以组织坐标变换。把杯子缩小、转向、放到桌上，以及换到相机视角，都能用相应的数学变换表达。

变换顺序通常有影响：先把物体移到远处再绕原点旋转，与先在原点旋转再平移，结果可能不同。模型、世界、观察空间，都是描述同一场景时使用的不同参照。

图形学常用四个分量的齐次坐标，把平移等操作统一写进矩阵计算。第一次知道这个用途即可，之后再追问投影里的 `w` 和透视除法。

### 3.4 其他数学在什么时候出现？

| 工具 | 直观用途 | 遇到它的地方 |
| --- | --- | --- |
| 插值 | 根据已知值计算中间值 | 三角形属性、关键帧、曲线 |
| 导数 | 描述变化速度 | 速度、曲面变化、优化 |
| 积分 | 把很多微小贡献加起来 | 光照、曝光、运动 |
| 概率与统计 | 用有限样本估计总体 | 路径追踪、降噪 |
| 数值方法 | 用有限步骤近似连续过程 | 布料、刚体、流体 |

**先掌握：** 点与向量、归一化、点积的方向意义、变换顺序。  
**以后深入：** 矩阵推导、法线的逆转置变换、积分与概率密度。  
**小实验：** 在纸上画一个不在原点的点，比较“先平移后旋转”和“先旋转后平移”。

## 4. 光栅化与采样：连续世界怎样进入像素格子？

这一节接续你原来的管线笔记。

光栅化把投影后的三角形转换为屏幕采样位置上的候选数据。深度测试再帮助判断谁挡住谁。这里有一个贯穿后续课程的问题：**真实或数学上的形状可以连续变化，电脑只能取有限次样本。**

想象用很稀疏的方格纸描一条斜线。有些格子中心落在线的一侧，有些落在另一侧，边缘就会形成台阶。把细密的条纹缩小，也可能出现原图没有的大条纹。这类现象叫**混叠**；锯齿只是其中一种表现。

“采样”可以先理解成：只在选定的位置或时刻获取信息。像素位置、纹理位置、时间、光线方向，都可以是采样对象。

改善结果通常需要合理地过滤和采样。可以多取一些样本，也可以在缩小前汇总细节，避免让一个样本冒充一大片区域。事后把所有东西弄模糊，会连真实细节一起损失。

| 名词 | 先这样理解 |
| --- | --- |
| 抗锯齿 | 减轻有限采样造成的不稳定和错误边缘 |
| SSAA，超采样抗锯齿 | 在更密的采样下渲染，再汇总到目标分辨率 |
| MSAA，多重采样抗锯齿 | 细化像素内的覆盖与深度采样，着色通常不按每个样本完整重做 |
| MipMap | 给纹理准备逐级缩小的版本，缩小时读取更合适的层级 |

注意：MSAA 主要改善几何边缘，对着色器内部的细碎闪烁不一定有效；MipMap 主要处理纹理缩小问题，也不等于通用的抗锯齿开关。

**先掌握：** 采样会丢失信息，几何复杂度与输出分辨率是不同的东西。  
**以后深入：** 频率、采样定理、重建滤波、透视校正插值。  
**小实验：** 把黑白棋盘图片不断缩小，观察它何时开始闪烁或出现花纹。

## 5. 着色与纹理：形状确定以后，表面为什么是这个颜色？

### 5.1 从白色球体理解光照

白色球体没有贴花纹，但放在灯下仍然有明暗。一个简单模型会根据表面朝向与光源方向的关系计算漫反射。

只看其中的方向因素，可以写成：

```text
方向带来的亮度系数 = max(0, dot(N, L))

N：单位表面法线
L：从表面指向光源的单位向量
dot：点积
max(0, ...)：把负数截成 0
```

表面朝着灯时系数较大，侧对灯时较小。这只是简化光照中的一个因素；完整结果还涉及光源强度、距离、材料和遮挡。

**漫反射**可以先理解为光向许多方向散开；**镜面反射**则更集中在某些方向，因此观察角度会明显影响高光。Blinn–Phong 是学习这种外观计算的经典简化模型，不必把它当成所有材质的物理定律。

### 5.2 为什么低多边形球也能显得平滑？

三角形本身是平的，但着色时可以使用平滑变化的顶点法线，经插值得到各处法线，再计算明暗。

这样能让内部的明暗连续，**却没有把几何轮廓变圆**。球的外边缘仍可能看出折角。

### 5.3 纹理是数据，不只是照片

UV 告诉着色器去纹理的哪个位置读数据。读到的内容可以是颜色，也可以是粗糙度、法线或其他参数。

| 纹理用途 | 改变什么 | 不应误认为 |
| --- | --- | --- |
| 基础颜色贴图 | 各处的基础颜色 | 已经包含所有照明结果 |
| 法线贴图 | 着色使用的局部朝向 | 通常不会直接改变网格轮廓 |
| 粗糙度贴图 | 各处反射的分散程度 | 单纯的一张亮度贴图 |
| 位移贴图 | 在相应实现下改变几何位置 | 与法线贴图完全相同 |

**先掌握：** 颜色、光照、法线和 UV 各负责什么。  
**以后深入：** 切线空间、各向异性过滤、材质模型的数学。  
**小实验：** 用同一个球体依次显示纯色、法线颜色、棋盘纹理和简单漫反射；每次只改变一项。

## 6. 几何：电脑可以用哪些方式描述形状？

### 6.1 网格只是其中一种

你已经知道三角形网格。它直接记录一些点和连接关系，适合许多绘制和编辑任务。但“一个球”还有别的表示办法。

| 表示 | 直观例子 | 优势与代价 |
| --- | --- | --- |
| 三角形网格 | 用小平片拼出球面 | 易绘制；光滑形状需要近似 |
| 隐式表面 | 用“到球心的距离等于半径”描述球面 | 某些内外判断方便；不能直接列出所有表面点 |
| 参数曲面 | 给两个参数，计算表面上的位置 | 适合有规则的光滑表面；复杂形状可能要拼接 |
| 点云 | 扫描得到一堆表面位置 | 容易记录采样；连接和表面不一定已知 |
| 体素 | 用三维小格子记录占据或属性 | 能描述体积；精细网格需要较多存储 |

“显式”和“隐式”可以这样区分：显式方法直接构造或列出表面；隐式方法给出判断位置是否在表面上的条件。上表是入门分类，实际系统还会组合多种表示。

### 6.2 曲线与曲面：怎样控制光滑形状？

贝塞尔曲线用一组控制点来影响曲线的走向，就像图像软件里的钢笔路径。控制点一般不要求全部位于曲线上。

它不只用于画轮廓，还能描述相机路径、运动轨迹。把类似想法扩展到两个参数，就能表示曲面。

### 6.3 网格处理：模型做出来之后还要处理什么？

- **细分：** 按规则增加网格元素，可以配合平滑规则改善形状。
- **简化：** 减少三角形，尽量保留重要轮廓和结构。
- **平滑：** 减轻噪声或局部不规则，也可能损失棱角和细节。
- **重网格化：** 重新安排顶点和连接，使网格更适合后续任务。

自动增加三角形，并不能凭空恢复原本不存在的雕刻细节。

**先掌握：** 一个形状可以有多种数据表示，选择取决于任务。  
**以后深入：** 曲面连续性、拓扑、细分规则与误差控制。  
**小实验：** 用“十二个三角形”和“一个三维占据数组”分别描述立方体，比较存储了什么。

## 7. 光线追踪：沿着一个方向，究竟会碰到什么？

光栅化从图元出发，寻找覆盖的位置。光线追踪提供另一种查询：**给定起点和方向，找到射线与场景的交点。**

### 7.1 用一根虚拟细线寻找表面

为了计算一个图像采样位置，可以从相机发出一条对应方向的射线：

```text
相机 → 图像采样位置对应的方向 → 最近交点 → 读取表面信息 → 计算外观
```

找到交点后，还可以发出其他射线。例如朝向光源查询遮挡，沿反射方向查询镜中的物体。实际实现要设置适当的射线区间和起点偏移，避免把表面自己误当成遮挡物。

“光线追踪”本身不保证完整模拟所有光照；查询哪些射线、怎样计算贡献，仍由具体算法决定。相关组成可对照 [PBRT 的光线追踪导论](https://pbr-book.org/4ed/Introduction/Photorealistic_Rendering_and_the_Ray-Tracing_Algorithm)。

### 7.2 场景很大时，为什么还能查得动？

如果每条射线都检查所有三角形，计算量会很大。可以把物体分组，为每组建立一个包围盒，再把盒子组织成树。

射线连一个大盒子都碰不到，就不必检查里面的所有三角形。这样的层级组织叫 **BVH，包围体层次结构**。盒子主要用于快速排除，最终仍需要精确求交；树的构建和场景变化后的更新也有成本。

**先掌握：** 射线查询回答相交和可见性问题，材质与光照决定颜色。  
**以后深入：** 射线与球／三角形求交、包围盒、BVH 构建与遍历。  
**小实验：** 在纸上画相机、两颗圆和一盏灯，用直线判断“相机看见谁”和“谁挡住灯”。

## 8. 光传输与路径追踪：一个表面收到的光从哪里来？

### 8.1 直接光与间接光

灯照到桌面，再进入相机，是一种直接照明路径。灯先照到红墙，红墙把一部分光反射到桌面，桌面再把光送向相机，就是间接照明。

```text
直接：灯 → 桌面 → 相机
间接：灯 → 红墙 → 桌面 → 相机
```

**全局光照（GI）** 考虑表面之间的光传递，尤其包括间接光。红墙附近的白色物体泛红，是一个直观例子。把所有暗处统一加亮，不能正确表达这种与位置、颜色和遮挡有关的传递。

### 8.2 辐射度量学：先说清“多少光”是什么意思

“这盏灯很亮”和“桌面很亮”不是同一种测量。辐射度量学用不同量描述光的能量传递：

| 名词 | 先抓住的区别 |
| --- | --- |
| 辐射通量／功率 | 每单位时间传递多少辐射能量 |
| 辐照度 Irradiance | 单位表面面积接收到多少辐射功率 |
| 辐射亮度 Radiance | 进一步区分方向，描述单位投影面积、单位立体角上的辐射功率 |

“立体角”衡量一片方向范围有多大，可以想象从一个位置看出去的小锥形视野。“投影面积”考虑表面对该方向呈现多大面积。

第一遍只记住：总量、每单位面积的量、还区分方向的量，不能混为一谈。上述是物理能量描述；考虑人眼敏感度的光度量又是另一套对应量。定义可查 [PBRT：辐射度量学](https://pbr-book.org/4ed/Radiometry,_Spectra,_and_Color/Radiometry)。

### 8.3 渲染方程先读成一句话

对常见的表面反射问题，可以先读成：

> 从表面朝观察方向离开的光，来自表面自身发出的光，以及各个入射方向经过材质和朝向加权后反射过来的光。

反射部分要汇总许多方向的贡献，因此会用到积分。入射光又可能来自其他表面的反射，所以整个场景会相互关联。

这句话还不是完整的所有光学现象模型。透射、参与介质等需要相应扩展。第一遍先理解为什么“只知道一个物体自己的颜色”不够。

### 8.4 为什么要用随机采样？

可能的光路太多，不能全部枚举。**路径追踪**通过采样光路来估计光传输；**蒙特卡洛积分**是用随机样本估计积分的数学工具。

可以类比调查平均身高：不用测遍所有人，但抽样方法和统计方式必须正确。不同概率抽到的样本，需要恰当加权，不能随便挑喜欢的结果取平均。

少量样本的估计会波动，在图像里形成噪点。增加样本通常能减轻噪声，但同一次增加不保证每个像素都更准确。对常见独立、有限方差的蒙特卡洛估计，典型误差量级随样本数平方根的倒数下降；想把误差减半，往往需要约四倍样本。参见 [PBRT：蒙特卡洛基础](https://pbr-book.org/4ed/Monte_Carlo_Integration/Monte_Carlo_Basics)。

### 8.5 高级光传输：怎样更容易找到重要的光路？

某些光路很难被普通采样碰到，例如光穿过玻璃后聚集到桌面，形成明亮的**焦散**。单纯增加样本可能很慢。

可以从相机和光源两端分别生成路径，再尝试连接，这是双向路径追踪的基本思路。光子映射则从光源追踪能量样本，再用它们估计表面附近的照明；Metropolis 光传输尝试在已有路径附近产生变化，让计算更集中于重要光路。

这些方法各有适用条件和估计上的权衡。第一遍认识“寻找有效光路也是一个算法问题”即可，不必立即实现。进一步阅读见 [PBRT 第三版：双向光传输方法](https://pbr-book.org/3ed-2018/Light_Transport_III_Bidirectional_Methods)。

**先掌握：** 间接光、对所有方向求和、用采样估计、噪声与样本数的关系。  
**以后深入：** 辐射度量学、概率密度、重要性采样、路径权重。  
**小实验：** 想象在相同白墙旁分别放红色和蓝色大纸板，预测墙面附近的间接光颜色。

## 9. 材质与复杂外观：真实世界为什么不只是“有颜色的表面”？

### 9.1 材质决定光往哪里去

一颗白色塑料球和一颗金属球可以有相似轮廓，却呈现不同外观。原因不只在基础颜色，还在反射怎样依赖入射方向、观察方向和波长。

**BRDF**描述表面反射的方向响应。先把它理解成一套规则：“光从这个方向进入时，表面会向那个方向反射多少。”它不是简单的单个反射百分比，也不是纹理图片的别名。

**BSDF**是更广的表面散射描述，可同时考虑反射与透射。

### 9.2 粗糙度到底改变了什么？

微表面理论把宏观表面看成许多极小表面的统计集合。微小表面朝向越分散，反射通常越分散，因此高光更宽、反射影像更模糊。粗糙度主要控制这种统计分布，而不是直接规定大块凹凸的高度。参见 [PBRT：微表面与粗糙度](https://pbr-book.org/4ed/Reflection_Models/Roughness_Using_Microfacet_Theory)。

### 9.3 光还可能进入内部

| 现象 | 日常例子 | 需要多考虑什么？ |
| --- | --- | --- |
| 折射与透射 | 玻璃杯里的物体看起来偏移 | 光穿过界面时改变方向 |
| 次表面散射 | 逆光的耳朵、蜡 | 光进入内部后，在别处离开 |
| 体积散射 | 雾中的光束 | 光在空间介质里散射和衰减 |
| 特殊方向结构 | 拉丝金属、头发、织物 | 细小结构让方向响应不同 |

因此，有些外观问题不能只靠给普通表面换张贴图解决。

**先掌握：** 材质是一套光学响应，复杂外观可能来自物体内部或空间介质。  
**以后深入：** 菲涅耳效应、能量守恒、微表面分布、体积传输。  
**小实验：** 观察同一扇窗在玻璃、磨砂玻璃和金属上的反射，比较清晰度与观察角度的影响。

## 10. 相机、光场与颜色：光算出来以后，还要怎样变成照片？

### 10.1 相机不只是一个位置

简单针孔相机决定投影方向。加入镜头与有限光圈，就要考虑聚焦和景深；加入曝光时间，就要考虑运动模糊。

| 设置或概念 | 主要影响 |
| --- | --- |
| 视野角 | 画面能容纳多大范围 |
| 对焦距离 | 哪个距离附近最清晰 |
| 光圈 | 进光与景深；还受其他条件影响 |
| 曝光时间 | 累积光的时间，以及运动模糊 |

一张照片可以汇总一个小时间段内、穿过镜头不同位置的光，因此成像也包含采样和积分。相机不是必须模仿真实器材，但物理相机模型能解释这些现象。参见 [GAMES101 第 19 讲：相机与光场](https://sites.cs.ucsb.edu/~lingqi/teaching/resources/GAMES101_Lecture_19.pdf)。

### 10.2 光场：除了颜色，还关心光往哪里走

普通照片把观察条件固定，记录二维位置上的图像。光场进一步描述光在不同位置、不同方向上的分布。在一定条件下，掌握这些信息可以支持改变视点或重新对焦。

第一次记住“位置和方向都重要”就够了，不需要马上理解高维参数化。

### 10.3 RGB、线性计算与显示

光的物理分布和人对颜色的感觉不是同一个概念。RGB 是一种颜色表示，需要具体的色彩空间来解释；三个数字不是完整的光谱。

常见图像里的 sRGB 数值带有非线性编码。物理光照的相加、平均等运算通常应在适当的线性空间中进行，再编码供显示。简单地把编码数值加起来，可能得到不符合预期的明暗。颜色表示与感知基础可参见 [PBRT：颜色](https://pbr-book.org/4ed/Radiometry,_Spectra,_and_Color/Color)。

**HDR**表示可以保留较大亮度范围；**色调映射**把这些亮度组织到目标显示范围。曝光、色调映射和颜色编码职责不同，不应都笼统叫“调亮”。

**先掌握：** 相机影响成像，颜色还需要正确的表示和显示过程。  
**以后深入：** 薄透镜、光谱、色域、颜色空间和色调映射。  
**小实验：** 用手机分别对焦近处和远处，观察清晰区域变化；再想想它与移动相机有什么不同。

## 11. 动画与模拟：怎样让虚拟世界动起来？

### 11.1 动画先解决“下一刻是什么样”

一段动画可以看成：随时间变化的场景状态。渲染器拿到某一时刻的状态，再生成画面。

**关键帧动画**让创作者指定重要时刻的状态，再用插值补出中间过程。例如第 0 秒手在桌边，第 1 秒手到杯子旁。插值曲线会影响动作是匀速、先慢后快，还是逐渐停下。

旋转的插值比位置复杂，后续会接触四元数等工具。现在不必背公式。

### 11.2 骨骼与蒙皮：骨头怎么带动皮肤？

角色通常由层级连接的骨骼控制。肩膀、上臂、前臂、手构成一条关系链。**蒙皮**让网格顶点根据骨骼变换和权重发生变形。

- **正向运动学（FK）：** 给定关节姿态，计算手最终在哪里。
- **逆向运动学（IK）：** 给定手想去的位置，寻找合适的关节姿态。

目标位置不一定可达，也可能对应多组姿态。这里的骨骼和蒙皮用于补充动画概念，后续可作为专门方向深入。

### 11.3 模拟：让规则决定怎么动

如果每一帧都手工摆布料，非常费力。模拟会定义质量、力、约束和初始状态，再计算运动。

例如把布料近似成一些质点和连接它们的弹簧：重力拉动质点，弹簧抵抗过度拉伸，碰撞处理阻止它穿过桌子。这是学习模型，并不意味着真实布料就是这种结构，也不代表所有布料算法都这样实现。

连续运动需要用有限时间步计算。步长过大或求解方法不合适，可能出现抖动、穿透甚至数值发散。因此物理模拟既研究物理规律，也研究怎样稳定地近似计算。

| 模拟对象 | 主要关心 |
| --- | --- |
| 刚体 | 平移、旋转、碰撞，通常不考虑形变 |
| 弹性物体与布料 | 拉伸、弯曲、恢复、碰撞 |
| 流体 | 速度、压力、流动及边界 |
| 粒子系统 | 大量小元素的运动和生命周期，可物理也可艺术控制 |

**先掌握：** 动画控制目标状态，模拟根据规则求运动，两者可以结合。  
**以后深入：** 四元数、IK、蒙皮、微分方程与数值稳定性。  
**小实验：** 分别描述“手动安排球的弹跳曲线”和“给定重力、碰撞规则计算弹跳”，比较谁更易控制、谁更容易响应场景变化。

## 12. 进入 GAMES202：同样的画面，怎样及时算完？

到这里，你已经知道一张画面依赖哪些信息。GAMES202 进一步提出时间约束。

以每秒 60 帧为例，平均每帧的间隔约为 `1000 ÷ 60 ≈ 16.7` 毫秒。几何、光照、阴影、后期处理等要共享有限的计算资源。CPU 和 GPU 可以重叠工作，但每一帧仍不能无限增加成本。

实时与离线描述的是时间和交互要求，不是两种固定算法：离线可以用光栅化，实时也可以用光线追踪。实际系统常组合多种方法。

接下来会反复遇到五种做法：

| 做法 | 生活类比 | 在渲染中的样子 |
| --- | --- | --- |
| 提前计算 | 做好备菜 | 预计算光照、查找表 |
| 近似表示 | 用简图代替全部细节 | 体素、低阶方向函数 |
| 只算必要部分 | 只整理今天要用的东西 | 剔除、灯光分组、按需采样 |
| 重用已有结果 | 接着昨天的进度做 | 屏幕空间效果、时间累积 |
| 从少量数据重建 | 根据有限测量估计整体 | 降噪、升采样 |

这些做法都需要问：**省掉了什么工作？失去了什么信息？什么时候会露出问题？**

理解这三个问题，比第一遍背下所有算法缩写更重要。

## 13. 实时阴影：怎样知道光被挡住了？

### 13.1 阴影图：先站到灯的位置看一次

可以先从光源视角渲染深度，保存各方向最近的表面，得到 **Shadow Map，阴影图**。正式绘制相机画面时，把待着色的位置变换到光源视角，再比较深度。

如果它比阴影图记录的最近表面更远，就说明前面可能有东西挡住灯。这里以深度越小越近为说明约定；具体系统的深度约定和比较方式可以不同。

为什么可能出现锯齿、条纹或阴影与物体分离？因为阴影图分辨率有限，深度也有误差。常用的深度偏移能缓解自遮挡条纹，但偏移过大又会导致阴影脱离接触处。

### 13.2 软阴影：光源不是一个数学点

面光源有面积。同一个位置可能只能看见光源的一部分，于是既不是完全照亮，也不是完全被挡，形成半影。

用手挡住较大的灯，在常见几何关系下，把手从墙面向灯靠近，影子往往会变软。软硬程度还取决于光源大小和整体位置关系。

| 方法 | 直观想法 | 主要限制 |
| --- | --- | --- |
| PCF | 对邻近位置分别做阴影深度比较，再平均比较结果 | 滤波范围并不自动等于物理半影宽度 |
| PCSS | 先估计遮挡物距离，再估计半影宽度，调整 PCF 范围 | 多次采样有成本，也可能有噪声与误差 |
| VSSM | 保存深度统计量，用统计估计帮助计算可变范围的软阴影 | 近似可能造成漏光等问题 |
| Moment Shadow Maps | 用更多深度矩信息估计可见性 | 存储、精度和近似效果需要权衡 |
| SDF 阴影 | 用到表面的距离信息辅助追踪与软阴影近似 | 依赖距离场质量、分辨率及更新方式 |

PCF 平均的是**比较后的可见性结果**，不是先把深度随意平均再做一次比较。PCSS 的核心步骤见 [NVIDIA：Percentage-Closer Soft Shadows](https://developer.download.nvidia.com/shaderlibrary/docs/shadow_PCSS.pdf)；统计方法可参见 [VSSM 原论文](https://jankautz.com/publications/VSSM_PG2010.pdf)。

**SDF，有符号距离场**，在理想定义中为位置记录到最近表面的距离，并用符号区分内外。利用距离信息可以安排前进步长；具体软阴影估计仍是算法近似。例子见 [Epic：距离场阴影](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-distance-field-shadows-in-unreal-engine)。

**先掌握：** 阴影属于光源可见性；软阴影来自有限大小光源的部分遮挡。  
**以后深入：** PCSS、矩方法、距离场追踪的推导与偏差处理。  
**小实验：** 改变真实灯的发光面积和手到墙的距离，分别观察影子软硬；不要一次改变所有条件。

## 14. 环境光照与预计算：整片天空也会照亮物体

### 14.1 环境光照不等于给所有东西加一个常量

金属球会反映周围窗户、天花板和墙壁的样子。周围不同方向的光可以用**环境贴图**表示，例如将方向映射到立方体的六张图。

每个方向的亮度和颜色可以不同。粗糙表面会汇总更宽范围的方向，光滑表面会保留更清晰的反射。

环境贴图通常把光照近似为来自远方，或在有限位置采样后用于附近区域。只用一张图，不会自动正确表现所有近处物体的遮挡、视差和动态变化。

### 14.2 预过滤与 Split Sum

如果每个像素都去汇总环境各方向的光，代价很高。可以预先制作适合不同粗糙度的环境贴图结果，渲染时查找。

**Split Sum**进一步把相关积分近似拆成便于预计算和查表的部分。先理解“把每个像素都要做的复杂汇总，改成提前计算加少量查询”，以后再学它的近似假设。经典实现背景见 [Epic：Real Shading in Unreal Engine 4](https://cdn2.unrealengine.com/Resources/files/2013SiggraphPresentationsNotes-26915738.pdf)。

### 14.3 PRT：提前记录物体如何传递光

**PRT，预计算辐射传输**，可以先针对固定几何，计算光照在遮挡与反射作用下的传递关系，再在运行时与光照表示组合。

它不是简单存下一张永远不变的最终照片。某些方法允许环境光照变化，但几何一旦发生不支持的变形，旧的传输关系就可能失效。经典低频方法使用**球谐函数**：先把它理解为用少量系数近似表示平缓变化的方向分布。参见 [Microsoft Research：PRT 原论文介绍](https://www.microsoft.com/en-us/research/publication/precomputed-radiance-transfer-real-time-rendering-dynamic-low-frequency-lighting-environments/)。

**先掌握：** 环境光照有方向，预计算用提前做的工作减少运行时计算。  
**以后深入：** 球谐展开、预过滤、Split Sum 的近似条件。  
**小实验：** 想象把镜面金属球从室外搬进房间。模型和材质都不变，反射内容为什么大变？

## 15. 实时全局光照：怎样便宜地估计反弹光？

GAMES101 让你理解间接光和路径追踪。GAMES202 会介绍不同的近似路线。它们不是必须全开的一串画质选项。

### 15.1 路线一：在三维场景里保存粗略信息

| 方法 | 核心想法 | 容易出现的问题 |
| --- | --- | --- |
| RSM，反射阴影图 | 从光源视角记录被照表面的信息，用它们近似间接光贡献 | 采样和额外可见性处理有限，信息也不完整 |
| LPV，光传播体积 | 在三维网格中记录方向光照，并向邻近格子传播 | 分辨率和传播近似会模糊细节或漏光 |
| 体素锥追踪／VXGI 相关路线 | 把场景体素化并建立层级，用具有一定宽度的查询汇总光照 | 占用存储，更新和查询有成本，粗表示可能漏光 |

RSM 可把受光的表面样本视为虚拟的次级光源，但并不意味着物体突然成为真正的自发光灯。它是一种计算近似。参见 [RSM 原论文](https://users.soe.ucsc.edu/~pang/160/s13/proposal/mijallen/proposal/media/p203-dachsbacher.pdf)。

LPV 用空间网格和紧凑的方向表示换取效率，概念可对照 [Light Propagation Volumes 讲义](https://advances.realtimerendering.com/s2009/Light_Propagation_Volumes.pdf)。体素锥追踪通过预过滤层级汇总较宽区域，而不是逐个命中原始三角形，参见 [NVIDIA 的体素锥追踪论文页面](https://research.nvidia.com/labs/rtr/publication/crassin2011givoxels/)。

### 15.2 路线二：利用已经画出的屏幕数据

“屏幕空间”可以先理解成：主要利用当前相机图像及配套的深度、法线等信息完成计算。

| 方法 | 想补充什么效果？ | 第一遍要知道的限制 |
| --- | --- | --- |
| SSAO，屏幕空间环境遮蔽 | 根据附近深度估计局部被遮挡程度，增强接触与缝隙的暗部 | 不是完整的光反弹计算 |
| SSDO，屏幕空间方向遮蔽 | 进一步保留方向关系，并可近似一部分间接光 | 仍然依赖有限的屏幕信息 |
| SSR，屏幕空间反射 | 在屏幕深度等数据中寻找反射方向对应的可见表面 | 画面外、被遮住的表面通常缺失 |

例如金属球本来应该反射身后的门，但门不在当前相机图像里。单靠当前屏幕数据，无法还原它的真实形状和颜色。引擎可以加入历史信息、探针或其他回退方法补充，但这已经是在组合额外来源。SSR 的画面外限制也可见 [EA 对实时反射的说明](https://www.ea.com/amp/news/battlefield-5-real-time-ray-tracing)。

### 15.3 为什么要了解这些可能不够准确的方法？

因为它们展示了重要的系统思路：已有一部分信息时，能用多少成本得到多大改善？失败时，是算法没调好，还是输入里根本没有所需信息？

**先掌握：** 三维方法保存场景信息，屏幕空间方法重用相机已有信息；两者都有缺失。  
**以后深入：** 体素层级、方向表示、屏幕空间追踪、漏光和回退策略。  
**小实验：** 在纸上画一个镜面和镜外的物体，只给自己一张相机照片，判断哪些反射信息能从照片推出。

## 16. 高质量着色：让材料可信，也让计算可控

### 16.1 PBR 是一套约束和建模思路

**PBR，基于物理的渲染**，强调用物理上合理的模型组织材质与光照。例如普通非发光表面不能凭空创造反射能量，反射会随观察角度改变。

物理合理不等于所有过程都精确模拟。实时系统仍然需要近似。模型、灯光、曝光和资源设置也都会影响最终画面。

GAMES202 会进一步讨论微表面模型和 GGX。**GGX**可以先看成描述微表面朝向分布的一种模型；完整微表面反射还需要考虑菲涅耳反射，以及微表面之间的遮挡等因素。

### 16.2 为什么还要考虑微表面之间的多次反射？

如果模型只计算一次微表面反射，会漏掉部分在微表面间继续反弹后离开的能量。一些多次散射近似尝试补偿这部分损失。

这里的“多次反射”发生在材质的微观模型里；前面讲房间墙壁之间的全局光照，发生在场景尺度。两个层次有关联，但不是同一段计算。微表面基础参见前文的 [PBRT 微表面章节](https://pbr-book.org/4ed/Reflection_Models/Roughness_Using_Microfacet_Theory)。

### 16.3 Disney、LTC 与 NPR 各在做什么？

| 名词 | 所处层次 | 直观解释 |
| --- | --- | --- |
| Disney Principled BRDF | 材质模型 | 用便于创作者理解的参数控制较丰富的外观 |
| LTC | 光照积分方法 | 用容易积分的分布近似复杂响应，加速面光源计算 |
| NPR，非真实感渲染 | 表达目标与方法集合 | 按卡通、水墨、插画等目标组织画面 |

Disney 模型的目标和设计背景见 [Disney 官方论文页面](https://www.disneyanimation.com/publications/physically-based-shading-at-disney/)。LTC 面光源方法见 [Real-Time Area Lighting](https://blog.selfshadow.com/publications/s2016-advances/)。

NPR 也会用到几何、深度、法线和光照，只是强调不同的视觉表达。例如把连续明暗分成几档，可以产生卡通色块；描边还要考虑轮廓提取与遮挡。

**先掌握：** 材质模型、求解方法和艺术目标是不同层次。  
**以后深入：** GGX、菲涅耳、能量补偿、LTC 和风格化表达。  
**小实验：** 让同一颗球分别呈现平滑明暗和三段明暗，观察几何不变时风格如何改变。

## 17. 实时光线追踪与降噪：只算少量光线，怎样得到稳定画面？

### 17.1 真正的困难不只在“射线能不能碰到物体”

硬件加速可以让某些射线查询更快，但每个像素追踪很多光路仍有成本。实时系统可能只计算少量样本，再结合其他信息重建较稳定的结果。

所以实时光追还需要采样、历史复用、降噪、材质处理和场景更新。并不是打开某个硬件功能，就自动得到没有误差的照片。

### 17.2 时间累积：借用前几帧

如果相邻帧看到的是同一块稳定表面，前几帧的样本可能继续有用。但相机和物体会移动，不能直接混合同一个屏幕位置。

- **运动向量：** 帮助描述表面在帧与帧之间的屏幕位移。
- **重投影：** 找到当前样本在历史画面中的对应位置。
- **时间累积：** 合并当前与有效历史样本，降低波动。

如果杯子移开，露出以前被挡住的桌面，那里就没有可直接使用的对应历史。这叫**去遮挡／新显露区域**。光照、材质变化也可能让历史失效。盲目累积会出现拖影。

### 17.3 空间降噪：邻居能帮忙，但不能随便混

把附近像素平均可以减轻噪声，却可能把杯子颜色抹到墙上。因此降噪会参考深度、法线等特征，尽量只混合相关表面的样本。

**联合双边滤波**可借助引导信息保持边缘；**SVGF**结合时间信息、方差估计和空间过滤；**RAE**在课程语境中指利用循环降噪自动编码器处理图像序列的学习方法。它们都需要面对细节、噪声和稳定性之间的取舍。

SVGF 的总体思路可对照 [NVIDIA 的 SVGF 论文页面](https://research.nvidia.com/publication/2017-07_spatiotemporal-variance-guided-filtering-real-time-reconstruction-path-traced)，RAE 见 [NVIDIA 的循环降噪自动编码器论文页面](https://research.nvidia.com/publication/2017-07_interactive-reconstruction-monte-carlo-image-sequences-using-recurrent)。降噪是在有限信息下估计结果，可能引入偏差，并不能保证恢复所有未采到的细节。

**先掌握：** 少量样本会有噪声，历史需要对齐且可能失效，滤波应尽量保持边缘。  
**以后深入：** 历史验证、方差估计、时空滤波和学习式重建。  
**小实验：** 用两张纸分别画移动前后的杯子，直接半透明叠在一起，再比较“先对齐杯子后叠加”的差别；观察新露出的背景仍有什么问题。

## 18. 抗锯齿、超采样与渲染组织：把一整帧安排好

### 18.1 TAA 与升采样：时间还可以帮助恢复画面

**TAA，时间抗锯齿**，通常让采样位置随帧轻微变化，再把当前与有效历史样本组合，以改善边缘和闪烁。它也会遇到历史失效、拖影和细节变软的问题。

**升采样**把较低分辨率的结果重建到较高分辨率。它可以利用邻域、运动和历史信息，具体方法不同。升采样与 SSAA 不同：SSAA 通常先多算再缩小，升采样通常从较少的当前图像样本重建较大输出。“超分辨率”“超采样”等产品用词可能重叠，学习时要看实际数据流。

### 18.2 前向、延迟与分块：灯多了怎么办？

| 组织方式 | 直观做法 | 常见权衡 |
| --- | --- | --- |
| 前向渲染 | 绘制表面时计算光照 | 思路直接；许多灯可能增加每次着色成本 |
| 延迟渲染 | 先保存表面信息，再集中计算光照 | 便于组织许多灯；增加缓冲读写，透明等需另外处理 |
| Tiled／Clustered | 把屏幕或视锥分区，为区域筛选相关灯 | 减少无关灯计算，也需要建立和维护列表 |

延迟渲染常用的 **G-buffer** 保存深度、法线、材质参数等表面信息，具体布局由系统决定。分块和聚类是一类灯光筛选策略，可以与不同渲染路径结合，不能简单当成互斥的三选一。

课程末尾还涉及级联思路、粒子和引擎等。以常见的级联阴影为例，可以为相机近处和远处分配不同的阴影覆盖与精度，让有限分辨率用得更合适。

### 18.3 研究一个算法，还要研究它在整帧中的位置

需要多少张中间图像？什么时候可重用？消耗计算多，还是图像读写多？瓶颈在 CPU 还是 GPU？

“少了几行代码”不保证更快，“多一个 Pass”也不能单独判定一定更慢。必须结合实际输入、硬件与测量理解成本。

**先掌握：** 一帧由多个环节组成，性能是整体安排的结果。  
**以后深入：** G-buffer、灯光列表、GPU 时间测量、内存带宽与资源管理。  
**小实验：** 假设房间有一百盏灯，其中九十盏照不到杯子，想想怎样避免杯子的每个像素都检查全部灯。

## 19. 把所有知识放回同一个房间

现在再看开头的场景，可以把一次制作与运行过程拆开。

### 19.1 制作资源时

1. 用曲面或网格制作杯子、桌子和角色，按需要简化模型。
2. 为表面安排 UV、法线、颜色与粗糙度等信息。
3. 给角色建立骨骼与蒙皮，制作动作或设置控制方式。
4. 配置灯光、相机，选择需要的预计算数据。

### 19.2 运行到这一帧时

1. 根据输入、动画和模拟，更新角色、布料、杯子与相机。
2. 找出需要处理的场景部分，准备绘制和计算任务。
3. 生成必要的阴影、场景或表面信息。
4. 根据所选渲染方法确定可见表面，计算直接光和间接光。
5. 按需要追踪反射或其他射线，使用降噪和历史信息。
6. 处理透明、后期效果、抗锯齿与颜色显示。
7. 提交画面，再准备下一帧。

这是示意性的任务关系，实际系统的阶段顺序会调整、交错或合并。

### 19.3 出问题时，先判断属于哪一类

| 画面问题 | 优先检查的方向 |
| --- | --- |
| 杯子形状或位置不对 | 几何、变换、坐标空间 |
| 花纹被拉伸或接缝异常 | UV、插值、纹理采样 |
| 陶瓷看起来像塑料或金属 | 材质、法线、环境光照、曝光 |
| 手够不到杯子或关节姿态怪 | 动画控制、IK、骨骼约束 |
| 袖口穿过桌子 | 碰撞、模拟步长、约束求解 |
| 阴影有条纹或脱离物体 | 阴影分辨率、精度、偏移 |
| 转动相机时反射突然消失 | 屏幕空间数据缺失、回退方式 |
| 运动时拖影 | 历史重投影与有效性判断 |
| 所有颜色都发灰 | 光照、曝光、色调映射、颜色编码 |
| 静止漂亮，运行很卡 | CPU／GPU 成本与整帧组织 |

这张表是排查入口，不是仅凭一个症状就能确定原因的诊断表。

## 20. 两门课之外，图形学还有哪些方向？

你希望了解整个领域，因此要知道地图的边界。下面是扩展方向，不冒充这两门课已经完整覆盖的课程内容，也不是必须继续学习的清单。

| 扩展方向 | 研究问题 | 与前文的连接 |
| --- | --- | --- |
| 几何处理与数字制造 | 怎样修复、变形、参数化形状，让它适合加工或打印？ | 网格、曲面、优化 |
| 角色动画与运动生成 | 怎样得到自然、可控、会响应环境的动作？ | 插值、运动学、模拟 |
| 高级物理模拟 | 怎样稳定模拟复杂布料、软体、液体和烟？ | 数值方法、碰撞、连续介质 |
| 计算成像 | 能否联合设计相机、采样方式和算法？ | 镜头、光场、重建 |
| 逆向渲染与三维重建 | 已知照片，怎样反推形状、材质、照明或相机？ | 把生成图像的过程反过来求解 |
| 可微渲染 | 怎样计算画面变化对场景参数的敏感程度？ | 渲染、导数、优化 |
| 神经渲染与新视角合成 | 怎样借助学习方法表示场景或生成新视角？ | 表示、采样、成像、重建 |
| 科学可视化 | 怎样把体数据、流场等复杂数据变得可理解？ | 几何、体绘制、颜色与感知 |
| 交互图形与 XR | 怎样在交互和头部运动下提供稳定视觉体验？ | 相机、立体视觉、实时性 |
| 图形系统与 GPU | 怎样高效组织数据、任务和硬件资源？ | 管线、并行计算、性能分析 |

这里有些方向与计算机视觉、机器学习、人机交互、应用数学相交，学科边界并不严格。

举两个经常听到的例子：**NeRF**的原始方法用神经网络表示空间位置和观察方向对应的密度与辐射信息；**3D Gaussian Splatting**的代表方法使用可优化的三维高斯表示场景，并支持高效的新视角绘制。它们都让“场景只能是三角形网格”的想法变得不够完整，但也不自动提供方便编辑的网格、独立材质或正确重照明。参见 [NeRF 作者项目页](https://www.matthewtancik.com/nerf)与 [3D Gaussian Splatting 官方实现](https://github.com/graphdeco-inria/gaussian-splatting)。

第一遍只要能把新名词放回一个问题：它是在描述形状、求光照、生成运动、恢复场景，还是提高效率？

## 21. 给零基础读者的实际学习路线

### 21.1 第一轮：把全貌看完

先用本导读理解所有分支，再按 GAMES101 的顺序认识各个主题。遇到数学细节可以标记，但不要因此永远停在矩阵这一关。

每个主题只写三句话：

```text
这个主题要解决：________。
它大致使用 ________，得到 ________。
它的主要限制是：________。
```

例如：

> SSR 要补充反射。它主要使用当前屏幕的深度与颜色等数据寻找反射内容。画面外或被遮住的表面信息不足，因此需要其他方法补充。

能写出这样的解释，就可以先进入下一节，不必马上实现 SSR。

### 21.2 第二轮：跟随 GAMES101 建立可操作的基础

以下是本导读建议的小练习，不是对官方作业编号的复述。不会编程时可先做纸笔和观察实验；开始实现时，再跟随课程提供的框架补语言与调试基础。

| 阶段 | 对应课程 | 可以做的最小练习 | 进入下一阶段的标志 |
| --- | --- | --- | --- |
| A：位置与画面 | 101 第 2～6 讲 | 三角形变换、遮挡、简单采样 | 能预测移动相机与物体的差别 |
| B：表面外观 | 101 第 7～9 讲 | 显示 UV、贴棋盘格、球体漫反射 | 能区分几何、纹理、法线与光照 |
| C：形状表示 | 101 第 10～12 讲 | 画贝塞尔曲线，比较网格粗细 | 知道同一形状可以怎样表示 |
| D：光路与反弹 | 101 第 13～18 讲 | 球体射线求交；之后运行小场景路径追踪 | 能解释交点、间接光与噪声 |
| E：成像与颜色 | 101 第 19～20 讲 | 观察景深，比较曝光与颜色处理 | 知道画面不是单纯的 RGB 相加 |
| F：时间与运动 | 101 第 21～22 讲 | 关键帧移动与简单弹簧运动 | 能区分动画控制和动力学模拟 |

每一阶段都采用“先预测 → 再观察 → 解释差异”的方式。仅仅运行出结果，还不等于理解了它为什么正确。

### 21.3 什么程度适合认真进入 GAMES202？

试着检查下面几项：

- 能解释模型、世界、观察空间，以及法线和光照方向为什么需要统一空间。
- 能解释光栅化、深度测试、纹理采样、渲染目标与多次绘制。
- 能区分直接光、间接光、材质响应与光源遮挡。
- 能把渲染方程读成“对方向贡献的加权汇总”。
- 能解释随机采样为何会产生噪声，以及历史为什么可能失效。
- 至少能阅读简单着色或计算代码，并具备逐步补微积分和概率的能力。

不要求先精通所有动画与几何算法，才能读 GAMES202；但为了你的“系统了解”目标，建议至少完成 101 全部主题的概念通读。

### 21.4 第三轮：沿 GAMES202 深入实时渲染

建议按“问题—基础方法—改进方法—失效场景”学习：

1. **阴影：** 阴影图 → PCF → PCSS → 了解统计与距离场方法。
2. **环境光照：** 环境贴图 → 粗糙度与预过滤 → 了解 Split Sum 和 PRT。
3. **全局光照：** 先比较三维信息和屏幕信息，再各挑一种方法深入。
4. **材质：** 微表面基本项 → GGX → 多次散射、Disney、面光源和风格化分支。
5. **实时光追：** 低样本噪声 → 重投影 → 时间累积 → 空间降噪与历史验证。
6. **整帧组织：** 抗锯齿与重建 → 灯光分区 → 渲染路径 → 测量性能。

第一遍不要把实现所有方法设成硬性目标。更合理的进度标志是：能比较两种方法的输入、输出、成本和失败情况，再选择一个实现。

### 21.5 你现在的下一步

你已有一篇直观的管线笔记，可以从 **GAMES101 第 2～4 讲对应的向量与变换**开始补基础，再接第 5～9 讲的采样、着色与纹理。之后继续完整看几何、光传输、成像和动画，建立全貌。

下一篇适合写成详细笔记的题目是：

> **《从零理解点、向量、法线与坐标空间》**

其中只解决四个问题：位置和方向有什么区别；法线为什么能帮助算明暗；点积在比较什么；同一个点为什么会有不同空间下的坐标。

### 22.2 参考答案

| 题号  | 核心解释                                    |
| --- | --------------------------------------- |
| 1   | 形状与光学响应可以分别定义，改材质即可改变许多外观特征。            |
| 2   | 一个改变观察条件，一个改变物体的场景变换；某个局部画面相似不代表场景状态相同。 |
| 3   | 插值法线改变着色朝向，没有增加或移动构成轮廓的几何。              |
| 4   | 前者主要改变着色法线，后者在相应实现下改变位置。                |
| 5   | 不决定；确定可见表面的方法与材质响应是不同层次。                |
| 6   | 还需要材质、光源、遮挡和可能的间接光等信息。                  |
| 7   | 红墙反射的光照到白色物体，形成带颜色的间接照明。                |
| 8   | 不一定，有限随机样本本来就会产生估计波动。                   |
| 9   | 常量缺少方向、位置、遮挡和表面之间的颜色传递。                 |
| 10  | 部分位置只看得到光源的一部分，半影范围随几何关系变化。             |
| 11  | 当前屏幕数据通常没有记录那些表面，需要额外信息补充。              |
| 12  | 不能，它主要估计局部遮蔽，不是完整的光传输求解。                |
| 13  | 数据是在一定假设下提前算好的，条件变了，数据可能不再适用。           |
| 14  | 同一屏幕位置可能已属于别的表面，原表面光照也可能变化。             |
| 15  | 可能损失边缘、纹理和细小高光，还可能混合不相干的表面。             |
| 16  | IK；FK 是已知关节状态计算末端位置。                    |
| 17  | 不一定，离散时间步、数值求解、碰撞和约束处理都会影响稳定性。          |
| 18  | 都不是必须；实时与离线是要求，光栅化与光追是方法。               |
| 19  | 不等于，202 主要深入实时渲染，其他方向仍有独立体系。            |
| 20  | 它解决什么问题，需要什么信息，省了什么工作，又可能失去什么？          |

能解释大部分题目的因果关系，说明你已经建立了概念地图；它不代表已掌握所有公式或实现。

## 23. 术语速查与继续阅读

### 23.1 基础与场景

| 术语                | 先记住的意思              |
| ----------------- | ------------------- |
| Geometry／几何       | 形状及其空间关系            |
| Mesh／网格           | 顶点和连接关系组织的表面        |
| Normal／法线         | 表面朝向的表示             |
| UV                | 纹理查找坐标              |
| Texture／纹理        | 可按坐标访问的图像或其他数据      |
| Material／材质       | 组织表面响应和参数           |
| Shader／着色器        | 执行指定图形计算的程序，不只用于涂颜色 |
| Rasterization／光栅化 | 从图元找到覆盖的采样位置        |
| Sampling／采样       | 在有限位置、时刻或方向获取信息     |
| Aliasing／混叠       | 采样不足等因素造成的错误模式      |
| Skinning／蒙皮       | 让网格顶点随骨骼等控制信息变形     |
| Simulation／模拟     | 根据规则与状态近似计算变化       |

### 23.2 光照与实时渲染

| 术语 | 先记住的意思 |
| --- | --- |
| Ray Tracing／光线追踪 | 查询射线与场景的相交，并用于渲染计算 |
| BVH | 用层级包围体排除不必检查的对象 |
| Path Tracing／路径追踪 | 通过采样光路估计光传输的一类方法 |
| GI／全局光照 | 考虑场景中表面之间的光传递，尤其是间接光 |
| BRDF | 表面反射如何依赖入射和出射方向 |
| PBR | 用物理上合理的模型和约束组织渲染 |
| IBL／基于图像的照明 | 用环境图像等信息提供照明 |
| PRT | 提前计算光照传递关系，运行时组合使用 |
| Shadow Map | 从光源视角记录的深度信息 |
| SDF | 位置到最近表面的有符号距离 |
| AO／环境遮蔽 | 对周围可见方向受遮挡程度的描述或近似 |
| SSR | 利用屏幕数据计算反射的近似方法 |
| G-buffer | 延迟渲染等流程保存表面信息的缓冲集合 |
| Reprojection／重投影 | 寻找跨帧或跨视图的对应位置 |
| Temporal Accumulation／时间累积 | 合并当前与有效历史样本 |
| Denoising／降噪 | 在有限、有噪数据上估计更稳定的结果 |
| TAA | 利用多帧信息改善采样与抗锯齿 |
| HDR | 较大亮度范围的表示或处理能力 |
| Tone Mapping／色调映射 | 将亮度范围组织到目标显示范围 |
