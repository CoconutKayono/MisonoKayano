# 在内容目录中引用内容（Reference content in a content directory）

> 来源：[Unity 6000.7 官方手册 · Reference content in a content directory](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-references.html)

你可以通过以下方式在 ScriptableObject 根资源中引用内容：

- 一个 [Loadable<T>](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-references.html#loadable-references) 引用，用于在运行时按需加载。
- 一个 [LoadableSceneId](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-references.html#loadable-scene-references) 引用，用于在运行时加载场景。
- 一个[直接引用](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-references.html#direct-references)，它始终包含在内容目录中。不过，Unity 会将根资源的所有直接引用完整加载到内存中，因此最佳实践是避免直接引用大型资源，尽量对所有资源使用 Loadable 引用。

你也可以使用[未跟踪引用](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-references.html#untracked-references)（untracked references）来发现仅存在于运行时的资源。

## Loadable 引用

你可以对 MonoBehaviour 或 ScriptableObject 派生类使用 `Loadable<T>`，在一个对象与另一个对象之间建立按需引用。可加载引用（loadable reference）意味着被引用的对象不需要立即加载，但它会自动包含在构建输出中。

[Loadable<T>](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Loading.Loadable_1.html) 类包含一个 [LoadableObjectId](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Loading.LoadableObjectId.html)，它根据被引用对象在源项目中的序列化位置来引用该对象。

## Loadable 场景引用

[LoadableSceneId](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Loading.LoadableSceneId.html) 与 `LoadableObjectId` 类似，但你可以用它引用场景，将场景带入构建并加载它们。没有用于指向场景的直接引用类型，你必须通过调用 `SceneManager` API 按需加载场景。更多信息，请参阅[在内容构建中包含场景](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-scenes.html)。

## 直接引用

直接引用（direct references）是 Unity 中最常用的引用类型。

直接引用的一个例子是 GameObject 与其某个组件之间的链接。具有直接引用关系的对象通常放在同一个序列化文件中，因为它们需要一起加载。

更多信息，请参阅[直接引用资源管理](https://docs.unity3d.com/6000.7/Documentation/Manual/assets-direct-reference.html)。

## 未跟踪引用

已跟踪引用（tracked references）是 ScriptableObject、MonoBehaviour 或其他序列化对象上的直接引用、`Loadable<T>` 或 `LoadableSceneId` 字段。Unity 构建内容目录时，会跟随这些字段并自动包含被引用的资源。

未跟踪引用（untracked reference）是指你的应用在运行时依赖某些内容，但序列化数据中没有任何信息告知构建管线这种依赖。相反，你的代码稍后自行发现内容，例如调用 [ContentLoadManager.GetRootAssets<T>](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Loading.ContentLoadManager.GetRootAssets__1.html) 并读取找到的根资源上的字段。

当你希望将内容拆分到多个内容目录，创建带有引导代码（bootstrap code）的小型 Player 并在运行时发现根资源时，可以使用未跟踪引用。

要使未跟踪引用在项目中生效，请执行以下操作：

1. 运行 [BuildPipeline.BuildContentDirectory](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPipeline.BuildContentDirectory.html) 时，将根资源 ScriptableObject 添加到 `rootAssetPaths`。
2. 在查找代码运行之前，在运行时注册该内容目录。
3. 保持 Player 和内容构建之间的根资源类型和字段布局一致。

### 何时避免使用未跟踪引用

对于简单的单一构建项目，如果每个依赖都可以是 Player 或引导场景中对象上的直接引用或 Loadable 引用，请避免使用未跟踪引用。

使用未跟踪引用意味着更容易遗漏依赖。例如，如果你忘记构建或注册内容目录，Unity 编辑器仍然可以使用项目资源，而 Player 构建会一直失败，直到内容目录被构建、发布并注册。在 AssetBundle 系统中，此功能类似于在代码中按地址或 AssetBundle 名称加载，而不在 Inspector 中分配资源。
