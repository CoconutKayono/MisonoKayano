# 创建内容目录（Create content directories）

> 来源：[Unity 6000.7 官方手册 · Create content directories](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html)

内容目录是内容构建过程的输出，类似于使用 AssetBundle 时包含 `.bundle` 文件和清单的文件夹。你不需要在 Unity 编辑器中为内容目录分配资源，而是创建一个 [ScriptableObject](https://docs.unity3d.com/6000.7/Documentation/Manual/class-ScriptableObject.html) 实例作为根资源，它引用你想包含在应用中的内容。然后将根资源路径传递给 [BuildPipeline.BuildContentDirectory](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPipeline.BuildContentDirectory.html)，以生成构建好的内容文件夹。

## 根资源概览

根资源是项目中的 [ScriptableObject](https://docs.unity3d.com/6000.7/Documentation/Manual/class-ScriptableObject.html#create-a-scriptableobject) [资源](https://docs.unity3d.com/6000.7/Documentation/Manual/class-ScriptableObject.html#create-a-scriptableobject)，用于定义内容构建中包含哪些内容。

如果你正在从 AssetBundle 系统迁移，根资源不需要镜像 AssetBundle。例如，如果你以前有十个 AssetBundle，你不需要十个根资源，因为内容目录中的内容可以独立加载和卸载，而不必加载根资源中的其他内容。一个包含所有内容的根资源适合大多数项目，必要时你可以为特定内容（例如可选内容包）创建更多根资源。

当你使用 [ContentLoadManager.RegisterContentDirectory](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Loading.ContentLoadManager.RegisterContentDirectory.html) 注册内容目录时，Unity 会自动将根资源加载到内存中，因此最佳实践是避免直接引用大型资源。

示例请参阅[创建 ScriptableObject 以定义根资源](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html#create-a-scriptableobject-root-asset)。

## AssetBundle 与内容目录创建过程的差异

内容目录旨在取代 [AssetBundle 系统](https://docs.unity3d.com/6000.7/Documentation/Manual/AssetBundlesIntro.html)。将资源分配到独立内容构建中的概念保持不变，但过程有以下不同：

| 工作流 | AssetBundle | 内容目录 |
| --- | --- | --- |
| 创建 | 在编辑器中创建命名的 AssetBundle，或创建 `.meta` 文件。 | 创建 ScriptableObject 实例，并在构建脚本中将其路径作为根资源传递。 |
| 分配资源 | 将每个资源分配到特定的 AssetBundle。 | 从 ScriptableObject 实例引用资源。 |
| 构建 | 运行 [BuildPipeline.BuildAssetBundles](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPipeline.BuildAssetBundles.html)。 | 使用输出文件夹路径和 `rootAssetPaths` 运行 [BuildPipeline.BuildContentDirectory](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPipeline.BuildContentDirectory.html)。 |
| 加载内容 | 使用 [AssetBundle.LoadFromFile](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/AssetBundle.LoadFromFile.html) 等方法显式加载每个依赖的 AssetBundle。 | 使用 [ContentLoadManager.RegisterContentDirectory](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Loading.ContentLoadManager.RegisterContentDirectory.html) 即可获得所有内容。 |
| 加载单个资源 | 使用 [AssetBundle.LoadAsset](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/AssetBundle.LoadAsset.html)。 | 使用 [Loadable<T>](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-references.html)。 |
| 加载场景 | 通过 [SceneManager](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SceneManagement.SceneManager.html) 按路径加载。 | 通过 SceneManager 按 [LoadableSceneId](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-scenes.html) 加载。 |

> **重要提示**：你只能使用内容目录创建本地内容构建，并随应用的 Player 构建一起分发。如果你想远程分发内容构建，或在用户安装 Player 后下载内容，则必须自己创建分发内容目录的机制，或使用 [AssetBundle 系统](https://docs.unity3d.com/6000.7/Documentation/Manual/AssetBundlesIntro.html)。

## 内容目录创建概览

要创建内容目录，请执行以下步骤：

1. [创建 ScriptableObject 根资源](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html#create-a-scriptableobject-root-asset)。
2. [在 Unity 编辑器中创建根资源](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html#create-the-root-asset)。
3. [构建内容目录](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html#build-the-content-directory)。
4. [可选：验证构建过程](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html#verify-the-build)。

## 创建 ScriptableObject 根资源

以下示例定义了一个可选内容包的根资源。它使用三种方式将内容包含在构建中：

- 一个 `Loadable<GameObject>`，用于在运行时按需加载的奖励预制件。
- 一个 `LoadableSceneId`，用于奖励关卡场景。
- 对轻量级元数据 ScriptableObject 的直接引用。

有关如何引用资源的更多信息，请参阅[在内容目录中引用内容](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-references.html)。

将以下内容保存为项目 Assets 文件夹中任意位置的 `ContentPackRootAsset.cs`：

```csharp
using UnityEngine;
using Unity.Loading;

// Lightweight metadata asset that the root asset references directly.
[CreateAssetMenu(fileName = "ContentPackMetadata", menuName = "Content/Content Pack Metadata")]
public class ContentPackMetadata : ScriptableObject
{
    public string description;

    // Stored as a string because Unity doesn't serialize System.DateTime.
    public string expirationDate;

    public int difficulty;
}

// Defines the name of the menu options as they appear in the Editor.
[CreateAssetMenu(fileName = "ContentPackRootAsset", menuName = "Content/Content Pack Root Asset")]
public class ContentPackRootAsset : ScriptableObject
{
    // Loadable: included in the build; load when needed with bonusPrefab.Load().
    public Loadable<GameObject> bonusPrefab;

    // Scene reference: included in the build; load with SceneManager when the directory is registered.
    public LoadableSceneId bonusLevel;

    // Direct reference to another lightweight ScriptableObject is fine here, such as metadata.
    public ContentPackMetadata metadata;
}
```

如果你有大量内容，不必在单个根资源上定义所有 `Loadable<T>` 引用。你可以创建 ScriptableObject 实例的层级结构，其中根资源直接引用其他 ScriptableObject 实例，每个实例跟踪不同类别的内容。只有层级结构顶层的 ScriptableObject 需要作为根资源传递给 `BuildPipeline.BuildContentDirectory`。更多信息，请参阅[构建内容目录](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html#build-the-content-directory)。

## 在编辑器中创建根资源

1. Unity 编译脚本后，在 Project 窗口中右键单击，选择 **Create > Content > Content Pack Root Asset**（来自 `[CreateAssetMenu]`）。
2. 为根资源命名（例如 `ContentPackRootAsset`），并将其放在稳定的路径，例如 `Assets/ContentPacks/ContentPackRootAsset.asset`。
3. 选择该资源，并在 Inspector 中分配你的内容包预制件、场景和 `ContentPackMetadata` 资源。

`.asset` 路径就是你传递给构建 API 的内容，例如：

```csharp
var parameters = new BuildContentDirectoryParameters
{
    outputPath = "Builds/ContentPack",
    rootAssetPaths = new[] { "Assets/ContentPacks/ContentPackRootAsset.asset" }
};
BuildPipeline.BuildContentDirectory(parameters);
```

Unity 随后会跟随内容目录中的引用，将元数据资源、奖励预制件和奖励关卡场景包含在内容目录构建中。

## 构建内容目录

以下示例是一个编辑器脚本，它使用前面的步骤调用构建 API 并创建内容目录：

```csharp
using UnityEditor;
using UnityEditor.Build.Reporting;

public static class BuildContentPackRootAsset
{
    [MenuItem("Build/Content Directories/Content Pack")]
    public static void Build()
    {
        var parameters = new BuildContentDirectoryParameters
        {
            // Folder for the built content directory (created if it does not exist).
            // Typically should be outside the Assets folder.
            outputPath = "Builds/ContentPack",

            // Project paths to ScriptableObject root assets for this pack.
            // Unity includes each root and every asset they reference (direct, Loadable, scenes).
            rootAssetPaths = new[]
            {
                "Assets/ContentPacks/ContentPackRootAsset.asset"
            },

            // Optional build flags (for example BuildContentOptions.CleanBuildCache).
            // See BuildContentOptions in the Scripting Reference.
            options = BuildContentOptions.None,

        };

        // Uses the active build target from Build Profiles.
        BuildReport report = BuildPipeline.BuildContentDirectory(parameters);
        if (report.summary.result == BuildResult.Succeeded)
            UnityEngine.Debug.Log($"Content directory built to: {parameters.outputPath}");
    }
}
```

然后你可以通过脚本添加到 **Build** 菜单下的菜单项创建内容构建。Unity 会将内容目录添加到项目的 Builds 文件夹（由 `outputPath` 定义）。

有关可选构建标志的更多信息，请参阅 [BuildContentOptions](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildContentOptions.html) [API 文档](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildContentOptions.html)。

要创建另一个内容目录，请使用不同的 `outputPath` 和不同的 `rootAssetPaths` 再次运行 `BuildContentDirectory`。

## 验证构建

要验证构建过程是否成功，你可以按以下方式检查构建结果：

- 在构建脚本中，检查 `BuildReport.summary.result`。例如，[前面的构建脚本](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html#build-the-content-directory)会在 `report.summary.result` 等于 `BuildResult.Succeeded` 时记录消息。
- 在编辑器中，打开 Build Analysis 窗口（**Window > Analysis > Build Analysis**），它会将构建结果显示为 Success、Failed 或 Cancelled。要确认特定资源是否包含在构建中，请检查 Assets 选项卡。

构建成功时，Unity 会将内容目录写入 `outputPath` 下的文件夹，包括一个构建清单文件。请将此文件夹中的每个文件与 Player 构建一起分发。要从脚本将输出打包到 Player 构建中，请参阅[创建自定义构建脚本](https://docs.unity3d.com/6000.7/Documentation/Manual/build-script-build.html)。
