# 内容目录简介（Introduction to content directories）

> 来源：[Unity 6000.7 官方手册 · Introduction to content directories](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-introduction.html)

内容目录是创建独立内容构建、随 Player 构建一起分发的一种方式。它是 [AssetBundle 系统](https://docs.unity3d.com/6000.7/Documentation/Manual/AssetBundlesIntro.html) 的替代方案，具有隐式去重、更短的加载时间和更低的内存开销等额外优势。内容目录与 Addressables 包兼容，Addressables 提供了在项目中组织内容的用户界面。

内容构建是对 Player 构建中内容的补充。这使你能够创建更小、更快的构建，并通过最小化构建中的内容量来减少资源重复。

> **重要提示**：内容目录构建仅支持本地内容构建，不支持远程内容分发。

## 构建过程的结构

在项目中使用内容目录时，你可以按以下方式组织构建过程：

- **Player 构建**：只包含启动应用所需的核心代码和内容。推荐做法是创建一个起始场景，从内容目录执行内容的初始加载。你可以从编辑器或通过脚本[构建 Player](https://docs.unity3d.com/6000.7/Documentation/Manual/building-introduction.html)。
- **内容构建**：构建一个或多个内容目录，随 Player 一起分发应用的内容。内容文件夹包含以下内容：
  - 项目的已构建内容。项目内容是指创建应用玩法所需的[资源](https://docs.unity3d.com/6000.7/Documentation/Manual/assets-supported-types.html)。
  - 一个清单文件（BuildManifest），其中包含加载内容所需信息的记录。

内容目录系统只重建已更改的内容，这有助于在项目开发时缩短迭代时间。

## 创建内容目录

内容目录使用称为根资源（root assets）的 [ScriptableObject 实例](https://docs.unity3d.com/6000.7/Documentation/Manual/class-ScriptableObject.html)来定义构建中包含的内容。然后你可以使用 [Loadable<T>](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Loading.Loadable_1.html) API 同步加载和卸载单个资源，或使用 `async` 和 `await` 关键字异步执行。更多信息，请参阅[创建内容目录](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html)。

## 与 AssetBundle 的比较

内容目录是 [AssetBundle 系统](https://docs.unity3d.com/6000.7/Documentation/Manual/AssetBundlesIntro.html) 的替代方案。下表描述了两个系统之间的差异：

| 特性 | 内容目录 | AssetBundle |
| --- | --- | --- |
| 组织方式 | 使用根资源组织应用中的内容。 | 必须将资源分配到明确的 AssetBundle。 |
| 布局 | 基于哈希命名的细粒度文件布局，可选择放在 Unity 存档中。 | 每个定义的 AssetBundle 对应一个单独的 Unity 存档文件。被引用的内容可能在多个 AssetBundle 中重复。 |
| 按需引用 | 使用 `Loadable<T>` 和 `LoadableSceneId` 将需要按需加载的内容放入构建。Unity 会自动在构建中包含被 Loadable 引用的资源。更多信息，请参阅[在内容目录中引用内容](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-references.html)。 | 使用字符串路径加载引用。 |
| 依赖 | 依赖按资源跟踪。Unity 会自动移除构建中重复的内容，并自动处理依赖。 | 依赖按 AssetBundle 跟踪。加载资源需要加载其 AssetBundle，并递归加载所有依赖的 AssetBundle，即使加载的资源本身并不引用它们。 |
| 远程内容交付 | 仅本地内容。 | 支持本地和远程内容。 |
| 构建清单 | 构建信息存储在 `ScriptsOnlyCache.yaml`、构建清单和 Asset Database 内跟踪的导入数据中。更多信息，请参阅[构建缓存位置参考](https://docs.unity3d.com/6000.7/Documentation/Manual/build-cache-location-reference.html)。 | 存储在 `.manifest` 文件和 `AssetBundleManifest` 中。 |
| 代码剥离 | 使用 [BuildPlayerOptions.previousBuildMetadataLocations](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPlayerOptions-previousBuildReportDirectories.html) 控制代码剥离。更多信息，请参阅[代码剥离如何影响内容](https://docs.unity3d.com/6000.7/Documentation/Manual/managed-code-stripping-content.html)。 | 使用 [BuildPlayerOptions.assetBundleManifestPath](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPlayerOptions-assetBundleManifestPath.html) 控制代码剥离。 |
| 构建回调 | 使用 [IPreprocessBuildWithContext](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Build.IPreprocessBuildWithContext.html) 和 [IPostprocessBuildWithContext](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Build.IPostprocessBuildWithContext.html)。这些回调会针对 Player 构建、内容目录构建以及使用 `BuildPipeline.BuildAssetBundles` 构建的 AssetBundle 调用。要检查正在进行的是哪种类型的构建，请检查 [BuildReport.summary.buildType](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Build.Reporting.BuildSummary-buildType.html)。`IPostprocessBuildWithContext` 会在所有 Player 和内容构建之后调用，无论它们是成功、失败还是取消。 | 使用 `IPreprocessBuildWithReport` 和 `IPostprocessBuildWithReport`。 |

> 提示：如果你使用 [Addressables 系统](https://docs.unity3d.com/Packages/com.unity.addressables@latest)，内容目录是兼容的。

## 替换 AssetBundle 代码

[BuildAssetBundle](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPipeline.BuildAssetBundles.html) 方法强制调用者定义每个 AssetBundle 的名称，并通过脚本或 Inspector 将资源和场景显式分配给它。因此，一些 AssetBundle 可能只是为了避免资源重复而存在，例如共享从多个 AssetBundle 引用的资源。这在内容目录中不是推荐的模式，最佳实践是创建[一个根资源](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html#root-asset-overview)来保存项目中的所有资源。

如果你现有的项目依赖通过字符串加载大量资源，请考虑使用一个充当资源列表（asset list）的 ScriptableObject，而不是定义许多根资源。单个资源列表可以暴露所有需要通过字符串加载的资源，你也可以将内容拆分为多个资源列表。

有关创建内容目录的更多信息，请参阅[创建内容目录](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html)。

## 限制

内容目录有以下限制：

- 你只能使用内容目录创建本地内容构建，并随应用的 Player 构建一起分发。如果你想远程分发内容构建，或在用户安装 Player 后下载内容，则必须自己创建分发内容目录的机制，或使用 [AssetBundle 系统](https://docs.unity3d.com/6000.7/Documentation/Manual/AssetBundlesIntro.html)。
- [根资源](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html#root-asset-overview)必须是 ScriptableObject 实例。
- 不能将 [BuildUsage](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Build.Content.BuildUsageTagSet.html) [API](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Build.Content.BuildUsageTagSet.html) 用于内容目录。使用此 API 的资源需要经过修改，才能在内容目录中正确加载。要解决资源问题，请使用 [Project Auditor](https://docs.unity3d.com/6000.7/Documentation/Manual/project-auditor/project-auditor.html)。
- 干净构建可能比 AssetBundle 构建时间慢。
- 不建议使用循环引用，并会在 Console 中打印警告。
- [Loadable 引用](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-references.html#loadable-references)仅在内容目录系统中受支持。
