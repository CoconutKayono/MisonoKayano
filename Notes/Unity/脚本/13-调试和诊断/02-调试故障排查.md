# 调试故障排查

> 原文：[Troubleshooting debugging](https://docs.unity3d.com/6000.7/Documentation/Manual/managed-debugging-troubleshooting.html)

大多数 Debugger 问题是由于 IDE 无法找到 Unity Editor 或 Unity Player 导致的。这意味着 Unity Editor 或 Player 无法正确连接 Debugger。由于 Debugger 使用 TCP 连接到 Editor 或 Player，连接问题通常由网络引起。下面列出了一些可以用来排查基本连接问题的步骤。

## 确保连接到正确的 Unity 实例

你可以将 IDE 连接到本地网络中任意启用了调试功能的 Unity Editor 或 Unity Player 实例。连接 Debugger 时，请确认连接的是正确的 Unity 实例。如果知道运行 Unity Player 的设备的 IP 地址或计算机名称，就能更容易地找到正确的实例。

## 验证与 Unity 实例的网络连接

IDE 使用与 Unity Profiler 相同的机制来查找要调试的 Unity 实例。如果 IDE 找不到预期的 Unity 实例，请尝试将 [Profiler 连接到该实例](profiler-profiling-applications.html)。如果 Profiler 也找不到该 Unity 实例，则运行 IDE 或 Unity 实例的计算机上可能存在防火墙。如果存在防火墙，请参阅[检查防火墙设置](#检查防火墙设置)。

## 确保设备只有一个活动的网络接口

许多设备有多个网络接口。例如，手机可能同时有活动的蜂窝网络连接和活动的 Wi-Fi 连接。为了使用 TCP 将 Debugger 正确连接到 Unity 实例，IDE 必须连接到设备上的正确网络接口。例如，如果计划通过 Wi-Fi 调试，请先将设备设为飞行模式以禁用所有其他网络接口，然后再启用 Wi-Fi。

你可以在 Player Log 中查看 Unity Player 告诉 IDE 使用的 IP 地址。查找类似下面的日志内容：

```text
Multi-casting "[IP] 10.0.1.152 [Port] 55000 [Flags] 3 [Guid] 2575380029 [EditorId] 4264788666 [Version] 1048832 [Id] iPhonePlayer(Example-iPhone):56000 [Debug] 1 [PackageName] iPhonePlayer" to [225.0.0.222:54997]...
```

此消息表示 IDE 将尝试使用 IP 地址 `10.0.1.152` 和端口 `56000` 连接设备。运行 IDE 的计算机必须能够访问此 IP 地址和端口。

## 检查防火墙设置

Unity 实例使用 TCP 连接与 IDE 通信。在大多数 Unity 平台上，此 TCP 连接使用随机选择的端口。通常不需要知道具体端口，因为 IDE 应该能够自动检测端口。如果自动检测失败，请使用网络分析工具确定运行 IDE 的计算机，或运行 Unity 实例的计算机或设备上可能被阻止的端口。找到这些端口后，请确保运行 IDE 的计算机和运行 Unity 实例的计算机都允许防火墙访问相应端口。

## 验证 Managed Debugging Information 可用

如果 Debugger 已连接到 Unity 实例，但断点没有加载，Debugger 可能无法找到代码的 Managed Debugging Information。Managed Code Debugging Information 存储在 `.pdb` 文件中，该文件应位于 Managed Assembly（`.dll` 文件）旁边。

启用[正确的 Preferences 和 Build 选项](managed-code-debugging.html)后，Unity 会自动生成此调试信息。但是，Unity 无法为项目中的 Managed Plug-in 生成调试信息。只有当关联的 `.pdb` 文件位于 Unity 项目磁盘上的 Managed Plug-in 旁边时，才能调试 Managed Plug-in 中的代码。

## 防止设备锁定

禁用用于调试应用程序的设备上的任何屏幕锁定功能。屏幕锁定会导致 Debugger 断开连接，并阻止它重新连接。在进行 Managed Code Debugging 时，不要锁定屏幕。如果屏幕已锁定，请在设备上重新启动应用程序，以便 Debugger 再次连接。

## Debugger 导致的内存和线程泄漏

Managed Debugger 会为操作系统线程句柄分配内存，以处理与线程启动和关闭相关的竞争条件。这会产生少量内存泄漏，通常不会影响应用程序的资源使用情况。但是，当创建和销毁大量线程时，内存泄漏可能变得明显，并使你难以追踪应用程序中的其他内存泄漏。因此，在排查内存泄漏时，建议禁用 Script Debugging。
