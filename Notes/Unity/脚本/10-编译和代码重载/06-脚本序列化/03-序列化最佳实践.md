# 序列化最佳实践

> 原文：[Serialization best practices](https://docs.unity3d.com/6000.7/Documentation/Manual/script-serialization-best-practices.html)

应用以下编码实践和组织原则，可以防止项目中的错误并优化序列化性能。

## 线程安全

大多数 Unity API 只能从主线程调用。不要从可序列化类型的构造函数和字段初始化器中调用 Unity API，因为它们在单独的 loading thread 上运行。

在 development build 中，如果尝试从 loading thread 调用主线程 API，Unity 会抛出错误。
在 release build 中，代码不会报错，但可能在应用中造成崩溃和其他意外行为。

**提示**：为了降低序列化期间出错的风险，不要调用会影响项目状态或涉及其他 Unity 对象的 API 方法。可以安全调用的 API 包括 `Debug.Log`，以及处理简单数据类型的 API，例如数学函数和 `Vector3`。

### Finalizer

不要从 finalizer 方法启动序列化。Finalizer 不在主线程上运行。它们何时运行由 garbage collector 决定，而且在某些情况下可能根本不会运行。

尝试从 finalizer 序列化数据可能导致意外行为和崩溃。详情请参阅 Microsoft 文档中的 [Finalizers](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/finalizers)。

## 组织数据

可以按以下方式组织数据，以确保充分利用 Unity 的序列化：

- 尽量让 Unity 序列化最小的数据集合。目的不是节省电脑硬盘空间，而是确保能够与项目的旧版本保持 backwards compatibility。开发后期，如果处理大量序列化数据，向后兼容会变得更加困难。
- 永远不要让 Unity 序列化重复数据或 cached data。这会给 backwards compatibility 带来重大问题，因为数据很容易不同步。
- 添加引用自定义 C# 类或结构体的字段时要谨慎。字段引用自定义 C# 类或结构体时，Unity 会将被引用对象的全部内容嵌入引用对象的序列化数据。如果结构变得复杂或嵌套很深，未来修改结构时会难以迁移数据。此外，同一对象的数据还可能无意中在序列化数据中重复多次。应尽量让 MonoBehaviour 和 ScriptableObject 派生类的结构扁平而简单。
- 在对象之间共享数据时使用 ScriptableObject。当引用继承自 `UnityEngine.Object` 的类（例如继承自 ScriptableObject 的类）时，Unity 只序列化引用，而不是整个对象图。因此数据只在 ScriptableObject 中序列化一次，而不是在每个引用点重复序列化。同样地，如果希望在一个 MonoBehaviour 或 ScriptableObject 中多次引用同一个自定义 C# 类，可以使用 `[SerializeReference]` 属性。详情请参阅[[01-序列化规则#自定义类的序列化]]。

## 清理过时的序列化数据

更改脚本或 Prefab 的结构时，Unity 不会立即重写所有已经引用旧结构的 Asset。现有序列化数据会保留在磁盘上，直到受影响的 Asset 再次保存。因此，Asset 可能积累过时的序列化数据：当前项目中已经不存在对应内容的字段和占位对象。

### 过时数据如何积累

过时数据通常以下列形式出现在 `.unity`、`.prefab` 和 `.asset` 文件中：

- **删除的序列化字段**：如果从 MonoBehaviour 或 ScriptableObject 脚本中删除 `[SerializeField]` 字段，之前为该字段赋值的 Asset 仍会在 YAML 数据中保留该值。该字段在运行时已不存在，因此值不可见，但直到 Asset 再次保存前仍会留在磁盘上。
- **嵌套 Prefab 对象的 stripped placeholder**：当 Scene 或另一个 Prefab 引用嵌套 Prefab 实例中的对象时，Unity 会在包含文件中添加 stripped placeholder object。如果之后从源 Prefab 中删除被引用对象，该占位对象会一直保留在包含文件中，直到该文件再次保存。
- **未使用的 Prefab override**：当 Prefab override 引用的脚本字段被重命名或删除时，Prefab 实例上的 override 条目会变为未使用。

### Unity 为什么不会自动删除过时数据

Unity 有意保留过时数据，而不是在每次脚本或 Prefab 更改时删除，原因有两个：

- **性能**：删除它需要 Unity 加载、修改并保存所有依赖变更脚本或 Prefab 的 Asset。对于大型项目，一次编辑可能意味着重写数千个文件。
- **数据恢复**：Unity 保留过时数据，以便你可以撤销临时删除而不丢失值。例如：
  - 如果删除序列化字段后又以相同名称加回来，之前序列化的值会自动重新连接。
  - 如果删除引用的 Asset 后将它连同 `.meta` 文件一起恢复（保持 GUID 不变），对它的引用仍然有效。

如果是重命名字段而不是删除字段，要保留数据，请使用 `[FormerlySerializedAs]` 属性。

### 重新序列化受影响的 Asset

要删除单个 Asset 中的过时数据，请在 Editor 中修改 Asset 的任意属性并保存。这会强制 Unity 使用当前脚本、Prefab 和 Asset 引用重写 Asset，并丢弃不再对应字段或引用对象的数据。

要清理大量 Asset 中的过时数据，可以从 Editor script 调用 `AssetDatabase.ForceReserializeAssets`。下面的示例从菜单项重新序列化项目中的每个 Asset：

```csharp
using UnityEditor;

public static class StaleDataCleanup
{
    [MenuItem("Tools/Reserialize All Assets")]
    static void ReserializeAll()
    {
        AssetDatabase.ForceReserializeAssets();
    }
}
```

不带参数时，`AssetDatabase.ForceReserializeAssets` 会重新序列化项目中的每个 Asset。要重新序列化特定子集，可以传入 Asset 路径列表，以及可选的 `ForceReserializeAssetsOptions` 值，以控制是否重写 Asset、其 `.meta` 文件，或两者都重写。

**重要**：`AssetDatabase.ForceReserializeAssets` 只能从菜单项等直接用户操作中运行。如果从 Unity callback（例如可能在 Scene 被修改时运行的 `OnEnable`）、Editor 处于 Play mode 时或 domain reload 期间调用，Unity 会抛出异常。

一次重新序列化大量 Asset 会产生大量文件变更。在跨项目运行前，应与团队和 version control system 协调。

﻿# 序列化最佳实践

> 原文：[Serialization best practices](https://docs.unity3d.com/6000.7/Documentation/Manual/script-serialization-best-practices.html)

应用以下 coding practices 和 organization principles，可以防止 errors，并优化项目中的 serialization performance。

## Thread safety

大多数 Unity APIs 只能从 main thread 调用。不要从 serializable types 的 constructors 和 field initializers 调用 Unity APIs，因为它们运行在独立的 loading thread 上。参阅 [[01-序列化规则|serializable types]]。

在 [development builds](https://docs.unity3d.com/6000.7/Documentation/Manual/build-profiles-reference.html) 中，如果你尝试从 loading thread 调用 main thread APIs，Unity 会抛出 error。在 release build 中，code 会无 error 运行，但可能在 application 中产生 crashes 和其他 unexpected behavior。

**提示**：为降低 serialization 期间发生 errors 的风险，不要调用会影响 project state 或涉及其他 Unity objects 的 API methods。安全调用的 APIs 包括 [`Debug.Log`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Debug.Log.html)，以及处理 simple data types 的 APIs，例如 [math functions](https://docs.unity3d.com/6000.7/Documentation/Manual/class-Mathf.html) 和 [`Vector3`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Vector3.html)。

### Finalizers

不要从 finalizer methods 发起 serialization。Finalizers 不在 main thread 上运行。由 [garbage collector](https://docs.unity3d.com/6000.7/Documentation/Manual/performance-garbage-collector.html) 决定它们何时运行，而且在某些情况下它们可能根本不运行。

尝试从 finalizer 序列化 data 可能导致 unexpected behavior 和 crashes。更多信息请参阅 Microsoft 关于 [Finalizers](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/finalizers) 的 documentation。

## 组织你的 data

你可以按以下方式组织 data，以确保 Unity serialization 得到最佳利用：

- 让 Unity 序列化尽可能小的数据集合。这样做的目的不是节省 computer hard drive 空间，而是确保可以维护项目旧版本的 backwards compatibility。如果处理大量 serialized data，backwards compatibility 可能会在开发后期变得更难维护。
- 永远不要让 Unity 序列化 duplicate data 或 cached data。这会给 backwards compatibility 带来重大问题，因为 data 可能 out of sync，因而具有很高的 error risk。
- 添加引用 custom C# classes 或 structs 的 fields 时要谨慎。当 fields 引用 custom C# classes 或 structs 时，Unity 会将被引用 object 的全部内容嵌入引用 object 的 serialized data。如果这种 structure 变得复杂或 deeply nested，那么将来修改 structure 时可能很难迁移 data。此外，object 的 data 也很容易在 serialized data 中被无意地重复多次。因此，应尽量让 MonoBehaviour 和 ScriptableObject derived classes 中的 structure 保持 flat 且 simple。
- 在 Objects 之间共享 data 的方式是使用 [ScriptableObjects](https://docs.unity3d.com/6000.7/Documentation/Manual/class-ScriptableObject.html)。当你引用派生自 `UnityEngine.Object` 的 class（例如派生自 ScriptableObject 的 class）时，Unity 只序列化 reference，而不是整个 object graph。因此 data 只会在 ScriptableObject 中序列化一次，而不是在每个引用它的位置序列化一次。同样，如果希望在单个 MonoBehaviour 或 ScriptableObject 中多次引用同一个 custom C# class，可以使用 [`[SerializeReference]`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SerializeReference.html) attribute。更多信息请参阅 [[01-序列化规则#自定义类的序列化|Serialization of custom classes]]。

## 清理过期的 serialized data

当你修改 script 或 prefab 的 structure 时，Unity 不会立即重写所有已经引用旧 structure 的 assets。Existing serialized data 会一直保留在 disk 上，直到受影响的 asset 再次保存。因此，assets 可能积累 stale serialized data：与当前 project 中任何内容都不再对应的 fields 和 placeholder objects。

### Stale data 如何积累

Stale data 通常以下列方式出现在 `.unity`、`.prefab` 和 `.asset` files 中：

- Removed serialized fields：如果从 MonoBehaviour 或 ScriptableObject script 中移除一个 `[SerializeField]` field，之前为该 field 赋过值的任何 asset 仍会在其 YAML data 中包含这个值。由于 class 中已不存在该 field，这个值在 runtime 不可见，但在 asset 再次保存前仍会留在 disk 上。
- Stripped placeholders for nested prefab objects：当 scene 或另一个 prefab 引用 [nested prefab](https://docs.unity3d.com/6000.7/Documentation/Manual/NestedPrefabs.html) instance 内的 object 时，Unity 会向 containing file 添加一个 [stripped placeholder object](https://docs.unity3d.com/6000.7/Documentation/Manual/yaml-prefab-serialization.html#stripped-objects)。如果之后从 source prefab 中移除被引用 object，该 placeholder 会一直保留在 containing file 中，直到该 file 再次保存。
- Unused prefab overrides：当 prefab override 引用的 script field 被重命名或删除时，prefab instance 上的 override entry 会变成 unused。关于如何专门移除 unused overrides，请参阅 [Remove unused override data](https://docs.unity3d.com/6000.7/Documentation/Manual/UnusedOverrides.html)。

### Unity 为什么不自动移除 stale data

Unity 有意保留 stale data，而不是在每次 script 或 prefab change 时删除它，原因有两个：

- **Performance**：移除它需要 Unity 加载、修改并保存依赖已修改 script 或 prefab 的每个 asset。对于大型 projects，这可能意味着一次 edit 就要重写数千个 files。
- **Data recovery**：Unity 保留 stale data，让你可以撤销 temporary removal 而不会丢失 values。例如：

  - 如果删除一个 serialized field，再用相同 name 将它加回来，之前 serialized 的 values 会自动重新附着。
  - 如果删除一个 referenced asset，并连同其 `.meta` file 一起恢复（这样 GUID 不变），指向它的 references 仍然有效。

如果是重命名 field 而不是移除它，请使用 [`[FormerlySerializedAs]`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Serialization.FormerlySerializedAsAttribute.html) attribute 来保留 data。

### 重新序列化受影响的 assets

要从单个 asset 中移除 stale data，请在 Editor 中修改 asset 的任意 property 并保存。这会强制 Unity 使用当前 scripts、prefabs 和 asset references 重写 asset，删除不再对应 field 或 referenced object 的任何 data。

要跨多个 assets 清理 stale data，请从 Editor script 调用 [`AssetDatabase.ForceReserializeAssets`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/AssetDatabase.ForceReserializeAssets.html) method。以下示例从 menu item 重新序列化 project 中的每个 asset：

```csharp
using UnityEditor;

public static class StaleDataCleanup
{
    [MenuItem("Tools/Reserialize All Assets")]
    static void ReserializeAll()
    {
        AssetDatabase.ForceReserializeAssets();
    }
}
```

不带 arguments 时，`AssetDatabase.ForceReserializeAssets` 会重新序列化 project 中的 every asset。要重新序列化特定 subset，请传入 asset paths 的 list，以及可选的 [`ForceReserializeAssetsOptions`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/ForceReserializeAssetsOptions.html) value，用于控制重写 assets、它们的 `.meta` files，或两者。

**重要**：`AssetDatabase.ForceReserializeAssets` 只会从 direct user actions（例如 menu item）运行。如果从 Unity callback（例如 `OnEnable`，它可能在 scene 被修改时运行）、Editor 处于 Play mode，或 domain reload 期间调用它，Unity 会抛出 exception。

一次重新序列化大量 assets 会产生大量 file changes。在跨 project 运行之前，请与 team 和 version control system 协调。
