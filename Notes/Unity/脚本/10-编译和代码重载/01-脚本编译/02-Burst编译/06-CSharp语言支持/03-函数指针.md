# 函数指针

> 原文：[Function pointers](https://docs.unity3d.com/6000.7/Documentation/Manual/burst/csharp-function-pointers.html)

要处理根据其他数据状态处理数据的动态函数，请使用 `FunctionPointer<T>`。由于 Burst 将委托视为托管对象，因此不能使用 [C# 委托](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/delegates/)处理动态函数。

## 支持细节

函数指针不支持泛型委托。此外，应避免在另一个开放泛型方法中封装 `BurstCompiler.CompileFunctionPointer<T>`。如果这样做，Burst 无法向委托应用所需属性、执行额外安全分析，也无法执行潜在优化。

参数和返回值类型受到与 `DllImport` 和内部调用相同的限制。更多信息请参阅 [[09-Native Plug-in和内部调用支持|DllImport 和内部调用]]。

### 与 IL2CPP 的互操作

函数指针与 IL2CPP 互操作时，委托必须带有 `System.Runtime.InteropServices.UnmanagedFunctionPointerAttribute`。将调用约定设置为 `CallingConvention.Cdecl`。Burst 会自动将此属性添加到与 `BurstCompiler.CompileFunctionPointer<T>` 一起使用的委托上。

## 使用函数指针

要使用函数指针，先确定要由 Burst 编译的静态函数，然后执行以下操作：

1. 为这些函数添加 `[BurstCompile]` 属性。
2. 为包含这些函数的类型添加 `[BurstCompile]` 属性。这有助于 Burst 编译器找到带有 `[BurstCompile]` 属性的静态方法。
3. 声明一个委托，为这些函数创建“接口”。
4. 为这些函数添加 `[MonoPInvokeCallbackAttribute]` 属性，使其兼容 IL2CPP。例如：

```csharp
// 指示 Burst 查找带有 [BurstCompile] 属性的静态方法
[BurstCompile]
class EnclosingType {
    [BurstCompile]
    [MonoPInvokeCallback(typeof(Process2FloatsDelegate))]
    public static float MultiplyFloat(float a, float b) => a * b;

    [BurstCompile]
    [MonoPInvokeCallback(typeof(Process2FloatsDelegate))]
    public static float AddFloat(float a, float b) => a + b;

    // MultiplyFloat 和 AddFloat 共用的接口
    public delegate float Process2FloatsDelegate(float a, float b);
}
```

5. 从常规 C# 代码编译这些函数指针：

```csharp
    // 包含 MultiplyFloat 的 Burst 编译版本
    FunctionPointer<Process2FloatsDelegate> mulFunctionPointer = BurstCompiler.CompileFunctionPointer<Process2FloatsDelegate>(MultiplyFloat);

    // 包含 AddFloat 的 Burst 编译版本
    FunctionPointer<Process2FloatsDelegate> addFunctionPointer = BurstCompiler.CompileFunctionPointer<Process2FloatsDelegate>(AddFloat);
```

`[MonoPInvokeCallbackAttribute]` 位于 `AOT` 命名空间下。如果由于某种原因该属性不可用，可以按如下方式在本地声明：

```csharp
public class MonoPInvokeCallbackAttribute : Attribute
{

}
```

有关 `[MonoPInvokeCallbackAttribute]` 和 iOS 环境中的使用示例，请参阅[从 Native 代码回调](https://docs.unity3d.com/6000.7/Documentation/Manual/ios-native-plugin-call-back.html)。

### 在 Job 中使用函数指针

要直接从 Job 使用函数指针，请将它们传递给 Job 结构体：

```csharp
    // 从 HPC# Job 调用函数指针
    var resultMul = mulFunctionPointer.Invoke(1.0f, 2.0f);
    var resultAdd = addFunctionPointer.Invoke(1.0f, 2.0f);
```

默认情况下，Burst 会异步编译 Job 的函数指针。要强制同步编译函数指针，请使用 `[BurstCompile(CompileSynchronously = true)]`。

### 在 C# 代码中使用函数指针

要从常规 C# 代码使用函数指针，应将 `FunctionPointer<T>.Invoke` 属性（也就是委托实例）缓存到静态字段中，以获得最佳性能：

```csharp
    private readonly static Process2FloatsDelegate mulFunctionPointerInvoke = BurstCompiler.CompileFunctionPointer<Process2FloatsDelegate>(MultiplyFloat).Invoke;

    // 从 C# 调用委托
    var resultMul = mulFunctionPointerInvoke(1.0f, 2.0f);
```

如果函数相对于 [P/Invoke](https://docs.microsoft.com/en-us/dotnet/standard/native-interop/pinvoke) 互操作开销过小，那么从 C# 使用 Burst 编译的函数指针可能比对应的纯 C# 版本更慢。

## 性能注意事项

在可行时，应使用 Job 而不是函数指针来运行 Burst 编译的代码，因为 Job 性能更好。由于 Job 安全系统默认提供了更多优化，Burst 对 Job 能执行更好的别名分析。

此外，不能将大多数 `[NativeContainer]` 结构体（例如 `NativeArray`）直接传递给函数指针，必须使用 Job 结构体。Native 容器结构体包含用于安全检查的托管对象，Burst 编译 Job 时可以绕过这些对象，但编译函数指针时不能绕过。

下面是一个在 Burst 中使用函数指针的不佳示例。该函数指针从输入指针计算 `math.sqrt`，并将结果存入输出指针。`MyJob` 将两个 `NativeArray` 作为来源提供给该函数指针，这并不是最佳方式：

```csharp
///不佳的函数指针示例
[BurstCompile]
public class MyFunctionPointers
{
    public unsafe delegate void MyFunctionPointerDelegate(float* input, float* output);

    [BurstCompile]
    public static unsafe void MyFunctionPointer(float* input, float* output)
    {
        *output = math.sqrt(*input);
    }
}

[BurstCompile]
struct MyJob : IJobParallelFor
{
     public FunctionPointer<MyFunctionPointers.MyFunctionPointerDelegate> FunctionPointer;

    [ReadOnly] public NativeArray<float> Input;
    [WriteOnly] public NativeArray<float> Output;

    public unsafe void Execute(int index)
    {
        var inputPtr = (float*)Input.GetUnsafeReadOnlyPtr();
        var outputPtr = (float*)Output.GetUnsafePtr();
        FunctionPointer.Invoke(inputPtr + index, outputPtr + index);
    }
}
```

此示例并不理想，原因如下：

- Burst 无法向量化该函数指针，因为传入的是单个标量元素。由于缺少向量化，损失了 4–8 倍性能。
- `MyJob` 知道 `Input` 和 `Output` NativeArray 不会别名，但该信息没有传递给函数指针。
- 不断跳转到内存中其他位置的函数指针会产生非零开销。

要以最佳方式使用函数指针，应始终在函数指针中批量处理数据，例如：

```csharp
[BurstCompile]
public class MyFunctionPointers
{
    public unsafe delegate void MyFunctionPointerDelegate(int count, float* input, float* output);

    [BurstCompile]
    public static unsafe void MyFunctionPointer(int count, float* input, float* output)
    {
        for (int i = 0; i < count; i++)
        {
            output[i] = math.sqrt(input[i]);
        }
    }
}

[BurstCompile]
struct MyJob : IJobParallelForBatch
{
     public FunctionPointer<MyFunctionPointers.MyFunctionPointerDelegate> FunctionPointer;

    [ReadOnly] public NativeArray<float> Input;
    [WriteOnly] public NativeArray<float> Output;

    public unsafe void Execute(int index, int count)
    {
        var inputPtr = (float*)Input.GetUnsafeReadOnlyPtr() + index;
        var outputPtr = (float*)Output.GetUnsafePtr() + index;
        FunctionPointer.Invoke(count, inputPtr, outputPtr);
    }
}
```

修改后的 `MyFunctionPointer` 接受要处理的元素 `count`，并循环访问 `input` 和 `output` 指针执行大量计算。`MyJob` 改为 `IJobParallelForBatch`，并将 `count` 直接传递给函数指针。这样性能更好，因为：

- Burst 会将 `MyFunctionPointer` 调用向量化。
- Burst 每次函数指针调用处理 `count` 项，因此调用开销按 `count` 倍降低。例如批次大小为 128 时，每个 `index` 分摊的函数指针开销只有之前的 1/128。
- 批处理相比不批处理可获得 1.53 倍性能提升。

不过，要获得最佳性能，应使用 Job。这样 Burst 能更充分地了解目标，并拥有最多优化机会：

```csharp
[BurstCompile]
struct MyJob : IJobParallelFor
{
    [ReadOnly] public NativeArray<float> Input;
    [WriteOnly] public NativeArray<float> Output;

    public unsafe void Execute(int index)
    {
        Output[i] = math.sqrt(Input[i]);
    }
}
```

这段代码比批处理函数指针示例快 1.26 倍，比非批处理函数指针示例快 1.93 倍。Burst 具有完美的别名信息，可以对上面的代码做最广泛的修改。相比两个函数指针示例，这段代码也简单得多。
