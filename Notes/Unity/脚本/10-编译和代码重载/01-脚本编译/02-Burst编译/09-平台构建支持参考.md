# 平台构建支持参考

> 原文：[Platform build support reference](https://docs.unity3d.com/6000.7/Documentation/Manual/burst/building-projects.html)

构建项目时，Burst 会编译代码，并在目标平台的 `Plugins` 文件夹中创建一个动态库。例如，在 Windows 上，路径为 `Data/Plugins/lib_burst_generated.dll`。

> **注意**：如果目标平台是 iOS，Unity 会生成静态库，以满足 Apple 对 TestFlight 提交的要求。

Job System Runtime 会在第一次调用 Burst 编译方法时加载生成的库。

要控制 Burst 的 AOT 编译，请在 Project Settings 窗口的 **Burst AOT Settings** 部分中设置（**Edit > Project Settings > Burst AOT Settings**）。更多信息请参阅 [[08-Burst AOT设置参考]]。

## 不支持交叉编译的平台

如果要编译到非桌面平台，Burst 编译需要特定的平台编译工具（类似于 [IL2CPP](https://docs.unity3d.com/6000.7/Documentation/Manual/scripting-backends-il2cpp.html)）。桌面平台（macOS、Linux、Windows）不需要外部工具链支持。

下表列出了各平台对 AOT 编译的支持级别。如果选择了无效目标（缺少工具或不受支持的目标），Unity 不会使用 Burst 编译，但仍会构建不含 Burst 优化的目标。

> **注意**：默认情况下，Burst 支持桌面平台（macOS/Linux/Windows）之间的交叉编译。

### 不支持的项目类型

以下项目不能使用 Burst 作为编译器：

- 从 Linux Editor 构建的 Android 项目。
- 通过 **Create Xcode Project** 选项生成的 Xcode 项目。

## 多个 Burst 目标

当 Burst 在一次构建中编译多个目标平台时，必须分别进行编译。例如，如果要编译 `X64_SSE2` 和 `X64_SSE4`，Burst 必须分别编译两次，为所选的每个目标生成代码。

为了尽量减少目标组合，Burst 目标平台在底层要求多个处理器指令集：

- `SSE4.2` 的前提是具有 `SSE4.2` 和 `POPCNT` 指令集。
- `AVX2` 的前提是具有 `AVX2`、`FMA`、`F16C`、`BMI1` 和 `BMI2` 指令集。
- `ARMV8A` 是基本的 Armv8-A CPU 目标。
- `ARMV8A_HALFFP` 是 `ARMV8A` 加上以下扩展：`fullfp16`、`dotprod`、`crypto`、`crc`、`rdm`、`lse`。实际而言，这对应 Cortex A75/A55 及更高版本的核心。
- `ARMV9A` 是 `ARMV8A_HALFFP` 加上 SVE2 支持。实际而言，这对应 Cortex X2/A710/A510 及更高版本的核心。**重要**：此目标目前仍处于实验阶段。

## 基于运行时 CPU 特性的动态分派

对于所有 `x86`/`x64` CPU 桌面平台，以及 Android 上的 64 位 Arm，Burst 会考虑运行时可用的 CPU 特性，将 Job 分派到它编译的不同版本。

对于 `x86` 和 `x64` CPU，Burst 在运行时仅支持 `SSE2` 和 `SSE4` 指令集。

例如，使用动态 CPU 分派时，如果 CPU 支持 `SSE3` 及以下指令集，Burst 会自动选择 `SSE2`。
