# 自定义脚本符号

> 原文：[Custom scripting symbols](https://docs.unity3d.com/6000.7/Documentation/Manual/custom-scripting-symbols.html)

除了 Unity 的[[03-Unity脚本符号参考|内置脚本符号]]之外，还可以定义自己的自定义脚本符号。定义自定义脚本符号的位置决定了它们生效的范围。可以在以下位置定义自定义符号：

- [资源文件](#整个项目的自定义符号)，用于项目中所有 Editor 和 Player 代码，不受当前活动[构建配置文件](https://docs.unity3d.com/6000.7/Documentation/Manual/build-profiles.html)影响的符号。
- [Player Settings](#平台的自定义符号)，用于在指定平台或其某个构建配置文件处于活动状态时，适用于所有 Editor 和 Player 代码的符号。
- [构建配置文件](#构建配置文件的自定义符号)，用于在指定构建配置文件处于活动状态时，适用于所有 Editor 和 Player 代码的符号。
- [代码](#通过代码定义的自定义符号)，根据所使用的 API，用于活动平台或单个 Player 构建的符号。

## 整个项目的自定义符号

可以使用[响应文件](https://learn.microsoft.com/en-us/visualstudio/msbuild/msbuild-response-files?view=vs-2022)资源，为整个项目定义自定义脚本符号：

1. 将文件命名为 `csc.rsp`，并将其放在项目 `Assets` 文件夹的根目录中。
2. 在以 `-define:` 开头的行中定义脚本符号，多个脚本符号之间使用分号分隔。

Unity 在启动时读取此文件，并在编译任何代码之前应用其中的设置。例如，如果在 `csc.rsp` 文件中加入唯一一行 `-define:UNITY_DEBUG;UNITY_TEST`，则 `UNITY_DEBUG` 和 `UNITY_TEST` 会作为全局定义的脚本符号，应用于项目中的所有 C# 脚本。

> **注意：** 更改 `.rsp` 文件后，必须等 Unity 重新编译脚本才能生效。可以更新或重新导入一个脚本文件来触发重新编译。

## 平台的自定义符号

可以按以下步骤定义平台专用的自定义脚本符号：

1. 打开 [Player Settings](https://docs.unity3d.com/6000.7/Documentation/Manual/class-PlayerSettings.html)。
2. 在 **Other Settings** > **Script Compilation** 部分中，找到 **Scripting Define Symbols** 列表。
3. 选择 **+** 按钮并在文本字段中输入符号名称，将新的脚本符号添加到列表中。使用 **-** 按钮移除现有列表项。
4. 完成列表编辑后，选择 **Apply** 应用更改。Unity 会使用新符号重新编译项目中的脚本。

> **注意：** **Copy Defines** 按钮会将列表中的当前自定义脚本符号复制到剪贴板，格式为以分号分隔的值字符串。

## 构建配置文件的自定义符号

可以按以下步骤为构建配置文件定义自定义脚本符号：

1. 在 [Build Profiles 窗口](https://docs.unity3d.com/6000.7/Documentation/Manual/build-profiles-reference.html)中，选择要为其定义符号的构建配置文件。
2. 选择 **Add Settings** > **Scripting Defines**。此时会在 **Scripting Defines** 折叠栏中显示脚本定义列表。
3. 选择 **+** 按钮并在文本字段中输入符号名称，将新的脚本符号添加到列表中。使用 **-** 按钮移除现有列表项。列表修改会自动保存并应用。

> **注意：** 可以使用 `-activeBuildProfile` [命令行参数](https://docs.unity3d.com/6000.7/Documentation/Manual/EditorCommandLineArguments.html)启动 Editor，使指定的构建配置文件及其自定义脚本符号从启动时起生效。

## 通过代码定义的自定义符号

可以使用以下 API 定义脚本符号：

- [`PlayerSettings.SetScriptingDefineSymbols`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/PlayerSettings.SetScriptingDefineSymbols.html)
- [`BuildProfile.scriptingDefines`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Build.Profile.BuildProfile-scriptingDefines.html)
- [`BuildPlayerOptions.extraScriptingDefines`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPlayerOptions-extraScriptingDefines.html)
- [`BuildPlayerWithProfileOptions.extraScriptingDefines`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPlayerWithProfileOptions-extraScriptingDefines.html)，在从[构建配置文件](https://docs.unity3d.com/6000.7/Documentation/Manual/build-profiles.html)构建时使用。
- [`Build.Player.ScriptCompilationSettings-extraScriptingDefines`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Build.Player.ScriptCompilationSettings-extraScriptingDefines.html)

`BuildPlayerOptions.extraScriptingDefines`、`BuildPlayerWithProfileOptions.extraScriptingDefines` 和 `Build.Player.ScriptCompilationSettings-extraScriptDefines` 仅适用于 Player 构建，因此不会影响 Editor 脚本。要定义同样适用于 Editor 脚本的脚本符号，请使用 [`PlayerSettings.SetScriptingDefineSymbols`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/PlayerSettings.SetScriptingDefineSymbols.html)，它等价于在 [Player Settings](#平台的自定义符号) 中配置平台专用脚本符号。使用构建配置文件时，应改为设置配置文件的 [`BuildProfile.scriptingDefines`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Build.Profile.BuildProfile-scriptingDefines.html)，因为该设置在配置文件处于活动状态时同时适用于 Editor 和 Player 代码。

> **重要：** 使用 `SetScriptingDefineSymbols` 在代码中创建的符号，必须等 Editor 重新获得控制权并重新编译脚本后才会生效。例如，如果在 Editor 脚本中使用 `SetScriptingDefineSymbols` 创建脚本符号，然后在下一行调用 `BuildPipeline.BuildPlayer`，上一行创建的新符号尚未生效。在这种情况下，作为 `BuildPlayer` 执行过程一部分运行的任何 Editor 代码都不会使用这些新符号，Player 可能无法按预期构建。

### 批处理模式下的自定义符号

Editor 在批处理模式下运行时，没有触发脚本重新编译的机制。如果需要在以批处理模式运行的 Editor 中定义特定符号，则这些符号必须在启动时就已通过[资源文件中的 `csc.rsp` 设置](#整个项目的自定义符号)完成定义。

## 脚本符号继承

如果在多个位置定义自定义脚本符号，Unity 会将适用于当前构建配置的所有符号相加。符号从每个作用域继承，而不是相互覆盖，规则如下：项目范围符号（来自 `csc.rsp`）+ 平台专用符号（来自 Player Settings）+ 构建配置文件符号（来自 Build Data）。只有与活动构建配置文件匹配的平台和构建配置文件符号才会被包含。

例如，假设项目在以下位置定义了以下自定义脚本符号：

| 位置 | 定义的符号 |
| --- | --- |
| `csc.rsp` | `SYMBOL_A` |
| Windows Player Settings | `SYMBOL_B` |
| WindowsBuildProfile1 | `SYMBOL_C` |
| WindowsBuildProfile2 | `SYMBOL_D` |

在此示例配置下，下表显示不同构建配置文件处于活动状态时，Editor 和 Player 代码中处于活动状态的符号：

| 活动的构建配置文件 | 活动的符号 |
| --- | --- |
| Android | `SYMBOL_A` |
| Windows | `SYMBOL_A`、`SYMBOL_B` |
| WindowsBuildProfile1 | `SYMBOL_A`、`SYMBOL_B`、`SYMBOL_C` |
| WindowsBuildProfile2 | `SYMBOL_A`、`SYMBOL_B`、`SYMBOL_D` |

可以在代码中使用 `#if` 指令测试此行为。有关更多信息，请参阅[[04-测试条件编译]]。
