# 预定义程序集参考

> 原文：[Predefined assemblies reference](https://docs.unity3d.com/6000.7/Documentation/Manual/script-compile-order-folders.html)

Unity 会根据脚本文件在项目文件夹结构中的位置，将脚本分为四个独立阶段进行编译。Unity 会为每个阶段创建一个独立的 C# project file（`.csproj`）和一个预定义程序集。如果没有脚本符合某个编译阶段的条件，Unity 不会创建对应的 project file 或程序集。

当脚本引用在不同阶段编译、因而位于不同程序集中的 Class 时，编译顺序很重要。基本规则是：脚本可以引用在其自身编译阶段或更早阶段编译的任何内容，但不能引用在更晚阶段编译的内容。

编译阶段如下：

| 阶段 | 程序集名称 | 脚本文件 |
| --- | --- | --- |
| 1 | `Assembly-CSharp-firstpass` | 位于名为 `Plugins` 的文件夹中的 Runtime 脚本。 |
| 2 | `Assembly-CSharp-Editor-firstpass` | 位于顶层 `Plugins` 文件夹内任意位置、名为 `Editor` 的文件夹中的 Editor 脚本。 |
| 3 | `Assembly-CSharp` | 不在名为 `Editor` 的文件夹中的所有其他脚本。 |
| 4 | `Assembly-CSharp-Editor` | 位于名为 `Editor` 的文件夹中的所有剩余脚本。 |

可以创建 Assembly Definition 文件，使用自定义程序集组织项目中的脚本。定义自定义程序集可以减少无关代码发生更改时 Unity 需要重新编译的代码量，并更好地控制对其他程序集的依赖。更多信息请参阅 [[00-程序集定义|将脚本组织到程序集]]。

Unity 为特定类型的资源保留了一些项目文件夹名称。其中一些文件夹会影响脚本编译顺序。有关这些文件夹的更多信息，请参阅 [保留文件夹名称参考](https://docs.unity3d.com/6000.7/Documentation/Manual/SpecialFolders.html)。
