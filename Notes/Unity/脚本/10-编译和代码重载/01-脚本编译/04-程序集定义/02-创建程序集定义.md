# 创建程序集资源

> 原文：[Creating assembly assets](https://docs.unity3d.com/6000.7/Documentation/Manual/assembly-definitions-creating.html)

可以使用两种特殊类型的资源创建并定义程序集：

- Assembly Definition（`.asmdef`）资源放置在包含脚本的文件夹根目录中，用于定义新程序集。
- Assembly Definition Reference（`.asmref`）资源放置在包含脚本的文件夹根目录中，用于将这些脚本包含到已有程序集中。

<a name="create-asmdef"></a>

## 创建 Assembly Definition

要创建 Assembly Definition：

1. 在 Project 窗口中找到包含要加入程序集的脚本的文件夹。
2. 在该文件夹中创建 Assembly Definition（菜单：**Assets** > **Create** > **Scripting** > **Assembly Definition**）。
3. 为资源指定名称。默认情况下，程序集文件使用分配给资源的名称，但可以在 **Inspector** 窗口中更改该名称。

Unity 会重新编译项目中的脚本以创建新程序集。之后可以编辑新 Assembly Definition 的属性：[[07-程序集定义Inspector窗口参考]]。

新程序集包含 Assembly Definition 所在文件夹中的所有脚本，以及没有自己的 Assembly Definition 或 Reference 文件的子文件夹中的脚本。在适用的情况下，Unity 会将脚本从其原程序集移除。

<a name="create-asmref"></a>

## 创建 Assembly Definition Reference

要创建 Assembly Definition Reference：

1. 在 Project 窗口中找到包含要加入被引用程序集的脚本的文件夹。
2. 在该文件夹中创建 Assembly Reference（菜单：**Assets** > **Create** > **Scripting** > **Assembly Definition Reference**）。
3. 为资源指定名称。

   Unity 会重新编译项目中的脚本以创建新程序集。完成后，可以编辑新 Assembly Definition Reference 的属性：[[08-程序集定义引用Inspector窗口参考]]。

4. 选择新的 Assembly Definition Reference 资源，在 **Inspector** 中查看其属性。
5. 设置 **Assembly Definition** 属性，使其引用目标 Assembly Definition 资源。
6. 点击 **Apply**。

被引用的程序集现在包含 Assembly Definition Reference 所在文件夹中的所有脚本，以及没有自己的 Assembly Definition 或 Reference 文件的子文件夹中的脚本。在适用的情况下，Unity 会将脚本从其原程序集移除。

<a name="create-platform-specific"></a>

## 创建特定于平台的程序集

要为特定平台创建程序集：

1. [[#create-asmdef|创建 Assembly Definition]]。
2. 选择新的 Assembly Definition，在 **Inspector** 中查看其属性。
3. 在 [[07-程序集定义Inspector窗口参考#platforms|Platforms]] 部分中，选中 **Any Platform** 选项并选择要排除的特定平台；或者取消选中 **Any Platform** 并选择要包含的特定平台。
4. 点击 **Apply**。

当为目标平台构建项目时，Unity 会根据此配置包含或排除该程序集。

<a name="create-editor-assembly"></a>

## 为 Editor 代码创建程序集

Editor 程序集允许将 Editor 脚本放在项目中的任意位置，而不只是名为 `Editor` 的顶层文件夹中。

要创建包含项目中 Editor 代码的程序集：

1. 在包含 Editor 脚本的文件夹中[[#create-platform-specific|创建特定于平台的程序集]]。
2. 仅包含 Editor 平台。
3. 如果还有包含 Editor 脚本的其他文件夹，请在这些文件夹中[[#create-asmref|创建 Assembly Definition Reference 资源]]，并将其设置为引用这个 Assembly Definition。

<a name="create-test-assembly"></a>

## 创建测试程序集

测试程序集是 Unity 预期用于包含测试的程序集。将测试放入测试程序集有以下好处：

- 测试代码与将交付给用户的应用程序代码分离，因此只有在需要时才编译测试代码。
- 测试程序集中的测试会自动对 [Test Framework package](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/test-framework-introduction.html) 可见，因此可以从 **Test Runner** 窗口运行这些测试。

如果一个程序集引用了 **nunit.framework.dll**，并且 Assembly Definition References 引用了 **UnityEngine.TestRunner** 和 **UnityEditor.TestRunner**，Unity 会自动将其识别为测试程序集。

有关安装 Test Framework package 和创建测试程序集的说明，请参阅 Unity 的 [Test Framework 文档](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/test-framework-introduction.html)。可以使用 Editor UI 创建一个预先配置相关引用的 Assembly Definition 文件，也可以通过 [[07-程序集定义Inspector窗口参考|Inspector 窗口]]或直接[[06-程序集定义文件格式|编辑 JSON 文件]]手动配置引用。

> **注意**：测试程序集不会作为常规构建管线的一部分进行编译，因此放在测试程序集中的代码会从标准[项目构建](https://docs.unity3d.com/6000.7/Documentation/Manual/BuildSettings.html)中排除。只有通过 **Test Runner** 窗口[运行 Player 中的 Play Mode 测试](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/workflow-run-playmode-test-standalone.html)时，测试程序集代码才会包含在 Player 构建中。如果生产代码意外没有编译进项目构建，请确认它没有放在测试程序集中。
