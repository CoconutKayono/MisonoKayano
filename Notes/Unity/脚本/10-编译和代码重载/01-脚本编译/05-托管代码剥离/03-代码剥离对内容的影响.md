# 代码剥离对内容的影响

> 原文：[How code stripping affects content](https://docs.unity3d.com/6000.7/Documentation/Manual/managed-code-stripping-content.html)

在 Unity 中构建 Player 时，UnityLinker 过程会通过移除未使用的类型来减小程序集体积。此过程可能剥离以下内容：

- 完整的 C# 类型，例如派生自 `MonoBehaviour` 或 `ScriptableObject` 的类。Unity 可以从 `UnityEngine.dll` 和 `Unity.dll` 等核心 Unity 程序集中剥离这些类型，但在自定义程序集被标记为已使用后，会在其中保留这些类型。
- 普通的 C# 结构体和类。
- 类的一部分（例如未使用的方法）。
- 完整的 Unity 模块，例如 AI 或 Physics（如果没有引用该模块中的任何类型）。

代码剥离对内容的影响会在 Player 中表现为 null reference exceptions、missing type errors 或崩溃。与 Player 分开构建的内容无法使用已从 Player 构建中剥离的类型。这适用于 [AssetBundle](https://docs.unity3d.com/6000.7/Documentation/Manual/AssetBundlesIntro.html) 内容、Addressables 内容以及[内容目录](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html)。

你可以使用 [Build Report Inspector](https://github.com/Unity-Technologies/BuildReportInspector) 的 Stripping 选项卡检查 Player 构建中保留了哪些模块和类型。

你可以在以下情况下阻止 Linker 剥离代码：

- [[#prevent-code-stripping-content-directories|阻止剥离内容目录中使用的类型]]
- [[#prevent-code-stripping-assetbundles|阻止剥离 AssetBundles 中使用的类型]]
- [[#prevent-code-stripping-addressables|阻止剥离 Addressables 中使用的类型]]
- [[#prevent-code-stripping-modules|阻止剥离模块代码]]

<a id="prevent-code-stripping-content-directories"></a>

## 阻止剥离内容目录中使用的类型

使用 [`BuildPipeline.BuildContentDirectory`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPipeline.BuildContentDirectory.html) 构建的[内容目录](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-create.html)可能包含不在 Player 构建任何场景或 Asset 中的类型。Unity 可能会从 Player 中剥离这些类型，从而导致内容在运行时加载失败。

每次内容目录构建都会在其 build report 目录中记录它使用的 C# 类型和 Unity object 类型，记录在 `ScriptsOnlyCache.yaml` 文件中。由于此记录包含 Unity object 类型，因此也会保留这些类型所属的模块。

要在 Player 中保留这些类型，请先构建内容目录，再通过以下 API 之一将内容目录的 build report 目录传递给 Player 构建：

- 当你只通过自定义 build script 触发 Player 构建，而不是从 **Build Profiles** 窗口触发时，使用 [`BuildPlayerOptions.previousBuildReportDirectories`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPlayerOptions-previousBuildReportDirectories.html)。
- [`BuildPlayerContext.AddPreviousBuildReportDirectory`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Build.BuildPlayerContext.AddPreviousBuildReportDirectory.html) 同时适用于自定义 build script 和 **Build Profiles** 窗口，因为你会从 [`BuildPlayerProcessor`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Build.BuildPlayerProcessor.html) 的 [build callback](https://docs.unity3d.com/6000.7/Documentation/Manual/build-callbacks.html) 中调用它。你可以在 callback 中构建内容目录，也可以用其他方式定位先前构建的 build report 目录，例如通过 [`BuildHistory`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Build.BuildHistory.html) API 或自己的项目配置来定位。

两个 API 接收的都是 build report 目录，而不是其中 `ScriptsOnlyCache.yaml` 文件的路径。如果该目录不是有效的 build report 目录，Player 构建会报错失败。

有关构建内容目录并在 Player 中保留其类型的完整 build script，请参阅[创建自定义 build script](https://docs.unity3d.com/6000.7/Documentation/Manual/build-script-build.html)。

<a id="prevent-code-stripping-assetbundles"></a>

## 阻止剥离 AssetBundles 中使用的类型

本节适用于使用 [`BuildPipeline.BuildAssetBundles`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPipeline.BuildAssetBundles.html) 构建的 AssetBundles，该 API 会生成 `.manifest` 文件。对于使用 Addressables 或 Scriptable Build Pipeline 构建的 AssetBundles，它们使用 `link.xml` 文件而不是 manifest，请参阅[阻止剥离 Addressables 中使用的类型](#prevent-code-stripping-addressables)。

Unity 可能会剥离存在于 AssetBundles 中、但不在 Player 构建所包含的任何场景或 Asset 中的 Unity object 类型。这意味着 AssetBundle 内容可能在 Play mode 测试时或在使用最小代码剥离的构建中正常工作，但在启用代码剥离的 Player 中构建时会出现错误或崩溃。

要解决此问题，可以创建一个直接包含 AssetBundle manifest 文件的自定义 build script，步骤如下：

1. 在构建 Player 之前[构建 AssetBundle](https://docs.unity3d.com/6000.7/Documentation/Manual/AssetBundles-Building.html)。输出文件夹中会为每个 AssetBundle 包含一个 `.manifest` 文件，并包含一个与输出文件夹同名的根 `.manifest` 文件。
2. 使用 [`BuildPipeline.BuildPlayer`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPipeline.BuildPlayer.html) API，将根 `.manifest` 文件的路径传入 Player 构建过程。

manifest 列出 AssetBundles 使用的 Unity object 类型，因此此方法也会保留这些类型所属的模块。

更多信息请参阅 [AssetBundle 文件格式参考](https://docs.unity3d.com/6000.7/Documentation/Manual/assetbundles-file-format.html) 和 [`BuildPlayerOptions.assetBundleManifestPath`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPlayerOptions-assetBundleManifestPath.html)。

你也可以使用 [[04-使用注释保留代码|Preserve Attribute]] 或在项目中手动编写 [[05-Link XML格式参考|`link.xml`]] 文件，进一步影响代码剥离行为。

<a id="prevent-code-stripping-addressables"></a>

## 阻止剥离 Addressables 中使用的类型

当 Addressables 构建 AssetBundles 时适用本节。如果将 Addressables 配置为改为构建内容目录，请遵循[阻止剥离内容目录中使用的类型](#prevent-code-stripping-content-directories)。

如果使用 [Addressables](https://docs.unity3d.com/Packages/com.unity.addressables@latest) 构建的内容中存在某种 Unity object 类型，但 Player 中构建的任何场景或 Asset 都不存在该类型，则 Unity 可能会剥离该类型。

Addressables 会在 `Library/com.unity.addressables` 文件夹中自动生成一个 [[05-Link XML格式参考|`link.xml`]] 文件，描述内容中使用的类型。只要 Addressables 内容在 Player 构建之前或同时完成构建，Player 构建就会将此 `link.xml` 文件纳入考虑。

你也可以使用 [[04-使用注释保留代码|Preserve Attribute]] 或在项目中手动编写 [[05-Link XML格式参考|`link.xml`]] 文件，进一步影响代码剥离行为。

<a id="prevent-code-stripping-modules"></a>

## 阻止模块剥离

如果需要在 Addressables 或 Scriptable Build Pipeline AssetBundle 构建中使用某个模块的类型，请确保 Player 构建包含引用该模块的内容。例如，要保留 Physics 模块，请将 Rigidbody 或 Collider 等组件添加到构建中包含的场景内某个 GameObject 上。这会创建 Player 构建过程能够识别的依赖关系，并保留该模块。

这是必需的，因为不能使用 `link.xml` 文件阻止完整的 Unity 模块（例如 AI 或 Physics）被剥离。

对于使用 [`BuildPipeline.BuildAssetBundles`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPipeline.BuildAssetBundles.html) 构建的 AssetBundles，或内容目录构建（包括由 Addressables 构建的内容目录），不需要此 workaround。两者都会记录自己使用的 Unity object 类型，因此将 manifest 或 build report 目录传递给 Player 构建后，也会保留这些类型所属的模块。

## 类型使用记录

Player 构建和内容目录构建都会将它们使用的类型记录在 `ScriptsOnlyCache.yaml` 文件中，你可以查看此文件来诊断代码剥离问题：

- Player 构建会将此文件写入 `Library/PlayerDataCache` 文件夹，以支持 [Incremental build pipeline](https://docs.unity3d.com/6000.7/Documentation/Manual/building-introduction.html#incremental-build-pipeline)，该 pipeline 可以复用先前 Player 构建的内容。在这种情况下，Player 构建会将文件中的缓存类型使用记录传递给 Unity Linker。
- 内容目录构建会将此文件写入其 build report 目录。当你将该目录传递给 Player 构建时，Player 构建会将记录的类型使用信息传递给 Unity Linker。更多信息请参阅 [Build history 文件参考](https://docs.unity3d.com/6000.7/Documentation/Manual/build-history-file-reference.html)。

> **注意**：`ScriptsOnlyCache.yaml` 文件使用的格式是内部格式，未来 Unity 版本可能会更改。要控制代码剥离，请在项目中使用 `link.xml` 文件，而不是直接修改此文件。
