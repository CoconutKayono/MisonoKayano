# 在 Managed Code 与 Unmanaged Code 之间传递数据

> 原文：[Pass data between managed and unmanaged code](https://docs.unity3d.com/6000.7/Documentation/Manual/plug-ins-native-pass-data.html)

在 Managed Code 与 Unmanaged Code 之间传递数据时，需要考虑数据如何存储和管理在内存中。本主题说明如何在 Unity 中的 Managed Code 与 Unmanaged Code 之间传递数据。

在 Function 之间传递数据时，参数和返回值可以复制到 Stack，或存储在 Heap 中。Stack 通常用于 Value Type，数据会在 Function Call 持续期间保留。生命周期不易预测的数据存储在 Heap 中。在 C# 中，Scripting Runtime 管理 Heap，包括移动数据以及释放不再使用的内存。在 Unmanaged Code 中，则需要直接请求并管理 Heap Memory。

从 Managed Code 调用 Unmanaged Function，或从 Unmanaged Code 调用 Managed Function 时，双方都可以直接访问 Stack Data。因此，可以直接传递 `float` 和 `int` 等小型 Value Type，无需额外预防措施。无需担心在另一侧访问数据之前数据消失。

但是，传递 String、Array 和某些 Struct 等 Reference Type 与较大的 Value Type 时，数据可能存储在 Heap 中。这种情况下，Managed Code 与 Unmanaged Code 之间传递的只有 Reference 或 Pointer。必须确保数据在可能被访问的整个期间都位于相同的内存位置。

对于普通的 Unmanaged Code 调用，Scripting Runtime 会为你处理这些事项。作为 Marshalling 的一部分，它会使相关 Managed Data 在调用返回前保持存活并位于原处。只有在 Unmanaged Code 保留对数据的引用，并在调用返回后访问数据的高级场景中才需要额外措施，例如异步 Callback，或 Native Code 保存 Pointer 以便稍后使用。在这些情况下，可以使用 [GCHandle](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.interopservices.gchandle?view=net-9.0) Struct 将 Object 固定（“pin”）在内存中。在释放 `GCHandle` 之前，Scripting Runtime 不会移动或释放被固定的 Object。

```csharp
 //Create a GCHandle to pin data in memory
 GCHandle handle = GCHandle.Alloc(yourObject, GCHandleType.Pinned);
 //... pass data to unmanaged code that retains it beyond the call ...
 handle.Free(); //Dispose of the handle when unmanaged code is finished
```
