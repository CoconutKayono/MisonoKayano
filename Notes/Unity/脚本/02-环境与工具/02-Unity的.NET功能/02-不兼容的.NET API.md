# 不兼容的 .NET API

> 原文：[Incompatible .NET API reference](https://docs.unity3d.com/6000.7/Documentation/Manual/dotnet-incompatible-api.html)

Unity Runtime 使用专门的程序集加载和管理系统来支持代码重载。UAC（Unity API Compatibility）Analyzer 会标记一些与 Unity 程序集生命周期不兼容或即将不兼容的 Reflection API。

| 警告代码 | 不兼容的 .NET API | 兼容的 Unity 替代方案 |
| --- | --- | --- |
| `UAC005` | `AppDomain.GetAssemblies` 会返回所有 AssemblyLoadContext（ALC）中已加载的程序集，包括处于卸载状态的程序集。使用这些过期引用可能导致 `TypeLoadException`、`NullReferenceException`、内存泄漏或 Editor 崩溃。 | `CurrentAssemblies.GetLoadedAssemblies` 只返回 Unity 托管环境中当前有效的程序集。 |
| `UAC006` | `AppDomain` 中的某些方法和 Event。它们不会在 Unity 程序集生命周期中正确触发或管理，可能导致代码重载期间 Handler 从不调用或调用时机错误。 | 使用 Unity 的 LifeCycle API 接收程序集卸载通知。 |
| `UAC007` | `Assembly.Location`。Unity 经常从 Memory Stream 加载程序集以避免文件锁定，因此该属性可能返回空字符串。 | `Assembly.GetLoadedAssemblyPath` Extension Method。 |
| `UAC020` | `Assembly.LoadFile` / `Assembly.LoadFrom` 会绕过 Unity 的程序集管理系统，阻止 Unity 在脚本重新编译和代码重载时正确卸载程序集，也可能导致版本冲突。 | `CurrentAssemblies.LoadFromPath`。 |
| `UAC023` | `BinaryFormatter`。该 Serializer 因严重安全漏洞已在现代 .NET 中废弃，不会被 Unity Runtime 支持。 | Unity 内置序列化系统、`JsonUtility` 或 `DataContract`。 |

## 代码迁移示例

下表展示不兼容代码片段及其替代写法：

| Namespace | 不兼容代码 | 替代代码 |
| --- | --- | --- |
| `UnityEngine.Assemblies` | `AppDomain.CurrentDomain.GetAssemblies()` | `CurrentAssemblies.GetLoadedAssemblies()` |
| `Unity.Scripting.LifecycleManagement` | `AppDomain.CurrentDomain.DomainUnload` | `[OnAssemblyUnloading]` |
| `UnityEngine` | `assembly.Location` | `assembly.GetLoadedAssemblyPath()` |
| `UnityEngine.Assemblies` | `Assembly.LoadFile(path)` | `CurrentAssemblies.LoadFromPath(path)` |
