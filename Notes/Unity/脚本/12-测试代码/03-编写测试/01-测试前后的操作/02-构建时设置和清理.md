# 构建时设置和清理

> 原文：[Setting up and cleaning up at build time](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/reference-setup-and-cleanup.html)

有时你可能需要在构建测试之前修改 Unity 或文件系统，然后在测试运行后清理这些修改。你可以通过以下任一方式，将构建前设置和构建后清理阶段纳入测试：

- 在测试类中实现 [IPrebuildSetup](https://docs.unity3d.com/Packages/com.unity.test-framework@latest/index.html?subfolder=/api/UnityEngine.TestTools.IPrebuildSetup.html) 和 [IPostBuildCleanup](https://docs.unity3d.com/Packages/com.unity.test-framework@latest/index.html?subfolder=/api/UnityEngine.TestTools.IPostBuildCleanup.html) 接口。
- 将 [`[PrebuildSetup]`](https://docs.unity3d.com/Packages/com.unity.test-framework@latest/index.html?subfolder=/api/UnityEngine.TestTools.PrebuildSetupAttribute.html) 和 [`[PostBuildCleanup]`](https://docs.unity3d.com/Packages/com.unity.test-framework@latest/index.html?subfolder=/api/UnityEngine.TestTools.PostBuildCleanupAttribute.html) 特性应用于测试类、单个测试或测试程序集，并将实现相应接口的类作为参数传入。例如，可以使用 `[PrebuildSetup("MyTestSceneSetup")]` 修饰测试方法，以执行名为 `MyTestSceneSetup` 且实现 `IPrebuildSetup` 的类中定义的构建前设置工作。

如果应用了 `PrebuildSetup` 或 `PostBuildCleanup` 特性的测试或测试类包含在当前测试运行中，这两个特性都会运行。当你运行所有测试，或定义一个包含该测试的[筛选器](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/extension-run-tests.html)时，该测试就会包含在测试运行中。如果多个测试引用相同的构建前设置或构建后清理，则该设置或清理只运行一次。

以下示例在测试类上实现 `IPrebuildSetup`，以定义构建测试前要执行的工作：

```csharp
[TestFixture]
public class CreateSpriteTest : IPrebuildSetup
{
    Texture2D m_Texture;
    Sprite m_Sprite;
    
    public void Setup()
    {

#if UNITY_EDITOR

        var spritePath = "Assets/Resources/Circle.png";

        var ti = UnityEditor.AssetImporter.GetAtPath(spritePath) as UnityEditor.TextureImporter;

        ti.textureCompression = UnityEditor.TextureImporterCompression.Uncompressed;

        ti.SaveAndReimport();

#endif
    }

    [SetUp]
    public void SetUpTest()
    {
        m_Texture = Resources.Load<Texture2D>("Circle");
    }

    [Test]
    public void WhenNullTextureIsPassed_CreateShouldReturnNullSprite()
    {

        // Check with Valid Texture.

        LogAssert.Expect(LogType.Log, "Circle Sprite Created");

        Sprite.Create(m_Texture, new Rect(0, 0, m_Texture.width, m_Texture.height), new Vector2(0.5f, 0.5f));

        Debug.Log("Circle Sprite Created");

        // Check with NULL Texture. Should return NULL Sprite.

        m_Sprite = Sprite.Create(null, new Rect(0, 0, m_Texture.width, m_Texture.height), new Vector2(0.5f, 0.5f));

        Assert.That(m_Sprite, Is.Null, "Sprite created with null texture should be null");

    }
}
```

> **提示**：如果设置/清理位于 **Play Mode** 程序集中，但需要访问仅限 Editor 的 API，请使用 `#if UNITY_EDITOR`。

## 使用测试数据进行设置和清理

你可以使用 [IPrebuildSetupWithTestData](https://docs.unity3d.com/Packages/com.unity.test-framework@latest/index.html?subfolder=/api/UnityEngine.TestTools.IPrebuildSetupWithTestData.html) 和 [IPostBuildCleanupWithTestData](https://docs.unity3d.com/Packages/com.unity.test-framework@latest/index.html?subfolder=/api/UnityEngine.TestTools.IPostBuildCleanupWithTestData.html) 接口，定义可以访问 [Test Data](https://docs.unity3d.com/Packages/com.unity.test-framework@latest/index.html?subfolder=/api/UnityEngine.TestTools.TestData.html) 的设置和清理方法。测试数据包含即将运行或刚刚运行的测试的信息。

相应的特性也存在，并且适用上文规定的相同规则和模式。

## 执行顺序

所有设置都会按确定的顺序逐一运行。使用特性定义的设置首先运行。然后，任何实现接口的测试类都会运行；这些测试类在其命名空间内按字母顺序排列，这与测试运行的顺序相同。

提供 `TestData` 对象的设置会按照上述顺序，在所有不提供数据的设置之前运行。清理操作也遵循相同规则。

在 Player 构建中，清理会在测试结束后立即运行；在 Unity Editor 中，清理只会在相关测试完成后运行。
