# 17. 以代码方式运行测试

> 原文：[17. Running tests programmatically](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/course/running-tests-programmatically.html)

## 学习目标

本节将介绍 `TestRunnerApi`，并教你如何以代码方式触发测试运行。

## 简介与动机

Test Framework 最近新增了 `TestRunnerApi`。这个 API 允许你以代码方式与 Test Framework 交互，例如列出测试、运行测试以及接收测试结果。

详细信息和示例请参阅 [TestRunnerApi 文档](https://docs.unity3d.com/Packages/com.unity.test-framework@latest/api/UnityEditor.TestTools.TestRunner.Api.TestRunnerApi.html)。

## 练习

[sample](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/course/test-framework-general-introduction.html#import-samples) `17_RunningTestsProgrammatically` 包含一个名为 `MyMonoBehaviour` 的 MonoBehaviour 脚本，该脚本有一个表示自身是否已配置的属性。项目还包含一个 Scene，其中有多个挂载了 `MyMonoBehaviour` 的 GameObject。

任务是创建一组 Scene 验证测试，验证 `MyScene.unity` 是否满足以下条件：

- Scene 中恰好有 5 个挂载了 `MyMonoBehaviour` 的 GameObject。
- 所有挂载了 `MyMonoBehaviour` 的 GameObject 都必须将 `IsConfigured` 设置为 `true`。

创建这些测试后，实现一个 `MenuItem`，使用 `TestRunnerApi` 触发 Scene 验证测试的运行，并将结果报告到 Console 日志。

建议为 Scene 验证测试设置一个 category，这样更容易创建只运行这些测试的过滤器。

## 提示

- 记得在传给 `Execute` 的过滤器中包含测试模式。
