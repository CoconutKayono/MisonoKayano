# 14. 保留测试状态

> 原文：[14. Preserve test state](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/course/preserve-test-state.html)

## 学习目标

本节将介绍如何使用序列化，让测试中的变量和信息在 Domain Reload 后继续保留。

## 简介与动机

发生 Domain Reload 时，所有脚本都会重新加载。这也意味着测试类成员中的大多数数据都会丢失。在某些情况下这会造成问题，因为你可能希望在 Domain Reload 期间保留某些信息。

解决方案是使用序列化。如果为相关字段添加 `[SerializeField]` 属性，该字段就会保留其值。请注意，Unity 的序列化存在一些限制，参阅 [Unity 序列化](https://docs.unity3d.com/6000.7/Documentation/Manual/script-serialization.html)。

## 练习

[sample](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/course/test-framework-general-introduction.html#import-samples) `14_PreserveTestState` 包含上一项练习的解决方案，但文件名现在改成了 GUID。

这意味着为了正确清理，`TearDown` 方法需要知道文件名。

目前，第一次运行测试时，`TearDown` 会因为没有获得文件名而失败。之后再次运行测试时，又会因为存在多个包含相同 C# 脚本的重复文件而失败。

任务是使用序列化修复文件名信息丢失的问题。

## 解决方案

解决方案很简单：只需为文件名字段添加 `[SerializeField]` 属性。该解决方案包含在 sample `14_PreserveTestState_Solution` 中。
