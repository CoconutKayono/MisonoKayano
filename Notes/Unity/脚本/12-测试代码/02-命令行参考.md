# 命令行参考

> 原文：[Command-line reference](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/reference-command-line.html)

Unity Test Framework 会在常规 [Unity Editor 命令行参数](https://docs.unity3d.com/6000.7/Documentation/Manual/EditorCommandLineArguments.html) 的基础上添加以下参数：

| 命令 | 描述 |
| --- | --- |
| `-assemblyNames` | 要在本次运行中包含的测试程序集列表，以分号分隔。分号分隔的列表应格式化为包含在引号中的字符串，例如 `-assemblyNames "firstAssembly;secondAssembly"`。 |
| `-forgetProjectPath` | 防止 Unity 将当前项目保存到 Unity Launcher/Hub 历史记录中。 |
| `-orderedTestListFile` | 指向 `.txt` 文件的路径，该文件包含要按指定顺序运行的完整测试名称。只要格式为文本，对文件名没有限制。每个测试占一行；如果测试有参数，请一并指定。<br><br>此类文件的内容示例：<br><br>`Unity.Framework.Tests.OrderedTests.NoParameters`<br>`Unity.Framework.Tests.OrderedTests.ParametrizedTestA(3,2)`<br>`Unity.Framework.Tests.OrderedTests.ParametrizedTestB("Assets/file.fbx")`<br>`Unity.Framework.Tests.OrderedTests.ParametrizedTestD(1.0f)`<br>`Unity.Framework.Tests.OrderedTests.ParametrizedTestE(null)`<br>`Unity.Framework.Tests.OrderedTests.ParametrizedTestF(False, 1)`<br>`Unity.Framework.Tests.OrderedTests.ParametrizedTestG(float.NaN)`<br>`Unity.Framework.Tests.OrderedTests.ParametrizedTestH(SomeEnum)` |
| `-playerHeartbeatTimeout` | 定义 Editor 在 Player 上启动测试运行后等待心跳的时长，单位为秒。默认值为 10 分钟。 |
| `-randomOrderSeed` | 用于随机化项目中测试（独立于测试夹具）的非零整数种子值。<br><br>`# normal order`<br>`Test_1`<br>`Test_2`<br>`Test_3`<br>`Test_4`<br><br>`# randomized with seed x`<br>`Test_3`<br>`Test_1`<br>`Test_4`<br>`Test_2`<br><br>`# randomized with same seed x and a new test`<br>`Test_3`<br>`Test_5`<br>`Test_1`<br>`Test_4`<br>`Test_2` |
| `-repeat` | 设置重复次数的整数。成功的测试最多重复此次数，或在测试失败时停止，以先发生者为准。 |
| `-retry` | 设置重试次数的整数。失败的测试最多重试此次数，或在测试成功时停止，以先发生者为准。 |
| `-runSynchronously` | 提供此参数可同步运行测试，确保所有测试都在同一个 Editor 更新调用中运行。此参数仅支持 Edit Mode 测试。需要跨越多帧的测试（例如带有 `[UnityTest]` 的测试），以及带有 `[UnitySetUp]` 或 `[UnityTearDown]` 脚手架的测试，都会被过滤掉。 |
| `-runTests` | 在项目中运行测试。 |
| `-testCategory` | 要在本次运行中包含的测试类别列表，以分号分隔；也可以使用正则表达式模式匹配类别名称。分号分隔的列表应格式化为包含在引号中的字符串，例如 `-testCategory "firstCategory;secondCategory"`。如果同时提供 `-testFilter` 和 `-testCategory`，则只运行同时匹配两者的测试。此参数支持使用 `!` 进行否定。使用 `!MyCategory` 可将带有 `MyCategory` 类别的测试排除在本次运行之外。 |
| `-testfilter` | 要运行的测试名称列表，以分号分隔；也可以使用正则表达式模式按测试的完整名称进行匹配。分号分隔的列表应格式化为包含在引号中的字符串，例如 `testFilter "Low;Medium"`。此参数支持使用 `!` 进行否定。测试筛选器 `!MyNamespace.Something.MyTest` 会运行除名为 `MyNamespace.Something.MyTest` 之外的所有测试。<br><br>按如下方式运行参数化测试的特定变体：`"ClassName\.MethodName\(Param1,Param2\)"`。 |
| `-testPlatform` | 运行测试的平台。可接受的值：<ul><li>`EditMode`：Edit Mode 测试。等同于从 **Test Runner** 窗口的 EditMode 标签页运行测试。</li><li>`PlayMode`：在 Editor 中运行的 Play Mode 测试。等同于从 **Test Runner** 窗口的 PlayMode 标签页运行测试。</li><li><a href="https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildTarget.html">BuildTarget</a> 枚举中的任意值：在为指定平台构建的 Player 上运行 Play Mode 测试。等同于使用 Test Runner 窗口 Player 标签页中的 Run All 选项。</li></ul><strong>注意</strong>：如果未为此参数指定值，则测试会在 Edit Mode 中运行。 |
| `-testResults` | 指定 Unity 保存测试结果文件的路径。默认情况下，Unity 会将文件保存在项目根文件夹中。测试结果遵循 NUnit 定义的 XML 格式；更多信息请参阅 [Test Result XML Format](https://docs.nunit.org/articles/nunit/technical-notes/usage/Test-Result-XML-Format.html)。目前，对于被测 Unity 各组件报告的退出代码，还没有通用定义。了解问题来源的最佳方式是查看错误消息和堆栈跟踪的内容。 |
| `-testSettingsFile` | 指向 [TestSettings.json](#test-settings) 文件的路径。 |

**注意**：Editor 的常规 `-quit` 命令行参数在测试运行期间不受支持。

## 测试设置参考

你可以在 `TestSettings.json` 文件中定义测试运行的选项。可以使用 `-testSettingsFile` 命令行参数指定此文件的位置。

以下示例展示了一个典型 `TestSettings.json` 文件的内容：

```json
{
  "scriptingBackend":"WinRTDotNET",
  "Architecture":null,
  "apiProfile":0,
  "featureFlags": { "requiresSplashScreen": true }
}
```

下表列出了 `TestSettings.json` 文件的有效选项和值：

| 选项 | 描述 |
| --- | --- |
| `apiProfile` | [.NET API 兼容级别](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/ApiCompatibilityLevel.html)。设置为以下值之一：<ul><li>1 - .Net 2.0</li><li>2 - .Net 2.0 Subset</li><li>3 - .Net 4.6</li><li>5 - .Net micro profile（当 **Stripping Level** 设置为 **Use micro mscorlib** 时，由 Mono 脚本后端使用）</li><li>6 - .Net Standard 2.0</li></ul> |
| `appleEnableAutomaticSigning` | 启用 Apple 设备的自动签名。更多信息请参阅 [PlayerSettings.iOS.appleEnableAutomaticSigning](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/PlayerSettings.iOS-appleEnableAutomaticSigning.html)。 |
| `appleDeveloperTeamID` | 设置 Apple 开发者帐户的团队 ID。更多信息请参阅 [PlayerSettings.iOS.appleDeveloperTeamID](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/PlayerSettings.iOS-appleDeveloperTeamID.html)。 |
| `architecture` | 目标 [Android 架构](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/AndroidArchitecture.html)。设置为以下值之一：<ul><li>None = 0</li><li>ARMv7 = 1</li><li>ARM64 = 2</li><li>All = 4294967295</li></ul> |
| `iOSManualProvisioningProfileType` | 更多信息请参阅 [PlayerSettings.iOS.iOSManualProvisioningProfileType](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/PlayerSettings.iOS-iOSManualProvisioningProfileType.html)。设置为以下值之一：<ul><li>0 - Automatic</li><li>1 - Development</li><li>2 - Distribution；[iOSManualProvisioningProfileID](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/PlayerSettings.iOS-iOSManualProvisioningProfileID.html)</li></ul> |
| `iOSTargetSDK` | iOS 的目标 SDK。设置为以下值之一，并以包含在引号中的字符串字面量形式提供：<ul><li>DeviceSDK</li><li>SimulatorSDK</li></ul> |
| `tvOSManualProvisioningProfileType` | 更多信息请参阅 [PlayerSettings.iOS.tvOSManualProvisioningProfileType](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/PlayerSettings.iOS-tvOSManualProvisioningProfileType.html)。设置为以下值之一：<ul><li>0 - Automatic</li><li>1 - Development</li><li>2 - Distribution；[tvOSManualProvisioningProfileID](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/PlayerSettings.iOS-tvOSManualProvisioningProfileID.html)</li></ul> |
| `tvOSTargetSDK` | tvOS 的目标 SDK。设置为以下值之一，并以包含在引号中的字符串字面量形式提供：<ul><li>DeviceSDK</li><li>SimulatorSDK</li></ul> |
| `scriptingBackend` | 设置为以下值之一，并以包含在引号中的字符串字面量形式提供：<ul><li>Mono2x</li><li>IL2CPP</li></ul> |
| `playerGraphicsAPI` | 设置测试在 Player 中执行时使用的图形 API。值可以是任意一个 [GraphicsDeviceType](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Rendering.GraphicsDeviceType.html)，并以包含在引号中的字符串字面量形式提供。只有当该值受目标平台支持时，才会进行设置。 |
| `webGLClientBrowserType` | 使用 WebGL 平台运行测试时所使用的浏览器。可接受的浏览器类型：<ul><li>Safari</li><li>Firefox</li><li>Chrome</li><li>Chromium</li></ul> |
| `webGLClientBrowserPath` | 设备上浏览器位置的绝对路径。如果未定义，则使用 `UNITY_AUTOMATION_DEFAULT_BROWSER_PATH` 环境变量中的路径。 |
| `androidBuildAppBundle` | 允许为测试构建 Android App Bundle（AAB）而不是 APK 的布尔设置。 |
| `featureFlags` | 可以打开或关闭 Unity Test Framework 功能的字符串和布尔值映射。目前支持的功能包括：<ul><li>`fileCleanUpCheck`：如果测试生成了未清理的文件，则抛出错误消息（而不是警告）。默认关闭。</li><li>`requiresSplashScreen`：默认情况下，Unity Test Framework 会禁用 Made with Unity 启动画面，以加快 Player 构建和测试运行。将此标志设置为 `true` 可覆盖默认行为，始终在 Player 构建中包含 Made with Unity 启动画面。</li></ul> |
