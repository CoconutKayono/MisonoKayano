# 使用自定义更新管理器

> 原文：[Using a custom update manager](https://docs.unity3d.com/6000.7/Documentation/Manual/events-per-frame-optimization.html)

Unity 内置的逐帧[事件函数](https://docs.unity3d.com/6000.7/Documentation/Manual/event-functions.html)更新（例如 `Update`、`FixedUpdate` 和 `LateUpdate`）在项目规模较大时可能影响性能。虽然这些回调会在 C# `MonoBehaviour` 脚本上调用，但函数调用来自 Unity 的 Native Code。Unity 必须维护内部列表，跟踪要调用这些更新函数的对象；`MonoBehaviour` 实例启用或停用时，会分别加入或移出这些列表。

为每个需要更新的 `MonoBehaviour` 实例添加相应回调很方便，但随着回调数量增加，这种方式会变得低效。从 Native Code 调用 Managed Code 回调有一项虽小但有意义的开销，可能导致：

- 调用大量 `Update` 回调时，Frame Time 变差。
- 实例化包含大量 `MonoBehaviour` 的 Prefab 时，调用每个 Component 的 `Awake` 和 `OnEnable` 回调会增加实例化时间。

为避免这些问题，可以创建一个全局的自定义 Update Manager Singleton，让 `MonoBehaviour` 脚本甚至普通 C# 对象订阅它，而不是依赖内置回调。Update Manager Singleton 可以将 `Update`、`LateUpdate` 和其他回调分发给订阅者，使所有更新代码都留在 Managed Layer 中。对象没有操作需要执行时，还可以取消订阅，从而减少每帧必须调用的函数数量。

## 何时使用自定义 Update Manager

当带有逐帧更新回调的 `MonoBehaviour` 实例达到数百或数千个时，自定义 Update Manager 可能带来收益。

消除很少执行的回调也能显著提升性能。例如：

```csharp
void Update()
{
    if (!someVeryRareCondition)
        return;

    // ... 某些操作 ...
}
```

如果项目中有许多类似的 `MonoBehaviour`，调用 `Update` 所花费的大量时间可能用于在 Native Code 和 Managed Code 之间切换，随后又立即退出。如果这些类只在 `someVeryRareCondition` 为 true 时订阅全局 Update Manager，并在条件不满足后取消订阅，就可以减少代码域切换和检查条件的开销。

> [!IMPORTANT]
> 自定义 Update Manager 不是适用于所有项目的通用方案。必须使用 [Profiler](https://docs.unity3d.com/6000.7/Documentation/Manual/Profiler.html) 分析项目的具体性能问题，确认它是否适合当前项目。根据项目中具体的性能瓶颈，也可以考虑将项目转换为使用 Entity Component System（ECS）架构，或[自定义 Player loop](04-自定义Player%20Loop.md)。

## 自定义 Update Manager 示例

首先创建一个 C# 脚本，定义更新接口：

```csharp
public interface IUpdatable
{
    void CustomUpdate(float deltaTime);
}
```

然后创建作为 Update Manager Singleton 的 `MonoBehaviour`。它实现内置的 `Update` 回调，其他 `MonoBehaviour` 脚本 Component 订阅它，而不是直接实现 `Update`：

```csharp
using System.Collections.Generic;
using UnityEngine;

// Singleton Update Manager。将它附加到 Scene 中的 GameObject。
public class UpdateManager : MonoBehaviour
{
    private static UpdateManager _instance;
    public static UpdateManager Instance => _instance;

    private readonly List<IUpdatable> updatables = new List<IUpdatable>();

    void Awake()
    {
        if (_instance == null)
            _instance = this;
        else
            Destroy(gameObject);
    }

    public void Register(IUpdatable updatable)
    {
        if (!updatables.Contains(updatable))
            updatables.Add(updatable);
    }

    public void Unregister(IUpdatable updatable)
    {
        updatables.Remove(updatable);
    }

    void Update()
    {
        float deltaTime = Time.deltaTime;

        // 可选：如果允许在遍历期间移除对象，为了性能可以反向遍历。
        foreach (var updatable in updatables)
        {
            updatable.CustomUpdate(deltaTime);
        }
    }
}
```

最后创建一个 `MonoBehaviour` 脚本 Component，在启用时注册到 Update Manager，在停用时取消注册。下面的示例使用自定义更新回调移动父 `GameObject`：

```csharp
using UnityEngine;

// 脚本 Component。将它附加到 Scene 中的 GameObject，
// 让它在每次自定义更新时移动。
public class MyMovingObject : MonoBehaviour, IUpdatable
{
    void OnEnable()
    {
        UpdateManager.Instance.Register(this);
    }

    void OnDisable()
    {
        if (UpdateManager.Instance != null)
            UpdateManager.Instance.Unregister(this);
    }

    public void CustomUpdate(float deltaTime)
    {
        // 在这里编写更新逻辑。
        transform.position += Vector3.right * deltaTime;
    }
}
```
