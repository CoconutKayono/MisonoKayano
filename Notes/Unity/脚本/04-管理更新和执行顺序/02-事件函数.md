# 事件函数

> 原文：[Event functions](https://docs.unity3d.com/6000.7/Documentation/Manual/event-functions.html)

Event Function 是一组所有 `MonoBehaviour` 脚本 Component 都可能接收的预定义回调。它们由不同的 Unity Editor 和 Engine 事件触发，包括：

- 常规帧更新和 Physics 更新。
- Scene 和对象生命周期事件，例如 Scene 中对象的初始化和销毁。
- UI 事件。
- Input 事件。
- Physics 事件。

在继承 `MonoBehaviour` 的类中实现正确的方法签名，就可以让 GameObject 响应这些源事件。完整回调列表请参阅 `MonoBehaviour` API 参考中的 **Messages** 部分。下面概览几组重要的 Event Function。

## 常规更新事件

运行中的游戏会持续渲染一系列帧。游戏编程的一个关键概念是在每帧渲染前修改对象的位置、状态和行为。`Update` 是 Unity 中编写这类代码的主要位置。`Update` 会在帧渲染前调用，也会在计算 Animation 前调用。

Physics 系统也会以离散时间步更新，方式与帧渲染类似。每次 Physics 更新前都会调用单独的 `FixedUpdate`。Physics 更新和帧更新的频率并不相同，因此将 Physics 代码放在 `FixedUpdate` 而不是 `Update` 中，通常可以得到更准确的结果。

有时还需要在所有对象的 `Update` 和 `FixedUpdate` 执行完毕、所有 Animation 计算完成后再进行修改。例如：

- Camera 应始终对准目标对象时，必须在目标对象移动后再调整 Camera 的方向。
- 脚本代码需要覆盖 Animation 的效果时，例如让角色的头部朝向 Scene 中的目标对象。

这类情况可以使用 `LateUpdate`。关于帧更新和 Physics 更新在整个 Event Function 顺序中的位置，请参阅 [[03-事件函数执行顺序]]。

## 初始化事件

通常需要在游戏过程中的任何更新发生前执行初始化代码。对象上的 `Start` 会在第一次帧更新或 Physics 更新前调用。Scene 加载时，会为 Scene 中的每个对象调用 `Awake`。

各种对象的 `Start` 和 `Awake` 调用顺序是不确定的，但所有 `Awake` 都会在第一次 `Start` 调用前完成。因此，`Start` 中的代码可以使用其他对象在 `Awake` 阶段完成的初始化。

关于初始化函数在整个 Event Function 顺序中的位置，请参阅 [[03-事件函数执行顺序]]。

## GUI 事件

对于使用旧版 IMGUI UI 系统的项目，`MonoBehaviour.OnGUI` 回调会定期调用，用于绘制和管理 UI 元素。

> [!NOTE]
> 即使 `OnGUI` 为空，只要将它添加到 Scene 中的对象上，也会把 IMGUI 处理加入帧处理过程，产生额外开销。只有项目使用 IMGUI UI 系统时才使用 `OnGUI`；该系统已经不再推荐使用。

## Input 事件

`MonoBehaviour` 还提供了一组以 `OnMouse` 为前缀的 Event Function（例如 `OnMouseOver`、`OnMouseDown`），用于响应鼠标操作。这些回调只支持使用旧版 Input Manager 的项目，该系统也已不再推荐使用。

## Physics 事件

Physics 系统会通过调用对象脚本 Component 上的 Event Function，报告与对象发生的 Collision。`OnCollisionEnter`、`OnCollisionStay` 和 `OnCollisionExit` 分别在接触建立、持续和结束时调用。对应的 `OnTriggerEnter`、`OnTriggerStay` 和 `OnTriggerExit` 会在对象的 Collider 被配置为 Trigger Collider 时调用。

关于 Physics Event Function 的更多信息，请参阅 Collider Interaction 文档。
