# 升级到 URP 17.1（Unity 6.1）

> 原文：[Upgrade to URP 17.1 (Unity 6.1)](https://docs.unity3d.com/6000.7/Documentation/Manual/urp/upgrade-guide-unity-6-1.html)


本页面介绍如何从旧版本的通用渲染管线 (URP) 升级到 URP 17.1（Unity 6.1）。

**注意：**要升级到 URP 17.2（Unity 6.2）及更高版本，请参阅主要的[升级 Unity](https://docs.unity3d.com/6000.7/Documentation/Manual/UpgradeGuides.html)部分。

有关将为内置渲染管线项目制作的资源转换为与 URP 兼容的资源的信息，请参阅[[06-使用渲染管线转换器转换资源]]页面。

## 从 URP 17.0（Unity 6.0）升级

### `_FORWARD_PLUS` 着色器关键字已弃用

在 Unity 6.1 中，`FORWARD_PLUS` 着色器关键字已弃用。在自定义着色器中改用 `CLUSTER_LIGHT_LOOP` 关键字。

有关如何使用这些关键字的更多信息，请参阅 [URP 中的着色器关键字和宏参考](https://docs.unity3d.com/6000.7/Documentation/Manual/urp/urp-shaders/shader-keywords-macros.html)。

## 从 URP 15 或 URP 16（Unity 2023.1、Unity 2023.2）升级

### 渲染图系统

URP 17 引入了[[01-URP 中的渲染图系统简介]]系统，其中包含编写自定义渲染通道方式的重大变化。

如果项目包含自定义渲染通道，请使用渲染图 API 重写这些通道。有关渲染图的更多信息，请参阅[[00-URP 中的渲染图系统]]部分。

如需查看使用渲染图 API 的 Scriptable Renderer Feature 及渲染通道的完整示例，请执行以下步骤：

1. 导入 URP 渲染图示例。有关更多信息，请参阅[[04-URP 的包示例参考]]。
2. 在 **Project** 窗口中，转到 **Samples** > **Universal Render Pipeline** > **17.2.0** > **URP RenderGraph Samples**。

**注意：**Unity 不再开发或改进不使用[[00-URP 中的渲染图系统]]的渲染路径。

在新的 URP 项目中，渲染图默认启用。

为保持兼容性，Unity 6 提供了禁用渲染图系统并使用早期 URP 版本渲染 API 的选项。要禁用渲染图，请启用以下复选框：

- **Project Settings** > **Graphics** > **Render Graph** > **Compatibility Mode (Render Graph Disabled)**

如果使用 Unity 6 打开一个由不包含渲染图的 URP 版本创建的现有项目，Unity 会在打开项目后自动启用兼容性模式。

如需进一步了解渲染图的实现，请参阅[[08-在 URP 中分析渲染图]]。

### Volume 框架

创建覆盖 `VolumeComponent.Override(VolumeComponent state, float interpFactor)` 方法的自定义 Volume 组件类时，每当更改 `VolumeParameter` 值，都必须在实现中将 `VolumeParameter.overrideState` 属性设置为 `true`。这样可确保 Volume 框架将参数重置为正确的默认值，并让框架每帧使用更少的资源，从而提高性能。

## 从 URP 13（Unity 2022.1）升级

### 删除了两个着色器定义

删除了 `SHADER_QUALITY_LOW/MEDIUM/HIGH` 和 `SHADER_HINT_NICE_QUALITY` 着色器定义。如果在自定义着色器中使用了这些定义，请考虑使用 `SHADER_API_MOBILE` 或 `SHADER_API_GLES` 定义替换 `SHADER_QUALITY_LOW/MEDIUM/HIGH`。

## 从 URP 12（Unity 2021.2）升级

### ScriptableRenderer API 行为的更改

现在，当 `ScriptableRendererFeature` 实例尝试在 `ScriptableRenderer` 类分配渲染目标之前访问渲染目标时，Unity 会发出错误。

`ScriptableRendererFeature` 类新增了虚函数 `SetupRenderPasses`，该函数会在渲染目标分配完毕并准备使用时调用。

如果代码在 `AddRenderPasses` 方法重写中使用 `ScriptableRenderer.cameraColorTarget` 或 `ScriptableRenderer.cameraDepthTarget` 属性，应将该实现移到 `ScriptableRendererFeature.SetupRenderPasses` 方法中。

对 `ScriptableRenderer.EnqueuePass` 方法的调用仍应放在 `AddRenderPasses` 方法中。

以下示例展示了如何更改代码以使用新 API。

使用旧 API 的代码：

```cs
public override void AddRenderPasses(ScriptableRenderer renderer,
                                    ref RenderingData renderingData)
{
    // The target is used before allocation
    m_CustomPass.Setup(renderer.cameraColorTarget);
     // Letting the renderer know which passes are used before allocation
    renderer.EnqueuePass(m_ScriptablePass);
}
```

使用新 API 的代码：

```cs
public override void AddRenderPasses(ScriptableRenderer renderer,
                                        ref RenderingData renderingData)
{
    // Letting the renderer know which passes are used before allocation
    renderer.EnqueuePass(m_ScriptablePass);
}

public override void SetupRenderPasses(ScriptableRenderer renderer,
                                          in RenderingData renderingData)
{
    // The target is used after allocation
    m_CustomPass.Setup(renderer.cameraColorTarget);
}
```

### Universal Renderer 现在使用 RTHandle 系统

Universal Renderer 现在使用 [RTHandle 系统](https://docs.unity3d.com/Packages/com.unity.render-pipelines.core@14.0/manual/rthandle-system.html)管理内部目标和内部通道。

`RenderTargetHandle` 结构体的所有用法都已标记为过时，该结构体将在未来移除。

公共接口 `ScriptableRenderer.cameraColorTarget` 和 `ScriptableRenderer.cameraDepthTarget` 已标记为过时。分别将它们替换为 `ScriptableRenderer.cameraColorTargetHandle` 和 `ScriptableRenderer.cameraDepthTargetHandle`。

`RTHandle` 目标不使用 `CommandBuffer.GetTemporaryRT` 方法，并且比 `RenderTargetIdentifier` 结构体持续存在更多帧。分配 `RTHandle` 目标时，`GraphicsFormat` 和 `DepthBufferBits` 属性只能设置为 0。`cameraDepthTarget` 属性必须与 `cameraColorTarget` 属性分开。

以下辅助函数可让您使用 RTHandle 系统创建和使用临时渲染目标，方式类似于以前使用 `GetTemporaryRT` 方法的方式：

- `RenderingUtils.ReAllocateIfNeeded`
- `ShadowUtils.ShadowRTReAllocateIfNeeded`

如果渲染目标在应用程序生命周期内不会改变，请使用 `RTHandles.Alloc` 方法分配 `RTHandle` 目标。此方法效率较高，因为代码不必每帧检查是否应分配渲染目标。

如果渲染目标是全屏纹理，即其分辨率与屏幕分辨率相同或为屏幕分辨率的一部分，请使用 `Vector2D.one` 等缩放因子来支持动态缩放。

以下示例展示了如何将使用 `RenderTargetHandle` API 的代码更改为使用新 API。

使用旧 API 的代码：

```cs
public class CustomPass : ScriptableRenderPass
{
    RenderTargetHandle m_Handle;
    // 使用旧 API 时，RenderTargetIdentifier 可能合并颜色和深度
    RenderTargetIdentifier m_Destination;

    public CustomPass()
    {
        m_Handle.Init("_CustomPassHandle");
    }

    public override void OnCameraSetup(CommandBuffer cmd, ref RenderingData renderingData)
    {
        var desc = renderingData.cameraData.cameraTargetDescriptor;
        cmd.GetTemporaryRT(m_Handle.id, desc, FilterMode.Point);
    }

    public override void OnCameraCleanup(CommandBuffer cmd)
    {
        cmd.ReleaseTemporaryRT(m_Handle.id);
    }

    public void Setup(RenderTargetIdentifier destination)
    {
        m_Destination = destination;
    }

    public override void Execute(ScriptableRenderContext context,
                                    ref RenderingData renderingData)
    {
        CommandBuffer cmd = CommandBufferPool.Get();
        // 为颜色和深度设置相同的目标
        ScriptableRenderer.SetRenderTarget(cmd, m_Destination, m_Destination, clearFlag,
                                              clearColor);
        context.ExecuteCommandBuffer(cmd);
        CommandBufferPool.Release(cmd);
    }
}
```

使用新 API 的代码：

```cs
public class CustomPass : ScriptableRenderPass
{
    RTHandle m_Handle;
    // 使用 RTHandle 后，颜色和深度属性必须分开
    RTHandle m_DestinationColor;
    RTHandle m_DestinationDepth;

    void Dispose()
    {
        m_Handle?.Release();
    }

    public override void OnCameraSetup(CommandBuffer cmd, ref RenderingData renderingData)
    {
        var desc = renderingData.cameraData.cameraTargetDescriptor;
        // 使用 RTHandle 后，颜色和深度属性必须分开
        desc.depthBufferBits = 0;
        RenderingUtils.ReAllocateIfNeeded(ref m_Handle, desc, FilterMode.Point,
                                         TextureWrapMode.Clamp, name: "_CustomPassHandle");
    }

    public override void OnCameraCleanup(CommandBuffer cmd)
    {
        m_DestinationColor = null;
        m_DestinationDepth = null;
    }

    public void Setup(RTHandle destinationColor, RTHandle destinationDepth)
    {
        m_DestinationColor = destinationColor;
        m_DestinationDepth = destinationDepth;
    }

    public override void Execute(ScriptableRenderContext context,
                                    ref RenderingData renderingData)
    {
        CommandBuffer cmd = CommandBufferPool.Get();
        ScriptableRenderer.SetRenderTarget(cmd, m_DestinationColor, m_DestinationDepth,
                                              clearFlag, clearColor);
        context.ExecuteCommandBuffer(cmd);
        CommandBufferPool.Release(cmd);
    }
}
```

## 从 URP 11.x.x 升级

- 前向渲染器资源更名为通用渲染器资源。在包含 URP 12 的 Unity 编辑器中打开现有项目时，Unity 会将现有的前向渲染器资源更新为通用渲染器资源。
- 通用渲染器资源包含 **Rendering Path** 属性，允许选择 Forward 或 Deferred Rendering Path。
- `ClearFlag.Depth` 方法不再隐式清除模板缓冲区。使用新方法 `ClearFlag.Stencil`。
- URP 12 及更高版本实现了 [[06-使用渲染管线转换器转换资源]] 功能。此功能取代了以前在 **Edit > Render Pipeline > Universal Render Pipeline > Upgrade…** 中提供的资源升级功能。

## 从 URP 10.0.x–10.2.x 升级

1. The file names of the following Shader Graph shaders were renamed. The new file names do not have spaces:
`Autodesk Interactive`
`Autodesk Interactive Masked`
`Autodesk Interactive Transparent`  If your code uses the `Shader.Find()` method to search for the shaders, remove spaces from the shader names, for example, `Shader.Find("AutodeskInteractive)`.

## 从 URP 7.2.x 及更高版本升级

1. URP 12.x.x does not support the package Post-Processing Stack v2. If your Project uses the package Post-Processing Stack v2, migrate the effects that use that package first.

### DepthNormals 通道

从 10.0.x 版本开始，URP 可以生成名为 `_CameraNormalsTexture` 的法线纹理。要在自定义着色器中渲染到此纹理，请添加名称为 `DepthNormals` 的通道。示例请参阅 `Lit.shader` 中的实现。

### 屏幕空间环境光遮挡 (SSAO)

URP 10.0.x 实现了屏幕空间环境光遮挡 (SSAO) 效果。

如果要在自定义着色器中使用 SSAO 效果，请注意以下与 SSAO 相关的内容：

- `_SCREEN_SPACE_OCCLUSION` 关键字。
- `Input.hlsl` 在 `InputData` 结构中包含新的声明 `float2 normalizedScreenSpaceUV`。
- `Lighting.hlsl` 包含 `AmbientOcclusionFactor` 结构，其中包含用于计算间接和直接遮挡的变量：

```cpp
struct AmbientOcclusionFactor
{
    half indirectAmbientOcclusion;
    half directAmbientOcclusion;
};
```

- `Lighting.hlsl` 包含以下用于对 SSAO 纹理进行采样的函数：

```cpp
half SampleAmbientOcclusion(float2 normalizedScreenSpaceUV)
```

- `Lighting.hlsl` 包含以下函数：

```cpp
AmbientOcclusionFactor GetScreenSpaceAmbientOcclusion(float2
normalizedScreenSpaceUV)
```

要在自定义着色器中支持 SSAO，请向着色器添加 `DepthNormals` 通道和 `_SCREEN_SPACE_OCCLUSION` 关键字。示例请参阅 `Lit.shader`。

如果自定义着色器实现了自定义光照函数，请使用 `GetScreenSpaceAmbientOcclusion(float2 normalizedScreenSpaceUV)` 函数获取 `AmbientOcclusionFactor` 值，用于光照计算。

### 阴影法线偏移

在 11.0.x 中，应用阴影法线偏移的公式略有修正，以便更好地配合点光源。因此，为了与早期版本的阴影轮廓完全匹配，可能需要在某些场景中调整该参数。对于 Directional Light，通常将 1.0 改为 1.4 就足够了。

### 中间纹理

在以前的 URP 版本中，如果 Renderer 包含任何活动的 Renderer Feature，URP 会通过中间 Renderer 执行渲染。在某些平台上，这会显著影响性能。在此版本中，URP 通过以下方式缓解该问题：URP 要求 Renderer Feature 使用 `ScriptableRenderPass.ConfigureInput` 方法声明其输入。该方法提供的信息可供 URP 自动确定是否需要通过中间纹理进行渲染。

为保持兼容性，Universal Renderer 中新增了 **Intermediate Texture** 属性。将该属性设置为 **Always** 时，URP 使用中间纹理；选择 **Auto** 时启用新行为。仅当 Renderer Feature 没有使用 `ScriptableRenderPass.ConfigureInput` 方法声明其输入时，才使用 **Always** 选项。

为确保现有项目正常工作，所有使用 Renderer Feature（不包括 URP 自带 Renderer Feature）的现有 Universal Renderer 资源，都会在 **Intermediate Texture** 属性中选择 **Always**。新创建的 Universal Renderer 资源则选择 **Auto**。

## 从 URP 7.0.x–7.1.x 升级

1. 先升级到 URP 7.2.0。请参阅[[17-升级到通用渲染管线版本 7.2.0]]。
2. URP 8.x.x 不支持 Post-Processing Stack v2 包。如果项目使用 Post-Processing Stack v2 包，请先迁移使用该包的效果。

## 从 LWRP 升级到 12.x.x

- LWRP 没有直接升级到 URP 12.x.x 的路径。请先按照步骤将 LWRP 升级到 URP 11.x.x，然后再从 URP 11.x.x 升级到 URP 12.x.x。


## 官方代码示例补充（Unity 6000.7）

### 官方代码片段 1

```csharp
public class CustomPass : ScriptableRenderPass
{
    RenderTargetHandle m_Handle;
    // With the old API, RenderTargetIdentifier might combine color and depth
    RenderTargetIdentifier m_Destination;

    public CustomPass()
    {
        m_Handle.Init("_CustomPassHandle");
    }

    public override void OnCameraSetup(CommandBuffer cmd, ref RenderingData renderingData)
    {
        var desc = renderingData.cameraData.cameraTargetDescriptor;
        cmd.GetTemporaryRT(m_Handle.id, desc, FilterMode.Point);
    }

    public override void OnCameraCleanup(CommandBuffer cmd)
    {
        cmd.ReleaseTemporaryRT(m_Handle.id);
    }

    public void Setup(RenderTargetIdentifier destination)
    {
        m_Destination = destination;
    }

    public override void Execute(ScriptableRenderContext context,
                                    ref RenderingData renderingData)
    {
        CommandBuffer cmd = CommandBufferPool.Get();
        // Set the same target for color and depth
        ScriptableRenderer.SetRenderTarget(cmd, m_Destination, m_Destination, clearFlag,
                                              clearColor);
        context.ExecuteCommandBuffer(cmd);
        CommandBufferPool.Release(cmd);
    }
}
```
