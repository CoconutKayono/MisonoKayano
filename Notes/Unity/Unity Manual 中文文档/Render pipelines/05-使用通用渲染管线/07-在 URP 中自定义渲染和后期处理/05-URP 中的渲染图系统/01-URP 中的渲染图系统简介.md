# URP 中的渲染图系统简介

> 原文：[Introduction to the render graph system in URP](https://docs.unity3d.com/6000.7/Documentation/Manual/urp/render-graph-introduction.html)


渲染图系统是通用渲染管线 (URP) 中用于编写[[01-URP 中的可编程渲染通道简介]]的一组 API。

使用渲染图 API 创建可编程渲染通道时，您需要向 URP 提供以下信息：

1. 要使用的纹理或渲染纹理。此阶段为录制阶段。
2. 要使用录制阶段产生的纹理或渲染纹理执行的图形命令。此阶段是执行阶段。

然后，您可以[[03-URP 中的自定义渲染通道工作流程]]。可编程渲染通道将成为 URP 内部渲染图的一部分，后者是 URP 逐步执行每一帧的渲染通道序列。URP 会自动优化渲染通道和渲染图，以最大限度减少渲染通道的数量以及渲染通道使用的内存和带宽。

## URP 如何优化渲染

URP 执行以下操作来优化渲染图中的渲染：

- 将多个渲染通道合并为单个渲染通道。
- 避免分配帧不使用的资源。
- 如果最终帧不使用渲染通道的输出，则避免执行渲染通道。
- 避免重复的资源，例如，使用单个纹理替换具有相同属性的两个纹理。
- 自动同步计算和图形 GPU 命令队列。

在使用基于图块的延迟渲染 (TBDR) 的移动平台上，URP 还可以将多个渲染通道合并为单个原生渲染通道。原生渲染通道将纹理保留在图块内存中，而不是将纹理从 GPU 复制到 CPU。因此，URP 使用更少的内存带宽并且渲染时间更短。

要检查 URP 如何在自定义渲染通道中优化渲染，请参阅[[08-在 URP 中分析渲染图]]。

## 渲染图系统中的资源

要声明资源并在渲染通道中使用它（例如纹理或待渲染对象列表），请调用返回资源句柄的渲染图系统 API。不能自行直接分配或释放资源。

渲染图系统只会在写入资源的第一个渲染通道即将执行时分配资源内存，并在读取资源的最后一个渲染通道执行后释放内存。这使渲染图能够高效管理内存，并避免为当前帧未使用的资源分配内存。

可以通过以下两种方式创建资源：

- 在渲染通道内创建资源。这些称为内部资源，其生命周期由渲染图系统处理。不能在渲染图实例之外访问它们，也不能在帧或摄像机之间传递它们。有关更多信息，请参阅[[02-在 URP 中的渲染图形系统中创建纹理]]。
- 从渲染通道外部导入现有资源，例如摄像机后备缓冲区，或希望渲染图跨多个帧使用的纹理。这些称为导入资源或外部资源，渲染图不处理其生命周期，因此可以在帧和摄像机之间传递。有关更多信息，请参阅[[00-在 URP 中的渲染通道之间传输纹理]]。

## 渲染通道类型

渲染图系统支持以下渲染通道类型。

| 类型 | API | 用途 |
| --- | --- | --- |
| Raster | `AddRasterRenderPass` | 默认使用。渲染图系统可以将兼容的光栅渲染通道合并，因此这是优化程度最高的通道类型。有关更多信息，请参阅[[02-在 URP 中使用渲染图系统编写渲染通道]]。 |
| Compute | `AddComputePass` | 当渲染通道运行计算着色器时使用。有关更多信息，请参阅[[00-在 URP 的渲染图系统中的计算着色器]]。 |
| Unsafe | `AddUnsafePass` | 只有在需要直接访问 `CommandBuffer` API，且无法通过光栅或计算渲染通道实现相同结果时使用。Unsafe 渲染通道不能与其他通道合并，并且其验证少于光栅和计算渲染通道。有关更多信息，请参阅[[10-在渲染图渲染通道中使用兼容性模式 API]]。 |
