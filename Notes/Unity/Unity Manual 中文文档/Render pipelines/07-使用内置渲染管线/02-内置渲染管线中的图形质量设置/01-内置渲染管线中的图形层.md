# 内置渲染管线中的图形层

> 原文：[Graphics tiers in the Built-In Render Pipeline](https://docs.unity3d.com/6000.7/Documentation/Manual/graphics-tiers.html)

**重要**：Built-In Render Pipeline 已弃用，并将在未来版本中废止。在整个 Unity 6.7 LTS 生命周期内，它仍会获得支持，包括 bug 修复和维护。有关迁移的信息，请参阅[从 Built-In Render Pipeline 迁移到 Universal Render Pipeline](https://docs.unity3d.com/6000.7/Documentation/Manual/urp/upgrading-from-birp.html)和[渲染管线功能比较](https://docs.unity3d.com/6000.7/Documentation/Manual/render-pipelines-feature-comparison.html)。

在 Built-in Render Pipeline 中，可以使用 graphics tier，让应用程序在功能不同的硬件上运行时应用不同的图形设置。可以使用 Unity 内置的 tier settings 配置常用设置，也可以在自己的 shader code 或 C# code 中定义 custom behavior。

**注意**：只有 Built-in Render Pipeline 支持此功能。在其他渲染管线中，Unity 仍会在启动时检查硬件，并将其值存储在 `Graphics.activeTier` 中；但是，此字段的值不会产生任何作用，Unity 也不会执行与 graphics tier 相关的其他操作。

## Graphics tier 概述

Unity 首次加载应用程序时，会检查硬件和 graphics API，并确定当前环境对应的 graphics tier。

Graphics tier 如下：

| 值 | 硬件 | 对应的 `GraphicsTier` enum 值 | 对应的 shader keyword |
| --- | --- | --- | --- |
| 1 | iOS：iPhone 5S 之前的 iPhone（不包括 5S，但包括 5C）、第五代及之前的 iPod、第四代及之前的 iPad、第一代 iPad mini；桌面端：DirectX 9 |  |  |
| 2 | Android：支持 OpenGL ES 3 的设备、支持 Vulkan 的设备；iOS：从 iPhone 5S 开始的 iPhone、iPad Air、第二代 iPad mini、第六代 iPod、AppleTV；WebGL：所有设备 | [`Tier2`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Rendering.GraphicsTier.Tier2.html) | `UNITY_HARDWARE_TIER2` |
| 3 | 桌面端：OpenGL、Metal、Vulkan、DirectX 11+ | [`Tier3`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Rendering.GraphicsTier.Tier3.html) | `UNITY_HARDWARE_TIER3` |

## Graphics tier 和 shader variant

在 Built-in Render Pipeline 中，Unity 可以生成与 graphics tier 对应的 shader variant。有关 shader variant 的定义，请参阅[Shader variants](https://docs.unity3d.com/6000.7/Documentation/Manual/shader-variants.html)。

**注意**：这些 tier shader variant 的工作方式与常规 shader variant 不同。在运行时，当 Unity 将 Shader object 加载到 CPU memory 中时，只会加载 active tier 的 variant，不会加载其他 tier 的 variant。这有助于减少 tier variant 对运行时的影响。

要生成 tier shader variant，Unity 会向所有 graphics shader 添加以下 shader keyword：

```hlsl
UNITY_HARDWARE_TIER1
UNITY_HARDWARE_TIER2
UNITY_HARDWARE_TIER3
```

可以在 HLSL code 中使用这些 keyword，为低端或高端硬件编写 conditional behavior，方式与使用其他 shader keyword 相同。例如：

```hlsl
#if UNITY_HARDWARE_TIER1
// Put code for tier 1 devices here
#else
// Put code for other devices here
#endif
```

有关在 HLSL code 中使用 shader keyword 的更多信息，请参阅[在 HLSL 中声明和使用 shader keyword](https://docs.unity3d.com/6000.7/Documentation/Manual/SL-MultipleProgramVariants.html)。

Unity 会根据当前 build target 的 tier settings 自动生成 tier shader variant，规则如下：

- 如果所有 tier 的所有设置都相同，Unity 不会生成任何 tier shader variant；
- 如果不同 tier 的设置存在任何差异，Unity 会生成所有 tier shader variant。

生成所有 tier shader variant 后，Unity 会识别并 deduplicate 相同的 tier shader variant。这意味着，如果两个 tier 的设置相同（例如 tier 1 不同，但 tier 2 和 tier 3 相同），这些 variant 不会增加应用程序的文件大小；Unity 加载 tier variant 的方式也意味着它们不会影响加载时间或运行时 memory usage。不过，这仍然会导致冗余的编译工作。

如果想为不同 tier 使用不同设置，但也知道这样会造成冗余工作（例如已知应用程序只会在 tier 1 和 tier 2 设备上运行），可以像处理其他 variant 一样，使用 script 从编译中剥离不需要的 tier variant。详情请参阅[Shader variant stripping](https://docs.unity3d.com/6000.7/Documentation/Manual/shader-variant-stripping.html)。

除自动行为外，还可以强制 Unity 针对每个 shader 生成 tier shader variant。如果在 HLSL code 中使用这些常量，并且希望确保 Unity 编译所需的 variant（无论当前 build 的 tier settings 是否不同），这一功能会很有用。

要手动强制 Unity 为指定 shader 生成 tier shader variant，请在 HLSL code 中使用 `#pragma hardware_tier_variants` preprocessor directive，并指定要为每个 tier 生成 variant 的 graphics API：

```hlsl
#pragma hardware_tier_variants gles3
```

有关此 directive 可用的 graphics API 名称列表，请参阅[定位 graphics API](https://docs.unity3d.com/6000.7/Documentation/Manual/SL-ShaderCompilationAPIs.html)。有关 `#pragma` directive 的一般信息，请参阅[pragma directive](https://docs.unity3d.com/6000.7/Documentation/Manual/SL-PragmaDirectives.html)。
