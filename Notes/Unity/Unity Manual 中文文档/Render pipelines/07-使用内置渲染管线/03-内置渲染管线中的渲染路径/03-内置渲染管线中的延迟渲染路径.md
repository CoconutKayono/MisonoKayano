# 内置渲染管线中的延迟渲染路径

> 原文：[Deferred rendering path in the Built-In Render Pipeline](https://docs.unity3d.com/6000.7/Documentation/Manual/RenderTech-DeferredShading.html)

> **重要**：Built-In Render Pipeline 已弃用，并将在未来版本中废止。它在整个 Unity 6.7 LTS 生命周期内仍受支持，包括错误修复和维护。有关迁移信息，请参阅 [从 Built-In Render Pipeline 迁移到 Universal Render Pipeline](https://docs.unity3d.com/6000.7/Documentation/Manual/urp/upgrading-from-birp.html) 和 [Render pipeline feature comparison](https://docs.unity3d.com/6000.7/Documentation/Manual/render-pipelines-feature-comparison.html)。

本页详细介绍 Unity Built-In Render Pipeline 中的 Deferred Shading [[01-内置渲染管线中的渲染路径简介|rendering path]]。有关 deferred shading 的入门技术概述，请参阅 [Wikipedia：deferred shading](http://en.wikipedia.org/wiki/Deferred_shading)。

## 概述

使用 deferred shading 时，影响 GameObject 的光源数量没有限制。所有光源都按 per-pixel 评估，因此都能正确地与 normal maps 等效果交互。此外，所有光源都可以有 cookies 和 shadows。

Deferred shading 的优点是，lighting 的处理开销与光源照射到的像素数量成正比。这由 Scene 中光源 volume 的大小决定，而与它照亮多少 GameObject 无关。因此，保持光源较小可以提高性能。Deferred shading 的行为也高度一致且可预测。每个光源的效果都按 per-pixel 计算，因此不存在在大三角形上失真的 lighting 计算。

缺点是，deferred shading 不真正支持 anti-aliasing，也不能处理半透明 GameObject（这些对象使用 [[02-内置渲染管线中的前向渲染路径|forward]] rendering）。它也不支持 Mesh Renderer 的 Receive Shadows 标志，且只以有限方式支持 culling masks。最多只能使用四个 culling mask。也就是说，culling layer mask 至少必须包含除任意四层之外的所有层，即 32 层中必须设置 28 层。否则会产生图形瑕疵。

## 要求

Deferred shading 要求显卡具有 Multiple Render Targets（MRT）、Shader Model 3.0（或更高版本）以及对 Depth render textures 的支持。2006 年以后生产的大多数 PC 显卡都支持 deferred shading，起始支持型号包括 GeForce 8xxx、Radeon X2400 和 Intel G45。

在移动设备上，所有至少运行 OpenGL ES 3.0 的设备都支持 deferred shading。

**注意**：使用 Orthographic projection 时不支持 deferred rendering。如果 Camera 的 projection mode 设置为 Orthographic，Camera 会回退到 Forward rendering。

**注意**：Deferred Rendering 不支持 Built-In Render Pipeline 中的 Single Pass Stereo Instancing。

## 性能注意事项

Deferred shading 中实时光源的渲染开销与光源照亮的像素数量成正比，**不**取决于 Scene 复杂度。因此，小型 Point Light 或 Spot Light 的渲染成本很低；如果它们被 Scene GameObject 完全或部分遮挡，成本会更低。

当然，带阴影的光源比不带阴影的光源昂贵得多。在 deferred shading 中，每个投射阴影的光源仍然需要将投射阴影的 GameObject 渲染一次或多次。此外，应用阴影的 lighting shader 比禁用阴影时使用的 shader 有更高的渲染开销。

## 实现详细信息

不支持 deferred shading 的 Shader 对象，会在 deferred shading 完成后使用 [[02-内置渲染管线中的前向渲染路径|forward rendering]] path 渲染。

下面列出 G-buffer 中 render target（RT0–RT4）的默认布局。数据类型放在每个 render target 的不同 channel 中，使用的 channel 标在括号内。

- RT0，ARGB32 格式：Diffuse color（RGB）、occlusion（A）。
- RT1，ARGB32 格式：Specular color（RGB）、smoothness（A）。
- RT2，ARGB2101010 格式：World space normal（RGB）、未使用（A）。
- RT3，ARGB2101010（非 HDR）或 ARGBHalf（HDR）格式：Emission + lighting + lightmaps + reflection probes buffer。
- Depth+Stencil buffer。

因此，默认 G-buffer 布局为 160 bits/pixel（非 HDR）或 192 bits/pixel（HDR）。

如果 Mixed lighting 使用 Shadowmask 或 Distance Shadowmask 模式，则使用第五个 target：

- RT4，ARGB32 格式：Light occlusion values（RGBA）。

因此，G-buffer 布局为 192 bits/pixel（非 HDR）或 224 bits/pixel（HDR）。

如果硬件不支持五个并发 render target，使用 shadowmask 的对象会回退到 forward rendering path。当 Camera 不使用 HDR 时，Emission+lighting buffer（RT3）采用 logarithmic encoding，以提供通常 ARGB32 texture 无法达到的更大 dynamic range。

请注意，当 Camera 使用 HDR rendering 时，不会为 Emission+lighting buffer（RT3）创建单独的 render target；而是使用 Camera 渲染到的 render target（即传给 image effects 的那个 target）作为 RT3。

### G-buffer pass

G-buffer pass 将每个 GameObject 渲染一次，将 diffuse 和 specular colors、surface smoothness、world space normals，以及 emission、ambient、reflections 和 lightmaps 存入 textures。Unity 将 G-buffer textures 设置为 global shader properties，供 shader 后续访问。属性名称为 `_CameraGBufferTexture0` 至 `_CameraGBufferTexture3`。

### Lighting pass

Lighting pass 根据 G-buffer 和 depth 计算 lighting。Lighting 在 screen space 中计算，因此处理耗时与 Scene 复杂度无关。Lighting 会添加到 emission buffer。

不穿过 Camera near plane 的 Point Light 和 Spot Light 会渲染为 3D shape，并启用 Z buffer 对 Scene 的测试。因此，被部分或完全遮挡的 Point Light 和 Spot Light 渲染成本很低。Directional Light，以及穿过 near plane 的 Point Light 或 Spot Light，会渲染为 fullscreen quad。

如果光源启用了 shadows，它们也会在此 pass 中渲染和应用。请注意，阴影并不是“免费”的：需要渲染 shadow caster，并应用更复杂的 light shader。

可用的 lighting model 只有 Standard。如果需要不同的 lighting model，可以创建默认 deferred shader 文件的自定义版本：

1. [下载 Built-In Render Pipeline shader 的源代码](https://docs.unity3d.com/6000.7/Documentation/Manual/StandardShaderMakeYourOwn.html)。
2. 在 `DefaultResourcesExtra` 文件夹中找到 `Internal-DeferredShading.shader` 文件。
3. 编辑文件以更改 lighting model。
4. 在 **Project** 窗口中，将文件添加到 **Assets** 文件夹下名为 **Resources** 的文件夹中。
5. 从主菜单选择 **Edit** > **Project Settings** > **Graphics**。
6. 在 **Built-in Shader Settings** 部分，将 **Deferred** 设置为 **Custom shader**，然后选择 shader 文件。
