# Unity `Text` 字体清晰度 FAQ

本文主要讨论 Unity 旧版 UGUI 的 `UnityEngine.UI.Text`，也就是 Inspector 中组件名称为 **Text** 的文本组件。

常见做法是：

1. 将 `Text` 的 `Font Size` 调大；
2. 保持文字内容和布局不变；
3. 将文字对象的 `Transform.localScale` 缩小到合适比例。

例如，将 `Font Size` 从 `20` 调到 `60`，再将 `Scale` 从 `1` 调到 `0.333`。很多情况下，这样显示出来的文字确实比直接使用 20 号字体更清晰。

## FAQ：为什么“字体调大，再缩小 Scale”会更清晰？

因为 `Text` 通常不是以矢量轮廓直接交给 GPU 实时绘制，而是先把字体字形栅格化，生成字体纹理或字体图集，再将这张纹理显示到 UI 上。

直接使用小字号时，字形在生成纹理阶段就已经被压缩成较少的像素。例如，一个笔画可能只有 1～2 个像素宽，曲线和斜线的信息会丢失。之后再放大，只能放大已经丢失细节的纹理，因此容易出现马赛克和锯齿。

而先使用大字号生成字形，相当于以更高的采样率保存字体轮廓；再通过缩小 `Scale` 将它缩回目标尺寸，相当于对高分辨率字形做一次下采样。下采样会综合周围多个像素的颜色，通常能让边缘更平滑、细节更稳定。

可以把它理解为图片处理中的“超采样”或“先大图渲染、再缩小”：

```text
小字号直接生成：  字体轮廓 → 少量像素 → 直接显示 → 容易锯齿

大字号再缩放：    字体轮廓 → 更多像素 → 缩小采样 → 边缘更平滑
```

## FAQ：这是真正的“矢量字体”吗？

不是。

`Text` 仍然是在使用栅格化后的字体纹理，只是先以更大的尺寸生成纹理，再缩小显示。它改善的是采样质量，不会让字体变成无限缩放仍然清晰的矢量图形。

因此，如果把最终显示尺寸再次放大，或者在不同分辨率、不同 Canvas 缩放比例下使用，效果仍然可能变差。

## FAQ：为什么直接调大 `Font Size` 不够，还要缩小 `Scale`？

`Font Size` 决定字形生成时的采样尺寸；`Scale` 决定生成后的 UI 对象在屏幕上的显示尺寸。

只调大 `Font Size`，文字最终也会变大，布局和视觉尺寸都会改变。调大字体后再缩小 `Scale`，可以在保留较高采样精度的同时，让文字回到原来的视觉大小。

例如：

```text
目标视觉字号：20
Font Size：60
Transform Scale：0.333
大致最终字号：60 × 0.333 ≈ 20
```

这里的“最终字号”只是便于理解的近似值，实际效果还会受到字体字面量、RectTransform、Canvas 缩放和像素对齐影响。

## FAQ：这种方法的主要优点是什么？

### 1. 小字号边缘更平滑

小字号的横线、斜线和圆弧拥有更多中间采样信息，缩小时更容易形成平滑边缘。

### 2. 能改善旧版 `Text` 的锯齿问题

旧版 `Text` 的字体纹理质量和采样方式有限。超采样式的做法可以在不替换整个 UI 系统的情况下，改善一部分显示效果。

### 3. 对细字体、斜体和曲线字体尤其明显

细笔画、圆角和斜线在低分辨率下更容易断裂或闪烁，先放大生成通常能保留更多轮廓信息。

### 4. 改动成本相对低

不需要修改字体文件，也不一定需要立刻迁移到 TextMeshPro，通常只需要调整 `Font Size` 和 `Transform Scale`。

## FAQ：这种方法的代价是什么？

### 1. 字体纹理和字体图集占用更多内存

字号变大后，字体字形需要更大的纹理空间。纹理面积与宽、高相关，字号扩大 3 倍时，单个字形所需面积可能接近扩大 9 倍；实际占用还取决于字符数量、图集布局和纹理格式。

中文字符数量多，代价会更加明显。

### 2. 可能增加生成字体纹理的时间

动态字体在运行时生成字符纹理。更大的字号意味着更高的栅格化成本，首次显示新字符时可能产生卡顿，尤其是在大量文本同时出现时。

### 3. 可能导致字体图集装不下

当使用动态字体或字符数量较多时，大字号可能使字体图集迅速填满，出现缺字、生成失败或额外图集分配。

### 4. 缩放后不一定更“锐”

这个技巧主要改善边缘平滑度，不保证笔画一定更锐利。缩放比例不合适、纹理过滤设置不合适或文字落在半像素位置时，仍可能出现发虚。

### 5. 可能影响布局和点击区域

如果通过 `Transform.localScale` 缩小文字，视觉尺寸虽然变小，但布局系统使用的 RectTransform 尺寸、父节点布局计算和点击区域可能与预期不一致。

在 `Horizontal/Vertical Layout Group`、`Content Size Fitter` 等组件中，尤其要检查实际布局结果。

### 6. 不同分辨率下效果可能不稳定

固定的 `Font Size` 与 `Scale` 组合只对某个尺寸范围最优。屏幕分辨率、Canvas Scaler 的参考分辨率或设备 DPI 发生变化后，文字可能重新变糊、变细或出现像素跳动。

## FAQ：推荐把字号放大多少？

没有适用于所有项目的固定倍数。可以从目标字号的 2～3 倍开始测试：

| 目标视觉字号 | 可尝试的 Font Size | 对应 Scale（近似） |
| --- | ---: | ---: |
| 16 | 32～48 | 0.5～0.333 |
| 20 | 40～60 | 0.5～0.333 |
| 24 | 48～72 | 0.5～0.333 |
| 32 | 64～96 | 0.5～0.333 |

倍率过低可能使文字发虚，倍率过高则会增加内存和生成成本。最终应在目标设备和实际 Game 窗口分辨率下观察，而不是只看 Scene 视图。

## FAQ：应该调整 `Font Size`，还是调整 `Transform Scale`？

建议采用以下原则：

- 用 `Font Size` 决定字体的采样质量和基本字形大小。
- 用布局、锚点和 Canvas Scaler 处理分辨率适配。
- 只有在确实需要超采样效果时，才使用适度的 `Transform Scale` 缩小。
- 尽量不要在同一层级上叠加多个小数缩放，例如父物体 `0.8`、文字自身 `0.6`、Canvas 又进行一次非整数缩放。

如果必须使用这个技巧，建议把文字节点的缩放集中管理，并记录“原始字号、放大倍率和最终 Scale”，避免后续维护时误以为字号异常。

## FAQ：`Text` 组件还需要检查哪些设置？

### Font Import Settings

检查字体文件是否正确导入，字体纹理是否被过度压缩。出现脏边、彩边或细节损失时，可尝试提高纹理质量或关闭有损压缩。

### Font Texture Size

动态字体或字体图集需要足够空间容纳实际字符。中文项目要特别关注图集是否装满。

### Best Fit

旧版 `Text` 的 `Best Fit` 会自动改变字号以适应区域，可能与手动超采样设置互相影响。若清晰度不稳定，可以先关闭 `Best Fit`，使用明确的字号和布局尺寸。

### Horizontal Overflow 与 Vertical Overflow

避免为了塞入文本而把字号压得过小。应根据需求选择换行、截断或扩大容器。

### Canvas Scaler

常规屏幕 UI 通常使用：

```text
UI Scale Mode: Scale With Screen Size
Reference Resolution: 使用项目设计分辨率
Screen Match Mode: Match Width Or Height
```

如果 Canvas 自身已经发生较大缩放，再对 Text 做一次小数缩放，最终采样效果可能不稳定。

## FAQ：为什么有时缩小 Scale 反而更糊？

常见原因包括：

1. 缩放比例过小，最终文字实际占用的像素不足。
2. 文字位置落在半像素坐标上，导致边缘采样不稳定。
3. 父节点或 Canvas 已经进行了一次非整数缩放。
4. 字体纹理使用了低质量压缩或不合适的过滤设置。
5. `Best Fit`、自动布局或分辨率变化再次改变了最终字号。
6. 放大后的字符数量过多，字体图集装满，部分字符使用了低质量或备用资源。

因此，“调大字号再缩小”不是无条件有效的开关，而是一种有代价的超采样技巧。

## FAQ：和 TextMeshPro 相比，应该怎么选？

如果是新项目，通常建议使用 TextMeshPro。TMP 使用 SDF 字体资源，在缩放、描边和不同字号下通常更稳定，也提供更完整的排版能力。

继续使用旧版 `Text` 的合理场景包括：

- 老项目改动范围需要尽量小。
- 现有 UI 依赖旧版组件和布局行为。
- 文本量少、目标分辨率固定，且经过实机验证。

即使暂时不能迁移，也可以使用本文介绍的超采样方法改善旧版 `Text`，但应同时评估字体图集、内存和动态生成成本。

## FAQ：最终应该怎样配置？

一个可作为起点的配置如下：

```text
Text 组件
├─ Font Size：目标字号的 2～3 倍
├─ Transform Scale：约 0.5～0.333
├─ Best Fit：通常关闭
├─ 对齐、换行和溢出：按实际布局设置
└─ 在目标分辨率和目标设备上验证
```

不要机械地把所有文字都放大 3 倍。标题、按钮文字和正文的最佳倍率可能不同；应以可读性、清晰度、内存占用和布局稳定性之间的平衡为准。

## 总结

“先把 `Font Size` 调大，再把 `Scale` 缩小”之所以有效，是因为它让旧版 `Text` 先以更高分辨率生成字体纹理，再通过下采样改善边缘质量。

它的优点是改动简单、能减少小字号锯齿；代价是更高的字体纹理内存、运行时生成成本、图集容量压力，以及可能出现的布局和分辨率适配问题。

对于旧版 `Text`，建议使用适度的 2～3 倍超采样并进行实机验证；对于新项目或需要多分辨率、高质量排版的项目，优先考虑 TextMeshPro。
