# 07｜透明、深度、剔除与模板测试

## 场景：返回 alpha=0.2，为什么仍然不透明

因为片元输出的 alpha 只是一个通道。是否把颜色与背景混合，还由 Blend 状态决定；先后顺序与遮挡又涉及 Queue、ZWrite、ZTest。

下列 Tags 是 **SubShader 标签**，Blend、ZWrite 等写在 **Pass 内、HLSLPROGRAM 外**。修改基础模板时应替换旧设置，避免重复冲突；保留 RenderPipeline=UniversalPipeline。

## 几种常用组合

| 场景 | Queue / RenderType | Blend | ZWrite | 片元侧配合 |
| --- | --- | --- | --- | --- |
| 不透明物体 | Geometry / Opaque | Off | On | 一般输出 alpha=1 |
| 树叶、栅栏镂空 | AlphaTest / TransparentCutout | Off | On | clip(alpha-cutoff) |
| 普通透明 | Transparent / Transparent | SrcAlpha OneMinusSrcAlpha | Off | 输出未预乘 RGB 与 alpha |
| 预乘透明 | Transparent / Transparent | One OneMinusSrcAlpha | Off | RGB 先乘 alpha，且只乘一次 |
| 加法光效 | Transparent / Transparent | One One | Off | 要用透明度调亮度时，在 RGB 中自行乘 alpha |
| 带 alpha 强度的加法 | Transparent / Transparent | SrcAlpha One | Off | 输出未预乘 RGB 与 alpha |

这些是常用起点，默认深度测试仍可保持 LEqual。透明排序、交叠和自遮挡并不会因为套用一组状态就自动解决。

RenderType 是分类标签，Queue 影响排队；仅写 Transparent 标签不会替你开启 Blend。

## 普通透明的完整状态片段

~~~shaderlab
// 替换 SubShader 的 Tags
Tags
{
    "RenderPipeline"="UniversalPipeline"
    "Queue"="Transparent"
    "RenderType"="Transparent"
}

// 放在 Pass 内、HLSLPROGRAM 外
Blend SrcAlpha OneMinusSrcAlpha
ZWrite Off
ZTest LEqual
Cull Back
~~~

frag 可继续返回纹理乘颜色，使用纹理 alpha 与 _BaseColor.a 控制透明度。

对 RGB 而言：

$$
C_{\text{out}}=C_{\text{src}}\alpha_{\text{src}}+
C_{\text{dst}}(1-\alpha_{\text{src}})
$$

src 是当前片元，dst 是渲染目标已有颜色。若渲染目标的 alpha 通道也有特定合成需求，可以为 RGB 与 alpha 分别指定因子：

~~~shaderlab
Blend SrcAlpha OneMinusSrcAlpha, One OneMinusSrcAlpha
~~~

前两个因子管 RGB，逗号后的两个管 alpha。[Unity Blend 参考](https://docs.unity3d.com/6000.0/Documentation/Manual/SL-Blend.html)

## 场景：树叶只保留有图案的部分

**frag 片段：**

~~~hlsl
half4 color = SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, IN.uv) * _BaseColor;
clip(color.a - 0.5);
return half4(color.rgb, 1);
~~~

这不是“剩下部分半透明”：低于阈值的片元被丢弃，其余片元按不透明方式绘制。通常使用上表 Cutout 状态。

AlphaToMask On 可在启用 MSAA 的适当场景下将 alpha 转为样本覆盖度，但效果依平台与采样配置，不等于普通半透明混合。

## 场景：控制谁挡住谁

| 语法 | 回答的问题 |
| --- | --- |
| ZTest LEqual | 当前片元能否通过已有深度的比较？ |
| ZTest Always | 总是通过深度测试；不会绕过模板测试等其他条件 |
| ZWrite On / Off | 通过测试后是否写入深度？ |
| ColorMask 0 | 不写颜色，但仍可能写深度或模板 |

ZWrite Off 不等于“不受遮挡”：如果 ZTest 仍是 LEqual，前面的不透明物体依然可以挡住它。ZTest Always 也不自动让对象最后绘制，还要考虑调度与排序。

更多：[ZWrite](https://docs.unity3d.com/6000.0/Documentation/Manual/SL-ZWrite.html)、[ZTest](https://docs.unity3d.com/6000.0/Documentation/Manual/SL-ZTest.html)。

## 场景：双面布片与外扩描边

- Cull Back：剔除背面，是常见默认设置。
- Cull Front：剔除正面，常见于外扩轮廓的反壳思路。
- Cull Off：两面都绘制，常用于薄片。

关闭剔除不会自动翻转背面法线，也不会自动让透明自重叠正确。若光照要求区分正反面，可以再使用正面系统语义及管线封装宏，按目标平台处理。

反壳描边还需要顶点外扩、Pass 调度与宽度定义，不是只有 Cull Front 就会出现轮廓。[Unity Cull](https://docs.unity3d.com/6000.0/Documentation/Manual/SL-Cull.html)

## 场景：只在模板标记区域画图

模板缓冲可先写标记，再由另一批绘制读取。以下使用最低一位，示例前提是这一位由你的效果管理、不会与管线或其他效果冲突，并且帧内按写入→读取顺序调度。

**遮罩对象 Pass 的 ShaderLab 状态：**

~~~shaderlab
ColorMask 0
ZWrite Off
Stencil
{
    Ref 1
    ReadMask 1
    WriteMask 1
    Comp Always
    Pass Replace
}
~~~

这里 Stencil 内的 Pass 是“测试通过时执行的操作”，不是外层 ShaderLab Pass 代码块。仍然需要遮罩对象的顶点/片元程序，且默认深度测试依然参与。

**被遮罩对象 Pass：**

~~~shaderlab
Stencil
{
    Ref 1
    ReadMask 1
    WriteMask 0
    Comp Equal
    Pass Keep
}
~~~

写入者先绘制，读取者才看得见标记；还需保证模板缓冲在预期时机清除。不应默认 URP 延迟渲染中的所有位都可以任意使用。该片段说明模板语法，不包含自动安排绘制顺序的 Renderer Feature。

依据：[Unity Stencil](https://docs.unity3d.com/6000.0/Documentation/Manual/SL-Stencil.html)。
