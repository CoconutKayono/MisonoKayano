# 08｜关键字、变体与调试

## 场景：给材质一个“边缘光开关”

这个示例接在第 06 篇的光照数据上，假设 frag 中已有 color、normalWS、positionWS。

**Properties：**

~~~shaderlab
[Toggle(_RIM_ON)] _UseRim("Use Rim", Float) = 0
~~~

**UnityPerMaterial：**

~~~hlsl
float _UseRim;
~~~

**HLSLPROGRAM 顶部：**

~~~hlsl
#pragma shader_feature_local _RIM_ON
~~~

**frag：**

~~~hlsl
#if defined(_RIM_ON)
    float3 rimN = normalize(IN.normalWS);
    float3 rimV = GetWorldSpaceNormalizeViewDir(IN.positionWS);
    float rim = pow(1.0 - saturate(dot(rimN, rimV)), 4.0);
    color.rgb += half3(0.1, 0.8, 1.0) * rim;
#endif
~~~

开关属性、关键字声明、条件代码三个部分要配套。#if 按关键字编译选择代码；它不是每片元读取 _UseRim 再判断。

## 场景：从脚本切换关键字

已有 Material 引用 material 时，可使用：

~~~csharp
var keyword = new UnityEngine.Rendering.LocalKeyword(material.shader, "_RIM_ON");
material.SetKeyword(keyword, true);
material.SetFloat("_UseRim", 1.0f);
~~~

SetFloat 主要同步属性数值；不能假设从脚本 SetFloat 会替你执行 Inspector 的 Toggle 逻辑并切换关键字。上例显式设置两者。[Unity LocalKeyword](https://docs.unity3d.com/cn/6000.0/ScriptReference/Rendering.LocalKeyword.html)

## 哪种条件机制适合什么场景

| 写法 | 适用情况 | 代价与注意 |
| --- | --- | --- |
| if (_UseRim > 0.5) | 小功能或经常运行时切换 | 运行时计算/分支，不新增此项变体 |
| shader_feature_local | 材质配置型可选功能 | 构建时未使用的组合可能被剥离 |
| multi_compile_local | 需要预先准备多种运行时组合 | 候选变体多，仍要考虑整体剥离流程 |
| multi_compile | 管线或全局关键字控制 | 范围更广，别让自定义名称冲突 |
| #define NAME value | 编译期常量/宏 | 不自动生成一套材质开关 |

运行时可能开启一个构建时从未使用的 shader_feature 状态，就要规划如何保留对应变体；不能只在 Editor 中切成功便认定 Player 一定可用。

local 主要控制关键字作用域，不意味着自动减少每个开关的组合数。10 个互相独立的二态变体开关，未剥离前就可能组合成 2¹⁰=1024 种状态，还没算其他 Pass 与平台因素。[Unity 关键字声明](https://docs.unity3d.com/cn/6000.0/Manual/SL-MultipleProgramVariants-declare.html)

## 场景：多选模式与空变体

~~~hlsl
#pragma multi_compile_local _ MODE_A MODE_B

#if defined(MODE_A)
    // A 的实现
#elif defined(MODE_B)
    // B 的实现
#else
    // 未启用本组关键字
#endif
~~~

一行表示一个关键字集合，_ 表示不定义本组关键字的选择。材质或脚本应保证互斥状态，不要把 MODE_A 和 MODE_B 同时开启后期待可预测地“叠加两种效果”。

## 场景：复用函数

把纯 HLSL 帮助函数保存到同目录的 EffectCommon.hlsl：

~~~hlsl
#ifndef FAQ_EFFECT_COMMON_INCLUDED
#define FAQ_EFFECT_COMMON_INCLUDED

float MakeBand(float x, float center, float width)
{
    return 1.0 - smoothstep(width, width + 0.02, abs(x - center));
}

#endif
~~~

在 Shader 中引用：

~~~hlsl
#include "EffectCommon.hlsl"
~~~

保护宏防止重复定义。普通 .hlsl 文件通常不放 ShaderLab 的 Properties、SubShader 外壳。这里的包含文件是示例片段，需自行新建后再引用。

## 常见 pragma

| 写法 | 用途 |
| --- | --- |
| #pragma vertex vert | 指定顶点入口 |
| #pragma fragment frag | 指定片元入口 |
| #pragma target 3.0 | 请求相应 Shader Model 能力，需考虑目标设备 |
| #pragma multi_compile_fog | 准备雾相关变体；还需传递雾因子与混雾代码 |
| #pragma multi_compile_instancing | 准备实例化变体；还需实例 ID 等配套宏 |

pragma 只声明需求或编译方式，不能替你完成实际效果逻辑。不要为了“避免报错”一律提高 target 到最高版本。

## 场景：用颜色检查中间值

**临时替换 frag 返回值；按数据存在情况选择：**

~~~hlsl
return half4(frac(IN.uv), 0, 1);               // 看 UV
return half4(normalize(IN.normalWS)*0.5+0.5,1); // 看法线
return half4(mask.xxx, 1);                     // 看遮罩
return half4(frac(IN.positionWS*0.1), 1);       // 看世界坐标周期
~~~

每次只保留一个 return。看标量时映射成灰度，看有负数的单位方向时先映射到 0—1，避免负值直接显示为黑色而掩盖信息。

## 从报错与症状查

| 问题 | 优先检查 |
| --- | --- |
| undeclared identifier | 名称拼写、变量作用域、缺少 include |
| 结构体没有这个成员 | Attributes/Varyings 与代码片段是否配套 |
| 材质粉色 | Console 编译错误、管线不匹配、Pass 是否可用 |
| 参数能调但画面不变 | HLSL 是否读取变量、关键字是否启用 |
| alpha 改了仍不透明 | Blend 与 Queue，见第 07 篇 |
| 模型能显示但没阴影 | 接收与投射是否都配置，见第 06 篇 |
| Editor 正常，打包功能消失 | 变体剥离、运行时启用状态、平台编译 |
| 多 Pass 少画一层 | LightMode、Renderer 调度，不能假设逐个执行 |

结合 Frame Debugger 查看实际执行了哪个 Pass、使用什么材质与渲染状态，比只盯着颜色猜测更有效。
