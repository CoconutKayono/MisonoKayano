# Unity Shader 技术美术的线性代数

> 目标：看到一个空间变换公式，就能想象画面如何变化；看到一个视觉问题，就能判断该使用哪个空间、哪一种变换。

这是一组原创学习笔记，不是 Unity 手册逐页翻译。数学部分从二维图形进入三维，代码以 **Unity 6、URP、HLSL** 为主。查证日期：2026-09-11。API 以项目实际安装的包版本为准，来源集中在 [[09-排错速查与参考资料]]。

## “注重表现意识”可以怎样理解

你的学习方向可以称为 **几何直觉驱动、面向视觉效果的数学学习**。

“数学分为逻辑和几何”并不准确：代数、几何是数学中的领域，逻辑则贯穿推理与证明。“几何就是表现”也不是严格等同：几何研究位置、形状和空间关系；美术表现还涉及光照、材质、色彩、构图和感知。但几何直觉确实是把线性代数变成可见效果的重要桥梁。

本教程每一步都尽量建立这条联系：

**视觉意图 → 空间关系 → 数学操作 → Shader 写法 → 观察与验证。**

例如：“扫描线始终水平”是视觉意图；“高度相对世界地面定义”是空间选择；“读取世界位置的 y 分量”才是计算。若先背一个矩阵名字，反而容易遗漏真正的需求。

## 全篇统一的约定

- 数学采用**列向量**：$p'=Mp$。右边的矩阵先作用。
- $M_{B\leftarrow A}$ 表示“输入 A 空间坐标，输出 B 空间坐标”，箭头用于标明方向。
- 二维图统一右为 +x，上为 +y。二维逆时针角度是图中约定，不直接替代 Unity 三维 Euler 角约定。
- 除投影章节外，都是欧氏空间中的线性或仿射变换。
- 图中点用圆点，基向量用带标签的箭头；变换前的参考图形使用虚线。
- 本教程的示意图由坐标公式精确绘制，不是 Unity 截图。图形与数值可以互相核对。

## 学会的标准

不用背公式，能回答下面四个问题，就抓住了主线：

1. 矩阵第一列为什么能看成局部 x 轴在目标空间中的去向？
2. 把世界点变到模型空间，为什么要先减去模型原点，再做逆线性变换？
3. 旋转后平移和先平移后旋转，为什么会分别像“原地转身再走”和“绕世界原点转”？
4. 物体拉宽后，为什么法线不能只用同样的矩阵拉宽？
