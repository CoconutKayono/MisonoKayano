# 脚本执行顺序

> 原文：[Script execution order](https://docs.unity3d.com/6000.7/Documentation/Manual/script-execution-order.html)

除了脚本内部函数的执行顺序外，应用程序还必须考虑 Unity 执行不同脚本 Component 的顺序。例如，如果有 `EngineBehaviour` 和 `SteeringBehaviour` 两个脚本，可能需要确保 `EngineBehaviour` 始终先于 `SteeringBehaviour` 更新。

可以通过以下方式配置脚本执行顺序：

- 在 Unity Editor 中，使用 Project Settings 窗口的 **Script Execution Order** 设置。
- 在代码中，为继承自 `MonoBehaviour` 的类添加 `[DefaultExecutionOrder]` Attribute。

## 重要注意事项与限制

- 在代码中使用 `[DefaultExecutionOrder]` 定义的顺序不会显示在 **Script Execution Order** 设置窗口中。如果代码中的 `[DefaultExecutionOrder]` 与 Project Settings 中为同一类型设置的值不同，Unity 使用 Editor UI 中定义的值。
- 如果将同一个脚本的多个实例添加到不同 `GameObject`，所有执行顺序值较小的实例都会先于值较大的实例执行，与脚本附加在哪个 `GameObject` 上无关。
- 以 Additive 方式加载多个 Scene 时，配置的脚本执行顺序会按 Scene 完整应用，而不是跨 Scene 交错应用。例如，`EngineBehaviour` 在一个 Scene 中配置为先于 `SteeringBehaviour` 执行时，会先完成该 Scene 的更新，再更新下一个 Scene。
- 如果多个脚本具有相同的配置执行顺序，或都使用默认执行顺序，它们之间的执行顺序不确定。即使测试时看起来始终一致，也不能依赖该行为，因为它不保证在不同构建、机器或 Unity 版本中保持一致。相关内容请参阅 [[03-事件函数执行顺序]]。

Script Execution Order 设置窗口不会影响以下内容：

- 标记了 `[RuntimeInitializeOnLoadMethod]` Attribute 的函数顺序。
- `OnDisable` 和 `OnDestroy` 函数的顺序。
