# 测试你的代码

> 原文：[Testing your code](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/test-framework-introduction.html)

为 Edit Mode 或 Play Mode 代码编写测试，然后通过 Unity Editor 的 **Test Runner** 窗口、命令行或代码运行这些测试。Unity Test Framework 集成了面向 .NET 语言的开源单元测试库 [NUnit](http://www.nunit.org/) 的定制版本，并在此基础上扩展了 Unity 专属功能。

Unity Test Framework 除了提供 [NUnit 测试](https://docs.nunit.org/articles/nunit/writing-tests/attributes/test.html)，还提供可以与帧、应用程序循环和 [[03-不进行Domain Reload进入Play Mode|Domain Reload]] 等 Unity 专属概念交互的 [Unity 测试](https://docs.unity3d.com/Packages/com.unity.test-framework@latest/index.html?subfolder=/api/UnityEngine.TestTools.UnityTestAttribute.html)。在 Play Mode 中，Unity 测试作为 [[01-编写和运行Coroutine|Coroutine]] 运行；在 Edit Mode 中，Unity 测试在 [`EditorApplication.update`](https://docs.unity3d.com/ScriptReference/EditorApplication-update.html) 回调循环中运行。

Unity 测试可以[[03-用于Editor的Yield指令|为 Unity Editor 生成 Yield 指令]]。指令完成后，测试运行会继续。你也可以在 Unity 测试中使用 `yield return null` 跳过一帧，将操作推迟到 `EditorApplication.update` 或[[01-每帧更新|逐帧游戏更新]]循环的下一次迭代。

本文档假设你熟悉 NUnit 以及 C# 单元测试的基本原则。如果不熟悉，请参阅 Microsoft 文档中的 [使用 NUnit 和 .NET Core 对 C# 进行单元测试](https://learn.microsoft.com/en-us/dotnet/core/testing/unit-testing-with-nunit) 和[单元测试最佳实践](https://learn.microsoft.com/en-us/dotnet/core/testing/unit-testing-best-practices)。

> **Note**：Unity Test Framework 是一个[核心 Unity Package](https://docs.unity3d.com/6000.7/Documentation/Manual/pack-core)，随 Unity Editor 安装程序一起分发。Unity Test Framework 当前使用基于 3.5 版本的 NUnit 定制版本。
