# 15. 测试用例

> 原文：[15. Test cases](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/course/test-cases.html)

## 学习目标

本节将介绍 `[TestCase]` 及类似的 NUnit 属性，以及如何在 UnityTest 中使用它们。

## 简介与动机

NUnit 提供了一些用于参数化测试的工具，可以使用不同的参数指定多个测试用例。这能大幅减少重复代码，让测试更容易使用。

下面是使用 `[TestCase]` 属性进行参数化测试的示例：

```csharp
[Test]
[TestCase(49, "a string", true)]
[TestCase(9, "something", false)]
public void MyTest(int firstValue, string secondValue, bool expectedOutcome)
{
    ...
}
```

这段代码会生成两个测试，每个测试向方法体传入不同的输入。

除了 `[TestCase]` 属性，NUnit 还提供 `[Values]` 属性，用于为每个独立输入指定一组值。例如：

```csharp
[Test]
public void MyTest([Values(49, 9)] int firstValue, [Values("a string", "something")] string secondValue)
{
    ...
}
```

指定多个输入参数时，它们会按照组合方式处理。这意味着每一种参数组合都会被测试。对于上面的示例，总共会得到 4 个用例：

```text
MyTest(49, "a string")
MyTest(49, "something")
MyTest(9, "a string")
MyTest(9, "something")
```

组合数量很容易急剧增加。有些组合可能没有价值，只会浪费时间，因此请谨慎使用这种方式。

`[TestCase]` 和 `[Values]` 都有更动态的对应版本，分别是 `[TestCaseSource]` 和 `[ValueSource]`。这两个属性都接收一个静态方法或数组，并由它们返回对象集合。

在这 4 种方式中，目前只有 `[ValueSource]` 受 `[UnityTest]` 支持。由于它会产生组合测试，如果测试需要多个参数并且为多个参数提供了 `[ValueSource]`，建议创建测试用例 struct。示例：

```csharp
[UnityTest]
public IEnumerator AddAsyncCalculatesCorrectValue([ValueSource(nameof(TestCases))] TestCase testCase)
{
    ...
}

private static IEnumerable TestCases()
{
    yield return new TestCase { value1 = 4, value2 = "a string" };
    yield return new TestCase { value1 = 8, value2 = "another string" };
}

public struct TestCase
{
    public int value1;
    public string value2;

    public override string ToString()
    {
        return $"{value1}, {value2}";
    }
}
```

## 练习

在 [sample](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/course/test-framework-general-introduction.html#import-samples) `15_TestCases` 中，有一个包含基础数学逻辑的类。它有两个方法：

- `Add` 接收两个整数，并将它们相加。
- `AddAsync` 也会将两个整数相加，但它以异步方式执行，并产生一个 `IEnumerator`。

任务是为这两个方法添加测试。`AddAsync` 会在几帧之后才返回结果，因此最适合使用 `[UnityTest]`。注意，只产生该 `IEnumerator` 还不够，因为 Test Framework 当前不支持嵌套产生。相反，应创建一个循环，逐个移动到下一个元素，直到迭代完成。在 `while` 循环的每一步，都让测试产生 `null`。

## 提示

- struct 中的 `ToString()` 实现用于在 Test Runner 树视图中提供可读信息。如果没有它，每个用例的测试参数只会显示 struct 名称。

## 解决方案

练习的解决方案位于 sample `15_TestCases_Solution` 中。两个方法的测试可以如下实现：

```csharp
[Test]
[TestCase(24, 80, 104)]
[TestCase(10, -15, -5)]
[TestCase(int.MaxValue, 10, int.MinValue + 9)]
public void AddCalculatesCorrectValue(int valueA, int valueB, int expectedResult)
{
    var myClass = new MyClass();

    var result = myClass.Add(valueA, valueB);

    Assert.That(result, Is.EqualTo(expectedResult));
}

[UnityTest]
public IEnumerator AddAsyncCalculatesCorrectValue([ValueSource(nameof(AdditionCases))] AddCase addCase)
{
    var myClass = new MyClass();

    var enumerator = myClass.AddAsync(addCase.valueA, addCase.valueB);
    while (enumerator.MoveNext())
    {
        yield return null;
    }
    var result = enumerator.Current;

    Assert.That(result, Is.EqualTo(addCase.expectedResult));
}

private static IEnumerable AdditionCases()
{
    yield return new AddCase { valueA = 24, valueB = 80, expectedResult = 104 };
    yield return new AddCase { valueA = 10, valueB = -15, expectedResult = -5 };
    yield return new AddCase { valueA = int.MaxValue, valueB = 10, expectedResult = int.MinValue + 9 };
}

public struct AddCase
{
    public int valueA;
    public int valueB;
    public int expectedResult;

    public override string ToString()
    {
        return $"{valueA} + {valueB} = {expectedResult}";
    }
}
```
