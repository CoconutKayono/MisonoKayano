# 10. 长时间运行的测试

> 原文：[10. Long running tests](https://docs.unity3d.com/6000.7/Documentation/Manual/test-framework/course/long-running-tests.html)

## 学习目标

本练习将介绍运行时间较长的 tests 的最佳实践和容易踩到的问题，例如 yield `WaitForSeconds` 的 tests。

## 简介与动机

在 Play Mode 中，UnityTest 可以返回 `WaitForSeconds` 等 yield instructions。之所以支持这一点，是因为在某些测试场景中，等待有限的一段时间是合理的。不过，总体来说，长时间运行的 tests 是一种应尽可能避免的不良实践。

如果无法避免长时间运行的 test，建议为 test 添加 `[Category]` 和 `[Explicit]` 属性。`[Category]` 属性用于为 test 标记 category name，之后可以将其作为 filter，有选择地运行 tests 子集。`[Explicit]` 属性可确保 test 在运行所有 tests 时不会默认执行。只有在 UI 中明确选中该 test，或选中其 category 时，才会运行该 test。

```csharp
[UnityTest]
[Explicit, Category("integration")]
public IEnumerator MySlowTest()
{
    ...
}
```

实际使用时，如果将一些长时间运行的 tests 归入 `integration` category，则只有在选中 `integration` category 时才会运行它们。这样，即使项目规模很大，也可以让 **All tests** 保持相对较快。

也可以在 class 级别指定 `[Explicit]` 和 `[Category]` 属性，此时它们会应用于该 class 中的所有 tests；还可以在 assembly 级别指定，此时它们会应用于该 assembly 中的所有 tests。下面是将属性应用于 assembly 的示例：

```csharp
[assembly:Explicit]
[assembly:Category("integration")]
```

在 `AssemblyInfo.cs` 文件中定义 assembly 级别的属性是一种良好实践。

## 练习

导入 sample `10_LongRunningTests`，它已经设置了一个用于 Play Mode 的 test assembly。

练习要求添加一个新的 UnityTest，使其 yield 一个 `WaitForSeconds` instruction，然后使用 `[Category]` 和 `[Explicit]` tags 对其进行相应标记。

点击 **RunAll** 时，test 应该被跳过。在 UI 的 category dropdown 中选中该 category 后，再点击 **RunAll**，test 就不应被跳过。

## 解决方案

sample `10_LongRunningTests_Solution` 包含解决方案。

实现的 test 可以如下所示：

```csharp
[UnityTest]
[Explicit, Category("integration")]
public IEnumerator ASlowTest()
{
    yield return new WaitForSeconds(5);
}
```
