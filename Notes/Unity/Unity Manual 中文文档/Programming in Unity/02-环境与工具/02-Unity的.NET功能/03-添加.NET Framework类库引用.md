# 添加 .NET Framework 类库引用

> 原文：[Add class library references to .NET Framework](https://docs.unity3d.com/6000.7/Documentation/Manual/dotnet-profile-assemblies.html)

当项目使用 .NET Framework API Compatibility Level 时，Unity 默认引用以下程序集：

```text
mscorlib.dll
System.dll
System.Core.dll
System.Runtime.Serialization.dll
System.Xml.dll
System.Xml.Linq.dll
```

如果 Unity 项目使用了默认不会参与编译的 .NET 类库 API，可以向 C# Compiler 提供要引用的额外程序集列表。

## 前提条件

项目的 API Compatibility Level 必须设置为 **.NET Framework**。如果项目使用 .NET Standard，则所有可引用的 .NET 类库 API 默认都已被引用。修改设置的方法是：在 Unity Editor 中选择 **Edit > Project Settings**，打开 **Player** 页签，在 **Other Settings > Configuration** 中将 **Api Compatibility Level** 设置为 **.NET Framework**。

## 创建 response 文件

要引用其他类库程序集，可以创建 `.rsp`（response）文件，向其中写入要传递给 C# Compiler 的命令行参数：

1. 在 Unity 项目的 `Assets` 文件夹中创建名为 `csc.rsp` 的文件。
2. 如果要引用的程序集文件还不在项目的 `Assets` 文件夹中，将它们移入该文件夹。
3. 在 `csc.rsp` 中填写要引用的程序集对应的命令行参数。

例如，如果项目使用定义在 `System.Net.Http.dll` 程序集中的 `HttpClient` 类，而该程序集尚未被引用，C# Compiler 可能会报告如下错误：

```text
The type `HttpClient` is defined in an assembly that is not referenced. You must add a reference to assembly 'System.Net.Http, Version=4.0.0.0, Culture=neutral, PublicKeyToken=b03f5f7f11d50a3a'.
```

要解决此错误，请创建 `csc.rsp`，并加入以下命令行参数：

```text
-r:System.Net.Http.dll
```

对于每个要引用的程序集，都要添加一行对应的命令行参数。

> [!IMPORTANT]
> 如果将 API Compatibility Level 从 .NET Framework 改为 .NET Standard，而 `csc.rsp` 引用了 .NET Standard 中不存在的程序集，编译会失败。要解决此问题，请在切换到 .NET Standard 前编辑 `csc.rsp`，移除仅存在于 .NET Framework Profile 中的程序集引用。

## 检查默认程序集

Unity 默认引用的程序集包括核心运行时、UnityEngine、UnityEditor（仅 Editor 程序集）以及项目包提供的程序集。默认引用会随 API Compatibility Level 和 Unity 版本变化，因此应以当前项目生成的程序集列表为准。

## 添加程序集引用

在项目的 `Assets` 目录中创建与编译目标匹配的 response 文件，并使用 `-r:` 或 `-reference:` 指定程序集路径。例如，可以在适用于 Editor 的 response 文件中加入某个 .NET Framework DLL 的引用。文件名和作用域必须遵循 Unity 对 C# Compiler response file 的约定，否则 Unity 不会把它应用到预期的程序集。

添加引用后重新触发脚本编译。使用程序集 API 前仍要确认它在当前 API Compatibility Level、Scripting Backend 和目标平台上可用；额外引用只解决编译期可见性，不能为 Player 提供目标平台不存在的运行时实现。
