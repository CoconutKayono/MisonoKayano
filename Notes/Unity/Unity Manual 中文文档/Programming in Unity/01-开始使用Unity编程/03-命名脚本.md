# 命名脚本

> 原文：[Naming scripts](https://docs.unity3d.com/6000.7/Documentation/Manual/naming-scripts.html)

为脚本文件和其中声明的类选择合适的名称非常重要。使用恰当的文件名，并将类组织到 Namespace 中，有助于编译器准确识别类，避免错误。

## 脚本文件名

创建脚本时输入的文件名，也会被用于脚本中定义的类名。最佳实践是让脚本文件名与其中定义的类名保持一致。

对于继承内置 Unity 类型 `MonoBehaviour` 和 `ScriptableObject` 的脚本，即使文件名不匹配，Unity 仍可能解析脚本中定义的类类型，但存在以下限制：

- 如果一个脚本中定义了多个类，Unity 会选择名称与文件名相同的类。
- 如果使用 C# `partial` 关键字，将一个继承自 `MonoBehaviour` 的类拆分到多个文件中，只有名称与 partial 类相同的文件才能将该类用作 Component。

> [!NOTE]
> 如果类名无法明确匹配到某个文件，Unity 会在所有这些情况下显示警告。

## 类名与 Namespace

当项目的不同部分声明了多个同名类时，就会产生命名冲突。项目规模越大、贡献者越多，发生命名冲突的可能性就越高。例如，一名开发者可能编写控制主玩家角色的代码，另一名开发者编写控制敌人的等效代码。如果两人都将主类命名为 `Controller`，编译器就无法判断代码中的 `Controller` 指的是哪一个类。

为避免类名冲突，C# 编程的最佳实践是使用 Namespace 组织类。Namespace 是一组类的集合；加在类名前的 Namespace 可以构成完整且无歧义的类名。关于 Namespace 的更多信息，请参阅 Microsoft 的 [Namespace 文档](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/namespaces/)。

下面的示例中，`Controller1` 和 `Controller2` 属于名为 `Enemy` 的 Namespace：

```csharp
namespace Enemy
{
    public class Controller1 : MonoBehaviour { }
    public class Controller2 : MonoBehaviour { }
}
```

在代码中使用完整名称即可明确引用这些类：`Enemy.Controller1` 和 `Enemy.Controller2`。你可以在已有类声明外添加 Namespace 声明，因此不必单独修改每个类的名称。无论类位于哪个源文件，都可以在类外添加 Namespace 声明。

可以在文件顶部添加 `using` 指令，避免反复输入 Namespace 前缀：

```csharp
using Enemy;
```

这样，编译器会将此文件中的 `Controller1` 和 `Controller2` 分别解析为 `Enemy.Controller1` 和 `Enemy.Controller2`。如果脚本还需要引用其他 Namespace 中的同名类（例如名为 `Player` 的类），就必须写出 Namespace 前缀。如果在同一文件中通过 `using` 导入了包含冲突类名的两个 Namespace，编译器会报告错误。

## 多个 Namespace 的限制

Unity 对 Namespace 与 `MonoBehaviour` 或 `ScriptableObject` 类有一项特殊限制：如果文件中定义了 `MonoBehaviour` 或 `ScriptableObject` 类，就不能在该文件中使用多个 Namespace。

Unity 会在 Console 中显示以下警告：

```text
Class MyClass can not exist in multiple namespaces in the same file, even if one is excluded with preprocessor directives. Please move these to separate files if this is the case.
```

如果文件在一个 Namespace 中定义了 `MonoBehaviour`，又在同一文件的另一个 Namespace 中定义了其他类，Unity 将无法识别这个 `MonoBehaviour` 类，因此你不能将它添加到 `GameObject` 上。

此限制在 Unity 2020.1 中引入，用于提升导入和编译速度。因此，一些在该限制引入前编写的旧 Asset Store Package 可能会因此无法正常工作。要修复相关问题，请将每个 Namespace 中的类代码拆分到不同文件中。
