# 序列化规则

> 原文：[Serialization rules](https://docs.unity3d.com/6000.7/Documentation/Manual/script-serialization-rules.html)

Unity 使用自己实现的、为运行时高效运行而设计的序列化系统。因此，Unity 中的序列化行为不同于其他编程环境。本页说明字段和类型必须满足哪些条件，Unity 才会序列化它们。

## 关键原则

Unity 序列化遵循以下原则：

- Unity 序列化 C# 类的字段，而不是属性。详情请参阅[属性的序列化](#属性的序列化)。
- Unity 支持标准 .NET 的 `[Serializable]` 和 `[NonSerialized]` 属性，但它们的行为还受到下文 Unity 特有规则的约束。
- Unity 会自动序列化继承自 `UnityEngine.Object` 的内置类型。只有作为 Unity 对象字段使用的自定义类或结构体需要添加 `[Serializable]`。
- `[Serializable]` 属性不会被子类继承。继承层次结构中的每个类都必须单独添加它。Unity 不要求无法修改的系统基类（例如 `System.Object`）带有 `[Serializable]`。对于其他无法修改的基类（例如第三方库中的类型），可使用 `[MakeSerializable]` 将其加入序列化层次结构。
- `[NonSerialized]` 会同时将字段排除在序列化和 Inspector 之外。如果只想在 Inspector 中隐藏字段而不阻止序列化，请使用 `[HideInInspector]`。

## 字段序列化规则

Unity 的 serializer 直接处理 C# 类的**字段**而不是属性，因此字段必须满足特定条件才会被序列化。

要使用字段序列化，必须确保该字段：

- 是 `public`，或带有 `[SerializeField]` 属性。
  - **注意**：某些情况下 `private` 字段也会被序列化。详情请参阅[[02-Unity如何使用序列化#热重载]]。
- 不是 `static`。
- 不是 `const`。
- 不是 `readonly`。
- 字段类型可被序列化，包括：
  - 基本数据类型（`int`、`float`、`double`、`bool`、`string` 等）。
  - Enum 类型（32 位或更小）。
  - 定长缓冲区。
  - Unity 内置类型，例如 `Vector2`、`Vector3`、`Rect`、`Matrix4x4`、`Color`、`AnimationCurve`。
  - 带有 `[Serializable]` 属性的自定义 Struct。
  - 对继承自 `UnityEngine.Object` 的对象的引用。
  - 带有 `[Serializable]` 属性的自定义类（参阅[自定义类的序列化](#自定义类的序列化)）。
  - 上述字段类型的一维 Array 或 `List<T>`。
  - 带有 `[SerializeField]` 属性的 `Dictionary<TKey, TValue>`。参阅 [[04-Dictionary序列化]]。

**注意**：使用默认的 inline serialization 时，如果同一个元素在集合中出现两次，序列化后的集合会包含两个独立副本，而不是对同一对象的两个引用。若要保留对同一对象的多个引用，请使用 `[SerializeReference]`。

**注意**：Unity 不支持多维数组、交错数组，或直接嵌套在另一个集合中的集合（例如 `List<Dictionary<string, int>>` 或 `Dictionary<string, int>[]`）。若要序列化此类结构，可以：

- 将嵌套类型包装在类或结构体中。
- 实现 `ISerializationCallbackReceiver`，使用序列化回调执行[[05-自定义序列化#自定义序列化]]。

下面的示例演示一个常见错误：自定义类缺少 `[Serializable]`：

```csharp
// INCORRECT: Missing [Serializable] — Unity won't serialize PlayerStats
public class PlayerStats
{
    public int health;
    public int mana;
}

public class Player : MonoBehaviour
{
    public PlayerStats stats; // This field won't be serialized
}
```

要使该类可序列化，请添加 `[Serializable]` 属性：

```csharp
// CORRECT: PlayerStats is now serializable
[System.Serializable]
public class PlayerStats
{
    public int health;
    public int mana;
}

public class Player : MonoBehaviour
{
    public PlayerStats stats; // Serialized correctly
}
```

更多示例以及编译时检测序列化问题的信息，请参阅[[07-序列化规则分析器参考]]。

## 自定义类的序列化

Unity 要序列化自定义类，该类必须：

- 带有 `[Serializable]` 属性。
- 不是 static。

当你把继承自 `UnityEngine.Object` 的类实例赋给字段并保存该字段时，Unity 会将字段序列化为对该实例的引用，并独立序列化实例本身。因此，多个字段引用同一实例时不会重复它。但对于不继承 `UnityEngine.Object` 的自定义类，Unity 会将实例状态直接包含在引用它的 MonoBehaviour 或 ScriptableObject 的序列化数据中。这有两种方式：**inline** 和 **`[SerializeReference]`**。

- **Inline serialization**：默认情况下，如果引用自定义类的字段没有指定 `[SerializeReference]`，Unity 会按值 inline 序列化该类。如果多个不同字段保存了同一自定义类实例的引用，序列化后它们会成为不同对象。Unity 反序列化这些字段时，它们包含的是数据相同但彼此独立的对象。
- **`[SerializeReference]` serialization**：如果指定 `[SerializeReference]`，Unity 会把对象建立为 managed reference。宿主对象仍将对象直接存储在自己的序列化数据中，但会存放在专用 registry 区域。

**重要**：`[SerializeReference]` 只能用于引用类型（类）的字段。不能用于 Struct、Enum 或基本类型（`int` 等）这类值类型。值类型始终 inline 序列化，不能按引用序列化。

`[SerializeReference]` 会带来一些开销，但支持以下情况：

- **Null 字段**。Inline serialization 无法表示 null；它会将 null 替换为一个字段未赋值的 inline 对象。
- **共享引用**。如果多个不同字段引用同一个自定义类实例而未使用 `[SerializeReference]`，序列化后它们会成为独立对象。
- **图和循环数据**（例如对象引用回自身）。Inline serialization 会按值复制完整对象图，因此不能表示循环。详情请参阅[序列化循环](#序列化循环)。
- **多态**。如果创建一个继承自父类的类，并将它赋给类型为父类的字段，而没有使用 `[SerializeReference]`，Unity 只会序列化属于父类的字段。反序列化时，Unity 会实例化父类，而不是派生类。
- **稳定标识符**，用于指向特定对象，而不必硬编码对象的数组位置或搜索整个数组。参阅 `Serialization.ManagedReferenceUtility.SetManagedReferenceIdForObject`。

**注意**：Inline serialization 更高效。除非明确需要 `[SerializeReference]` 提供的某项功能，否则应使用 inline serialization。有关如何使用 `[SerializeReference]` 的完整详情，请参阅 [SerializeReference](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SerializeReference.html) 文档。

使用 `[SerializeReference]` 时，Unity 不会严格强制要求 `[Serializable]`，但如果类未标记 `[Serializable]`，会在 Console 中显示警告。可以使用 `[MakeSerializable]` 属性抑制此警告。

### 序列化循环

使用 inline serialization（不带 `[SerializeReference]`）时，Unity 按如下方式处理循环：

- **直接自引用**（类包含自身类型的字段）：Unity 在序列化时完全忽略该类。反序列化后，此类型的任何字段始终为 null。
- **间接循环**（例如 **A** > **B** > **A**）：Unity 会序列化该结构，但在递归 10 层后停止并丢弃剩余数据。

对于直接自引用，Unity 会静默忽略该字段。对于间接循环，Unity 会记录一条表示超过序列化深度限制的警告，并丢弃剩余数据。对相关字段使用 `[SerializeReference]`，可以正确序列化带循环的数据结构。有关编译时检测循环问题的信息，请参阅分析器规则 [[07-序列化规则分析器参考#uac1005|UAC1005]] 至 [[07-序列化规则分析器参考#uac1008|UAC1008]]。

## 属性的序列化

Unity 不会序列化属性。但是，如果属性由字段支持，则该字段可以被序列化。

- 如果属性有显式 backing field，Unity 会按普通序列化规则序列化它。例如：

```csharp
public int MyInt
{
get => m_backing;
private set => m_backing = value;
}
[SerializeField] private int m_backing;
```

- 如果属性是 auto-property，编译器会为它隐式生成 private backing field，普通序列化规则适用于此 backing field。可以在属性的属性上使用 `field:` 前缀，将属性应用到此字段。例如：

```csharp
// Serialize the implicit backing field behind this property
[field: SerializeField]
public int MyInt { get; set; }

// Serialize the implicit backing field behind this property as a reference instead of inline
[field: SerializeReference]
public MyType MyReferenceToType { get; set;}

// Do not serialize the backing field for this property even when hot-reloading
[field: NonSerialized]
public bool NeverSerializedProperty { get; set;}
```

## 避免常见序列化问题

Unity 会跳过不符合序列化规则的字段，而且通常不会产生明显错误，这可能导致意外的数据丢失。为避免最常见的问题，请遵循以下实践：

- **为每个准备序列化的自定义类和结构体添加 `[Serializable]`。** 这同时适用于 inline serialization 和 `[SerializeReference]`。
- **为继承层次结构中的每个类标记 `[Serializable]`。** 该属性不会被继承，因此每个类都必须显式标记。
- **对复杂关系使用 `[SerializeReference]`。** 如果数据结构包含 null 引用、多态、共享引用或循环，请使用 `[SerializeReference]` 而不是 inline serialization。
- **避免 inline serialization 中的循环。** 没有 `[SerializeReference]` 时，直接自引用循环会使 Unity 完全忽略字段，间接循环则受到 10 层递归限制。使用索引、ID 或 `[SerializeReference]` 避免这些问题。
- **不要对值类型使用 `[SerializeReference]`。** Struct、基本类型和 Enum 始终 inline 序列化；`[SerializeReference]` 只适用于引用类型（类）。

[[07-序列化规则分析器参考]]会在编译时检测这些问题，并在 IDE 中提供实时反馈。

﻿# 序列化规则

> 原文：[Serialization rules](https://docs.unity3d.com/6000.7/Documentation/Manual/script-serialization-rules.html)

Unity 使用自己设计的 serialization system，以便在 runtime 高效运行。因此，Unity 中的 serialization 与其他 programming environment 中的 serialization 行为不同。本页说明字段和类型必须满足哪些条件，Unity 才会序列化它们。

## 关键原则

以下原则适用于 Unity serialization：

- Unity 序列化 C# classes 的 fields，而不是它们的 properties。详情请参阅“[属性的序列化](#属性的序列化)”部分。
- Unity 支持标准 .NET 的 [`[Serializable]`](https://learn.microsoft.com/en-us/dotnet/api/system.serializableattribute?view=net-9.0) 和 [`[NonSerialized]`](https://learn.microsoft.com/en-us/dotnet/api/system.nonserializedattribute) attributes，但它们的行为还受下文所述 Unity-specific rules 的约束。
- Unity 会自动序列化继承自 [`UnityEngine.Object`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Object.html) 的 built-in types。只有当 custom classes 或 structs 作为 Unity objects 中的 fields 使用时，才需要为它们应用 `[Serializable]`。
- `[Serializable]` attribute 不会被 subclasses 继承。你必须将它应用到 inheritance hierarchy 中的每个 class。Unity 不要求对无法修改的 system base classes（例如 `System.Object`）添加 `[Serializable]`。对于其他无法修改的 base classes（例如 third-party libraries 中的 types），使用 [`[MakeSerializable]`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/MakeSerializableAttribute.html) 将它们加入 serialization hierarchy。
- `[NonSerialized]` 会将 field 同时排除在 serialization 和 Inspector 之外。若要在 Inspector 中隐藏 field 但不阻止 serialization，请使用 [`[HideInInspector]`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/HideInInspector.html)。

## 字段序列化规则

Unity serializers 直接作用于 C# classes 的 **fields**，而不是它们的 properties，因此只有满足特定条件的 fields 才会被 Unity 序列化。

要使用 field serialization，必须确保该 field：

- 是 `public`，或带有 [`[SerializeField]`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SerializeField.html) attribute。

  **注意**：在某些情况下，`private` fields 也会被序列化。详情请参阅 [[02-Unity如何使用序列化#热重载|Hot reloading]]。
- 不是 `static`。
- 不是 `const`。
- 不是 `readonly`。
- 具有可序列化的 field type：

  - Primitive data types（`int`、`float`、`double`、`bool`、`string` 等）。
  - Enum types（32 bits 或更小）。
  - Fixed-size buffers。
  - Unity built-in types，例如 `Vector2`、`Vector3`、`Rect`、`Matrix4x4`、`Color`、`AnimationCurve`。
  - 带有 `[Serializable]` attribute 的 custom structs。
  - 对继承自 [UnityEngine.Object](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Object.html) 的 objects 的 references。
  - 带有 `[Serializable]` attribute 的 custom classes（参阅[自定义类的序列化](#自定义类的序列化)）。
  - 上述 field type 的 array 或 `List<T>`。
  - 带有 `[SerializeField]` attribute 的 `Dictionary<TKey, TValue>`。参阅 [[04-Dictionary序列化]]。

**注意**：使用默认的 inline serialization 时，如果同一个 element 在 collection 中出现两次，序列化后的 collection 会包含两个独立副本，而不是指向同一 object 的两个 references。要保留同一 object 的多个 references，请使用 [`[SerializeReference]`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SerializeReference.html)。

**注意**：Unity 不支持 multidimensional arrays、jagged arrays，或直接嵌套在另一个 collection 中的 collections（例如 `List<Dictionary<string, int>>` 或 `Dictionary<string, int>[]`）的 serialization。若需要序列化此类结构，有两个选项：

- 将 nested type 包装在 class 或 struct 中。
- 实现 [`ISerializationCallbackReceiver`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/ISerializationCallbackReceiver.html)，使用 serialization callbacks 执行 [[05-自定义序列化|custom serialization]]。

以下示例展示了 custom class 缺少 `[Serializable]` 的常见错误：

```csharp
// INCORRECT: Missing [Serializable] — Unity won't serialize PlayerStats
public class PlayerStats
{
    public int health;
    public int mana;
}

public class Player : MonoBehaviour
{
    public PlayerStats stats; // This field won't be serialized
}
```

要使 class 可序列化，请添加 `[Serializable]` attribute：

```csharp
// CORRECT: PlayerStats is now serializable
[System.Serializable]
public class PlayerStats
{
    public int health;
    public int mana;
}

public class Player : MonoBehaviour
{
    public PlayerStats stats; // Serialized correctly
}
```

## 自定义类的序列化

要让 Unity 序列化 custom class，必须确保该 class：

- 具有 [`[Serializable]`](https://learn.microsoft.com/en-us/dotnet/api/system.serializableattribute?view=net-9.0) attribute。
- 不是 static。

当你将派生自 `UnityEngine.Object` 的 class instance 赋给一个 field，且 Unity 保存该 field 时，Unity 会将该 field 序列化为指向该 instance 的 reference。Unity 独立序列化 instance 本身，因此当多个 fields 被赋给同一个 instance 时不会重复它。但对于不派生自 `UnityEngine.Object` 的 custom classes，Unity 会将 instance 的 state 直接包含在引用它的 MonoBehaviour 或 ScriptableObject 的 serialized data 中。这可以通过两种方式发生：**inline** 和 **`[SerializeReference]`**。

- **Inline serialization**：默认情况下，如果引用该 class 的 field 没有指定 `[SerializeReference]`，Unity 会按 value 将 custom classes inline 序列化。这意味着，如果你在几个不同 fields 中存储对 custom class instance 的 reference，序列化后它们会变成不同的 objects。之后 Unity 对 fields 进行 deserialization 时，它们会包含数据相同但彼此独立的 objects。
- **`[SerializeReference]` serialization**：如果指定了 `[SerializeReference]`，Unity 会将 object 建立为 managed reference。host object 仍然将 objects 直接存储在自己的 serialized data 中，但存储在一个专用 registry section 中。

**重要**：只能在 reference types（classes）的 fields 上使用 `[SerializeReference]`。不能将它用于 structs、enums 或 primitive types（`int`、`float` 等）等 value types。Value types 总是 inline 序列化，不能按 reference 序列化。

`[SerializeReference]` 会增加一些 overhead，但支持以下情况：

- **Null fields**。Inline serialization 无法表示 null，而会用一个 fields 未赋值的 inline object 替换 null。
- **Shared references**。如果不使用 `[SerializeReference]`，在多个不同 fields 中存储对同一 custom class instance 的 reference 时，序列化后会变成独立 objects。
- **Graphs and cyclical data**（例如 object 引用自身）。Inline serialization 按 value 复制完整 object graph，因此无法表示 cycles。详情请参阅[序列化循环](#序列化循环)。
- **Polymorphism**。如果创建一个派生自 parent class 的 class，并将其赋给以 parent class 为 type 的 field，那么不使用 `[SerializeReference]` 时 Unity 只会序列化属于 parent class 的 fields。Unity 对 class instance 进行 deserialization 时，会实例化 parent class，而不是 derived class。
- **Stable identifiers**，用于指向特定 object，而无需硬编码 object 的 array position 或搜索整个 array。参阅 [`Serialization.ManagedReferenceUtility.SetManagedReferenceIdForObject`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Serialization.ManagedReferenceUtility.SetManagedReferenceIdForObject.html)。

**注意**：Inline serialization 更高效，除非明确需要 `[SerializeReference]` 支持的某项功能，否则应使用 inline serialization。有关 `[SerializeReference]` 用法的完整细节，请参阅 [`SerializeReference`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SerializeReference.html) documentation。

使用 `[SerializeReference]` 时，Unity 不会严格强制要求 `[Serializable]`，但如果 class 未标记 `[Serializable]`，会在 Console 中显示 warning。可以使用 [`[MakeSerializable]`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/MakeSerializableAttribute.html) attribute suppress 此 warning。

### 序列化循环

使用 inline serialization（不带 `[SerializeReference]`）时，Unity 按如下方式处理 cycles：

- **Direct self-reference**（class 包含自身 type 的 field）：Unity 在 serialization 中完全忽略该 class。反序列化后，这种 type 的任何 field 始终为 null。
- **Indirect cycles**（例如 **A** > **B** > **A**）：Unity 会序列化该 structure，但在递归 10 层后停止，并丢弃其余 data。

对于 direct self-references，Unity 会静默忽略该 field。对于 indirect cycles，Unity 会记录 warning，指出超出 serialization depth limit，并丢弃剩余 data。对存在 cycles 的 data structures 使用 `[SerializeReference]`，可正确完成 serialization。要在 compile time 检测 cycle issues，请参阅 analyzer rules [[07-序列化规则分析器参考#UAC1005|UAC1005]] 到 [[07-序列化规则分析器参考#UAC1008|UAC1008]]。

## 属性的序列化

Unity 不序列化 properties。不过，如果 property 有 backing field，该 field 可以被序列化。

- 如果 property 有显式 backing field，Unity 会根据常规 serialization rules 对其进行序列化。例如：

```csharp
public int MyInt
{
get => m_backing;
private set => m_backing = value;
}
[SerializeField] private int m_backing;
```

- 如果 property 是 auto-property，compiler 会隐式生成一个 private backing field，常规 serialization rules 适用于这个 backing field。可以在 property 的 attributes 上使用 `field:` prefix，为该 field 应用 attributes。例如：

```csharp
// Serialize the implicit backing field behind this property
[field: SerializeField]
public int MyInt { get; set; }

// Serialize the implicit backing field behind this property as a reference instead of inline
[field: SerializeReference]
public MyType MyReferenceToType { get; set;}

// Do not serialize the backing field for this property even when hot-reloading
[field: NonSerialized]
public bool NeverSerializedProperty { get; set;}
```

## 避免常见的 serialization issues

Unity 会跳过不符合其 serialization rules 的 fields，且通常不会产生可见 error，这可能导致意外的数据丢失。要避免最常见的问题，请遵循以下实践：

- **为准备序列化的每个 custom class 和 struct 添加 `[Serializable]`。** 这同时适用于 inline serialization 和 `[SerializeReference]`。
- **为 inheritance hierarchy 中的每个 class 标记 `[Serializable]`。** 该 attribute 不会被继承，因此每个 class 都必须显式标记。
- **对复杂 relationships 使用 `[SerializeReference]`。** 如果 data structure 涉及 null references、polymorphism、shared references 或 cycles，请使用 `[SerializeReference]`，而不是 inline serialization。
- **避免 inline serialization 中的 cycles。** 不使用 `[SerializeReference]` 时，direct self-reference cycles 会使 Unity 完全忽略该 field，而 indirect cycles 使用 10 层 recursion limit 进行 serialization。使用 indices、IDs 或 `[SerializeReference]` 避免这些问题。
- **不要在 value types 上使用 `[SerializeReference]`。** Structs、primitives 和 enums 总是 inline 序列化；`[SerializeReference]` 只适用于 reference types（classes）。

[[07-序列化规则分析器参考|Serialization rules analyzer]] 会在 compile time 检测这些 issues，并在 IDE 中提供 real-time feedback。
