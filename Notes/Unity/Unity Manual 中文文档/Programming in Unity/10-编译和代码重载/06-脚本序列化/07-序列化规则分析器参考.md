# 序列化规则分析器参考

> 原文：[Serialization rules analyzer reference](https://docs.unity3d.com/6000.7/Documentation/Manual/script-serialization-analyzer.html)

Unity 提供 serialization Roslyn diagnostic analyzer，通过在编译时检测使用 Unity serialization system 时的常见错误，帮助你编写正确的序列化代码。它会在 IDE 中提供实时反馈，在序列化问题造成运行时问题之前阻止它们。

有关 Unity 序列化规则的详细信息，请参阅 [[01-序列化规则]]。有关常见序列化问题及避免方法的摘要，请参阅[[01-序列化规则#避免常见序列化问题]]。

### UAC1000：SerializeReference 字段类型缺少 Serializable 属性

**严重性**：Warning。

使用 `[SerializeReference]` 序列化字段时，其类型应带有 `[Serializable]` 属性。如果类型缺少 `[Serializable]`，Unity 会发出警告。尽管该类型在其他序列化上下文中不被视为可序列化，字段仍会通过 `[SerializeReference]` 序列化，这可能造成不一致行为。要避免此问题，请将 `[Serializable]` 添加到类，或在无法修改类型时使用 `[MakeSerializable]` 属性。

为类型标记 `[Serializable]`（无法修改类型时使用 `[MakeSerializable]`）可以明确表达意图，并使不同 Unity serialization path 的行为保持一致。没有该标记时，`[SerializeReference]` 字段仍会持久化数据，而依赖类型可序列化性的其他序列化形式可能跳过它，导致结果不一致。

**错误示例：与 `[SerializeReference]` 一起使用的类缺少 `[Serializable]`**：

```csharp
// INCORRECT: Missing [Serializable] on CustomData
public class CustomData
{
    public int value;
}

public class MyBehaviour : MonoBehaviour
{
    [SerializeReference] public CustomData data; // UAC1000: CustomData lacks [Serializable]
}
```

**正确示例：为类添加 `[Serializable]`**：

```csharp
// CORRECT: Add [Serializable] to the class
[System.Serializable]
public class CustomData
{
    public int value;
}

public class MyBehaviour : MonoBehaviour
{
    [SerializeReference] public CustomData data; // OK
}
```

### UAC1001：Public 字段因缺少 Serializable 属性而被序列化跳过

**严重性**：Warning。

Unity 会将自定义类的 public 字段视为序列化候选。类型没有 `[Serializable]` 时，Unity 不会序列化该类型的字段；进入 Play mode 或保存 Scene 时可能丢失数据。

根据意图，可以采取以下修复方式：

- 如果需要序列化，为字段类型添加 `[Serializable]`。
- 如果不需要序列化，将字段改为 private。
- 为字段添加 `[System.NonSerialized]`，明确标记不序列化。
- 如果只需要 public API surface，将字段转换为属性（Unity 不序列化属性）。

没有 `[Serializable]` 时，Unity 会在序列化期间跳过字段，造成数据丢失。问题在于代码可以成功编译，但字段会在序列化和反序列化周期中丢失值。

**错误示例：作为序列化字段使用的类缺少 `[Serializable]`**：

```csharp
// INCORRECT: Missing [Serializable] on PlayerStats
public class PlayerStats
{
    public int health;
    public int mana;
}

public class Player : MonoBehaviour
{
    public PlayerStats stats; // UAC1001: PlayerStats lacks [Serializable]
}
```

**正确示例：为类添加 `[Serializable]`**：

```csharp
// CORRECT: Add [Serializable] to the class
[System.Serializable]
public class PlayerStats
{
    public int health;
    public int mana;
}

public class Player : MonoBehaviour
{
    public PlayerStats stats; // OK - will be serialized inline
}
```

### UAC1002：继承层次结构的序列化不完整

**严重性**：Warning。

序列化层次结构中的每个类都必须显式标记 `[Serializable]`，因为该属性不会从基类继承到派生类。如果层次结构中的任意类缺少 `[Serializable]`，Unity 可能不会序列化该类声明的字段，从而在进入 Play mode、保存 Scene 或执行 domain reload 时造成意外数据丢失。

如果无法修改基类（例如它来自第三方库或预编译 assembly），可使用 assembly-level 的 `[MakeSerializable]` 属性将其标记为可序列化，而无需修改源代码。修复此警告后，analyzer 也会检查基类自己的字段。详情参阅[限制：基类字段分析](#limitations)。

**错误示例：继承层次结构中的基类缺少 `[Serializable]`**：

```csharp
// INCORRECT: Missing [Serializable] on base class
public class BaseEntity
{
    public string name;
}

[System.Serializable]
public class Enemy : BaseEntity  // UAC1002: Enemy's hierarchy incomplete (BaseEntity lacks [Serializable])
{
    public int damage;
}
```

**正确示例：在层次结构中的每个类上标记 `[Serializable]`**：

```csharp
// CORRECT: Mark each class in the hierarchy with [Serializable]
[System.Serializable]
public class BaseEntity
{
    public string name;
}

[System.Serializable]
public class Enemy : BaseEntity
{
    public int damage;
}

public class GameManager : MonoBehaviour
{
    public Enemy enemy; // OK - entire hierarchy is serializable
}
```

**另一种正确示例：对无法访问的基类使用 `[MakeSerializable]`**：

如果无法修改基类（例如它来自预编译 assembly 或第三方库），可以使用 `[MakeSerializable]` assembly 属性：

```csharp
// CORRECT: Use [MakeSerializable] for inaccessible base classes
[assembly: UnityEngine.Serialization.MakeSerializable(typeof(ThirdPartyLibrary.BaseEntity))]

namespace ThirdPartyLibrary
{
    // This class is from a precompiled assembly - you can't modify it
    public class BaseEntity
    {
        public string name;
    }
}

namespace YourGame
{
    [System.Serializable]
    public class Enemy : ThirdPartyLibrary.BaseEntity
    {
        public int damage;
    }

    public class GameManager : MonoBehaviour
    {
        public Enemy enemy; // OK - BaseEntity marked serializable via [MakeSerializable]
    }
}
```

### UAC1003：在 Struct 上使用 `[SerializeReference]`

**严重性**：Error。

`[SerializeReference]` 只能用于引用类型（类）。它提供 null 支持、多态和共享引用等引用语义，而这些语义与值类型不兼容。Struct 是值类型，始终 inline 序列化，因此在 Struct 上使用 `[SerializeReference]` 会导致运行时错误。

**错误示例：在 Struct 上使用 `[SerializeReference]`**：

```csharp
// INCORRECT: Using [SerializeReference] on a struct
[System.Serializable]
public struct Vector3D
{
    public float x, y, z;
}

public class MyBehaviour : MonoBehaviour
{
    [SerializeReference] public Vector3D position; // UAC1003: Error - can't use [SerializeReference] on struct
}
```

**正确示例：从 Struct 字段移除 `[SerializeReference]`**：

```csharp
// CORRECT: Remove [SerializeReference] from the struct field
[System.Serializable]
public struct Vector3D
{
    public float x, y, z;
}

public class MyBehaviour : MonoBehaviour
{
    public Vector3D position; // OK - structs are always serialized inline
}
```

**另一种正确示例：使用类**：

```csharp
// CORRECT: Use a class instead of a struct
[System.Serializable]
public class Vector3D
{
    public float x, y, z;
}

public class MyBehaviour : MonoBehaviour
{
    [SerializeReference] public Vector3D position; // OK - class can use [SerializeReference]
}
```

### UAC1004：在基本类型或 Enum 上使用 `[SerializeReference]`

**严重性**：Warning。

内置类型（`int`、`float`、`bool` 等）和 Enum 都是值类型，因此始终 inline 序列化。Unity 会静默忽略这些类型上的 `[SerializeReference]`，而不是产生运行时错误。Struct 的行为不同：Unity 会抛出由 [UAC1003](#uac1003) 捕获的错误。移除多余的 `[SerializeReference]` 可以让字段的序列化意图更加清晰。

**错误示例：在基本类型或 Enum 上使用 `[SerializeReference]`**：

```csharp
// INCORRECT: Using [SerializeReference] on a primitive and an enum
public enum GameState
{
    Menu,
    Playing,
    Paused
}

public class GameController : MonoBehaviour
{
    [SerializeReference] public int score; // UAC1004: int is a primitive type
    [SerializeReference] public GameState state; // UAC1004: GameState is an enum
}
```

**正确示例：从基本类型和 Enum 字段移除 `[SerializeReference]`**：

```csharp
// CORRECT: Remove [SerializeReference] from primitive and enum fields
public enum GameState
{
    Menu,
    Playing,
    Paused
}

public class GameController : MonoBehaviour
{
    public int score; // OK - primitives don't need [SerializeReference]
    public GameState state; // OK - enums don't need [SerializeReference]
}
```

### UAC1005：序列化类中的直接自引用循环

**严重性**：Warning。

类包含自身类型的字段时，会形成直接自引用循环。Unity 的 inline serialization 按值复制对象图，无法表示循环。为避免无限循环，Unity 会在序列化时忽略包含直接自引用循环的类型的字段。这会造成难以调试的数据丢失：字段可以成功编译，但反序列化后始终为 null。[UAC1006](#uac1006) 在类型声明之外的字段使用位置报告同一个问题。

表示自引用数据有两种常见且有效的方式：

- 在链接字段上使用 `[SerializeReference]`（支持循环和引用语义）。
- 使用集合（例如 `List<Node>` 或 `Node[]`）表示子节点或链接。集合可以为空，对象图也可以保持无循环；但如果添加 `this` 等形成循环，没有 `[SerializeReference]` 仍然不能正确表示循环。

**错误示例：inline-serialized 类中的直接自引用循环**：

```csharp
// INCORRECT: Direct self-reference cycle
[System.Serializable]
public class Node
{
    public string data;
    public Node next; // UAC1005: Direct self-reference - Unity will ignore this field
}

public class LinkedList : MonoBehaviour
{
    public Node head; // After serialization, head will always be null
}
```

**正确示例：对自引用链接使用 `[SerializeReference]`**：

```csharp
// CORRECT: Use [SerializeReference] for self-referential links
[System.Serializable]
public class Node
{
    public string data;
    [SerializeReference] public Node next; // OK - [SerializeReference] supports cycles
}

public class LinkedList : MonoBehaviour
{
    [SerializeReference] public Node head; // OK - preserves linked structure
}
```

**另一种正确示例：重新设计以避免循环**：

```csharp
// CORRECT: Redesign to avoid cycle
[System.Serializable]
public class NodeData
{
    public string data;
    public int nextIndex; // Store index instead of direct reference
}

public class LinkedList : MonoBehaviour
{
    public NodeData[] nodes; // OK - no direct cycles
}
```

### UAC1006：字段使用了包含直接自引用循环的类型

**严重性**：Warning。

使用包含直接自引用循环的类型时，Unity 会在序列化期间忽略该字段。即使问题类型在其他位置声明，警告也会出现在使用位置，使你能注意到数据丢失。有关直接自引用循环的成因和修复方法，参阅 [UAC1005](#uac1005)。

**错误示例：字段使用了包含直接自引用循环的类型**：

```csharp
// INCORRECT: Field uses type with direct self-reference cycle
[System.Serializable]
public class TreeNode
{
    public string value;
    public TreeNode left; // Direct self-reference
    public TreeNode right; // Direct self-reference
}

public class Tree : MonoBehaviour
{
    public TreeNode root; // UAC1006: TreeNode contains self-reference cycles
    // After serialization, the root field will be ignored and remain null
}
```

**正确示例：对循环引用使用 `[SerializeReference]`**：

```csharp
// CORRECT: Use [SerializeReference] for cyclic references
[System.Serializable]
public class TreeNode
{
    public string value;
    [SerializeReference] public TreeNode left; // Fixed with [SerializeReference]
    [SerializeReference] public TreeNode right; // Fixed with [SerializeReference]
}

public class Tree : MonoBehaviour
{
    [SerializeReference] public TreeNode root; // OK - preserves tree structure
}
```

### UAC1007：序列化类中的深层自引用循环

**严重性**：Warning。

当类包含形成间接循环的字段（A > B > A 或 A > B > C > A）时，Unity 仍会序列化该结构，但将递归限制为 10 层。这不同于会被完全忽略的[直接循环](#uac1005)。达到 10 层后，Unity 会记录警告并丢弃剩余数据，可能造成深层嵌套树或图的数据丢失。此警告会报告在参与循环的字段上。[UAC1008](#uac1008) 会在使用位置报告同一个问题。

**错误示例：使用 inline serialization 的深层自引用循环**：

```csharp
// INCORRECT: Deep self-reference cycle with inline serialization
[System.Serializable]
public class Parent
{
    public string name;
    public Child child; // UAC1007: Creates deep cycle (Parent → Child → Parent)
}

[System.Serializable]
public class Child
{
    public string name;
    public Parent parent; // Creates the cycle back to Parent
}

public class Family : MonoBehaviour
{
    public Parent root; // Will serialize up to 10 levels: Parent→Child→Parent→Child...
}
```

**正确示例：对深层循环使用 `[SerializeReference]`**：

```csharp
// CORRECT: Use [SerializeReference] for deep cycles
[System.Serializable]
public class Parent
{
    public string name;
    [SerializeReference] public Child child; // OK - [SerializeReference] handles cycles
}

[System.Serializable]
public class Child
{
    public string name;
    [SerializeReference] public Parent parent; // OK - preserves bidirectional relationship
}

public class Family : MonoBehaviour
{
    [SerializeReference] public Parent root; // OK - no depth limit
}
```

**另一种正确示例：重新设计以避免循环**：

```csharp
// CORRECT: Redesign to avoid cycles
[System.Serializable]
public class Parent
{
    public string name;
    public List<string> childNames; // Store references differently
}

[System.Serializable]
public class Child
{
    public string name;
    public string parentName; // Use name lookup instead of direct reference
}

public class Family : MonoBehaviour
{
    public List<Parent> parents; // OK - no cycles
    public List<Child> children; // OK - no cycles
}
```

### UAC1008：字段使用了包含深层自引用循环的类型

**严重性**：Warning。

使用包含深层自引用循环的类型时，Unity 会使用 10 层递归限制序列化它，可能造成深层嵌套实例的静默数据丢失。即使问题类型在其他位置声明，警告也会出现在使用位置。有关深层循环的成因和修复方法，参阅 [UAC1007](#uac1007)。

**错误示例：字段使用了包含深层自引用循环的类型**：

```csharp
// INCORRECT: Field uses type with deep self-reference cycle
[System.Serializable]
public class A
{
    public B b; // Creates deep cycle: A -> B -> A
}

[System.Serializable]
public class B
{
    public A a; // Completes the cycle
}

public class Host : MonoBehaviour
{
    public A root; // UAC1008: A contains a deep self-reference cycle
}
```

**正确示例：使用 `[SerializeReference]` 避免深度限制**：

```csharp
// CORRECT: Use [SerializeReference] to avoid depth limits
[System.Serializable]
public class GraphNode
{
    public string id;
    [SerializeReference] public List<GraphNode> connections; // OK - no depth limit
}

public class Graph : MonoBehaviour
{
    [SerializeReference] public List<GraphNode> nodes; // OK - handles arbitrary depth
}
```

**另一种正确示例：使用 ID**：

```csharp
// CORRECT: Use IDs instead of direct references
[System.Serializable]
public class GraphNode
{
    public string id;
    public List<string> connectionIds; // Store IDs instead of references
}

public class Graph : MonoBehaviour
{
    public List<GraphNode> nodes; // OK - no cycles, resolve IDs at runtime

    public GraphNode FindNode(string id)
    {
        return nodes.Find(n => n.id == id);
    }
}
```

### UAC1009：不支持序列化的集合类型

**严重性**：Warning。

Unity serialization system 支持一维数组（`T[]`）、`List<T>` 和 `Dictionary<TKey, TValue>`。使用不支持集合类型的字段不会被序列化，可能造成数据丢失，因为字段可以编译并在运行时工作，但会在序列化周期（例如保存 Scene 或重载 domain）后丢失值。

不支持的集合类型包括：

- 多维数组（例如 `int[,]`、`int[,,]`）。
- 交错数组（例如 `int[][]`）。
- 嵌套集合，即 `List<T>` 或数组的元素类型本身是集合（例如 `List<List<T>>`、`List<Dictionary<TKey, TValue>>` 和 `Dictionary<TKey, TValue>[]`）。
- `HashSet<T>`、`Queue<T>`、`Stack<T>` 和 `System.Collections.Generic` 中的其他集合。

**错误示例：使用不支持的集合类型进行序列化**：

```csharp
// INCORRECT: Using unsupported collection types
public class InventorySystem : MonoBehaviour
{
    public int[,] grid; // UAC1009: Multidimensional array not supported
    public int[][] jaggedArray; // UAC1009: Jagged array not supported
    public List<Dictionary<string, int>> itemCountsHistory; // UAC1009: Collection element type is Dictionary<,>
    public Dictionary<string, int>[] itemCountsByLevel; // UAC1009: Array element type is Dictionary<,>
    public HashSet<string> unlockedAchievements; // UAC1009: HashSet not supported
    public Queue<string> messageQueue; // UAC1009: Queue not supported
    public Stack<string> undoStack; // UAC1009: Stack not supported
}
```

**正确示例：将运行时集合标记为 `[NonSerialized]`**：

如果不需要这些字段持久化（例如它们是 runtime-only 数据结构），可以将字段设为 non-public，或在必须保持 public 时使用 `[System.NonSerialized]`。这会明确承认字段不会序列化，并抑制警告：

```csharp
// CORRECT: Mark runtime-only collections as [NonSerialized]
public class InventorySystem : MonoBehaviour
{
    [System.NonSerialized] public List<Dictionary<string, int>> itemCountsHistory; // OK - explicitly marked as non-serialized
    [System.NonSerialized] public HashSet<string> unlockedAchievements; // OK - runtime-only data
    [System.NonSerialized] public Queue<string> messageQueue; // OK - transient queue
    [System.NonSerialized] public Stack<string> undoStack; // OK - runtime undo stack

    private void Awake()
    {
        // Initialize runtime collections
        itemCountsHistory = new List<Dictionary<string, int>>();
        unlockedAchievements = new HashSet<string>();
        messageQueue = new Queue<string>();
        undoStack = new Stack<string>();
    }
}
```

**另一种正确示例：使用受支持的集合类型**：

如果需要数据持久化，请转换为受支持的集合类型：

```csharp
// CORRECT: Use supported collection types
[System.Serializable]
public struct KeyValuePair
{
    public string key;
    public int value;
}

public class InventorySystem : MonoBehaviour
{
    public List<KeyValuePair> itemCounts; // OK - List is supported
    public List<string> unlockedAchievements; // OK - List instead of HashSet
    public List<string> messageQueue; // OK - List instead of Queue
    public List<string> undoStack; // OK - List instead of Stack

    // Helper methods to maintain collection semantics
    public int GetItemCount(string itemName)
    {
        var pair = itemCounts.Find(p => p.key == itemName);
        return pair.value;
    }

    public void SetItemCount(string itemName, int count)
    {
        int index = itemCounts.FindIndex(p => p.key == itemName);
        if (index >= 0)
            itemCounts[index] = new KeyValuePair { key = itemName, value = count };
        else
            itemCounts.Add(new KeyValuePair { key = itemName, value = count });
    }
}
```

**另一种正确示例：使用实现 `ISerializationCallbackReceiver` 的自定义可序列化包装类**：

如果需要保留 `HashSet` 或 Dictionary 的完整语义，同时让数据保持序列化，可以创建实现 `ISerializationCallbackReceiver` 的包装类。这样可以使用 Unity 支持的格式（Array 或 `List<T>`）存储，并在序列化回调中转换运行时集合：

```csharp
// CORRECT: Use a custom serializable wrapper
[System.Serializable]
public class SerializableHashSet<T> : ISerializationCallbackReceiver
{
    [SerializeField] private List<T> items = new List<T>();
    private HashSet<T> hashSet;

    public void OnBeforeSerialize()
    {
        if (hashSet == null) hashSet = new HashSet<T>(items);
        items.Clear();
        items.AddRange(hashSet);
    }

    public void OnAfterDeserialize()
    {
        hashSet = new HashSet<T>(items);
    }

    // Add collection methods (Add, Remove, Contains, Count, etc.) as needed.
}

public class AchievementManager : MonoBehaviour
{
    public SerializableHashSet<string> unlockedAchievements; // OK - custom serializable wrapper
}
```

相同模式也适用于使用并行 key-value List 的 `Dictionary<TKey, TValue>`。完整、可直接使用的 `SerializableHashSet<T>` 和 `SerializableDictionary<TKey, TValue>` 实现请参阅[[05-自定义序列化#可复用的可序列化集合]]。

**注意**：当不支持的集合类型作为元素出现在受支持集合中时，UAC1009 同样适用。例如，`List<Dictionary<string, int>>` 和 `Dictionary<string, int>[]` 都会被标记，因为它们的元素不能由 Unity 序列化。

### UAC1010：在不可序列化类型上使用 `[SerializeField]`

**严重性**：Warning。

在字段上应用 `[SerializeField]` 不会使其类型变为可序列化。该属性只是指示 Unity 保存字段；如果字段类型不可序列化，Unity 不会保存值，字段会在序列化周期（例如重新加载 Scene、重载 domain 或重新打开项目）后重置。

根据意图选择以下修复方式：

- 如果需要序列化，使字段类型可序列化，例如添加 `[Serializable]`，或无法修改类型时使用 `[MakeSerializable]`。
- 如果不需要序列化，移除 `[SerializeField]`，或使用其他方式将字段设为不序列化。
- 如果字段必须保持 public 但不应序列化，添加 `[System.NonSerialized]`，明确表达意图。

**错误示例：在不可序列化类型上使用 `[SerializeField]`**：

```csharp
// INCORRECT: Using [SerializeField] on a non-serializable type
public class MyWindowState : BaseState
{
    public List<int> expandedItems;
}

public class MyWindowManager : ScriptableObject
{
    [SerializeField] private MyWindowState m_WindowState; // UAC1010: Unity won't persist this field
}
```

**正确示例：不需要持久化时移除 `[SerializeField]`**：

```csharp
// CORRECT: Remove [SerializeField] when persistence isn't needed
public class MyWindowState : BaseState
{
    public List<int> expandedItems;
}

public class MyWindowManager : ScriptableObject
{
    private MyWindowState m_WindowState; // OK - not serialized
}
```

**正确示例：不需要持久化时将字段标记为 `[NonSerialized]`**：

```csharp
// CORRECT: Mark the field as [NonSerialized]
public class MyWindowState : BaseState
{
    public List<int> expandedItems;
}

public class MyWindowManager : ScriptableObject
{
    [System.NonSerialized] public MyWindowState windowState; // OK - explicitly not serialized
}
```

**正确示例：需要持久化时将类型设为 `[Serializable]`**：

```csharp
// CORRECT: Make the type [Serializable]
[System.Serializable]
public class MyWindowState : BaseState
{
    public List<int> expandedItems;
}

public class MyWindowManager : ScriptableObject
{
    [SerializeField] private MyWindowState m_WindowState; // OK - type is now serializable
}
```

### UAC1011：Enum 类型超过 32 位大小限制

**严重性**：Warning。

Unity serialization system 只支持 32 位或更小的 Enum 类型（`byte`、`sbyte`、`short`、`ushort`、`int` 和 `uint`）。底层类型为 `long`（64 位有符号）或 `ulong`（64 位无符号）的 Enum 超出限制，无法正确序列化，可能在序列化周期后造成数据丢失。

该规则适用于直接 Enum 字段，也适用于用作 Dictionary 键或值的 Enum。当问题 Enum 是 Dictionary 键或值类型时，只有 Unity 实际序列化 Dictionary（字段带有 `[SerializeField]`，参阅 [UAC1015](#uac1015)）时才报告 UAC1011。没有 `[SerializeField]` 时 Unity 会跳过 Dictionary 字段的序列化，analyzer 不会报告错误。如果键和值都是 64 位 Enum，analyzer 会在同一字段上报告两个 UAC1011，一个标识键类型，一个标识值类型。

**错误示例：使用 64 位 Enum 进行序列化**：

```csharp
// INCORRECT: Using a 64-bit enum for serialization
public enum LargeEnum : long
{
    Value1 = 1L,
    Value2 = 2L,
    Value3 = long.MaxValue
}

public class GameData : MonoBehaviour
{
    public LargeEnum largeEnum; // UAC1011: 64-bit enum exceeds Unity's 32-bit limit
}
```

**正确示例：使用 32 位或更小的 Enum 底层类型**：

```csharp
// CORRECT: Use a 32-bit-or-smaller enum underlying type
public enum SmallEnum : int
{
    Value1 = 1,
    Value2 = 2,
    Value3 = int.MaxValue
}

public class GameData : MonoBehaviour
{
    public SmallEnum smallEnum; // OK - 32-bit enum is supported
}
```

**正确示例：将 Enum 字段标记为不序列化**：

如果不需要 Enum 字段持久化，可以将它设为 non-public；如果必须保持 public，则使用 `[System.NonSerialized]`：

```csharp
// CORRECT: Mark the enum field as non-serialized
public enum LargeEnum : long
{
    Value1 = 1L,
    Value2 = 2L
}

public class GameData : MonoBehaviour
{
    [System.NonSerialized] public LargeEnum largeEnum; // OK - explicitly marked as non-serialized

    private void Awake()
    {
        // Initialize runtime enum value
        largeEnum = LargeEnum.Value1;
    }
}
```

**错误示例：64 位 Enum 作为 Dictionary 键或值**：

```csharp
// INCORRECT: 64-bit enum used as a dictionary key or value
public enum LargeEnum : long
{
    Value1 = 1L,
    Value2 = 2L
}

public class GameData : MonoBehaviour
{
    [SerializeField] public Dictionary<LargeEnum, int> byEnum; // UAC1011: key type is a 64-bit enum
    [SerializeField] public Dictionary<int, LargeEnum> byId;   // UAC1011: value type is a 64-bit enum
}
```

将 Enum 的底层类型改为 32 位或更小（`int`、`uint`、`short`、`ushort`、`byte`、`sbyte`），或将键/值替换为受支持的类型。

### UAC1012：使用 interface 或 abstract 键/值类型的可序列化 Dictionary

**严重性**：Error。

Unity serialization system 支持 `Dictionary<TKey, TValue>` 字段，但只有在 `TKey` 和 `TValue` 都是具体类型时才支持。反序列化时 Unity 必须实例化每个键和值；interface 或 abstract 类型没有可以实例化的具体实现，因此无法完成该操作。将任一侧设为此类类型，会在加载 Dictionary 时产生运行时错误。

`UnityEngine.Object` 子类是例外。即使 `Renderer` 或 `Collider` 这样的 abstract 基类也可作为键或值，因为 Unity 会将它们存储为 PPtr instance ID，并在加载时解析具体实例。只要键或值类型继承自 `UnityEngine.Object`，无论该类型本身是否 abstract，都适用这一例外。

只有 Unity 实际序列化 Dictionary 时才报告 UAC1012。字段带有 `[SerializeField]` 时 Unity 才序列化 Dictionary（参阅 [UAC1015](#uac1015)）。没有该属性时 Unity 跳过 Dictionary 字段序列化，analyzer 不报告错误。

每个有问题的一侧会产生一条诊断。如果 `TKey` 和 `TValue` 都是 interface 或 abstract 类型，analyzer 会在同一字段上报告两条 UAC1012，分别标识键类型和值类型，使你可以一次修复两个问题。

**错误示例：Interface 键类型**：

```csharp
// INCORRECT: IInventoryItem is an interface, so Unity can't instantiate keys
public interface IInventoryItem { }

[System.Serializable]
public class Sword : IInventoryItem { }

public class Inventory : MonoBehaviour
{
    [SerializeField] public Dictionary<IInventoryItem, int> counts; // UAC1012: interface key type
}
```

**错误示例：Abstract 值类型**：

```csharp
// INCORRECT: AbstractEnemy is abstract, so Unity can't instantiate values
public abstract class AbstractEnemy { }

public class GameState : MonoBehaviour
{
    [SerializeField] public Dictionary<int, AbstractEnemy> enemiesById; // UAC1012: abstract value type
}
```

**错误示例：键和值都是 interface 或 abstract 类型**：

```csharp
// INCORRECT: both sides are problematic — two UAC1012 diagnostics are reported
public interface IFoo { }
public abstract class AbstractBar { }

public class Host : MonoBehaviour
{
    // UAC1012 (key type 'IFoo') and UAC1012 (value type 'AbstractBar')
    [SerializeField] public Dictionary<IFoo, AbstractBar> data;
}
```

**正确示例：使用具体的键和值类型**：

```csharp
// CORRECT: Concrete, [Serializable] types on both sides
[System.Serializable]
public class InventoryItem
{
    public string id;
}

public class Inventory : MonoBehaviour
{
    [SerializeField] public Dictionary<int, InventoryItem> itemsBySlot; // OK
}
```

**正确示例：允许抽象的 UnityEngine.Object 子类**：

```csharp
// CORRECT: Renderer is abstract but derives from UnityEngine.Object,
// so it's stored as a PPtr instance ID
public class MaterialOverrides : MonoBehaviour
{
    [SerializeField] public Dictionary<Renderer, Material> overrides; // OK
}
```

**正确示例：不需要持久化时标记为 `[NonSerialized]`**：

```csharp
// CORRECT: Skip serialization entirely
public class Inventory : MonoBehaviour
{
    [System.NonSerialized] public Dictionary<IInventoryItem, int> runtimeCounts; // OK
}
```

### UAC1013：使用 IEnumerable 键类型的可序列化 Dictionary

**严重性**：Error。

Dictionary 键必须在条目生命周期内产生稳定哈希。大多数实现 `IEnumerable` 的类型（例如 `List<T>` 或数组）都是可变的，因此插入后其哈希可能改变，破坏 Dictionary。即使内容不变，Unity serialization backend 也无法正确往返这些键，因为它按值序列化键，却要求在保存/加载过程中保留键身份。UAC1013 会报告键类型实现 `IEnumerable` 的字段，但有两个例外：

- `string`。虽然它实现 `IEnumerable<char>`，但 string 不可变，Unity 将它作为基本键处理。
- 继承自 `UnityEngine.Object` 的类型。这些类型以 PPtr instance ID 存储，底层类型是否具有 IEnumerable 形状无关紧要。

复合 Struct 键会进行传递检查。如果 Struct 键包含类型实现 `IEnumerable` 的字段，该 Struct 也会被拒绝，因为键哈希依赖不稳定的内部集合。

只有 Unity 实际序列化 Dictionary 时才报告 UAC1013；字段没有 `[SerializeField]` 时会跳过序列化（参阅 [UAC1015](#uac1015)）。

**错误示例：List 或 Array 键类型**：

```csharp
// INCORRECT: List<T> and arrays are mutable IEnumerable types
public class TagBuckets : MonoBehaviour
{
    [SerializeField] public Dictionary<List<int>, string> byTags; // UAC1013: List<int> key
    [SerializeField] public Dictionary<int[], int> counts; // UAC1013: int[] key
}
```

**错误示例：包含 IEnumerable 字段的 Struct 键**：

```csharp
// INCORRECT: Composite struct key contains a List<int> field
[System.Serializable]
public struct CompositeKey
{
    public int id;
    public List<int> tags; // Inner IEnumerable field invalidates the struct as a key
}

public class Buckets : MonoBehaviour
{
    [SerializeField] public Dictionary<CompositeKey, int> counts; // UAC1013: CompositeKey contains an IEnumerable field
}
```

**正确示例：使用可哈希的包装 Struct**：

```csharp
// CORRECT: Wrap the key data in a struct whose fields are all hashable primitives
[System.Serializable]
public struct TagSetKey
{
    public int hash; // Pre-computed stable hash of the tag set

    public override int GetHashCode() => hash;
    public override bool Equals(object obj) => obj is TagSetKey other && other.hash == hash;
}

public class TagBuckets : MonoBehaviour
{
    [SerializeField] public Dictionary<TagSetKey, string> byTags; // OK
}
```

**正确示例：扁平化为基本类型键**：

```csharp
// CORRECT: Use a string or int key derived from the original collection
public class TagBuckets : MonoBehaviour
{
    [SerializeField] public Dictionary<string, string> byJoinedTags; // Key is a comma-joined tag string
}
```

**正确示例：不需要持久化时标记为 `[NonSerialized]`**：

```csharp
// CORRECT: Skip serialization entirely
public class TagBuckets : MonoBehaviour
{
    [System.NonSerialized] public Dictionary<List<int>, string> runtimeByTags; // OK
}
```

### UAC1014：在 Dictionary 上使用 `[SerializeReference]`

**严重性**：Error。

`[SerializeReference]` 为单个对象引用提供多态引用语义，包括 null 支持和共享引用。Unity 的 Dictionary backend 将 `Dictionary<TKey, TValue>` 序列化为键值条目的 inline 数组，而不是多态的单个引用，因此 `[SerializeReference]` 不适用于 Dictionary 字段，也不能用于它们。此规则与 [UAC1003](#uac1003) 对 Struct 字段上的相同误用进行报告的方式一致。

**错误示例：在 Dictionary 字段上使用 `[SerializeReference]`**：

```csharp
// INCORRECT: [SerializeReference] is invalid on Dictionary<,>
public class Inventory : MonoBehaviour
{
    [UnityEngine.SerializeReference] public Dictionary<string, int> counts; // UAC1014
}
```

**正确示例：将 `[SerializeReference]` 替换为 `[SerializeField]`**：

```csharp
// CORRECT: [SerializeField] routes the field through Unity's normal dictionary backend
public class Inventory : MonoBehaviour
{
    [SerializeField] public Dictionary<string, int> counts; // OK - serialized inline as entries
}
```

**正确示例：在 private 字段上使用 `[SerializeField]`**：

```csharp
// CORRECT: [SerializeField] is the supported way to serialize a private dictionary field
public class Inventory : MonoBehaviour
{
    [SerializeField] private Dictionary<string, int> m_Counts; // OK
}
```

**正确示例：不需要持久化时标记为 `[NonSerialized]`**：

```csharp
// CORRECT: Skip serialization entirely
public class Inventory : MonoBehaviour
{
    [System.NonSerialized] public Dictionary<string, int> runtimeCounts; // OK
}
```

### UAC1015：Dictionary 字段缺少 `[SerializeField]` 属性

**严重性**：Warning。

对大多数字段类型，Unity 默认序列化 public 字段。Dictionary 字段是例外：Unity 的原生 Dictionary serialization backend 会明确检查 `[SerializeField]` 属性，即使字段是 public，没有该属性也会跳过字段。当 `Dictionary<TKey, TValue>` 字段处于可序列化位置（没有 `[NonSerialized]`，且字段没有 `[SerializeReference]`）但缺少 `[SerializeField]` 时，规则会发出警告。没有该属性，Dictionary 内容会静默地无法持久化。

存在 `[SerializeReference]` 时不会报告该规则，因为 [UAC1014](#uac1014) 已经报告此误用。将 `[SerializeReference]` 替换为 `[SerializeField]` 后，两个诊断都会解决。

**错误示例：没有 `[SerializeField]` 的 public Dictionary 字段**：

```csharp
// INCORRECT: Unity's dictionary backend skips this field because it has no [SerializeField]
public class Inventory : MonoBehaviour
{
    public Dictionary<int, string> counts; // UAC1015
}
```

**正确示例：添加 `[SerializeField]`**：

```csharp
// CORRECT: [SerializeField] tells Unity's dictionary backend to serialize the field
public class Inventory : MonoBehaviour
{
    [SerializeField] public Dictionary<int, string> counts; // OK
}
```

**正确示例：不需要持久化时标记为 `[NonSerialized]`**：

```csharp
// CORRECT: opt out of serialization entirely
public class Inventory : MonoBehaviour
{
    [System.NonSerialized] public Dictionary<int, string> runtimeCounts; // OK
}
```

### UAC1016：Dictionary 键或值类型不可序列化

**严重性**：Error。

可序列化 Dictionary 的键和值类型自身必须可序列化。当键或值类型无法通过 analyzer 对普通字段使用的相同可序列化检查时，此规则报告错误。类型必须是基本类型、Enum、可序列化类型的 Array 或 `List<T>`、`[Serializable]` 类或 Struct、`UnityEngine.Object` 子类（以 PPtr instance ID 存储）、serialization whitelist 中的内置支持类型，或通过 `[MakeSerializable]` 选择加入的类型。

Dictionary 将此情况作为 **error** 而非 warning（对比 `[SerializeField]` 应用于不可序列化类型时的 [UAC1010](#uac1010)，以及 List 元素不可序列化时的 [UAC1001](#uac1001)）。不可序列化的 Dictionary 键或值意味着条目往返完全损坏：Unity 无法在反序列化时重建条目，因此数据丢失比类似的 `List<T>` 情况更严重。

只有 Unity 实际序列化 Dictionary 时才报告 UAC1016；没有 `[SerializeField]` 时跳过字段（参阅 [UAC1015](#uac1015)）。如果同一字段触发 [UAC1012](#uac1012)，UAC1016 会被抑制，因为 interface 或 abstract 类型错误已经覆盖该键或值位置。

**错误示例：Dictionary 值类型缺少 `[Serializable]`**：

```csharp
public class DictValue
{
    public string key;
    public string value;
}

// INCORRECT: DictValue is a plain class without [Serializable], so the dictionary entries can't be serialized
public class Host : MonoBehaviour
{
    [SerializeField] public Dictionary<int, DictValue> data; // UAC1016 (value type)
}
```

**正确示例：将值类型标记为 `[Serializable]`**：

```csharp
[System.Serializable]
public class DictValue
{
    public string key;
    public string value;
}

public class Host : MonoBehaviour
{
    [SerializeField] public Dictionary<int, DictValue> data; // OK
}
```

**正确示例：使用 UnityEngine.Object 子类（PPtr）**：

```csharp
// CORRECT: UnityEngine.Object subclasses serialize as PPtr instance IDs and don't need [Serializable]
public class Host : MonoBehaviour
{
    [SerializeField] public Dictionary<int, GameObject> objects; // OK
}
```

### UAC1017：Tuple 类型不受序列化支持

**严重性**：Warning。

Unity serialization system 不支持 Tuple 类型（例如 `(int x, int y)` 或 `ValueTuple<int, string>`）。Tuple 类型字段会被序列化忽略且不会产生运行时警告，因此在进入 Play mode、保存 Scene 或 domain reload 时会造成数据丢失。

根据意图选择以下方式：

- 如果需要字段持久化，将 Tuple 替换为包含相同字段的 `[Serializable]` Struct 或 Class。
- 如果不需要字段持久化，将字段设为 private；如果必须保持 public，则添加 `[System.NonSerialized]`。

**错误示例：Tuple 类型的 public 字段**：

```csharp
// INCORRECT: Tuple type is ignored by serialization
public class GameData : MonoBehaviour
{
    public (int x, int y) position; // UAC1017: Tuple type is not supported by the serialization system
}
```

**正确示例：使用可序列化 Struct**：

```csharp
// CORRECT: Use a [Serializable] struct instead of a tuple
[System.Serializable]
public struct Point2D
{
    public int x;
    public int y;
}

public class GameData : MonoBehaviour
{
    public Point2D position; // OK - serializable struct
}
```

**正确示例：不需要持久化时标记为不序列化**：

```csharp
// CORRECT: Mark as non-serialized if persistence isn't needed
public class GameData : MonoBehaviour
{
    [System.NonSerialized] public (int x, int y) position; // OK - explicitly not serialized
}
```

### UAC1018：字段名与 FormerlySerializedAs 参数冲突

**严重性**：Warning。

重命名序列化字段时，可以在重命名后的字段上添加 `[FormerlySerializedAs("previousName")]`，使 Unity 从旧名称迁移已有数据。如果之后又添加一个名称等于 `previousName` 的字段，同一类型中的两个字段会映射到同一个序列化名称，导致不正确的序列化，并可能在序列化周期后丢失数据。

Analyzer 会在字段名等于同类型另一字段 `[FormerlySerializedAs("...")]` 字符串的字段上报告警告。要解决冲突，可以重命名新字段、删除它、将它标记为 `[NonSerialized]`（例如冲突字段只是保留源兼容性的 `[Obsolete]` 占位符时），或从重命名字段移除匹配的 `[FormerlySerializedAs]` 参数。

**错误示例：新字段名与 FormerlySerializedAs 参数冲突**：

```csharp
// INCORRECT: textureAsset conflicts with [FormerlySerializedAs("textureAsset")] on icon
public class IconLibrary : MonoBehaviour
{
    [FormerlySerializedAs("textureAsset")]
    public Texture2D icon;
    public Texture2D textureAsset; // UAC1018: name conflicts with the [FormerlySerializedAs] argument above
}
```

**正确示例：重命名新字段**：

为新字段指定一个不与其他字段的 `[FormerlySerializedAs]` 参数冲突的名称：

```csharp
// CORRECT: New field name doesn't conflict with any [FormerlySerializedAs] argument.
// Alternatively, if migration from "textureAsset" is no longer needed, remove
// the [FormerlySerializedAs] attribute and reuse "textureAsset" on the new field.
public class IconLibrary : MonoBehaviour
{
    [FormerlySerializedAs("textureAsset")]
    public Texture2D icon;
    public Texture2D fallbackTexture; // OK - distinct from the [FormerlySerializedAs] argument
}
```

### UAC1021：DictionaryDisplayForType 属性必须以 Dictionary<TKey, TValue> 为目标

**严重性**：Error。

assembly-level 的 `[DictionaryDisplayForType]` 属性用于自定义某一种准确类型的所有 Dictionary 的 Inspector 显示。传给 `typeof(...)` 的类型必须是完整指定的 `Dictionary<TKey, TValue>`，例如 `typeof(Dictionary<string, SkillLevel>)`。未绑定的 generic（`typeof(Dictionary<,>)`）或不是完整指定 Dictionary 的类型无法匹配 Dictionary 字段，因此 Unity 会忽略该属性。

有关该属性的详情，参阅[[04-Dictionary序列化#按类型自定义-dictionary]]。

**错误示例：未绑定的 generic 目标**：

```csharp
// INCORRECT: typeof(Dictionary<,>) is an unbound generic, not a fully specified dictionary type
[assembly: DictionaryDisplayForType(typeof(Dictionary<,>),
    layout = DictionaryLayout.OneColumnWithValueVisible)] // UAC1021
```

**错误示例：目标不是 Dictionary**：

```csharp
// INCORRECT: SkillLevel is not a Dictionary<TKey, TValue>
[assembly: DictionaryDisplayForType(typeof(SkillLevel), keyLabel = "Skill")] // UAC1021

[System.Serializable]
public struct SkillLevel
{
    public int rank;
    public float bonus;
}
```

**正确示例：指定完整的 Dictionary 类型**：

```csharp
// CORRECT: a fully specified Dictionary<TKey, TValue>
[assembly: DictionaryDisplayForType(typeof(Dictionary<string, SkillLevel>),
    layout = DictionaryLayout.OneColumnWithValueVisible)] // OK

[System.Serializable]
public struct SkillLevel
{
    public int rank;
    public float bonus;
}
```

### UAC1022：DictionaryDisplayForType 属性必须应用在定义 Dictionary 键或值类型的 assembly 中

**严重性**：Error。

只有当 Dictionary 的键类型或值类型（或通过 Array element type 和 generic type argument 在任意深度嵌套其中的类型）定义在与该属性相同的 assembly 中时，`[DictionaryDisplayForType]` 才能设置 Dictionary 的样式。`Dictionary<TKey, TValue>` 本身是 framework type，不必在你的 assembly 中定义；只需要键或值类型在其中定义。此 ownership 规则阻止某个 assembly 中的声明改变它并不拥有的 Dictionary 形状（如 `Dictionary<int, int>`）的显示。如果目标的键和值都没有在声明 assembly 中定义，Unity 会忽略该属性。

有关 ownership 要求的详情，参阅[[04-Dictionary序列化#按类型自定义-dictionary]]。

**错误示例：目标不使用声明 assembly 中的任何类型**：

```csharp
// INCORRECT: neither int is defined in this assembly, so the rule can't own this dictionary type
[assembly: DictionaryDisplayForType(typeof(Dictionary<int, int>),
    keyLabel = "Id", valueLabel = "Count")] // UAC1022
```

**正确示例：键或值类型定义在此 assembly 中**：

```csharp
/ CORRECT: SkillLevel is defined in this assembly, so the dictionary type is owned here
[assembly: DictionaryDisplayForType(typeof(Dictionary<string, SkillLevel>),
    keyLabel = "Skill", valueLabel = "Level")] // OK

[System.Serializable]
public struct SkillLevel
{
    public int rank;
    public float bonus;
}
```

**正确示例：此 assembly 的类型嵌套在值中**：

```csharp
/ CORRECT: SkillLevel (defined here) is nested inside List<T>, so the dictionary type is still owned here
[assembly: DictionaryDisplayForType(typeof(Dictionary<int, List<SkillLevel>>))] // OK

[System.Serializable]
public struct SkillLevel
{
    public int rank;
    public float bonus;
}
```

## Generics

当字段类型是 constructed generic（例如 `Holder<CustomData>` 或 `Holder<int>`）时，analyzer 会检查 generic type definition 中的每个 type parameter，以决定对应的 type argument 是否需要可序列化。

只有当 type parameter 出现在 generic type definition 的序列化字段中时，analyzer 才会验证它。对于每个被验证的 type parameter，analyzer 使用与直接字段相同的规则检查对应 type argument。如果 type argument 违反规则，analyzer 会报告相应规则。

`List<T>` 是例外。Analyzer 会将 `List<T>` 的元素类型作为 [UAC1009](#uac1009) 的一部分检查，而不是使用本节描述的 generic type argument 规则。

### Analyzer 针对无效 type argument 报告哪条规则

Analyzer 根据 type argument 无效的原因报告不同规则。下面的示例展示几种规则；所有 analyzer 规则对 generic type argument 的应用方式都与对直接字段的应用方式相同。

```csharp
public class CustomData { public int value; }

public struct Vector3D { public float x, y, z; }

[System.Serializable]
public class Holder<T> { public T value; }

[System.Serializable]
public class RefHolder<T> { [SerializeReference] public T value; }

public class Player : MonoBehaviour
{
    public Holder<CustomData> data;           // UAC1001: CustomData lacks [Serializable]
    public RefHolder<Vector3D> pos;           // UAC1003: Vector3D is a struct, but RefHolder uses [SerializeReference] on T
    public Holder<int[][]> jaggedGrid;        // UAC1009: jagged array not supported
    public Holder<(int x, int y)> point;      // UAC1017: tuple not supported
    public Holder<PlayerStats> stats;         // OK - PlayerStats is serializable
}
```

### 不验证 type argument 的情况

如果 type parameter 没有出现在 generic type definition 的任何序列化字段中（例如使用 `T` 的唯一字段带有 `[NonSerialized]`），则不会验证对应的 type argument，analyzer 也不会报告警告。

```csharp
[System.Serializable]
public class Holder<T> { [System.NonSerialized] public T value; }

public class Player : MonoBehaviour
{
    public Holder<Dictionary<string, int>> cache; // OK - T only used in [NonSerialized] field
}
```

### 有效的 type argument

当所有 type argument 都满足序列化规则时，analyzer 不报告警告。例如，围绕 `[Serializable]` 类型、内置 primitive 或受支持集合的 generic wrapper 都不会产生警告。

## 抑制警告

如果有正当理由抑制特定 analyzer 警告，可以使用 `#pragma warning disable` 指令：

```csharp
#pragma warning disable UAC1001
public class IntentionallyUnserializedClass
{
    public int value;
}
#pragma warning restore UAC1001
```

不建议抑制这些警告，因为它们表示重要的序列化问题，可能在运行时造成问题。

## 限制：基类字段分析

Analyzer 只分析 serialization root 类型上的字段（例如标记了 `[Serializable]` 的类型、继承自 `UnityEngine.Object` 的类型等）。即使未作为 serialization root 的基类属于带 serialization root 的继承层次结构，analyzer 也不会分析它的字段。下面的示例中，`DerivedClass` 因其基类 `BaseClass` 缺少 `[Serializable]` 而触发 UAC1002；但 `BaseClass` 自身的字段（`settings` 和 `data`）不会触发警告，因为 `BaseClass` 不是 serialization root。

```csharp
public class BaseClass
{
    public Dictionary<string, int> settings; // No UAC1015 — BaseClass isn't a serialization root
    public CustomData data; // No UAC1001 — BaseClass isn't a serialization root
}

public class CustomData { }

[System.Serializable]
public class DerivedClass : BaseClass // UAC1002: BaseClass lacks [Serializable]
{
    public int value; // This field is analyzed
}
```

如果希望获得基类字段的警告，请为基类添加 `[Serializable]`，使它成为 serialization root：

```csharp
[System.Serializable]
public class BaseClass
{
    public Dictionary<string, int> settings; // UAC1015: reported
    public CustomData data; // UAC1001: reported
}

public class CustomData { }

[System.Serializable]
public class DerivedClass : BaseClass
{
    public int value;
}
```

如果需要验证基类字段，请为基类标记 `[Serializable]`。这样会使它成为 serialization root，并启用 analyzer 对其字段的检查。
