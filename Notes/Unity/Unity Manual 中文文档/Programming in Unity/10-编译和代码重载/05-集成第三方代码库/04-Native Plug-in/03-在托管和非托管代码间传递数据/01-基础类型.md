# Primitive Type

> 原文：[Primitive types](https://docs.unity3d.com/6000.7/Documentation/Manual/plug-ins-native-pass-primitives.html)

Primitive Type 是较小的 Value Type。当它们作为 Function Parameter 或 Return Value 使用时，会被复制到 Stack（或 CPU Register）中。从 Managed Code 调用 Unmanaged Function 时，不需要 Pin 或以其他方式管理 Primitive Type 的生命周期。

与 C 和其他 Language 相比，C# 对许多 Primitive Type 使用不同的名称。关于与 Managed C# Type 对应的 Unmanaged C Language Type 列表，请参阅 [Platform invoke data types](https://learn.microsoft.com/en-us/dotnet/framework/interop/marshalling-data-with-platform-invoke#platform-invoke-data-types)。

下表展示每个 C# Type **默认** Marshalling 到的 C Type。Default Marshalling 只是起点，并不是保证；它可能因 Platform 以及上下文（Parameter、Return Value 或 Struct Field）而变化。例如，`System.Boolean` 默认 Marshalling 为 4-byte Value，`System.Char` 则根据调用的 `CharSet` 进行 Marshalling。当默认表示不是所需结果时，使用 [MarshalAsAttribute](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.interopservices.marshalasattribute) 控制确切表示形式。

一些示例包括：

| C# base type | C# alias name | Unmanaged C type |
| --- | --- | --- |
| System.Int32 | int | int32_t |
| System.Single | float | float |
| System.Char | char | char |
| System.Boolean | bool | int32_t |
| System.Byte | byte | unsigned char |

**Note**：Native Code 中应使用固定宽度的 C Type（例如来自 `<stdint.h>` 的 `int32_t`），不要使用 `int` 或 `long`。尤其是 `long` 的大小因 Platform 而异：Windows 上为 32-bit，而大多数其他 Desktop 和 Mobile Platform 上为 64-bit。如果 Managed 与 Unmanaged 两侧对 Type 大小的理解不一致，数据就会损坏。
