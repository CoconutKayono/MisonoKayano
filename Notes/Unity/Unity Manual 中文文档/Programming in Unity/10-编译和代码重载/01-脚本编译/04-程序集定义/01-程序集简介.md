# Unity 中的程序集简介

> 原文：[Introduction to assemblies in Unity](https://docs.unity3d.com/6000.7/Documentation/Manual/assembly-definitions-intro.html)

Unity 提供两种特殊的资源类型——Assembly Definition 和 Assembly Reference，用于帮助将脚本组织到程序集内。

程序集是一个 C# Code Library，其中包含由脚本定义并编译得到的 Class 和 Struct，同时还定义了对其他程序集的引用。有关 C# 中程序集的更多信息，请参阅 [.NET 中的程序集](https://learn.microsoft.com/en-us/dotnet/standard/assembly/)。

默认情况下，Unity 几乎会将所有游戏脚本编译到名为 `Assembly-CSharp.dll` 的预定义程序集中。Unity 还会创建一些更小的专用预定义程序集，请参阅 [[09-预定义程序集参考]]。

这种安排对小型项目来说基本可用，但随着项目代码增加，会出现以下缺点：

- 每次修改一个脚本时，Unity 都必须重新编译所有其他脚本，从而增加迭代式代码修改的整体编译时间。
- 任意脚本都可以直接访问其他脚本中定义的类型，这会让重构和改进代码更加困难。
- 所有脚本都会针对所有平台进行编译。

通过定义程序集，可以组织代码以促进模块化和复用。定义在自定义程序集中的脚本不再添加到默认程序集，并且只能访问其他自定义程序集中的脚本。

<a name="defining-assemblies"></a>

## 定义程序集

要将项目代码组织到程序集内，请为每个目标程序集创建一个文件夹，并将应属于该程序集的脚本移动到相应文件夹中。然后创建 Assembly Definition 资源来指定程序集属性：[[02-创建程序集定义#create-asmdef|创建 Assembly Definition 资源]]。

Unity 会将包含 Assembly Definition 的文件夹中的所有脚本编译为一个程序集，并使用该资源中定义的名称和其他设置。除非子文件夹有自己的 Assembly Definition 或 Assembly Reference 资源，否则该程序集也会包含子文件夹中的脚本。

要将非子文件夹中的脚本包含到现有程序集中，请在该非子文件夹中创建 Assembly Reference 资源，并将其设置为引用定义目标程序集的 Assembly Definition 资源。例如，无论项目中的 Editor 文件夹位于何处，都可以将所有 Editor 文件夹中的脚本合并到它们自己的程序集中。

Unity 会按照由依赖关系决定的顺序编译程序集。不能指定编译发生的顺序。

<a name="find-assembly"></a>

## 查找脚本所属的程序集

要识别脚本所属的程序集，请在 Project 窗口中选择脚本文件，在 Inspector 窗口中查看其属性。如果存在 Assembly Definition，Inspector 的 **Assembly Information** 部分会显示程序集文件名和 Assembly Definition。

<a name="special-folders"></a>

## Editor 文件夹

通常，无论脚本位于何处，Unity 都会将名为 `Editor` 的文件夹中的脚本编译到预定义的 `Assembly-CSharp-Editor` 程序集中：[[09-预定义程序集参考]]。但是，如果在某个文件夹中创建 Assembly Definition，而该文件夹下包含 `Editor` 文件夹，Unity 就不再将这些 Editor 脚本放入预定义的 Editor 程序集。相反，它们会进入 Assembly Definition 创建的新程序集，而这可能不是它们应属的程序集。要管理 `Editor` 文件夹，可以在每个 `Editor` 文件夹中创建 Assembly Definition 或 Assembly Reference 资源，将这些脚本放入一个或多个 Editor 程序集。更多信息请参阅 [[02-创建程序集定义#create-editor-assembly|为 Editor 代码创建程序集]]。

有关将保留文件夹名称 `Editor` 用于 Editor 脚本的更多信息，请参阅 [保留文件夹名称参考](https://docs.unity3d.com/6000.7/Documentation/Manual/SpecialFolders.html)。
