# 有条件地包含程序集

> 原文：[Conditionally including assemblies](https://docs.unity3d.com/6000.7/Documentation/Manual/assembly-definition-includes.html)

可以使用预处理器符号控制是否编译程序集，以及是否将程序集包含在应用程序的构建中（包括 Editor 中的 Play mode）。可以在 Assembly Definition 选项的 **Define Constraints** 列表中指定程序集被使用时必须已定义的符号：

1. 选择程序集对应的 Assembly Definition，在 [[07-程序集定义Inspector窗口参考|Inspector]] 中查看其属性。
2. 在 **Define Constraints** 部分，点击 **+** 按钮向约束列表添加新符号。
3. 输入符号名称。
4. 点击 **Apply**。

有关可用于 define constraints 的脚本符号，请参阅 [[07-程序集定义Inspector窗口参考#define-constraints|Define Constraints]]。

<a name="define-symbols"></a>

## 根据 Unity 和项目 Package 版本定义符号

如果需要根据项目是否使用特定版本的 Unity 或 Package，在程序集内编译不同代码，可以向 **Version Defines** 列表添加条目。该列表指定何时定义符号的规则。对于版本号，可以指定一个逻辑表达式，使其计算为特定版本或版本范围。

有条件地定义符号：

1. 选择程序集对应的 Assembly Definition 资源，在 **Inspector** 中查看其属性。
2. 在 **Version Defines** 部分，点击 **+** 按钮向列表添加条目。
3. 设置以下属性：

   - **If resource**：选择必须已安装的 **Unity**、Package 或 Module，只有这样才能定义该符号。
   - **version is**：计算为特定版本或版本范围的表达式。有关语法规则，请参阅[版本定义表达式](#version-define-expressions)。
   - **set define**：版本条件满足时要定义的脚本符号。

   **Version expression outcome** 会显示表达式计算出的版本。如果结果显示 **Invalid**，则表示表达式语法不正确。

4. 点击 **Apply**。

在 Assembly Definition 中定义的符号，其作用域仅限于为该定义创建的程序集中的脚本。

> **注意**：可以将 **Version Defines** 列表中定义的符号用作 **Define Constraints**。这意味着可以指定仅当项目中还安装了给定 Package 的特定版本时，才使用某个程序集。

<a name="version-define-expressions"></a>

### 版本定义表达式

可以使用表达式指定确切版本或版本范围。

版本表达式使用数学[区间表示法](https://en.wikipedia.org/wiki/Interval_(mathematics))：方括号 `[]` 表示范围包含端点，圆括号 `()` 表示范围不包含端点。

下表说明语法：

| 表达式 | 计算结果 |
| --- | --- |
| `[1.3,3.4.1]` | `1.3.0 <= x <= 3.4.1` |
| `(1.3.0,3.4)` | `1.3.0 < x < 3.4.0` |
| `[1.1,3.4)` | `1.1.0 <= x < 3.4.0` |
| `(0.2.4,5.6.2-preview.2]` | `0.2.4 < x <= 5.6.2.-preview.2` |
| `[2.4.5]` | `x = 2.4.5` |
| `2.1.0-preview.7` | `x >= 2.1.0-preview.7` |

> **注意**：表达式中不允许有空格，也不支持通配符。

### Unity 版本方案

当前版本的 Unity（以及所有支持 Assembly Definition 的版本）使用由三部分组成的版本标识符：`MAJOR.MINOR.REVISION`，例如 `6000.0.33f1`。

- `MAJOR` 版本是四位数字：对于 Unity `2022.x.z` 及更早版本，它表示发行年份；从 Unity 6（`6000.x.z`）开始，它表示主要技术版本。
- `MINOR` 版本表示目标发行季度，例如 `1`、`2`、`3` 或 `4`。
- `REVISION` 标识符本身包含三部分，格式为 `RRzNN`，其中：
  - `RR` 是一位或两位数字的修订号。
  - `z` 是表示发行类型的字母：
    - `a` = alpha 发行版
    - `b` = beta 发行版
    - `f` = 普通 public 发行版
    - `c` = China 发行版（等同于 f）
    - `p` = patch 发行版
    - `x` = experimental 发行版
  - `NN` 是一位或两位数字的递增编号。

发行类型标识符的比较顺序如下：

> `a < b < f = c < p < x`

alpha 发行版早于 beta，beta 早于普通（`f`）或 China（`c`）发行版。对于相同修订号，patch 发行版总是晚于普通或 China 发行版；experimental 发行版晚于任何其他发行类型。请注意，experimental 发行版末尾没有递增编号。

下面的示例表达式包含 Unity 的所有 `6000.0` 或 `6000.1` 版本，但不包含 `6000.2` 或更高版本：

```text
[6000.0,6000.2)
```

### Package 和 Module 版本号

Package 和 Module 的版本标识符有四部分，遵循 [Semantic Versioning](https://semver.org/) 格式：`MAJOR.MINOR.PATCH-LABEL`。前三部分始终是数字，但 label 是字符串。处于 preview 状态的 Unity Package 使用字符串 `preview` 或 `preview.n`，其中 `n > 0`。

下面的示例表达式包含 `MAJOR.MINOR` 版本在 3.2 到 6.1（含）之间的 Package 所有版本：

```text
[3.2,6.1]
```
