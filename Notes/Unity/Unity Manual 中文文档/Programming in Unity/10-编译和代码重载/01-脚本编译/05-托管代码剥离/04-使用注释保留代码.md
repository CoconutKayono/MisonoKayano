# 使用注释保留代码

> 原文：[Preserving code using annotations](https://docs.unity3d.com/6000.7/Documentation/Manual/managed-code-stripping-preserving.html)

你可以使用注释来阻止 Unity Linker 剥离代码中的特定部分。当应用程序生成 Unity 执行静态分析时尚不存在的运行时代码时，这会很有用，例如通过 [reflection](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/concepts/reflection) 生成代码。注释可以向 Unity Linker 提供关于不应剥离哪些代码模式的一般指导，也可以指示不要剥离某个特定的、已定义的代码部分。

你可以采用两种主要方法为代码添加注释，以便在 Managed Code Stripping 过程中保留代码：

- <a id="root-annotations"></a>[[#root-annotations|根注释]]将代码的一部分标识为根。Unity Linker 不会剥离标记为根的代码。根注释使用起来不那么复杂，但也可能导致 Unity Linker 保留本应剥离的一些代码。
- [[#dependency-annotations|依赖注释]]定义代码元素之间的连接。与根注释相比，依赖注释可以减少不必要的代码保留。

在更高的剥离级别下，这两种技术都能更好地控制 Unity Linker 剥离的代码量，并降低关键代码被剥离的可能性。当代码通过 reflection 引用其他代码时，注释尤其有用，因为 Unity Linker 并不总能检测到 reflection 的使用。

保留使用 reflection 或在运行时生成其他代码的代码，可以显著降低应用程序执行时出现意外行为的可能性。有关 Unity Linker 能识别的 reflection 模式示例，请参阅 [Unity Intermediate Language Linker reflection 测试套件](https://github.com/Unity-Technologies/linker/tree/unity-master/test/Mono.Linker.Tests.Cases/Reflection)。

## 根注释

根注释会强制 Unity Linker 将代码元素视为根，这些代码元素不会在代码剥离过程中被剥离。根据需要保留带构造函数的单个类型还是程序集，可以使用两种根注释：

- <a id="PreserveAttribute"></a>[[#PreserveAttribute|Preserve Attribute]]：将单个类型标注为根，以保留这些类型。
- <a id="LinkXMLAnnotation"></a>[[#LinkXMLAnnotation|Link.xml]]：将程序集以及这些程序集中的类型或其他代码实体标注为根，以保留它们。

### 使用 Preserve Attribute 注释根

使用 [`[Preserve]`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Scripting.PreserveAttribute.html) Attribute，可以将代码的特定部分单独排除在 Unity Linker 的静态分析之外。要使用此 Attribute 注释一段代码，请将 `[Preserve]` 添加到希望保留的第一段代码的正前方。以下列表描述了使用 `[Preserve]` Attribute 注释不同代码元素时，Unity Linker 会保留哪些实体：

- **Assembly**：保留程序集中所有已使用和已定义的类型。要将 `[Preserve]` Attribute 赋给程序集，请将 Attribute 声明放在该程序集包含的任意 C# 文件中，并置于所有 namespace 声明之前。
- **Type**：保留一个类或类型及其默认构造函数。
- **Method**：保留该方法、声明该方法的类型、该方法返回的类型，以及所有参数的类型。
- **Property**：保留该属性、声明该属性的类型、属性的值类型，以及获取和设置属性值的方法。
- **Field**：保留该字段、字段类型，以及声明该字段的类型。
- **Event**：保留该事件、声明该事件的类型、事件返回的类型、`[add]` accessor 和 `[remove]` accessor。
- **Delegate**：保留 delegate 类型以及该 delegate 调用的所有方法。

当希望同时保留某个类型及其默认构造函数时，使用 `[Preserve]` Attribute。如果希望只保留其中一个而不是两者，使用 `link.xml` 文件。

你可以在任何程序集和任何 namespace 中定义 `[Preserve]` Attribute。可以使用 [`PreserveAttribute`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Scripting.PreserveAttribute.html) 类、创建它的子类，或创建自己的类。例如：

```csharp
class Foo
{
    [Preserve]
    public void PreservedMethod(){}
}
```

### 使用 Link XML 文件注释根

你可以在项目中包含名为 `link.xml` 的 `.xml` 文件，以保留特定程序集或程序集中的特定部分。`link.xml` 文件必须位于项目的 `Assets` 文件夹或其子目录中，并且必须在文件中包含 `<linker>` 标签。Unity Linker 会将 `link.xml` 文件中保留的任何程序集、类型或成员视为根类型。

项目中可以使用任意数量的 `link.xml` 文件。因此，你可以为每个 plug-in 提供单独的保留声明。不能在 package 中包含 `link.xml` 文件，但可以从非 package 的 `link.xml` 文件中引用 package 程序集。

有关如何设置 `link.xml` 文件格式的信息，请参阅 [[05-Link XML格式参考]]。

## 依赖注释

依赖注释定义各种代码元素之间的依赖关系。这些注释对于保留 Unity Linker 无法进行静态分析的代码模式（例如 reflection）很有用。当没有根元素使用这些代码元素时，这些注释还可以确保它们不会被错误地保留。可以使用两种方法改变 Unity Linker 处理代码元素的方式：

- <a id="AnnotationAttributes"></a>[[#AnnotationAttributes|注释 Attribute]]：指示 Unity Linker 保留特定的代码模式，例如保留派生自已注释类型的任何类型。
- <a id="AlwaysLinkAssemblyAttribute"></a>[[#AlwaysLinkAssemblyAttribute|AlwaysLinkAssemblyAttribute]]：指示 Unity Linker 即使某个程序集没有被项目中的其他程序集引用，也要处理该程序集。

### 注释 Attribute

当某个 API 始终需要时，`[Preserve]` Attribute 很有用。其他 Attribute 适用于更一般的保留场景。例如，可以使用 [`[RequireImplementorsAttribute]`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Scripting.RequireImplementorsAttribute.html) 注释 interface，以保留实现该 interface 的所有类型。

要注释特定的代码模式，请使用以下一个或多个 Attribute：

- [`RequireImplementorsAttribute`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Scripting.RequireImplementorsAttribute.html)：将实现此 interface 的所有类型标记为依赖项。
- [`RequireDerivedAttribute`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Scripting.RequireDerivedAttribute.html)：将派生自此类型的所有类型标记为依赖项。
- [`RequiredInterfaceAttribute`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Scripting.RequiredInterfaceAttribute.html)：将类型上的 interface implementations 标记为依赖项。
- [`RequiredMemberAttribute`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Scripting.RequiredMemberAttribute.html)：将类型的所有成员标记为依赖项。
- [`RequireAttributeUsagesAttribute`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Scripting.RequireAttributeUsagesAttribute.html)：将 custom attributes 标记为依赖项。

你可以组合这些 Attribute，以更精确地控制 Unity Linker 保留代码的方式。

### AlwaysLinkAssembly Attribute

[`[AlwaysLinkAssembly]`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Scripting.AlwaysLinkAssemblyAttribute.html) Attribute 会强制 Unity Linker 搜索某个程序集，不论该程序集是否被构建中包含的其他程序集引用。此 Attribute 只能应用于程序集。

此 Attribute 不会直接保留程序集中的代码。相反，它会指示 Unity Linker 对该程序集应用[[06-Unity Linker标记规则参考#root-marking-rules|根标记规则]]。如果程序集中的代码元素都不符合该程序集的根标记规则，Unity Linker 仍会从构建中移除该程序集。

对包含一个或多个带有 `[RuntimeInitializeOnLoadMethod]` Attribute 的方法、但可能不包含项目中任何场景直接或间接使用的类型的 precompiled 或 package 程序集，请使用此 Attribute。

如果某个程序集定义了 `[assembly: AlwaysLinkAssembly]`，同时又被构建中包含的另一个程序集引用，则此 Attribute 对输出没有影响。
