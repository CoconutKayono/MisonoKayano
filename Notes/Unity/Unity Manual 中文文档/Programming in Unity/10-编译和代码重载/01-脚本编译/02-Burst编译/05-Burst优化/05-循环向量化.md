# 循环向量化

> 原文：[Loop vectorization](https://docs.unity3d.com/6000.7/Documentation/Manual/burst/optimization-loop-vectorization.html)

Burst 使用[循环向量化](https://llvm.org/docs/Vectorizers.html#loop-vectorizer)来提升代码性能。这项技术一次循环处理多个值，而不是每次只处理一个值，因此可以提升代码运行速度。例如：

```csharp
[MethodImpl(MethodImplOptions.NoInlining)]
private static unsafe void Bar([NoAlias] int* a, [NoAlias] int* b, int count)
{
    for (var i = 0; i < count; i++)
    {
        a[i] += b[i];
    }
}

public static unsafe void Foo(int count)
{
    var a = stackalloc int[count];
    var b = stackalloc int[count];

    Bar(a, b, count);
}
```

Burst 会将 `Bar` 中的标量循环转换为向量化循环。它不再一次循环一个值，而是生成一次循环处理多个值的代码，从而生成更快的代码。

下面是 Burst 为上述 `Bar` 循环针对 `AVX2` 生成的 `x64` 汇编：

```x86asm
.LBB1_4:
    vmovdqu    ymm0, ymmword ptr [rdx + 4*rax]
    vmovdqu    ymm1, ymmword ptr [rdx + 4*rax + 32]
    vmovdqu    ymm2, ymmword ptr [rdx + 4*rax + 64]
    vmovdqu    ymm3, ymmword ptr [rdx + 4*rax + 96]
    vpaddd     ymm0, ymm0, ymmword ptr [rcx + 4*rax]
    vpaddd     ymm1, ymm1, ymmword ptr [rcx + 4*rax + 32]
    vpaddd     ymm2, ymm2, ymmword ptr [rcx + 4*rax + 64]
    vpaddd     ymm3, ymm3, ymmword ptr [rcx + 4*rax + 96]
    vmovdqu    ymmword ptr [rcx + 4*rax], ymm0
    vmovdqu    ymmword ptr [rcx + 4*rax + 32], ymm1
    vmovdqu    ymmword ptr [rcx + 4*rax + 64], ymm2
    vmovdqu    ymmword ptr [rcx + 4*rax + 96], ymm3
    add        rax, 32
    cmp        r8, rax
    jne        .LBB1_4
```

Burst 将循环展开并向量化为四条 `vpaddd` 指令，每条计算 8 次整数加法，因此每次循环迭代总共计算 32 次整数加法。

## 循环向量化 intrinsic

Burst 包含用于表达循环向量化假设的实验性 intrinsic：`Loop.ExpectVectorized` 和 `Loop.ExpectNotVectorized`。Burst 随后会在编译时验证循环是否向量化。这对于可能破坏自动向量化的情况很有用，例如向代码中引入分支：

```csharp
[MethodImpl(MethodImplOptions.NoInlining)]
private static unsafe void Bar([NoAlias] int* a, [NoAlias] int* b, int count)
{
    for (var i = 0; i < count; i++)
    {
        if (a[i] > b[i])
        {
            break;
        }

        a[i] += b[i];
    }
}
```

这会将汇编改为：

```x86asm
.LBB1_3:
    mov        r9d, dword ptr [rcx + 4*r10]
    mov        eax, dword ptr [rdx + 4*r10]
    cmp        r9d, eax
    jg         .LBB1_4
    add        eax, r9d
    mov        dword ptr [rcx + 4*r10], eax
    inc        r10
    cmp        r8, r10
    jne        .LBB1_3
```

这并不理想，因为循环是标量循环，每次迭代只有一次整数加法。代码中很难直接发现这种情况，因此可以使用 `Loop.ExpectVectorized` 和 `Loop.ExpectNotVectorized` 表达循环向量化假设。Burst 随后会在编译时验证循环是否向量化。

下面的示例在原始 `Bar` 示例中加入 `Loop.ExpectVectorized` intrinsic：

```csharp
[MethodImpl(MethodImplOptions.NoInlining)]
private static unsafe void Bar([NoAlias] int* a, [NoAlias] int* b, int count)
{
    for (var i = 0; i < count; i++)
    {
        Unity.Burst.CompilerServices.Loop.ExpectVectorized();

        a[i] += b[i];
    }
}
```

Burst 随后会在编译时验证循环是否向量化。如果循环没有向量化，Burst 会发出编译器错误。下面的示例会产生错误：

```csharp
[MethodImpl(MethodImplOptions.NoInlining)]
private static unsafe void Bar([NoAlias] int* a, [NoAlias] int* b, int count)
{
    for (var i = 0; i < count; i++)
    {
        Unity.Burst.CompilerServices.Loop.ExpectVectorized();

        if (a[i] > b[i])
        {
            break;
        }

        a[i] += b[i];
    }
}
```

Burst 会在编译时发出以下错误：

```text
LoopIntrinsics.cs(6,9): Burst error BC1321: The loop is not vectorized where it was expected that it is vectorized.
```

**注意**：这些 intrinsic 在 `if` 语句内部不起作用。Burst 不会阻止这种情况发生，因此你不会看到编译时错误。
