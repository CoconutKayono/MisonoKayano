# 声明无别名指针和结构体

> 原文：[Declaring non-aliasing pointers and structs](https://docs.unity3d.com/6000.7/Documentation/Manual/burst/aliasing-noalias.html)

使用 `[NoAlias]` 属性向 Burst 提供有关指针和结构体别名关系的额外信息。

在大多数用例中，你不需要使用 `[NoAlias]` 属性。如果结构体定义已经带有 `[NativeContainer]` 属性，或者字段位于 Job 结构体中，则不需要应用该属性，因为 Burst 会在这些情况下推断出无别名信息。

提供 `[NoAlias]` 属性是为了构造 Burst 无法自行推断别名关系的复杂数据结构。如果把 `[NoAlias]` 用在实际上可能与其他指针别名的指针上，可能会产生未定义行为，使错误难以追踪。

可以按以下方式使用该属性：

- 用在函数参数上，表示该参数不与函数的任何其他参数别名。
- 用在结构体字段上，表示该字段不与结构体中任何其他带 `[NoAlias]` 的字段别名。
- 用在结构体上，表示结构体的地址不会出现在结构体自身内部。
- 用在函数返回值上，表示返回的指针不与同一函数返回的任何其他指针别名。

## NoAlias 函数参数

下面是一个发生别名的示例：

```csharp
int Foo(ref int a, ref int b)
{
    b = 13;
    a = 42;
    return b;
}
```

对于这段代码，Burst 生成以下汇编：

```x86asm
mov     dword ptr [rdx], 13
mov     dword ptr [rcx], 42
mov     eax, dword ptr [rdx]
ret
```

这表示 Burst 执行以下操作：

- 将 13 存入 `b`。
- 将 42 存入 `a`。
- 重新加载 `b` 的值并返回。

Burst 必须重新加载 `b`，因为它不知道 `a` 和 `b` 是否由同一块内存支持。

为代码添加 `[NoAlias]` 属性可以改变这一点：

```csharp
int Foo([NoAlias] ref int a, ref int b)
{
    b = 13;
    a = 42;
    return b;
}
```

此时 Burst 生成以下汇编：

```x86asm
mov     dword ptr [rdx], 13
mov     dword ptr [rcx], 42
mov     eax, 13
ret
```

在这种情况下，加载 `b` 的操作被替换为将常量 13 移入返回寄存器。

## NoAlias 结构体字段

下面的示例与前一个示例相同，但应用于结构体：

```csharp
struct Bar
{
    public NativeArray<int> a;
    public NativeArray<float> b;
}

int Foo(ref Bar bar)
{
    bar.b[0] = 42.0f;
    bar.a[0] = 13;
    return (int)bar.b[0];
}
```

Burst 为此生成以下汇编：

```x86asm
mov     rax, qword ptr [rcx + 16]
mov     dword ptr [rax], 1109917696
mov     rcx, qword ptr [rcx]
mov     dword ptr [rcx], 13
cvttss2si       eax, dword ptr [rax]
ret
```

在这种情况下，Burst 执行以下操作：

- 将 `b` 中数据的地址加载到 `rax`。
- 将 42 存入该地址（`1109917696` 是 `0x42280000`，也就是 `42.0f`）。
- 将 `a` 中数据的地址加载到 `rcx`。
- 将 13 存入该地址。
- 重新加载 `b` 中的数据并将其转换为整数后返回。

如果你知道两个 `NativeArray` 不由同一块内存支持，可以将代码改为：

```csharp
struct Bar
{
    [NoAlias]
    public NativeArray<int> a;

    [NoAlias]
    public NativeArray<float> b;
}

int Foo(ref Bar bar)
{
    bar.b[0] = 42.0f;
    bar.a[0] = 13;
    return (int)bar.b[0];
}
```

给 `a` 和 `b` 都添加 `[NoAlias]` 后，Burst 会知道它们在该结构体中互不别名，并生成以下汇编：

```x86asm
mov     rax, qword ptr [rcx + 16]
mov     dword ptr [rax], 1109917696
mov     rax, qword ptr [rcx]
mov     dword ptr [rax], 13
mov     eax, 42
ret
```

这表示 Burst 可以直接返回整数常量 42。

## NoAlias 结构体

Burst 假设指向结构体的指针不会出现在结构体自身内部。但在某些情况下并非如此：

```csharp
unsafe struct CircularList
{
    public CircularList* next;

    public CircularList()
    {
        // “空”列表指向自身。
        next = this;
    }
}
```

链表是少数几种在结构体内部可以访问结构体自身指针的结构之一。

下面的示例说明在结构体上使用 `[NoAlias]` 的作用：

```csharp
unsafe struct Bar
{
    public int i;
    public void* p;
}

float Foo(ref Bar bar)
{
    *(int*)bar.p = 42;
    return ((float*)bar.p)[bar.i];
}
```

Burst 生成以下汇编：

```x86asm
mov     rax, qword ptr [rcx + 8]
mov     dword ptr [rax], 42
mov     rax, qword ptr [rcx + 8]
mov     ecx, dword ptr [rcx]
movss   xmm0, dword ptr [rax + 4*rcx]
ret
```

在这种情况下，Burst 会：

- 将 `p` 加载到 `rax`。
- 将 42 存入 `p`。
- 再次将 `p` 加载到 `rax`。
- 将 `i` 加载到 `ecx`。
- 返回 `p` 中由 `i` 指定的索引处的值。

在这种情况下，Burst 两次加载 `p`。这是因为它不知道 `p` 是否指向结构体 `bar` 的地址。将 42 存入 `p` 后，它必须从 `bar` 重新加载 `p` 的地址，这是一项开销较大的操作。

添加 `[NoAlias]` 可以避免这种情况：

```csharp
[NoAlias]
unsafe struct Bar
{
    public int i;
    public void* p;
}

float Foo(ref Bar bar)
{
    *(int*)bar.p = 42;
    return ((float*)bar.p)[bar.i];
}
```

Burst 生成以下汇编：

```x86asm
mov     rax, qword ptr [rcx + 8]
mov     dword ptr [rax], 42
mov     ecx, dword ptr [rcx]
movss   xmm0, dword ptr [rax + 4*rcx]
ret
```

此时 Burst 只加载一次 `p` 的地址，因为 `[NoAlias]` 告诉它 `p` 不可能是指向 `bar` 的指针。

## NoAlias 函数返回值

有些函数只能返回唯一指针。例如，`malloc` 只返回唯一指针。在这种情况下，`[return:NoAlias]` 可以向 Burst 提供有用的信息。

**重要**：只对保证产生唯一指针的函数使用 `[return: NoAlias]`，例如 bump 分配器或 `malloc`。Burst 为了性能会积极内联函数，因此对于小函数，Burst 会将其内联到调用者中，即使没有该属性也能得到相同结果。

下面的示例使用由栈分配支持的 bump 分配器：

```csharp
// 只返回 stackalloc 内存中的唯一地址。
// 这里显式禁止内联，因为 Burst 总会尝试内联这类小函数，
// 从而失去该示例想要表达的效果。
[MethodImpl(MethodImplOptions.NoInlining)]
unsafe int* BumpAlloc(int* alloca)
{
    int location = alloca[0]++;
    return alloca + location;
}

unsafe int Func()
{
    int* alloca = stackalloc int[128];

    // 在 alloca 开头存储大小。
    alloca[0] = 1;

    int* ptr1 = BumpAlloc(alloca);
    int* ptr2 = BumpAlloc(alloca);

    *ptr1 = 42;
    *ptr2 = 13;

    return *ptr1;
}
```

这会生成以下汇编：

```x86asm
push    rsi
push    rdi
push    rbx
sub     rsp, 544
lea     rcx, [rsp + 36]
movabs  rax, offset memset
mov     r8d, 508
xor     edx, edx
call    rax
mov     dword ptr [rsp + 32], 1
movabs  rbx, offset "BumpAlloc(int* alloca)"
lea     rsi, [rsp + 32]
mov     rcx, rsi
call    rbx
mov     rdi, rax
mov     rcx, rsi
call    rbx
mov     dword ptr [rdi], 42
mov     dword ptr [rax], 13
mov     eax, dword ptr [rdi]
add     rsp, 544
pop     rbx
pop     rdi
pop     rsi
ret
```

Burst 执行的关键操作是：

- 将 `ptr1` 放入 `rdi`。
- 将 `ptr2` 放入 `rax`。
- 将 42 存入 `ptr1`。
- 将 13 存入 `ptr2`。
- 再次加载 `ptr1` 并返回。

如果添加 `[return: NoAlias]` 属性：

```csharp
[MethodImpl(MethodImplOptions.NoInlining)]
[return: NoAlias]
unsafe int* BumpAlloc(int* alloca)
{
    int location = alloca[0]++;
    return alloca + location;
}

unsafe int Func()
{
    int* alloca = stackalloc int[128];

    // 在 alloca 开头存储大小。
    alloca[0] = 1;

    int* ptr1 = BumpAlloc(alloca);
    int* ptr2 = BumpAlloc(alloca);

    *ptr1 = 42;
    *ptr2 = 13;

    return *ptr1;
}
```

它会生成以下汇编：

```x86asm
push    rsi
push    rdi
push    rbx
sub     rsp, 544
lea     rcx, [rsp + 36]
movabs  rax, offset memset
mov     r8d, 508
xor     edx, edx
call    rax
mov     dword ptr [rsp + 32], 1
movabs  rbx, offset "BumpAlloc(int* alloca)"
lea     rsi, [rsp + 32]
mov     rcx, rsi
call    rbx
mov     rdi, rax
mov     rcx, rsi
call    rbx
mov     dword ptr [rdi], 42
mov     dword ptr [rax], 13
mov     eax, 42
add     rsp, 544
pop     rbx
pop     rdi
pop     rsi
ret
```

在这种情况下，Burst 不会重新加载 `ptr2`，而是将 42 移入返回寄存器。
