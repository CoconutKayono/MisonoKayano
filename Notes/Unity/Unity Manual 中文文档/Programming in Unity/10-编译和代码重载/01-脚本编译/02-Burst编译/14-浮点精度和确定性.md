# 浮点精度和确定性

> 原文：[Float precision and determinism](https://docs.unity3d.com/6000.7/Documentation/Manual/burst/float-precision-determinism.html)

可以使用相关 API 配置 Burst 浮点数计算的精度和确定性程度。在需要特定精度级别或跨平台可复现性时，这一点非常重要。

## 浮点精度

使用 [`FloatPrecision`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Burst.FloatPrecision.html) 枚举定义 Burst 的浮点精度。

浮点精度以 ULP（unit in the last place，最后一位的单位，也称最小精度单位）衡量。这是浮点数之间的间隔，即有效数字中最低位为 1 时所代表的值。`Unity.Burst.FloatPrecision` 提供以下精度：

- `FloatPrecision.Standard`：默认值，与 `FloatPrecision.Medium` 相同，精度为 3.5 ULP。
- `FloatPrecision.High`：精度为 1.0 ULP。
- `FloatPrecision.Medium`：精度为 3.5 ULP。
- `FloatPrecision.Low`：精度按函数定义，并且函数可能会规定有效输入的受限范围。

> **注意**：在 Burst API 的早期版本中，`FloatPrecision` 枚举名为 `Accuracy`。

### 低浮点精度

如果使用 [`FloatPrecision.Low`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Burst.FloatPrecision.Low.html) 模式，以下函数的精度为 350.0 ULP。其他所有函数都继承 `FloatPrecision.Medium` 的 ULP：

- `Unity.Mathematics.math.sin(x)`
- `Unity.Mathematics.math.cos(x)`
- `Unity.Mathematics.math.exp(x)`
- `Unity.Mathematics.math.exp2(x)`
- `Unity.Mathematics.math.exp10(x)`
- `Unity.Mathematics.math.log(x)`
- `Unity.Mathematics.math.log2(x)`
- `Unity.Mathematics.math.log10(x)`
- `Unity.Mathematics.math.pow(x, y)`
  - 不支持用负数 `x` 的分数次幂。
- `Unity.Mathematics.math.fmod(x, y)`

## 浮点数学模式

使用 [`FloatMode`](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Burst.FloatMode.html) 枚举定义 Burst 的浮点数学模式。它提供以下模式：

- `FloatMode.Default`：默认为 `FloatMode.Strict` 模式。
- `FloatMode.Strict`：Burst 不会重新排列计算，并遵守非规格化数和 `NaN`（Not a Number，非数）等特殊浮点值。这是默认值。
- `FloatMode.Fast`：Burst 可以重新排列指令，并使用专用或精度较低的硬件 SIMD 指令。
- `FloatMode.Deterministic`：确保 Burst 中的浮点计算具有确定性，即在所有支持的平台上保持一致。仅支持 64 位架构。

对于支持将乘法和加法（例如 `a * b + c`）合并为单条指令的硬件，可以使用 `FloatMode.Fast` 启用这项优化。不过，重新排列这些指令可能导致精度降低。

对于不要求计算顺序完全一致、也不要求以统一方式处理 NaN 的场景，可以使用 `FloatMode.Fast`。

当应用程序要求浮点计算在不同平台和硬件上产生一致结果时，使用 `FloatMode.Deterministic`。

## 浮点确定性

在确定性模拟、网络通信或任何跨平台可复现性至关重要的场景中，一致的浮点结果尤其重要。

启用 `FloatMode.Deterministic` 时：

- Burst 使用确定性的数学函数实现。
- Burst 禁用可能引入平台差异的某些浮点优化。
- 所有平台都会将次正规（非规格化）浮点数刷新为零，从而消除次正规数处理方式不同造成的不一致。

禁用部分优化可能会降低浮点计算性能。实际性能影响取决于具体使用场景。

IEEE 754 中的 `NaN` 值编码为所有指数位都设为 1 且尾数非零。`FloatMode.Deterministic` 不保证 `NaN` 的表示逐位相同。如果计算结果为 `NaN`，所有平台都会产生 `NaN`，但 `NaN` 的确切位模式可能因平台而异。

使用硬件特定的 intrinsic 或平台特定的指令，仍可能造成平台间差异；如果要保持确定性，应避免使用这些内容。

请注意，`FloatMode.Deterministic` 只适用于 Burst 编译的代码。以下因素仍可能破坏确定性：

- 如果传入 Burst 编译代码的输入包含浮点计算，可能会引入非确定性。
- 如果从未设置为使用 `FloatMode.Deterministic` 的代码中，将函数指针传入已设置该模式的 Burst 编译代码，可能会破坏确定性。
