# 引用类型管理

> 原文：[Reference type management](https://docs.unity3d.com/6000.7/Documentation/Manual/performance-reference-types.html)

托管代码中的所有非空[引用类型对象](https://docs.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/reference-types)和所有[装箱后的值类型对象](https://docs.microsoft.com/en-us/dotnet/csharp/programming-guide/types/boxing-and-unboxing)都必须分配在托管堆上，因此这些对象可能会导致应用程序出现性能问题。下面的各个部分概述了可以用来提升代码性能的方法。

## 避免反复连接字符串

C# 中的字符串是[不可变的引用类型](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/reference-types)。Unity 会在托管堆上分配引用类型，并由垃圾回收器管理。由于字符串一旦创建就不能更改，应尽量避免创建临时字符串。

下面的示例代码将字符串数组合并为一个字符串。每次在循环中添加一个新字符串时，`result` 变量之前的内容都会变得多余，代码还会分配一个全新的字符串。

```csharp
// 错误的 C# 脚本示例：反复连接字符串会产生大量
// 临时字符串。
using UnityEngine;

public class ExampleScript : MonoBehaviour {
    string ConcatExample(string[] stringArray) {
        string result = "";

        for (int i = 0; i < stringArray.Length; i++) {
            result += stringArray[i];
        }

        return result;
    }

}
```

如果输入的 `stringArray` 包含 `{ “A”, “B”, “C”, “D”, “E” }`，此方法会在堆上为以下字符串生成存储空间：

- `“A”`
- `“AB”`
- `“ABC”`
- `“ABCD”`
- `“ABCDE”`

在这个示例中，只需要最终字符串，其他字符串都是多余的分配。输入数组中的项目越多，此方法生成的字符串就越多，并且每个字符串都比前一个更长。

如果需要连接大量字符串，请使用 Mono 库的 [`System.Text.StringBuilder`](http://msdn.microsoft.com/en-gb/library/system.text.stringbuilder.aspx) 类。前一个脚本的改进版本如下：

```csharp
// 良好的 C# 脚本示例：StringBuilder 避免创建临时字符串，
// 只为最终结果字符串分配堆内存。
using UnityEngine;
using System.Text;

public class ExampleScript : MonoBehaviour {
    private StringBuilder _sb = new StringBuilder(16);

    string ConcatExample(string[] stringArray) {
        _sb.Clear();

        for (int i = 0; i < stringArray.Length; i++) {
            _sb.Append(stringArray[i]);
        }

        return _sb.ToString();
    }
}
```

除非反复连接操作调用得非常频繁（例如每帧更新时调用），否则反复连接字符串不会对性能造成太大影响。下面的示例每次调用 `Update` 时都会分配新字符串，并持续生成垃圾回收器必须处理的对象：

```csharp
// 错误的 C# 脚本示例：每帧都将分数值转换为字符串，
// 再与“Score: ”连接，因此每帧都会生成字符串。
using UnityEngine;
using UnityEngine.UI;

public class ExampleScript : MonoBehaviour {
    public Text scoreBoard;
    public int score;
    
    void Update() {
        string scoreText = "Score: " + score.ToString();
        scoreBoard.text = scoreText;
    }
}
```

为了避免垃圾回收器持续执行，可以配置代码，使文本只在分数发生变化时更新：

```csharp
// 良好的 C# 脚本示例：仅在分数发生变化时
// 执行分数转换
using UnityEngine;
using UnityEngine.UI;

public class ExampleScript : MonoBehaviour {
    public Text scoreBoard;
    public string scoreText;
    public int score;
    public int oldScore;
    
    void Update() {
        if (score != oldScore) {
            scoreText = "Score: " + score.ToString();
            scoreBoard.text = scoreText;
            oldScore = score;
        }
    }
}
```

进一步改进的方法，是将分数标题（显示 `“Score: ”` 的部分）和分数显示存储在两个不同的 `UI.Text` 对象中，这样就不需要连接字符串了。代码仍然需要将分数值转换为字符串，但这比前面的版本更好：

```csharp
// 最佳 C# 脚本示例：仅在分数发生变化时执行分数转换，
// 并且移除了字符串连接
using UnityEngine;
using UnityEngine.UI;

public class ExampleScript : MonoBehaviour {
   public Text scoreBoardTitle;
   public Text scoreBoardDisplay;
   public string scoreText;
   public int score;
   public int oldScore;

   void Start() {
       scoreBoardTitle.text = "Score: ";
   }

   void Update() {
       if (score != oldScore) {
           scoreText = score.ToString();
           scoreBoardDisplay.text = scoreText;
           oldScore = score;
       }
   }
}
```

要获得更高程度的优化，可以使用 UGUI 包中 [`TMPro.TMP_Text`](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/api/TMPro.TMP_Text.html#TMPro_TMP_Text_SetText_System_Char___) 类的 `SetText(Char [])` 方法。`SetText` 方法允许使用并重复使用 `char` 数组，逐位构建分数；还可以直接更新 `char` 数组中的值，而不需要使用字符串。

有关 C# 字符串处理最佳实践的更多信息，请参阅 Microsoft 的 [.NET 中比较字符串的最佳实践](https://learn.microsoft.com/en-us/dotnet/standard/base-types/best-practices-strings)文档。

## 避免闭包和匿名方法

通常应尽可能避免 C# 中的闭包。在性能敏感型代码中，尤其是在每帧执行的代码中，应尽量减少使用[匿名方法](https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/types/anonymous-types)和[方法引用](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/method-parameters#reference-parameters)。

C# 中的方法引用属于引用类型，因此会在托管堆上分配。这意味着，将方法引用作为参数传递时，可能会产生临时分配。无论传递的是匿名方法还是预定义方法，都会发生这种分配。

此外，将匿名方法转换为闭包时，传递闭包所需的内存量会大幅增加。

下面的代码示例中，需要按照特定顺序对随机数列表进行排序。示例使用匿名方法控制列表的排序顺序，并且排序不会产生任何分配。

```csharp
// 良好的 C# 脚本示例：使用匿名方法对列表排序。
// 此排序方法不会产生垃圾

List<float> listOfNumbers = getListOfRandomNumbers();

listOfNumbers.Sort( (x, y) =>

(int)x.CompareTo((int)(y/2)) 

);
```

为了让这段代码可复用，可以将常量 2 替换为局部作用域中的变量：

```csharp
// 错误的 C# 脚本示例：匿名方法变成了闭包，
// 并且每次调用时都会分配内存来存储 desiredDivisor 的值。

List<float> listOfNumbers = getListOfRandomNumbers();

int desiredDivisor = getDesiredDivisor();

listOfNumbers.Sort( (x, y) =>

(int)x.CompareTo((int)(y/desiredDivisor))

);
```

现在，匿名方法需要访问其作用域之外的变量，因此该方法已经变成闭包。`desiredDivisor` 变量必须传入闭包，以便闭包代码能够使用它。

为了确保向闭包传入正确的值，C# 会生成一个可以保存闭包所需外部作用域变量的匿名类。当闭包传入 `Sort` 方法时，会实例化这个类的一个副本，并使用 `desiredDivisor` 整数的值初始化该副本。

执行闭包需要实例化其生成类的一个副本，而在 C# 中所有类都是引用类型。因此，执行闭包需要在托管堆上分配对象。

## 避免将值类型转换为引用类型

值类型变量被自动转换为引用类型时，这个过程称为[装箱](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/types/boxing-and-unboxing)。装箱是 Unity 项目中最常见的意外临时内存分配来源之一。当把原始值类型变量（例如 `int` 和 `float`）传递给对象类型方法时，最容易发生装箱。

在下面的示例中，`x` 中的整数会被装箱，以便传递给 `object.Equals` 方法，因为对象上的 `Equals` 方法要求传入一个对象。

```csharp
int x = 1;

object y = new object();

y.Equals(x);
```

尽管装箱会导致意外的内存分配，C# IDE 和编译器却不会发出装箱警告。这是因为 C# 假设小型临时分配可以由分代垃圾回收器和对分配大小敏感的内存池高效处理。

Unity 的托管内存分配器确实会为小型和大型分配使用不同的内存池，但 Unity 的[垃圾回收器](https://docs.unity3d.com/6000.7/Documentation/Manual/performance-garbage-collector.html)不是分代垃圾回收器，因此无法高效地清除装箱产生的小型、高频临时分配。

### 识别装箱

在 CPU 跟踪中，装箱会显示为若干方法中的调用，具体取决于所使用的脚本后端。它们具有以下形式之一，其中 `<example class>` 是类或结构体的名称，`…` 表示若干参数：

```csharp
<example class>::Box(…)
Box(…)
<example class>_Box(…)
```

要查找装箱，也可以搜索反编译器或 IL 查看器的输出，例如 ReSharper 内置的 [IL 查看器工具](https://www.jetbrains.com/help/resharper/Viewing_Intermediate_Language.html)，或 [dotPeek 反编译器](https://www.jetbrains.com/decompiler/)。对应的 IL 指令是 `box`。

## 避免使用 params 修饰符

使用 [`params` 修饰符](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/method-parameters#params-modifier)列出可选参数的方法，会为传入的参数分配一个数组。如果存在不依赖该修饰符的方法重载，请使用这些重载。
