# 遮挡剔除

> 原文：[Occlusion culling](https://docs.unity3d.com/6000.7/Documentation/Manual/OcclusionCulling.html)

Occlusion Culling 是一种处理过程，可以阻止 Unity 对被其他 GameObject 完全遮挡（occluded）的 GameObject 执行渲染计算。

每帧，Camera 都会执行 Culling 操作，检查 Scene 中的 Renderer，并排除不需要绘制的 Renderer。默认情况下，Camera 会执行 Frustum Culling，排除位于 Camera [[01-相机视图简介#视锥体|View Frustum]] 外的所有 Renderer。但是，Frustum Culling 不会检查 Renderer 是否被其他 GameObject 遮挡，因此 Unity 仍可能将 CPU 和 GPU 时间浪费在最终帧中不可见的 Renderer 上。Occlusion Culling 会阻止这些无效操作。

![常规 Frustum Culling 会渲染 Camera 视图内的所有 Renderer](OcclusionFrustumCulling.jpg)

![Occlusion Culling 会移除被较近 Renderer 完全遮挡的 Renderer](OcclusionFullCulling.jpg)

## 何时使用遮挡剔除

要判断 Occlusion Culling 是否可能改善项目的运行时性能，请考虑以下事项：

- 减少无效渲染操作可以节省 CPU 和 GPU 时间。但 Unity 内置的 Occlusion Culling 会在 CPU 上执行运行时计算，这可能抵消它节省的 CPU 时间。因此，当项目由于 overdraw 受限于 GPU 时，Occlusion Culling 最有可能改善性能。
- Unity 会在运行时将 Occlusion Culling 数据加载到内存中，必须确保有足够的内存加载这些数据。
- Occlusion Culling 最适合用于由实体 GameObject 将彼此清晰分隔的小型、明确区域组成的 Scene，例如由走廊连接的房间。
- 可以使用 Occlusion Culling 遮挡剔除 Dynamic GameObject，但 Dynamic GameObject 不能遮挡其他 GameObject。如果项目在运行时生成 Scene 几何体，Unity 内置的 Occlusion Culling 不适合该项目。

## 工作原理

Occlusion Culling 会在 Unity Editor 中生成 Scene 数据，然后在运行时使用这些数据判断 Camera 可以看到什么。生成数据的过程称为 baking。

在烘焙 Occlusion Culling 数据时，Unity 会将 Scene 划分为 cells，并生成描述 cell 内几何体以及相邻 cells 之间可见性的数据。Unity 会在可能时合并 cells，以减少生成数据的大小。可以在 [[07-Occlusion Culling窗口参考]]中更改参数，并在 Scene 中使用 [[05-创建高精度遮挡区域|Occlusion Area]] 配置烘焙过程。

在运行时，Unity 会将烘焙数据加载到内存中。对于启用了 **Occlusion Culling** 属性的每个 Camera，Unity 会查询这些数据，以判断 Camera 可以看到什么。启用 Occlusion Culling 后，Camera 会同时执行 Frustum Culling 和 Occlusion Culling。

> [!NOTE]
> 如果项目使用 URP 或 HDRP，也可以使用 [[10-URP中的GPU遮挡剔除]]，或参考 [HDRP 中的 GPU Occlusion Culling](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.4/manual/gpu-culling.html)。
