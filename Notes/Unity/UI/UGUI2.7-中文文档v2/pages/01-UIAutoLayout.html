自动布局（Auto Layout）

Rect Transform 布局系统足够灵活，能够处理多种布局，也支持完全自由地放置元素。但有时需要更有结构的布局方式。

Auto Layout 系统可以把元素放入嵌套的布局组，如水平组、垂直组或网格，还能根据内容自动调整元素大小。例如，按钮可动态调整为恰好容纳文字和 Padding 的尺寸。

Auto Layout 建立在基本的 Rect Transform 布局系统之上，可以选择仅用于部分元素，也可以用于全部元素。

理解布局元素（Layout Elements）

Auto Layout 基于 Layout Element（布局元素）和 Layout Controller（布局控制器）两个概念。布局元素是带有 Rect Transform 的 GameObject，也可带有其他组件。它提供自身期望尺寸的信息，但不直接设置大小；布局控制器使用这些信息计算应分配的尺寸。

布局元素通过以下属性定义自身尺寸需求：

  • 最小宽度（Minimum width）
  • 最小高度（Minimum height）
  • 最大宽度（Maximum width）
  • 最大高度（Maximum height）
  • 首选宽度（Preferred width）
  • 首选高度（Preferred height）
  • 弹性宽度（Flexible width）
  • 弹性高度（Flexible height）

Content Size Fitter 和各类 Layout Group 都会使用布局元素提供的信息。布局组内元素的尺寸分配遵循以下基本原则：

  • 先分配 Minimum 最小尺寸。
  • 如果剩余空间足够，再分配 Preferred 首选尺寸。
  • 如果仍有额外空间，再按 Flexible 弹性尺寸分配。

任何带有 Rect Transform 的 GameObject 都可作为布局元素。默认的 Minimum、Preferred 和 Flexible 尺寸均为 0；为对象添加某些组件会改变这些布局属性。

Image 和 Text 就是提供布局属性的组件示例：它们会把 Preferred width / height 调整为与 Sprite 或文字内容匹配的尺寸。

布局元素组件（Layout Element Component）

要覆盖 Minimum、Preferred 或 Flexible 尺寸，可在 GameObject 上添加 Layout Element 组件。

Layout Element 可以覆盖一个或多个布局属性。勾选需要覆盖的属性，然后填写新的值。

更多信息请参阅 Layout Element 参考页面。

理解布局控制器（Layout Controllers）

布局控制器负责控制一个或多个布局元素（即带 Rect Transform 的 GameObject）的尺寸，也可能控制位置。它既可以控制自身所在 GameObject 的布局元素，也可以控制子级布局元素。

同一个组件可以同时充当 Layout Controller 和 Layout Element。

内容尺寸适配器（Content Size Fitter）

Content Size Fitter 是控制自身布局元素尺寸的控制器。最简单的体验方式，是给带 Text 组件的 GameObject 添加 Content Size Fitter。

将 Horizontal Fit 或 Vertical Fit 设为 Preferred，Rect Transform 就会调整宽度和／或高度，使其适应 Text 内容。

更多信息请参阅 Content Size Fitter 参考页面。

宽高比适配器（Aspect Ratio Fitter）

Aspect Ratio Fitter 是控制自身布局元素尺寸的控制器。

它可以根据宽度调整高度，或根据高度调整宽度；也可以让元素适合父级内部或包围父级。Aspect Ratio Fitter 不考虑 Minimum、Preferred 等布局尺寸信息。

更多信息请参阅 Aspect Ratio Fitter 参考页面。

布局组（Layout Groups）

Layout Group 控制子级布局元素的尺寸和位置。例如，Horizontal Layout Group 将子元素横向排列，Grid Layout Group 将子元素排成网格。

布局组不控制自己的尺寸。它自身也是一个布局元素，其尺寸由其他布局控制器控制，或手动设置。

无论布局组获得多大空间，它通常都会根据各子元素报告的 Minimum、Preferred 和 Flexible 尺寸，为它们分配合适的空间。布局组因此可以任意嵌套。

更多信息请参阅 Horizontal Layout Group、Vertical Layout Group 和 Grid Layout Group 参考页面。

受驱动的 Rect Transform 属性（Driven Properties）

Auto Layout 的布局控制器会自动控制某些 UI 元素的尺寸和位置，因此不应同时在 Inspector 或 Scene View 中手动编辑这些值；手动修改的结果会在下一次布局计算时被控制器重置。

Rect Transform 用 Driven Properties 表示这种控制关系。例如，Horizontal Fit 为 Minimum 或 Preferred 的 Content Size Fitter 会驱动同一 GameObject 的 Rect Transform 宽度。宽度会显示为只读，Rect Transform 顶部的信息框会提示哪些属性正被 Content Size Fitter 驱动。

Driven Properties 还有另一个作用：改变 Game View 的分辨率或大小就可能改变布局，继而改变这些属性的值，但不应仅因此将 Scene 标记为存在未保存修改。所以受驱动属性的值不会作为 Scene 的一部分保存，变化也不会让场景进入已修改状态。

技术细节（Technical Details）

Auto Layout 内置了若干组件，也允许创建以自定义方式控制布局的新组件。实现系统识别的特定接口即可参与自动布局。

布局接口（Layout Interfaces）

组件实现 ILayoutElement 接口后，Auto Layout 会将其视为布局元素。

组件实现 ILayoutGroup 接口后，应负责驱动子级的 Rect Transform。

组件实现 ILayoutSelfController 接口后，应负责驱动自身的 RectTransform。

布局计算（Layout Calculations）

Auto Layout 按以下顺序评估并执行布局：

  1. 调用 ILayoutElement 的 CalculateLayoutInputHorizontal，计算 Minimum、Preferred 和 Flexible 宽度。顺序为自底向上：先子级、后父级，使父级能够使用子级的信息。
  2. 调用 ILayoutController 的 SetLayoutHorizontal，计算并设置实际宽度。顺序为自顶向下：先父级、后子级，因为子级宽度分配依赖父级可用的总宽度。完成后，各布局元素的 Rect Transform 获得新宽度。
  3. 调用 ILayoutElement 的 CalculateLayoutInputVertical，计算 Minimum、Preferred 和 Flexible 高度。顺序为自底向上：先子级、后父级，使父级能够使用子级的信息。
  4. 调用 ILayoutController 的 SetLayoutVertical，计算并设置实际高度。顺序为自顶向下：先父级、后子级，因为子级高度分配依赖父级可用的总高度。完成后，各布局元素的 Rect Transform 获得新高度。

因此，系统先计算宽度，再计算高度。高度计算可以依赖宽度，但宽度计算不能依赖高度。

触发布局重建（Layout Rebuild）

当组件的某项属性变化使当前布局失效时，需要重新计算布局。可使用以下调用触发：

LayoutRebuilder.MarkLayoutForRebuild (transform as RectTransform);

重建不会立即发生，而是在当前帧结束、渲染开始前执行。这样可以避免同一帧内反复重建布局造成性能开销。

建议在以下位置触发布局重建：

  • 可能改变布局的属性 Setter。
  • 以下回调：OnEnable、OnDisable、OnRectTransformDimensionsChange、OnValidate（仅编辑器需要，运行时不需要）、OnDidApplyAnimationProperties。
