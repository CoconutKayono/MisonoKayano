# 第三人称摄像机方案

这是一份用于确定第三人称摄像机方向的设计笔记。

目标不是马上写代码，而是先回答：需要什么样的摄像机、它要解决哪些问题，以及应该按照什么顺序实现。

---

## 一、先从“我要什么摄像机”开始

第三人称摄像机并不是一种固定实现。它应该根据游戏体验来决定。

在设计之前，先明确以下问题：

| 问题 | 需要确定的内容 |
| --- | --- |
| 摄像机看谁 | 玩家角色、载具、队伍中心、当前目标，还是多个目标的中心点 |
| 摄像机是否由玩家控制 | 完全固定、玩家自由旋转、部分自动旋转，还是由系统接管 |
| 玩家是否始终位于画面中心 | 居中、偏左肩、偏右肩，或根据移动方向动态偏移 |
| 摄像机距离是否固定 | 固定距离、可缩放距离、根据场景自动调整 |
| 摄像机高度是否固定 | 固定高度、根据角色状态变化，或根据地形变化 |
| 角色朝向由谁决定 | 角色移动方向、摄像机朝向、鼠标瞄准方向，或锁定目标方向 |
| 是否需要战斗功能 | 瞄准、锁定目标、切换目标、近战绕圈、远程射击 |
| 摄像机是否允许穿墙 | 通常不允许，需要处理遮挡和碰撞 |
| 视角是否需要自动调整 | 转弯跟随、移动时回正、进入狭窄空间时调整 |
| 游戏使用什么输入设备 | 鼠标键盘、手柄、触摸屏，或多种设备 |

如果这些问题没有答案，摄像机很容易在实现过程中反复重写。

---

## 二、几种摄像机方案

### 方案 A：固定跟随摄像机

#### 体验

摄像机始终处在玩家身后某个固定偏移位置，只跟随玩家移动，不允许玩家自由旋转视角。

#### 适合场景

- 线性关卡
- 需要控制镜头构图的游戏
- 简单原型
- 不强调探索和战斗自由度的游戏

#### 需要处理的问题

1. 跟随玩家位置
2. 保持固定距离和高度
3. 始终朝向玩家或玩家前方
4. 防止摄像机穿墙
5. 处理玩家快速移动时的平滑跟随

#### 优点

- 最容易实现
- 参数较少
- 行为稳定
- 适合验证角色移动和场景结构

#### 缺点

- 玩家无法观察身后或侧面
- 不适合自由探索
- 战斗和瞄准会受到限制

#### 实现顺序

1. 固定摄像机与玩家的相对位置
2. 实现位置跟随
3. 实现朝向跟随
4. 添加移动和旋转平滑
5. 添加碰撞处理

---

### 方案 B：自由旋转的轨道摄像机

这是最典型的第三人称摄像机方案。

#### 体验

摄像机围绕玩家旋转。玩家通过鼠标或右摇杆控制水平旋转和垂直旋转，角色通常根据摄像机方向移动。

#### 主要结构

```text
玩家角色
  └── Camera Target / Pivot
        └── Camera
```

- `Target`：摄像机跟随的对象，通常位于角色胸口或头部附近
- `Pivot`：摄像机旋转中心，负责保存 `Yaw` 和 `Pitch`
- `Camera`：位于 Pivot 后方的实际摄像机

#### 需要处理的问题

1. 找到稳定的跟随目标
2. 读取鼠标或手柄输入
3. 计算水平旋转 `Yaw`
4. 计算垂直旋转 `Pitch`
5. 限制垂直旋转角度
6. 根据旋转和距离计算摄像机位置
7. 平滑跟随和旋转
8. 防止摄像机穿过墙壁或地面
9. 决定角色是否跟随摄像机方向转身
10. 处理摄像机上下边界和极端角度

#### 优点

- 探索自由度高
- 适用于大多数动作和冒险游戏
- 摄像机与角色移动可以自然结合
- 是后续扩展瞄准、锁定和战斗模式的基础

#### 缺点

- 比固定跟随复杂
- 输入、旋转、碰撞之间容易相互影响
- 需要处理摄像机遮挡、穿墙和视角抖动

#### 实现顺序

1. 只实现摄像机跟随目标
2. 只实现水平旋转
3. 添加垂直旋转和角度限制
4. 根据旋转计算摄像机位置
5. 添加位置和旋转平滑
6. 添加摄像机碰撞检测
7. 决定角色移动方向是否使用摄像机坐标系
8. 添加移动时自动回正

---

### 方案 C：肩扛式摄像机

#### 体验

摄像机不在玩家正后方，而是位于左肩或右肩一侧。玩家通常可以自由旋转，并且摄像机中心用于瞄准。

#### 适合场景

- 第三人称射击
- 使用弓、枪械或魔法的角色
- 需要明确瞄准方向的动作游戏

#### 需要处理的问题

1. 设置肩部偏移 `Shoulder Offset`
2. 让摄像机朝向瞄准点，而不是简单看向玩家
3. 让角色的攻击方向与摄像机中心一致
4. 处理左右肩切换
5. 处理摄像机与墙壁之间的碰撞
6. 防止肩部偏移导致角色被墙体遮挡
7. 处理瞄准状态和普通移动状态之间的切换

#### 优点

- 瞄准方向清晰
- 画面构图更适合战斗
- 可以自然支持左右肩切换

#### 缺点

- 角色可能被摄像机遮挡
- 墙角和狭窄空间更难处理
- 摄像机和角色移动的关系更加复杂

#### 实现顺序

1. 先实现方案 B 的基础轨道摄像机
2. 添加左右肩偏移
3. 添加屏幕中心射线和瞄准点
4. 让角色攻击方向使用瞄准点
5. 添加瞄准状态切换
6. 添加肩膀切换
7. 最后处理遮挡和特殊场景

---

### 方案 D：锁定目标摄像机

#### 体验

玩家锁定敌人或交互目标后，摄像机同时关注玩家和目标。玩家可以围绕目标移动，摄像机自动保持双方处于合适位置。

#### 适合场景

- 近战动作游戏
- Boss 战
- 需要精确观察敌人的游戏
- 类似 Souls-like 的战斗系统

#### 需要处理的问题

1. 目标筛选
2. 目标锁定和解除锁定
3. 多个目标之间的切换
4. 计算玩家与目标的中间关注点
5. 根据玩家和目标距离调整摄像机距离
6. 防止玩家或目标离开屏幕
7. 处理目标被遮挡、死亡或离开范围
8. 处理锁定状态下的角色移动方向

#### 优点

- 近战战斗更稳定
- 不容易丢失敌人
- 摄像机可以自动构图

#### 缺点

- 自动控制感较强
- 多目标切换容易让玩家迷失
- 摄像机碰撞和画面构图更加复杂

#### 实现顺序

1. 先完成方案 B
2. 实现目标搜索和目标筛选
3. 实现锁定状态
4. 让摄像机同时关注玩家和目标
5. 添加锁定状态下的移动
6. 添加目标切换
7. 处理目标失效和摄像机碰撞

---

### 方案 E：自动导演式摄像机

#### 体验

摄像机大部分时间由系统控制，根据玩家移动、场景、剧情或战斗状态自动选择角度。

#### 适合场景

- 剧情游戏
- 线性动作游戏
- 关卡演出
- 需要镜头语言的游戏

#### 需要处理的问题

1. 镜头触发区域
2. 预设摄像机位置
3. 镜头切换和过渡
4. 玩家控制权和系统控制权的切换
5. 镜头优先级
6. 场景遮挡和构图
7. 镜头切换时的突变和晕眩

#### 优点

- 可以精确控制画面
- 适合剧情和演出
- 可以隐藏场景缺陷

#### 缺点

- 规则较多
- 调试成本高
- 不适合一开始就作为基础方案实现

#### 实现顺序

1. 先完成一种稳定的玩家控制摄像机
2. 添加预设镜头
3. 添加镜头触发区域
4. 添加镜头优先级
5. 添加平滑过渡
6. 添加剧情和战斗状态接管

## 三、方案对比

| 方案 | 玩家自由度 | 实现难度 | 适合重点 | 建议优先级 |
| --- | ---: | ---: | --- | ---: |
| 固定跟随 | 低 | 低 | 原型、线性关卡 | 1 |
| 自由轨道 | 高 | 中 | 通用第三人称探索 | 最高 |
| 肩扛式 | 高 | 中高 | 射击、瞄准 | 2 |
| 锁定目标 | 中 | 高 | 近战、Boss 战 | 3 |
| 自动导演 | 低到中 | 高 | 剧情、演出 | 4 |

对于“自己实现一个通用第三人称摄像机”，建议以方案 B 为核心，之后再扩展方案 C 或方案 D。

---

## 四、所有方案都需要面对的问题

### 1. 跟随目标问题

摄像机不应直接跟随角色脚底或根节点的精确位置，否则摄像机会随动画产生不必要的上下抖动。

通常需要单独设置一个 `Camera Target` 或 `Camera Pivot`，位置大约在角色胸口到头部之间。

### 2. 输入问题

需要明确：

- 鼠标移动是否控制摄像机
- 手柄右摇杆是否控制摄像机
- 水平和垂直灵敏度是否分别设置
- 是否支持反转 Y 轴
- 输入是否需要根据帧率处理

### 3. 旋转问题

摄像机通常拆成两个角度：

- `Yaw`：水平旋转，围绕角色转一圈
- `Pitch`：垂直旋转，通常需要上下限位

不建议直接累加 `Transform.eulerAngles`，应注意角度范围、旋转顺序和万向节问题。

### 4. 平滑问题

需要分别决定：

- 跟随位置的平滑速度
- 摄像机旋转的平滑速度
- 摄像机距离变化的平滑速度
- 碰撞恢复时的平滑速度

所有内容共用一个平滑参数，通常会导致操作感不稳定。

### 5. 碰撞和遮挡问题

摄像机不能只检测最终位置，否则摄像机可能在移动过程中穿过墙体。

典型过程是：

```text
计算摄像机理想位置
  ↓
从 Camera Target 向理想位置进行 SphereCast
  ↓
发现障碍物后缩短摄像机距离
  ↓
将摄像机移动到障碍物前方
  ↓
障碍物消失后平滑恢复原距离
```

使用球形检测通常比单条 `Raycast` 更可靠，因为真实摄像机具有一定体积。

### 6. 角色移动问题

如果角色移动使用世界坐标，摄像机旋转和角色移动方向会互相割裂。

常见设计是：

```text
摄像机水平朝向
  ↓
计算前方和右方
  ↓
将输入方向转换到摄像机坐标系
  ↓
得到角色移动方向
```

但也可以让角色朝向与移动方向无关，例如瞄准游戏或锁定目标游戏。这个选择应在设计初期确定。

### 7. 狭窄空间问题

需要考虑：

- 玩家进入墙角
- 玩家贴近墙壁
- 低矮天花板
- 楼梯和斜坡
- 门框和柱子
- 摄像机被障碍物夹住

这些问题不能只靠增加一个碰撞检测就完全解决，必要时还需要调整摄像机高度、距离或旋转角度。

### 8. 视觉舒适度问题

需要避免：

- 摄像机快速旋转造成眩晕
- 碰撞后距离突然改变
- 角色移动时画面上下抖动
- 摄像机贴墙时穿插模型
- 摄像机回正过于频繁
- 垂直角度达到极限后继续反向跳转

## 五、推荐的实现顺序

不要一开始同时实现输入、碰撞、锁定和战斗。建议分成以下阶段。

### 阶段 1：确定目标和空间关系

1. 创建玩家角色
2. 创建 `Camera Target`
3. 确定摄像机距离
4. 确定摄像机高度
5. 确定摄像机是否偏左或偏右
6. 让摄像机保持一个固定偏移

### 阶段 2：实现最小跟随

1. 摄像机跟随 `Camera Target`
2. 摄像机看向目标
3. 处理玩家移动
4. 验证摄像机不会产生明显抖动

### 阶段 3：加入玩家控制

1. 读取水平输入
2. 实现 `Yaw`
3. 读取垂直输入
4. 实现 `Pitch`
5. 限制 `Pitch` 范围
6. 验证不同帧率下的操作一致性

### 阶段 4：加入平滑

1. 平滑跟随位置
2. 平滑摄像机旋转
3. 平滑摄像机距离
4. 调整输入灵敏度和阻尼

### 阶段 5：加入碰撞

1. 选择摄像机碰撞层
2. 从目标向理想摄像机位置检测
3. 碰撞后缩短距离
4. 防止摄像机进入墙体
5. 障碍物消失后恢复距离
6. 处理墙角、地面和天花板

### 阶段 6：连接角色移动

1. 根据摄像机水平朝向计算移动方向
2. 决定角色是否自动转向移动方向
3. 处理静止时的角色朝向
4. 处理奔跑、后退和横移

### 阶段 7：扩展玩法功能

根据游戏需求选择性加入：

- 瞄准模式
- 肩膀切换
- 锁定目标
- 自动回正
- 冲刺时拉远摄像机
- 受击时摄像机震动
- 室内外摄像机模式切换
- 剧情镜头接管

---

## 六、当前建议

第一版不要追求完整的“万能第三人称摄像机”。

建议先实现：

1. 一个 `Camera Target`
2. 水平和垂直自由旋转
3. 固定摄像机距离
4. `Pitch` 角度限制
5. 基本跟随平滑
6. `SphereCast` 摄像机碰撞
7. 摄像机相对移动

这七项完成后，已经具备一个可用的基础第三人称摄像机。瞄准、锁定、肩膀切换和自动导演都应建立在这个基础上，而不是一开始就混在一起实现。
