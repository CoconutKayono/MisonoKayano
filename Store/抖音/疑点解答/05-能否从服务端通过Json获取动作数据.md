# 给策划的回复：能否从服务端通过 JSON 获取动作数据？

> 用途：直接复制/转述给策划。
> 背景：策划问"抖音平台能不能在客户端调用我们服务端的动作资源？能不能通过传 JSON 文件作为动作数据来播放动作？"
> 结论先行：**"动作资源"本身不能从服务端下发；但"服务端通过 JSON 下发动作指令、客户端播本地动画"完全可以实现。** 下面用大白话讲清楚。

---

## 一、一句话结论

**抖音虚拟世界里，动画资源是"随游戏包发到每个玩家手机上的"，服务端发不了资源本体，但可以发"播放指令"——客户端收到指令后，用本地已有的动画播出来。**

打个比方：资源相当于"超市里的商品"，服务端相当于"下单系统"。下单系统能告诉玩家"买哪件商品"，但商品本身得靠物流（游戏包更新）提前摆在玩家手里的货架上。服务端**不能临时把新商品塞进玩家手里**。

---

## 二、三个关键事实

| # | 事实 | 影响 |
| --- | --- | --- |
| 1 | 抖音虚拟世界**不支持运行时下载/加载任何资源**（`Resources.Load`、`UnityWebRequest` 全部被平台禁用） | 动画、模型等资源必须随游戏包（AssetBundle）提前下发 |
| 2 | 客户端 ↔ 服务端通信（RemoteEvent/RemoteFunction）**只能传基础类型**（整数、字符串、布尔等），**不能传资源对象**，也**不能传表格**；但**可以传 JSON 字符串** | 服务端可以把"动作 ID + 参数"打包成 JSON 字符串下发 |
| 3 | 播放动画的 API（`PlayAnimation`）接收的是**本地已配置好的动画剪辑引用** | 客户端得有一张"动作 ID → 本地动画"的对照表 |

---

## 三、对策划问题的直接回答：JSON 能不能当"动作数据"？

**要看 JSON 里装的是什么：**

### ✅ 情况一：JSON 描述"播哪个动作、怎么播"——可以

如果 JSON 里放的是**动作 ID、动画名、mask、循环次数**这类**指令/配置**，完全可以。服务端把 JSON 编码成字符串下发，客户端解析后查本地动画表播放：

```
服务端:  {"actionId":1001, "mask":"UpperBody", "loop":3}  →  dkjson.encode → 字符串
客户端: 收到字符串 → dkjson.decode → 查本地表 → PlayAnimation(clip, nil, mask)
```

> **注意：传的是 JSON 字符串，不是 JSON 文件。** 平台通信只认基础类型，所以 JSON 要用 `dkjson.encode` 转成字符串再传。

### ❌ 情况二：JSON 含关键帧/骨骼数据，想"生成"动画——不可以

如果意图是"把动画的关键帧、骨骼变换数据放在 JSON 里，运行时解析并**动态生成一个能播的动画**"，平台不支持：

1. 动画必须是**随包分发的 `AnimationClip` 资源**，运行时无法加载/生成新动画资源。
2. `Resources.Load`、`UnityWebRequest`、`System.IO` 全被平台禁用，没有"从数据创建动画"的官方 API。
3. 就算硬造出动画，也**没有接口把它挂到角色上播放**——动作播放只认本地资源引用。

> **一句话：JSON 只能告诉客户端"放哪段已有的动画、怎么放"，不能成为"动画本身"。**

## 四、JSON 指令方案的实际效果

### 4.1 服务端（DS）下发 JSON 动作指令

```lua
-- 服务端：把动作指令打包成 JSON 字符串广播
local cmd = { actionId = 1001, mask = "UpperBody", loop = 3 }
ServerToClientEvent:FireAllClients(dkjson.encode(cmd))   -- 传字符串
```

### 4.2 客户端：解析 JSON → 查本地表 → 播放

```lua
-- 客户端：收到 JSON 字符串
ServerToClientEvent.onClientEvent:AddListener(function(jsonStr)
    local cmd = dkjson.decode(jsonStr)            -- JSON字符串 → Lua表
    local cfg = ActionTable[cmd.actionId]         -- 查本地配置（Excel导出的Lua表）
    if cfg then
        local clip = clipByName[cfg.animName]     -- 本地已打包的动画资源
        if clip then
            local mask = (cmd.mask == "UpperBody")
                and DouyinAnimatorMask.UpperBody
                or  DouyinAnimatorMask.WholeBody
            actor:PlayAnimation(clip, nil, mask)
        end
    end
end)
```

### 4.3 运营上能做到什么程度

| 诉求 | 能否通过 JSON 指令实现 |
| --- | --- |
| 服务端决定"谁、什么时候、播哪个动作" | ✅ 能 |
| 服务端动态调动作参数（mask、循环、速度） | ✅ 能 |
| 服务端开关某个动作（ID 放行/禁止） | ✅ 能 |
| 服务端下发**新动画资源本体**（不改包） | ❌ 不能，需重新发布版本 |
| 服务端下发**全新的动作 ID**（客户端包里没有） | ❌ 不能，动画不在本地就播不了 |

> 补充说明：策划可能觉得"加了新动作，只要服务端发个 ID 客户端就该能播"。这里有个前提——**这个动作的动画资源必须已经在客户端包里**（随包发布）。如果只是"新增 ID 但复用已有动画/组合参数"，服务端 JSON 指令完全够用；如果是"全新动画"，必须走一次版本更新。

## 五、给策划的建议口径

> "抖音虚拟世界因为平台限制，**动作等资源必须随游戏包下发，无法由服务端在运行时推送**。但我们能做到：**服务端通过 JSON 下发动作指令（动作 ID + 参数），客户端解析后播放本地动画**。所以"由服务端决定动作表现"的需求可以满足，包括动态调整动作参数、开关动作。唯一的边界是：**全新动画资源**必须随游戏包更新，无法靠 JSON 下发。"

---

## 六、一句话备忘

**资源靠包更新，指令靠服务端（JSON 字符串）。服务端定"播什么"，客户端定"怎么播"。**
