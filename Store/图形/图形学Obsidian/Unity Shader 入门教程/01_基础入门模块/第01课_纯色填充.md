# 第 01 课 · 纯色填充：写你的第一段 Unity Shader

> 对着色器说「画成什么颜色」，是一切渲染的起点。
> 学习环境：Unity 6.x + URP + HLSL（ShaderLab 做壳、HLSL 做核）。

「画成什么颜色」是所有渲染的起点。这一课我们从最朴素的开始：让物体变成纯红色。整段 Shader 里真正决定颜色的，其实只有一行——我们就把这一行吃透。

---

## 1. 完整代码：让物体变成纯红色

```hlsl
Shader "Lesson/01_SolidColor"
{
    SubShader
    {
        Tags
        {
            "RenderType" = "Opaque"
            "RenderPipeline" = "UniversalPipeline"
        }

        Pass
        {
            HLSLPROGRAM
            #pragma vertex vert
            #pragma fragment frag

            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

            struct Attributes
            {
                float4 positionOS : POSITION;
            };

            struct Varyings
            {
                float4 positionHCS : SV_POSITION;
            };

            Varyings vert (Attributes IN)
            {
                Varyings OUT;
                OUT.positionHCS = TransformObjectToHClip(IN.positionOS.xyz);
                return OUT;
            }

            half4 frag () : SV_Target
            {
                return half4(1, 0, 0, 1);   // ★ 真正决定颜色的一行
            }
            ENDHLSL
        }
    }
}
```

先别管那几十行「外壳」。记住一个事实：**这段代码里，真正决定画面是什么颜色的，只有片元着色器里的这一行**：

```hlsl
return half4(1.0, 0.0, 0.0, 1.0);
```

其余所有代码，都是在为这一行「搭台子」。台子怎么搭，我们在《小灶解析》里讲，现在先把这一行拆开。

---

## 2. 怎么把它跑起来

1. 在 Project 窗口里右键 → **Create → Shader → Unlit Shader**，会生成一个 `.shader` 文件，命名成 `01_SolidColor`。
2. 双击打开，把里面原有的内容**全部删掉**，粘入上面的完整代码，`Ctrl + S` 保存。回到 Unity 会自动编译。
3. 新建一个材质：Project 窗口右键 → **Create → Material**，命名如 `RedMat`。
4. 选中这个材质，在 Inspector 最上方的 **Shader 下拉框**里，找到 `Lesson → 01_SolidColor`。
5. 把材质拖到场景里的 Cube 或 Sphere 上，物体会变成纯红色。

---

## 3. 拆开理解那一行

### return + SV_Target：把答案交给屏幕

着色器的工作是：物体覆盖到的每个像素都来问它「我该是什么颜色？」，片元着色器就回答一个颜色。

在 Unity/HLSL 里，片元着色器是一个**「会返回颜色的函数」**——它不把颜色写进某个全局变量，而是直接 `return` 出去。函数签名末尾的 `: SV_Target` 就是在告诉 GPU：「这个函数的返回值，就是最终写进画面的颜色。」

所以记住这个对应关系：**片元着色器 `return` 什么，像素就显示什么。**

### half4 / float4：装着 4 个颜色数字的盒子

`float4` 是一个装着 **4 个浮点数**的容器，分别代表**红、绿、蓝、透明度**：

```
half4(  1.0,  0.0,  0.0,  1.0  )
         红    绿    蓝   透明度
```

每个数字的范围是 0.0 到 1.0，把它理解成百分比：

- `1.0` = 100%，这个颜色通道开到最大
- `0.5` = 50%，开一半
- `0.0` = 0%，完全关掉

所以 `half4(1.0, 0.0, 0.0, 1.0)` 的意思是：红色 100%、绿色 0%、蓝色 0%、不透明 → **纯红色**。

透明度这个通道先固定写 1.0（不透明），暂时不用管它。

> 你可能注意到代码里写的是 `half4` 而不是 `float4`。`half4` 是「精度减半」的 `float4`，颜色这种数据用一半精度就够了，而且更快。**现在你把它当成 `float4` 看即可**，二者的「4 个颜色数字」含义完全一样。细节见《小灶解析》第 ③ 条。

## 4. 试着改一改

对照下面的表格，替换 `frag` 里 `return` 的那一行，感受效果：

| 颜色 | 代码（frag 里 return 的那一行） |
|------|------|
| 绿 | `return half4(0.0, 1.0, 0.0, 1.0);` |
| 蓝 | `return half4(0.0, 0.0, 1.0, 1.0);` |
| 白 | `return half4(1.0, 1.0, 1.0, 1.0);` |
| 黑 | `return half4(0.0, 0.0, 0.0, 1.0);` |
| 灰 | `return half4(0.5, 0.5, 0.5, 1.0);` |

观察灰色那一行：红绿蓝三个数**相等**时就是灰，数值越大越偏白、越小越偏黑。这是后面理解「颜色」和「光照」的一个重要直觉。

## 5. 练习

练习区（也就是你粘进去的代码）现在是黑色的，修改 `frag` 里 `return` 的 `half4`，让它变成红色。

初始状态：

```hlsl
half4 frag () : SV_Target
{
    return half4(0.0, 0.0, 0.0, 1.0);   // 黑色
}
```

### 答案解析

把第一个数改成 1.0：

```hlsl
return half4(1.0, 0.0, 0.0, 1.0);
```

四个数字分别对应：

- `1.0` → 红色开到最大
- `0.0` → 绿色关掉
- `0.0` → 蓝色关掉
- `1.0` → 完全不透明（固定写这个）

初始的 `half4(0.0, 0.0, 0.0, 1.0)` 三个颜色通道全是 0，所以是黑色。把第一个 0.0 改成 1.0，红色通道打开，就变成红色了。

进阶：把 `1.0` 换成 `0.5`，看看会变成什么颜色。（答案是**暗红色**——红色开一半，就是暗红。）

## 6. 【小灶解析】专家补充

### ① 「壳」与「核」：ShaderLab 负责组织，HLSL 负责计算

Unity 的 `.shader` 文件是**两层结构**：

- **ShaderLab**：最外面那层「壳」，负责「组织」——这个 Shader 叫什么（`Shader "Lesson/01_SolidColor"`）、属于哪套管线（`Tags` 里的 `"RenderPipeline" = "UniversalPipeline"`）、里面有几个 `Pass`。它不干「算颜色」的活。
- **HLSL**：夹在 `HLSLPROGRAM` 和 `ENDHLSL` 之间的部分，才是真正跑在 GPU 上、做计算的地方。你写的 `vert` 和 `frag` 函数就在这里面。

所以本课的代码可以这样理解：ShaderLab 是一份「工程文件」，HLSL 才是那份「代码」。你后面要学的几乎所有「写逻辑」，都发生在 HLSL 里。

### ② 为什么纯色也要写顶点着色器？

片元着色器不会凭空对像素运行——它只能处理「光栅化之后剩下的像素」。而光栅化需要先知道「三角形在屏幕上的位置」，这个位置是**顶点着色器**算出来的。

所以哪怕颜色是写死的，管线也必须先走完这一串：顶点着色器把模型顶点从「模型空间」变换到「裁剪空间」（`TransformObjectToHClip` 干的就是这件事）→ 光栅化把三角形铺成像素 → 片元着色器给每个像素填颜色。少了第一步，后面就无米下锅。这一整条流水线，正是贯穿全部课程的主线。

（顺带认识一下命名：`positionOS` 里的 `OS` 是 Object Space 模型空间，`positionHCS` 里的 `HCS` 是 Homogeneous Clip Space 齐次裁剪空间。这是 URP 官方的命名习惯，你会在各种 URP Shader 里反复见到。）

### ③ 精度三兄弟：float4 / half4 / fixed4

- `float4`：32 位浮点，精度最高。顶点位置、矩阵这类「数要大、要精确」的数据用它。
- `half4`：16 位浮点，精度减半。颜色、方向（法线）这类数据用它足够，而且**省带宽、省电**——在移动端尤其明显。
- `fixed4`：老管线时代的低精度类型，现代 URP 里基本等同于 `half4`，属于历史遗留，新代码不必特意用。

现代 URP 的惯用法是：**位置/矩阵用 float，颜色用 half**。所以你会看到 `positionHCS` 是 `float4`，而 `frag` 返回的是 `half4`。这个「该用多高精度」的取舍，本身就是 TA 的性能基本功之一。

### ④ SV_Target 里的 SV 是什么？

`SV` 是 **System Value（系统值）** 的缩写。HLSL 里的「语义（Semantics）」是写给编译器和硬件看的标签，告诉它「这块数据要接到管线的哪个口」。

- 不带前缀的（如 `POSITION`、`NORMAL`）是**用户自定义语义**，含义相对灵活；
- `SV_` 开头的（如 `SV_POSITION`、`SV_Target`）是**系统强制语义**，硬件约定好了用途：`SV_POSITION` = 顶点最终屏幕位置，`SV_Target` = 片元输出到渲染目标的颜色。

这就是为什么「顶点着色器的输出」和「片元着色器的输出」都必须挂 `SV_` 语义——它们是硬性规定，写错名字会直接编译报错。

### ⑤ 为什么颜色用 0~1，而不是 0~255？

你可能习惯「红 = RGB(255, 0, 0)」这种 0~255 的写法。Shader 里统一用 0.0~1.0 的浮点，原因是 GPU 是浮点机器，用「比例」表示颜色更直观（1.0 = 100%），也方便和后面的光照「能量」概念对齐——PBR 里很多运算都建立在「0~1 代表能量比例」这个约定上。这也是为什么你能看到 0.5 表示「一半」，而不会看到 127。
