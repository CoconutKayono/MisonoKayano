# N01｜用一个向量移动方块

**学完这张卡，你能解释 `(1,0,0)` 为什么能让方块沿 X 轴移动，以及把 1 改成 2 后为什么移动更多。**

## 必须掌握：把向量当成一支有长度的箭头

位置回答“在哪里”，位移回答“从这里往哪边走多少”。一支带长度的箭头就能表达位移；我们用**向量**描述它。

先让 Cube 的旋转为 0、缩放为 1。在这个设置下：

| 向量 | 箭头含义 |
| --- | --- |
| `(1,0,0)` | 沿 +X 走 1 |
| `(0,1,0)` | 沿 +Y 走 1 |
| `(2,0,0)` | 仍沿 +X，但走 2 |

“方向相同”不代表“向量相同”：第三支箭头比第一支长。

想移动整个方块，可以给每个顶点加相同的位移。**顶点**就是组成模型形状的点。所有点一起平移，方块形状不变。

## 核心代码：给位置加一支箭头

这段位于完整示例的 `Vert` 函数中：

```hlsl
float3 direction = _Direction.xyz;
float3 offset = direction * _Amount;
float3 movedPosition = input.positionOS + offset;
Output output;
output.positionCS = TransformObjectToHClip(movedPosition);
return output;
```

`_Direction.xyz` 取材质参数的前三个数；`_Amount` 是倍率。真正决定移动量的是两者的乘积。最后的转换函数暂时当成“把这个位置交给画面”的模板。

例如 `_Amount=0.5`：方向参数 `(1,0,0)` 得到位移 `(0.5,0,0)`；改成 `(2,0,0)` 后，位移变为 `(1,0,0)`。**0.5 此时还不保证是固定距离，因为方向参数也带长度。**

以后法线和光方向也用三个数表达，先分清“朝向”和“长度”，就不容易把错误长度带进光照计算。

## 先预测，再验证：只改 X 分量

用 Unity 6 的 URP 场景，Cube 位于原点、旋转为 0、缩放为 1，相机留出足够空间。复制完整 Shader，创建材质选择 `BeginnerNPR/N01VectorMove` 并赋给 Cube。

基准：Direction=`(1,0,0,0)`，Amount=0.5。第四个分量不用管。

只把 Direction 的 X 从 1 改为 2，其他都不动。

先预测：方块只是保持朝向，还是移动到更远处？预期是位移从 0.5 变为 1。注意 Inspector 中 Transform 的 Position 仍为原值：本例改的是绘制时的位置，没有修改游戏对象的位置。

## 理解即可

这几个数字是按物体自己的轴解释的。今天物体没有旋转和缩放，所以暂时不会感觉到差别；N03 再专门观察它。

## 完整示例

保存为 `N01VectorMove.shader`，或复制 [独立文件](../示例/N01VectorMove.shader)。

```shaderlab
Shader "BeginnerNPR/N01VectorMove"
{
    Properties
    {
        _Direction("Direction XYZ",Vector)=(1,0,0,0)
        _Amount("Amount",Range(0,0.5))=0.5
    }
    SubShader
    {
        Tags { "RenderPipeline"="UniversalPipeline" "RenderType"="Opaque" }
        Pass
        {
            Tags { "LightMode"="SRPDefaultUnlit" }
            HLSLPROGRAM
            #pragma vertex Vert
            #pragma fragment Frag
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
            CBUFFER_START(UnityPerMaterial)
                float4 _Direction;
                float _Amount;
            CBUFFER_END
            struct Input { float3 positionOS : POSITION; };
            struct Output { float4 positionCS : SV_POSITION; };
            Output Vert(Input input)
            {
                float3 direction = _Direction.xyz;
                float3 offset = direction * _Amount;
                float3 movedPosition = input.positionOS + offset;
                Output output;
                output.positionCS = TransformObjectToHClip(movedPosition);
                return output;
            }
            float4 Frag() : SV_Target { return float4(1,0.6,0.1,1); }
            ENDHLSL
        }
    }
}
```

保持 Cube 在画面中央附近，避免误把离开视野当作代码失效。粉色时查 Console 和 URP 设置；若启用了 Depth Priming，本组先关闭。示例只用于观察绘制位置，不会同步移动碰撞体。

## 带走这些

**三个结论**

1. 位移向量是一支带长度的箭头。
2. 位置加上位移，得到移动后的位置。
3. 方向参数变长，会让本例的移动距离增加。

**两个自测**

- `(0,2,0)×0.5` 得到什么位移？——`(0,1,0)`。
- 为什么 Transform 的 Position 没变？——Shader 修改绘制位置，没有修改对象的 Transform。

**一个最小实践：** 回到基准，只把 Direction 改成 `(0,1,0,0)`，预测并观察沿 Y 移动。

**什么时候继续深入：** 想让方向只负责朝向，让距离由一个参数单独决定时，进入 [N02：归一化](N02-让方向只负责朝向.md)。
