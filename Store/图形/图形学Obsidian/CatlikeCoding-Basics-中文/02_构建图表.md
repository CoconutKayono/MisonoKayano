## 创建一排方块

编程时，对数学的良好理解至关重要。在最基础的层面上，数学就是「对代表数字的符号进行操纵」。解方程归结为：把一组符号改写成另一组——通常是更短的——符号。数学规则规定了这种改写如何进行。

例如，我们有函数 `f(x)=x+1`。我们可以用一个数字代入它的 `x` 参数，比如 3。这得到 `f(3)=3+1=4`。我们把 3 作为输入实参，最后得到 4 作为输出。我们可以说这个函数把 3 映射到 4。写得更短些，就是一个「输入-输出」对，比如 (3,4)。我们可以创建很多形如 `(x,f(x))` 的对，例如 (5,6)、(8,9)、(1,2)、(6,7)。但是当我们按输入数字排序这些对时，函数更容易理解：(1,2)、(2,3)、(3,4)……依此类推。

函数 `f(x)=x+1` 很容易理解。$f(x)=(x-1)^4+5x^3-8x^2+3x$ 就难多了。我们可以写出几个输入-输出对，但这多半无法让我们很好地把握它所表示的映射。我们需要很多彼此靠近的点，最后会变成一片难以解析的数字海洋。相反，我们可以把这些对解释为形如 `[[x],[f(x)]]` 的二维坐标。这是一个 2D 向量，上面的数字表示水平坐标（X 轴），下面的数字表示垂直坐标（Y 轴）。换句话说，`y = f(x)`。我们可以在平面上绘制这些点。如果使用的点足够多、彼此足够靠近，我们最终会得到一条线。结果就是一个图表。

![`x` 在 −2 到 2 之间的图表，用 Desmos 绘制。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/graph.png)

看一看图表，就能快速了解函数的行为。这是个好用的工具，所以让我们在 Unity 里创建一个。我们从新建项目开始，和[上一篇教程](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/)第一节描述的一样。

### 预制体

图表是通过在适当的坐标处放置点来创建的。为此，我们需要一个点的 3D 可视化。我们直接用 Unity 默认的立方体游戏对象即可。往场景里加一个，命名为 *Point*。移除它的 `BoxCollider` 组件，因为我们用不到物理。

> **方块是可视化图表最好的方式吗？**
>
> 你也可以用粒子系统或线段，但单个方块最简单易用。

我们将用一个自定义组件来创建这个立方体的许多实例，并把它们放在正确的位置。为此，我们要把立方体变成一个游戏对象模板。把立方体从层级窗口拖到项目窗口，这会创建一个新资源，称为预制体（prefab）。它是一个预先制作好的游戏对象，存在于项目中，而非场景里。

![Point 预制体资源，单列和双列布局。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/prefab-project-one-column.png)

我们用来创建预制体的游戏对象仍然在场景里，但现在它是一个预制体实例（prefab instance）。它在层级窗口里有一个蓝色图标，右侧有一个箭头。它检视窗口的头部也表明它是一个预制体，并显示几个额外的控件。位置和旋转现在用粗体显示，表示该实例的值覆盖了预制体的值。你对实例做的其他更改也会以这种方式表示。

![Point 预制体实例。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/prefab-instance-hierarchy.png)

选中预制体资源时，它的检视窗口会显示它的根游戏对象和一个用于打开预制体的大按钮。

![预制体资源检视窗口。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/prefab-inspector.png)

点击 *Open Prefab* 按钮会让场景窗口显示一个只包含该预制体对象层级的场景。你也可以通过实例的 *Open* 按钮、层级窗口里实例右侧的箭头，或在项目窗口里双击该资源来进入。当预制体层级复杂时这很有用，但对我们简单的点预制体来说不是这样。

![我们预制体的层级窗口。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/prefab-hierarchy.png)

你可以通过层级窗口里它名字左侧的箭头退出预制体场景。

> **为什么预制体场景的背景是统一的深蓝色？**
>
> 如果你打开的是场景里某个预制体实例，那么场景窗口会根据窗口顶部显示的 *Context* 设置来显示它的周围环境。如果你打开的是预制体资源，那就没有上下文。对于资源，预制体场景默认禁用了天空盒，还有其他一些东西。你可以通过场景窗口的工具栏来配置它，就像配置普通场景窗口一样。天空盒可以通过那个「带星号的层叠」样式的下拉菜单来切换。注意观察：当你进出预制体资源模式时，场景工具栏设置是如何变化的。

预制体是配置游戏对象的一种便捷方式。如果你修改预制体资源，所有场景里它的实例都会以相同方式改变。例如，修改预制体的缩放也会改变仍在场景里的那个立方体的缩放。不过，每个实例使用自己的位置和旋转。而且，游戏对象实例可以被修改，从而覆盖预制体的值。注意，在播放模式下，预制体和实例之间的关系会断开。

我们将用脚本来创建预制体实例，这意味着我们不再需要当前场景里的那个预制体实例。所以删掉它，通过 *Edit / Delete*、相应的键盘快捷键，或层级窗口里它的右键菜单。

### Graph 组件

我们需要一个 C# 脚本来用点预制体生成图表。创建一个，命名为 `Graph`。

![Scripts 文件夹里的 Graph C# 资源。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/graph-asset.png)

我们从一个扩展了 `MonoBehaviour` 的简单类开始，这样它就能用作游戏对象的组件。给它一个可序列化字段，用于持有对预制体的引用以实例化点，命名为 `pointPrefab`。我们需要访问 `Transform` 组件来定位这些点，所以把字段类型设为 `Transform`。

```diff
+using UnityEngine;

+public class Graph : MonoBehaviour {

+	[SerializeField]
+	Transform pointPrefab;
+}
```

往场景里加一个空游戏对象，命名为 *Graph*。确保它的位置和旋转都是零，缩放为 1。把我们的 `Graph` 组件添加到这个对象上。然后把预制体资源拖到图表的 *Point Prefab* 字段上。现在它持有了对预制体 `Transform` 组件的引用。

![带预制体引用的 Graph 游戏对象。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/graph-with-prefab.png)

### 实例化预制体

实例化一个游戏对象是通过 `Object.Instantiate` 方法来完成的。这是 Unity `Object` 类型的一个公开方法，`Graph` 通过扩展 `MonoBehaviour` 间接继承了这个类型。`Instantiate` 方法克隆作为参数传给它的任何 Unity 对象。对于预制体，结果就是一个实例被添加到当前场景中。让我们在 `Graph` 组件苏醒时做这件事。

```diff
public class Graph : MonoBehaviour {

	[SerializeField]
	Transform pointPrefab;

+	void Awake () {
+		Instantiate(pointPrefab);
+	}
}
```

> **MonoBehaviour 的完整继承链是什么？**
>
> `MonoBehaviour` 扩展 `Behaviour`，`Behaviour` 扩展 `Component`，`Component` 扩展 `Object`。

如果我们现在进入播放模式，*Point* 预制体的一个实例会在世界原点生成。它的名字和预制体相同，末尾附加了 *(Clone)*。

![实例化的预制体，在场景窗口里沿 Z 轴观察。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/instantiated-prefab.png)

> **你能在播放模式下打开场景窗口吗？**
>
> 可以，但进入播放模式时，Unity 总是把游戏窗口强制放到前台。如果游戏窗口和场景窗口共享一个面板，那个场景窗口就会被隐藏。但你可以在播放模式下切回场景窗口。另外，你可以配置编辑器布局，让一个或多个游戏窗口和场景窗口同时可见。记住，Unity 必须渲染所有这些窗口，所以打开得越多，速度就越慢。

要把点放到别处，我们需要调整实例的位置。`Instantiate` 方法会给我们一个对它创建之物的引用。因为我们传给它的是一份 `Transform` 组件引用，所以返回的也是它。让我们用一个变量跟踪它。

```diff
	void Awake () {
+		Transform point = Instantiate(pointPrefab);
	}
```

在[上一篇教程](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/)里，我们通过给枢轴 `Transform` 的 `localRotation` 属性赋一个四元数来旋转时钟指针。改变位置的方式相同，只是我们必须给 `localPosition` 属性赋一个 3D 向量。

3D 向量用 `Vector3` 结构体类型创建。例如，让我们把点的 X 坐标设为 1，Y 和 Z 坐标保持为零。`Vector3` 有一个 `right` 属性，能给我们这样一个向量。用它来设置点的位置。

```diff
		Transform point = Instantiate(pointPrefab);
+		point.localPosition = Vector3.right;
```

![右移一个单位的方块。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/one-unit-to-the-right.png)

现在进入播放模式，我们仍然得到一个方块，只是位置略有不同。让我们再实例化一个，并把它再往右放一步。这可以通过把 `right` 向量乘以 2 来实现。重复实例化和定位，然后把乘法加到新代码里。

```diff
	void Awake () {
		Transform point = Instantiate(pointPrefab);
		point.localPosition = Vector3.right;

+		Transform point = Instantiate(pointPrefab);
+		point.localPosition = Vector3.right * 2f;
	}
```

> **我们能对结构体和数字做乘法吗？**
>
> 通常不能，但可以定义这样的功能。做法是用一种特殊语法创建一个方法，让它能像乘法一样被调用。这里，看起来是简单乘法的东西，实际上是一次方法调用，类似 `Vector3.Multiply(Vector3.right, 2f)`。结果是这样一个向量：它等于 `right` 向量的所有分量都翻倍。
>
> 能够像简单运算一样使用方法，能让写代码更快、更易读。它不是必需的，但很好用，就像能隐式使用命名空间一样。这种便捷的语法被称为语法糖（syntactic sugar）。
>
> 话虽如此，只有当方法严格匹配原运算符的含义时，才应该把方法当作运算符使用。对于向量，一些数学运算符是明确定义的，所以用在那些地方没问题。

这段代码会产生编译错误，因为我们试图定义 `point` 变量两次。如果我们想用另一个变量，必须给它起不同的名字。或者，我们复用已有的变量。用完第一个点后，我们不需要保留它的引用了，所以把新点赋给同一个变量。

```diff
		Transform point = Instantiate(pointPrefab);
		point.localPosition = Vector3.right;

-//		Transform point = Instantiate(pointPrefab);
+		point = Instantiate(pointPrefab);
		point.localPosition = Vector3.right * 2f;
```

![两个实例，X 坐标为 1 和 2。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/two-instances.png)

### 代码循环

让我们创建更多点，直到有十个。我们可以把同样的代码再重复八遍，但那会是非常低效的编程。理想情况下，我们只为一个点写代码，然后指示程序多次执行它，每次略有变化。

`while` 语句可以让一个代码块重复执行。把它应用到我们方法的前两条语句上，并移除其他语句。

```diff
	void Awake () {
+		while {
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right;
+		}
-//		point = Instantiate(pointPrefab);
-//		point.localPosition = Vector3.right * 2f;
	}
```

`while` 关键字后面必须跟一个放在圆括号里的表达式。只有当表达式求值为真（true）时，`while` 后面的代码块才会执行。之后，程序会循环回 `while` 语句。如果此时表达式再次求值为真，代码块就会再次执行。这会一直重复，直到表达式求值为假（false）。然后程序跳过 `while` 语句后面的代码块，继续往下执行。

所以我们必须在 `while` 后面加一个表达式。我们必须小心，确保循环不会永远重复。无限循环会导致程序卡死，需要用户手动终止。能编译通过的最安全表达式就是 `false`。

```diff
		while (false) {
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right;
		}
```

> **我们能在循环里定义 point 吗？**
>
> 可以。虽然代码会被重复，但我们只定义了一次变量。它在循环的每次迭代中被复用，就像我们之前手动做的那样。
>
> 你也可以在循环前定义 `point`。这样你也能在循环外使用这个变量。否则，它的作用域仅限于 `while` 循环的代码块。

限制循环可以通过跟踪我们重复了多少次代码来实现。我们可以用一个整数变量来跟踪。它的类型是 `int`。它会包含循环的迭代次数，所以命名为 `i`。它的初始值是零。为了能在 `while` 表达式里使用它，它必须定义在表达式之上。

```diff
+		int i = 0;
		while (false) {
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right;
		}
```

每次迭代，把这个数字加一，方法是将它设为自己加 1。

```diff
		int i = 0;
		while (false) {
+			i = i + 1;
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right;
		}
```

现在 `i` 在第一次迭代开始时变成 1，第二次迭代开始时变成 2，依此类推。但 `while` 表达式是在每次迭代之前求值的。所以恰好在第一次迭代之前 `i` 是零，第二次之前是 1，依此类推。所以在第十次迭代之后 `i` 是十。此时我们想停止循环，所以它的表达式应该求值为假。换句话说，只要 `i` 小于十，我们就应该继续。数学上表示为 `i < 10`。代码里也这么写，用 `<` 小于运算符。

```diff
		int i = 0;
		while (i < 10) {
			i = i + 1;
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right;
		}
```

现在进入播放模式后，我们会得到十个方块。但它们都落在同一位置。要沿 X 轴把它们排成一行，把 `right` 向量乘以 `i`。

```diff
			point.localPosition = Vector3.right * i;
```

![沿 X 轴排成一行的十个方块。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/ten-cubes.png)

注意，目前第一个方块的 X 坐标是 1，最后一个方块的 X 坐标是 10。让我们改成从零开始，把第一个方块放在原点。我们可以通过把 `right` 乘以 `(i - 1)` 而不是 `i`，让所有点左移一个单位。不过，我们可以把 `i` 的递增移到代码块末尾、乘法之后，而不是开头，从而省掉那次额外的减法。

```diff
		while (i < 10) {
-//			i = i + 1;
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right * i;
+			i = i + 1;
		}
```

### 简洁语法

因为循环一定次数太常见了，所以让循环代码保持简洁会很方便。一些语法糖能帮到我们。

首先，考虑迭代次数的递增。当执行形如 `x = x * y` 的运算时，可以缩写为 `x *= y`。这对所有作用于两个操作数的运算符都有效。

```diff
-//			i = i + 1;
+			i += 1;
```

更进一步，当把一个数加 1 或减 1 时，可以缩写为 `++x` 或 `--x`。

```diff
-//			i += 1;
+			++i;
```

赋值语句的一个特性是，它们也可以用作表达式。这意味着你可以写 `y = (x += 3)` 这样的东西。那会让 `x` 加三，并把结果也赋给 `y`。这提示我们可以在 `while` 表达式里递增 `i`，从而缩短代码块。

```diff
		while (++i < 10) {
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right * i;
-//			++i;
		}
```

不过，现在我们是在比较之前递增 `i`，而不是之后，这会导致少一次迭代。专门针对这种情况，递增和递减运算符也可以放在变量之后，而不是之前。那个表达式的结果是改变之前的原值。

```diff
-//		while (++i < 10) {
+		while (i++ < 10) {
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right * i;
		}
```

虽然 `while` 语句适用于所有类型的循环，但有一种替代语法特别适合遍历范围，那就是 `for` 循环。它的工作方式和 `while` 一样，只是迭代变量的声明和它的比较都放在圆括号里，用分号隔开。

```diff
-//		int i = 0;
-//		while (i++ < 10) {
+		for (int i = 0; i++ < 10) {
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right * i;
		}
```

那会产生编译错误，因为还有第三部分用于递增迭代器，在另一个分号之后，与比较部分分开。这部分在每次迭代结束时执行。

```diff
-//		for (int i = 0; i++ < 10) {
+		for (int i = 0; i < 10; i++) {
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right * i;
		}
```

> **为什么在 for 循环里用 i++ 而不是 ++i？**
>
> 因为递增表达式不被用于任何其他地方，用哪个版本都无所谓。我们也可以用 `i += 1` 或 `i = i + 1`。
>
> 经典 for 循环的形式是 `for (int i = 0; i < someLimit; i++)`。你会在很多程序和脚本里遇到这个代码片段。

### 改变定义域

目前，我们的点被赋予 X 坐标 0 到 9。在处理函数时，这个范围不太方便。通常 X 用 0–1 的范围。或者在处理以零为中心的函数时，用 −1–1 的范围。让我们相应地重新定位这些点。

把十个方块放在一条两单位长的线段上会让它们重叠。为了防止这一点，我们要减小它们的缩放。每个方块默认在每个维度上大小为 1，所以为了让它们能装下，我们必须把缩放减小到 `2/10 = 1/5`。我们可以把每个点的本地缩放设为 `Vector3.one` 属性除以五。除法用 `/` 斜杠运算符。

```diff
		for (int i = 0; i < 10; i++) {
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right * i;
+			point.localScale = Vector3.one / 5f;
		}
```

把场景窗口切换到正交投影（orthographic projection），可以更好地观察方块的相对位置，正交投影忽略透视。点击场景窗口右上角坐标轴小部件下方的标签，可以在正交和透视模式之间切换。如果你通过场景窗口工具栏关掉天空盒，白色方块也更容易看清。

![小方块，在无天空盒的正交场景窗口中观察。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/small-cubes.png)

要再把方块聚拢回来，把它们的位移也除以五。

```diff
			point.localPosition = Vector3.right * i / 5f;
```

这让它们覆盖 0–2 的范围。要把它变成 −1–1 的范围，在缩放向量之前先减 1。用圆括号表示数学表达式的运算顺序。

```diff
			point.localPosition = Vector3.right * (i / 5f - 1f);
```

![从 −1 到 0.8。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/from-1-to-08.png)

现在第一个方块的 X 坐标是 −1，最后一个方块的 X 坐标是 0.8。然而，方块大小是 0.2。因为方块以它的位置为中心，第一个方块的左侧在 −1.1，最后一个方块的右侧在 0.9。要用方块整齐地填满 −1–1 的范围，我们必须把它们右移半个方块。这可以通过在 `i` 除以五之前给它加 0.5 来实现。

```diff
			point.localPosition = Vector3.right * ((i + 0.5f) / 5f - 1f);
```

![填满 −1–1 的范围。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/from-1-to-1.png)

### 把向量提出循环

虽然所有方块的缩放相同，但我们每次循环迭代都会重新计算它。我们不必这么做，缩放是不变的。相反，我们可以在循环前计算一次，存进一个 `scale` 变量，然后在循环里使用它。

```diff
	void Awake () {
+		var scale = Vector3.one / 5f;
		for (int i = 0; i < 10; i++) {
			Transform point = Instantiate(pointPrefab);
			point.localPosition = Vector3.right * ((i + 0.5f) / 5f - 1f);
			point.localScale = scale;
		}
	}
```

我们也可以在循环前为位置定义一个变量。因为我们沿 X 轴创建一条线，只需要在循环里调整位置的 X 坐标。这样我们就不再需要乘以 `Vector3.right`。

```diff
+		Vector3 position;
		var scale = Vector3.one / 5f;
		for (int i = 0; i < 10; i++) {
			Transform point = Instantiate(pointPrefab);
-			//point.localPosition = Vector3.right * ((i + 0.5f) / 5f - 1f);
+			position.x = (i + 0.5f) / 5f - 1f;
+			point.localPosition = position;
			point.localScale = scale;
		}
```

> **我们能单独修改向量的分量吗？**
>
> `Vector3` 结构体有三个浮点字段：`x`、`y` 和 `z`。这些字段是公开的，所以我们可以修改它们。
>
> 因为结构体的行为像简单值，所以理想上它们应该是不可变的（immutable）。一旦构造出来，就不应该改变。如果你想用不同的值，就给字段或变量赋一个新的结构体，就像我们对数字做的那样。如果我们说 `x = 3`，然后又说 `x = 5`，我们是给 `x` 赋了另一个数字。我们没有把数字 3 本身改成 5。然而，Unity 的向量类型是可变的（mutable）。这样做既是为了方便，也是为了性能，因为向量分量经常被单独操纵。
>
> 要理解如何操作可变向量，你可以把 `Vector3` 的使用看作「用三个独立 `float` 值的便捷替代」。你可以独立访问它们，也可以整组复制和赋值。

这会导致编译错误，抱怨使用了未赋值的变量。这是因为我们把 `position` 赋给了某个东西，却还没设置它的 Y 和 Z 坐标。我们可以先把 `position` 设为零向量来修复，做法是把 `Vector3.zero` 赋给它。

```diff
-		//Vector3 position;
+		var position = Vector3.zero;
		var scale = Vector3.one / 5f;
```

### 用 X 定义 Y

思路是，我们方块的位置被定义为 `[[x],[f(x)],[0]]`，这样就能用它们来显示函数。此时 Y 坐标总是零，表示平凡函数 `f(x) = 0`。要显示不同的函数，我们必须在循环里、而不是循环之前确定 Y 坐标。让我们先让 Y 等于 X，表示函数 `f(x)=x`。

```diff
		for (int i = 0; i < 10; i++) {
			Transform point = Instantiate(pointPrefab);
			position.x = (i + 0.5f) / 5f - 1f;
+			position.y = position.x;
			point.localPosition = position;
			point.localScale = scale;
		}
```

![Y 等于 X。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/y-equals-x.png)

一个稍微不那么显然的函数是 `f(x)=x^2`，它定义了一条最小值在零处的抛物线（parabola）。

```diff
			position.y = position.x * position.x;
```

![Y 等于 X 的平方。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-a-line-of-cubes/y-equals-x-squared.png)

## 创建更多方块

虽然此时我们有了一个能用的图表，但它很丑。因为我们只用了十个方块，暗示出的线看起来很块状、很离散。如果用更多、更小的方块会好看得多。

### 可调的分辨率

与其用固定数量的方块，不如让它可配置。为此，给 `Graph` 添加一个可序列化的整数字段，用于分辨率，命名为 `resolution`。给它一个默认值 10，也就是我们现在用的值。

```diff
	[SerializeField]
	Transform pointPrefab;

+	[SerializeField]
+	int resolution = 10;
```

![可配置的分辨率。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-more-cubes/configurable-resolution.png)

现在我们可以通过检视窗口修改分辨率来调整图表。不过，并非所有整数都是有效的分辨率，至少要为正。我们可以指示检视窗口为我们的分辨率强制一个范围。做法是给它附加 `Range` 特性。我们可以把 `resolution` 的两个特性各自放在方括号里，也可以把它们合并成一个逗号分隔的特性列表。让我们用后者。

```diff
	[SerializeField, Range]
	int resolution = 10;
```

检视窗口会检查一个字段是否附加了 `Range` 特性。如果有，它就会约束值并显示一个滑块。不过，为此它需要知道允许的范围。所以 `Range` 需要两个参数——就像方法一样——表示最小值和最大值。让我们用 10 和 100。

```diff
	[SerializeField, Range(10, 100)]
	int resolution = 10;
```

![设为 50 的分辨率滑块。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-more-cubes/resolution-slider.png)

> **这能保证 resolution 被限制在 10–100 吗？**
>
> `Range` 特性所做的全部事情，就是指示检视窗口用那个范围的滑块。它不会以任何其他方式影响 `resolution`。所以我们可以写代码给它赋一个超出范围的值，但我们不会那么做。

### 可变实例化

要利用配置好的分辨率，我们必须改变实例化多少个方块。在 `Awake` 里，不再是循环固定次数，迭代次数现在由 `resolution` 约束，而不是总是 `10`。所以如果分辨率设为 50，进入播放模式后我们会得到 50 个方块。

```diff
		for (int i = 0; i < resolution; i++) {
			…
		}
```

> **`…` 是什么意思？**
>
> 它表示我省略了一些没有变化的代码。

我们还必须调整方块的缩放和位置，让它们保持在 −1–1 的定义域内。每次迭代要走的步长现在是二除以分辨率。把这个值存进一个变量，用它来计算方块的缩放和它们的 X 坐标。

```diff
+		float step = 2f / resolution;
		var position = Vector3.zero;
		var scale = Vector3.one * step;
		for (int i = 0; i < resolution; i++) {
			Transform point = Instantiate(pointPrefab);
			position.x = (i + 0.5f) * step - 1f;
			…
		}
```

![使用分辨率 50。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-more-cubes/resolution-50.png)

### 设置父对象

以分辨率 50 进入播放模式后，场景里会出现大量实例化的方块，项目窗口里也是如此。

![这些点是根对象。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-more-cubes/many-root-objects.png)

这些点目前是根对象，但让它们成为图表对象的子对象更合理。我们可以在实例化一个点之后，通过调用它 `Transform` 组件的 `SetParent` 方法来建立这种关系，把期望的父 `Transform` 传给它。我们可以通过 `Graph` 的 `transform` 属性（从 `Component` 继承而来）获取图表对象的 `Transform` 组件。在循环代码块的末尾做这件事。

```diff
		for (int i = 0; i < resolution; i++) {
			…
+			point.SetParent(transform);
		}
```

![这些点是图表的子对象。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/creating-more-cubes/child-objects.png)

当设置新父对象时，Unity 会尝试让对象保持它原来的世界位置、旋转和缩放。我们这里不需要这样。我们可以给 `SetParent` 传 `false` 作为第二个参数来表明这一点。

```diff
			point.SetParent(transform, false);
```

## 给图表上色

白色的图表不好看。我们可以用另一种纯色，但那也没意思。更有趣的是用点的位置来决定它的颜色。

一种直接调整每个方块颜色的方法，是设置它材质的颜色属性。我们可以在循环里做。因为每个方块颜色不同，这意味着我们最终会为每个对象得到一份独特的材质实例。而且之后让图表动起来时，我们还得一直调整这些材质。虽然可行，但效率不高。如果能用一个材质，直接使用位置作为颜色，那就好得多。可惜 Unity 没有这样的材质。所以我们自己做一个。

### 创建表面着色器

GPU 运行着色器（shader）程序来渲染 3D 对象。Unity 的材质资源决定使用哪个着色器，并允许配置它的属性。我们需要创建一个自定义着色器来获得我们想要的功能。通过 *Assets / Create / Shader / Standard Surface Shader* 创建一个，命名为 *Point Surface*。

![着色器和预制体一起放在 Point 文件夹里，单列和双列布局。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/point-surface-one-column.png)

现在我们有了一个着色器资源，可以像脚本一样打开它。我们的着色器文件包含定义表面着色器（surface shader）的代码，它使用的语法和 C# 不同。它包含一个表面着色器模板，但我们会删掉一切，从零开始创建一个最小的着色器。

> **表面着色器是如何工作的？**
>
> Unity 提供了一个框架，用来快速生成执行默认光照计算的着色器，你可以通过调整某些值来影响它。这样的着色器被称为表面着色器。遗憾的是，它们只适用于默认渲染管线。我们稍后会讲通用渲染管线。

Unity 对着色器资源有自己的语法，总体上大致像 C#，但它是多种语言的混合。它以 `Shader` 关键字开头，后面跟一个定义着色器菜单项的字符串。字符串写在双引号里。我们用 *Graph/Point Surface*。之后是一个用于着色器内容的代码块。

```diff
+Shader "Graph/Point Surface" {}
```

着色器可以有多个子着色器（sub-shader），每个由 `SubShader` 关键字后跟一个代码块定义。我们只需要一个。

```diff
Shader "Graph/Point Surface" {

+	SubShader {}
}
```

在子着色器下面，我们还想添加一个对标准漫反射着色器的回退（fallback），写法是 `FallBack "Diffuse"`。

```diff
Shader "Graph/Point Surface" {

	SubShader {}

+	FallBack "Diffuse"
}
```

表面着色器的子着色器需要一个用 CG 和 HLSL 两种着色器语言的混合体编写的代码段。这段代码必须用 `CGPROGRAM` 和 `ENDCG` 关键字括起来。

```diff
	SubShader {
+		CGPROGRAM
+		ENDCG
	}
```

第一条需要的语句是一条编译器指令，称为 pragma。它写成 `#pragma` 后跟指令。这里我们需要 `#pragma surface ConfigureSurface Standard fullforwardshadows`，它指示着色器编译器生成一个带标准光照、完全支持阴影的表面着色器。`ConfigureSurface` 指的是用于配置着色器的方法，我们稍后要创建它。

```diff
		CGPROGRAM
+		#pragma surface ConfigureSurface Standard fullforwardshadows
		ENDCG
```

> **pragma 是什么意思？**
>
> pragma 这个词来自希腊语，指一个动作或需要完成的事。它在许多编程语言里用于发出特殊的编译器指令。

接着是 `#pragma target 3.0` 指令，它设定了着色器目标级别和质量的下限。

```diff
		CGPROGRAM
		#pragma surface ConfigureSurface Standard fullforwardshadows
+		#pragma target 3.0
		ENDCG
```

我们将基于世界位置给点着色。要让这在表面着色器里生效，我们必须为配置函数定义输入结构体。它必须写成 `struct Input`，后跟一个代码块，再加一个分号。在代码块里，我们声明一个结构体字段，具体是 `float3 worldPos`。它会包含被渲染之物的世界位置。`float3` 类型是着色器里 `Vector3` 结构体的等价物。

```diff
		CGPROGRAM
		#pragma surface ConfigureSurface Standard fullforwardshadows
		#pragma target 3.0

+		struct Input {
+			float3 worldPos;
+		};
		ENDCG
```

> **这是否意味着移动图表会影响它的颜色？**
>
> 是的。用这种方法，只有当我们把 *Graph* 对象留在原处——世界原点、无旋转、缩放为 1——着色才是正确的。
>
> 还要注意，这个位置是按顶点（vertex）确定的。我们这里就是方块每个角。颜色会跨方块的各个面插值。方块越大，颜色过渡越明显。

在那下面，我们定义 `ConfigureSurface` 方法，不过在着色器里它总是被称为函数（function），而不是方法。它是一个带两个参数的 `void` 函数。第一个是输入参数，类型是我们刚定义的 `Input`。第二个参数是表面配置数据，类型为 `SurfaceOutputStandard`。

```diff
		struct Input {
			float3 worldPos;
		};

+		void ConfigureSurface (Input input, SurfaceOutputStandard surface) {}
```

第二个参数必须在它的类型前写 `inout` 关键字，表示它既被传入函数，也用于函数的结果。

```diff
		void ConfigureSurface (Input input, inout SurfaceOutputStandard surface) {}
```

现在我们有了一个能工作的着色器，为它创建一个材质，命名为 *Point Surface*。让它使用我们的着色器：在它检视窗口头部的 *Shader* 下拉列表里选择 *Graph / Point Surface*。

![Point Surface 材质。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/point-surface-material.png)

材质目前是纯哑光黑。我们可以在配置函数里把 `surface.Smoothness` 设为 0.5，让它看起来更像默认材质。写着色器代码时，我们不必给 `float` 值加 `f` 后缀。

```diff
		void ConfigureSurface (Input input, inout SurfaceOutputStandard surface) {
+			surface.Smoothness = 0.5;
		}
```

现在材质不再是完全哑光的了。你可以在检视窗口头部的材质小预览图里看到，也可以在它底部可调整大小的预览图里看到。

![中等光滑度的材质预览。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/material-preview.png)

我们也可以让光滑度可配置，就像为它添加一个字段并在函数里使用一样。默认风格是给着色器配置选项加下划线前缀，并把下一个字母大写，所以用 `_Smoothness`。

```diff
+		float _Smoothness;

		void ConfigureSurface (Input input, inout SurfaceOutputStandard surface) {
			surface.Smoothness = _Smoothness;
		}
```

要让这个配置选项出现在编辑器里，我们必须在着色器顶部、子着色器之上添加一个 `Properties` 代码块。在里面写 `_Smoothness`，后跟 `("Smoothness", Range(0,1)) = 0.5`。这给了它 *Smoothness* 标签，把它暴露为 0–1 范围的滑块，并把默认值设为 0.5。

```diff
Shader "Graph/Point Surface" {

+	Properties {
+		_Smoothness ("Smoothness", Range(0,1)) = 0.5
+	}

	SubShader {
		…
	}
}
```

![可配置的光滑度。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/configurable-smoothness.png)

让我们的 *Cube* 预制体资源使用这个材质，而不是默认材质。这会把点变成黑色。

![黑色的点。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/black-points.png)

### 基于世界位置上色

要调整点的颜色，我们必须修改 `surface.Albedo`。因为反照率和世界位置都有三个分量，我们可以直接把位置用作反照率。

```diff
		void ConfigureSurface (Input input, inout SurfaceOutputStandard surface) {
+			surface.Albedo = input.worldPos;
			surface.Smoothness = _Smoothness;
		}
```

![彩色的点。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/colored-points.png)

> **反照率（albedo）是什么意思？**
>
> Albedo 在拉丁语里意为「白度」。它是表面漫反射光多少的度量。如果反照率不是纯白，那么一部分光能就会被吸收而不是被反射。

现在世界 X 位置控制点颜色的红色分量，Y 位置控制绿色分量，Z 控制蓝色分量。但我们图表的 X 定义域是 −1–1，负的颜色分量没有意义。所以我们必须把位置减半，再加 ½，让颜色适应定义域。我们可以对三个维度一次性做完。

```diff
			surface.Albedo = input.worldPos * 0.5 + 0.5;
```

为了更好地判断颜色是否正确，让我们修改 `Graph.Awake`，显示函数 `f(x)=x^3`，它让 Y 也从 −1 变到 1。

```diff
			position.y = position.x * position.x * position.x;
```

![X 的立方，偏蓝。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/x-cubed.png)

结果是偏蓝的，因为所有方块面的 Z 坐标都接近零，这会把它们的蓝色分量设为接近 0.5。我们可以通过只把红绿通道包含进反照率来消除蓝色。在着色器里，可以只给 `surface.Albedo.rg` 赋值，并只用 `input.worldPos.xy`。这样蓝色分量保持为零。

```diff
			surface.Albedo.rg = input.worldPos.xy * 0.5 + 0.5;
```

因为红加绿得到黄，这会让点从左下角接近黑色开始，随着 Y 起初比 X 增长更快而变绿，随着 X 追上来而变黄，随着 X 增长更快而略偏橙，最后在右上角接近亮黄。

![X 的立方，从绿到黄。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/x-cubed-green-yellow.png)

### 通用渲染管线

除了默认渲染管线，Unity 还有通用渲染管线和高清渲染管线，分别简称 URP 和 HDRP。两条渲染管线有不同的特性和限制。当前的默认渲染管线仍然能用，但它的功能集已冻结。几年后 URP 很可能成为默认。所以让我们让图表也能配合 URP 工作。

如果你还没用 URP，去包管理器安装你的 Unity 版本所验证的最新 *Universal RP* 包。我这里装的是 10.4.0。

![已安装 URP 包。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/urp-installed.png)

> **我在包管理器哪里能找到 URP？**
>
> 确保你把包过滤器设为 *Unity Registry* 而不是 *In Project*。然后搜索 *universal*，或向下滚动列表直到找到它。

这不会自动让 Unity 使用 URP。我们首先必须为它创建一个资源，通过 *Assets / Create / Rendering / Universal Render Pipeline / Pipeline Asset (Forward Renderer)*。我命名为 *URP*。这也会自动为渲染器创建另一个资源，我这里命名为 *URP_Renderer*。

![放在单独文件夹里的 URP 资源，单列和双列布局。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/urp-assets-one-column.png)

接下来，去项目设置的 *Graphics* 部分，把 URP 资源赋给 *Scriptable Renderer Pipeline Settings* 字段。

![使用 URP。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/urp-used.png)

以后要切回默认渲染管线，只需把 *Scriptable Renderer Pipeline Settings* 设为 *None*。这只能在编辑器里做，构建出的独立应用无法更改渲染管线。

> **HDRP 呢？**
>
> HDRP 是一条复杂得多的渲染管线。我不会在我的教程里讲它。

### 创建着色器图

我们当前的材质只适用于默认渲染管线，不适用于 URP。所以使用 URP 时，它会被替换成 Unity 的错误材质，即纯品红色。

![方块变成了品红色。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/error-material.png)

我们必须为 URP 创建一个单独的着色器。我们可以自己写一个，但那样目前非常难，而且升级到新版 URP 时很可能损坏。最好的办法是用 Unity 的着色器图（shader graph）包来可视化地设计着色器。URP 依赖这个包，所以它已经随 URP 包自动安装了。

通过 *Assets / Create / Shader / Universal Render Pipeline / Lit Shader Graph* 创建一个新的着色器图，命名为 *Point URP*。

![Point URP 着色器图资源，单列和双列布局。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/point-urp-one-column.png)

可以通过在项目窗口里双击它的资源，或按它检视窗口里的 *Open Shader Editor* 按钮来打开这个图。这会为它打开一个着色器图窗口，里面可能被多个节点和面板搞得杂乱。这些是黑板（blackboard）、图检视器和主预览面板，它们可以调整大小，也可以通过工具栏按钮隐藏。还有两个相连的节点：*Vertex* 节点和 *Fragment* 节点。这两个用于配置着色器图的输出。

![一切可见的默认 Lit 着色器图。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/default-lit-shader-graph.png)

着色器图由表示数据或运算的节点组成。目前，*Fragment* 节点的 *Smoothness* 值设为 0.5。要把它变成可配置的着色器属性，按 *Point URP* 黑板面板上的加号按钮，选择 *Float*，把新条目命名为 *Smoothness*。这会给黑板添加一个表示该属性的圆角按钮。选中它，把图检视器切到 *Node Settings* 标签页，查看这个属性的配置。

![带默认设置的 Smoothness 属性。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/smoothness-property-default.png)

*Reference* 是属性在内部被识别的名字。它对应我们在表面着色器代码里给属性字段命名 `_Smoothness` 的方式，所以这里也用同样的内部名字。然后把下面的默认值设为 0.5。确保它的 *Exposed* 开关处于启用状态，因为这决定材质是否为它生成一个着色器属性。最后，要让它显示为滑块，把它的 *Mode* 改为 *Slider*。

![已配置的 Smoothness 属性。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/smoothness-property-configured.png)

接下来，把圆角的 *Smoothness* 按钮从黑板拖到图里的空白处。那会给图添加一个光滑度节点。把它连接到 *PBR Master* 节点的 *Smoothness* 输入上，做法是从其中一个圆点拖到另一个。这会创建它们之间的连接。

![已连接的 Smoothness。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/smoothness-connected.png)

现在你可以通过 *Save Asset* 工具栏按钮保存这个图，并创建一个使用它的、名为 *Point URP* 的材质。着色器的菜单项是 *Shader Graphs / Point URP*。然后让 *Point* 预制体使用那个材质，而不是 *Point Surface*。

![使用我们着色器图的 URP 材质。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/point-urp-material.png)

### 用节点编程

要给点上色，我们必须从一个位置节点开始。在图里空白处打开右键菜单，选择 *New Node*，创建一个。选择 *Input / Geometry / Position*，或直接搜索 *Position*。

![世界位置节点。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/world-position-node.png)

现在我们有了一个位置节点，默认设为世界空间。你可以把光标悬停上去，按出现的向上箭头来折叠它的预览可视化。

用同样的方法创建一个 *Multiply* 和一个 *Add* 节点。用它们把位置的 XY 分量缩放 0.5，再加 0.5，同时把 Z 设为零。这些节点会根据它们连接到什么来调整输入类型。所以先连接节点，再填它们的常量输入。然后把结果连接到 *Fragment* 的 *Base Color* 输入。

![着色后的着色器图。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/colored-shader-graph.png)

你可以通过按 *Multiply* 和 *Add* 节点右上角（悬停时出现）的箭头来压缩它们的视觉尺寸。那会隐藏它们所有未连接到其他节点的输入和输出，去掉很多杂乱。你也可以通过 *Vertex* 和 *Fragment* 节点的右键菜单删除分量。这样就能隐藏所有保持默认值的东西。

![压缩后的着色器图。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/compacted-shader-graph.png)

保存着色器资源后，我们现在在播放模式下能得到和使用默认渲染管线时相同的彩色点。此外，播放模式里会出现一个调试更新器，在一个单独的 *DontDestroyOnLoad* 场景里。这是用于调试 URP 的，可以忽略。

![播放模式里的 URP 调试更新器。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/coloring-the-graph/urp-debug-updater.png)

从这点起，你可以用默认渲染管线或 URP。从一条切换到另一条后，你还必须更改 *Point* 预制体的材质，否则它会变成品红色。如果你好奇图生成的着色器代码，可以通过图检视器的 *View Generated Shader* 按钮查看。

## 让图表动起来

显示静态图表很有用，但动态图表看起来更有意思。所以让我们添加对动画函数的支持。做法是把时间作为额外的函数参数，用形如 `f(x,t)` 的函数而不是 `f(x)`，其中 `t` 是时间。

### 跟踪这些点

要让图表动起来，我们必须在时间推进时调整它的点。我们可以每帧删除所有点再创建新的，但那样效率很低。更好的做法是持续使用同样的点，每次更新调整它们的位置。为此，我们要用一个字段来持有对这些点的引用。给 `Graph` 添加一个 `Transform` 类型的 `points` 字段。

```diff
	[SerializeField, Range(10, 100)]
	int resolution = 10;

+	Transform points;
```

这个字段允许我们引用单个点，但我们需要访问所有点。我们可以通过在类型后放一对空方括号，把字段变成数组（array）。

```diff
	Transform[] points;
```

`points` 字段现在是对一个数组的引用，数组元素的类型是 `Transform`。数组是对象，不是简单值。我们必须显式创建这样一个对象，并让字段引用它。做法是写 `new` 后跟数组类型，我们这里就是 `new Transform[]`。在 `Awake` 里、循环之前创建数组，并把它赋给 `points`。

```diff
+		points = new Transform[];
		for (int i = 0; i < resolution; i++) {
			…
		}
```

创建数组时，我们必须指定它的长度。这定义了它有多少个元素，创建后不能改变。长度写在构造数组时的方括号里。让它等于图表的分辨率。

```diff
		points = new Transform[resolution];
```

现在我们可以用对点的引用填充数组。访问数组元素，是在数组引用后的方括号之间写下它的索引（index）。和循环的迭代计数器一样，数组索引从零开始表示第一个元素。所以我们可以用它给相应的数组元素赋值。

```diff
		points = new Transform[resolution];
		for (int i = 0; i < resolution; i++) {
			Transform point = Instantiate(pointPrefab);
+			points[i] = point;
			…
		}
```

如果我们连续多次赋同一个东西，可以把这些赋值串联起来，因为赋值表达式的结果就是被赋的值，就像上一篇教程里解释的那样。

```diff
			Transform point = points[i] = Instantiate(pointPrefab);
-			//points[i] = point;
```

我们现在在遍历点的数组。因为数组的长度和分辨率相同，我们也可以用长度来约束循环。每个数组都有一个 `Length` 属性用于此目的，所以用它。

```diff
		points = new Transform[resolution];
		for (int i = 0; i < points.Length; i++) {
			…
		}
```

### 更新这些点

要在每帧调整图表，我们需要在 `Update` 方法里设置点的 Y 坐标。这样我们就不再需要在 `Awake` 里计算它们。X 坐标仍可以在这里设置，因为我们不会改变它们。

```diff
		for (int i = 0; i < points.Length; i++) {
			Transform point = points[i] = Instantiate(pointPrefab);
			position.x = (i + 0.5f) * step - 1f;
-//			position.y = position.x * position.x * position.x;
			…
		}
```

添加一个 `Update` 方法，带一个和 `Awake` 一样的 `for` 循环，但代码块里还没有任何代码。

```diff
	void Awake () {
		…
	}

+	void Update () {
+		for (int i = 0; i < points.Length; i++) {}
+	}
```

循环的每次迭代开始时，我们先获取当前数组元素的引用并存入一个变量。

```diff
		for (int i = 0; i < points.Length; i++) {
+			Transform point = points[i];
		}
```

之后，我们取回点的本地位置，也存入一个变量。

```diff
		for (int i = 0; i < points.Length; i++) {
			Transform point = points[i];
+			Vector3 position = point.localPosition;
		}
```

现在我们可以像之前一样，基于 X 设置位置的 Y 坐标。

```diff
		for (int i = 0; i < points.Length; i++) {
			Transform point = points[i];
			Vector3 position = point.localPosition;
+			position.y = position.x * position.x * position.x;
		}
```

因为位置是结构体，我们只调整了局部变量的值。要把它应用到点上，必须重新设置它的位置。

```diff
		for (int i = 0; i < points.Length; i++) {
			Transform point = points[i];
			Vector3 position = point.localPosition;
			position.y = position.x * position.x * position.x;
+			point.localPosition = position;
		}
```

> **难道我们不能直接设置 point.localPosition.y 吗？**
>
> 如果 `localPosition` 是一个公开字段，那我们就能直接设置点位置的 Y 坐标。然而，`localPosition` 是一个属性（property）。它把向量值的一份副本传给我们，或把我们赋给它的东西复制进去。所以我们最终调整的是一个局部向量值，完全不影响点的位置。由于我们没有先把它显式存进变量，那个操作会毫无意义，并产生编译错误。

### 显示正弦波

从现在起，在播放模式下，我们图表的点每帧都会被重新定位。我们还注意不到这一点，因为它们总是落在相同的位置。我们必须把时间纳入函数，才能让它改变。不过，简单地把时间加进去会让函数上升并很快消失在视野外。为了防止这一点，我们必须用一个会变化但保持在固定范围内的函数。正弦函数是理想选择，所以我们用 `f(x)=sin(x)`。我们可以用 `Mathf.Sin` 方法来计算它。

```diff
			position.y = Mathf.Sin(position.x);
```

![X 的正弦，从 −1 到 1。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/animating-the-graph/sin-x.png)

> **Mathf 是什么？**
>
> 它是 `UnityEngine` 命名空间里的一个结构体，包含一组数学函数和常量。因为它处理浮点数，它的类型名被加了 *f* 后缀。

正弦波在 −1 和 1 之间振荡。它每 2π——读作「two pie」——个单位重复一次，也就是说它的周期大约是 6.28。因为我们图表的 X 坐标在 −1 到 1 之间，目前看到的重复图案不到三分之一。要看到它的全貌，把 X 缩放 π 倍，于是得到 `f(x)=sin(pix)`。我们可以用 `Mathf.PI` 常量作为 π 的近似值。

```diff
			position.y = Mathf.Sin(Mathf.PI * position.x);
```

![πX 的正弦。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/animating-the-graph/sin-pix.png)

> **什么是正弦波和 π？**
>
> 正弦是一个三角函数，作用于一个角度。我们这里最有用的例子是半径为 1 的圆，即单位圆。圆上每个点都有一个角度 `theta`——读作「theta」——以及一个 2D 位置。定义这些位置坐标的一种方式是 `[[sin(theta)],[sin(theta+pi/2)]]`。这表示从圆的顶部开始，沿顺时针方向绕行。除了 `sin(theta+pi/2)`，你也可以用余弦，得到 `[[sin(theta)],[cos(theta)]]`。
>
> ![πX 的正弦和余弦。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/animating-the-graph/sin-cos-pix.png)
>
> 角度 `theta` 以弧度（radian）表示，对应沿单位圆周走过的距离。走到一半时，走过的距离等于 π，大约 3.14。所以整个圆周的长度是 2π。换句话说，π 是圆的周长与其直径之比。

要给这个函数做动画，在计算正弦之前，把当前游戏时间加到 X 上。它通过 `Time.time` 获取。如果我们把时间也缩放 π 倍，函数就会每两秒重复一次。所以用 `f(x,t)=sin(pi(x+t))`，其中 `t` 是已流逝的游戏时间。这会随时间推进正弦波，把它向负 X 方向推移。

```diff
			position.y = Mathf.Sin(Mathf.PI * (position.x + Time.time));
```

动画中的正弦波。

因为 `Time.time` 的值对循环的每次迭代都相同，我们可以把属性调用提出循环外。

```diff
+		float time = Time.time;
		for (int i = 0; i < points.Length; i++) {
			Transform point = points[i];
			Vector3 position = point.localPosition;
			position.y = Mathf.Sin(Mathf.PI * (position.x + time));
			point.localPosition = position;
		}
```

### 钳制颜色

正弦波的振幅是 1，这意味着我们的点到达的最低和最高位置是 −1 和 1。然而，因为这些点是有大小的方块，它们会略微超出这个范围。这样我们可能得到负的或大于 1 的绿色分量。虽然这并不显眼，但让我们做得正确些，把颜色钳制（clamp）在 0–1 范围内。

对我们的表面着色器，可以通过把生成的颜色传入 `saturate` 函数来实现。这是一个特殊函数，把所有分量钳制到 0–1。这是着色器里的常见操作，称为饱和（saturation），函数也因此得名。

```diff
			surface.Albedo.rg = saturate(input.worldPos.xy * 0.5 + 0.5);
```

在着色器图里，可以用 *Saturate* 节点做同样的事。

![着色器图里饱和后的颜色。](https://catlikecoding.com/unity/tutorials/basics/building-a-graph/animating-the-graph/saturated-shader-graph.png)
