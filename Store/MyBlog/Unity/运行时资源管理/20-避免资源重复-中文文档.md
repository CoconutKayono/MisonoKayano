# 避免资源重复（Avoiding asset duplication）

> 来源：[Unity 6000.7 官方手册 · Avoiding asset duplication](https://docs.unity3d.com/6000.7/Documentation/Manual/assets-avoid-duplication.html)

资源重复发生在 Unity 递归跟随[直接引用](https://docs.unity3d.com/6000.7/Documentation/Manual/assets-direct-reference.html)以确保构建包含所有必需对象时。资源和场景不会在不同构建之间共享，因此相同的内容可能既出现在 Player 构建中，也出现在你使用 [AssetBundle](https://docs.unity3d.com/6000.7/Documentation/Manual/AssetBundles-Building.html) 或 [Addressables](https://docs.unity3d.com/Packages/com.unity.addressables@latest) 制作的内容专用构建中。对于小对象这也许不是问题，但对于纹理或网格等大型资源，这可能导致构建体积过大。

## 使用 AssetBundle 或 Addressables 尽量减少资源重复

要避免或尽量减少资源重复，你可以尽量减少进入 Player 构建的内容量，将所有内容放入 [AssetBundle](https://docs.unity3d.com/6000.7/Documentation/Manual/AssetBundlesIntro.html) 或 [Addressables](https://docs.unity3d.com/Packages/com.unity.addressables@latest) 中。

要创建最小化的 Player 构建，请只包含一个起始场景，其中包含一个使用 AssetBundle 或 Addressable API 引导其余内容加载的 MonoBehaviour。你还应该避免将任何资源放入 [Resources 文件夹](https://docs.unity3d.com/6000.7/Documentation/Manual/assets-resources-system.html)，如果它们也被内容专用构建引用的话。你可以使用 [StreamingAssets](https://docs.unity3d.com/6000.7/Documentation/Manual/StreamingAssets.html) 文件夹或托管在 CDN 上，将 AssetBundle 或 Addressable 构建的输出与 Player 构建一起分发。

## AssetBundle 中的资源重复

Unity 使用 [Asset Database](https://docs.unity3d.com/6000.7/Documentation/Manual/AssetDatabase.html) 在对象构建为 AssetBundle 时发现其所有依赖。Unity 使用此依赖信息确定要包含在 AssetBundle 中的对象集合。

AssetBundle 分配发生在资源级别。显式分配到 AssetBundle 的资源中的对象只包含在该特定 AssetBundle 中。根据所使用的 [BuildPipeline.BuildAssetBundles](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/BuildPipeline.BuildAssetBundles.html) 方法，资源通过以下方式显式分配：设置其 [AssetImporter.assetBundleName](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/AssetImporter.assetBundleName.html) 属性为非空字符串，或将其列在 [AssetBundleBuild.assetNames](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/AssetBundleBuild.assetNames.html) 中。

如果同一资源被不同 AssetBundle 引用，资源可能会在 AssetBundle 中重复。如果该资源没有显式分配到 AssetBundle，Unity 会将其内容复制到引用它的每个 AssetBundle 中。

例如，如果两个对象被分配到单独的 AssetBundle，但共享对同一个依赖对象的引用，Unity 会将依赖对象复制到两个 AssetBundle 中。这些重复的依赖也会被实例化，意味着两个副本被视为具有唯一标识符的不同对象。这会增加应用 AssetBundle 的整体体积，并且如果两个父 AssetBundle 都被加载，会导致对象的两份独立副本被加载到内存中。

为防止这种情况发生，请确保共享资源被显式分配到 AssetBundle。更多信息，请参阅[处理 AssetBundle 之间的依赖](https://docs.unity3d.com/6000.7/Documentation/Manual/AssetBundles-Dependencies.html)。[UnityDataTools](https://github.com/Unity-Technologies/UnityDataTools) 是识别 AssetBundle 中重复内容的有用工具。

Addressables 对隐式引用的资源也存在相同的重复问题。在这种情况下，你可以通过将[共享资源分配到组](https://docs.unity3d.com/Packages/com.unity.addressables@latest/?subfolder=/manual/Groups.html)来避免。Addressables 的 Analyze 工具有助于诊断和解决资源重复。
