# 在内容构建中包含场景（Include scenes in a content build）

> 来源：[Unity 6000.7 官方手册 · Include scenes in a content build](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-scenes.html)

Unity 会将 Build Profile 窗口的 [Scene List](https://docs.unity3d.com/6000.7/Documentation/Manual/build-profile-scene-list.html) 中的场景直接构建到 Player 构建中，而不是包含在内容构建中。Player 启动时，Unity 会自动加载列表中的第一个场景。

为了保持构建效率，请在 Scene List 中创建一个启动场景，作为访问内容目录构建中内容的入口。这种方法可以避免资源重复，并将所有内容保留在内容目录构建中。

这个单一启动场景通常包含一个或多个 MonoBehaviour 组件，它们在运行时注册内容目录，然后从其中加载一个或多个场景和其他初始内容。

## 在内容目录中包含场景

要在内容目录中包含场景，请使用 `LoadableSceneId`。你也可以使用此结构体从脚本和 Unity 编辑器中引用这些场景。

你可以在 MonoBehaviour 和 ScriptableObject 派生类中将 `LoadableSceneId` 用作字段类型。在编辑器中创作内容时，你可以通过 Inspector 或从脚本中为 `LoadableSceneId` 类型的字段分配场景。

```csharp
// Example of assigning a LoadableSceneId field from scripting
myMonoBehaviour.m_Scene = LoadableSceneIdEditorUtility.CreateLoadableSceneId(scenePath);
```

在内部，`LoadableSceneId` 使用 [Asset Database GUID](https://docs.unity3d.com/6000.7/Documentation/Manual/asset-database-contents.html) 作为场景的唯一标识符。这意味着即使你重命名场景资源或在项目中移动它，引用仍然有效。

当你构建内容目录时，Unity 会递归遍历根资源及其所有依赖，找到每个被 `LoadableSceneId` 引用的场景。Unity 会自动在构建输出中包含每个被引用的场景，并会深入每个场景，将其需要的任何其他依赖也纳入构建。因此，`LoadableSceneId` 引用不仅限于根资源，构建会包含从根资源可达的任何对象上由 `LoadableSceneId` 字段引用的任何场景。

在运行时和 Play 模式下，你可以将 `LoadableSceneId` 字段与 [SceneManager](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SceneManagement.SceneManager.html) [API](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SceneManagement.SceneManager.html) 一起使用来加载和卸载场景。加载场景之前，你必须先注册包含该场景的内容目录。有关注册内容目录的更多信息，请参阅[加载内容目录](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-load.html)。

> **注意**：[Loadable<T>](https://docs.unity3d.com/6000.7/Documentation/Manual/content-directories-references.html) 与场景不兼容，因为你的应用可能需要多次加载场景。`LoadableSceneId` 是 `LoadableObjectId`（用于资源）的场景对应物。

## 场景的运行时加载

要在 Player 或 Play 模式中加载场景，请调用以下方法：

```csharp
AsyncOperation SceneManager.LoadSceneAsync(Unity.Loading.LoadableSceneId, LoadSceneParameters);
```

该调用返回一个 `AsyncOperation` 实例，你可以用它跟踪异步加载。常见模式是订阅 `AsyncOperation.completed`，然后在回调中调用 [SceneManager.GetSceneByLoadableSceneId(loadableSceneId)](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SceneManagement.SceneManager.GetSceneByLoadableSceneId.html) 检索加载的 Scene。

你可以逐个加载场景，也可以通过 [LoadSceneParameters](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SceneManagement.LoadSceneParameters.html) [参数](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SceneManagement.LoadSceneParameters.html)叠加加载。在 Single 模式下，所有其他已打开的场景都会关闭。在 Additive 模式下，已经加载的场景保持打开。有关更多信息，请参阅 [SceneManagement.LoadSceneMode](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SceneManagement.LoadSceneMode.html)。

如果两个 `LoadableSceneId` 值引用同一个场景，并且你在 Additive 模式下对每个值调用 `LoadSceneAsync`，Unity 会将该场景加载两次，作为两个不同的场景实例。

要卸载场景，请调用 [UnloadSceneAsync](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SceneManagement.SceneManager.UnloadSceneAsync.html)。

例如，启动场景可以包含一个带有 `LoadableSceneId` 字段的 MonoBehaviour，这些字段引用其他场景。你可以在创作时在 Inspector 中分配场景，运行时脚本可以响应事件（如角色移动或按钮按下）加载和卸载场景。

以下示例在启动时叠加加载两个场景，并响应事件卸载其中一个：

```csharp
using System.Collections;
using UnityEngine;
using UnityEngine.SceneManagement;
using Unity.Loading;

public class SceneLoader : MonoBehaviour
{
    // Use the Inspector to assign scenes to these fields.
    [SerializeField]
    LoadableSceneId m_CubeSceneReference;

    [SerializeField]
    LoadableSceneId m_SphereSceneReference;

    // Store references to the loaded scenes so you can unload them later.
    Scene m_CubeScene;
    Scene m_SphereScene;

    void Start()
    {
        // LoadSceneMode.Additive loads the new scene alongside the current scene.
        // Use LoadSceneMode.Single instead if you want to replace the current scene.
        AsyncOperation cubeLoad = SceneManager.LoadSceneAsync(m_CubeSceneReference, new LoadSceneParameters(LoadSceneMode.Additive));

        // completed fires when the load finishes. Retrieve the Scene object at that
        // point so you can unload it later. The _ parameter is the completed AsyncOperation, which isn't needed here.
        cubeLoad.completed += _ => { m_CubeScene = SceneManager.GetSceneByLoadableSceneId(m_CubeSceneReference); };

        StartCoroutine(WaitAndLoadAnotherScene(1.0f));
    }

    // Loads a second scene additively after a delay.
    private IEnumerator WaitAndLoadAnotherScene(float delay)
    {
        yield return new WaitForSeconds(delay);
        AsyncOperation sphereLoad = SceneManager.LoadSceneAsync(m_SphereSceneReference, new LoadSceneParameters(LoadSceneMode.Additive));
        sphereLoad.completed += _ => { m_SphereScene = SceneManager.GetSceneByLoadableSceneId(m_SphereSceneReference); };
    }

    // Call in response to a game event, such as a button press.
    public void WhenSomeEventHappens()
    {
        // Check isLoaded before unloading: the scene might still be loading
        // when this method is called.
        if (m_CubeScene.isLoaded)
            SceneManager.UnloadSceneAsync(m_CubeScene);
    }

    // Unload both scenes when this MonoBehaviour is destroyed to free memory.
    void OnDestroy()
    {
        if (m_CubeScene.isLoaded)
            SceneManager.UnloadSceneAsync(m_CubeScene);

        if (m_SphereScene.isLoaded)
            SceneManager.UnloadSceneAsync(m_SphereScene);
    }
}
```

## LoadableSceneId 使用示例

以下是在项目中使用 `LoadableSceneId` 的示例。你可以在同一个构建中使用多个这些模式。

### 场景之间切换

场景可以包含一个 MonoBehaviour，当条件满足时卸载当前场景并加载不同的场景。此模式适合同一时间只激活单个场景的项目，例如在关卡之间或大型 3D 世界的区域之间切换的游戏。

以下示例在角色进入 2D 触发器时切换到目标场景：

```csharp
using UnityEngine;
using UnityEngine.SceneManagement;

[RequireComponent(typeof(Collider2D))]
public class SceneTransition : MonoBehaviour
{
    public Unity.Loading.LoadableSceneId TargetScene;

    private void OnTriggerEnter2D(Collider2D col)
    {
        if (TargetScene.IsValid)
            SceneManager.LoadSceneAsync(TargetScene, new LoadSceneParameters(LoadSceneMode.Single));
    }
}
```

使用此模式，你不需要像 AssetBundle 或 Addressables 那样维护单独的待构建场景列表（在那些系统中，你需要将每个场景分配到 AssetBundle 或组）。但是，场景引用分散在项目各处，而不是集中在一个根资源中，这意味着很难了解构建包含多少场景。另一种选择是将场景集中在一个根资源中，如下一节所述。

### 将场景集中到根资源中

对于场景较多的项目，持有 `LoadableSceneId` 字段列表的 ScriptableObject 派生类可以提供构建中所有场景的单一可见记录。这样更容易了解项目中包含哪些场景，并提供一个集中管理场景加载逻辑的位置，而不必将引用分散在场景中的许多 MonoBehaviour 对象上。

在运行时使用 [ContentLoadManager.GetRootAssets<T>](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Loading.ContentLoadManager.GetRootAssets.html) 从已注册的内容目录中检索根资源。

以下示例定义了一个场景列表，其中包含主菜单、UI 场景的命名字段和一个关卡数组：

```csharp
public class CustomSceneList : ScriptableObject
{
    public LoadableSceneId MainMenu;
    public LoadableSceneId UI;
    public LoadableSceneId[] Levels;

    // Include a single asset of this type in the root asset list.
    // Use this method to retrieve it in the Player or during Editor Play mode.
    static public CustomSceneList Get()
    {
        return ContentLoadManager.GetRootAssets<CustomSceneList>()[0];
    }
}
```

### 从内容目录查找场景

你可以将场景构建到单独的内容目录中，让 Player 构建中的代码在运行时发现它们。使用 [ContentLoadManager.RegisterContentDirectory](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Loading.ContentLoadManager.RegisterContentDirectory.html) 注册内容目录，使用 [ContentLoadManager.GetRootAssets<T>](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/Unity.Loading.ContentLoadManager.GetRootAssets.html) 检索根资源，然后使用 [SceneManager.LoadSceneAsync](https://docs.unity3d.com/6000.7/Documentation/ScriptReference/SceneManagement.SceneManager.LoadSceneAsync.html) 加载场景。

以下示例注册了一个包含 `CustomSceneList` 根资源（如上一节所定义）的内容目录，并从其中加载一个关卡场景：

```csharp
public class LoadSceneFromRootAsset
{
    // Reuses the CustomSceneList root asset defined in the previous example.
    public static IEnumerator LoadLevelScene(string contentDirectoryPath, Action<Scene> onSceneLoaded)
    {
        ContentLoadManager.RegisterContentDirectory(contentDirectoryPath);
        CustomSceneList root = ContentLoadManager.GetRootAssets<CustomSceneList>()[0];
        LoadableSceneId sceneReference = root.Levels[0];
        AsyncOperation op = SceneManager.LoadSceneAsync(sceneReference, new LoadSceneParameters(LoadSceneMode.Additive));

        yield return op;

        Scene loadedScene = SceneManager.GetSceneByLoadableSceneId(sceneReference);
        onSceneLoaded?.Invoke(loadedScene);
    }
}
```

> **重要提示**：避免将同一个场景同时构建到 Player 构建和内容目录中。这会在构建输出中重复该场景及其依赖，增加构建体积。没有公开 API 可以选择运行时加载哪个副本，因此结果不可预测。
