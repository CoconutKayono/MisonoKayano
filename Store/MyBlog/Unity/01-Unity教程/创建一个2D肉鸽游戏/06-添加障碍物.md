## 概要（Summary）

为了让游戏更具挑战性，不妨加入一些障碍物，让穿越游戏棋盘不再那么一帆风顺。

到本教程结束时，你将完成以下内容：

- 创建墙壁预制体。
- 编写代码，让游戏启动时在游戏棋盘上随机生成一定数量的 Wall 游戏对象。
- 编写代码，阻止玩家角色进入 Wall 游戏对象所占据的瓦片。
- 添加功能，让玩家角色能够伤害 Wall 游戏对象；墙壁一旦被摧毁，玩家角色就可以移动到它原来占据的瓦片上。

## 1. 概述（Overview）

为了让穿越游戏棋盘更有趣，本教程将引导你在棋盘上随机放置墙壁。然后，你将编写代码，让玩家角色能够摧毁这些墙壁，并将它们从游戏棋盘上移除。

## 2. 添加障碍物（Add obstacles）

让我们在 CellObject 概念的基础上继续，创建一个供玩家克服的障碍物。一堵能阻挡玩家角色的墙壁是个很好的选择，因为你已经在棋盘边框上做过类似的事了。我们还要添加这样的功能：每次玩家撞上墙壁，墙壁都会受到伤害；在承受一定伤害之后，墙壁被摧毁，该单元格变为可通行。

有几个精灵可以用来做墙壁：

这些精灵是整格瓦片精灵（full tile sprites），意味着它们会覆盖整个单元格，就像你之前使用的地面或墙壁精灵一样。你可以把它们当作普通精灵使用，渲染在瓦片地图之上，等它们被摧毁后，底层的瓦片地图就会显露出来。但与其这样，不如修改瓦片地图在该单元格使用的瓦片。

在这么小的游戏里，这两种技术的差别微乎其微，但在大规模地图上差别会很大：单个精灵是一个接一个渲染的，而瓦片地图是批量渲染的，因此瓦片地图要高效得多。

你不能给单个单元格添加组件（比如 CellObject）。不过，这不会成为问题，因为这种新型单元格对象——我们称它们为 WallObject——只是一个没有精灵的空游戏对象。它仍会被放置在单元格中，但它的存在只是为了持有组件，并通过脚本修改它下方的瓦片地图。

要创建 WallObject 并将其添加到游戏中，请按照以下说明操作：

1. 在 Hierarchy 窗口中，创建一个空游戏对象，命名为 "Wall"。

    记住，你不使用精灵；CellObject 会修改瓦片地图。

2. 在 Project 窗口中右键点击 Scripts 文件夹，选择 Create > Scripting > MonoBehaviour Script，命名为 "WallObject"。

```csharp
public class WallObject : CellObject
{
}
```

WallObject 和 FoodObject 一样，继承自 CellObject。

3. 将 WallObject 脚本作为组件添加到 Wall 游戏对象上，把 Wall 游戏对象拖入你的 Prefabs 文件夹，然后从场景中删除 Wall 游戏对象。

4. 在 BoardManager 中添加一个 WallObject 类型的公共变量 "WallPrefab"，并创建一个与 GenerateFood 函数非常相似的 GenerateWall 函数。

    GenerateWall 函数会在关卡中生成一定数量的墙壁。

```csharp
void GenerateWall()
{
   int wallCount = Random.Range(6, 10);
   for (int i = 0; i < wallCount; ++i)
   {
       int randomIndex = Random.Range(0, m_EmptyCellsList.Count);
       Vector2Int coord = m_EmptyCellsList[randomIndex];

       m_EmptyCellsList.RemoveAt(randomIndex);
       CellData data = m_BoardData[coord.x, coord.y];
       WallObject newWall = Instantiate(WallPrefab);

       newWall.transform.position = CellToWorld(coord);

       data.ContainedObject = newWall;
   }
}
```

5. 在 Init 方法内部、调用 GenerateFood 函数之前，调用上面的 GenerateWall 方法。

```csharp
public void Init()
    {
        ... (all code above)
        GenerateWall() ; // new line
        GenerateFood();
    }
```

这样，所有将生成墙壁的单元格都会从空单元格列表中移除，食物也就无法在那里生成。

在编辑器中，将你的 WallPrefab 赋值给 BoardManager 上的 WallPrefab 槽位。现在进入 Play 模式：由于 WallObject 类目前是空的，它们还不会改变棋盘，你也看不到它们，但在 Hierarchy 窗口中选择它们，会看到它们位于关卡中正确的位置。即使功能尚未完成，也要想办法像这样测试，这能让你在出现问题时缩小需要调试的代码范围，所以始终要设法间歇性地测试你正在做的事情。即使墙壁不可见，你也可以利用 Scene 视图和 Hierarchy 窗口，在进入下一步之前检查生成代码是否正常。

Wall 游戏对象需要做两件 CellObject 目前做不到的事情：

- 把它所在位置的瓦片精灵改成墙壁精灵。
- 阻止玩家角色进入单元格。

让我们先解决瓦片替换的问题。正如之前讨论过的，遇到问题时，试着把它变得更通用是个好主意，这样你就能构造出一个可能覆盖多种用例的解决方案。

目标是在 CellObject 被放置在单元格上之后，让代码执行某个动作。这似乎是你在其他 CellObject 上也可能想做的事情，而不只是墙壁。因此，为 CellObject 添加一个在对象被放置后调用的新虚函数会很有帮助。这个函数还需要知道它被放在哪个单元格上。

我们可以把这些需求合并到一个 Init 虚函数中，它接收一个存储坐标的 Vector2Int，表示它被放置的单元格。

```csharp
public class CellObject : MonoBehaviour
{
   protected Vector2Int m_Cell;

   public virtual void Init(Vector2Int cell)
   {
       m_Cell = cell;
   }
  
   public virtual void PlayerEntered()
   {
      
   }
}
```

注意：m_Cell 是 protected（受保护）而不是 private（私有）。private 会让 FoodObject 或 WallObject 等 CellObject 的子类无法访问它。而 protected 允许 WallObject 这样的子类访问它，同时仍然对无关的其他类隐藏。

6. 将 BoardManager 脚本中的 GenerateWall 函数更新为下面的样子，在实例化新的 Wall 之后立即调用 Init：

```csharp
void GenerateWall()
{
   int wallCount = Random.Range(6, 10);
   for (int i = 0; i < wallCount; ++i)
   {
       int randomIndex = Random.Range(0, m_EmptyCellsList.Count);
       Vector2Int coord = m_EmptyCellsList[randomIndex];

       m_EmptyCellsList.RemoveAt(randomIndex);
       CellData data = m_BoardData[coord.x, coord.y];
       WallObject newWall = Instantiate(WallPrefab);
      
       //init the wall
       newWall.Init(coord);
      
       newWall.transform.position = CellToWorld(coord);

       data.ContainedObject = newWall;
   }
}
```

要完成这一组更改，你需要在 WallObject 类中重写 Init 函数，让它修改 Tilemap 的瓦片。然而，当你尝试这样做时，你可能会意识到：从 BoardManager 类之外，无法访问 Tilemap。就像你添加的、把单元格索引转换为世界坐标的方法一样，把这个方法也放在 BoardManager 上是有道理的。

7. 给 BoardManager 添加以下新方法：

```csharp
public void SetCellTile(Vector2Int cellIndex, Tile tile)
{
   m_Tilemap.SetTile(new Vector3Int(cellIndex.x, cellIndex.y, 0), tile);
}
```

因为这个新函数是 public 的，你可以让 WallObject 使用它，最终在 Init 函数中更换瓦片。

8. 将以下代码添加到你的脚本中：

```csharp
using UnityEngine;
using UnityEngine.Tilemaps;

public class WallObject : CellObject
{
   public Tile ObstacleTile;
  
   public override void Init(Vector2Int cell)
   {
       base.Init(cell);
       GameManager.Instance.BoardManager.SetCellTile(cell, ObstacleTile);
   }
}
```

注意：一定要先调用 base.Init()。这会调用它继承的类（CellObject）中的 Init 函数，并在设置瓦片之前给 m_Cell 变量赋值。如果你不先调用 base.Init，m_Cell 变量将保持未赋值状态！作为一般规则，除非你知道基类版本默认什么都不做、或者你想完全覆盖它的行为，否则始终调用被重写函数的基类版本。

9. 保存你的脚本。选择 Wall 预制体，在 Inspector 窗口中，把你想要使用的瓦片赋值给 Obstacle Tile 槽位。

    如果你要用的精灵还不是瓦片，可以通过 Tile Palette 创建它，就像你在之前课程中所做的那样。

    如果现在进入 Play 模式，你应该终于能看到墙壁瓦片被随机添加到游戏棋盘上了。

然而，玩家角色仍然可以移动到墙壁上面。这是因为目前墙壁在初始化时只是更改了瓦片地图的瓦片。要阻止玩家角色移动到墙壁上，你可以在 WallObject 的 Init 代码中把 CellData 的 Passable 属性改为 false。

单独这样做效果不错，但在游戏中，你还希望玩家角色能够通过一定次数的撞击来摧毁墙壁。而你的玩家角色移动代码在单元格不可通行时，甚至不会检查单元格里有没有东西。

和往常一样，遇到问题时，用抽象的方式描述它，有助于弄清楚你需要做什么来解决它。在本例中：

- 检测玩家是否想要移动到某个单元格。
- 如果该单元格有特殊条件（本例中是有墙壁），阻止玩家移动到那里。

要添加这个功能，玩家角色代码需要询问 CellObject 代码：玩家角色是否可以进入该单元格，以及 CellObject 代码是否会允许。

在 CellObject 中新增一个虚方法 PlayerWantsToEnter 就能实现这个目的。当玩家角色试图移动到某个单元格时，玩家角色移动代码会对该单元格中的对象调用这个方法；这个方法返回 true（玩家角色可以进入，比如 FoodObject）或 false（不能进入，比如 WallObject）：

```csharp
public virtual bool PlayerWantsToEnter()
{
   return true;
}
```

然后，你可以修改 PlayerController 的 Update 函数中 if(hasMoved) 条件里的代码，来使用这个新方法：

```csharp
if(cellData != null && cellData.Passable)
{
   GameManager.Instance.TurnManager.Tick();

   if (cellData.ContainedObject == null)
   {
       MoveTo(newCellTarget);
   }
   else if(cellData.ContainedObject.PlayerWantsToEnter())
   {
       MoveTo(newCellTarget);
       //Call PlayerEntered AFTER moving the player! Otherwise not in cell yet
       cellData.ContainedObject.PlayerEntered();
   }
}
```

让我们仔细看看上面的代码行：

- 如果单元格可以通行，游戏就会 tick 一次（撞上物体会计入一个回合，但无法进入单元格，比如外墙或不可摧毁的墙，则不会）。
- 然后，一个条件块会执行几项检查：
  - 如果玩家试图移动到的单元格没有单元格对象，玩家角色就可以移动到该单元格。
  - 如果单元格有单元格对象，就会对该对象调用 PlayerWantsToEnter；如果返回 true，玩家角色就可以进入。

目前，PlayerWantsToEnter 函数的基类版本返回 true，所以玩家角色总是可以移动到这些单元格。但让我们在 WallObject 内部重写这个函数，让它能在 CellObject 是墙壁时返回 false：

```csharp
public class WallObject : CellObject
{
   public Tile ObstacleTile;
  
   public override void Init(Vector2Int cell)
   {
       base.Init(cell);
       GameManager.Instance.BoardManager.SetCellTile(cell, ObstacleTile);
   }

   public override bool PlayerWantsToEnter()
   {
       return false;
   }
}
```

现在，如果你进入 Play 模式，新放置的墙壁应该能阻止玩家角色移动到该单元格了！

## 3. 重构（Refactoring）

在继续之前，花点时间回顾一下你到目前为止所做的事情，考虑是否有可以清理或简化代码的地方，以便更好地面向未来。

如果你寻找代码重复，可能会注意到：在 BoardManager 中，放置食物和墙壁使用了相似的代码——两者都是把一个 CellObject 添加到单元格中。但目前，你的食物放置没有对新 FoodObject 调用 Init。在这里这不是问题，因为 FoodObject 没有重写 Init，也没有使用 Init 函数初始化的 m_Cell 属性；但如果你忘记初始化你编写的其他 CellObject，这可能会成为错误的来源。

因此，现在正是整合这部分代码的好时机：创建一个 AddObject 函数，把给定的 CellObject 添加到给定单元格中，并负责把它放到正确的位置、对它调用 Init：

```csharp
void AddObject(CellObject obj, Vector2Int coord)
{
   CellData data = m_BoardData[coord.x, coord.y];
   obj.transform.position = CellToWorld(coord);
   data.ContainedObject = obj;
   obj.Init(coord);
}
```

现在，让我们用这个新函数来把 FoodObject 和 WallObject 添加到单元格中，而不是手动操作；新的 GenerateWall 和 GenerateFood 函数现在看起来是这样的：

```csharp
void GenerateWall()
{
   int wallCount = Random.Range(6, 10);
   for (int i = 0; i < wallCount; ++i)
   {
       int randomIndex = Random.Range(0, m_EmptyCellsList.Count);
       Vector2Int coord = m_EmptyCellsList[randomIndex];

       m_EmptyCellsList.RemoveAt(randomIndex);
       WallObject newWall = Instantiate(WallPrefab);
       AddObject(newWall, coord);
   }
}

void GenerateFood()
{
   int foodCount = 5;
   for (int i = 0; i < foodCount; ++i)
   {
       int randomIndex = Random.Range(0, m_EmptyCellsList.Count);
       Vector2Int coord = m_EmptyCellsList[randomIndex];

       m_EmptyCellsList.RemoveAt(randomIndex);
       FoodObject newFood = Instantiate(FoodPrefab);
       AddObject(newFood, coord);
   }
}
```

这样，如果以后你使用 AddObject 函数向棋盘添加新类型的对象，一切都会被正确设置。

完成所有这些更改后，别忘了在 Play 模式下试玩一下游戏，确保你没有弄坏任何东西，再继续！

## 4. 破坏墙壁（Damaging walls）

目前，当玩家撞上墙壁单元格时，他们无法移动，但食物计数器会减少，因为撞击被计为一个回合。那么，让我们添加破坏墙壁的功能。运用你目前学到的所有知识，你应该能自己完成。但首先，让我们写下这个功能需要做的事情：

- 在 WallObject 中创建一个新的计数器变量，存储该墙壁的生命值点数。
- 在 Init 期间、墙壁瓦片替换之前，保存该单元格的原始瓦片（这样墙壁被摧毁后，你可以把它设置回去）。这需要你在 BoardManager 中添加一个新函数，就像我们为 SetCellTile 做的那样！
  - 注意：Tilemap 类包含一个名为 GetTile 的函数（与 SetTile 类似），它允许你获取某个单元格的瓦片。但如果你查看文档，会发现这个函数返回的是 BaseTile，而不是 Tile。别担心，你可以轻松解决这个问题：使用这个函数的泛型版本 `GetTile<Tile>()` 来获取实际的 Tile。
- 当 WallObject 中的 PlayerWantsToEnter 函数被调用时，将生命值计数减 1；当生命值降到 0 时，WallObject 被摧毁，墙壁瓦片被移除，并恢复为原始瓦片。

WallObject

```csharp
public class WallObject : CellObject
{
   public Tile ObstacleTile;
   public int MaxHealth = 3;

   private int m_HealthPoint;
   private Tile m_OriginalTile;
  
   public override void Init(Vector2Int cell)
   {
       base.Init(cell);

       m_HealthPoint = MaxHealth;
      
       m_OriginalTile = GameManager.Instance.BoardManager.GetCellTile(cell);
       GameManager.Instance.BoardManager.SetCellTile(cell, ObstacleTile);
   }

   public override bool PlayerWantsToEnter()
   {
       m_HealthPoint -= 1;

       if (m_HealthPoint > 0)
       {
           return false;
       }

       GameManager.Instance.BoardManager.SetCellTile(m_Cell, m_OriginalTile);
       Destroy(gameObject);
       return true;
   }
}
```

BoardManager

```csharp
public Tile GetCellTile(Vector2Int cellIndex)
    {
        return m_Tilemap.GetTile<Tile>(new Vector3Int(cellIndex.x,     cellIndex.y, 0));
    }
```

上面是我们的解决方案；你的可能会略有不同！注意，我们声明了一个公共属性 MaxHealth，这样我们就可以在 Inspector 窗口中更改 WallObject 拥有多少生命值。这样一来，我们就可以拥有需要更多或更少伤害才能摧毁的墙壁。

进入 Play 模式，看看玩家现在如何在经过一定次数的撞击后摧毁墙壁。恭喜，你为游戏玩法增加了不少复杂度！别忘了把更改保存到 UVCS！
