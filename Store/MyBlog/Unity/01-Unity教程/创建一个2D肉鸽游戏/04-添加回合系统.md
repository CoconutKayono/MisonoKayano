## 概要（Summary）

这是一款回合制游戏，这意味着它需要一种方式来管理回合。

到本教程结束时，你将完成以下内容：

- 创建一个 TurnManager 脚本，用来记录玩家角色的每一次移动，并把每一次移动计为一个回合。
- 重构游戏的初始化代码，以适应这个新系统。

## 1. 概述（Overview）

现在你已经有了一个可以在游戏棋盘上移动的玩家角色，下一步就是为这款回合制游戏添加回合系统。在本教程中，你将添加并编写这套系统：每当玩家角色移动时，它负责统计回合数，并通知你的游戏「一个回合已经发生」，这样你就可以围绕这个功能创建其他的游戏机制。

## 2. 回合管理器（Turn manager）

如果你回到任务清单，拥有一个可移动的玩家之后的下一个任务，就是在玩家角色移动时实现回合系统。

要创建回合系统，请按照以下说明操作：

1. 在 Project 窗口中右键点击 Scripts 文件夹，选择 Create > Scripting > Empty C# Script。将这个脚本命名为 "TurnManager"。

在这种情况下，你不需要使用 MonoBehaviour 脚本，因为与你之前编写的其他脚本不同，这个脚本是一个纯粹的数据类，只处理数据，不与任何游戏对象关联，因此它不需要继承 MonoBehaviour。

```csharp
using UnityEngine;

public class TurnManager
{
  
}
```

由于这不是 MonoBehaviour 脚本，也不存在于场景中，因此没有 Start 或 Update 方法，所以你需要手动创建/初始化它，就像你初始化 Vector3 或你的 CellData 那样。

你可以通过以下几种方式来实现：

- 在 BoardManager 的 Start 方法中。
- 在 PlayerController 的 Spawn 方法中。
- 在一个新的系统中，由该系统在开始时负责初始化一个关卡所需的一切。

最后一个方案看起来是最干净的，因为随着游戏变得越来越复杂，你可能还会有其他东西需要初始化。

想一想游戏的启动流程。目前你只依赖 BoardManager 的 Start 方法来初始化一切，但以后当你需要处理多个关卡时，你可能需要再次调用初始化代码。

与其这样，不如创建一个 GameManager 游戏对象，把它作为游戏启动时所需一切事物的入口。它由一个脚本组成，其 Start 方法将做以下事情：

- 初始化 TurnManager。
- 触发棋盘生成（BoardGeneration）。
- 生成玩家（Spawn the Player）。

所以，你既有一些新代码要写，也有一些重构要先做！

1. 在 Main 场景中，创建一个新的空游戏对象，命名为 "GameManager"。

2. 在 Project 窗口中右键点击 Scripts 文件夹，选择 Create > Scripting > MonoBehaviour Script。将这个脚本命名为 "GameManager"。

3. 将 GameManager 脚本作为组件添加到 GameManager 游戏对象上。

4. 在脚本内创建两个公共引用：

   - 一个用于棋盘，类型为 BoardManager。
   - 一个用于玩家，类型为 PlayerController。

5. 创建一个 TurnManager 类型的私有变量。

6. 在 GameManager 脚本的 Start 方法中做以下事情：

   - 初始化 TurnManager（它只是一个普通类，所以可以使用 `new`）。
   - 初始化关卡（你需要把 BoardManager 中的 Start 方法重命名为 Init，并将其设为 public，这样才能从这个 Start 方法中调用它）。
   - 在 (1,1) 位置生成玩家，因此你需要从 BoardManager 的 Init 方法中移除对生成玩家的调用。

你应该能完全靠自己完成这些，下面是最终脚本的样子：

BoardManager

```csharp
public class BoardManager : MonoBehaviour
{
   public class CellData
   {
       public bool Passable;
   }

   private CellData[,] m_BoardData;
   private Tilemap m_Tilemap;
   private Grid m_Grid;
  
   public int Width;
   public int Height;
   public Tile[] GroundTiles;
   public Tile[] WallTiles;
  
   public void Init()
   {
       m_Tilemap = GetComponentInChildren<Tilemap>();
       m_Grid = GetComponentInChildren<Grid>();
      
       m_BoardData = new CellData[Width, Height];

       for (int y = 0; y < Height; ++y)
       {
           for(int x = 0; x < Width; ++x)
           {
               Tile tile;
               m_BoardData[x, y] = new CellData();

               if(x == 0 || y == 0 || x == Width - 1 || y == Height - 1)
               {
                   tile = WallTiles[Random.Range(0, WallTiles.Length)];
                   m_BoardData[x, y].Passable = false;
               }
               else
               {
                   tile = GroundTiles[Random.Range(0, GroundTiles.Length)];
                   m_BoardData[x, y].Passable = true;
               }

               m_Tilemap.SetTile(new Vector3Int(x, y, 0), tile);
           }
       }
   }

   public Vector3 CellToWorld(Vector2Int cellIndex)
   {
       return m_Grid.GetCellCenterWorld((Vector3Int)cellIndex);
   }

   public CellData GetCellData(Vector2Int cellIndex)
   {
       if (cellIndex.x < 0 || cellIndex.x >= Width
           || cellIndex.y < 0 || cellIndex.y >= Height)
       {
           return null;
       }

       return m_BoardData[cellIndex.x, cellIndex.y];
   }
}
```

GameManager

```csharp
public class GameManager : MonoBehaviour
{
   public BoardManager BoardManager;
   public PlayerController PlayerController;

   private TurnManager m_TurnManager;
  
   // Start is called once before the first execution of Update after the MonoBehaviour is created
   void Start()
   {
       m_TurnManager = new TurnManager();
      
       BoardManager.Init();
       PlayerController.Spawn(BoardManager, new Vector2Int(1,1));
   }
}
```

别忘了在 GameManager 的 Inspector 窗口中分配 BoardManager 和 PlayerCharacter 的引用，并进入 Play 模式，检查玩家角色是否仍能在棋盘上正常移动。

重要提示：如果游戏在 Play 模式下不能正常工作，请仔细阅读控制台中出现的错误，并试着理解它们：

- 空引用（Null Reference）错误意味着某个东西没有被正确赋值——你可能忘了在 GameManager 游戏对象的 Inspector 窗口中分配引用。
- "Expected"（应为...）或 "does not exist"（不存在）错误通常是拼写错误：你在变量名上犯了错，或者代码中某个地方缺少了括号或分号。

## 3. 回合计数（Ticking turn）

现在你已经重构了初始化阶段，终于可以让回合系统滴答作响了。

为此，你需要一个保存当前回合数的私有成员变量（在构造函数中初始化为 1），以及一个 Tick 方法，将计数加 1，并使用 Debug.Log 方法打印当前的回合数，如下所示：

```csharp
public class TurnManager
{
   private int m_TurnCount;

   public TurnManager()
   {
       m_TurnCount = 1;
   }

   public void Tick()
   {
       m_TurnCount += 1;
       Debug.Log("Current turn count : " + m_TurnCount);
   }
}
```

然后，你需要在玩家每次移动时调用 Tick。但该怎么做呢？唯一持有 TurnManager 引用的地方在 GameManager 内部。

你可以像处理 BoardManager 那样，把 GameManager 传给 Player，但由于游戏中有很多其他东西可能都需要访问 GameManager，更好的做法是探索另一种方法：单例模式（singleton pattern）。

使用单例模式意味着：在你的游戏/应用中，某个类只能有一个实例，并且你可以通过一个静态成员从任何地方访问它。

就像你在代码架构中做的每一个决定一样，单例模式也有其缺点：它难以与多线程一起使用，也会让单元测试变得更困难。这些都属于高级用例，在这个项目中你无需操心，但编程讲究培养好习惯，所以通常最好谨慎使用单例。不过，在某些情况下，它是一个强大的工具，能让代码写起来更快、理解起来更简单。就 TurnManager 脚本而言，单例模式的这些缺点，换来的是不必把 GameManager 传递到应用中每一个需要它的对象那里——这是值得的。

这是新的单例 GameManager：

```csharp
public class GameManager : MonoBehaviour
{
   public static GameManager Instance { get; private set; }
  
   public BoardManager BoardManager;
   public PlayerController PlayerController;

   private TurnManager m_TurnManager;

   private void Awake()
   {
       if (Instance != null)
       {
           Destroy(gameObject);
           return;
       }
      
       Instance = this;
   }
  
   void Start()
   {
       m_TurnManager = new TurnManager();
      
       BoardManager.Init();
       PlayerController.Spawn(BoardManager, new Vector2Int(1,1));
   }
}
```

这段代码中有几个新东西，让我们逐一查看：

- 有一个名为 Instance 的静态 GameManager 属性成员。它将存储对你的 GameManager 的引用。你可以看到这里有两个关键字：get 和 set。set 前面有 private 关键字。这意味着，读取这个成员变量（get）对代码中的所有部分都可用，但写入这个成员变量的值（set）只能从类内部进行。
- 添加了一个名为 Awake 的新方法。当游戏对象被创建时，它会在 Start 之前被调用。在这个方法中，会发生以下事情：
  - 代码会测试 Instance 是否为 null。如果不是，说明已经存在一个 GameManager。由于单例模式要求唯一，这种情况本不应发生，所以我们会销毁这个 GameManager 并退出该方法（因为这是一个 void 类型的方法，"return;" 不会返回任何内容）。
  - 如果还没有存储任何 GameManager（Instance 为 null），我们就把这个 GameManager 存储到 Instance 中。

现在，你可以在代码中的任何地方使用下面的实例来访问 GameManager：

```csharp
GameManager.Instance
```

现在，如果你把 GameManager 的 TurnManager 变量改为 public，其他脚本也可以透过 GameManager.Instance 访问它。注意，在下面的代码示例中，我们使用了与 Instance 变量相同的技巧：把 TurnManager 的 set 属性定义为 private，这样只有 GameManager 脚本可以修改这个变量，但 get 属性保持 public，这样其他脚本就可以访问 TurnManager。

```csharp
public class GameManager : MonoBehaviour
{
   public static GameManager Instance { get; private set; }
  
   public BoardManager BoardManager;
   public PlayerController PlayerController;

   public TurnManager TurnManager { get; private set;}

   private void Awake()
   {
       if (Instance != null)
       {
           Destroy(gameObject);
           return;
       }
      
       Instance = this;
   }
  
   void Start()
   {
       TurnManager = new TurnManager();
      
       BoardManager.Init();
       PlayerController.Spawn(BoardManager, new Vector2Int(1,1));
   }
}
```

然后，在 PlayerController 的 Update 方法中，你可以在调用 MoveTo 之前先「滴答」一下 TurnManager：

```csharp
if(hasMoved)
{
   //check if the new position is passable, then move there if it is.
   BoardManager.CellData cellData = m_Board.GetCellData(newCellTarget);

   if(cellData != null && cellData.Passable)
   {
       GameManager.Instance.TurnManager.Tick();
       MoveTo(newCellTarget);
   }
}
```
