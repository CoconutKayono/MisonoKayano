## 1. 概述（Overview）

## 2. 创建基础敌人（Create a basic enemy）

你最后想为游戏添加的，就是敌人。为游戏添加敌人会用到你目前学到的所有知识：

- 它们会在游戏的每个回合行动。
- 它们本质上是一种会移动的 CellObject，因此在某种意义上它们像墙壁一样：会阻止玩家角色进入它们所在的单元格，并且在受到伤害、生命值降到 0 时被摧毁。
- 如果回合发生时玩家角色与它们相邻，它们可以伤害玩家角色（将玩家的食物数量减少 1）。
- 如果回合发生时玩家角色不在它们旁边，它们就会向玩家角色靠近一格。

回顾之前的所有教程，你应该已经具备独自成功为游戏添加敌人所需的所有知识了！以下是你的实现需要满足的要求清单：

- 你的 Enemy 脚本继承自 CellObject。
- 敌人需要一个在回合发生时收到通知的机制。看看你在每回合减少食物时是怎么做的。别忘了给敌人添加一个 OnDestroy 函数来移除回调！否则回调仍会试图通知已被销毁的敌人「一个回合发生了」。
  - 注意：正如《添加食物资源》教程所示，既然 `+=` 可以向回调添加函数，`-=` 就会移除它，所以只需调用 `OnTick -= YourMethod`，就能让 YourMethod 不再每个回合都被调用。

- 当回合发生时，敌人会检查玩家角色的位置。如果玩家就在旁边，它们就伤害玩家角色（扣除一些食物点数）；如果玩家不在旁边，它们就向玩家角色靠近一格。
- 敌人移动时，由于它们是 CellObject，它们需要把自己从移出的单元格中移除，并把自己添加到移入的单元格中。

正如本项目一开始讨论的那样，当面对像这样的大任务时，把它拆分成一个个小步骤是很好的做法：这让你可以逐段调试，而不是花很长时间写代码、无法逐个测试每个功能，最后得到一个难以一次性调试的庞大复杂问题！

下面是一个创建敌人的可行计划：

1. 先创建游戏对象，只带敌人的待机动画。这将是你所有工作的基础。
2. 把 Enemy 脚本创建为 CellObject 的子类，但暂时让它的所有函数都保持为空。
3. 根据该游戏对象创建预制体，并尝试把这个 Enemy 预制体生成到 BoardManager 中（记住，它们也是 CellObject！）。

    现在你可以测试：玩的时候敌人是否出现在游戏中了！你可能已经有一个 bug 要修复，因为敌人可能没有出现。检查你的 Hierarchy 窗口；如果它在 Hierarchy 窗口中，但在 Scene 视图中不可见，回忆一下当初你是怎样让玩家角色和食物精灵渲染到瓦片地图上方的。

4. 确认敌人出现在游戏中之后，就可以开始为它编码了！修改 Enemy 脚本，让它阻止玩家角色进入它的单元格，并且会承受伤害（你需要在 Enemy 脚本中添加生命值跟踪），一旦生命值归零就被摧毁。简而言之，让它变得和 WallObject 一模一样。
5. 确认这一步正常后，让敌人每回合向玩家角色移动！你需要找出敌人需要移动到哪个单元格，才能离玩家更近。这可能是最难的部分。试试不同的代码来实现它。

    - 提示：如果你无法弄明白如何让敌人向玩家角色移动，这里有一个解决方案：检查这两个单元格在 X 和 Y 方向上的距离，然后沿着距离最大的轴移动（例如，如果玩家角色在 X 方向距离为 3、在 Y 方向距离为 -4，你就需要把敌人向下移动一格才能靠近玩家）。别忘了测试目标单元格是否为空！你不希望敌人钻进墙壁里！你也可以把食物单独处理作为额外加分项，但一个好的初步测试是：同样禁止敌人进入含有食物的单元格。

6. 现在测试敌人是否在尝试靠近玩家角色。在这一步，你可能会遇到一个 bug：敌人钻到玩家角色下面。别忘了：如果敌人已经与玩家相邻，就不要再让它试图接近玩家——敌人永远不应该尝试进入玩家角色所在的单元格！
7. 最后，你可以添加这样的功能：当轮到敌人行动时，如果它与玩家角色直接相邻，就攻击玩家角色，并从食物储备中扣除一定数量的食物。

以下是最终敌人脚本的一个可能版本：

Enemy

```csharp
public class Enemy : CellObject
{
   public int Health = 3;
  
   private int m_CurrentHealth;

   private void Awake()
   {
      GameManager.Instance.TurnManager.OnTick += TurnHappened;
   }

   private void OnDestroy()
   {
       GameManager.Instance.TurnManager.OnTick -= TurnHappened;
   }

   public override void Init(Vector2Int coord)
   {
      base.Init(coord);
      m_CurrentHealth = Health;
   }

   public override bool PlayerWantsToEnter()
   {
       m_CurrentHealth -= 1;

       if (m_CurrentHealth <= 0)
       {
          Destroy(gameObject);
       }

       return false;
   }

   bool MoveTo(Vector2Int coord)
   {
       var board = GameManager.Instance.BoardManager;
       var targetCell =  board.GetCellData(coord);

      if (targetCell == null
          || !targetCell.Passable
          || targetCell.ContainedObject != null)
      {
          return false;
      }
    
      //remove enemy from current cell
      var currentCell = board.GetCellData(m_Cell);
      currentCell.ContainedObject = null;
    
      //add it to the next cell
      targetCell.ContainedObject = this;
      m_Cell = coord;
      transform.position = board.CellToWorld(coord);

      return true;
   }

   void TurnHappened()
   {
      //We added a public property that return the player current cell!
      var playerCell = GameManager.Instance.PlayerController.Cell;

      int xDist = playerCell.x - m_Cell.x;
      int yDist = playerCell.y - m_Cell.y;

      int absXDist = Mathf.Abs(xDist);
      int absYDist = Mathf.Abs(yDist);

      if ((xDist == 0 && absYDist == 1)
          || (yDist == 0 && absXDist == 1))
      {
          //we are adjacent to the player, attack!
          GameManager.Instance.ChangeFood(3);
      }
      else
      {
          if (absXDist > absYDist)
          {
              if (!TryMoveInX(xDist))
              {
                  //if our move was not successful (so no move and not attack)
                  //we try to move along Y
                  TryMoveInY(yDist);
              }
          }
          else
          {
              if (!TryMoveInY(yDist))
              {
                  TryMoveInX(xDist);
              }
          }
      }
   }

   bool TryMoveInX(int xDist)
   {
      //try to get closer in x
     
      //player to our right
      if (xDist > 0)
      {
          return MoveTo(m_Cell + Vector2Int.right);
      }
    
      //player to our left
      return MoveTo(m_Cell + Vector2Int.left);
   }

   bool TryMoveInY(int yDist)
   {
      //try to get closer in y
     
      //player on top
      if (yDist > 0)
      {
          return MoveTo(m_Cell + Vector2Int.up);
      }

      //player below
      return MoveTo(m_Cell + Vector2Int.down);
   }
}
```

注意：这个脚本的移动代码稍微复杂一些！在我们的实现中，如果沿一个方向移动失败，我们会尝试沿另一个方向移动，以处理墙壁或对象把敌人卡住的情况。

（译注：原文正文说敌人攻击玩家是「扣除一定数量的食物」，但示例代码里写的是 `ChangeFood(3)`——这会把食物增加 3。如果你希望敌人攻击时减少食物，应改成负数，例如 `ChangeFood(-3)`。）

## 3. 挑战（Challenge）

你的敌人仍然非常简单。下面是一些改进它、让它更有活力的想法。你的挑战是想办法实现这些功能：

- 让 Enemy 游戏对象在攻击玩家角色时播放攻击动画，甚至还可以给玩家角色添加一个受击动画。
  - 注意：你可能需要试验一下过渡设置，来处理敌人播放攻击动画和玩家角色受击的时序。也许一个从攻击到受击的过渡，用其中一个打断另一个，会有所帮助；多试验一下，找到最适合你的方式！

- 让敌人像玩家角色一样平滑地在单元格之间移动。敌人需要以与玩家角色相同的速度移动，以确保两次移动持续的时间相同。这可能是一个重构的契机：创建一个 ObjectMover 系统，它接收一组需要移动的对象及它们的目标，并在其所有对象的移动完成之前，阻止用户的任何输入。
