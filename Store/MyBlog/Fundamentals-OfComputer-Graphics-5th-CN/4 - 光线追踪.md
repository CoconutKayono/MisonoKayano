# 4 - 光线追踪（Ray Tracing）

计算机图形学的基本任务之一是对三维物体进行渲染：即，将场景中众多排列在三维空间里的几何物体，根据特定视点，计算出一幅显示这些物体的二维图像。这与几个世纪以来建筑师和工程师绘制图纸以向他人传达设计理念的操作如出一辙。

从根本上说，渲染是一个以一组物体为输入、以像素阵列为输出的过程。无论如何，渲染都涉及考虑每个物体对每个像素的贡献，并且可以通过两种基本方式来组织。
- 在**物体顺序渲染**中，依次处理每个物体，对每个物体找出其影响的所有像素并进行更新。
- 在**图像顺序渲染**中，依次处理每个像素，对每个像素找出所有影响它的物体并计算出该像素的值。
- 两者的区别可以理解为循环嵌套的顺序：在图像顺序渲染中，“对每个像素”的循环在外层；而在物体顺序渲染中，“对每个物体”的循环在外层。

> [!NOTE] 旁注
> 如果输出的是矢量图像而非光栅图像，则渲染不必涉及像素，但本书假设为光栅图像。

图像顺序渲染器和物体顺序渲染器可以生成完全相同的图像，但各自适合计算不同类型的效果，且性能特征差异显著。我们将在第9章讨论完这两种方法后，深入比较它们各自的优势。不过，概括来说，图像顺序渲染更容易实现，能产生的效果也更灵活，但（通常，但并不总是）生成同等质量的图像需要更长的执行时间。

> [!NOTE] 旁注
> 在光线追踪器中，可以轻松计算出精确的阴影和反射，而这在以物体为序的框架中很难做到。

光线追踪是一种用于生成$3D$场景渲染图的图像顺序算法，我们首先讨论它，因为无需开发物体顺序渲染所涉及的数学工具，就能让光线追踪器运行起来。

无论以何种方式实现，渲染都要考虑每个物体对每个像素的贡献，这一过程可以按两种一般方式组织：

```cpp
for every object:
  计算该物体对哪些像素有贡献

for every pixel:
  计算该像素命中了哪个物体，以及该物体看起来如何
```
## 4.1 基本光线追踪算法（The Basic Ray-Tracing Algorithm）

光线追踪器的工作原理是逐个像素进行计算。对于每个像素，其基本任务是找到在该像素位置所看到的物体。每个像素“看向”不同的方向，像素所看到的任何物体都必须与**视线 （viewing ray）** 相交——视线是从视点出发、沿该像素观察方向射出的一条射线。我们要找的，是与视线相交且离相机最近的那个物体，因为它会遮挡住它后面所有其他物体的视野。一旦找到该物体，**着色（shading）** 计算将利用交点、表面法线以及其他信息（取决于所需的渲染类型）来决定该像素的颜色。
如图4.1所示，光线与两个三角形相交，但只有首先被击中的三角形 $T_2$​ 会被着色。

因此，一个基本光线追踪器包含三个部分：
1. **生成光线**（ray generation）：根据相机的几何信息，计算每个像素对应视线的起点和方向；
2. **光线求交**（ray intersection）：找出与视线相交的最近物体；
3. **着色**（shading）：根据光线求交的结果计算像素颜色。

基本光线追踪程序的结构如下：
```text
对于每个像素，执行：
    计算视线
    找到光线击中的第一个物体及其表面法线 n  
	将像素颜色设置为根据击中点、光源和 n 计算出的值  
```

## 4.2 透视（Perspective）

用二维绘画或绘图表现三维物体或场景的问题，早在计算机出现之前数百年，就已被艺术家们研究过了；照片同样是用二维图像表现三维场景。虽然成像方式五花八门，从立体主义绘画、鱼眼镜头（fisheye lens，图4.2）到周边相机，但艺术、摄影与计算机图形学的标准方法都是线性透视（linear perspective）：把三维物体投影到图像平面上，使场景中的直线在图像中仍是直线。

最简单的投影类型是平行投影（parallel projection）：三维点沿投影方向移动，直到命中图像平面，从而映射为二维点（图4.3-4.4）。所得到的视图由投影方向与图像平面的选择决定。若图像平面垂直于观察方向，则称该投影为**正交投影**（orthographic projection）；否则称为**斜投影**（oblique projection）。

平行投影常用于机械制图与建筑图纸，因为它能保持平行线的平行性，并保持与图像平面平行的平面物体的尺寸和形状。

![Figure 4.3](Pasted%20image%2020240229205241.png)

平行投影的优点也正是它的局限。在我们的日常经验中（照片中更是如此），物体随距离增大而变小，因此向远处延伸的平行线看起来并不平行。这是因为眼睛和相机并非沿单一观察方向收集光线，而是收集通过特定视点的光线。正如文艺复兴以来的艺术家们所知，我们可以用**透视投影**（perspective projection）产生自然逼真的视图：只需沿通过单一点——即视点——的直线投影，而不是沿平行线投影（图4.4）。于是，离视点更远的物体投影后自然更小。透视视图由视点（而非投影方向）和图像平面的选择决定。与平行视图一样，透视视图也有斜视图与非斜视图之分，区别在于图像中心处的投影方向。

![Figure 4.4](Pasted%20image%2020240229205928.png)

你可能学过**三点透视**（three-point perspective）这种艺术约定——一套手工构建透视视图的方法（图4.5）。关于透视，一个令人惊讶的事实是：只要遵循透视背后简单的数学规则，透视绘画的所有规则都会被自动满足——物体直接向眼睛投影，并在其与眼前的视平面相交处被绘制出来。

## 4.3 计算视图光线（Computing Viewing Rays）

由上一章可知，生成光线的基本工具是视点（对平行视图而言是视线方向）和图像平面。确定相机几何细节的方法有很多；本节讲解一种基于标准正交基（orthonormal basis）的方法，它支持普通与倾斜的平行投影，也支持透视视图。

![Figure 4.5](Pasted%20image%2020240229210346.png)

要生成光线，首先需要光线的数学表示。光线本质上就是一个原点加一个传播方向，三维参数直线正是理想之选。如第2.7.7节所述，从视点 $\vec{e}$ 出发、穿过图像平面上点 $\vec{s}$ 的三维参数直线（图4.6）为：

$$\vec{p}(t) = \vec{e} + t(\vec{s} - \vec{e})$$

![Figure 4.6](Pasted%20image%2020240229211752.png)

这可以解读为：“从 $\vec{e}$ 出发，沿向量 $(\vec{s} - \vec{e})$ 方向移动比例距离 $t$，即可得到点 $\vec{p}$。”因此，给定 $t$ 就能确定一个点 $\vec{p}$。其中 $\vec{e}$ 是光线的原点，$\vec{s} - \vec{e}$ 是光线的方向。

注意 $\vec{p}(0) = \vec{e}$、$\vec{p}(1) = \vec{s}$；更一般地，若 $0 < t_1 < t_2$，则 $\vec{p}(t_1)$ 比 $\vec{p}(t_2)$ 更靠近视点。此外，若 $t < 0$，则 $\vec{p}(t)$ 位于视点“后方”。在寻找被光线击中、且不在视点后方的最近物体时，这些事实将很有用。

在代码中，光线通常用某种结构或对象表示，该结构或对象存储位置与方向。例如，在面向对象的程序中，我们可能会写：

```text
class Ray
    Vec3 o                        // 光线原点
    Vec3 d                        // 光线方向
    Vec3 evaluate(real t)         // 计算光线上的点
    return o + t*d
```

要计算视图光线，我们需要知道 $\vec{e}$（已知）和 $\vec{s}$。求 $\vec{s}$ 看似困难，但只要选对坐标系，其实非常直接。

![Figure 4.7](Figure%204.7.png)

我们所有的光线生成方法都从一个称为**相机坐标系**（camera frame）的标准正交坐标系开始（图4.7）：$\vec{e}$ 表示视点，$\vec{u}$、$\vec{v}$、$\vec{w}$ 为三个基向量。其中 $\vec{u}$ 指向右方（从相机视角看），$\vec{v}$ 指向上方，$\vec{w}$ 指向后方，从而 $\{\vec{u}, \vec{v}, \vec{w}\}$ 构成右手坐标系。构建相机坐标系最常见的方法是：由视点（即 $\vec{e}$）、视线方向（即 $-\vec{w}$）和上向量（up vector）出发，采用第2.4.7节“由两个向量构造标准正交基”的方法，构造出一个 $\vec{v}$、$\vec{w}$ 位于视线方向与上方向所张成平面内的基（图4.8）。

![Figure 4.8](Pasted%20image%2020240229212736.png)

### 4.3.1 正交视图（Orthographic Views）

对于正交视图，所有光线的方向都是 $-\vec{w}$。虽然平行视图没有视点，我们仍可用相机坐标系的原点来定义光线起始的平面，这样物体仍可能位于相机后方。

视图光线应从由点 $\vec{e}$ 与向量 $\vec{u}$、$\vec{v}$ 张成的平面开始；剩下的唯一信息是图像在该平面上的位置。我们用四个数字定义图像尺寸，分别对应图像的四条边：$l$ 与 $r$ 是图像左、右边缘的位置，沿 $\vec{u}$ 方向从 $\vec{e}$ 起测量；$b$ 与 $t$ 是图像下、上边缘的位置，沿 $\vec{v}$ 方向从 $\vec{e}$ 起测量。通常 $l < 0 < r$ 且 $b < 0 < t$（见图4.9a）。

![Figure 4.9](Pasted%20image%2020240229213450.png)

第3.2节讨论了图像中的像素坐标。要把一幅 $n_x \times n_y$ 像素的图像放进大小为 $(r - l) \times (t - b)$ 的矩形中，像素在水平方向上的间距应为 $(r - l)/n_x$，垂直方向上的间距为 $(t - b)/n_y$，并在边缘留出半个像素的空隙，以便像素网格在图像矩形内居中。

这意味着栅格图像中位置为 $(i, j)$ 的像素，其位置由公式（4.1）给出：

$$u = l+ \frac{r-l}{n_x}(i+0.5)$$
$$v = b+ \frac{t-b}{n_y}(j+0.5)$$

其中 $(u,v)$ 是该像素在图像平面上位置的坐标，相对于原点 $\vec{e}$ 和基 $\{\vec{u}, \vec{v}\}$ 度量。

在正交视图中，可以直接把像素的图像平面位置作为光线起点，且光线方向已知为视线方向。生成正交视图光线的步骤如下：

1. 用公式 (4.1) 计算 $u$ 和 $v$；
2. $\text{ray.o} \leftarrow \vec{e} + u\vec{u} + v\vec{v}$；
3. $\text{ray.d} \leftarrow -\vec{w}$。

制作倾斜平行视图非常简单：只需让图像平面法向量 $\vec{w}$ 与视线方向 $\vec{d}$ 分开指定。步骤完全相同，只需用 $\vec{d}$ 代替 $-\vec{w}$。当然，$\vec{u}$、$\vec{v}$ 的构建仍然依赖 $\vec{w}$。

### 4.3.2 透视视图（Perspective Views）

对于透视视图，所有光线共享同一个原点——视点；每个像素的区别仅在于方向。图像平面不再位于 $\vec{e}$ 处，而是在 $\vec{e}$ 前方距离 $d$ 的位置；这个距离称为图像平面距离，通常也叫**焦距**（focal length），因为在这里选择 $d$ 的作用与在真实相机中选择焦距相同。每条光线的方向由视点和像素在图像平面上的位置决定。该情况如图4.9所示，相应步骤与正交投影类似：

1. 用公式 (4.1) 计算 $u$ 和 $v$；
2. $\text{ray.o} \leftarrow \vec{e}$；
3. $\text{ray.d} \leftarrow -d\vec{w} + u\vec{u} + v\vec{v}$。

与平行投影一样，可以通过分别指定图像平面法向量与投影方向，创建倾斜透视视图。

## 4.4 光线与物体的交点（Ray-Object Intersection）

生成光线 $\vec{e} + t\vec{d}$ 之后，下一步是找到它与任何物体的第一个交点，其中 $t > 0$。在实践中，求解一个稍更一般的问题更有用：在区间 $[t_0, t_1]$ 内找到光线与表面的第一个交点。基本的光线求交问题即 $t_0 = 0$、$t_1 = +\infty$ 的情形。我们将针对球体与三角形求解该问题；多个物体的情形将在下一节讨论。

### 4.4.1 光线与球面求交（Ray-Sphere Intersection）

给定光线 $\vec{p}(t) = \vec{e} + t\vec{d}$ 与隐式曲面 $f(\vec{p}) = 0$（见第2.7.3节），我们希望知道二者在何处相交。当光线上的点满足隐式方程时即发生相交，因此所求的 $t$ 值满足：

$$f(\vec{p}(t)) = 0 \quad \text{或} \quad f(\vec{e} + t\vec{d}) = 0$$

中心为 $\vec{c} = (x_c, y_c, z_c)$、半径为 $R$ 的球体可由隐式方程描述为：

$$(x - x_c)^2 + (y - y_c)^2 + (z - z_c)^2 - R^2 = 0$$

同样的方程可以写成向量形式：

$$(\vec{p} - \vec{c}) \cdot (\vec{p} - \vec{c}) - R^2 = 0$$

满足该方程的任何点 $\vec{p}$ 都在球面上。把光线上的点 $\vec{p}(t) = \vec{e} + t\vec{d}$ 代入该方程，就得到关于 $t$ 的方程，凡能产生球面上点的 $t$ 值都满足它：

$$(\vec{e} + t\vec{d} - \vec{c}) \cdot (\vec{e} + t\vec{d} - \vec{c}) - R^2 = 0$$

整理各项可得：

$$(\vec{d} \cdot \vec{d})t^2 + 2\vec{d} \cdot (\vec{e} - \vec{c})t + (\vec{e} - \vec{c}) \cdot (\vec{e} - \vec{c}) - R^2 = 0$$

这里，除参数 $t$ 外所有量均为已知，因此这是关于 $t$ 的经典二次方程，即具有如下形式：

$$At^2 + Bt + C = 0$$

该方程的解法在第2.2节讨论。二次方程解中平方根号下的项 $B^2 - 4AC$ 称为判别式（discriminant），它告诉我们实数解的个数。判别式为负时，平方根是虚数，直线与球体不相交；判别式为正时有两个解：一个对应光线进入球体的位置，一个对应光线离开球体的位置；判别式为零时，光线与球体相切，恰好接触一个点。代入球体的各项并约去因子 2，得到：

$$t = \frac{-\vec{d} \cdot (\vec{e} - \vec{c}) \pm \sqrt{(\vec{d} \cdot (\vec{e} - \vec{c}))^2 - (\vec{d} \cdot \vec{d})((\vec{e} - \vec{c}) \cdot (\vec{e} - \vec{c}) - R^2)}}{(\vec{d} \cdot \vec{d})}$$

其中：

- $\vec{e}$ 是光线起点
- $\vec{d}$ 是光线方向向量
- $\vec{c}$ 是球心
- $R$ 是球体半径

判别式为：
$$\Delta = (\vec{d} \cdot (\vec{e} - \vec{c}))^2 - (\vec{d} \cdot \vec{d})((\vec{e} - \vec{c}) \cdot (\vec{e} - \vec{c}) - R^2)$$

- 当 $\Delta < 0$ 时：无交点
- 当 $\Delta = 0$ 时：相切，一个交点
- 当 $\Delta > 0$ 时：相交，两个交点（$t_1$ 和 $t_2$，分别对应进入和离开球体的位置）

这个公式是光线追踪中球体求交的标准算法基础。

实际实现中，应当先检查判别式的值，再计算其他项。为在区间 $[t_0, t_1]$ 内正确找到最近的交点，需要考虑三种情况：若两个解中较小的一个落在区间内，它就是第一个击中点；否则，若较大的解落在区间内，它就是第一个击中点；再否则，就没有击中。

如第2.7.4节所述，点 $\vec{p}$ 处的法向量由梯度给出：$\vec{n} = 2(\vec{p} - \vec{c})$。单位法向量为 $\frac{\vec{p} - \vec{c}}{R}$。

### 4.4.2 光线与三角形求交（Ray-Triangle Intersection）

为计算光线与参数曲面的交点，我们建立一个方程组，使笛卡尔坐标全部匹配：

$$
\begin{cases}
x_e + t x_d = f(u,v) \\
y_e + t y_d = g(u,v) \\
z_e + t z_d = h(u,v)
\end{cases}
$$

或者

$$\vec{e} + t\vec{d} = \vec{f}(u,v)$$

- $(x_e, y_e, z_e)$ 是光线起点 $\vec{e}$ 的坐标分量
- $(x_d, y_d, z_d)$ 是光线方向向量 $\vec{d}$ 的坐标分量
- $f(u,v), g(u,v), h(u,v)$ 分别是参数曲面在 $x, y, z$ 方向上的参数方程
- $\vec{f}(u,v) = (f(u,v), g(u,v), h(u,v))$ 是参数曲面的向量参数方程
- $t$ 是光线参数
- $(u,v)$ 是曲面参数

这里有三个方程和三个未知数（$t$、$u$ 和 $v$）。当曲面是参数平面时，参数方程是线性的，可如第2.9.2节所述用向量形式表示。若三角形的三个顶点为 $\vec{a}$、$\vec{b}$、$\vec{c}$，则当下式成立时发生相交：

$$\vec{e} + t\vec{d} = \vec{a} + \beta(\vec{b} - \vec{a}) + \gamma(\vec{c} - \vec{a}) \quad (4.2)$$

对某些 $t$、$\beta$ 和 $\gamma$ 成立。求解该方程会同时告诉我们：

- $t$：交点沿光线的位置
- $(\beta, \gamma)$：交点相对于三角形的位置

交点 $\vec{p}$ 将位于 $\vec{e} + t\vec{d}$ 处，如图4.10所示。

再次依据第2.9.2节，当且仅当 $\beta > 0$、$\gamma > 0$ 且 $\beta + \gamma < 1$ 时，交点位于三角形内部。否则，光线击中三角形外的平面，即未击中三角形。

若无解，则要么三角形退化，要么光线与包含三角形的平面平行。

为求解方程(4.2)中的 $t$、$\beta$ 和 $\gamma$，我们将其从向量形式展开为三个坐标的三个方程：

**公式推导：**

将向量方程：
$$\vec{e} + t\vec{d} = \vec{a} + \beta(\vec{b} - \vec{a}) + \gamma(\vec{c} - \vec{a})$$

展开为分量形式，得到：

**x 坐标方程：**
$$e_x + tx_d = a_x + \beta(b_x - a_x) + \gamma(c_x - a_x)$$

**y 坐标方程：**
$$e_y + ty_d = a_y + \beta(b_y - a_y) + \gamma(c_y - a_y)$$

**z 坐标方程：**
$$e_z + tz_d = a_z + \beta(b_z - a_z) + \gamma(c_z - a_z)$$

整理为标准线性方程组形式：

$$\begin{cases}
tx_d - \beta(b_x - a_x) - \gamma(c_x - a_x) = a_x - e_x \\
ty_d - \beta(b_y - a_y) - \gamma(c_y - a_y) = a_y - e_y \\
tz_d - \beta(b_z - a_z) - \gamma(c_z - a_z) = a_z - e_z
\end{cases}$$

这是一个关于 $(t, \beta, \gamma)$ 的 3×3 线性方程组，可以使用矩阵方法（如克拉默法则）或高斯消元法求解。

可以将其改造成线性方程组：
$$\begin{bmatrix} x_a-x_b&&x_a-x_c&&x_d\\y_a-y_b&&y_a-y_c&&y_d\\z_a-z_b&&z_a-z_c&&z_d \end{bmatrix}\begin{bmatrix} \beta \\ \gamma \\ t \end{bmatrix}=\begin{bmatrix} x_a-x_e\\y_a-y_e\\z_a-z_e \end{bmatrix}$$

求解 3×3 线性方程组最经典的快速方法是克拉默法则（Cramer's rule）：这里不作详细推导。它可以化简为一步完成的计算式。

### 4.4.3 软件中的光线求交（Ray Intersection in Software）

在光线追踪程序中使用面向对象设计是个好主意：创建名为 Surface 的类，并派生出 Triangle、Sphere 等子类。任何光线可以相交的对象——包括表面的组合或加速结构（第12.3节）——都应是 Surface 的子类。这样，光线追踪程序对整整个模型只持有一个 Surface 引用，从而可以透明地添加新类型的物体与加速结构。

Surface 类的核心接口是与光线求交的方法（Kirk & Arvo, 1988）：

```cpp
class Surface
{
    HitRecord hit(Ray r, real t0, real t1);
};
```

这里，`(t0, t1)` 是光线上返回命中检测的区间，`HitRecord` 是保存一次表面相交所需全部数据的类：

```cpp
class HitRecord
{
    Surface s;  // 被击中的表面
    real t;     // 击中点沿光线的参数
    Vec3 n;     // 击中点处的表面法向量
};
```

被击中的表面、$t$ 值和表面法向量是最基本的信息，但也可以存储其他数据，如纹理坐标或切向量。视编程语言而定，命中记录（hit record）可能不是直接从函数返回，而是通过引用传入并填充。未击中可用 $t = \infty$ 的命中记录表示。

**扩展的 HitRecord 设计：**

```cpp
class HitRecord
{
    Surface* surface;      // 被击中的表面
    real t;               // 击中点沿光线的参数
    Vec3 normal;          // 表面法向量
    Vec2 texCoords;       // 纹理坐标 (u, v)
    Vec3 tangent;         // 切向量
    Vec3 bitangent;       // 副切向量
    bool frontFace;       // 是否为正面击中
  
    // 构造函数初始化为未击中状态
    HitRecord() : t(INFINITY) {}
};
```

**不同语言的实现方式：**

**C++ 引用传递版本：**
```cpp
bool hit(const Ray& r, real t0, real t1, HitRecord& record);
```

**返回值版本：**
```cpp
HitRecord hit(const Ray& r, real t0, real t1);
```

**击中检测逻辑：**
```cpp
// 检查是否击中
if (record.t != INFINITY && record.t >= t0 && record.t <= t1) {
    // 有效击中
    Vec3 hitPoint = r.origin + record.t * r.direction;
    // 进行光照计算...
} else {
    // 未击中，返回背景色
}
```

### 4.4.4 光线与一组物体求交（Ray Intersection with a Group of Objects）

当然，大多数有趣的场景都由多个物体组成；当光线与场景求交时，必须只找出沿光线方向离相机最近的交点。实现这一点的一个简单方法，是把一组物体本身当作另一种类型的物体：要让光线与一个组相交，只需让光线与该组中的各个物体相交，并返回 $t$ 值最小的那个交点。以下代码在区间 $t \in [t_0, t_1]$ 内测试命中：

```cpp
class Group : public Surface
{
    list<Surface*> surfaces;  // 组中所有表面的列表
  
    HitRecord hit(Ray ray, real t0, real t1)
    {
        HitRecord closest_hit;     // 初始化为未击中状态 (t = ∞)

        for (Surface* surf : surfaces) {
            HitRecord rec = surf->hit(ray, t0, t1);
            if (rec.t < INFINITY) {
                closest_hit = rec;
                t1 = rec.t;        // 缩小搜索区间
            }
        }
        return closest_hit;
    }
};
```

注意到 `t1 = t` 可以不断缩小求交区间，因此新的击中目标必然更近。

**算法要点分析：**

1. **区间缩减优化**：代码通过缩小交点区间 $[t_0, t_1]$ 来优化性能，使得对 `surf.hit` 的调用只会击中比当前最近交点更近的表面。

2. **递归结构**：Group 类作为 Surface 的子类，可以包含其他 Group，形成层次化的场景结构。

3. **最近交点查找**：通过比较 $t$ 值确保返回的是最近的有效交点。

**优化版本：**
```cpp
HitRecord hit(Ray ray, real t0, real t1)
{
    HitRecord closest_hit;
    real closest_t = t1;
  
    for (Surface* surf : surfaces) {
        HitRecord rec = surf->hit(ray, t0, closest_t);
        if (rec.t < closest_t) {
            closest_hit = rec;
            closest_t = rec.t;  // 持续缩小搜索范围
        }
    }
    return closest_hit;
}
```

一旦光线-场景求交功能正常工作，我们就可以渲染出图像，但更好的结果还需要包含更多的视觉线索，正如我们接下来要描述的那样。

## 4.5 着色（Shading）

一旦确定像素的可见表面，就通过求值着色模型（shading model）来计算像素值。具体做法完全取决于应用需求——方法从简单的启发式算法到复杂的基于物理的模型不一而足。同一套着色模型既可以用于光线追踪，也可以用于以物体为序的渲染方法。

第5章描述了一个适用于基础光线追踪器的简单着色模型，本章图像即由该模型生成。若想获得更真实的效果，可以升级到第14章讨论的模型，它们更接近真实表面的物理属性。本节讨论光线追踪器如何计算着色计算的输入。

**着色计算的核心流程：**

```cpp
Vec3 shade(const HitRecord& hit, const Ray& ray, const Scene& scene)
{
    // 1. 获取表面材质属性
    Material mat = hit.surface->getMaterial(hit.texCoords);
  
    // 2. 计算几何信息
    Vec3 hitPoint = ray.origin + hit.t * ray.direction;
    Vec3 normal = hit.normal;
    Vec3 viewDir = -normalize(ray.direction);
  
    // 3. 光照计算
    Vec3 color = computeLighting(hitPoint, normal, viewDir, mat, scene);
  
    return color;
}
```

**着色输入参数的计算：**

1. **交点位置**：$\mathbf{p} = \mathbf{o} + t\mathbf{d}$
2. **表面法向量**：从 HitRecord 获取或重新计算
3. **视线方向**：$\mathbf{v} = -\hat{\mathbf{d}}$（光线方向的反向）
4. **材质属性**：漫反射系数、镜面反射系数、粗糙度等
5. **纹理坐标**：用于纹理查找和程序化材质

**光线追踪的优势：**

- **精确可见性**：准确计算哪些光源可以到达表面点
- **全局光照**：自然支持反射、折射和阴影
- **材质一致性**：相同的着色模型可以无缝集成

无论选择简单的 Phong 模型还是复杂的 PBR（基于物理的渲染，physically based rendering）模型，光线追踪器都能提供准确的几何和可见性信息，作为着色计算的基础。

### 4.5.1 光源（Light Sources）

为支持着色计算，光线追踪程序总包含一个光源列表。第5章的着色模型需要三类光源：**点光源**（point light，从空间中一点发射光线）、**方向光源**（directional light，从单一方向照亮场景）和**环境光源**（ambient light，提供恒定照明以填充阴影）。更高级的系统中还支持其他类型的光源，如**面光源**（area light，本质上是发光的场景几何体）或**环境贴图光源**（environment light，用图像表示来自天空等远处光源的光照）。

从点光源或方向光源计算着色需要特定的几何信息。在光线追踪器中，一旦确定视线光线击中表面，就拥有了确定以下四个向量所需的全部信息：

• **着色点**（shading point）$\mathbf{x}$：在交点对应的 $t$ 值处求值视线光线即可得到。
• **表面法向量** $\mathbf{n}$：取决于表面类型（球面、三角形等），每个表面都需要能够计算其在光线交点处的法向量。
• **光照方向** $\mathbf{l}$：作为着色计算的一部分，根据光源位置或方向计算。
• **视线方向** $\mathbf{v}$：即视线光线方向的反向（$\mathbf{v} = -\mathbf{d}/\|\mathbf{d}\|$）。

环境光源的着色计算简单得多：由于光线来自四面八方，没有 $\mathbf{l}$ 向量；着色不依赖于 $\mathbf{v}$；对第5章的简单模型而言，甚至不依赖于 $\mathbf{x}$ 或 $\mathbf{n}$。

在包含多个光源的场景中计算着色，只需把各光源的贡献相加。在基础光线追踪器中，遍历所有光源、计算每个光源的着色贡献并累加到像素颜色即可。

### 4.5.2 软件中的着色（Shading in Software）

光线追踪程序通常包含表示光源与材质的对象。光源可以是 Light 类子类的实例，且必须包含完整描述光源所需的全部信息。由于着色还需要描述表面材质的参数，另一个有用的类是 Material，它封装了求值着色模型所需的一切。

不同系统在光源与材质之间划分着色计算的方式不同。与本章叙述一致的一种做法是：光源负责整体光照计算，材质负责计算 BRDF 值：

```cpp
class Light{
  Color illuminate(Ray ray, HitRecord hrec)
}
class Material{
  Color evaluate(Vec3 l, Vec3 v, Vec3 n)
}
```

> BRDF 是**双向反射分布函数**（Bidirectional Reflectance Distribution Function）的缩写。
> BRDF 是计算机图形学中描述表面如何反射光线的数学函数。具体来说：
> BRDF 函数 $f_r(\omega_i, \omega_o)$ 描述了当光线从方向 $\omega_i$ 入射到表面上时，有多少光线会沿着方向 $\omega_o$ 反射出去。
>
> - **输入**：入射光方向和出射光方向（都相对于表面法向量）
> - **输出**：反射光与入射光的比值
> - **单位**：通常是 $sr^{-1}$（每球面度）
>
> 1. **Lambert 漫反射 BRDF**：
>    `f_r = ρ/π`
>    其中 ρ 是反照率，π 是归一化因子
> 2. **Phong 镜面反射 BRDF**：
>    `f_r = (n+2)/(2π) * (R·V)^n`
>    其中 n 是光泽度指数
> 3. **Cook-Torrance 微表面 BRDF**：
>    `f_r = DFG/(4(N·L)(N·V))`
>    包含分布项 D、菲涅尔项 F 和几何项 G
>
> BRDF 允许我们：
>
> - 精确模拟不同材质的光学特性
> - 实现物理真实的渲染
> - 支持复杂的材质如金属、塑料、皮肤等
>
> BRDF 是现代基于物理渲染（PBR）的核心概念。

每个 surface 都保存对自身材质的引用，因此点光源类可以写成：

```cpp
// cpp伪代码
class PointLight: Light {
  Color I;
  Vec3 p;
  
  Color illuminate(Ray ray, HitRecord hrec){
    Vec3 x = ray.evaluate(hrec.t); // 计算交点位置
    real r = ||p-x||; // 计算光源距离
    Vec3 l = (p-x)/r; // 计算光照方向（从交点指向光源的单位向量）
    Vec3 n = hrec.normal; // 获取表面法向量
    Color E = max(0, dot(n, l))*I/r^2;  // Lambert漫反射，这里的r^2是光线衰减和距离平方呈反比
    Color k = hrec.surface.material.evaluate(l, v, n); // BRDF计算，表示材质如何反射光线，v 应该是视线方向向量（从交点指向相机）
    return kE; // 材质响应*光照强度
  }
}
```

这些计算假设 Color 类包含 RGB 分量并支持逐分量乘法。这种安排也让环境光便于作为光源处理：只需把环境光系数设为材质的一个属性：

```cpp
// 环境光类，继承自Light基类
class AmbientLight, subclass of Light
    // 环境光强度（颜色）
    Color Ia
  
    // 计算环境光对指定交点的光照贡献
    Color illuminate(Ray ray, HitRecord hrec)
        // 从命中表面的材质中获取环境光反射系数
        Color ka = hrec.surface.material.ka

        // 返回环境光贡献：环境光系数 × 环境光强度
        return ka * Ia
```

包含交点计算和多光源处理的完整光线着色计算可以写成：

```cpp
function shade-ray (Ray ray, real t0, real t1)
    // 计算光线与场景中所有物体的交点，返回最近的命中记录
    HitRecord rec = scene.hit(ray, t0, t1)

    // 检查是否找到有效交点（t值小于无穷大表示有交点）
    if rec.t < ∞ then
        // 初始化累积颜色为黑色
        Color c = (0,0,0)

        // 遍历场景中的所有光源
        for light in scene.lights do
            // 计算当前光源对该交点的光照贡献并累加
            c = c + light.illuminate(ray, rec)

        // 返回所有光源贡献的总和
        return c
    else
        // 光线未命中任何物体，返回背景色
        return background-color
```

这种设置保持了材质与光源的合理分离，并允许以后透明地添加新类型的材质与光源。纹理（texture）会为光线追踪器的架构增加一些复杂性，详见第11.2.5节。

着色本身让三维物体的图像更加逼真、更易理解，但它无法显示物体与物体之间的相互作用。例如，图4.12中的球体看起来像是漂浮在它们所依靠的地面上方。

### 4.5.3 阴影（Shadows）

在光线追踪器中实现基本着色后，点光源与方向光源的阴影可以非常容易地添加。设想我们位于表面上某点 $\mathbf{x}$：当且仅当朝光源方向“看”时，在我们与光源之间看到某个物体，点 $\mathbf{x}$ 才处于阴影中。若光源与点之间没有物体，光线就不会被阻挡。

这可以用图4.13说明：光线 $\mathbf{x} + t_l$ 没有碰到任何物体，因此点 $\mathbf{x}$ 不在阴影中；而点 $\mathbf{x'}$ 处于阴影中，因为光线 $\mathbf{x'} + t_{l'}$ 碰到了物体。用于判断点是否处于阴影中的光线称为**阴影光线**（shadow ray），以区别于视线光线。

在着色算法中，我们把“光线是否被阴影遮蔽”作为条件判断，与光源着色贡献的累加一起处理。简单实现中，阴影光线在 $t \in [0, r]$ 区间内检测，但由于数值误差，这可能导致与点 $p$ 所在的表面相交。为避免该问题，通常测试 $t \in (e, r]$，其中 $e$ 是一个非常小的正数（如图4.14所示）。

通过投射阴影光线并添加条件判断，可以把阴影测试加入上文提到的 `PointLight illuminate` 方法：

```cpp
HitRecord srec = sence.hit(Ray(x, l), 0, r)
if srec.t < inf then
	point in shadow
else
	point in light
```

方向光源的阴影测试类似，只是用 $t_1 = \infty$ 代替 $r$。

注意，每个光源的着色计算都需要一条独立的阴影光线，而计算环境光着色时不需要进行阴影测试。

阴影在表现邻近物体之间的位置关系方面起着重要的视觉作用，如图4.15所示。

### 4.5.4 镜面反射（Specular Reflection）

![镜面反射](Pasted%20image%2020240301200512.png)

在光线追踪程序中添加理想镜面反射（specular reflection）很直观。关键观察如图4.16所示：从方向 **e** 观察的观察者，看到的是表面沿方向 **r** 可见的内容。向量 **r** 是向量 **-d** 关于表面法向量 **n** 的反射，可以利用 **d** 在表面法向量方向上的投影来计算（公式4.3）：

$$\mathbf{r} = \mathbf{d} - 2(\mathbf{d} \cdot \mathbf{n})\mathbf{n}$$

现实世界中，光线从表面反射时会损失一些能量，且不同颜色的损失可能不同。例如，金属反射黄光的效率高于蓝光，因此会改变被反射物体的颜色。这可以在 `shade-ray` 中通过递归调用实现：在所有光源计算完毕后再累加一项贡献：

```cpp
// 添加镜面反射贡献
color c = c + km * shade-ray(Ray(p, r), ε, ∞)
```

其中 $k_m$（表示“镜面”mirror）是镜面反射的 RGB 颜色系数。与阴影光线同理，需要传入 $t_0 = ε$：我们不希望反射光线击中它出发的那个物体。

上述递归调用的问题是它可能永不终止。例如，从房间内部出发的光线会永远反弹下去。解决办法是设置最大递归深度；并且只在 $k_m$ 非零时才生成反射光线，代码会更高效。

使用常数镜面反射系数 $k_m$ 会产生简单光线追踪器特有的外观（图4.17）；现实中该系数随入射角显著变化。更好的模型参见第14章。

## 笔记（Notes）

### 常见问题（Frequently Asked Questions）

**• 为什么光线追踪中没有透视矩阵？**

透视矩阵（在 Z 缓冲中）的存在，是为了把透视投影转换为平行投影。光线追踪中不需要它，因为透视投影可以轻松地通过从视点向外发散光线来隐式实现。

**• 光线追踪能否实现交互式渲染？**

对于足够小的模型和图像，任何现代 PC 都有足够的计算能力实现交互式光线追踪。实际应用中，全屏实现需要多个 CPU 配合共享帧缓冲区。计算机性能的增长速度远快于屏幕分辨率的提升，因此在传统 PC 上以屏幕分辨率对复杂场景进行光线追踪只是时间问题。

**• 光线追踪在硬件图形程序中有用吗？**

光线追踪常用于拾取（picking）操作。当用户在 3D 图形程序中点击某个像素时，程序需要确定该像素位置可见的是哪个物体。光线追踪是确定这一点的理想方法。

### 练习（Exercises）

#### 练习 1

光线 $(1,1,1) + t(-1,-1,-1)$ 与以原点为中心、半径为 1 的球体的交点的光线参数是什么？注意：这是一个很好的调试案例。

##### 解答

为了求解光线与球体的交点，需要将光线方程代入球面方程。

**给定条件：**
- 光线：$\mathbf{o} + t\mathbf{d} = (1,1,1) + t(-1,-1,-1)$
- 球面：$x^2 + y^2 + z^2 = 1$（以原点为中心，半径为 1）

**求解过程：**

将光线方程的各分量表示为：
- $x = 1 - t$
- $y = 1 - t$
- $z = 1 - t$

代入球面方程：
$(1-t)^2 + (1-t)^2 + (1-t)^2 = 1$

展开：
$3(1-t)^2 = 1$

$(1-t)^2 = \frac{1}{3}$

$1-t = \pm\frac{1}{\sqrt{3}}$

因此：
$t = 1 \mp \frac{1}{\sqrt{3}}$

**交点的光线参数为：**
- $t_1 = 1 - \frac{1}{\sqrt{3}} = 1 - \frac{\sqrt{3}}{3} \approx 0.423$
- $t_2 = 1 + \frac{1}{\sqrt{3}} = 1 + \frac{\sqrt{3}}{3} \approx 1.577$

**为什么这是个好的调试案例：**

这个案例有几个特点使其成为理想的调试用例：
1. 光线起点 $(1,1,1)$ 在球外
2. 光线方向 $(-1,-1,-1)$ 指向原点
3. 计算结果简洁，容易验证
4. 两个交点都在正的 $t$ 值处，符合物理意义

#### 练习 2

光线 $(1,1,1) + t(-1,-1,-1)$ 与顶点为 $(1,0,0)$、$(0,1,0)$ 和 $(0,0,1)$ 的三角形相交时的重心坐标和光线参数是什么？注意：这是一个很好的调试案例。

##### 解答：使用 Möller-Trumbore 算法

**给定条件：**
- 光线：$\mathbf{O} + t\mathbf{D} = (1,1,1) + t(-1,-1,-1)$
- 三角形顶点：$\mathbf{V_0} = (1,0,0)$，$\mathbf{V_1} = (0,1,0)$，$\mathbf{V_2} = (0,0,1)$

**步骤1：计算边向量**
- $\mathbf{E_1} = \mathbf{V_1} - \mathbf{V_0} = (-1,1,0)$
- $\mathbf{E_2} = \mathbf{V_2} - \mathbf{V_0} = (-1,0,1)$

**步骤2：计算向量**
- $\mathbf{P} = \mathbf{D} \times \mathbf{E_2} = (-1,-1,-1) \times (-1,0,1) = (-1,2,-1)$
- $det = \mathbf{E_1} \cdot \mathbf{P} = (-1,1,0) \cdot (-1,2,-1) = 1 + 2 + 0 = 3$

**步骤3：计算 u 坐标**
- $\mathbf{T} = \mathbf{O} - \mathbf{V_0} = (1,1,1) - (1,0,0) = (0,1,1)$
- $u = \frac{\mathbf{T} \cdot \mathbf{P}}{det} = \frac{(0,1,1) \cdot (-1,2,-1)}{3} = \frac{0 + 2 - 1}{3} = \frac{1}{3}$

**步骤4：计算 v 坐标**
- $\mathbf{Q} = \mathbf{T} \times \mathbf{E_1} = (0,1,1) \times (-1,1,0) = (-1,-1,1)$
- $v = \frac{\mathbf{D} \cdot \mathbf{Q}}{det} = \frac{(-1,-1,-1) \cdot (-1,-1,1)}{3} = \frac{1 + 1 - 1}{3} = \frac{1}{3}$

**步骤5：计算光线参数 t**
- $t = \frac{\mathbf{E_2} \cdot \mathbf{Q}}{det} = \frac{(-1,0,1) \cdot (-1,-1,1)}{3} = \frac{1 + 0 + 1}{3} = \frac{2}{3}$

##### 验证

**检查重心坐标约束：**
- $u = \frac{1}{3} \geq 0$ ✓
- $v = \frac{1}{3} \geq 0$ ✓
- $u + v = \frac{2}{3} \leq 1$ ✓

**重心坐标：**
- $\alpha = 1 - u - v = 1 - \frac{1}{3} - \frac{1}{3} = \frac{1}{3}$
- $\beta = u = \frac{1}{3}$
- $\gamma = v = \frac{1}{3}$

**验证交点：**

光线上的点：$(1,1,1) + \frac{2}{3}(-1,-1,-1) = (\frac{1}{3}, \frac{1}{3}, \frac{1}{3})$

重心坐标计算的点：$\frac{1}{3}(1,0,0) + \frac{1}{3}(0,1,0) + \frac{1}{3}(0,0,1) = (\frac{1}{3}, \frac{1}{3}, \frac{1}{3})$ ✓

##### 最终答案

- **光线参数：** $t = \frac{2}{3}$
- **重心坐标：** $(\alpha, \beta, \gamma) = (\frac{1}{3}, \frac{1}{3}, \frac{1}{3})$

##### 为什么这是个好的调试案例

1. **对称性：** 重心坐标完全相等，易于验证
2. **简单数值：** 所有坐标都是简单分数
3. **几何直观：** 交点位于三角形的重心
4. **边界测试：** 可以验证算法的数值稳定性

##### Möller-Trumbore 算法详解

###### 算法背景

[Möller-Trumbore 算法](https://zhuanlan.zhihu.com/p/451582864)是计算机图形学中用于**光线-三角形相交测试**的经典算法，由 Tomas Möller 和 Ben Trumbore 在 1997 年提出。它直接计算重心坐标，避免了先计算平面交点再判断是否在三角形内的两步过程。

###### 算法原理

**核心思想：** 直接求解线性方程组，同时得到光线参数 $t$ 和重心坐标 $(u,v)$。

设三角形的三个顶点为 $\mathbf{V_0}$、$\mathbf{V_1}$、$\mathbf{V_2}$，光线为 $\mathbf{O} + t\mathbf{D}$。

三角形上任意一点可以用重心坐标表示：
$$\mathbf{P} = (1-u-v)\mathbf{V_0} + u\mathbf{V_1} + v\mathbf{V_2}$$

展开后：
$$\mathbf{P} = \mathbf{V_0} + u(\mathbf{V_1} - \mathbf{V_0}) + v(\mathbf{V_2} - \mathbf{V_0})$$

定义边向量：
- $\mathbf{E_1} = \mathbf{V_1} - \mathbf{V_0}$
- $\mathbf{E_2} = \mathbf{V_2} - \mathbf{V_0}$

则：$$\mathbf{P} = \mathbf{V_0} + u\mathbf{E_1} + v\mathbf{E_2}$$

###### 关键步骤解析

1. 第二步中 P 和 det 的含义

**向量 P：**
$$\mathbf{P} = \mathbf{D} \times \mathbf{E_2}$$

**几何意义：**
- $\mathbf{P}$ 是光线方向向量 $\mathbf{D}$ 与三角形边向量 $\mathbf{E_2}$ 的叉积
- 它垂直于 $\mathbf{D}$ 和 $\mathbf{E_2}$ 构成的平面
- 用于后续计算重心坐标 $u$

**行列式 det：**
$$det = \mathbf{E_1} \cdot \mathbf{P} = \mathbf{E_1} \cdot (\mathbf{D} \times \mathbf{E_2})$$

**几何意义：**
- $det$ 是由 $\mathbf{E_1}$、$\mathbf{D}$、$\mathbf{E_2}$ 构成的**标量三重积**
- 表示这三个向量构成的平行六面体的**有向体积**
- **关键作用：**
  - 如果 $det = 0$，说明光线与三角形平行，无交点
  - $det$ 的符号决定了三角形的朝向（背面剔除）
  - $det$ 作为分母，用于归一化重心坐标

###### 数学推导核心

通过联立方程：
$$\mathbf{O} + t\mathbf{D} = \mathbf{V_0} + u\mathbf{E_1} + v\mathbf{E_2}$$

重新排列：
$$t\mathbf{D} - u\mathbf{E_1} - v\mathbf{E_2} = \mathbf{O} - \mathbf{V_0}$$

这是一个 3×3 的线性方程组，Möller-Trumbore 算法通过巧妙的向量运算直接求解，避免了矩阵求逆的计算开销。

###### 算法优势

1. **高效性：** 一次计算同时得到 $t$、$u$、$v$
2. **数值稳定：** 避免了两步法可能的数值误差累积
3. **内存友好：** 只需要临时存储几个向量
4. **易于优化：** 可以提前退出，支持背面剔除

#### 练习 3

对“良好”（非对抗性）模型上的光线追踪进行粗略的时间复杂度计算。将你的分析分为预处理和图像计算两个阶段，以便预测静态模型多帧光线追踪的行为。

##### 预处理阶段（Preprocessing Phase）

**主要任务：构建加速数据结构**

**BVH（边界体积层次结构，Bounding Volume Hierarchy）构建**
- **输入：** $N$ 个三角形
- **时间复杂度：** $O(N \log N)$
- **空间复杂度：** $O(N)$

**具体分析：**

```text
构建过程：
1. 排序三角形：O(N log N)
2. 递归分割：O(N) × O(log N) 层 = O(N log N)
3. 计算包围盒：O(N)

总计：O(N log N)
```

##### 其他预处理任务

- 纹理加载：$O(T)$（T 为纹理大小）
- 材质参数设置：$O(M)$（M 为材质数量）
- 相机参数计算：$O(1)$

**预处理总复杂度：** $O(N \log N + T + M)$

##### 图像计算阶段（Image Computation Phase）

**主要参数：**
- 图像分辨率：$W \times H$
- 每像素采样数：$S$
- 平均递归深度：$D$
- 场景三角形数：$N$

**单条光线的遍历复杂度**

使用 BVH 加速结构：
- **理论最优：** $O(\log N)$
- **实际情况：** $O(\sqrt{N})$ 到 $O(\log N)$ 之间

**原因分析：**
```cpp
// BVH遍历的典型情况
期望遍历节点数 ≈ log₂(N) + 几何复杂度修正
实际交点测试数 ≈ √N （对于"良好"场景）
```

**完整像素计算**

每个像素需要：
- 主光线：1 条
- 阴影光线：$L$ 条（L 为光源数量）
- 反射/折射光线：递归深度 $D$

**单像素复杂度：**
$$O((1 + L + D) \times \log N)$$

**总图像计算复杂度**
$$O(W \times H \times S \times (1 + L + D) \times \log N)$$

**多帧渲染分析（静态模型）**

1. 第一帧
```text
总时间 = 预处理时间 + 渲染时间
       = O(N log N) + O(W×H×S×(1+L+D)×log N)
```

2. 后续帧（相同静态场景）
```text
总时间 = 渲染时间（预处理可重用）
       = O(W×H×S×(1+L+D)×log N)
```

**实际数值估算**

**典型场景参数：**
- 分辨率：1920×1080
- 三角形数：100 万
- 每像素采样：4
- 递归深度：5
- 光源数：3

**计算量估算：**
```
像素总数：2,073,600
每像素光线数：4 × (1 + 3 + 5) = 36
总光线数：≈ 75百万条
每条光线BVH遍历：log₂(10⁶) ≈ 20次节点访问
总BVH访问：≈ 15亿次
```

**复杂度总结表**

| 阶段   | 一次性成本    | 每帧成本            | 主导因子     |
| ------ | ------------- | ------------------- | ------------ |
| 预处理 | $O(N \log N)$ | $O(1)$              | 场景复杂度   |
| 渲染   | -             | $O(W×H×S×D×\log N)$ | 图像质量设置 |

**性能优化策略**

1. **预处理优化：**
   - 使用 SBVH（Spatial BVH）
   - 并行构建加速结构

2. **渲染优化：**
   - 自适应采样
   - 重要性采样
   - GPU 并行化

3. **多帧优化：**
   - 时间相干性利用
   - 增量更新加速结构

**结论**

对于静态模型的多帧渲染，预处理成本会被摊销到多帧中，使得后续帧的渲染效率显著提高。这种分析对于实时光线追踪和离线渲染的性能预测都具有重要价值。
